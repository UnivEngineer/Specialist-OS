# Совместная сборка релоцируемых DLL v3 и MEM rev70

Промежуточная сборка от 25 ноября 2026 года довела BIOS до D809h при начале шрифтового слота D800h. В объединённом дереве обе разработки используют одну карту памяти и одну таблицу системных вызовов. Дополнительно исправлена обработка неизвестного номера BIOS и локальной DOS в MAIN. Диспетчер проверяет границу перед чтением адреса из таблицы. Вызов из фиксированной DLL через F806h и вызов с пакетом через F800h возвращают CF=1 и DOS_ERR_UNSUPPORTED. На отказе F800h сохраняет восемь исходных байтов MX_REGS.

| Файл     | Размер в байтах | Размещение |
| -------- | --------------: | ---------- |
| BIOS.sys |           6 107 | C000h–D7DAh, свободно 37 байт до D800h |
| DOS.sys  |          31 471 | 0100h–7BEEh, свободно 145 байт до переменных в 7C80h |
| IO.sys   |             796 | MAIN 416, банковая часть 380 |
| MEM.sys  |           3 070 | Транспорт rev70 |

Дважды выполнена штатная `scripts/build/build-all.ps1`, в новом клоне с исходниками интеграции и в рабочем проекте. Обе сборки прошли для MMX Flash + floppy, MX ROM + floppy и RAMFOS. BIOS, DOS, IO, MEM, загрузочное ПЗУ MX и Monitor-2 совпадают побайтно. Monitor-2 также совпадает с историческим эталоном. Журналы SjASMPlus содержат предупреждения, в частности о нулевой длине заполнения и ORG в измерительной сборке. [Карта памяти](System.layout.json) · [Сборка в клоне](clean-build.log) · [Сборка рабочего дерева](build-all.log)

SHA-256 системной flash MMX из клона — `3218a100aee386db38c179e00e9b33934edfcb70d3d994a231815d189af38f5d`, из рабочего проекта — `d2d22f4c7b28a8ed28e44a98c912b289c35dc2b7a38870220ef9db8c044aac20`. В рабочей копии тексты NC.HLP и EDIT.HLP имеют окончания CRLF, из Git они извлекаются с LF. В игровом H: такую же разницу даёт Ball.bat. Оба системных образа прошли по 80 проверок печати в скрытом Emu80 при фиксированных 32×, результаты совпали по тактам и регистрам во всех случаях. ## Проверки

- На Intel 8080 проверены 76 вариантов передачи регистров и прямых вызовов, вложенные вызовы, неизвестные группы, первый и последний недоступные номера BIOS и DOS, границы памяти и устойчивость SP. Стенд SDK сверил фиксированные адреса и раскладку структур. Отдельно прошли WORD16/HIGH8 с многопорционной таблицей поправок, 54 случая выделения памяти и 314 вариантов CPM32. [Вызовы](syscalls.json) · [CPM32](cpm32/result.json)
- В MMX проверены загрузка, активация и выгрузка перемещаемых DLL в MAIN, DOS и EXEC. При аппаратном Reset DOS сохранила резидентный модуль и освободила незавершённую загрузку. Проверены переустановка ВГ93, секторные операции, вложенные BAT, ENUM и FILEOPS. [Модули](final/modules/result.json) · [Драйверы](final/drivers/result.json)
- На исходном MX с одним банком RELTEST вызвал две MAIN DLL и вернулся в NC_MN. По клавиатуре EDIT_MN открыл AUTOEXEC.BAT, принял изменение и вернулся в NC_MN после отказа от сохранения. [Однобанковый MX](final/mx/result.json)
- Стенд фиксированных DLL v2 прошёл 25 групп без пропусков, включая MAINMOD, BANKMOD и программу на C SDK. Вызовы 01FFh и 0102h проверены из обеих DLL. Выполнены аппаратный Reset с сохранением DOS и перезагрузка ядра при сохранённом ОЗУ. В прежнем ядре дескриптор BAT оставался открытым с позицией на конце файла. В новом ядре kernelCold сбрасывает его через batDiscard, AUTOEXEC заново устанавливает RAM-диск и запускает NC_MN. [Результаты v2](legacy-v2.json)
- Упаковщики Python и PowerShell дали одинаковый результат для 737 входов. Из них 341 образ принят и 396 отклонены. В двух сборках побайтно совпали 225 файлов SYS, DLL, FNT, CPU, COM, EXE, MON и I80 из каталога bin, исключая отдельные тестовые модули.
