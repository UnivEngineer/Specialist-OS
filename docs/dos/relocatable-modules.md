# Релоцируемые DLL и драйверы MXOS2

План по рабочей копии от 23 ноября 2026 г.

Первый законченный этап — две MAIN DLL, собранные от нуля, одновременно вызываются по своим handle на оригинальном MX, где единственный дополнительный банк уже занят DOS. Предлагается выбирать базу один раз и исправлять внутренние ссылки при холодной загрузке. База остаётся постоянной до выгрузки. Пользовательские вызовы MODULE_LOAD/CALL/UNLOAD и выбор target в A для этого достаточны.

## Где DOS сегодня принимает решение об адресе

| Что размещается | Кто загружает | Что удерживает место и как происходит вызов |
|---|---|---|
| MAIN DLL | `moduleLoad → imageOpen → mdMain → moduleMainClaimStrict → memoryReserveMain` | Полный интервал из заголовка, включая рабочую память ниже load и BSS. Одна из восьми записей модуля и одна из 32 записей аллокатора. MEM вызывает сохранённый entry в MAIN. |
| BANK DLL | `mdBank` | Выделяется целый свободный EXEC-банк, затем ставится профиль транспорта. Две одинаковые базы в разных банках уже возможны. |
| Обычная DOS DLL | `mdDos → dosArenaImage` | Запись модуля хранит фактические start/end, entry и DOS_IO_PAGE. Отдельная FAR-аллокация не нужна. Действуют правила владельцев, активных вызовов, CACHEABLE и RETAIN. |
| ENUM.DLL и FILEOPS.DLL | `overlayEnsure` | Два частных дескриптора с ready/active/end. Загрузчик требует entry = load = согласованная база, проверяет копию таблицы экспорта ядра по base+3. Фасады прямо вызывают константу адреса. |
| Установщик физического драйвера | `FILE_EXEC → keDriver` | Сценарий сборки измеряет тело и компонует его к верхней границе арены. Во время исполнения DOS защищает diStart/diEnd, проверяет переданный DRIVER_INSTALL и копирует службу. Время жизни службы больше времени жизни установщика. |

По `mxos.inc` и имеющемуся `bin/DOS.sym` арена банка DOS занимает **[9B00h,C9D8h), 11 992 байта**. Служба дискеты начинается с 9D00h, ENUM с 9F00h, FILEOPS с A700h. В README DOS и API MEM ещё встречается прежняя граница 9800h. BAT ищет непрерывное свободное окно сверху через `arenaProbe` и `arenaObstacle`. При занятии его окна `dosArenaImage` отсоединяет окно с сохранением позиции чтения. Арена MAIN устроена иначе. Доверенный диапазон ARENA принадлежит приложению, а для статического образа загрузчик учитывает карту владельцев, системный предел, шрифт и минимальную кучу. Вызывать обычный ALLOC от имени приложения для выбора адреса DLL было бы ошибкой. ## Формат и изготовление образа

Предлагаемый вариант для первого этапа — явная разновидность нативного контейнера для релоцируемых образов. Обычные фиксированные COM/EXE/DLL/FNT и существующие образы носителей остаются читаемыми. Различие определяется версией и заголовком. Расширение файла и специальные значения адресов для этого не нужны. FILE_EXEC, RUN, загрузчики шрифтов и оверлеев должны отклонять неподдерживаемые сочетания до записи в память.

* Макет файла: базовый заголовок, расширение, инициализированное тело, таблица. Вариант для реализации — версия 3, headerBytes=40. В байтах 0–31 сохранить размещение существующих полей. Для v3 определить memoryBegin=0, memoryEnd=размер всего интервала, load и entry как смещения от его начала, bytes как длину тела. BSS задаётся явно. Политика, стек, minHeap, target-флаги и options сохраняют своё назначение.
* В расширении байт 32 задаёт вид поправок (0 — WORD16, 1 — HIGH8), байт 33 — log2 выравнивания базы, слово 34 — число записей, слово 36 — calcCS таблицы, слово 38 — резерв с обязательным нулём. Слова little-endian. Для v3 определить сумму заголовка по всем 40 байтам с обнулённым полем собственной суммы. Сумма тела считается до изменения первого операнда. Для пустой таблицы зафиксировать нулевую сумму. Расширить сохранение/восстановление файлового контекста либо хранить расширение отдельно и явно сохранять его при вызовах, читающих другие файлы.
* В таблице хранить строго возрастающие 16-битные смещения **от начала тела**. Для WORD16 по каждому смещению лежит слово, к которому прибавляется база всего интервала. Например, при load=0020h запись 0001h указывает на операнд по base+0021h. Значение 0120h становится 6120h при base=6000h. Для HIGH8 запись указывает на один старший байт, прибавляется base/256. Один режим на файл. Адрес BIOS, регистр устройства и абсолютный экспорт ядра в таблицу не входят.
* Проверки упаковщика и DOS должны совпадать: известные версия/режим/флаги, допустимая степень выравнивания, HIGH8 только при кратности 256, непустое тело, entry внутри тела, load+bytes+BSS в интервале, стек и minHeap допустимы для target. Длина файла в точности headerBytes+bytes+2×count. Умножение, концы интервалов и округление проверять на перенос до усечения к 16 битам. Запись вместе с шириной целиком принадлежит телу, дубликаты и перекрытия запрещены. Фиксированная внешняя память и отдельные пространства `DISP` требуют явного описания в исходнике.
* Прежний `tasm/sjasmplus.exe` версии 1.18.3 проверен с `--i8080`. Блок при ORG 0 из `call foo` (foo=0) и `call 0C000h` с RELOCATE_TABLE дал `CD 00 00 CD 00 C0 | 01 00`. Та же сборка с RELOCATE_START HIGH завершилась ошибкой `Unexpected: HIGH`. Комплектный ассемблер обновлён до официального [1.24.0](https://github.com/z00m128/sjasmplus/releases/tag/v1.24.0). Windows-релиз проверен с --i8080: у внутреннего CALL и отдельного LD H,HIGH tbl таблица содержит позиции 0002h и 0004h. После прибавления 60h к этим байтам результат побайтно совпал со сборкой от 6000h, включая абсолютный CALL C000h. Принудительная сборка проекта на обеих версиях дала побайтно одинаковые бинарники и SystemRom_emu80_writable.bin. Адреса BIOS/DOS и профили MAIN/EXEC у NC и EDIT совпали. В тесте COPYBEN переименована метка pair, совпавшая с новым оператором. Для реализации использовать штатную генерацию таблиц для обоих режимов.
* В `scripts/images/executable.py` и сборщике компонента довести метки конца тела, таблицы и рабочего интервала до упаковщика. Вычитать load из позиций таблицы, если SjASMPlus выдал координаты от начала интервала. Проверить побайтовым сравнением с независимой сборкой того же кода на двух заданных базах, включая перенос младшего байта и адрес BSS. Такая проверка выявляет пропущенные зависимости в EQU, арифметике и таблицах DW. Для HIGH8 повторить на двух разных страницах с инструкцией, загружающей только старший байт. Включить новые входы и результаты в штатный build_cache. ## Выбор интервала и момент публикации

1. После imageOpen хранить исходные смещения отдельно от вычисленных адресов. Общий внутренний шаг получает target и требования, возвращает base, фактические load/entry и границы. Поля v_imageHeader, v_tmpFileDescr и аргументы существующих проверок сегодня местами читаются напрямую. Перевести проверки размещения на единое фактическое описание. Отдельно учитывать размер резерва и проверяемый запас minHeap.
2. В MAIN сначала проверить прежний адрес для совпавшего vacant REUSABLE. Затем искать сверху вниз, чтобы оставить непрерывное пространство под рост приложения. Верхнюю границу брать из системного ограничения MAIN с учётом резидентных блоков. Каждый кандидат выровнять вниз, при конфликте перескочить ниже начала препятствия. Просматривать таблицы модулей и аллокаций, статические образы, буферы владельцев и требуемую кучу активного родителя. Опубликованный memTop может отражать уже занятый интервал и сам по себе не описывает все свободные промежутки. Выделить чистую проверку из moduleMainClaimStrict. Его нынешний успешный путь может освобождать ресурсы.
3. В DOS переиспользовать обход препятствий arenaProbe. Сначала искать без вытеснения и предпочитать место вне действующего окна BAT (нынешний probe допускает использование окна). Если свободного места нет, искать с учётом разрешённых политикой освобождений. В обеих картах проба только сообщает препятствие. Окончательный claim выбранного интервала один раз выполняет разрешённые освобождения. PRESERVE сохраняет живые записи, MANAGED может вытеснить разрешённый неактивный кэш, EXCLUSIVE в MAIN сохраняет действующую семантику запроса всей MAIN. Проверять место в реестрах до вытеснения. Фиксированные и перемещаемые модули должны видеть занятость друг друга.
4. Удерживать резерв на всё время чтения и поправок. Читать тело существующим imageLoad в нужную страницу с прежним быстрым путём полных секторов. Читать таблицу небольшими порциями через сохранённый FAT-курсор; для MAIN/EXEC использовать банковый транспорт либо исполнять ограниченную обработку в целевой странице. Предусмотреть слово, пересекающее страницу или границу порции. Не обращаться из DOS напрямую по числовому MAIN-адресу. Таблица не занимает резидентную память модуля.
5. Только после проверки обеих сумм и всех записей разрешить холодный MODULE_ACTIVATE, затем опубликовать handle/ready. При ошибке чтения, поправки или активации снять временные записи, восстановить kdPage, флаги FAR/суммы, владельца и файловый контекст. Частично исправленное тело под приватным резервом можно отбросить. Vacant, затронутый записью, инвалидировать даже при отказе. При REUSABLE попадание допустимо только при прежних фактических базе и диапазоне, действительном ключе тома и сохранных байтах. Тогда выполнить тёплый ACTIVATE без повторного прибавления. При иной базе или отказе тёплой активации перечитать исходное тело. Для Reset во время подготовки проверить уборку неопубликованных резервов.

## Последовательность внедрения

| Этап | Работы и условие перехода |
|---|---|
| 1. Контейнер и MAIN | Две небольшие тестовые DLL с внутренними CALL/JP/DW, изменяемыми данными, внешним системным вызовом и BSS. Принудительно занять предпочтительное место, загрузить обе, чередовать вызовы, проверить независимость данных и освобождение в обратном и прямом порядке. Покрыть холодный и повторный REUSABLE. Пилот не требует свободного EXEC. |
| 2. Прикладные потребители | До перевода UI_GFX разделить внутренние адреса и обмен с клиентом. Сейчас GFX_BASE=1B00h, GFX_RESULT=3360h, GFX_PACKET=3380h, NC регистрирует пакет, а GFX_BIND передаёт ёмкость. Передать адрес клиентского пакета и согласовать место результата через BIND/ответ, обновить NC, EDIT и остальных потребителей одного ABI. Проверить абсолютные ссылки и полученные указатели после unload. Аналогично инвентаризировать редакторские оверлеи и страницы шрифтов. |
| 3. DOS DLL и кэш служб | Сначала перенести обычную DOS DLL через mdDos и проверить RETAIN/Reset. Затем подключить ту же внутреннюю загрузку к overlayEnsure, записать фактические base/entry/end в дескрипторы ENUM/FILEOPS и перевести все фасады на косвенный вызов с сохранением входных регистров на 8080. Сохранить проверку таблиц host по фактической базе и закрепление курсора ENUM/транзакции FILEOPS. Проверить одновременный обход и копирование из BAT. |
| 4. Перемещаемый установщик | Подключить keDriver к тому же размещению и исправлению. diStart/diEnd и проверка указателей DRIVER_INSTALL должны относиться к новому телу; границы инициализированных полей проверять именно по загруженным байтам. Снять привязку build-driver.py к концу арены для переведённых компонентов. У flash/ROM служба H: копируется в локальные слоты банков по LOCAL_DRIVER_ADDR (F9C0h в текущей карте), DOS_DRIVER_IMAGE хранит подготовленный образ. Исправлять ссылки установщика на источник, сохраняя адреса исполнения отдельно скомпонованной службы и контракт копирования в банки. |
| 5. Перемещаемая служба дискеты | У FLOPPY.COM служба внутри DISP 9D00h. Выделить её самостоятельное описание внутри контейнера установщика с собственными размером, входом и таблицей от начала службы. Резервировать второе место с учётом активного установщика и прежней службы. Копировать и исправлять по базе службы ровно один раз. Обновить DRIVER_INSTALL, diPrepareFloppy, учёт интервала в arena.inc, публикацию/сброс реестра и прямой CALL в kernelFloppyIO. Сначала полностью подготовить замену, затем переключить запись диска и освободить прежнее место. Если второго участка нет, вернуть ошибку с рабочей старой службой. |
| 6. BANK и страницы | Общую поправку можно применять в выбранном EXEC-банке после установки профиля. Сохранить правило целого банка и проверку стека. HIGH8 внедрять для конкретного шрифтового модуля после проверки инструментов и всех выражений HIGH/LOW. Смена базы и перемещение между банками имеют разные контракты. |

## Приёмка и стоимость

* Расширить check-image-memory/stream и moduletest. Проверить обрезанную таблицу, неверную сумму, последнюю валидную WORD16, выход на один байт за конец, перекрытие, переполнение при выборе базы, полную таблицу владельцев, фрагментацию и отсутствие выровненного интервала при достаточной сумме свободных байтов. После отказа сверить соседние данные, число живых записей и возможность следующей успешной загрузки.
* В Emu80 проверить настоящий ввод из NC, запуск из вложенного BAT и продолжение с правильного байта, занятый курсор/службу, Replace/Reset/RETAIN, повторную установку FLOPPY при нехватке места и обмен сектором до и после замены. Для H: проверить чтение, запись и flush с установленной службой. Для фиксированных приложений и носителей использовать имеющиеся проверки загрузки. Пересобрать SDK, образы и потребителей изменённого ABI, обновить карты в README и api.md по символам.
* Для этапа MAIN проверить NC_MN.COM и EDIT_MN.COM с одним банком ДОЗУ. Для банковых NC/EDIT отдельно проверить транспорт, вызов графической DLL и исчерпание банков. Зафиксировать размеры ядра и промежутки в System.layout.json/листингах, стоимость таблицы (2 байта на запись), пиковый scratch, потерю от выравнивания, время холодной загрузки и тёплого повторного вызова для MAIN и EXEC раздельно. Внутренний CALL после поправки сохраняет код операции и число тактов; у бывших прямых вызовов из системного фасада появится стоимость косвенного перехода. Измерить её отдельно.

Исторический ориентир — переданное описание Beeper: установка исправляет адреса внутренних меток один раз. В MXOS2 размер шага определяет конкретный образ. Для WORD16 допустимо побайтовое размещение, для HIGH8 нужна страница 256 байт. Приведённая страница Altair DOS при проверке вернула HTTP 404. [Указанное руководство Altair DOS](https://orion.01.gg/docs/orion128-soft-cpm80-altair-dos-01_clean.html)
