# RAM-драйверы: причина замедления и варианты через аккумулятор

31.10.2026. Отдельное исследование после [ramd-001](../ramd-001/RESULTS.md). **Модель Emu80, CPU и CLK1=2 МГц; аппаратных измерений нет.** Штатные исходники, настройки сборки, bin/ и images/ этим опытом не менялись. Опытные DOS загружались только в RAM изолированной машины Emu80-flash-test; после опытов восстановлены исходный DOS и обычный NC.

## Результат

Буферный обмен через развёрнутый аккумуляторный код быстрее предыдущего стекового варианта и прежнего прямого цикла. Обычный буферный цикл медленнее. Ещё один контрольный вариант — развёртка прежнего прямого обмена без буфера — оказался самым быстрым на чтении, но немного уступил буферному на записи.

| Вариант | Чтение, такты | Запись, такты | Чтение, КиБ/с | Запись, КиБ/с | DOS, байт | Хвост, байт |
|---|---:|---:|---:|---:|---:|---:|
| Прежний прямой цикл | 16981 | 18236 | 29.124 | 27.103 | 5946 | 0 |
| Буфер 18, POP/PUSH | 20584 | 20548 | 24.066 | 24.094 | 6341 | 159 |

Такты — полный вызов C863h без 27 тактов внешней обвязки CALL/JMP. Скорость — ВИ53, медиана трёх повторов последовательного режима, по 32 сектора на повтор. Измерительный интервал дополнительно включает 198 тактов на операцию, как в DISKBEN. RND также выполнен; все повторы, скорости и отличия PIT от номинала находятся в [measurements.json](measurements.json). Это короткая проверка прототипов, а не повтор всей серии 1024 чтений из ramd-001. Два прежних варианта дали в точности прежние номинальные такты полного вызова.

## Почему стековый проиграл

Сам POP/PUSH эффективен. POP BC/DE/HL = 30 тактов, PUSH HL/DE/BC = 33. Передача шести байт одним проходом занимает 63 такта. В секторе 42 такие группы и остаток 4 байта. Один проход: `42×63 + 2×10 + 2×11 = 2688` тактов; два прохода через буфер — **5376**.

На чтение полный вызов занял 20584, то есть оставшиеся **15208** тактов ушли на обслуживание: обёртку DOS, выбор страниц, пересчёт и сохранение указателей, настройку SP, изменение общего переходника и переходы между шестибайтными группами. На запись — 15172 такта обслуживания. Это расходы каждой секторной операции. Однократная установка копий драйвера в эти числа не входит; проверочного чтения после установки в MXOS нет.

Вывод ramd-001 относится к конкретной сложной реализации со стеком. Он не доказывает, что буферизация сама по себе медленнее.

## Обычный аккумуляторный цикл

Один проход стандартного цикла:

```asm
    ld a,(hl)       ; 7 тактов
    ld (de),a       ; 7
    inc hl          ; 5
    inc de          ; 5
    dec b           ; 5
    jp nz,copy      ; 10, независимо от результата условия на 8080
```

39 тактов на байт, два прохода — 78, или 19968 на полезный сектор ещё до обслуживания порций. Это больше 65/70 тактов старого прямого цикла. Полный рабочий прототип дал 26860/26504 такта. Простое удаление стека здесь не помогает.

## Развёрнутый буферный вариант

[unrolled.inc](unrolled.inc): буфер FFC3h–FFCFh, 13 байт. 19 полных порций по 13 байт, последняя — 9. DE указывает на источник, HL — на назначение, B считает порции, C хранит страницу и направление. Указатели остаются в регистрах весь сектор; изменения SP и переходника нет. Для записи DE/HL обмениваются при входе. Пока основной банк выключен, исполняется хвостовой код, CALL/PUSH/POP не используются.

Развёртка адресует каждый байт общего буфера непосредственно:

```asm
    ld a,(de)               ; 7 тактов
    ld (ramdBuffer+index),a  ; 13
    inc de                  ; 5
    ; Во второй фазе:
    ld a,(ramdBuffer+index)  ; 13
    ld (hl),a               ; 7
    inc hl                  ; 5
```

Два прохода стоят 50 тактов/байт, или 12800 на сектор. Остальное в полном вызове — 3451 такт на чтении и 3127 на записи. По сравнению со стековым вариантом копирование само по себе дороже, но обслуживание намного дешевле. Код хвоста занимает 174 байта и укладывается в FF00h–FFAFh; NC остаётся по FFB0h. На сектор приходится 40 смен банка и 20 повторных включений основной RAM, всего 60 записей маппера.

Проверка формул независимо от показаний ВИ53:

- Чтение: `353 + 27 + 19×804 + 595 = 16251`.
- Запись: `328 + 48 + 19×788 + 579 = 15927`.

353/328 — обёртка DOS с проверкой аргументов; 27/48 — вход нового драйвера; 804/788 — полная порция; 595/579 — последняя порция с возвратом. По отношению к прежнему прямому драйверу номинальная скорость полного вызова выше примерно на 4,5% на чтении и 14,5% на записи.

## Прямой развёрнутый вариант

[direct.inc](direct.inc) сохраняет 512 переключений на сектор, но разворачивает прежние циклы по семь байт. Первая порция — четыре байта, затем 36×7. Данные проходят напрямую между банками через регистры, промежуточного буфера нет. Чтение требует 55 тактов/байт плюс 37 проверок цикла на сектор; запись — 60. Полный вызов: 14823/16078 тактов. Хвост — 169 байт.

Таким образом, количество переключений банка не является достаточной мерой скорости: этот вариант имеет больше переключений, но меньше другой работы. Он приведён отдельно от реализации буферного обмена.

## Проверка и воспроизведение

[build.py](build.py) собирает пять DOS в `.codex-tmp/ramd-002/`, сохраняя общие ABI, проверки аргументов и фиксированные точки. Подменяется только внутренний буферный драйвер; установщик взят из существующего кода. Все пять сборок SjASMPlus `--i8080` прошли без ошибок и предупреждений. Пересечения ORG_PAD нет.

```powershell
python -X utf8 docs/diskbench/ramd-002/build.py
# Запустить отдельный Emu80-flash-test с MCP 19781 и обычным ROM-профилем.
python -X utf8 docs/diskbench/ramd-002/measure.py
python -X utf8 docs/diskbench/ramd-002/report.py
```

`measure.py` проверяет путь процесса слушателя перед изменением RAM. Проверены страницы 0/1/15, сектор FEh, невыровненный буфер 4001h и крайний допустимый FE00h, все 256 байт данных, A/BC/DE/HL/SP и CF, неизменность хвостовых копий во всех 16 страницах, сохранность boot/FAT/корня до и после каждой серии. Каждая запись DISKBEN дополнительно проверена чтением. Оба направления, последовательный и псевдослучайный доступ измерены через ВИ53. Показания сопоставлены с номинальными CPU-тактами; время хоста не используется.

Три новых варианта не переключают SP. Сервисный побайтовый драйвер, формат диска и карта памяти сохранены. Прототипы требуют того же резерва FF00h–FFAFh, что и Buffered, и не предназначены для страниц обычного приложения, которому обещаны все байты до FFBFh. Flash не программировалась. Исходная штатная сборка восстановлена в эмуляторе. Это результаты отдельных прототипов; параметры штатного сборщика сохранены.
