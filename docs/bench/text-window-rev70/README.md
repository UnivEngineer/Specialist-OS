# Банковая печать через 32-байтное окно, MEM rev70

Банк читает ASCIIZ один раз в прямом порядке. `MEM_TEXT_FILL` загружает байт из HL, записывает его в общее окно FFC0h–FFDFh и проверяет на NUL. После 32 байт либо терминатора MEM знает длину готовой порции. При ненулевой длине происходит один переход в MAIN и обратно. MAIN передаёт шрифту HL=FFC0h и точное число печатных байтов в BC. Возвращаемый клиенту HL указывает на исходный NUL. [Отправитель](../../../source/mem/text.inc) · [Переход и возврат](../../../source/bios/mem-mapped.inc) · [Выбор обработчика](../../../source/bios/bankText.inc)

| Печатных байтов в ASCIIZ | BC при последовательных вызовах штатного движка | Переходов в MAIN |
| -----------------------: | ---------------------------------------------- | ---------------: |
|                        0 | —                                              |                0 |
|                       31 | 31                                             |                1 |
|                       32 | 32                                             |                1 |
|                       33 | 32, 1                                          |                2 |
|                       64 | 32, 32                                         |                2 |
|                       65 | 32, 32, 1                                      |                3 |

Для Z применяется `printStringLim` штатного шрифта по D830h. Он обрабатывает управляющие коды и состояние ESC между порциями. При RAW_Z MEM передаёт ту же точную длину существующему `printStringRawLim` по D80Fh. При RAW_LIM длину задаёт клиент, включая нулевые коды глифов. Предварительный strlen, запуск полного CPM32 для переноса из окна и копирование строки на стек исключены из строкового пути. Слово по D81Eh объявляет поддержку нового входа. Для прежнего FNT1 или перехваченного ASCIIZ-вектора MEM печатает полную порцию как 31+1 на одном посещении MAIN, используя FFDFh для временного NUL. [Контракт движка](../../../source/font/README.md)

Работающий MEM использует все 32 байта под данные. FFDEh и FFDFh свободны от постоянных меток. Для короткого остатка CPM32 последний байт временно хранит счётчик. При печати движок владеет окном до возврата. Пачка команд, допускающая вложенные банковые обращения, сохраняет свой список на локальном стеке MAIN. Загрузчик и аварийное восстановление могут разместить переходник в окне перед установкой рабочих копий MEM. [Протоколы MEM](../../../source/mem/transport.md)

## Такты Intel 8080

Emu80 с физическим маппером MMX, 2 МГц, скрытое окно, фиксированное ускорение 32×. Измерен весь интервал от CALL до следующей команды клиента. Шрифт — штатный 6×8 Rotate. Для каждого входа взят соответствующий прямой вектор BIOS в MAIN, одинаковые позиция курсора, видеопамять и байты строки. Длина в таблице исключает завершающий NUL у Z и RAW_Z. Результаты F806h совпали у банков DOS и EXEC.

В объединённой сборке BIOS заканчивается перед D7D6h, до шрифтового слота D800h остаётся 42 байта. Сегмент IO в MAIN занимает 416 байт, банковый — 380 байт. Версии BIOS 6.1, DOS 3.1, внутренний ABI MEM rev70. Штатная полная сборка прошла для MMX Flash + floppy, MX ROM + floppy и RAMFOS. Для каждой из трёх сборок выполнено по 80 проверок TEXT в Emu80. Результаты обеих сборок rev70 совпали по тактам и регистрам во всех 80 случаях. [Журнал build-all](build-all.log) · [Проверенный объединённый MMX-образ](C-Flash-512k-MMX-System-Emu80.bin)

В стенде 8080 проверены 850 случаев на 17 шрифтовых движках. Посимвольный вывод служил эталоном для всей видеопамяти, курсора, состояния ESC и режимов KOI. Входы с длиной проверены на BC=0, границах блоков и страниц, регистрах, стеке и чтениях с последнего байта окна. Отдельная трасса MEM проверила единственное чтение каждого байта исходной ASCIIZ по порядку и адрес начала каждой порции в движке, включая совместимые старые векторы. Проверены вложенные пачки с перезаписью всего окна. [Результат по движкам](font-engines.log) · [Тест шрифта](../../../scripts/tests/check-font-text-lim.py) · [Тест транспорта](../../../scripts/tests/check-mem-inline-nested.py)

На изолированной rev70 выполнен 91 вызов копировщика на физическом маппере Emu80, включая 27 чтений ROM. В десяти замерах горячая итерация CPM32 заняла 1022 такта. При тёплом Reset загрузчик восстановил повреждённые участки двух хвостов DATA и сохранил сектор B:. Для обновления на rev70 использованы реальные снимки банков DOS и DATA из загруженных образов rev68 и rev69. Новый образ распознал прежний диск B: по восьми байтам CPM32 из FF0Eh–FF15h. В обоих прогонах 65 024 байта первого банка B: ниже FE00h совпали после bootstrap, а ещё 512 контрольных байт сверены после запуска NC.
