# Четверки без кеша, 08.11.2026

Добавлены quadDynamicRender и quadHalfRender в самостоятельный FONTBEN, штатный BIOS-рендер не менялся. Старые BIOS, полная таблица 12 КБ и cold/warm кеш сохранены. Каждый режим измеряется в main и из страницы DOS тем же циклом, по четыре кода на вызов. 1200 отфильтрованных байт README, 89 различных кодов, 48×25, без прокрутки.

## Сборка трех экранных байтов

Пусть a,b,c,d — четыре шестибитных строки шрифта. Экранные байты равны `(a<<2)|(b>>4)`, `((b<<4)&F0h)|(c>>2)`, `((c<<6)&C0h)|d`. На 8080 b поворачивается через RRCA четыре раза один раз; обе части сохраненного результата извлекаются AND 03h и AND F0h. Для c аналогично: два RRCA, затем AND 0Fh и AND C0h. Два ADD A сдвигают a влево на два. Части, вышедшие через границу байта, используются в соседнем байте; повторного сдвига для них нет. d используется без сдвига.

Повороты используются повторно в пределах строки и не записываются в промежуточную битмапу. DE — экран, B/C — временные части строки; POP HL получает четыре исходных указателя из восьмибайтной рабочей области. После чтения строк указатели обновляются. На время четверки SP указывает эту область, а не настоящий стек; до восстановления SP отсутствуют CALL/PUSH/RET. Источники шрифта только читаются. По четыре строки развёрнуты, всего две итерации. Каждый из трех экранных байтов записывается целиком один раз, восемь строк дают 24 записи, ни одного чтения видеопамяти. Маски выделяют части глифов, а не сохраняют экранный фон.

Dynamic не запрашивает BIOS-кеш, не читает/пишет его арену, не имеет lookup/FIFO/защиты/промахов и работает при нулевом доступном кеше. Half использует одну заранее построенную таблицу ROR8(glyphByte,4) объёмом 2048 байт, по восемь на все 256 кодов. Из неё берется b; четыре RRCA на строку исключаются, обе части по-прежнему используются повторно. Таблица неизменна во время измерения и находится в первых 2048 байтах предоставленной BIOS арены. Lookup и теги не нужны, адрес — base+code×8. quadPrepareHalf получает границы Query, проверяет восемь байт выравнивания/размер 2048 и строит таблицу вне таймера. Предыдущий кеш помечается недействительным; сам Query/построение не входят в результат, как генерация полной таблицы при сборке. Рендер без подготовленной таблицы возвращает CF=1 до записи. Потребление памяти — 0 или 2048 дополнительных байт битмап против 4096 у ограниченного кеша, существующий исходный шрифт общий.

Общий контракт: HL — текст, C=0..48 кратно четырем, X кратен восьми пикселям, вся строка помещается на экране, baselineY>=7. A/BC/DE/HL сохранены, CF=0 успех/1 отказ; остальные флаги разрушены. Нулевая длина допустима. Хвосты, инверсия, интерпретация управляющих кодов и прокрутка отсутствуют, как у прежнего сырого входа. Фильтрация README выполнена до таймера. Генераторы нормализованы под FONT.FNT 256×8, не читают MXFN непосредственно.

## Результаты Emu80

Один интеграционный прогон, ВИ53 CLK1=2 МГц, квант 0,128 мс. Копирование/обмен кодами, вычисление указателей, цикл, таймер, переключение страниц включены. Очистка экрана, загрузка/фильтрация текста и подготовка постоянных таблиц исключены. Это эмуляторные измерения, физическое оборудование не проверялось. Все числа ниже получены одной и той же конечной сборкой; добавление выбора новых режимов слегка изменило общую обвязку четверок относительно quad-opt-001.

|---|---:|---:|

| Полная таблица посимвольно | 504,448 | 705,792 |

На этом корпусе отсутствие кеша замедляет вывод относительно warm на 6,01% в main / 5,21% в DOS; одна таблица ROR4 — на 3,37% / 2,92%. Заранее сохранённый поворот экономит 14,464 мс на экран в обоих случаях. Сложность кеша даёт небольшой выигрыш относительно этих новых режимов; полная таблица заметно быстрее всех. Разница включает разные стратегии доступа к глифам: кеш/полная таблица пишут целые столбцы с двумя удерживаемыми источниками, динамический режим переиспользует повороты внутри строки и обновляет четыре указателя. Это сравнение целых реализаций, не изолированная цена RRCA против lookup и не доказательство оптимальности бескешевого кода. Число промахов кеша осталось cold/warm 193/185, 168 слотов.

## Проверки

OS собрана без ошибок и предупреждений SjASMPlus --i8080. Главный блок до 1F2Bh, ниже 2000h; рендер 2000h–2108h; общий блок четверок 526 байт с 2200h, новые ядра/подготовка 708 байт с 240Eh, общий конец 26D2h ниже шрифта 2800h. Конец файла прежний 6000h, размер 24 КБ; размещение шрифта/полной таблицы и банкового образа не менялось.

z88dk-ticks -m8080: 1096 случаев четверок и 1046 скалярных. Новые проверки охватывают все 256 кодов в обоих режимах, непустой фон, границы/пакеты из нескольких четверок, отказ для хвостов и плохих координат, сохранение регистров/возврат со штатным SP, неизменность источников и кеш-арены во время рендера, отсутствие зависимости от ёмкости кеша. Построение всей таблицы ROR4 проверено отдельно через реальную службу Query IO.SYS, а также отказы при отсутствующей таблице/нулевой и малой арене. Машинный код новых ядер допускает только чтение глифов через HL, POP HL указателей и экранные записи STAX D; LDAX D отсутствует. Пиксельные записи, управляющая обвязка SP и результат проверены независимо.

Собственный видимый Emu80 без звука: FONTBEN.COM набран обычными клавишами в нижней строке NC (command.png), каждый экран сравнен по всем 9216 байтам с BIOS, Bitmap PASS. Все 2048 байт таблицы ROR4 прочитаны обратно и совпали с эталоном. Резерв DOS 2048 байт и общее окно 32 байта восстановлены; возврат в NC подтвержден returned.png, экземпляр закрыт. Сводка results.png; JSON содержит времена, промахи, статус восстановления и SHA-256 бинарников/образа. Предыдущие отчёты сохранены отдельно.
