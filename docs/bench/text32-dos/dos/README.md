# DOS — строки и двоичные дескрипторы через окно MEM

Измерялся участок передачи пути или дескриптора с проверкой диапазона. Диспетчер системных вызовов, разбор имён, работа FAT и обращения к носителю за пределами замера. До изменения брались машинные инструкции из исходного DOS rev68. Для `OPEN_PATH` и общего пути `kdPath` (CHDIR и другие операции) измеряется путь от подготовки параметров переноса до входа в дальнейшую обработку. В точках входа в дальнейшую обработку стенд подставляет `RET`. Текущее чтение измерено от `kdFetchPath` до возврата. Замер фиксированных структур охватывает `kdFetch` и `kdStore` целиком. Одинаковая заглушка прибавляет 130 тактов, которые вычтены для обеих версий.

Тестовый код исполняется в `z88dk-ticks -m8080` с исходными образами DOS и MEM. Стенд задаёт код вызывающей страницы MAIN или EXEC, но использует плоскую память. Время включает инструкции переключения, а состояние физических страниц отдельно проверяется в Emu80.

Для `B:/DATA.BIN` (12 байт с нулём) `OPEN_PATH` выполняет один перенос строки с двумя записями маппера. Раньше выполнялось 12 однобайтовых переносов. Другие входы прекращают чтение на терминаторе, поэтому размер строки определяет число обращений к окну. Строка длиной 128 байт использует четыре порции и сохраняет близкие к прежнему сплошному переносу затраты.

Два полных блока выгоднее передать развёрткой CPM32. Для 64-байтного `FILE_HANDLE` и больших объектов остаётся этот маршрут. Новый выбор маршрута добавляет 80 тактов. Нулевые байты внутри двоичных объектов передаются наравне с остальными. Проверена точная длина и сохранение BC.

## Проверки

Полная проверка файлового API прошла на изолированном образе BIOS 6.1/DOS 3.1 в скрытом Emu80 32×, MCP 19781. В MAIN пройдены длины 1, 31, 32, 33, 64, 65, 127 и 128 байт с контрольными байтами в хвосте DOS-буфера, терминатор в FBFFh, отклонение неполной строки и пересечения FC00h, FILE_EXEC до CR, сохранение FH_BUFFER после OPEN_PATH и неперезаписанный хвост GETCWD. Из загруженного EXEC-профиля проверены терминатор в F7FFh, отказ на F800h и FFFFh, границы порций, возврат в исходную страницу с сохранённым стеком и результаты HL/DE/BC у FILE_NAME_PREPARE. Прошли также чтение, запись, EOF, вложенные пути, COPY и обёртки файлового ввода-вывода. [Сценарий проверки](../../../../scripts/emu80/check-unified-file-api.py) · [Журнал Emu80](emu80.log)
