# Фиксированный KOI-7R 6×8

Основной профиль KOI-7R в MXOS — `FONT 6x8/K7Rotate`. Также доступны `FONT 6x8/K7Packed` и `FONT 6x8/K7Hybrid`. У всех постоянная нижняя резервация равна нулю. Семь младших битов входного байта индексируют латинские знаки и кириллицу KOI-7R. Управляющий режим проверяет исходный код до преобразования индекса. Для `7Fh` хранится пустой глиф, инверсия даёт фон инверсного знакоместа. Вызов переключения кодировки сохраняет фиксированный режим. Вход псевдографики рисует восьмистрочное тело.

Rotate хранит один набор `y/y+4` в половинах страницы и разворачивает все восемь строк столбца, включая перепривязку между половинами. Packed хранит три совмещённые фазы и разворачивает по четыре строки между сменами половин. Код позиционирования и установки помещается в хвосте после таблиц. Hybrid вычисляет внешние фазы поворотами, а для среднего столбца объединяет две раздельные полуплоскости через `OR`. У этой пары в одной 256-байтной странице лежат обе фазы одной пиксельной строки.

K7Fast занимает шесть КиБ данных. Три пары фаз уложены в страницы с двумя половинами по 128 кодов. Тег бита 7 присваивается второму и четвёртому коду четвёрки до отрисовки. Средняя пара фаз хранит половины наоборот, поэтому тег используется повторно. Скалярное ядро выбирает готовые фазы по X. Этот вариант собран отдельно для модели 8080 и верхних адресов legacy. В текущем слоте MXOS размер таблиц уже превышает всю ёмкость слота.

## Что измерялось

- В Emu80 MX2 на 2 МГц сравнивались старые движки в режиме KOI-7R и три фиксированных движка. Один корпус на 924 байта приведён к семибитному набору перед замером. Контрольные CR/LF сохранены. На 108 этапах совпали пиксели и курсор, включая MAIN и три банковых маршрута для строк.
- В модели 8080 прошли 512 сравнений по трём строковым API, полному набору семибитных кодов, алиасам старшего бита, правому краю и инверсии. Полный KOI-7 Fast прошёл 924 байта RawLim за 281 551 такт против 276 609 у KOI-8 Fast в режиме KOI-7R. Прибавка 1,8%.
- Переключение действующего KOI-8 в KOI-7R измерялось по `setEncoding` в модели 8080. Установка фиксированного движка с A: измерялась отдельно от точки входа FONT до `committed` в Emu80. Поле счётчика откалибровано на NOP. Замеры показывают примерно 9/27/55 мс для переключения и 0,50–0,62 с для установки.
- Выполнены сборочные пробы восьмистрочного Rotate. У KOI-8 с вырезанным переключателем код заканчивается на E553h, за границей E400h на 339 байт. У штатного K7Rotate с полной развёрткой код доходит до E2CBh и оставляет 309 байт перед таблицей.

## Встраиваемые секции

Для оценки собраны те же пиксельные ядра с тонкими адаптерами по D000h в Мониторе‑2 и D300h в проектном RAMFOS-MXOS. Учитываются код, таблицы и межстраничное выравнивание. У Монитора сохраняется XOR при отрисовке, у RAMFOS используется запись поверх знакоместа. Старые адреса вызываются для управления, DEL и перевода строки. Проверены 96 сочетаний пикселей и курсора в модели 8080.

Матрица размеров показывает секцию нового движка целиком. Итоговый размер полностью заменённого ядра зависит от того, какие исторические ветви вывода и таблицы остаются для пользовательского знакогенератора, ESC и DEL. Эталонный Монитор‑2 по-прежнему имеет 4096 байт и собственный знакогенератор на 768 байт. Проектный RAMFOS-MXOS имеет 6880 байт и знакогенератор на 1536 байт. В нём пробы помещаются до F800h. Полный исторический RAMFOS занимает 16 352 байта, для него нужна отдельная перекомпоновка. [Сборочная разметка и размеры](legacy-size.json)

## Воспроизведение

В локальной рабочей копии соберите OS, `SystemEmuWritable`, `SystemHardware 512` и `Games2M`. Выполните `seed-flash.ps1`. Затем используйте [проверку CPU](check-cpu.py), [встраиваемые пробы](legacy-size.py), [проверку развёртки](unroll.py) и [прогоны Emu80](check.py). Результат объединяет [сборщик отчёта](merge.py).
