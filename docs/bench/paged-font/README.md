# Построчная адресация шрифта

CPU-модель Intel 8080, 2 МГц. Полный FONT.FNT, 256 глифов, одинаковые 1152 байта README, 48×24. Подготовка данных исключена. Сравниваются прежние standalone-ядра из текущего FONTCOM и отдельные экспериментальные ядра paged.inc; это не замер BIOS API или реального компьютера.

| Ядро | Линейные глифы, мс | Строки по страницам, мс |
|---|---:|---:|
| 6×8: вращения | 493,526 | 335,462 |
| 6×8: пререндер | 300,998 | 170,438 |
| 8×8 | 244,262 | 151,214 |

Прежние точки входа включают собственную проверку координат и обновление курсора; новые принимают проверенный адрес VRAM. Поэтому разница включает упрощение пакетного пути, а не только замену умножения адреса на INC H. Полный фронтенд BIOS, API-переходы и компактный MXFN сюда не входят.

После оптимизации циклов новые ядра занимают суммарно 833 байта; шрифт 2048 байт, пререндер 10240 байт. Столбцы 6×8 пишутся тремя проходами, каждый через два указателя на глифы. Для вращений временная часть байта хранится в операнде OR; для пререндера используется непосредственное OR (HL). Экран не читается. Рабочие данные и код изменяемые, вход нерекурсивный, аппаратные прерывания должны быть выключены.

Девять сопоставлений полных экранов: новый README и все 256 кодов для трёх ядер, старый README для трёх ядер. Сохранены AF/BC/DE/HL/SP новых ядер, BC/DE/HL/SP старых, исходные таблицы. Сборка --i8080: ошибок и предупреждений нет. Ядра ещё не подключены в COM-матрицу и BIOS.


## Встраивание

Построчные ядра включены в FONTBEN и BIOS. Системный FONT.FNT транспонируется bootstrap в E300h–EAFFh. BIOS — 8625 байт, включая оба одиночных пути, переключение KOI и управление пререндером. BIOS_UPPER_VARIABLES расширен до 272 байт и начинается с EE90h; стек/буфер сдвинуты на 16 байт вниз. Нижние 33 байта сохраняют исторические смещения Монитора-2; это не проверка совместимости всего исторического ПО.

CPU 8080, полный штатный шрифт: printChar 777,250 мс, пакетные четверки с вращениями 430,011 мс, с пререндером 267,723 мс. Прямой строковый фронтенд на печатном корпусе не ускоряет длинную строку: он нужен для игнорирования управляющих байтов без изменения ESC-состояния. Отдельный ABI bios_printStringReal=C8EDh не проходит общий диспетчер, MXCALL-варианты 0131h/0132h сохранены.

Emu80, ВИ53 2 МГц, полный публичный API с позиционированием: 459,392 / 297,088 мс (final-emulator/results.json). Битмапы обоих путей совпали, загрузка NC и инверсный диалог F7 проверены. Подготовка пререндера исключена. Все тестовые экземпляры видимые, без звука и закрыты. Это эмулятор, не физический компьютер.

FONTBEN -E=PAGED -Q: 18 MAIN/BANK этапов, Bitmap PASS, запись/чтение/усечение B:\FONTBEN.TXT, возврат NC, выгрузка модулей без утечек. Прямой MAIN-пакет: вращения 360,448 мс, пререндер 198,272 мс, 8x8 185,472 мс. BANK-Serial по-прежнему включает побайтовую передачу в main; Far48/Far1152 измеряют явный перенос. Системные -K пути проверяются отдельно, включая новый прямой фронтенд из банка. Тесты standalone-кеша перенесены в свободную нижнюю область, поскольку прежний адрес DB90h теперь занят BIOS; рабочий кеш стенда использует временные 2 КБ 7E00h–85FFh.

Удалены неактивные reboot1.inc/reboot2.inc/initFont.inc и псевдоним printString1.inc. Коллекция исторических standalone-ядер намеренно сохранена для сравнения. В DEBUG два вызова посимвольного printStringB заменены одним пакетом имени 8.3: восемь проверок изображения во всех фазах, сохранения DE/AF, продвижения HL на 11 байт и неизменности входа прошли. Файлы NC принадлежат отдельному агенту; его изменения не включаются в оценку этой работы.

Финальная очистка удалила также неиспользуемый 13-байтный v_char для старого ПЗУ-рендера и внутренний псевдоним fontResolve. Итоговые CPU-проверки: BIOS 228, Monitor/Opt 5376, кеш 1046, четверки 2569, 8x8 536, 4x8 1597, фильтры 358, диспетчер 130 случаев. Отчёт -K: 16 MAIN/BANK этапов, Bitmap/файл/возврат/выгрузка PASS. После удаления неиспользуемых данных проверены финальная сборка, фиксированный C8EDh и карта памяти; вывод в Emu80 относится к предшествующей эквивалентной реализации рендера.


Таблица CPU-модели обновлена после оптимизации циклов 10.11; прежние результаты сохранены в results-before-loop-opt.json. Старый раздел ВИ53 выше описывает исторический запуск до оптимизации. Свежие полные вызовы ABI/API и сравнение до/после — в [engine-grid](../engine-grid/README.md).


Циклы вращений и пререндера разделены: выбор производится при инициализации DLL, а не на каждой четвёрке или пакете. Дополнительное разделение обновило CPU-времена в таблице выше; оба ядра сохраняют прежний внешний контракт.
