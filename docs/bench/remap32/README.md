# Построчный FONTBEN с восьмибайтной перекодировкой блоков

2026-11-10. FontMap.com сохраняет построчный полный шрифт и ядра PageRaw/PagePre прежнего FontBen.com. Отличается только чтение четвёрки: каждый код перекодируется через таблицу из восьми байтов. Изображения шрифта и пяти плоскостей при смене KOI не переставляются. Постоянный код BIOS этим экспериментом не изменён; временная подмена входов нужна только для замера самостоятельных ядер.

Три RLC, затем AND 07h дают исходные старшие три бита. По ним читается старшая часть нового кода; младшие пять бит берутся из исходного кода. Чтение таблицы встроено в заполнение четырёх кодов, без дополнительного прохода по временному буферу. В варианте identity KOI-8 никакой обход таблицы не включён: замер намеренно включает перекодировку каждого символа. KOI-7 проверен CPU-тестом заменой записи 3 с 60h на E0h; фильтрация управляющих кодов и старших диапазонов полного BIOS здесь не тестируется.

## Потоковый прогон через штатные BIOS API

2026-11-10. В обоих вариантах одинаковый исходный корпус README без замены A3h: 1152 печатных байта + 24 CRLF + NUL, всего 1201 байт. Шаг строк 10 пикселей; SETCURSORPOS внутри интервала нет. MAIN вызывает PRINTSTRING_MAIN один раз на весь поток. BANK Win256 — один PRINTSTRING_BANK из исполняемого банка, с текущим штатным буфером до 256 байт; прежнее имя Win20 было устаревшим. BANK Far48 — 24 memcpy_far по 50 байт (48 символов + CRLF), локальный NUL и 24 PRINTSTRING_MAIN. BANK Far1152 — один memcpy_far 1201 байта и один PRINTSTRING_MAIN. Названия Far48/Far1152 отражают число печатных символов.

Standalone временно подключён к старым JMP-входам BIOS и таблице MXCALL. Сырые ядра сохранены; общий ASCIIZ-фронтенд выделяет печатные пакеты до 48 байт. Полные четвёрки 6×8 идут выбранному движку, невыровненные края порций — исходному посимвольному BIOS. CRLF всегда обрабатывает BIOS. После каждого этапа и при ошибке загрузки исходные адреса восстанавливаются. Вызовы MODULECALL и дочерний FbMain.dll удалены. Для CHAR каждый байт, включая CRLF, выводится через MXCALL PRINTCHAR; PRINTCHARREAL получает только печатные байты в своей отдельной строке теста.

Таймер ВИ53 настраивается и читается локально. Один полный вывод должен укладываться в период 8,388608 с. Подготовка, очистка, построение фаз, загрузка/возврат BANK COM, проверка битмапы и инфострока исключены; перенос данных, диспетчер API и отрисовка включены. Это замер внутри Emu80 при 2 МГц, не физического оборудования.

У новой методики добавились общий ASCIIZ-фронтенд и CRLF, поэтому изменение MAIN-времени само по себе не означает замедления пиксельного ядра. CPU-замеры неизменённых сырых ядер остались прежними.

## Предыдущий прогон с построчной установкой курсора

Emu80, CPU и ВИ53 2 МГц, 1152 символа README, 48×24. Оба COM запущены клавиатурой через NC в собственном видимом экземпляре без звука и штатно вернулись в NC. По 12 этапов; Bitmap PASS; модули выгружены, утечек выделений нет, резерв DOS сохранён. Экземпляры закрыты. Подготовка шрифта и пререндера исключена из интервала вывода.

Для сопоставимости с предыдущим FontBlk-тестом код A3h в корпусе обоих сравнительных прогонов заменён пробелом через --block32-corpus. Корпуса совпадают побайтно. Это ограничение только сравнения: сам FontMap сохраняет все 256 глифов, включая Ёё. Проверка CPU отдельно прогоняет все коды без такой замены.

## Подготовка пререндера

Новый генератор BIOS занимает 115 байт вместо 117. Пять проходов сохранены, но последние две плоскости строятся из уже готовых первых двух. Такая же зависимость введена в универсальный подготовительный код построчных вариантов FONTBEN.

| Результат | Источник | Операции |
|---|---|---|
| b<<2 | Шрифт | Два ADD A,A |
| b>>2 | Шрифт | Два RRC, AND 0Fh |
| b<<6 | Шрифт | Два RRC, AND C0h |
| b>>4 | Готовый b>>2 | Два RRC, AND 03h |
| b<<4 | Готовый b<<2 | Два ADD A,A |

Это по две операции сдвига/вращения в каждом из пяти проходов, вместо прежних 2+2+2+4+4. Объединение нескольких результатов в одном проходе потенциально позволяет разделять вращения между результатами, но потребует другой организации указателей и записей; глобальный минимум всех возможных генераторов этим тестом не установлен. В универсальном генераторе стенда остаются NOP-заполнители и маска FFh в патчируемом шаблоне; их время не входит в измерение рендера.

Полный FONTRENDER BUILD в модели 8080 теперь 237,438 мс при 2 МГц; новый замер его подготовки по ВИ53 отдельно не проводился. Прежние 262,016 мс были эмуляторным замером предыдущей версии. Проверены все 64 допустимых значения шестибитной строки, все пять плоскостей, штатные процедуры подготовки всех трёх сборок FONTBEN и 12 952 проверки BIOS-рендера. Сборка ОС и системного образа, layout и SDK ABI проходят без ошибок.
