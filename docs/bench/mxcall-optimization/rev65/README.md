# Проверки MEM rev65 на физическом маппере Emu80

[Итоговые размеры, такты BIOS и CPM32](RESULTS.md)

До сборок сохранён rev64 с MEM SHA-256 606CF80FB3ECE5F656DFC5A9A8D312C57AFA0157282D6B8577FE15340764FB45 и системным образом 9D1B8508D793319EDEB74A8C0CF7B7B80374AD20CC5B4AE398A3C004C979758B. Снимок включает BIOS/DOS/MEM/IO, весь banked, NC/CLI, карту компоновки, прежние замеры и список хешей. [Манифест](rev64-bin/manifest.json)

Стенд использует отдельный MCP-слот 19781, скрытый ключ -Hidden с Qt offscreen и фиксированные 32×, подтвердившиеся через sys_info. Временный runtime и его копии образов отделены от штатных. Загрузка выполняет настоящий bootstrap до входа biosBootExec. Для теста ABI в EXEC размещаются те же сегменты, что устанавливает загрузчик, DATA использует штатный хвост, ROM читается через маппер. Сценарий клавиатуры запускается отдельно и использует штатную загрузку обоих вариантов NC.

На rev64 прошли 704 сценария матрицы FAR/ROM/MOVE с MAIN, DOS, EXEC и DATA. Основная серия проверяет чистые числа порций 32 байта, точные остатки, несколько смещений, короткие и нулевые запросы, ошибки банка/диапазона, исходные регистры и SP, содержимое и защитные байты. Для FAR измерены начальный COMMAND и повторный профиль. Отдельно сняты 96 сценариев MOVE между владельцами MAIN/DOS/EXEC. [Основная серия](before/result.json) [Удалённый MOVE](before-remote-move/result.json)

Штатная клавиатурная загрузка rev64 прошла с резидентного NC из EXEC в CLI и запуском NC_MN из MAIN. Команда сверена в буфере перед Enter, вход MAIN и образ NC проверены на останове. [Клавиатура](before-user/result.json)

Первый кандидат C343194D… не дошёл до входа NC EXEC. В штатной загрузке mdInstallPart передал FC00h → FC00h, 03C0h байт, DOS → банк 6. Перед последней порцией при DE=FFA0h счётчик был 0102h. После записи порции до DE=FFC0h он стал 011Eh, поскольку перекрытый хвост назначения получил параметры из DOS. Следующая порция дошла до DE=FFE0h и затёрла общее окно. Следом CPU наблюдался на FFC9h. Снимок сделан с остановами на штатном коде, без подмены гостевой памяти. [След](nc-trace-candidate-1/events.json)

На втором кандидате BF0A785B… с сокращённым копированием префикса установка NC в EXEC и нормальный переход EXEC → CLI → NC MAIN прошли. Клавиатурный сценарий сверил команду C:/DOS/NC_MN.COM, штатный Enter и код MAIN на странице 0. [Прогон candidate-2](candidate2-user/result.json)

На candidate-2 прошли 99 сценариев выделенных CALL BIOS, включая HEX. Проверены MAIN/DOS/EXEC, COMMAND/COPY, выключенная и включённая очередь. Включённая очередь вошла в один callback, который видел позицию курсора до вызываемой операции. В трёх дополнительных сценариях callback печатал N, а исходный вызов с сохранённым C печатал Q. Содержимое VRAM и курсор совпали с двумя историческими CALL C809h, AF/BC/DE/HL/SP и весь образ окна совпали с ожидаемыми. [Регистры и время](candidate2-bios/result.json)

В 96 опытах удалённого MOVE между MAIN/DOS/EXEC кратные 32 ускорились во всех 32 ненулевых случаях. Для 56 случаев с остатком 48 быстрее и 8 медленнее. Перекрытие со сдвигом +1 и длиной 257 байт MAIN → EXEC заняло 15703 → 11203 такта, EXEC → MAIN 15703 → 8557. [Парные результаты](remote-move-comparison.json)

Полная матрица candidate-2 прошла 704/704. Для FAR все 168 ненулевых случаев кратных 32 ускорились на 1879–1930 тактов при COMMAND и на 1102–1153 тактов при повторе. Из 189 хвостов COMMAND быстрее все, из 189 хвостов повтора быстрее 161, наибольшее замедление 130 тактов. Из 18 случаев ROM все быстрее на 1922 такта при COMMAND и 1145 тактов при повторе. В парное сравнение скоростей не входят 66 запросов MOVE в DATA, для которых публичный результат поменялся на E7h. [Полный прогон](candidate2-copy/result.json) [Сравнение](candidate2-copy-comparison.json)

Исторические восемь операций F806 измерены на замороженном rev64 отдельно для MAIN и EXEC, с теми же AF/BC/DE/HL, позицией курсора и памятью, что у выделенных входов. [Исторические измерения F806](before-legacy/result.json)

На финальном образе 864D1030…1273047 все восемь снятых операций вернули CF=1 и A=0Ah через F800h и F806h из MAIN и EXEC. Все 32 вызова сохранили пакет, VRAM, курсор, верхнюю границу памяти, страницу, стек и управление владельцем банка. [Отказы по операциям](final-legacy/result.json) [Хеши финальной сборки](latest-bin/manifest.json)

Проверены CPM32, номера страниц и диапазоны, FAR и MODE MOVE с перекрытиями, граница длины 32 и 8192 байта. [Банковый транспорт](final-transport/result.json)

На образе 864D1030… основная матрица повторена полностью, 704/704. Все 168 случаев FAR из полных порций и 18 чтений ROM стали быстрее. Перекрытие со сдвигом +1 на 257 байт MAIN → EXEC заняло 15703 → 11274 такта, EXEC → MAIN 15703 → 8611. На CBCBECF4…062302 повторно прошёл штатный 16-банковый клавиатурный маршрут NC EXEC → CLI → NC MAIN, затем оба редактора с чтением файла и возвратом по F10. [16 банков](final2-user/result.json)

Для профиля исходного MX все 16 значений селектора ДОЗУ адресуют один физический объект RAM, который занимает DOS. В тестовой копии CBCBECF4…062302 изменены только 169 байт AUTOEXEC, чтобы убрать запуск RAMDISK на четырёх банках и запустить NC_MN. BIOS и DOS определили один банк, свободных EXEC нет. Клавиатурная команда запустила EDIT_MN из NC_MN на странице 0, нажатие X добавило один байт к исходному документу, F10 и отказ от сохранения вернули NC_MN.
