# Транспорт CPM32 с общим прямым циклом

Три обязательные замены одноимённых файлов в `source/mem/` — `copy-resident.inc`, `copytail.inc`, `copy.inc`. `copy-prepare.inc` сохраняет установку пар выбора, счётчика и SP инициатора. Полное окно дважды вызывает `moveTransportBlock32`; остаток 1..31 дважды вызывает `moveTransportForward`. Все вызовы выполняются на приватном стеке. Ядро и этот стек должны быть доступны по одним адресам в DATA и в верхней области MAIN, видимой при выборе ROM. В области FFC0h–FFDFh находятся пары установки или данные.

| Адреса   | Байты | Назначение                         |
| -------- | ----: | ---------------------------------- |
| FE87–FECC |    70 | Установка параметров и остаток    |
| FED0–FEFF |    48 | Вход и обработчик COMMAND          |
| FF00–FF03 |     4 | Защитная сигнатура                 |
| FF04–FF44 |    65 | Полное окно и возврат к инициатору |
| FF45–FF4C |     8 | Локальные пары и счётчик           |
| FF4D–FF52 |     6 | Приватный стек                     |
| FF53–FFBE |   108 | Место для части общего ядра        |
| FFBF      |     1 | Признак профиля EXEC               |

Опциональные `remote-move-prepare.inc` и `remote-move.inc` добавляют вызов `moveCoreCount` в другом DATA-банке с произвольным перекрытием. Первая часть выполняется в полном профиле после проверки диапазонов и сохранения регистров `bankCopyEnter`. Вторая часть занимает 23 байта в DATA. Суммарная глубина стека для `moveCoreCount` до вершины этого стека — шесть байт. Диапазоны пользователя должны лежать ниже `MEM_DATA_START`.

Плоский тест использует штатную матрицу `scripts/tests/check-cpm32.py`. Для такого теста ядро временно собрано с адресом E000h, а транспорт и LOCALBLOCK используют адреса из собственных файлов символов. Физические мапперы и укладку общего ядра нужно проверять на собранном системном образе.

## Проверка с маппером

Команда из корня репозитория: `python docs/bench/mxcall-optimization/unified-move32/transport/check-banked.py`. Она собирает тестовые файлы в каталоге исследования. Эталон — штатные `bin/banked/TRANSPORT.bin`, `LOCALBLOCK.bin` и `CLIENT.bin`. Для прототипа ядро тестово установлено по E000h в каждом банке. В режиме ROM адреса 8000h–FFBFh принадлежат MAIN. Только FFC0h–FFDFh содержит общую память. Выбор страниц выполняет сам машинный код через FFFCh, FFFDh и FFFEh.

На вариант прошли 1695 кейсов. Матрица покрывает 0–65 байт, 255–257, 1024 и 8192 байта, три выравнивания и восемь сочетаний инициатора, источника и приёмника, включая ROM 0/15. Проверены данные, соседние байты, сохранность источника, исходная страница, регистры и SP, последовательность переключений и данные в окне. Выборка команд по адресам окна запрещена проверкой. Публичный нулевой запрос не меняет окно и банк. Для ROM и совпавших страниц источника и приёмника транспорт вызван через доверенный вход.

| Байты | Штатный CPM32, такты | Общий цикл, такты | Разница |
| ----: | -------------------: | ----------------: | ------: |
|    31 |                 4863 |              4511 |    −352 |
|    32 |                 3457 |              4062 |    +605 |
|    33 |                 3876 |              4573 |    +697 |
|   256 |                10251 |             15091 |   +4840 |
|  1024 |                35080 |             54440 |  +19360 |

Таблица относится к публичному входу с инициатором MAIN, источником DATA 2 и приёмником DATA 4 с нечётными смещениями. Такты посчитаны от входа в процедуру до возврата, без команды CALL инициатора. В плоском z88dk-ticks разницы для 31, 32, 33, 256 и 8192 байт совпали с моделью до такта. Полные результаты сохранены в `banked-result.json`.

## Контейнер с ядром в резидентном хвосте

Команда из корня репозитория: `python docs/bench/mxcall-optimization/unified-move32/transport/check-layout.py docs/bench/mxcall-optimization/unified-move32/layout/out`. Тест читает `MEM.sys`, `TRANSPORT.sym` и `LOCALBLOCK.sym`. MAIN получает только свою часть LOCAL, DOS и EXEC — полные сегменты, каждый DATA — только транспорт FE00h–FFBFh. За пределами установленных сегментов модель оставляет байт команды HLT. Проверяется сохранность хвоста DATA за исключением параметров CPM32, приватного стека и изменяемых операндов ядра.

В окончательной укладке вход в удалённый банк передаёт HL, DE, BC в регистрах и переносит пару возврата через SP. Восемь байт приватного стека расположены с FF4Dh. Совпадение страниц сохраняет содержимое окна, а перенос внутри удалённого банка выбирает ровно две страницы. Прошли 711 проверок, включая публичный F80F, совместимый MOVE, перекрытие локальных и удалённых диапазонов в обе стороны, окно 0–65 байт, длины до 8193 байт, физическое копирование ROM и исключающую границу FE00h. Для допустимых диапазонов проверены фактические данные, соседние байты, регистры и страница возврата. Выборка команд из аппаратного окна запрещена. Результаты всех замеров и SHA-256 контейнеров находятся в `layout-result.json`.
