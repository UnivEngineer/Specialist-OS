# Общий прямой цикл moveCore и CPM32

Исследовательский вариант rev66 собран отдельно от рабочей rev65. Общий машинный код занимает 221 байт во всех банках. Его прямая развёртка из 16 пар занимает 80 байт. CPM32 выполняет два прохода на каждую полную порцию, сначала 32 байта из источника в окно, затем из окна в назначение. Для каждого прохода CPM32 вызывает по FE7Fh подпрограмму, которая устанавливает счётчики и SP и передаёт управление развёртке FF61h. Для остатка FE4Fh переносит один нечётный байт при необходимости и по числу оставшихся пар вычисляет вход в ту же развёртку. Полный локальный перенос с выбором направления входит по FE16h. Обвязка и обратный цикл занимают 115 байт, горячая часть с управлением SP и счётчиками занимает 106 байт. Контейнер содержит 30 байт заголовка, 1600 байт LOCALBLOCK, 448 байт CLIENT, 960 байт TRANSPORT и 32 байта физически общего окна. В MAIN устанавливаются первые 1280 байт LOCALBLOCK. В DOS и EXEC ставится весь сегмент. Полный адресный резерв F1C0h–FFBFh занимает 3584 байта и включает слот драйвера H:. В DATA нижняя граница передвинута с FE87h на FE00h. Байт детектора ДОЗУ перенесён с FFBEh на FF4Dh в стек транспорта, а проверка свежести RAM-диска использует восемь байт COMMAND по FED0h, совпадающие с rev65. Сектора FEh и FFh уже зарезервированы FORMAT, поэтому ёмкость тома B: в целых секторах сохранилась. В исследовательском F80F верхняя исключающая граница ненулевого публичного диапазона составляет FE00h. Доверенный физический вход доступен загрузчику и драйверам. [Размеры и границы BIOS/DOS](layout/out/System.layout.json) · [Контейнер MEM](layout/out/MEM.sys)

Из BIOS/DOS убрано старое тело переноса в 301 байт. В BIOS сохранены точка Монитора C42Dh и автономный движок размером 62 байта для STD, восстановления и прямого чтения отображённого ROM/flash. Активация быстрого near после установки MEM и возврат к автономному пути перед STD требуют ещё 48 байт с вызовами. В MEM освобождена прежняя 111-байтная реализация EXEC. Перестановка внутренних служб освободила FE00h для общего ядра и резидентного входа DATA. Слот H: сохранил 576 байт. [Парная линковка и переключение BIOS](bios/README.md)

## Такты 8080

От первого байта точки входа до возврата с RET включительно. В левом столбце прямой C42Dh в основной памяти, в остальных инициатор MAIN и два разных DATA-банка. F80F включает разбор и проверку пакета. Физический вход принимает уже проверенный запрос. Пары чисел соответствуют rev65 и rev66. [Калибровка C42Dh](bios/switch-result.json) · [Модель банков и сырые замеры](transport/layout-result.json)

| Байты | C42Dh, MAIN, вперёд | F80Fh, DATA → DATA | Физический вход, DATA → DATA |
| ----: | ------------------: | -----------------: | ---------------------------: |
|    31 |        1171 → 1016  |       4873 → 4011  |                 4373 → 3541  |
|    32 |        1051 → 1041  |       3467 → 4072  |                 2967 → 3602  |
|    33 |        1080 → 1065  |       3886 → 4969  |                 3386 → 4499  |
|   256 |        5020 → 4986  |     10261 → 15241  |                9761 → 14771  |
|  1024 |      18862 → 18498  |     35090 → 55070  |               34590 → 54600  |

В rev65 запись пары в окно занимает 26 тактов (POP H и SHLD), чтение из окна и запись в назначение — 27 (LHLD и PUSH H). Общее ядро rev66 читает пару через POP D и записывает через HL двумя MOV с двумя INX. Это 34 такта в каждом направлении. За 16 пар на обеих сторонах окна передача данных занимает 848 → 1088 тактов (+240). На повторяющемся полном окне ещё 385 тактов добавили вызовы и подготовка указателей, стека и внутренних счётчиков (74 → 459). Два выбора банка занимают суммарно 70 тактов, внешний счётчик при обычном повторе — 30. Трассировка 256-байтного F80F от входа в bankCopyTail до следующего входа даёт 1022 → 1647 тактов, то есть +625 на окно. Весь запрос F80F занимает 10261 → 15241 такт. На физическом переносе 1024 байт получено +20010 тактов, около 10 мс при 2 МГц.

Обратное копирование в локальной странице использует короткий парный цикл. Прямой вызов C42Dh на 256 байтах с перекрытием и сдвигом назначения на один байт вверх занял 5202 → 10139 тактов. Выбор направления в этой реализации зависит от порядка начальных адресов. При большем адресе назначения выполняется обратная ветвь, включая непересекающиеся диапазоны. Чтение отображённого ROM/flash через низкий BIOS и STD также платит за компактный автономный цикл. [Разбор BIOS и контроль перекрытия](bios/README.md)

## MOVE

F80F обеспечивает семантику memmove при совпадении страниц. В текущей странице MEM вызывает локальное ядро. Для переноса целиком внутри другой страницы HL, DE и BC пересекают маппер с источником, назначением и длиной. На время выбора целевой страницы SP переносит пару для возврата в исходный банк. Целевая страница сохраняет её в своём хвосте и устанавливает собственный восьмибайтный стек транспорта. Весь обмен с общим окном в этом пути отсутствует. После штатного сброса очереди содержимое и профиль окна сохраняются. Для двух разных страниц остаётся CPM32. Опытный F815h/A=0 оставлен совместимым входом к тому же пути, отдельный режим MOVE больше не требуется. Остальные операции F815h сохраняют свои входы. ## Проверка и воспроизведение

SjASMPlus в режиме 8080 собрал четыре сегмента MEM. Парная сборка BIOS/DOS, полная цель OS, упаковка SystemEmuWritable и сборка комплектов исходного MX (ROM 32/48 КиБ) выполнены в отдельной рабочей копии. На модели банков прошло 711 проверок, включая перекрытие в обе стороны, отсутствие записи в окно и ровно два выбора страницы для удалённого локального переноса. Для самого ядра проведено 1592 трассировочных случая и 82 независимых проверки z88dk-ticks.

На MX2 с фиксированным ускорением 32× в Emu80 проверены холодный запуск NC EXEC, тёплый Reset, вызов NC MAIN из CLI с клавиатуры и 126 переносов через установленные F80F/F815. Для 25 сценариев сравнивалось всё содержимое окна. F80F на 256 байтах между DATA занял 15258 тактов вместе с CALL инициатора, то есть 15241 такт от входа, как в модели. При переходе с подставленного хвоста DATA rev65 загрузчик перезагрузил несовместимую DOS, сохранил признак существующего RAM-диска и все 256 байт контрольного сектора B:. [Системная проверка](emu/README.md)

Для повторной сборки нужна отдельная копия исходной rev65. Наложить изменения из каталога bios в порядке, указанном в его README. После исходной парной сборки выполнить из каталога исходной rev65 команду `python docs/bench/mxcall-optimization/unified-move32/layout/build.py --checkout <путь-к-копии>`. Она переносит новую раскладку и подставляет адреса общего ядра в импорты BIOS/DOS. В выбранной копии выполнить `scripts/build/build-project.ps1 OS` и `scripts/images/build-image.ps1 SystemEmuWritable`. Для проверки собранного контейнера передать каталог с MEM.sys, TRANSPORT.sym и LOCALBLOCK.sym в `transport/check-layout.py`.
