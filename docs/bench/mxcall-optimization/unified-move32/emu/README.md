# Системная проверка Emu80

`check-hidden.py` проверяет готовый экспериментальный C-flash из локального checkout. Скрипт требует SHA-256 образа. Он копирует ранее проверенный runtime в отдельный каталог слота 19781, сверяет хеши Emu80 и Qt offscreen, запускает через штатный `run.ps1 -Hidden -Flash -Mcp` и проверяет PID слушателя, отсутствие видимого окна, режим 32× без full throttle и заглушённый звук. В конце закрывает только собственный процесс.

Переносы выполняются через установленные при загрузке F80Fh и F815h. Для CPM32 проверяются байты и активный банк, возвращаемые регистры, SP, неизменность пакета и сторожевых байтов. Для DATA→DATA счётчики точек останова на общей прямой развёртке и остатке проверяют фактическое прохождение обеих половин. Запросы к последнему допустимому байту и блоку проверяют исключающую границу FE00h. Отклонённые запросы должны вернуть E2h, сохранить содержимое назначения и не входить в цикл копирования.

Холодный старт идёт с включения процесса, затем выполняется тёплый Reset. В гостевой клавиатуре NC EXEC набирается `C:`, выполняется Enter, затем F10 открывает CLI. Команда `C:/DOS/NC_MN.COM` вводится в CLI и запускает профиль NC MAIN. Снимки получены через MCP `screen` из offscreen runtime.

Такты в `result.json` включают внешний CALL и банковый транспорт. Служебные вмешательства стенда находятся за границами измерения. Проверка относится к модели Emu80.

Промежуточный образ с SHA-256 `1b97cce092c118cf8587672dfd7b3a96dbed469e1afaae81980547252c75e45b` прошёл загрузку и клавиатурный сценарий, 120 вызовов F80Fh/F815h, включая 6 ожидаемых отказов E2h. Полные данные сохранены в `control-1b97cce0.json`.

На C-flash с SHA-256 `a22ba91012a13ee4cbfcfe20033ef915f6d6dd31ca84724f60330bccfc45dfb0` холодная загрузка дошла до NC EXEC в странице 6. Тёплый Reset подтвердил ревизию 66, одинаковый код с FE00h в MAIN, DOS и DATA и переход BIOS C107h → FE16h. Клавиатурный переход в CLI и запуск NC MAIN завершились успешно. Предыдущий образ `800bb051…` сохранён в отчёте `control-800bb051.json`.

Для миграции в первый банк B: подставлен точный DATA-хвост FE87h–FFBFh из сборки rev65. Перед Reset проверено, что сигнатура FED0h совпадает, а прежний код FF04h отличается. DOS получила ревизию 65, загрузочный сектор B: — контрольный образец. При Reset bootstrap загрузил DOS rev66 и установил новый DATA-хвост, сохранив `BOOT_RAM_FRESH=0`. После загрузки NC EXEC все 256 байт контрольного сектора совпали. Миграция выполнена на оперативной памяти отдельного экземпляра.

Из 126 проверок F80Fh/F815h шесть подтвердили ожидаемый отказ E2h, 25 подтвердили сохранение всех 32 байтов окна. Для перекрывающегося MOVE в удалённом DATA проверены оба направления из MAIN, DOS и EXEC. Собственный процесс завершён, порт 19781 свободен.
