# Перенос копировщика BIOS и DOS

Измерение сделано парным сборщиком `python scripts/build/build-bios-dos.py` в изолированной копии рабочего состояния MEM rev65. Обе сборки завершились с нулём ошибок и предупреждений SjASMPlus 1.24.0. Концы диапазонов исключающие.

|-----------------------------------|------------------:|------------------:|--------:|
| BIOS.sys, байт                    |              6138 |              5899 |    −239 |
| BIOS.sys, диапазон                |       C000h–D7FAh |       C000h–D70Bh |    −EFh |
| Блок копирования BIOS, байт       |               301 |                62 |    −239 |
| Блок копирования BIOS, диапазон   |       CE23h–CF50h |       C1DAh–C218h |         |

C42Dh и обёртка BIOS INPUT C8BAh сохранили адреса. Прямой вход ROM/AT512KS перемещается с CF4Ah на C206h. Парный сборщик генерирует его новый импорт. 62-байтный цикл BIOS работает на текущей карте и пользуется обычным стеком. Старт BIOS, recovery, замена FFC0h и RUN STD не зависят от наличия полного MEM. Банковая DOS использует внешний moveCore по E00Eh и moveBytesForward по E05Bh. Обе метки проверены реальной сборкой компактного `../core.inc` по E000h–E11Ch. В MAIN область E000h относится к модулю шрифта. В этой сборке E000h зарезервирован условно только для эксперимента с DOS.

CPU-проверка через z88dk-ticks `-m8080` прошла для 60 вызовов исходного BIOS, 60 вызовов компактного BIOS и 59 вызовов изменённой DOS с ядром в E000h. Проверены байты назначения, HL/BC, сохранение DE у near-входа, возврат PC/SP, пустой случай, перекрытие, совпадение адресов и исключающий конец 10000h. Прямое копирование 256 байт стоило 5012 тактов в BASE BIOS, 12456 в компактном BIOS и 4905 при вызове внешнего движка DOS. В каждое значение включён одинаковый тестовый код. Эти числа описывают плоскую CPU-модель без аппаратного отображения ROM, flash и страниц MX.

Сборка измеряет размеры после уплотнения. Загрузчик и восстановление образа MEM по E000h не изменялись, системный образ, Reset, STD и физические драйверы не запускались. Компактный цикл уменьшает BIOS, но замедляет его near-копирование и верхний ROM-путь. Штатная установка должна выбрать, где сохранить быстрый прямой путь.

## Воспроизведение

В отдельной копии того же rev65 выполнить `python scripts/build/build-bios-dos.py`, сохранить `bin/BIOS.sys`, `bin/DOS.sys`, `bin/System.layout.json`, `bin/System.linked.sym` и `bin/banked/KERNEL.sym` в `baseline-measure/`. Применить `git apply <путь-к-experiment.patch>` и повторить команду сборки. Для проверки подготовить `external-test.asm` с `ORG 0E000h` и `INCLUDE "<путь-к-core.inc>"`, собрать `./tasm/sjasmplus.exe --i8080 -DMOVE_COMPACT_BACK=1 --raw=external-test.bin --sym=external-test.sym external-test.asm` и запустить `python <путь-к-verify-bios-experiment.py>` из той же копии. В скрипте указаны пути к z88dk-ticks и каталогу результата этой машины.

## MAIN через общее ядро MEM rev66

Повторная парная сборка с переключаемым JMP дала 5947 байт BIOS.sys (−191 к BASE, +48 к варианту с автономным BIOS), C000h–D73Bh. DOS.sys остался 29714 байт, IO — 431. Участок BIOS C107h–C170h состоит из 3 байт JMP, 40 байт переключения и проверки версии и 62 байт автономного цикла. Ещё 5 байт добавились в вызовах установки и восстановления. Связанный RUN также собран без ошибок и предупреждений. Адреса и реальные опкоды приведены в [листинге](switch-listing.txt).

C42Dh сохраняет исторический ABI. По умолчанию JMP C107h указывает на автономный цикл C132h. После bootstrap или программного восстановления sysInstall сравнивает слово по F658h с ревизией 66. При совпадении JMP указывает на FE16h, где лежит вход того же ядра, которое вызывают DOS и перенос MEM. DOS использует FE16h/FE47h, взятые из TRANSPORT.sym реальной экспериментальной сборки. Проверка ревизии определяет совместимость образа. Перед восстановлением BIOS сбрасывает JMP и копирует шлюз отдельным вызовом C132h. RUN STD сбрасывает JMP до переключения карты. При выходе RUN восстановление MX повторно проверяет установленный MEM. Стороннему переключателю STD, который продолжает использовать этот BIOS, нужен тот же сброс перед записью порта.

ROM512KS и AT512KS сохраняют прямой автономный цикл по C15Eh. Он нужен независимо от того, установлен ли полный MEM и отображает ли ROM-драйвер верхнее окно. Для ускорения этого пути потребуется проверка карты конкретного профиля и отдельное переключение прямого входа. Патч не меняет bootstrap или содержимое экспериментального MEM. Для настоящей загрузки BIOS/DOS/RUN и rev66 MEM должны быть упакованы вместе.

Такты рассчитаны от входа C42Dh до возврата включительно. В каждом случае стенд повторял вызов с заменой только первого байта C42Dh на RET. Контроль дал 139 тактов, из которых 10 приходится на RET. Из результата вычтены остальные 129 тактов, включая внешний CALL, настройку аргументов и сохранение результата. В переднем направлении стенд копировал 2800h → 2000h. Для заднего прохода использованы перекрывающиеся диапазоны 2000h → 2001h. На 256 байтах прямой путь MAIN занял на 34 такта меньше BASE, обратный занял на 4937 тактов (94,9 %) больше.

CPU-стенд z88dk-ticks проверил финальные BIOS и установленные по своим адресам сегменты MEM rev66 (LOCALBLOCK, CLIENT, TRANSPORT, WINDOW). Прошли 63 случая, включая исходный BIOS, холодный вход, отказ для ревизии 65, активированный rev66 и отключение перед STD. В последнем случае код от F000h заменён инструкциями HALT. Проверены перекрытие, перенос 32 байт из/в FFC0h и регистры near-ABI. Измерение сделано в плоской модели Intel 8080, запуск аппарата и Emu80 не выполнялся.

Для этой версии после `experiment.patch` применить [switch.patch](switch.patch) и повторить парную сборку. Входы MEM взяты из `../layout/out/TRANSPORT.sym`. Запустить `python <путь-к-verify-switch.py>` из той же копии с сохранённым BASE. Скрипт загружает сегменты MEM из `bin/banked` собранной OS, сверяет их байты и экспорт символов с `../layout/out`.
