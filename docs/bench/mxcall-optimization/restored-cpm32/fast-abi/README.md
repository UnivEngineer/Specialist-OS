# Проверка быстрых вызовов BIOS в rev68

Проверены восемь фиксированных входов из MAIN, DOS и EXEC, с незавершённой очередью и без неё, в профилях окна COMMAND и COPY. Результаты сравнивались с прямыми вызовами BIOS в MAIN. Сверены регистры, стек, контекст вызова, все 32 байта окна, экран и состояние курсора либо MEMTOP. В варианте с очередью тест также проверял один вызов обработчика и вложенное чтение курсора. Отдельно проверены три вложенных вызова печати, где обработчик очереди сам печатает.

Такты включают CALL тестового клиента. В столбцах профилей показаны пары «без очереди / с очередью». Для каждой пары результаты COMMAND и COPY совпали.

| Вход                  | Прямой MAIN | MAIN        | DOS         | EXEC        |
| --------------------- | ----------: | ----------: | ----------: | ----------: |
| `mx_printChar`        |        1010 | 1184 / 1555 | 1577 / 1974 | 1577 / 1974 |
| `mx_getCursorPos`     |          53 |   149 / 520 |   175 / 572 |   175 / 572 |
| `mx_setCursorPos`     |          69 |   149 / 520 |   175 / 572 |   175 / 572 |
| `mx_printCharRaw`     |         934 | 1108 / 1479 | 1501 / 1898 | 1501 / 1898 |
| `mx_printHexByte`     |        2610 | 2784 / 3155 | 3177 / 3574 | 3177 / 3574 |
| `mx_printHexWord`     |        5092 | 5266 / 5637 | 5659 / 6056 | 5659 / 6056 |
| `mx_getMemTop`        |          53 |   163 / 534 |   199 / 596 |   199 / 596 |
| `mx_setMemTop`        |          53 |   173 / 544 |   209 / 606 |   209 / 606 |

Набор `bios` прошёл 99 случаев. Вложенная печать заняла 2974 такта в MAIN и 3760 тактов в DOS и EXEC. Набор `legacy` прошёл 32 случая. Восемь снятых номеров проверены через пакетный и встроенный вызовы из MAIN и EXEC. Каждый вход вернул ошибку неподдерживаемой операции с сохранением пакета, экрана, курсора и MEMTOP.

Оба набора запускались в собственном скрытом Emu80 32× с выключенным звуком, без full throttle, на порту 19782. Образ `C-Flash-512k-MMX-System-Emu80.bin` имеет SHA-256 `8fe06d83ac003eedc21396d1747231d4b6d1600e88b83d3899df03dee118928d`. В приватной копии фиксированного тестового EXE заменён номер MCP-порта 19781 на 19782. Порт, PID, путь процесса, отсутствие видимого окна и скорость проверены перед прогонами. ## Аудит исходников ядра и драйверов

[Проверка](audit.py) просмотрела 193 файла ASM и INC. В BIOS 70, DOS 79, UI-GFX 4, IO 11, flash 18, floppy 2, RAM-диске 9. Совпадений со старыми восемью именами и номерами операций либо прямыми числовыми адресами заменивших их шлюзов нет. В DOS вывод символа и доступ к курсору и MEMTOP идут через символы фиксированных входов. RAM-диск печатает через `mx_printHexByte` и `mx_printChar`. Поддерживаемые групповые операции печати строк, десятичных чисел, клавиатуры, глифов и арифметики по-прежнему используют свои имена.

## Контроль FAR-копирования

Набор F80F прошёл 32 случая в том же образе. Восемь межбанковых сценариев проверили длины 31, 32, 33 и 256 байт из начальных профилей COMMAND и COPY. Остальные 24 проверили перекрытие на один байт в обе стороны для длины 1, 32 и 256 байт. DATA вызывался из MAIN, DOS и EXEC, удалённый MAIN вызывался из EXEC. Сравнивались полезные данные, граничные байты, регистры, контекст и профиль окна. При одной странице все 32 байта окна сохранились. [Сценарий](sample-f80f.py) · [Результаты](f80f-sample/result.json)

Повтор штатного набора `remote-move` на 19782 прошёл 168 случаев. На первом прогоне через 19783 после 51 успешного случая один вызов из EXEC в MAIN с длиной 1 байт и сдвигом +1 не дошёл до точки возврата. Изолированная трасса этого вызова, повтор 96 случаев для полных профилей с трассировкой этого вызова и полный повтор без трассировки прошли. Причина единичного расхождения не установлена. [Штатный повтор](remote-retry/result.json)

Архивная rev65 прошла 38 случаев контрольного сценария. В 18 MOVE по одной странице DATA возвращён исторический отказ E7h. Шесть неперекрывающихся переносов в одном DATA прошли через CPM32 и оставили профиль COPY. SHA-256 архивного образа `864d1030c68cbf0610e40ef33578cd95cd981ef468930d9d4fab6e8571273047`.
