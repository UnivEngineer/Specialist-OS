# Возврат CPM32 и проверка быстрого ABI, rev68

Между разными банками снова работают специализированные 8080-развёртки rev65. В первом проходе 16 пар POP/SHLD переносят 32 байта из источника в окно FFC0h–FFDFh. Во втором 16 пар LHLD/PUSH выгружают окно в назначение. При остатке от 1 до 31 байта копируется ровно указанная длина. Обе стороны маппера исполняют код своих резидентных хвостов. [Полный блок](../../../../source/mem/copytail.inc) · [Остаток](../../../../source/mem/copy-resident.inc)

При совпадении страниц F80Fh и F815h/A=0 по-прежнему поддерживают перекрытие. При обращении в удалённую страницу адреса и длина пересекают маппер в HL, DE и BC. Код для MAIN, DOS и EXEC разворачивает прямой проход до 32 байт. В DATA прямой цикл копирует четыре байта за итерацию. Его 62 байта и адрес входа устанавливаются при создании страницы DATA и при смене DATA/EXEC. Содержимое общего окна сохраняется при одностраничном MOVE после сброса очереди. [Прямой ход полного профиля](../../../../source/mem/local-forward.inc) · [Прямой ход DATA](../../../../source/mem/data-forward.inc)

## Такты

Инициатор — MAIN, источник и назначение межбанкового теста — два разных DATA. Для полного вызова отсчёт начинается на первой инструкции точки входа и заканчивается возвратом. Внешний CALL добавляет 17 тактов. Прямой вызов BIOS C42Dh показан для тех же длин и прямого направления внутри MAIN. Стоимость одного окна измерена между соседними входами в горячий цикл.

| Операция                                       | rev65 | rev66 | rev68 |
| ---------------------------------------------- | ----: | ----: | ----: |
| Горячий шаг CPM32, 32 байта                    |  1022 |  1647 |  1022 |
| F80Fh, 31 байт                                 |  4873 |  4011 |  4843 |
| F80Fh, 32 байта                                |  3467 |  4072 |  3437 |
| F80Fh, 256 байт                                | 10261 | 15241 | 10231 |
| F80Fh, 1024 байта                              | 35090 | 55070 | 35060 |
| Физический вход CPM32, 256 байт                |  9761 | 14771 |  9761 |
| Физический вход CPM32, 1024 байта              | 34590 | 54600 | 34590 |
| Прямой C42Dh из MAIN, 256 байт                 |  5020 |  4986 |  4976 |
| Прямой C42Dh из MAIN, 1024 байта               | 18862 | 18498 | 18488 |
| MOVE внутри удалённого DATA, 256 байт, сдвиг −1 |   E7h |  6217 |  7147 |

Все 54 физических межбанковых сценария совпали с rev65 до такта. Публичный F80Fh стал быстрее rev65 на 30 тактов в 45 сценариях, межбанковый MOVE — на 33 такта в 45 сценариях. Для одиночного хвоста из 31 байта rev66 быстрее rev68 на 832 такта. В Emu80 на четырёх маршрутах проверены память и SP посередине обеих развёрток. В каждом случае интервал между окнами составил 1022 такта. В модели прошли 632 сценария rev65, 669 сценариев rev66 и 669 сценариев rev68. [Матрица 8080](model/README.md) · [Замеры в Emu80](emu/README.md)

В Emu80 полный `CALL F80Fh` из MAIN между двумя разными DATA на 256 байт занял 10278 тактов у rev65 и 10248 у rev68. На 8192 байта получено 264030 и 264000 тактов. Для сравнения, прямой `CALL C42Dh` внутри MAIN на 256 байт занял 5037 и 4993 такта соответственно. Во всех этих значениях учтены внешний CALL и RET. | DOS.sys                                   | 30015 | 29714 | 29828 |          +114 |
| IO.sys                                    |   811 |   811 |   811 |             0 |

Код экранных обработчиков, который исполняется только после выбора MAIN, размещён в BIOS. Освободившееся место использует локальная развёртка MEM. В DOS входят шаблон прямого цикла DATA и код установки при загрузке и освобождении EXEC. Все 448 байт хвоста размещаются в FE00h–FFBFh внутри прежнего двухсекторного резерва. Для DOS FILL действует та же исключающая граница FE00h, что для F80Fh. Запрос, пересекающий границу, возвращает ошибку до первой записи.

## Сборка и программы

Rev68 перенесена в основное дерево. Штатная цель `scripts/build/build-all.ps1` собрала ОС, приложения, игровые цели и образы MMX Flash + floppy, MX ROM + floppy и RAMFOS. Monitor2.mon побайтно совпал с историческим эталоном. В скрытом Emu80 на фиксированных 32× проверены восемь BIOS-векторов из MAIN, DOS и EXEC, флаги, регистры, очередь, оба профиля окна и отказ по прежним номерам через F800h и F806h. Для каждой операции записана стоимость прямого BIOS-вызова из MAIN. [Таблица быстрых входов](fast-abi/README.md) · [Протокол полной сборки](build-all.log)

На готовом MX2 проверены NC и EDIT в обоих профилях, ввод и выход через CLI, холодный старт, тёплый Reset, сохранение 256 байт сектора B: при обновлении и установка DATA → EXEC → DATA настоящими MODULE_LOAD/UNLOAD. На исходном однобанковом MX отдельно проверены NC_MN, EDIT_MN и CLI. [Системная проверка и снимки](emu/README.md) · [Результаты MX](emu/original-mx-result.json)

Проверка SDK охватывает восемь адресов ABI и шесть переходников C, локальную кучу, F80Fh и MOVE с перекрытием и границей FE00h. Отдельно собраны девять модульных примеров. На финальном MX2 программа C FILEHANDLE проверила консоль, курсор, чтение и установку MEMTOP и файловый обмен с B:. Её тест клавиатурного API использует временные заглушки BIOS. Реальные события клавиатуры проверены в NC, EDIT и CLI. [Протокол SDK](model/README.md) · [Результат программы C](model/sdk-runtime-result.json)

В основном дереве прошли 47 наборов проверок CPU и сборки. Исторический стенд загрузки монолитной DOS с заголовком v1 сохранился для прежнего формата. Для текущих образов используется проверка RUN в банковой системе. При первом дополнительном прогоне удалённого MOVE из EXEC в MAIN один вызов не дошёл до контрольной точки. Тот же вызов прошёл с трассировкой, а затем весь набор из 168 вызовов прошёл без остановов. Причина первой остановки осталась неустановленной. [Системные тесты](system-tests/README.md) · [Повторная проверка MOVE](fast-abi/README.md)

В FontBench исправлены привязка экспериментальных шрифтов к сокращённой таблице BIOS и вывод отсутствующих глифов в PACKED. Пересобран диск H: с приложениями. Из NC прошли девять нативных запусков приложений в MAIN, DOS и EXEC, включая меню RUN и прямой FILE_EXEC. [Отдельный отчёт FontBench, 72 измерения](../../FontBen-rev68.md) · [FontBench и RUN](emu/README.md) · [Результат упаковки образов](build-all-fontbench.log)

При удержании ↓ без прокрутки получены медианы между готовыми кадрами со второго повторения. В MAIN у NC это 37,042 мс (27,00 строки/с), у EDIT 31,959 мс (31,29 строки/с). В EXEC с назначенными драйвером 12/2 тика получено 65,408 мс (15,29 строки/с) и 65,795 мс (15,20 строки/с) соответственно. У NC EXEC штатный повтор выставлен только в RAM теста, выпуск использует 8/1. В ожидании у NC счётчик F806h равен нулю.
