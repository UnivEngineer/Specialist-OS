# MAIN без свободного EXEC

Проверка выполнена на отдельной копии Emu80 в MCP-слоте 19784. Профиль сохраняет MAIN 36 КиБ, экран 12 КиБ и системную область C000h–FFFFh. Отключён MX2_MODELS, выбран SpecVideoRam с защёлкой curColorMx. Все 16 значений селектора RAM адресуют один физический объект ramDisk0, который занимает DOS. Профиль использует штатную модель MXOS и системную flash C:. Начальный вход Emu80 идёт сразу через MX ROM. [Конфигурация](specialist-mx2.conf) [Запуск](launch.conf)

В исходном образе MMX AUTOEXEC останавливается на RAMDISK -P 4 с ERROR 14. В тестовой копии release-образа MEM rev63 заменили только 169 байт AUTOEXEC по смещению 27136. Убрали создание B: и выбрали NC_MN.COM. Образы и исходники выпуска не менялись. [Штатный AUTOEXEC на одном банке](boot-prompt.png) [Тестовый AUTOEXEC](AUTOEXEC.BAT) [Хеши](image.json)

В видимом окне при фиксированных 32×, без звука и мониторинга ленты, BIOS определил один банк. bankPageCount=1 прочитан и в MAIN, и в DOS. NC_MN дошёл до mainLoop на странице 0. С клавиатуры введена команда `C:/DOS/EDIT_MN.COM C:/AUTOEXEC.BAT`; строка сверена побайтно в vars.cmdLine. EDIT_MN открыл файл на той же странице. Клавиша X увеличила документ со 169 до 170 байт, сохранив весь исходный текст после добавленного символа. F10 и Discard вернули в NC_MN на странице 0. [Ввод в EDIT_MN](edit-input.png) [Возврат в NC_MN](nc-return.png) [Результат](result.json)

Сценарий проверяет приложения в MAIN при отсутствии физического EXEC и использует флеш-диски модели MMX. Проверка начального входа через STD ROM и испытания на физическом MX в охват не входят.

## Отображение набранной строки

В том же однобанковом профиле повторены ревизия 2791c88 и итоговый MEM rev63. Перед Enter выдержано 350 мс после последней клавиши. Во всех четырёх кадрах (до ввода и после, на каждой ревизии) видно только приглашение. PNG побайтно одинаковы. При этом ввод изменяет 146 байт VRAM в каждой сборке, а дампы всей области 9000h–BFFFh для соответствующих состояний совпадают между сборками. Полный клавиатурный сценарий обеих ревизий прошёл. По этому сравнению различий от оптимизации MXCALL в отрисованном кадре и видеопамяти нет. Причина расхождения кадра и VRAM в этом профиле отдельно не локализована.
