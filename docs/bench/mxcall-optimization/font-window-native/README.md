# Эксперимент с ограниченным ASCIIZ в пакетном FNT1

Здесь описана опытная ветка D836h. Измерение полного вызова на Emu80 выявило замедление RAW_Z, и в рабочей сборке сохранён прежний ABI FNT1. [Исходный замер](../../text-stack32/baseline/result.json) · [Итоговый замер](../../text-stack32/final/result.json)

Слово `FONT_ENGINE_TEXT_EXT` по D81Eh равно D833h только в модулях с новым входом. D830h и D833h ведут в точную счётную печать. D836h потребляет до 32 байт из FFC0h–FFDFh и возвращает HL на терминатор или FFE0h. ASM-сборки Rotate, Packed6K, Fast12K, K7Rotate, K7Packed и K7Hybrid прошли без предупреждений. Rotate заканчивается на EC7Bh, K7Packed перед таблицей на DFFEh.

Проверка `scripts/tests/check-font-text-lim.py` дала 696 случаев для новых модулей и 550 для остальных. 396 из них проверяют ограниченный ASCIIZ со всеми положениями NUL и полным окном, остальные покрывают прежние входы точной длины. CPU-трасса исключает чтение FFE0h и байтов после первого NUL. Пиксели и состояние сравниваются с посимвольным эталоном.

Для 32 печатных символов при X=0 `ticks.py` сопоставляет старый стенд 31+1 с прямым D836h. Одинаковая обвязка вызова включена в обе цифры, дополнительная проверка BIOS в новой цифре отсутствует.

| Модуль   |           Z, такты |       RAW_Z, такты |
| -------- | -----------------: | -----------------: |
| Rotate   |      21489 → 17245 |      21324 → 17262 |
| Packed6K |      18634 → 14133 |      18469 → 14150 |
| Fast12K  |      15791 → 11445 |      15626 → 11462 |
| K7Rotate |      22411 → 17925 |      22182 → 17942 |
| K7Packed |      21792 → 17309 |      21563 → 17326 |
| K7Hybrid |      21939 → 17405 |      21710 → 17422 |

У Rotate чистый текст при X=2 показал +245/+91 такт для Z/RAW_Z, поскольку после невыровненной головы остаётся одинаковое число полных четвёрок. NUL на 15-й или 31-й позиции может давать преимущество старому пути. Полная таблица по смещениям и управляющим кодам сохранена в [ticks.json](ticks.json).
