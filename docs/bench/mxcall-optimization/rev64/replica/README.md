# Выделенный переход EXEC → MAIN для GET_CURSOR_POS

z88dk-ticks исполнил инструкции 8080 в плоской памяти с BIOS.sys rev64. Время считается с внешнего CALL до продолжения приложения. Прямой и реплицированный варианты вызывают тот же исторический вектор C81Eh. Два коротких варианта выполняют чтение координат из MAIN отдельной реализацией без CALL C81Eh. [Листинг](replica.asm) [Стенд](measure.py) [Результаты](result.json)

| Маршрут | Такты | Байты реплики, по одной копии на страницу |
|---|---:|---:|
| MAIN, прямой CALL C81Eh | 53 | — |
| EXEC, F806h в штатном Emu80 | 539 | — |
| EXEC, реплика с CALL C81Eh и MAIN bankServiceSP | 224 | 30 |
| EXEC, реплика с чтением cursorY и загрузкой bankPage | 108 | 16 |
| EXEC, реплика с чтением cursorY и установочным LD A,phys | 97 | 14 |

Девять CPU-сценариев сочетали страницы 2, 6 и 16 с тремя комбинациями AF, курсора и вершины MAIN. Проверены координаты HL, сохранность AF/BC/DE/SP, адрес продолжения, значения для двух записей маппера, защитные байты обоих стеков и неизменность FFC0h–FFDFh. В варианте с C81Eh два байта MAIN ниже bankServiceSP занимает адрес от внутреннего CALL. В обоих вариантах чтения область стека MAIN целиком сохраняется. [Отдельный замер F806h](../profile/profile.json)

В плоской модели FFFCh и FFFDh являются ячейками RAM. Фактическое переключение и расположение данных в разных страницах проверены по карте профиля. После STA FFFCh инструкции продолжаются в реплике по тем же адресам MAIN. Результат C81Eh остаётся в HL, адрес приостановленного стека EXEC остаётся в DE, физический селектор возврата в A. После STA FFFDh первая инструкция, работающая с памятью стека, исполняется после SPHL в исходном EXEC. Эти варианты не обращаются к общему окну, поскольку команды перехода целиком лежат в реплике, а стек и адреса данных расположены вне окна. [Карта Emu80](../../../../../scripts/emu80/specialist-mx2.conf) [Вектор и контракт](../../../../../source/bios/setGetCursorPos.inc)

Размещение по FD80h используется только внутри стенда. Для установки реальной службы нужны свободный одинаковый диапазон в MAIN и каждой исполняемой странице и известный селектор возврата. Вызов исторического вектора также требует свободных двух байт ниже действующего bankServiceSP в MAIN, штатно опущенного ниже активной части служебного стека. C81Eh сохраняет A и DE, не вызывает другие службы и не переходит повторно между банками. Эта проверка не распространяется на функции с иным ABI, собственными вложенными вызовами или включёнными прерываниями.

## Проверка на переключаемых страницах Emu80

Повторено в отдельном экземпляре Emu80 со штатным маппером MX2 и неизменённым загрузочным образом rev64. Изолированная сборка эмулятора задаёт скорость 32× при запуске. Применены ключ -Hidden и Qt offscreen, MainWindowHandle равен нулю, звук ВИ53 и мониторинг ленты отключены. MCP подтвердил 32× без полного ускорения. [Стенд Emu80](measure-emu80.py) [Результаты Emu80](emu-result.json) [Поправка частной сборки эмулятора](emu80-speed.patch)

Во всех 36 измерениях на страницах 2, 6 и 16 получены те же 53/224/108/97 тактов. Страницы различались сигнатурами в одном и том же адресе. На каждой физической стороне участки машины, которые обязан исполнять другой банк, заменены HLT. В EXEC записаны неверный курсор, HLT на C81Eh и неподходящий bankServiceSP. Пройденные вызовы вернули HL из MAIN и исходные AF/BC/DE/SP в исходной странице. Для каждой реплики watchpoint зарегистрировал по одному обращению FFFCh/FFFDh и ноль чтений и записей по всем 32 адресам окна. Вызов C81Eh положил ожидаемый адрес возврата на два байта стека MAIN. Варианты прямого чтения сохранили весь страж MAIN.

До установки тестовых реплик штатный F815h MOVE из MAIN с FAR3:4000h → FAR3:4001h, 257 байт, вернулся с AF=0046h, исходным SP и FFDFh=02h. За 15703 такта получено точное перекрывающееся копирование с сохранёнными граничными байтами.
