# Локальные драйверы ввода, звука и часов

Архитектурный разбор по сборке MEM rev64. Приложение объявляет, какие службы ему нужны. При загрузке IO связывает эти импорты с реализацией платформы в той странице, где они будут вызваны. Опрос клавиши, выдача звука и чтение часов выполняются обычным локальным `CALL` с параметрами в регистрах. Поиск файла, проверку образа и получение прав на устройство можно выполнять через DOS один раз за сеанс.

## Размещение и память

| Что занимает память сейчас | Размер | Где находится |
| -------------------------- | -----: | ------------- |
| Сегмент IO.SYS для MAIN    |  443 Б | F000h–F1BAh в MAIN |
| KEYBANK для DOS и EXEC     |  380 Б | F040h–F1BBh в каждой такой странице |
| Слот KEYBANK целиком       |  384 Б | F040h–F1BFh, далее начинается MEM |
| Стек EXEC                  |  576 Б | EE00h–F03Fh, верхняя граница F040h |

В DOS процедура `mdInstall` копирует в выдаваемый EXEC первым блоком 1984 байта от F040h. В эти байты входят слот клавиатуры и 1600 байт MEM. Верхняя граница приложения EE00h проверяется отдельно. При прежних границах исключение всех 380 байт KEYBANK даёт приложению **0 байт** дополнительной непрерывной памяти. Если убрать слот из обязательного хвоста и поднять верх прежнего 576-байтного стека до F1C0h, новый низ стека будет EF80h. Для EXEC без этих служб это **до 384 байт** сверх нынешней границы, до учёта новых векторов и метаданных. Изменятся также размещение аргументов, проверка образа и публикация доступного приложению диапазона. [Карта сборки](../../../../bin/System.layout.json) · [Установка и ограничения EXEC](../../../../source/dos/modules.inc) · [Границы стека](../../../../source/include/mxos.inc)

У штатного `MODULE_LOAD` есть три места загрузки — MAIN, новый банк EXEC и арена DOS. Образ имеет фиксированные адреса. Для банкового приложения нужен способ установить локальный драйвер в **уже занятый этим приложением EXEC**. Для первой версии подойдёт системный комплект IO с несколькими независимо загружаемыми секциями. Вариант без релокаций — заранее скомпонованные профили под объявленные наборы импортов, размещённые у верхней границы, со стеком непосредственно под выбранным профилем. Для проверки достаточно профилей без устройств, только часы и клавиатура с часами. Привязка прямых входов и расчёт границ должны завершаться до передачи управления программе. Для MAIN на исходном MX экран и клавиатура уже доступны через BIOS Монитора-2. Бенчмарку в MAIN достаточно локального драйвера часов в проверенной области MAIN, свободный EXEC для этого не требуется. [Соглашения загрузчика](../../../../source/mem/api.md)

## Службы и владение

- **Клавиатура.** Основной профиль оставляет ожидание, проверку удержания и отсчёт автоповтора в банке, а раскладку — в единственном декодере MAIN. Нынешний KEYBANK уже входит в MAIN при новом нажатии и созревшем повторе. Предлагаемый BIOS-вход связывается там со сменным декодером ЙЦУКЕН/ЯВЕРТЫ. Программа, которой нужен минимальный срок выдачи события, может запросить местную копию драйвера и активной раскладки. В обоих случаях состояние потока ввода принадлежит клиенту, за изображение курсора отвечает MAIN. [KEYBANK](../../../../source/io/KEYBANK.asm) · [Декодер и регистры события](../../../../source/bios/getch3.inc)
- **Звук.** Драйвер реализует возможности платы. На MX тон ВИ53 через `bios_beepTimer` перепрограммирует три канала. Щелчок клавиатуры в `TIMER_CLOCK` использует согласованную с часами перезагрузку и поправку `keyBias`. Обе службы обращаются к одному физическому устройству из разных банков. DOS уже ведёт владельца и освобождает его при завершении приложения, выгрузке модуля или сбросе. Этот учёт нужен и при локально загруженном коде. [Таймер DOS](../../../../source/dos/memory.inc) · [Звук BIOS](../../../../source/bios/beepTimer.inc)
- **Измерительные часы.** Открытие запрашивает максимальную длительность между двумя отсчётами и возвращает реальную шкалу времени, например длительность тика в виде дроби, и предел интервала. Драйвер выбирает подходящий режим, захватывает устройство и ждёт готовности. Отказ позволяет вывести причину до начала измерения. Горячий вход возвращает в HL убывающий U16 по модулю 65536, сохраняет BC и DE. Вариант MX также сохраняет флаги. Разность равна `(начало − конец) & FFFFh`. Для более длинных серий программа суммирует соседние разности в U32. Настройка, пересчёт в миллисекунды и вывод выполняются вне измеряемой операции. Завершение сеанса освобождает устройство. [Текущие часы и накопитель](../../../../source/include/timing.md)

На MX драйвер измерений может использовать существующий `TIMER_RAW` при открытии и `TIMER_RELEASE` при закрытии. При `TIMER_CLOCK` канал 2 имеет другой режим и поправку на щелчки. Рабочий модуль, которого запустил уже владеющий измерительными часами контроллер, получает локальный вход только для чтения того же сеанса. Передавать произвольный NEAR-адрес между банками нельзя. Код чтения связывается в каждом банке исполнителя, делитель задаёт владелец один раз. При тайм-ауте запуска владелец также освобождается. [Контракты и владение](../../../../source/mem/api.md#владение-ви53)

У MX текущая реализация `pitTimerRead` занимает 10 байт. По инструкциям 8080 прямой локальный `CALL` вместе с телом и `RET` занимает **71 такт**. Вход через добавочный вектор `JMP` дал бы 81 такт. Поэтому горячий вызов выгодно привязать непосредственно к телу при загрузке. Это расчёт для существующего тела MX. [Инструкции чтения](../../../../source/include/timing-pit.inc)

## Перенос измерителей

| Измеритель | Что потребуется заменить |
| ---------- | ------------------------ |
| COPYBEN | Прямые init/read и константу 2 МГц. Захватить часы до подмены окна и хвоста FF00h, освободить после восстановления. [Код](../../../../source-apps/copybench/COPYBEN.asm) |
| TEXTBEN, FONTBEN | Общий init в MAIN и чтение в рабочих банках. Выдать рабочим модулям доступ на чтение к сеансу владельца. У FONT.COM отдельно есть инструментальная сборка FONT_BENCH. [Общий вход](../../../../source-apps/textbench/standalone.inc) · [Банковое чтение](../../../../source-apps/textbench/module-timing.inc) · [FONT](../../../../source/font/FONT.asm) |
| DISKBEN | Контроллеру и измерителям MAIN/DOS/EXEC нужен общий формат времени. Медленный рабочий режим сейчас меняет делитель на 1024 после готовности режима 256. Драйвер должен дождаться готовности уже с выбранным делителем. В отчёте пересчитывать и мс, и КиБ/с по фактической шкале. [Рабочий модуль](../../../../source-apps/diskbench/worker.asm) · [Отчёт](../../../../source-apps/diskbench/DISKBEN.asm) |
| SORTBEN | Обычный и длинный интервалы для сортировки вставками. Сейчас ядро само выставляет 256 либо 4096. Выбирать по требуемому диапазону, пересчитывать по метаданным открытого сеанса. [Ядра](../../../../source-apps/sortbench/kernels.inc) |

При CLK1 = 2 МГц делители 256, 1024 и 4096 дают шаги 128, 512 и 2048 мкс. Периоды U16 составляют 8,388608, 33,554432 и 134,217728 с. Разрыв между соседними отсчётами должен быть строго меньше периода. На 2,5 МГц шаг короткого режима равен 102,4 мкс, поэтому единый бинарник должен получать точный масштаб от драйвера. Зависимость от модели часов включает общий код пересчёта, подписи отчётов и расчёт скорости DISKBEN. [Пересчёт времени](../../../../source/include/timing.inc) · [Дисковый отчёт](../../../../source-apps/diskbench/DISKBEN.asm)

Хостовый `benchmark-mxcall.py` читает `cpu_ticks` эмулятора. Такой счётчик позволяет сравнить прямой BIOS из MAIN, локальный драйвер и межбанковый путь с точностью до инструкции. У короткого режима ВИ53 один тик на 2 МГц равен 256 тактам CPU. Для проверки будущей реализации нужны оба вида данных — накладные расходы пустой пары чтений в тактах и время пакета операций, полученное гостевой программой. Проверку переносимости можно провести на одном бинарнике с двумя реализациями часов с разным масштабом, включая границу U16, занятый таймер, отказ запуска и дочернее чтение. [Профилировщик F806h](../../../../scripts/emu80/benchmark-mxcall.py)
