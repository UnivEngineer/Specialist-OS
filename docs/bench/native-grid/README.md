## Пакетный курсор, 2026.11.11

Адрес экрана вычисляется один раз на пакет. DE продвигается между четвёрками, курсор фиксируется при выходе по числу нарисованных групп. Проверка правого края выполняется по старшему байту экранного адреса. Управляющий код внутри четвёрки оставляет её начало внешнему посимвольному обработчику.

MAIN RawLim с пререндером: 210.048 → 204.928 мс, без пререндера: 374.528 → 368.000 мс. BIOS занимает 9164 байта. Инверсия остаётся самомодификацией NOP/CPL; таблица её адресов сокращена до шести описаний столбцов. Удаление исполняемого NOP потребовало бы отдельного обычного ядра или упаковки и восстановления машинного кода при смене режима.

Проверки пакетного курсора: 13743 случая в модели 8080, включая управляющие коды во всех позициях четвёрки, и полный прогон 36 этапов Emu80 с пиксельным эталоном и чтением отчёта с RAM-диска.

### Оценка текстовых окон

Прямоугольник требует четыре границы и, если настраивается, шаг строки. Вместе с сохранением полного экранного режима это примерно 4–8 байт состояния. Ограничение пакета правой границей и установка левой границы при CR/переносе позволяют оставить пиксельные ядра прежними. Дополнительная цена возникает при входе в пакет и переходе строки. Самомодифицируемые операнды CP/LD позволяют менять границы без отдельных чтений памяти на каждый глиф.

Текущая прокрутка использует сплошной memmove экранной памяти. Для окна нужно копировать каждый байтовый столбец отдельно, затем очищать нижнюю полосу. Для ширины W байтов, высоты H пикселей и шага S копируется W*(H-S) и очищается W*S байтов. При невыровненных боковых границах крайние столбцы дополнительно требуют масок и чтения соседних пикселей. Для 6×8 выравнивание границ по 24 пикселям одновременно удобно для четвёрок и байтов экрана.

Предварительная оценка кода границ, переходов и прокрутки — несколько сотен байт, ориентировочно 200–400 для байтовых границ с переиспользованием memcpy. Это оценка по исходникам, реализации и замеров окон пока нет. Свободно 52 байта до FONT_ADDR, поэтому потребуется освобождение места или изменение размещения BIOS.

## Раздельные ядра, 2026.11.11

Обычные и инверсные ядра вращения/пререндера разделены. В обычных нет NOP, в инверсных выполняется CPL на каждый итоговый байт. Вход выбирается один раз на пакет. После переноса UI в подключаемую библиотеку и удаления измерительного таймера из BIOS API размер BIOS — 9209 байт, до шрифта E400h остаётся 7 байт.

MAIN RawLim с пререндером: обычный вывод 191.488 мс, инверсный 205.440 мс. Разница близка к 13.824 мс на 6912 дополнительных CPL по 4 такта при 2 МГц, с учётом дискретности таймера и выбора входа. Оба полных прогона по 36 этапов прошли пиксельный эталон, чтение отчёта с RAM-диска, освобождение ресурсов и возврат в NC. CPU — 13743 проверки рендера и 1488 проверок ABI/движков.

Параметр FontBen.com -I включает инверсию для BIOS. Полная [инверсная таблица](../native-grid-inverse/README.md), исходные результаты и отчёт находятся в соседнем каталоге. Повтор: python source-apps/fontbench/check-grid.py --inverse. Номера MXCALL генерируются в начале общей сборки, перед сборкой банковых программ.

## Скалярный пререндер, 2026.11.11

При валидном FONTRENDER скалярный вывод и неполные пакеты используют исходную нулевую фазу и готовые сдвиги остальных фаз. При выключенной или устаревшей таблице, а также линейном альтернативном шрифте используются вращения. Линейная и построчная раскладки разделяют один развёрнутый скалярный код, шаг указателя изменяется INC HL/INC H при смене раскладки. Размер BIOS — 9170 байт, шрифт остаётся E400h.

Прогон выявил регрессию скалярной скорости. MAIN printCharRaw: OFF 762.752 мс, ON 948.736 мс. Прежний вариант до объединения скалярных ядер и проверки FONTRENDER занимал 722.944 мс. Четвёрки RawLim с пререндером сохранили 191.488 мс. Текущий scalarPre читает раздельные части глифа из двух плоскостей, выполняет чтение и маскирование VRAM и имеет цикл по парам строк. Это корректный согласованный режим, но он требует дальнейшей оптимизации для выигрыша в посимвольной печати.

Все 36 обычных MAIN/BANK этапов прошли независимый пиксельный эталон и проверку ресурсов. Модель 8080 прошла 13743 проверки, включая фазы, инверсию, края, управляющие коды и устаревшие таблицы. [CPU-результаты](scalar-pre-cpu/results.json).
