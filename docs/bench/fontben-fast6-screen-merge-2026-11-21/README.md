# 6×8 Fast. Слияние фрагментов через экран и через регистры

Четыре шестибитных глифа A, B, C, D дают три байта `A<<2 | B>>4`, `B<<4 | C>>2`, `C<<6 | D`. Формулы сдвига влево приведены по модулю 256. Обозначения фаз взяты из предложенного цикла. Для строки глифа `y` таблицы Fast уже содержат нужные маски.

| Фаза | Глиф | Значение | Страница относительно `fontPreBase / 256` |
|---|---|---|---|
| 0 | A | `A << 2` | `+y` |
| 3L | B | `B >> 4` | `+24+y` |
| 3R | B | `B << 4` | `+32+y` |
| 1L | C | `C >> 2` | `+8+y` |
| 1R | C | `C << 6` | `+16+y` |
| 2 | D | `D` | `FONT_ADDR / 256 + y` |

## Такты Intel 8080

Нормальный вывод. В таблице одна четвёрка на одной пиксельной строке. Тело продвигает указатель экрана на три столбца. Последний переход к новому коду текста и проверка границы включены в Stream. Страницы шрифта подставлены в операнды `MVI B` или `MVI H` перед проходом. Подготовка прохода и переход по Y идут отдельно.

| Вариант | Тело, такты | Stream, такты | Stream, байты | Чтений / записей экрана |
|---|---:|---:|---:|---:|
| Предложенный `DE` по тексту, слияние через экран | 225 | 252 | 48 | 3 / 6 |
| Два `POP DE`, слияние через экран | 202 | 224 | 42 | 3 / 6 |
| `DE` по тексту, адрес экрана временно в `SP` | 231 | 258 | 52 | 0 / 3 |
| Текущий `6FastStream`, два `POP BC` и `OR (HL)` по шрифту | 170 | 192 | 38 | 0 / 3 |

В предложенном теле чтение четырёх кодов с переносом в `C` стоит 48 тактов. Три продвижения `DE` стоят 15. Шесть загрузок старшей части адреса и шесть чтений шрифта стоят 84. Слияние добавляет три `OR (HL)` по экрану за 21 и три промежуточные записи за 21. Три итоговые записи и три продвижения `H` стоят 36. При переходе к следующей четвёрке ещё один `INC DE` и проверка `LD A,H / CP n / JP NZ` прибавляют 27.

В пробе с адресом экрана в `SP` регистры `B` и `C` хранят два готовых байта, а `A` — третий. Первый фрагмент третьего байта временно лежит в `H`: инструкция `LD H,(HL)` успевает прочитать его по старому адресу. Сохранение адреса экрана в `SP` стоит 5 тактов, извлечение через `LD HL,0 / ADD HL,SP` — 20. Это 25 тактов на четвёрку. Сохранение SP вызывающего кода через `LD HL,0 / ADD HL,SP / LD (nn),HL` и восстановление через `LD SP,n` стоят ещё 46 тактов один раз на весь участок. CPU не использует стек для вызовов, пока SP занят адресом экрана.

## Почему Stream уступил штатному Fast и Packed

В штатном ядре обе буквы загружаются в указатели шрифта перед выводом целого экранного столбца. Следующие семь пиксельных строк меняют номер страницы, сохраняя младшие байты адресов. Столбцовый цикл развёрнут. Его три столбца чередуют направление. В Stream проходу по всей строке приходится заново загрузить коды и индексы и проверить правую границу на каждой пиксельной строке.

Приращения `RawLim` измерены разницей между 16 и 4 глифами с тем же начальным курсором. Это стоимость ещё одной полной четвёрки внутри участка. Подготовка всего участка и восьми проходов исключена разностью.

| Операции на четвёрку высотой восемь строк | Fast штатный | Fast Stream | Packed штатный | Packed Stream |
|---|---:|---:|---:|---:|
| Чтение и перенос кодов, включая сканер штатного ядра | 242 | 400 | 242 | 400 |
| Старшие байты адресов таблиц | 252 | 336 | 252 | 168 |
| Чтения шрифта, слияние и запись | 504 | 504 | 840 | 840 |
| Продвижение экранного адреса внутри цикла | 120 | 120 | 120 | 120 |
| Проверка границы | 22 | 176 | 22 | 176 |
| Всего | **1140** | **1536** | **1476** | **1704** |

У Fast переплата за чтение и раскладку кодов даёт 158 из 396 тактов, проверка границы — 154, загрузка страниц — 84. Packed экономит 84 такта на старших байтах таблиц. Фазы Packed содержат соседние биты, которые при слиянии отбрасывает `XOR / AND / XOR`.

Если чередовать вертикальное направление между четвёрками, исчезает возврат по Y на семь строк. Предложенному порядку обхода всё равно приходится возвращать указатель текста и столбец экрана для каждой из восьми строк четвёрки. Горизонтальное чередование для целой строки может сэкономить перестановку указателей на краю. Тогда правая версия начинает с фазы 2, идёт через 1R, 1L, 3R, 3L и заканчивает фазой 0. Тело всё так же читает и пишет байты экрана в тех же количествах.

## Проверка

SjASMPlus `--i8080` и z88dk-ticks в режиме 8080. 152 проверки сравнили экран и указатели с независимым шестибитным эталоном на всех восьми пиксельных строках. Длины 4, 16 и 64 глифа включают переход адреса текста через границу страницы. Для Stream проверены нормальный и инверсный вывод.
