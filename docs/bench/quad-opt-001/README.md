# Оптимизация FONTBEN и ёмкость FONTKOI, 08.11.2026

Экспериментальный standalone-рендер; штатные BIOS/DOS-рендеры не изменялись. Сохранены посимвольные пути, полная таблица 12 КБ, cold/warm и вызовы из main/DOS, отказ для хвостов и невыровненного X.

Четверка теперь пишется тремя проходами по восьми строкам. Первый столбец собирается из phase0 и первого байта phase6, второй — из второго байта phase6 и первого phase4, третий — из второго phase4 и исходного глифа. В каждом проходе BC — экран, DE/HL — два источника; OR объединяет только подготовленные части глифов. Ни чтения экрана, ни сохраняющих масок не требуется, каждый экранный байт записывается целиком один раз. Между проходами меняются источники и восстанавливается Y, INC B выбирает следующий экранный столбец. Машинный код ограничен проверяемым набором инструкций без LDAX B, AND, CALL и стека; 24 экранные записи. Пиксельное ядро сократилось с 370 до 196 байт, весь блок четверок — с 685 до 506 байт. Четыре кода больше не копируются во внутренний scratch; читаются прямо из текста. Четырёхбайтный буфер переходника DOS остаётся, поскольку исходная страница недоступна в main.

Hit кеша четверок теперь не вызывает отдельный декодер и не сохраняет AF на стеке; номер удерживается в B, защита двух последних полученных указателей обновляется непосредственно. Развёрнута генерация восьми строк каждой запрошенной фазы. Посимвольная исходная фаза проверяется до INVALID и вообще не вызывает Query/подготовку, что дополнительно проверено по неизменности всей кеш-арены. Проверки параметров остаются на входе пакета; управляющие коды уже отфильтрованы при загрузке README и не разбираются повторно в сыром рендере. Скалярный BIOS для сравнения сохраняет свой полный фронтенд.

Прототипы чтения битмапы через SP протестированы отдельно: одинаковые экранные данные и восстановление SP; цена включает переключение и восстановление стека, передачу масок и тот же контракт сохранения регистров. Однобайтный вариант 484 против 431 такта, двухбайтный 785 против 746; проигрыш 53/39 тактов. Рост кода 13/11 байт. Поэтому POP-варианты не подключены в рендер; проверочный источник и результаты воспроизводит source-apps/fontbench/check-stack.py. Это цена двух конкретных реализаций, не доказательство невозможности других стековых алгоритмов.

## Замеры

Emu80, ВИ53 CLK1=2 МГц, квант 0,128 мс, один интеграционный прогон. Те же 1200 байт README, 89 различных кодов, 48×25, 168 слотов. Загрузка и очистка вне измерения; подготовка, поиск/промахи, защита, цикл, таймер и межстраничные вызовы внутри. Main/DOS передают одинаковые порции по четыре символа; из DOS — BC/DE и четырёхбайтный буфер кодов. Это результаты эмулятора, физическое оборудование не проверялось.

## FONTKOI и 4 КБ

Анализируется неизменённый assets/system-rom/FONTKOI.FNT с проверкой MXFN штатным parser: 1328 байт, 162 кода в диапазонах 20h–7Fh/C0h–FFh плюс A3h/B3h. Они содержат 147 разных битмап, одинаковые глифы разделяют запись. Фазы 0/4/6 в нынешнем полностью разложенном формате требуют 8+16+16=40 байт на глиф: 6480 байт для всех кодов, 5880 после объединения одинаковых битмап. С заголовком и 256 двухбайтными указателями — 6424 байта. В 4096 не помещается.

Проверенный альтернативный формат содержит по восемь заранее повёрнутых байт для каждой из трёх фаз: 147×24=3528 байт. Фаза 0 уже готова к OR, для фаз 4/6 две экранные части упакованы в один байт и выделяются AND 0Fh/0C0h и AND 03h/0F0h соответственно. Вращений в рендере не нужно, но дополнительные маски отличают эту схему от текущего быстрого ядра. 256 двухбайтных относительных указателей занимают 512 байт, заголовок 32: **4072 байта**, запас **24 байта**. Непредставленные коды указывают на пробел. Поиск охватывает все 256 байт без поиска диапазона. Указатели при загрузке можно релокировать в абсолютные без роста образа. Альтернатива с 256 однобайтными номерами занимает 3784 байта без заголовка, но требует вычисления index×24.

Данные должны размещаться плотно, без округления таблиц до границы страницы: нынешнее начало арены DB90h не выровнено. Исходный FONTKOI остаётся вне этих 4 КБ; вместимость зависит от битмап конкретного файла. Это оценка и проверочный образ, не подключённый в рендер формат и не замер его скорости. analyze-fontkoi.py записывает FONTKOI.preshift-packed.bin и проверяет восстановление всех частей для 256×8 строк; исходный шрифт не меняется.

## Проверки и артефакты

OS собрана без ошибок и предупреждений; системный образ собран, 27 файлов совпали с манифестом. По листингу главный блок заканчивается на 1E28h, ниже 2000h; quad 2200h–23F9h, ниже шрифта 2800h; все фиксированные данные и конец 6000h сохранены. Генераторы стали больше, блок четверок меньше; сдвиг конца главного блока +252 байта, уменьшение quad на 179 байт, суммарно +73 байта используемого кода/данных внутри прежнего файла 24 КБ.

Независимый z88dk-ticks -m8080: 1046 скалярных и 556 пакетных случаев, плюс четыре стековых микротеста; результаты в cpu-scalar/, cpu/, stack/. Проверка упакованного шрифта — fontkoi/. Все 9216 байт изображения каждого варианта совпали с BIOS, Bitmap PASS. Штатный запуск FONTBEN.COM выполнен клавиатурой в нижней строке NC (command.png), результат results.png, подтверждён возврат в NC (returned.png). Восстановлены 2048 байт резерва DOS и 32 байта общего окна. Собственный видимый Emu80 без звука закрыт. results.json содержит времена, промахи, статус восстановления/возврата и SHA-256 использованных образов.
