## Последнее решение автора

- Все вызовы String*Z всегда копируют до первого NUL прямым циклом с развёрткой ×4, без чтения за NUL. Предварительного strlen нет. Пустая строка заканчивается в банке. Указатель HL возвращается на NUL.
- Для String*Lim передаётся точное BC. Полные окна идут стеком, короткие прямым циклом ×4 с точным остатком. Для неполного окна замеры показали устойчивое преимущество общего стекового пути с 29 байт, включая нечётные длины. Программист может явно выбрать счётный вызов.
- Автор **подтвердил добавление публичного обычного `printStringLim`**, с управляющими кодами той же семантики, что у `printStringZ`. HL указывает на буфер, BC задаёт точную длину с возможными нулями. При возврате HL указывает за буфер, AF/BC/DE сохранены. Штатный сырой `RawLim` уже существует.
- Эмулятор запускать только скрыто с `-Hidden` и фиксированными 32×. Не запускать матрицы FontBen. В отчёте указывать такты прямого BIOS из MAIN рядом с банковым вызовом.

Предложенная и проверенная следующая фиксированная точка прямого BIOS — C8F9h сразу после C8F6h. Обновить `source/include/mxos.inc`, таблицу фиксированных JMP, native F800/F806, `source/io/MAINBIOS.asm`, декодер `source/mem/text-route.inc`, режим 3 и SDK. В `bankText.printWindow` выделить новый режим, не смешивать с RAW_PSEUDO или COMMAND. Для старого FNT и перехваченного printChar нужен цикл по точному BC через публичный printChar. При штатном FNT и объявленной capability допускается D830h. Согласовать с `print_chunks`, если агент ещё доступен, и забрать его файлы из указанного выше checkout.
2. Агент `model_speed` проверяет совместное использование настоящего горячего CPM32 FF0Eh (`POP HL; SHLD`) в отдельном checkout `C:\Users\Vovan\AppData\Local\Specialist-OS\workspaces\2f01b64aafd4454493b39aa85463020b`. Предварительный снимок — [physical-cpm32.patch](physical-cpm32.patch). Идея переносит пары выбора банков в аргументы LXI вместо LHLD, что экономит 6 тактов на пару и оплачивает ветку JZ после чтения. Сохранить сигнатуру FF0Eh, все физические банки и безопасный восьмибайтовый стек удалённого MOVE. Проверить CPM32/remote MOVE перед слиянием. Не считать этот опыт готовым по одному снимку. Заключительная рабочая реализация Z не требует модификации шрифтов, D833h/D836h не входят в ABI.
3. Добавить CPU и Emu80 проверки обычного LIM из MAIN/DOS/EXEC, NUL внутри BC, BC=0, ESC через границу окна, старый FNT и перехватчики. Для штатного образа прогнать `scripts/build/build-all.ps1`, `scripts/images/build-image.ps1 SystemEmuWritable`, `scripts/tests/check-mem-inline-nested.py`, `check-cpm32.py`, `check-mem-operations.py`, тесты парной линковки и `scripts/emu80/benchmark-mem-bank.py --suite text` и `--suite user`. Проверить порог 28/29/30/31/32 и показать прямой BIOS MAIN. Для новой операции, отсутствовавшей в rev70, сравнивать со штатным счётным движком либо отметить отсутствие старого публичного входа.
4. Актуализировать `source/mem/api.md`, `README.md`, `transport.md`, README BIOS, SDK, локальный `docs/CHANGELOG.md` и отдельный итоговый отчёт. Перед сдачей сравнить размеры MEM/BIOS/DOS/хвостов и проверить обычный запуск NC и EDIT в MAIN и EXEC. Автор не просил коммита или публикации.
