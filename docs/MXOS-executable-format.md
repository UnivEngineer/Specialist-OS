# Исполняемые файлы MXOS2: COM, EXE, RKS

Решение от 02.11.2026. Реализация: DOS, RUN.COM и сборщик образов; версия контейнера 1, версия интерфейса RUN 2.0. Это замена прежнего проекта 64/96-байтного EXE, а не дополнительный совместимый вариант. Старые внутренние образы MXOS нужно пересобрать.

Здесь **MS DOS** — система Microsoft для x86; **DOS MXOS2** — ядро аппаратных и файловых сервисов «Специалиста». Префикс bios_ исторический и не означает отдельного обязательного BIOS. Одинаковые расширения с MS DOS не означают совместимости кода.

## Расширения и исполнители

| Расширение | Содержимое | Исполнитель |
|---|---|---|
| COM | Родной контейнер MXOS2, заголовок 16 байт + код | DOS; через RUN без ключа — MX |
| EXE | Побайтно тот же контейнер | NC.EXT → RUN; без ключа — меню среды |
| RKS | Стандартные адреса начала/конца, нагрузка и сумма | NC.EXT → RUN; без ключа — MON |
| SYS | Сырой первичный DOS.SYS | Загрузчик системы, не командный исполнитель |
| MON | Сырой бинарник сменного ядра | Адаптер RUN, знающий раскладку ядра |
| CPU/I80 | Исходный формат для сборщика | CPU — текстовые адреса, I80 — код |
| BAT | Команды DOS | Явный выбор режима и подготовка программы |

EXE временно используется при исследовании коллекции. Совместимую с MXOS2 программу можно переименовать из EXE в COM без перекодирования. Для подтверждённых исключений создаётся BAT с явным `A:RUN.COM -STD/-RF/-MON ...`. RKS остаётся штатным контейнером исторической коллекции и не требует конвертации для запуска.

Среда и имя монитора в COM/EXE не спрятаны. Главная цель — совместимость ядра MXOS2 в MX и STD; подмена ядра остаётся отдельным выбором. Автопоиск одноимённого BAT не реализуется на этом этапе.

## Заголовок COM/EXE — ровно 16 байт

Все слова little-endian. Адреса абсолютные, перемещения и BSS в версии 1 нет.

| Смещение | Размер | Значение |
|---:|---:|---|
| 00h | 2 | CDh,20h: x86 INT 20h, безопасный выход при попытке запуска как COM в MS DOS |
| 02h | 2 | ASCII MX |
| 04h | 1 | Версия контейнера: 01h |
| 05h | 1 | Флаги: 00h — обычное/нейтральное размещение; 01h IMAGE_FLAG_DRIVER — инициализатор в банке DOS; 02h IMAGE_FLAG_BANK — обязательный отдельный EXEC-банк; 04h IMAGE_FLAG_MAIN — подтверждённая совместимость с main/MXOS BIOS; сочетания и остальные биты запрещены |
| 06h | 2 | Адрес загрузки нагрузки |
| 08h | 2 | Адрес входа |
| 0Ah | 2 | Размер нагрузки N, ненулевой |
| 0Ch | 2 | Штатная контрольная сумма нагрузки bios_calcCS |
| 0Eh | 2 | bios_calcCS первых 14 байт заголовка |
| 10h | N | Машинный код и данные 8080 |

Размер всего файла равен N+16. Вход должен находиться внутри нагрузки. Проверяются сигнатура, версия/флаги, длина, суммы и диапазоны. Заголовок не попадает по адресу загрузки программы. Повреждённый контейнер не трактуется исполнителем как старый сырой EXE.

Это не MZ/PE: Windows не получает допустимого заголовка EXE. При запуске как COM в среде MS DOS выполняется INT 20h до исполнения байтов 8080. Собственного длинного сообщения для MS DOS нет, чтобы сохранить 16 байт.

Используется существующая аддитивная контрольная сумма DOS, а не новый полиномиальный CRC. Для байтов d[0..N−1] младший байт — сумма всех байтов по модулю 256; старший — сумма первых N−1 байтов с переносами из накопления младшего. Суммы рассчитываются при загрузке с накопителя; повторной проверки после копирования в памяти нет.

## CPU/I80 и миграция

Сборка системной утилиты создаёт пару:

```text
RUN.cpu:        RUN.i80:
E800            машинный код 8080 без контейнера
E800
```

Первое число CPU — загрузка, второе — вход; оба шестнадцатеричные ASCII без префикса. CPU без соседнего I80 — сырой образ с загрузкой и входом 0000h. Сырые EXE коллекции переименовываются в CPU с сохранением байтов. Исходные архивные имена и оригиналы *.exe.bin сохраняются как свидетельства происхождения.

Сборщик принимает старые сырые EXE/BIN, CPU/I80, RKS и новые COM/EXE. Выход выбирается расширением в первом столбце манифеста: COM/EXE получают общий заголовок, RKS получает стандартный контейнер. Для старого RAW EXE/BIN третий столбец задаёт адрес; CPU/I80 задаёт оба адреса самостоятельно. Из разных адресов загрузки и входа нельзя получить RKS без потери смысла, поэтому такой запрос отклоняется.

```text
RUN.COM       ../bin/RUN.cpu
GAME.EXE      games/Game.cpu
GAME.RKS      games/Game.rks
RAMFOS.MON    ../bin/RAMFOS.mon
DOS.SYS       ../bin/DOS.sys
```

SYS и MON копируются как бинарники. MON не получает адрес в заголовке: у RAMFOS две области исполнения, раскладка задаётся адаптером.

## DOS, FAT и ABI

DOS исполняет BAT и COM. EXE/RKS обрабатываются ассоциациями NC:

```text
RKS A:RUN.COM
EXE A:RUN.COM
```

Служба ассоциаций пока остаётся в NC. Общая системная служба может появиться отдельно; файловый исполнитель DOS не вызывает RUN скрытно.

В FAT-описателе больше нет адреса загрузки. Байты 12h–13h снова DIR_LstAccDate; сборщик записывает ноль. DIR_FileSize в 1Ch–1Fh хранит точное число байтов всего файла N, включая контейнер. Исторический N−1 устранён синхронно в DOS, NC, редакторе, TAPE, CHKDSK и сборщике. Пустой файл имеет N=0 и firstCluster=0.

C854h: bios_imageOpen, HL=дескриптор, A=16 — прочитать первый сектор COM/EXE в секторный кэш и проверить заголовок; HL=вход, DE=загрузка, BC=размер тела. A=4 — открыть первый сектор RKS, HL=IMAGE_LOAD_CONTEXT, DE=буфер; RUN заполняет нормализованные поля адресов/размера. C848h: bios_fileLoad, DE=назначение; остаток первого сектора копируется, полные последующие секторы читаются прямо по месту, последний точный хвост копируется из кэша. COM/EXE возвращает HL=вход после проверки тела; RKS возвращает BC=сумму, HL=курсор после тела, DE=следующий кластер для проверки суммы RUN. Контекст действителен до следующей файловой операции, между C854h и C848h нельзя менять том. C845h: точный N и исходный буфер. C866h: сырой секторный fileLoad2 по DE с округлением до полного сектора.

Стандартный размер и освобождение поля адреса готовят записи каталога к FAT16. Это не завершение всей FAT16: свободные записи FFh, самоссылка конца цепочки, геометрия и прочие отклонения остаются отдельной задачей. FAT12 не вводится.

## RUN.COM и среды

```text
A:RUN.COM -MX H:GAME.COM
A:RUN.COM -STD H:GAME.EXE
A:RUN.COM -RF H:GAME.RKS
A:RUN.COM -MON H:GAME.RKS
A:RUN.COM -MON:Monitor2 H:GAME.EXE
```

Короткая команда `run` без диска и расширения разрешается DOS как `A:RUN.COM`; исходный диск возвращается до входа, поэтому `run BUDI-RF.exe` использует игру с текущего диска. То же правило доступно COM-командам из BAT.

Ключ режима можно ставить до или после имени, в том числе между аргументами программы; регистр не важен. Например, `RUN GAME.EXE -STD` равнозначно `RUN -STD GAME.EXE`. RUN исключает свои ключи из передаваемых аргументов, сохраняя порядок остальных. Без ключа неподтверждённый COM/EXE (flags=0) вызывает меню; RKS сохраняет прежний выбор MON. MAIN/DRIVER/BANK передаются нативному загрузчику без меню:

```text
MXOS2 EXECUTABLE LAUNCHER V2.0
GAME.EXE: LOAD ADDRESS 0000, RUN ADDRESS 0100
PLEASE CHOOSE THE RUNTIME MODE:
1 - MX:  MX HARDWARE, MXOS2 CORE
2 - STD: STD HARDWARE, MXOS2 CORE
3 - RF:  MX HARDWARE, RAMFOS CORE
4 - MON: STD HARDWARE, MONITOR-2 CORE
5 - MON:CUSTOM: STD HARDWARE, CUSTOM CORE
>
```

Пункт 5 запрашивает имя файла монитора. По умолчанию A:, расширение MON. Сейчас поддерживается 4096-байтный образ с совместимым прологом Monitor-2; это не универсальный ABI произвольных мониторов.

MX не переключает аппаратуру. STD останавливает ВИ53, включает STD, белый цвет, KOI-7, оставляет ядро MXOS2. MON делает STD-подготовку и загружает Monitor2.mon. RF загружает RAMFOS.MON непосредственно общим переходником RUN, без RAMRUN. RET из MX/STD возвращает вызывающей стороне; из MON/RF — холодная загрузка MXOS2.

## Текущие границы реализации

Компактный DOS сначала читает контейнер во временную область с 0000h, проверяет его, затем переносит только нагрузку с учётом перекрытия. Максимальный размер контейнера DOS — 8EFFh; RUN ограничивает его 8C00h для защиты собственного нижнего переходника. Прямое блочное чтение по адресу назначения с отдельной обработкой первого/последнего секторов пока не реализовано. На формат файла это ограничение не влияет, но текущий загрузчик имеет меньший предел, чем 16-битное поле N.

Нижняя нагрузка RUN заканчивается не выше 8C00h. В MX допускается системная нагрузка DC00h–FAFFh; в RF — D300h–F7FFh. MON/STD используют нижнюю нагрузку. Ядро временно загружается в экран с 9000h после цвета 00h и очистки; затем нижний переходник заменяет системную память без дальнейших обращений к прежнему ядру.

RAMFOS.MON — 6880 байт: первые 1300h в C000h–D2FFh, следующие 07E0h в F800h–FFDFh. Точки файлового сервиса RAMFOS пока возвращают отказ; замена ядра не означает наличие FAT-адаптера.

## Размещение загрузчика с 03.11.2026

Для обычного MX экран не используется: краевые секторы проходят через штатный кэш DOS. Нижнее тело читается сразу по месту; 0000h больше не является буфером целого контейнера. Верхнее тело, перекрывающее RUN/DOS или активный драйвер, требует временного нижнего размещения до окончания файловых операций. Заголовок и сумма RKS в него не включаются.

Только MON/RF используют скрытый экран: ядро с 9000h, временный переходник с AB00h, временный SP=BF00h. Передача Monitor-2 завершается через короткий EAxx-переходник, поэтому очистка экрана новым ядром не уничтожает адрес продолжения. Программа MX/STD в нижнем ОЗУ получает аргументы с EA00h и переходник с EA80h; нижние 8C00h/8E00h используются только для верхней нагрузки.


### Инициализаторы драйверов (07.11.2026)

COM с IMAGE_FLAG_DRIVER загружается FILEEXEC в физическую страницу ДОЗУ 0 с 9000h; тело должно завершаться не выше C000h. DE указывает на аргументы в строке этой страницы. После RET арена освобождается для следующего инициализатора. Код служб, их параметры и строки передаются DOS через DRIVER_INSTALL; указатели в арене после возврата не сохраняются. Для драйверов H: служба собрана под общий адрес F940h в DOS и main. Основная память вызывающей программы не используется под тело инициализатора. Расширение COM оставлено для ручного запуска из CLI/AUTOEXEC; признак исполнения определяется заголовком.

Флаг BANK задаётся в ASM как IMAGE_FLAGS = IMAGE_FLAG_BANK после подключения mxos.inc. Штатная сборка переносит символ через третью строку CPU в байт 05h контейнера. DLL с BANK принимается MODULELOAD только для MODULE_TARGET_BANK. Нативный FILEEXEC DOS загружает такой COM/EXE через механизм модулей в свободный EXEC-банк. DE — NEAR-указатель аргументов в этом банке; RET возвращает исходные банк/SP и освобождает образ и его собственные ресурсы. RUN передаёт MAIN/DRIVER/BANK нативному FILEEXECNATIVE DOS без меню и без ассоциаций; неподтверждённые COM/EXE без ключа режима показывают меню.
