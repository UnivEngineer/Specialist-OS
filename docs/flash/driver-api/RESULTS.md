# Дескрипторы драйверов, запись с проверкой и DISKBEN

Дата: 2026-10-31. Проверки выполнены в отдельной установке `Emu80-flash-test` через MCP. Это результаты модели, без измерений на плате.

Реализованы B=0FFh (две ASCII-строки: имя и описание) и B=5 (запись, повторное чтение и побайтовое сравнение 256 байт). B=1 полного сравнения не делает. FlashFst по B=5 ждёт готовности записанного чипа; B=4 по-прежнему нужен для завершения всех операций, ранее запущенных через B=1.

## Проверки

- Дескрипторы встроенных ROM/RAM, внешнего ROM.COM, Flash, FlashFst, FlashSys; отсутствие дескриптора у пустого драйвера.
- Инфо-панель NC после замены Flash на FlashFst без перезапуска NC: `info-Flash.png`, `info-FlashFst.png`.
- B=1 и B=5 у всех flash-драйверов, чтение результата, сохранность BC/DE/HL/SP, исходного буфера и границы стека в 320 байтах ниже SP.
- Системные образы настоящего размера 128/256/512 КБ: `results-128.json`, `results-256.json`, `results-512.json`.
- Ошибка чтения и намеренное несовпадение данных возвращают CF=1, diskWriteErr=1, не нарушают стек.
- Аппаратный запрет J4 отклоняет B=5, образ не меняется, стек восстановлен: `locked.json`.
- Настоящее меню DISKBEN: оба выбора 0/1, четыре режима в каждом прогоне, FAT и каталог не изменены: `diskbench.json`, `diskbench-b1.png`, `diskbench-b5.png`. Независимое чтение после измерения остаётся включённым.
- Регрессия распределения кластеров, F5 NC, заполненной FAT, тайм-аутов, чтения Flash/FlashFst и завершения записи: `interleave.json`.
- Регрессия DISKBEN на RAM-диске B: все четыре измерения, сверка ВИ53 с тактами CPU, нулевой бюджет flash, граничные BPB, FORMAT и запуск DISKBEN через fileExec. Отчёты генератора: `source-apps/diskbench/build/Buffered/` и `source-apps/diskbench/build/safety.json`.

## Размер и память

| Компонент | До изменения, байт | После, байт | Конец |
|---|---:|---:|---|
| DOS | 6530 | 6624 | D9E0h, ниже командной строки DA00h |
| NC | 4048 | 4131 | вместе с переменными/списком ниже FB00h |
| Flash | 303 | 351 | DF5Fh |
| FlashFst | 472 | 503 | DFF7h |
| FlashSys | 261 | 311 | DD37h |

Общая проверка занимает 81 байт кода DOS. Временный буфер 256 байт размещается на стеке; для B=5 требуется 320 свободных байт стека. DISKBEN предоставляет свой стек ниже 8FDFh. Маленький исторический стек сам по себе не подходит для этой функции. Постоянных 256 байт RAM не добавлено. Дескрипторы встроенных драйверов и их обработчик размещены в свободных фиксированных промежутках; ORG_PAD и стандартные точки входа сохранены. Начальное нулевое состояние FlashFst уже входит в COM, повторный цикл обнуления при входе удалён. Для B=5 отдельные циклы программирования в драйверах не создавались.

## Сборка

`build-project.ps1 OS`: ошибок и предупреждений SjASMPlus нет. Дополнительно собран вариант DOS с RAMD_BUFFERED=0 и DISK_DRIVER_CHECKED=0. Пересобраны SystemRom_emulator.bin, SystemRom_emu80_writable.bin и SystemRom_128K.bin / SystemRom_256K.bin / SystemRom_512K.bin.

Для использования новых B=5-драйверов нужно загружать обновлённый DOS: они вызывают общий сервис C89Fh. Используйте обычный таск Emu80 с пересборкой.
