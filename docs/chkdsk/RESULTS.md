# CHKDSK и общий движок переноса памяти

31.10.2026. Проверки выполнены на CPU 8080 в изолированном Emu80, не на физическом оборудовании.

## CHKDSK

`A:CHKDSK.COM B:`; без аргумента — запрос буквы диска. Результат — `bin/CHKDSK.com`, 1973 байта, адрес 0000h. Входит в сборку OS и системный ROM. [Описание и границы формата](../../source-apps/chkdsk/README.md).

Первый проход: BPB и границы областей, зарезервированные FAT-ячейки, дубликаты имён, размер и диапазон цепочек, циклы/пересечения, свободные и bad в цепочке, потерянные кластеры. После ошибок структуры суммы не проверяются. Поддерживается существующий MXOS-формат: 256-байтные сектор и кластер, одна FAT, до 2 МиБ и 256 записей корня; N−1 и самоссылка в конце цепочки. Подкаталоги/LFN не обходятся и явно отмечаются как неподдерживаемые. Утилита не исправляет диск и не добавляет полей в каталог.

Второй проход: встроенные суммы простого RKS и заголовка/образа MXEX v1. Используется C82Ah `bios_calcCS`, порции по 256 байт с правильным переносом состояния C и B, где последний байт исключается из старшего аккумулятора. Отдельный файл эталонных сумм по решению пользователя не создаётся. Файлы без эталона получают `NO STORED CS`. Старый сборщик образов мог удалять заголовок/сумму RKS; такие сырые payload нельзя считать проверенными.

[validation.json](validation.json): 26 образов/вариантов с искусственными ошибками, длины payload 1, 255, 256, 257, 511, 512, 513, 16000. В исправных примерах совпали суммы RKS и MXEX; повреждения payload и заголовка обнаружены. После каждого случая побайтно проверена неизменность тестового RAM-диска. Отказ чтения даёт отдельный статус 4. Записей во flash не выполнялось.

Штатный `bios_fileExec` загрузил CHKDSK с нового ROM. Проверка A: дала 0 ошибок структуры и 21 файл без встроенной суммы — [launch.json](launch.json), [экран](system-scan.png). Проверены запуск без аргумента и выбор клавишей, возврат в NC, вставка символа в середину строки с сохранением терминатора и соседних байтов — [interface.json](interface.json).

## Перенос памяти

Общий код `source/dos/move8080.inc`, 139 байтов. C42Dh и внутренний memmove используют его; DEBUG T вызывает C42Dh. Контракт C42Dh из исходной таблицы ABI сохранён: HL=начало, DE=конец+1, BC=назначение, DE сохраняется. Дополнительно корректны перекрытие и пустой диапазон. Внутренний memmove сохраняет BC/DE/HL. DEBUG переводит свой включительный конец в полуинтервал. Исправлены выбор направления и захват лишнего байта прежнего memmove; вызывающие места редактора строки теперь явно включают терминатор. Стек DEBUG использует STACK_ADDR, а не хвост страницы с кодом RAM-драйвера.

Вперёд данные читаются POP DE, назад записываются PUSH DE. Нечётный байт обрабатывается отдельно. Горячая пара: 63 такта вперёд, 64 назад; на пару по два чтения и записи полезных байтов, без промежуточной копии данных. Чётный путь в измеренном направлении назад: `393 + 32*N` тактов полного C42Dh. Выбор направления, сохранение SP и нечётный хвост включены в полные замеры.

| Байтов | Исторический C42Dh, такты | Новый C42Dh, такты | Ускорение |
|---|---:|---:|---:|
| 1 | 94 | 326 | 0.29 |
| 2 | 178 | 457 | 0.39 |
| 3 | 262 | 486 | 0.54 |
| 8 | 682 | 649 | 1.05 |
| 16 | 1354 | 905 | 1.50 |
| 256 | 18199 | 8585 | 2.12 |
| 4096 | 290839 | 131465 | 2.21 |

Замеры — реальное исполнение инструкций CPU эмулятора, без внешних 27 тактов CALL/JMP тестовой обвязки. Исторический код собран из коммита `5e83e32` и перемещён в тестовую RAM; значения сравниваются для неперекрывающегося назначения выше источника. Для одного–трёх байтов новая универсальная процедура дороже; выигрыш на больших блоках не переносится на все длины. Для 4096 байт выигрыш 2,21 раза: около 65,7 мс вместо 145,4 мс при 2 МГц без ожиданий.

Проверены 67 сценариев: пустой блок, 1/2/3 байта, нечётные длины, граница 256 байт, 4096 байт, совпадение, перекрытие в обе стороны, случайные диапазоны, выходные регистры/SP, внутренний вход и DEBUG T. Ожидаемые результаты получены из снимка памяти до копирования.

Ограничения стека: код самомодифицируется при сохранении SP, не реентерабелен, работает при запрещённых прерываниях. Нельзя затрагивать активный стек, выполняемый код или аппаратные регистры. Перенос с оборотом адреса и полный 64-КБ блок не поддерживаются. Конец 10000h можно представить DE=0.

## Исправление отображения буквы диска

После основной серии запрос CHKDSK переведён с bios_getch на штатный bios_input с полем длиной один символ. Буква отображается, выбор подтверждается Enter; подсказка обновлена. Запуск с аргументом не требует дополнительного ввода.

Повторены build: OS, SystemEmu, SystemEmuFlash — без ошибок и предупреждений. check-interface.py проверил запуск из ROM с аргументом и без него, содержимое поля до Enter, переход к проверке после Enter и возврат в NC. Отображение подтверждено визуально: [drive-input.png](drive-input.png). Размер CHKDSK после изменения: 1991 байт. SHA-256: `8e47e8feff6d3e4489c4b4f4eb3ac048c985d2698e76379bd979af466493fbe4`.
