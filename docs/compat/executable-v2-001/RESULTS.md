# COM/EXE и RUN v2 — результат

02.11.2026. Реализованы общий 16-байтный контейнер COM/EXE, нативный исполнитель COM в DOS, стандартный RKS через NC.EXT, общий RUN.COM с MX/STD/RF/MON и меню EXE. Проект source/run заменяет source/launch и отдельный RAMRUN. RAMFOS.MON — сырой 6880-байтный образ двух областей ядра. Утилиты собираются CPU/I80; raw EXE коллекции переименованы в CPU, системные COM упаковываются сборщиком.

FAT хранит точный N и не хранит адрес загрузки. Синхронно изменены загрузка/создание, NC, E, DEBUG, TAPE, DISKBEN и CHKDSK. Новая подготовка/загрузка образа использует C854h/C848h; создание принимает буфер в DE. Нулевые файлы создаются без цепочки. Полная стандартная FAT16 не реализована.

## Проверено

- `build-project.ps1 All`: 8080, ноль ошибок/предупреждений. DOS 6656 байт, конец DA00h; RUN.I80 1822 байта, контейнер RUN.COM 1838 байт.
- Проверка размещения DOS: 77 адресов ABI, нет наложений, шесть отрицательных вариантов отвергнуты. См. layout/.
- Хостовые контейнеры: 24 round-trip для размеров 1,239,240,241,255,256,257,4096; 128 испорченных вариантов отвергнуты; отдельные адреса входа, CPU/I80 и bare CPU проверены. Неподдерживаемая версия не превращается в raw EXE.
- Системный flash 512 КиБ: 22 файла побайтно совпали с преобразованным манифестом. Games2M: 140 файлов, 6568 секторов данных, по 1642 сектора на чип, без общих/потерянных кластеров; контейнеры сохранены.
- Клавиатура NC в отдельном видимом Emu80: 10 контрольных сценариев, все 5 пунктов меню, COM непосредственно через DOS и через RUN, RKS по умолчанию, явные STD и MON:Monitor2. Отдельный вход 1010h при загрузке 1000h; первая область нагрузки намеренно содержит HLT. Результаты и снимки ui/.
- Контрольные программы ожидали клавишу после записи метки, затем выполняли RET. Проверены возврат в NC и холодный старт для MON/RF. Команды не записывались в память, PC/SP не устанавливались; использовался kbd_send без фокуса Windows.
- Enter по BUDI2-MX.EXE через NC.EXT вызвал меню RUN; снимок association-menu.png. Выбор RF для BUDI-RF.EXE вывел игровой экран, rf-keyboard.png. Это проверка запуска, не прохождение игры.
- F5 через клавиатуру: ADSKOK.RKS → UICOPY.RKS на тестовом H:, 18182 байта совпали, стандартный размер N сохранён. См. copy.json.
- E открыл нулевой файл, принял abc и сохранил `61 62 63 0D FF`, DIR_FileSize=5. См. editor.json.
- Статический обход 199 файлов коллекции после переименования: ошибок контейнеров нет. Находки остаются кандидатами, подтверждённая совместимость этим тестом не объявляется.

## Ограничения

DOS пока читает весь контейнер в 0000h–8EFFh, RUN ограничивает исходный файл 8C00h ради переходника. Прямой блочный путь с первым/последним буферным сектором ещё не реализован. Суммы вычисляются один раз при загрузке, не после копирования. MON:custom требует 4096-байтный образ и совместимый пролог Monitor-2. Файловые вызовы загружаемого RAMFOS ещё возвращают отказ, FAT-адаптера нет. Проверки выполнены на модели Emu80; аппаратные тайминги и вся коллекция игр не проверялись.

Исторические исходники LAUNCH/RAMRUN, вспомогательные RKS-модули и старые тесты сохранены в baseline/. Они не являются проверкой RUN v2. Новые проверки — scripts/tests/check-executable-v2.py и scripts/emu80/check-executable-ui.py. Сторонние изменения рабочего дерева не откатывались. docs/ остаётся локальным и игнорируемым Git.
