# Банковый вызов BIOS — 06.11.2026

Реализован принимающий адаптер MAINBIOS в штатном BIOS.SYS и клиент F800h/F806h для исполняемого банка. Само файловое ядро DOS пока остаётся в основной памяти. Тест запускает штатную ОС из пересобранного SystemEmuWritable, проверяет образ адаптера, загруженный bootstrap, затем устанавливает транспорт и CLIENT в собственном остановленном экземпляре. Ввод/запуск NC этим тестом не заменяются: это проверка ABI после обычной загрузки NC.

Проверка: `python scripts/emu80/check-banked-bios.py --report docs/banked/bios-005`. Итог: 60 случаев, включая пакетный F800h и регистровый F806h, точное совпадение AF/BC/DE/HL с прямыми вызовами, строки 20/255/256/521 байт и границу F800h, геометрию/тулбар/инверсию/копирование прямоугольников, ошибки указателей и неподдержанные операции, отказ при повторном входе, GETCH с клавишей Enter и цепочку main→DOS→BIOS→DOS→main. Страница, SP, owner/home, глубина и защитные байты стеков восстановлены. Исходные данные и SHA-256 бинарников: [result.json](result.json); изображение: [bank-bios.png](bank-bios.png).

Принимающий адаптер занимает 861 байт по DA00h–DD5Ch, включая 261 байт буфера; клиент — 152 байта F800h–F897h. Новый BIOS.SYS занимает 7517 байт (C000h–DD5Ch, с промежутками фиксированной карты), DOS.SYS — 15849 байт, как до добавления адаптера. Служебный стек main E400h–E7FFh, банка F400h–F7FFh. Стек, его нижняя граница и начальный SP задаются отдельно по страницам. Общий транспорт по FC00h по-прежнему требует разрешить конфликт хвоста FF00h с прежним сохранением NC и заменить установку старого RAMD перед включением банковой загрузки по умолчанию.

Регистры передаются через кадровый профиль общего окна, без двух вызовов memcpy_far для пакета. Принимающая сторона использует сохранённый локально пакет, поэтому последующий memcpy_far для строки может временно заменить окно. Списки графики до 256 байт предварительно проверяются целиком; ASCIIZ печатаются пачками до 256 байт. Автоматического выбора регистры/короткий буфер/memcpy_far ещё нет; по последнему решению пользователя это отдельный этап.

Контрольные времена из предыдущего прогона того же исполняемого шлюза (bios-003, до включения его бинарника в BIOS.SYS): SETCURSOR 0,4785 мс локально и 2,5465 мс из банка; строка 20 байт 14,9985/26,7895 мс; строка 521 байт 428,1255/472,9510 мс. Это модель Emu80, 8080 2 МГц; измерения включают обвязку API и не являются будущим сравнительным бенчмарком вариантов строкового транспорта. Переход от двух FAR-копий регистров к общему кадру уменьшил добавочную стоимость скалярного вызова с 7,498 до 2,068 мс.

Регрессии: полная сборка OS и SystemEmuWritable без ошибок/предупреждений; проверка размещения BIOS/DOS и 83 случая основного системного диспетчера. Банковый физический обмен после изменения транспорта: 39 случаев в [disk-006](../disk-006/result.json), включая чтение/запись/verify H:, A: и B:, ошибочные параметры и границы страниц. Тестовые эмуляторы запускались видимыми, без звука, и закрывались в finally.

Остаётся для банковой DOS: локальные данные/арифметические процедуры ядра, маршалинг файловых структур и callback, вызовы BIOS вместо прямых обращений к его переменным, переключение загрузчика на банк 0 и исключение этой страницы из RAM-диска. Подключённые к BIOS операции не делают FILEEXEC и CLI автоматически банковыми.
