# SortBench

Самостоятельный нативный MAIN-бенчмарк `SORTBEN.COM` для Intel 8080. Сравнивает Shell, вставки, стабильное слияние, quicksort с разбиением Lomuto и оптимизированный LSD radix. Код сортировок находится здесь; NC не подключает сравнительные методы и не является зависимостью сборки SortBench. `sort-radix.inc` — отдельная копия рабочего radix из NC на момент выделения бенчмарка, которую можно изменять для экспериментов независимо.

## Запуск и результаты

В системном образе: `A:\BENCH\SortBen\SortBen.com`. На первом экране S или Enter выбирает синтетические записи, H — первые N записей корня H:. Затем клавиши 1/2/3/4/5 выбирают 32/64/128/250/255 записей; Enter выбирает 128. Escape на этих экранах завершает программу. Если на H: меньше записей, используется фактическое количество. Контексты H: и выбранный диск восстанавливаются после чтения списка.

Программа последовательно проверяет оба порядка: имя[8]+расширение[3] и расширение[3]+имя[8]. После первой таблицы ожидается Enter; дополнительной очистки экрана между таблицами нет. В протоколе обе таблицы сохраняются подряд. Каталоги идут перед файлами; при равных полных ключах сохраняется исходный порядок. Синтетические записи имеют имена FILE0000…FILE00FE, расширения ASM/TXT/COM/без расширения, каталоги через каждые девять записей и фиксированное перемешивание 8-битным LFSR с seed 5Ah. Записи не переставляются: сортируются байтовые индексы.

Для сравнительных методов измеряются исходный буфер с upperCase при различии байтов и отдельный нормализованный буфер. Прямой CALL компаратора подменяется перед сортировкой по режиму 8+3/3+8. Radix использует нормализованные разряды, пропускает постоянные столбцы, ограничивает диапазон счётчиков и чередует индексные буферы. Время подготовки обоих вариантов ключей выводится отдельно.

ВИ53 настроен на 2 МГц. В измеряемый интервал не входят получение списка DOS, заполнение начального индекса, подготовка ключей и вывод. Шаг таймера обычных методов — 128 мкс; для вставок — 2048 мкс, чтобы не переполняться на больших списках. Выводится время одного прохода в миллисекундах с тремя дробными знаками. Для статистики программу нужно запускать повторно. Пререндер шрифта отключается.

После каждого сравнительного метода проверяется совпадение индексов с radix-эталоном и терминатор FFh. По завершении проверяется контрольная сумма исходных записей; при расхождении выводится BENCHMARK FAILED. Протокол сохраняется в `B:\SORTBEN.TXT`; если B: недоступен, результаты остаются на экране. Последняя клавиша возвращает управление DOS/NC. Данные H: не изменяются.

## Сборка и проверки

`python source-apps/sortbench/build.py` собирает `bin/SORTBEN.i80`, `.cpu`, `.sym` и `.lst` с `--i8080`. В `.i80` находятся код и статические данные; рабочие области не записываются в образ. Сборка входит в `build: OS`, готовый COM-контейнер создаёт сборщик системного образа. Генерируемые варианты сравнения находятся в локальной папке build/.

`python source-apps/sortbench/check.py` проверяет фактический бинарник в модели 8080: оба режима, все методы, исходные/подготовленные ключи, 0/1/255 записей, KOI-8, каталоги с расширениями, совпадающие ключи и внутренние пробелы. Исходные записи дополнительно сравниваются побайтно с входом. Это проверка алгоритмов; пользовательский ввод и сохранение протокола отдельно проверяются через клавиатуру Emu80.

Фиксированные рабочие области MAIN: 4000h–4FFFh — исходные FILE_INFO, 5000h–5FFFh — нормализованная копия, 6000h–70FFh — индексы и ключи, 7200h — эталон индексов, 7300h–7AFFh — текст протокола; стек растёт вниз от 8B00h. Программа проверяет доступность памяти до 8AFFh. Требуются штатные BIOS/DOS MXOS; это отдельная COM-программа, а не автономный загрузочный ROM.

`kernels.inc` также используется хостовым измерителем `scripts/emu80/benchmark-nc-sort.py`; без SORTBEN_STANDALONE он предоставляет остановки для MCP. Хостовый стенд использует собственные входные наборы и многократные PIT-замеры, а интерактивная программа — один проход и выбранный пользователем источник.
