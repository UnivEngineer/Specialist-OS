# CopyBen: near- и межбанковое копирование

Актуальное сравнение размеров запросов, выравнивания, времени жизни COPY и исторических алгоритмов находится в [сводке от 13.11.2026](#сводка-nearfar--13112026). Новая матрица запускается compare.py; benchmark.py и COPYBEN.COM сохраняют отдельные исторические контракты. Старый FAR/R4 для benchmark.py теперь собирается автономно из r4-reference.asm и не подменяется текущим транспортом MEM.

Стенд собирает копировщики отдельно от DOS и запускает их в собственном видимом Emu80 с выключенным звуком. Он не требует исторической сборки ядра или файлов из `docs/`. Полная матрица — автономный ASM-стенд с управляющим Python-сценарием; отдельная COPYBEN.COM описана ниже. В полной матрице при тесте намеренно заменяются окно FFC0h–FFDFh и хвосты выбранных страниц, поэтому после начала измерений файловые функции не вызываются. Эмулятор закрывается в `finally`, в том числе при ошибке. Занятый MCP-порт 19781 не используется.

## Сборка и запуск

```powershell
python source-apps/copybench/build.py
python source-apps/copybench/benchmark.py --runtime .local/monitor2-001 --report docs/banked/copybench-003
python source-apps/copybench/report.py docs/banked/copybench-003
```

Нужны SjASMPlus из `tasm/`, Python, отдельный runtime Emu80 с MCP и собранные штатные системные образы для первоначальной загрузки. Результаты сборки находятся в `bin/copybench/`; прототип FAR собирается отдельно в `bin/banked/`. Каталог отчёта каждый раз выбирается новый: существующий `result.json` не перезаписывается. Старый вход `scripts/emu80/benchmark-banked-copy.py` перенаправляет сюда.

## Варианты

| Имя | Алгоритм |
|---|---|
| Builtin block | Локальная копия встроенного блочного драйвера, прямой побайтовый перенос |
| RAMD R4 | Локальный regs4.inc: четыре байта через BC/DE и SP |
| Builtin byte | Сервисный побайтовый ABI: отдельный CALL на каждый байт |
| stack | Буфер 18 байт в общем окне, POP/PUSH |
| loop | Буфер 12 байт, обычный цикл через аккумулятор |
| unrolled | Буфер 13 байт, развёрнутый цикл через аккумулятор |
| direct | Прямой перенос, развёртка по семь байтов |
| regs2 / regs4 / regs6 | Прямой перенос по 2 / 4 / 6 байтов через регистры |
| CPM16 | Оригинальный копировщик Syabr CP/M 0.1, буфер 16 байт |
| FAR | Зафиксированный R4: `r4-far.inc`, `r4-tail.inc`, общий запрос переноса |

Исторические `.inc` восстановлены из опытов от 31.10.2026: `docs/diskbench/ramd-002/RESULTS.md` и `docs/diskbench/ramd-003/RESULTS.md`. Старые отчёты и исходники сохранены на прежних местах. Удалена только зависимость от установщика тогдашнего DOS; установку окон и хвостов выполняет стенд. `regs4.inc` представляет RAMD R4. Встроенные варианты зафиксированы в `builtin_block.inc` и `builtin_byte.inc` по исходникам от 06.11.2026; оба занимают ровно 32 байта. Ни COPYBEN.COM, ни полная матрица не выбирают эти реализации из текущего BIOS: устанавливаются локальные копии. R4 FAR зафиксирован в r4-far.inc/r4-tail.inc/r4-abi.inc перед переходом системного транспорта на CPM16; строки R4 в COPYBEN сохраняют прежний смысл. Рабочий CPM16 проверяется отдельным check-banked-transport.py.

`CPMCOPY.asm` восстановлен из `CPM/CPM.RKS` внешнего архива `syabr-cpm-0.1.zip`: блок загрузочного образа 3900h–39A3h, исполняемый по FF00h. Сборка побайтно воспроизводит все 164 байта, включая слово сохранённого SP. Внутреннее представление страниц CP/M: FFh — основная память, 0…7 — физические страницы ДОЗУ. Исходный архив для сборки стенда не нужен.

## Методика

Основные размеры — 256 байт и 8 КиБ, чтение и запись между main и страницей ДОЗУ. CPM16 и FAR дополнительно проверяются для переноса между двумя страницами из третьей. В JSON логическая страница 0 означает main, 1…16 — физические страницы ДОЗУ 0…15. Для FAR также измеряются короткие запросы. Установка кода и первоначального профиля исключена из измерения; подготовка параметров каждого вызова включена. FAR дополнительно сохраняет и восстанавливает все 32 байта окна и проверяет запрос. CPM16 этого не делает, а размер должен быть положительным и кратным 16.

Три повтора обязаны дать одинаковое количество тактов CPU. Данные проверяются побайтно после каждого переноса, также проверяются SP и защитные байты перед и после назначения. Измерение использует такты эмулируемого CPU, не время хоста. Время вычисляется для 2 МГц, скорость — десятичные кБ/с. `result.json` содержит параметры, отдельные повторы и SHA-256 бинарников. Это модель Emu80, не измерение физического оборудования.

Исторические таблицы включали полную обёртку C863h и использовали КиБ/с, а этот стенд измеряет непосредственные вызовы копировщиков с собственным циклом. Числа разных методик нельзя сравнивать без поправки на обвязку и единицы.

Граничные случаи FAR, вложенность, сохранность стандартного окна и контекста отдельно проверяются командой `python scripts/emu80/check-banked-transport.py --report docs/banked/transport-new`. Сравнение сохранённых результатов поддерживает `scripts/emu80/compare-banked-performance.py`.


## COPYBEN.COM на самом компьютере

COPYBEN.COM входит в штатную сборку OS и манифест системного диска A:. Запуск: `A:\COPYBEN.COM`. Программа сравнивает прямой ROM→RAMD с ROM→main→Builtin block и ROM→main→Builtin byte на 8192 байтах. Затем измеряет RAM→RAMD и RAMD→RAM для Builtin block, Builtin byte, stack, loop, unrolled, direct, regs2, RAMD R4, regs6 и CPM16. Дополнительно сравнивает R4 и CP/M в блочном и универсальном вариантах для main↔RAMD и RAMD→RAMD. Всего 35 замеров в 21 строке: RAM→RAMD и RAMD→RAM выводятся парой через `/`, первое число — запись, второе — чтение. Каждое число появляется сразу после собственного замера и побайтовой проверки. `!` после первого числа означает ошибку записи; статус в конце парной строки относится к чтению. CLK1 таймера должен быть 2 МГц.

Используется системный ROM через FFFEh: страница 0, адреса 2000h–3FFFh; это не внешний ROM-диск H:. Приёмник — 4000h–5FFFh последней обнаруженной страницы ДОЗУ. Исходные данные приёмника, оба хвоста FF00h–FFBFh и все 32 байта окна сохраняются до тестов и восстанавливаются после последнего замера. ROM/flash не программируется. Восстановление рассчитано на нормальное завершение теста; принудительный сброс во время переноса прервёт его.

Тест освобождает DOSMOD и требует основную память до 88FFh. Для контрольного чтения используется буфер 8800h–88FFh: при включённом ROM нижняя половина main RAM недоступна для записи. Сохранение и восстановление RAM, проверка данных и печать не входят во время переноса. Для ROM замер включает подготовку окна; в тестах RAM↔RAMD установка кода и окна выполняется до замера. Перед записью приёмник заполняется инверсией эталона, перед чтением инвертируется буфер main: пустой перенос не может пройти проверку. После результатов программа ждёт клавишу и возвращается в оболочку.

Короткие запросы FAR и вызов из третьей страницы ДОЗУ измеряются отдельным `benchmark.py`. Перенос между двумя банками с инициатором в main также включён в COPYBEN.COM. COPYBEN.COM содержит локальные копии исторических алгоритмов и CP/M; системная сборка генерирует их бинарные образы через `build.py`.


Повторяемая проверка запуска из NC: `python source-apps/copybench/check-native.py --report docs/bench/copyben-rom-new`. Она вводит COPYBEN клавишами эмулятора, проверяет восстановление исходных данных банка, обоих хвостов и общего окна, сохраняет снимок результатов. Полная матрица с локальными копиями: docs/bench/copybench-local-001/RESULTS.md.

Строки интерфейса, названия вариантов и пробельные отступы находятся в `text.inc`; генератор их не перезаписывает. Измерения подключают общие `sdk/asm/lib/timing.inc` и `timing-ms.inc` напрямую, без зависимости от проекта diskbench. Ширина целой части числа задаётся `TIMING_NUMBER_WIDTH` в `COPYBEN.asm`.

### Блочный и универсальный контракты

Строки `Regs R4` и `CP/M buf16` оставлены как исторические ориентиры: первая вызывает специальный 256-байтный драйвер main↔RAMD 32 раза, вторая вызывает исходный CP/M один раз на 8192 байта, кратные 16. Они не представляют одинаковый ABI. Остальные исторические секторные варианты тоже остаются в таблице.

Новая матрица `enginetests.inc` сравнивает четыре входа из `copyengines.inc` и общего FAR/R4. Во всех направлениях используются один запрос на 8192 байта либо 32 запроса по 256 байт. Инициатор — main. Новые R4-входы используют одинаковую схему двух переключателей для всех направлений; исторический драйвер `Regs R4` специализирован для main↔RAMD и может быть быстрее.

| Строка | Контракт |
|---|---|
| R4 blk256 | Ровно 256 байт; источник выровнен по 256; SP сохранён, остальные регистры разрушены, окно рабочее |
| CPM blk256 | Ровно 256 байт через 16 порций исходного CP/M; тот же внешний блочный контракт |
| R4 univ | Произвольная длина и выравнивание; зафиксированный `r4-far.inc` и `r4-tail.inc` |
| CPM univ | Полные 16-байтные порции исходного CP/M и точный побайтовый остаток 1–15 байт |

У универсальных входов одинаковый пакет `{srcPage, srcOffset:word, dstPage, dstOffset:word, count:word}`, логические страницы 0=main, 1–16=ДОЗУ. Они проверяют номера страниц и границы до FF00h, поддерживают нулевой запрос, сохраняют BC/DE/HL, SP и все 32 байта окна. A=0/CF=0 при успехе; E0h/CF=1 — недопустимая страница, E2h/CF=1 — недопустимый диапазон. Пересечение диапазонов запрещено контрактом memcpy, не проверяется. Прерывания должны быть выключены; код, стек и состояние не должны входить в переносимые диапазоны. CP/M-обёртка пока предназначена только для инициатора main, это внутренний тестовый вход, не опубликованный ABI BIOS.

Блочные входы не выполняют универсальные проверки и не сохраняют окно или регистры данных: это обязанность вызывающего драйвера. Хвосты устанавливаются заранее вне замера. Параметры, рабочее переключение окна, вызовы и возвраты входят в замер; резервное копирование, инверсия назначения, проверка и восстановление RAM-диска — нет.

Межбанковый тест переносит 4000h–5FFFh из последней обнаруженной страницы в предпоследнюю; при одной странице пропускается. В main находятся только резервные копии, данные передаются непосредственно через регистры R4 или 16-байтное общее окно CP/M. Перед каждым замером назначение инвертируется относительно источника, затем проверяется побайтно. Исходные данные и хвосты обеих страниц, хвост main и исходное окно восстанавливаются после испытаний. Файловые операции при подменённых хвостах запрещены.

Проверка интерфейса и восстановления: `python source-apps/copybench/check-native.py --report docs/bench/copyben-new`. Отдельная проверка алгоритмов и ABI: `python source-apps/copybench/check-engines.py --report docs/bench/copyengines-new` (загружает тестовый код напрямую, не считается проверкой UI). Последняя проверяет длины 0, 1, 3, 4, 15, 16, 17, 255, 256, 257, 8191, 8192, невыровненные адреса, сохранение источника и защитных байтов, ошибки страницы/диапазона, окно, регистры и SP. Оба сценария используют собственный видимый Emu80 без звука и закрывают его в finally.

Приложение настраивает ВИ53 через `lib/timing-pit.inc` и читает убывающий счётчик прямым `CALL io_pitRead`. Отсчёт занимает 71 такт 8080 вместе с CALL и RET в MAIN и в исполняемом банке. [Интерфейс измерительного таймера](../../sdk/asm/lib/timing.md)

## Сводка near/far — 13.11.2026

Все скорости в следующих таблицах — **КиБ/с (1024 байта)** при 2 МГц. Near измерен на CPU-модели Intel 8080 z88dk-ticks, far — на модели Emu80; это не замеры физического оборудования. По три повтора с одинаковыми тактами; проверены данные, неизменность источника, защитные байты и SP. Для far также проверено восстановление COMMAND после серии. Чтения таймера внутри передающего цикла нет: учитывается целиком интервал исполнения CPU, включая подготовку каждого запроса.

### Near: один адресный контекст

Основная таблица: источник 2000h, назначение 5000h, области не пересекаются. Вызовы серии развёрнуты в стенде; каждый заново загружает параметры, поэтому цена CALL/RET и подготовки не скрыта. У специальных 256-байтных входов нет универсальных проверок и сохранения регистров данных; SP сохраняется. Знак «—» означает, что контракт не поддерживает один вызов на 8 КиБ.

| Алгоритм | 256 Б | 8 КиБ одним вызовом | 32 × 256 Б | Ограничение |
|---|---:|---:|---:|---|
| byte | 40.39 | 40.68 | 40.45 | Обычный побайтовый цикл |
| BIOS memmove | 95.24 | 105.09 | 95.59 | Универсальный, выбор направления |
| BIOS forward | 101.01 | 108.12 | 101.41 | Непересекающиеся области |
| stack256 | 105.22 | — | 105.65 | Фиксированные 256 Б, любой адрес |
| stack256 aligned | 107.18 | — | 107.63 | Назначение xx00h |
| byte256 aligned x8 | 76.44 | — | 76.67 | Назначение xx00h, разворот ×8 |

Общий BIOS memmove при назначении выше источника выбирает обратное направление даже без перекрытия. При копировании 9000h → 3000h он идёт вперёд и даёт 108.02 КиБ/с на 8 КиБ. Прямой forward-вход исключает этот выбор. Смещения 00h/01h и F0h/FCh проверены отдельно: выравнивание само по себе не ускоряет POP/PUSH или MOV на 8080. Специализированный alignedStack256 экономит счётчик: INC L стоит те же 5 тактов, что INX H, но формирует Z; на 16 байт исчезает DEC B. Разбиение большого near-переноса на отдельные вызовы по 256 байт не является безусловным ускорением.

### Far: подготовка, порции и время жизни COPY

Основная таблица: MAIN → DATA, 2000h → 4000h. «COPY» — профиль сохраняется между 32 вызовами, COMMAND восстанавливается один раз в конце; «COMMAND» — восстановление после каждого сектора. Построение всех FAR-пакетов и финальное восстановление входят в замер. Установка экспериментального кода в страницы выполняется до измерения, но дублирование рабочих параметров CPU в оба хвоста входит в каждый вызов.

| Алгоритм | 256 Б | 8 КиБ одним вызовом | 32 × 256, COPY | 32 × 256, COMMAND |
|---|---:|---:|---:|---:|
| MEM | 37.21 | 50.44 | 43.56 | 37.26 |
| CPM original | 44.13 | 45.25 | 44.21 | — |
| local16 | 32.26 | 51.26 | 38.85 | 32.30 |
| local32 | 35.32 | 59.79 | 43.37 | 35.36 |
| local32 aligned256 | 36.05 | — | 44.48 | 36.10 |
| local32 aligned batch | 36.64 | 61.54 | 45.39 | 36.70 |

Контракты различаются. MEM — действующий проверяющий FAR-вход, ленивое сохранение COMMAND и точный размер. Для физического ROM используется доверенный внутренний вход, а не публичный FAR-код. CPM original — исторический CP/M, положительный размер кратен 16, окно не сохраняется; поэтому колонки его серии показывают сырую цену без COMMAND. local16/local32 — приватные прототипы: размер кратен порции, границы и страницы гарантирует стенд; параметры находятся в хвостах источника/назначения. Начальный source selector также записывается в хвост инициатора, если он третий. local32 aligned256 требует ровно 256 байт и выровненный источник. local32 aligned batch принимает целые 256-байтные секторы одним вызовом: младший C завершает сектор, B увеличивается один раз на сектор, отдельный счётчик считает секторы. Эти прототипы не установлены в MEM.SYS.

Проверены MAIN↔DATA, DATA→DATA с третьим инициатором, ROM→DATA и ROM→верхняя MAIN; младшие адреса 00h/01h/F0h/FCh, пересечение страницы и пакеты на 256 Б/8 КиБ. У байтового счётчика aligned-варианта ограничение выравнивания обязательно; это отдельный контракт, а не ускорение любого адреса. Полные матрицы не смешивают направления, даже когда показатели совпадают.

Исторический near memcpy из 5e83e32, совпадающий по инструкциям с вариантом 2022 года, давал 27.51 КиБ/с на 16 КиБ (CPU-модель 04.11.2026, CALL/RET включены, загрузка регистров исключена). Это контроль медленного цикла с CALL сравнения на каждом байте, не нынешний byteCopy из первой таблицы. В полном DOS-замере от 31.10.2026 R4 давал 44,675/42,287 КиБ/с чтения/записи; отличие от автономной строки выше связано с обёрткой DOS и измерением ВИ53 с дополнительными 198 тактами на операцию. Эти цифры не следует смешивать или объявлять регрессией чистого движка.

Исходные исторические такты, методика и SHA-256 сохранены в [reference.json](reference.json); сборка восьми локальных исторических образов проверена на совпадение с этими SHA-256. Десятичные кБ/с старых отчётов здесь не используются. Старые таблицы и комментарии README выше оставлены как история прежнего стенда; единицы и контракты актуального сравнения задаёт этот раздел.

### Практический выбор

Для непересекающегося near-диапазона сначала использовать готовый прямой стековый копировщик и передавать весь диапазон одним вызовом. Не заменять его побайтовым циклом только ради выравнивания. Специальный секторный вход сравнивать с прямым входом на том же размере, включая подготовку. Для far передавать максимальную доступную пачку и сохранять COPY до конца серии; стоимость COMMAND нельзя прятать за границей замера. Увеличение полезной порции окна проверять отдельно от цены дублирования параметров: local16/local32 отличаются именно шириной порции при одной обвязке. Ограниченные aligned-входы не подменяют универсальный memcpy_far.

### Воспроизведение

```powershell
python source-apps/copybench/build.py
python source-apps/copybench/check-local.py --out docs/bench/copyben-new/cpu
python source-apps/copybench/compare.py --report docs/bench/copyben-new --runtime .local/rom-pio-19782 --port 19782
python source-apps/copybench/compare-report.py --report docs/bench/copyben-new --update-readme
```

Для повторного входа после прерывания far-матрицы используется --stage far --resume; исходники и замороженные входы должны оставаться теми же, SHA-256 бинарников проверяются по far-builds.json. --algorithms ограничивает список вариантов. --port задаёт клиентский адрес уже настроенного MCP-сервера, не меняет порт EXE Emu80. Эмулятор собственный, видимый, muted; занятый порт не используется, процесс закрывается в finally. После подмены хвостов запрещены файловые вызовы и возврат в NC: отдельный процесс закрывается целиком. Это ABI-стенд, не проверка интерфейса запуска COPYBEN.COM. Near-часть запускается отдельно через --stage near и не открывает эмулятор.

## Производственный CPM32, 13 ноября 2026

memcpy_far переведён на CPM32: все 32 байта окна заняты данными, селекторы и счётчики находятся в локальных хвостах. Адреса произвольные; остаток 1–31 байт не читает за границей. Секторный путь 256 байт сохранён, длинный запрос использует тот же движок с одной подготовкой на весь участок. Это отдельный замер производственного кода, историческая большая таблица выше остаётся снимком прежних реализаций.

| Движок, MAIN инициирует DATA → EXEC | 256 байт | 8 КиБ одним вызовом |
|---|---:|---:|
| Прежний CPM16 | 40.80 КиБ/с | 50.63 КиБ/с |
| CPM32 | 40.46 КиБ/с | 60.13 КиБ/с |

Emu80, 8080 2 МГц, невыровненные адреса xx01, время включает публичный вызов и подготовку, COPY остаётся активным. На отдельном секторе выигрыша нет; на длинном блоке — около 19%. Проверены реальные MAIN/EXEC/DATA/ROM, данные, границы, регистры и SP. Воспроизведение: scripts/emu80/check-cpm32.py с отдельным видимым muted runtime; CPU-границы — scripts/tests/check-cpm32.py. Стоимость подготовки отдельно измеряет scripts/tests/measure-mem-copy-setup.py.

Для 8 КиБ доверенный вход готовится за 3750 тактов из COMMAND или 2825 при уже активном COPY: 1.875/1.413 мс при 2 МГц. Это включает установку параметров в обоих хвостах, а не только смену профиля. Возврат COPY → COMMAND стоит 1184 такта (0.592 мс); уже активный COMMAND — 58 тактов. Пакетный FILEHANDLE теперь использует эти длинные переносы; промежуточные данные полного сектора через буфер DOS не идут. Bootstrap и перенос старого DATA-хвоста требуют отдельного завершения и этим замером не проверены.
