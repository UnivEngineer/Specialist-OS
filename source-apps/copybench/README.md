# Автономный бенчмарк межстраничных копировщиков

Стенд собирает копировщики отдельно от DOS и запускает их в собственном видимом Emu80 с выключенным звуком. Он не требует исторической сборки ядра или файлов из `docs/`. Полная матрица — автономный ASM-стенд с управляющим Python-сценарием; отдельная COPYBEN.COM описана ниже. В полной матрице при тесте намеренно заменяются окно FFC0h–FFDFh и хвосты выбранных страниц, поэтому после начала измерений файловые функции не вызываются. Эмулятор закрывается в `finally`, в том числе при ошибке. Занятый MCP-порт 19781 не используется.

## Сборка и запуск

```powershell
python source-apps/copybench/build.py
python source-apps/copybench/benchmark.py --runtime .local/monitor2-001 --report docs/banked/copybench-003
python source-apps/copybench/report.py docs/banked/copybench-003
```

Нужны SjASMPlus из `tasm/`, Python, отдельный runtime Emu80 с MCP и собранные штатные системные образы для первоначальной загрузки. Результаты сборки находятся в `bin/copybench/`; прототип FAR собирается отдельно в `bin/banked/`. Каталог отчёта каждый раз выбирается новый: существующий `result.json` не перезаписывается. Старый вход `scripts/emu80/benchmark-banked-copy.py` перенаправляет сюда.

## Варианты

| Имя | Алгоритм |
|---|---|
| Builtin block | Локальная копия встроенного блочного драйвера, прямой побайтовый перенос |
| RAMD R4 | Локальный regs4.inc: четыре байта через BC/DE и SP |
| Builtin byte | Сервисный побайтовый ABI: отдельный CALL на каждый байт |
| stack | Буфер 18 байт в общем окне, POP/PUSH |
| loop | Буфер 12 байт, обычный цикл через аккумулятор |
| unrolled | Буфер 13 байт, развёрнутый цикл через аккумулятор |
| direct | Прямой перенос, развёртка по семь байтов |
| regs2 / regs4 / regs6 | Прямой перенос по 2 / 4 / 6 байтов через регистры |
| CPM16 | Оригинальный копировщик Syabr CP/M 0.1, буфер 16 байт |
| FAR | Текущий `source/banked/copy.inc` и `copytail.inc`, общий запрос переноса |

Исторические `.inc` восстановлены из опытов от 31.10.2026: `docs/diskbench/ramd-002/RESULTS.md` и `docs/diskbench/ramd-003/RESULTS.md`. Старые отчёты и исходники сохранены на прежних местах. Удалена только зависимость от установщика тогдашнего DOS; установку окон и хвостов выполняет стенд. `regs4.inc` представляет RAMD R4. Встроенные варианты зафиксированы в `builtin_block.inc` и `builtin_byte.inc` по исходникам от 06.11.2026; оба занимают ровно 32 байта. Ни COPYBEN.COM, ни полная матрица не выбирают эти реализации из текущего BIOS: устанавливаются локальные копии. Текущий экспериментальный FAR, напротив, намеренно берётся из source/banked, чтобы измерять его развитие.

`CPMCOPY.asm` восстановлен из `CPM/CPM.RKS` внешнего архива `syabr-cpm-0.1.zip`: блок загрузочного образа 3900h–39A3h, исполняемый по FF00h. Сборка побайтно воспроизводит все 164 байта, включая слово сохранённого SP. Внутреннее представление страниц CP/M: FFh — основная память, 0…7 — физические страницы ДОЗУ. Исходный архив для сборки стенда не нужен.

## Методика

Основные размеры — 256 байт и 8 КиБ, чтение и запись между main и страницей ДОЗУ. CPM16 и FAR дополнительно проверяются для переноса между двумя страницами из третьей. В JSON логическая страница 0 означает main, 1…16 — физические страницы ДОЗУ 0…15. Для FAR также измеряются короткие запросы. Установка кода и первоначального профиля исключена из измерения; подготовка параметров каждого вызова включена. FAR дополнительно сохраняет и восстанавливает все 32 байта окна и проверяет запрос. CPM16 этого не делает, а размер должен быть положительным и кратным 16.

Три повтора обязаны дать одинаковое количество тактов CPU. Данные проверяются побайтно после каждого переноса, также проверяются SP и защитные байты перед и после назначения. Измерение использует такты эмулируемого CPU, не время хоста. Время вычисляется для 2 МГц, скорость — десятичные кБ/с. `result.json` содержит параметры, отдельные повторы и SHA-256 бинарников. Это модель Emu80, не измерение физического оборудования.

Исторические таблицы включали полную обёртку C863h и использовали КиБ/с, а этот стенд измеряет непосредственные вызовы копировщиков с собственным циклом. Числа разных методик нельзя сравнивать без поправки на обвязку и единицы.

Граничные случаи FAR, вложенность, сохранность стандартного окна и контекста отдельно проверяются командой `python scripts/emu80/check-banked-transport.py --report docs/banked/transport-new`. Сравнение сохранённых результатов поддерживает `scripts/emu80/compare-banked-performance.py`.


## COPYBEN.COM на самом компьютере

COPYBEN.COM входит в штатную сборку OS и манифест системного диска A:. Запуск: `A:\COPYBEN.COM`. Программа сравнивает прямой ROM→RAMD с ROM→main→Builtin block и ROM→main→Builtin byte на 8192 байтах. Затем измеряет RAM→RAMD и RAMD→RAM для Builtin block, Builtin byte, stack, loop, unrolled, direct, regs2, RAMD R4, regs6 и CPM16. Дополнительно сравнивает R4 и CP/M в блочном и универсальном вариантах для main↔RAMD и RAMD→RAMD. Всего 35 замеров в 21 строке: RAM→RAMD и RAMD→RAM выводятся парой через `/`, первое число — запись, второе — чтение. Каждое число появляется сразу после собственного замера и побайтовой проверки. `!` после первого числа означает ошибку записи; статус в конце парной строки относится к чтению. CLK1 таймера должен быть 2 МГц.

Используется системный ROM через FFFEh: страница 0, адреса 2000h–3FFFh; это не внешний ROM-диск H:. Приёмник — 4000h–5FFFh последней обнаруженной страницы ДОЗУ. Исходные данные приёмника, оба хвоста FF00h–FFBFh и все 32 байта окна сохраняются до тестов и восстанавливаются после последнего замера. ROM/flash не программируется. Восстановление рассчитано на нормальное завершение теста; принудительный сброс во время переноса прервёт его.

Тест освобождает DOSMOD и требует основную память до 88FFh. Для контрольного чтения используется буфер 8800h–88FFh: при включённом ROM нижняя половина main RAM недоступна для записи. Сохранение и восстановление RAM, проверка данных и печать не входят во время переноса. Для ROM замер включает подготовку окна; в тестах RAM↔RAMD установка кода и окна выполняется до замера. Перед записью приёмник заполняется инверсией эталона, перед чтением инвертируется буфер main: пустой перенос не может пройти проверку. После результатов программа ждёт клавишу и возвращается в оболочку.

Короткие запросы FAR и вызов из третьей страницы ДОЗУ измеряются отдельным `benchmark.py`. Перенос между двумя банками с инициатором в main также включён в COPYBEN.COM. COPYBEN.COM содержит локальные копии исторических алгоритмов и CP/M; системная сборка генерирует их бинарные образы через `build.py`.


Повторяемая проверка запуска из NC: `python source-apps/copybench/check-native.py --report docs/bench/copyben-rom-new`. Она вводит COPYBEN клавишами эмулятора, проверяет восстановление исходных данных банка, обоих хвостов и общего окна, сохраняет снимок результатов. Полная матрица с локальными копиями: docs/bench/copybench-local-001/RESULTS.md.

Строки интерфейса, названия вариантов и пробельные отступы находятся в `text.inc`; генератор их не перезаписывает. Измерения подключают общие `source/include/timing.inc` и `timing-ms.inc` напрямую, без зависимости от проекта diskbench. Ширина целой части числа задаётся `TIMING_NUMBER_WIDTH` в `COPYBEN.asm`.

### Блочный и универсальный контракты

Строки `Regs R4` и `CP/M buf16` оставлены как исторические ориентиры: первая вызывает специальный 256-байтный драйвер main↔RAMD 32 раза, вторая вызывает исходный CP/M один раз на 8192 байта, кратные 16. Они не представляют одинаковый ABI. Остальные исторические секторные варианты тоже остаются в таблице.

Новая матрица `enginetests.inc` сравнивает четыре входа из `copyengines.inc` и общего FAR/R4. Во всех направлениях используются один запрос на 8192 байта либо 32 запроса по 256 байт. Инициатор — main. Новые R4-входы используют одинаковую схему двух переключателей для всех направлений; исторический драйвер `Regs R4` специализирован для main↔RAMD и может быть быстрее.

| Строка | Контракт |
|---|---|
| R4 blk256 | Ровно 256 байт; источник выровнен по 256; SP сохранён, остальные регистры разрушены, окно рабочее |
| CPM blk256 | Ровно 256 байт через 16 порций исходного CP/M; тот же внешний блочный контракт |
| R4 univ | Произвольная длина и выравнивание; общий экспериментальный `source/banked/copy.inc` и `copytail.inc` |
| CPM univ | Полные 16-байтные порции исходного CP/M и точный побайтовый остаток 1–15 байт |

У универсальных входов одинаковый пакет `{srcPage, srcOffset:word, dstPage, dstOffset:word, count:word}`, логические страницы 0=main, 1–16=ДОЗУ. Они проверяют номера страниц и границы до FF00h, поддерживают нулевой запрос, сохраняют BC/DE/HL, SP и все 32 байта окна. A=0/CF=0 при успехе; E0h/CF=1 — недопустимая страница, E2h/CF=1 — недопустимый диапазон. Пересечение диапазонов запрещено контрактом memcpy, не проверяется. Прерывания должны быть выключены; код, стек и состояние не должны входить в переносимые диапазоны. CP/M-обёртка пока предназначена только для инициатора main, это внутренний тестовый вход, не опубликованный ABI BIOS.

Блочные входы не выполняют универсальные проверки и не сохраняют окно или регистры данных: это обязанность вызывающего драйвера. Хвосты устанавливаются заранее вне замера. Параметры, рабочее переключение окна, вызовы и возвраты входят в замер; резервное копирование, инверсия назначения, проверка и восстановление RAM-диска — нет.

Межбанковый тест переносит 4000h–5FFFh из последней обнаруженной страницы в предпоследнюю; при одной странице пропускается. В main находятся только резервные копии, данные передаются непосредственно через регистры R4 или 16-байтное общее окно CP/M. Перед каждым замером назначение инвертируется относительно источника, затем проверяется побайтно. Исходные данные и хвосты обеих страниц, хвост main и исходное окно восстанавливаются после испытаний. Файловые операции при подменённых хвостах запрещены.

Проверка интерфейса и восстановления: `python source-apps/copybench/check-native.py --report docs/bench/copyben-new`. Отдельная проверка алгоритмов и ABI: `python source-apps/copybench/check-engines.py --report docs/bench/copyengines-new` (загружает тестовый код напрямую, не считается проверкой UI). Последняя проверяет длины 0, 1, 3, 4, 15, 16, 17, 255, 256, 257, 8191, 8192, невыровненные адреса, сохранение источника и защитных байтов, ошибки страницы/диапазона, окно, регистры и SP. Оба сценария используют собственный видимый Emu80 без звука и закрывают его в finally.
