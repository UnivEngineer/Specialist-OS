# Проверка публичного API модулей

`RELTEST.COM` проверяет v3 на исходном MX с одним банком ДОЗУ. Поместите в текущий каталог RELOCA.DLL (WORD16, REUSABLE), RELOCB.DLL (HIGH8) и запустите RELTEST.COM. Контроллер одновременно загружает две MAIN DLL, чередует вызовы, проверяет раздельные счётчики и BSS, выгружает обе и повторно вызывает прежний экземпляр RELOCA через тёплую активацию. Выводит `Relocatable MAIN DLLs PASS` при успехе, сохраняет 55AAh по символу testResult и ждёт клавишу.

Для отдельной тестовой дискеты после сборки MX и `python source-apps/moduletest/build.py` выполните `python source-apps/moduletest/prepare-floppy.py docs/dos/relocatable-test/MX-with-reltest.img`. На MX2 проверка `python scripts/emu80/check-relocatable-modules.py --port 19782` дополнительно выполняет RELOCD в DOS и RELOCE в EXEC, проверяет отказы на повреждённых файлах, освобождение записей и смещение MAIN DLL с занятого места. Протокол содержит фактические адреса и время публичных LOAD/CALL в тактах эмулятора. Используйте свободный MCP-слот.

Команда сборки `python source-apps/moduletest/build.py` создаёт в `bin/moduletest` файлы BANKMOD.DLL (загрузка 0100h), MAINMOD.DLL (6000h), DOSMOD.DLL (арена DOS), MRET.DLL и контроллер MODTEST.COM (0000h). Контейнеры DLL и COM имеют 32-байтный заголовок MXOS2 v2. Модули предназначены для moduleLoad/moduleCall, а MODTEST запускается как программа MAIN.

После копирования MODTEST.COM и DLL на B: запустить B:\MODTEST.COM из NC/CLI. Контроллер регистрирует main-арену 6000h–7FFFh, загружает BANKMOD в свободный EXEC-банк, вызывает через локальный MX_REGS, проверяет результат, выгружает; затем повторяет для MAINMOD и DOSMOD. На успехе пишет Module API PASS и ждёт клавишу. После RET оболочка восстанавливается обычным загрузчиком. На малой машине должен быть хотя бы один свободный DATA-банк, не занятый DOS/B:.

Стенд `scripts/emu80/check-modules.py` готовит файлы на B: видимого Emu80 через файловый API DOS. Укажите выделенные `--runtime` и `--port`. Стенд выбирает NC_MN в тестовой копии AUTOEXEC, проверяет вложенные вызовы, владельцев памяти, дескрипторы, RETAIN, Reset, C SDK и ввод MODTEST с клавиатуры. Параметр `--system` принимает готовый образ после сверки с бинарниками ядра, BIOS и NC в bin. Результаты остаются в `.local/modules-dos`.

Обычный запуск проверяет отказ BIOS 01FFh в MAIN и BANK, затем принудительную перезагрузку DOS с обнулением `v_dosModuleReady`. Чтобы отдельно проверить оставшиеся группы, `--main-bios-reserved-slot` проверяет отказ BIOS на пустом слоте 0102h в MAIN, а `--hardware-reset-only` использует аппаратный Reset с действующим DOS. Стенд сохраняет пропуски этих двух проверок в результате JSON.

MODULE.asm собирается тремя способами с MAIN_MODULE=0/1/2 для BANK/MAIN/DOS. A=0 проверяет регистры; A=1 вызывает BIOS и DOS; A=2 оставляет выделение для очистки при unload; A=3 пытается выгрузить активный handle из HL; A=4 получает обработанный отказ BIOS; A=5 загружает, вызывает и выгружает MRET; A=6 пишет слово DE по FAR-адресу B:HL; A=7 возвращает mx_memInfo; A=8 оставляет дочерний MRET для рекурсивной очистки; A=12 читает 37 байт README.TXT через FILEHANDLE в локальный буфер. Номера относятся только к тестовому модулю, не к ABI ядра.


BANKAPP.asm — самостоятельное банковое COM/EXE-приложение с `IMAGE_FLAGS = IMAGE_FLAG_BANK`. Штатный FILE_EXEC получает `B:\BANKAPP.COM Test arguments`, выделяет EXEC-банк и передаёт DE как локальный указатель на `Test arguments`. Приложение проверяет назначение банка, печатает аргументы через BIOS, выделяет FAR-блок и возвращается RET; DOS освобождает этот блок вместе с образом. Тест упаковывает одно тело также в EXE и проверяет оба расширения, включая ввод через редактор NC. DLL с BANK также допустим, но только для MODULE_TARGET_BANK.


MAINAPP.COM (MAIN=04h) загружается по 0000h и затирает нижний RUN. DOSAPP.COM (DRIVER=01h) проверяет выполнение инициализатора в банке DOS. scripts/emu80/check-run-native.py использует также EXE-копии и нейтральные UNKNOWN.COM/EXE для проверки прямого запуска DOS, меню явного RUN и запуска с указанным режимом. Опция --std-only проверяет RET после STD. MAINMOD.DLL помечен MAIN и отвергается при попытке загрузить его в EXEC-банк.

DOSMOD.DLL собран с MAIN_MODULE=2 и DRIVER-флагом по DOS_BANK_DRIVER_ADDR. A=9 вызывает RETAIN с ключом 4444h, A=10 проверяет конфликт с фиксированным DOSAPP.EXE, A=11 читает загрузочный сектор в локальный 512-байтный буфер и возвращает размер сектора в HL. A=12 читает 37 байт из README.TXT на системном диске. DRVPROBE.COM проверяет обратный конфликт, вызывая MODULE_LOAD DOS из работающего DRIVER-инициализатора. При пересечении DOS возвращает ACTIVE и сохраняет код инициализатора.
