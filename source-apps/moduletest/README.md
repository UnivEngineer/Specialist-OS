# Проверка публичного API модулей

Сборка: python source-apps/moduletest/build.py. Результаты в bin/moduletest: BANKMOD.DLL (загрузка 0100h), MAINMOD.DLL (6000h), DOSMOD.DLL (арена DOS), MRET.DLL и контроллер MODTEST.COM (0000h). Это штатные 16-байтные COM-контейнеры, а не вручную скопированный код. Модули предназначены для moduleLoad/moduleCall, а MODTEST — обычная main-программа. Они не меняют аппаратное окно и не используют адреса внутренних процедур MEM/DOS.

После копирования MODTEST.COM и DLL на B: запустить B:\MODTEST.COM из NC/CLI. Контроллер регистрирует main-арену 6000h–7FFFh, загружает BANKMOD в свободный EXEC-банк, вызывает через локальный MX_REGS, проверяет результат, выгружает; затем повторяет для MAINMOD и DOSMOD. На успехе пишет Module API PASS и ждёт клавишу. После RET оболочка восстанавливается обычным загрузчиком. На малой машине должен быть хотя бы один свободный DATA-банк, не занятый DOS/B:.

Проверка python scripts/emu80/check-modules.py готовит файлы на B: своего изолированного видимого эмулятора через файловый API DOS. До неё собрать OS, SystemEmuWritable и эти примеры. Порт 19781 должен быть свободен. Стенд проверяет API, включая ошибки, вложенные BIOS/DOS, дочерние модули, очистку, Reset, C SDK и нормальный запуск MODTEST через клавиатуру NC. Тестовые файлы и результат JSON остаются в .local/modules-dos; тестовый эмулятор закрывается в finally. FONTBEN/TEXTBEN этот стенд не изменяет.

MODULE.asm собирается тремя способами с MAIN_MODULE=0/1/2 для BANK/MAIN/DOS. A=0 проверяет регистры; A=1 вызывает BIOS и DOS; A=2 оставляет выделение для очистки при unload; A=3 пытается выгрузить активный handle из HL; A=4 получает обработанный отказ BIOS; A=5 загружает, вызывает и выгружает MRET; A=6 пишет слово DE по FAR-адресу B:HL; A=7 возвращает mx_memInfo; A=8 оставляет дочерний MRET для рекурсивной очистки; A=12 читает 37 байт README.TXT через FILEHANDLE в локальный буфер. Номера относятся только к тестовому модулю, не к ABI ядра.


BANKAPP.asm — самостоятельное банковое COM/EXE-приложение с `IMAGE_FLAGS = IMAGE_FLAG_BANK`. Штатный FILE_EXEC получает `B:\BANKAPP.COM Test arguments`, выделяет EXEC-банк и передаёт DE как локальный указатель на `Test arguments`. Приложение проверяет назначение банка, печатает аргументы через BIOS, выделяет FAR-блок и возвращается RET; DOS освобождает этот блок вместе с образом. Тест упаковывает одно тело также в EXE и проверяет оба расширения, включая ввод через редактор NC. DLL с BANK также допустим, но только для MODULE_TARGET_BANK.


MAINAPP.COM (MAIN=04h) загружается по 0000h и затирает нижний RUN; DOSAPP.COM (DRIVER=01h) проверяет выполнение инициализатора в банке DOS. scripts/emu80/check-run-native.py использует также EXE-копии и нейтральные UNKNOWN.COM/EXE, проверяя автоматический выбор и меню при сохранённой EXE→RUN. Опция --std-only проверяет RET после STD. MAINMOD.DLL теперь явно помечен MAIN и отвергается при попытке загрузить его в EXEC-банк.

DOSMOD.DLL собран с MAIN_MODULE=2 и DRIVER-флагом по DOS_BANK_DRIVER_ADDR. A=9 проверяет отказ RETAIN, A=10 — отказ запуска DOSAPP.EXE, пока арена занята DLL, A=11 — RAW-чтение boot в собственный 512-байтный буфер и возврат размера сектора в HL. DRVPROBE.COM проверяет обратный конфликт: MODULE_LOAD DOS из работающего DRIVER-инициализатора возвращает ACTIVE, не затирая его код. Публичные операции MODULE_LOAD/CALL/UNLOAD и регистрационные пакеты не изменили номера и размер.
