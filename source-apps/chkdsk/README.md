# CHKDSK.COM

При запуске CHKDSK явно освобождает DOSMOD через C8DBh, прежде чем использовать карту кластеров и верхние секторные буферы. Диагностика использует резидентные службы; следующий запуск NC восстанавливает модуль.

Диагностика текущего FAT16-подобного формата MXOS, без исправлений и записи на диск. Запуск: `A:CHKDSK.COM B:`. Первое слово аргументов выделяет `bios_argNext` DOS (C8B7h). Без аргумента программа спрашивает букву A–H: штатный ввод отображает символ, выбор подтверждается Enter. При запуске явно выбирается KOI-8. Имена выводятся без заполнения пробелами, с точкой перед расширением, в исходном регистре и кодировке каталога. После результата выводится `Press any key to exit`; после любой клавиши через `bios_getch` утилита переводит строку и возвращается с исходным режимом KOI и стеком. Приглашение CLI начинается на следующей строке.

Первый проход проверяет BPB и границы FAT/корня/данных, зарезервированные FAT[0]/FAT[1], дубликаты имён, номера и длины цепочек, свободные/плохие ячейки внутри цепочки, циклы, пересечения файлов и потерянные кластеры. Для повреждённой цепочки печатается имя, для потерянного кластера — его номер. LFN и метки пропускаются; подкаталоги обходятся с проверкой цепочек, записей `.`/`..` и пересечений кластеров.

Только при отсутствии ошибок структуры второй проход проверяет встроенные суммы:

- простой RKS: два адреса little-endian, нагрузка, двухбайтовая сумма;
- COM/EXE MXOS2 v1 с префиксом `CD 20 MX 01 00`: сумма первых 14 байт заголовка и отдельная сумма нагрузки; заголовок занимает 16 байт, длина файла равна длине нагрузки плюс 16. Это проверка целостности, а не возможности запуска в выбранной среде.

Используется существующий `bios_calcCS`; большие файлы проверяются порциями по 256 байт с объединением состояния исторической суммы. Весь файл в ОЗУ не загружается. BSS и поле среды исполнения в новом контейнере отсутствуют.

SYS/MON и другие сырые форматы без встроенной суммы получают `NO STORED CS`. Вычисленная сумма без эталона не объявляется успешной проверкой. Для RKS контейнер распознаётся по расширению независимо от регистра и точному соответствию адресов и длины. Файла внешних эталонных сумм нет.

## Поддерживаемая геометрия

Сектор и кластер 256 байт, одна FAT, 16..8192 секторов (до 2 МиБ), до 64 секторов FAT и до 256 записей корня. Размер корня округляется вверх; последний сектор ограничен точным числом записей. Имена с первой буквой E5h декодируются из 05h; дубликаты сравниваются без учёта регистра. Принимается сигнатура MXOS256, точный размер N, E5h для удаления и 00h для конца каталога. Самоссылка в конце цепочки считается ошибкой; распознаётся EOC FFF8h–FFFFh, FFF7h — bad. Пустой файл имеет размер и первый кластер 0. Стандартные FAT12/16/32 здесь не реализованы.

Утилита не вызывает файловые операции, не использует и не изменяет кэш DOS. Перед запуском не должно быть других операций с томом. Геометрия дополнительно сопоставляется с размером, который сообщает установленный физический драйвер; у некоторых драйверов этот размер сам берётся из BPB.

## Память и сборка

Код загружается по 0000h и занимает менее 2000h. Имена — 2000h..2AFFh, FAT — 4000h..7FFFh, карта занятости — 8000h..83FFh, секторные буферы и заголовок — 8400h..8A3Fh. Используется стек вызывающей программы выше этих буферов; штатный DOS размещает его в системной области. Системная область не используется для собственных данных. Достаточно базовых 36 КБ ОЗУ.

Из этого каталога:

```powershell
../../scripts/build/build-if-needed.ps1 CHKDSK com 0
```

Входит в `build: OS`, результат `bin/CHKDSK.cpu` / `bin/CHKDSK.i80`, в системный манифест добавлен `CHKDSK.COM`. Тест с записью только в RAM изолированного Emu80:

```powershell
python source-apps/chkdsk/check-emulator.py --runtime D:/Projects/RetroPC/Specialist/Emulator/Emu80-flash-test
python source-apps/chkdsk/check-interface.py --runtime D:/Projects/RetroPC/Specialist/Emulator/Emu80-flash-test
```
