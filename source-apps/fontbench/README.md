# Бенчмарк выровненного рендера 8×8

В конце документа приведено сводное сравнение со сдвинутым 5×7 и прямым пакетным выводом.

Отдельный стенд для Intel 8080, 2 МГц: сетка 48×32 в экране 384×256. Координаты X и Y кратны восьми, один глиф полностью заменяет восемь последовательных байт экранной колонки. Чтения прежнего фона, масок, сдвигов битмапа и интерпретации управляющих символов в `draw8` нет.

`FONT8.asm` содержит рендер, вывод из общего буфера и прокрутку на восемь пикселей. Рендер принимает C = код 0..255, HL = экранный адрес ячейки, сохраняет AF/BC/DE/HL/SP. Адрес ячейки и перенос строки вычисляет программа. Все глифы имеют размер 8×8; знакогенератор — 256×8 байт.

Для воспроизводимого изображения стенд заранее расширяет шесть бит штатного `assets/system-rom/FONT.FNT` до восьми по ближайшему пикселю. Это только подготовка тестового шрифта вне измерения, файл FONT.FNT и системный шрифт не изменяются. Рендер работает со всеми восемью битами каждого байта; время не зависит от рисунка. Полярность можно поменять предварительной инверсией знакогенератора.

## Размещение и ABI

| Область | Назначение |
|---|---|
| 0100h | Измеряемая программа, текст, счётчик строк; основное ОЗУ либо страница 0 |
| 6000h–67FFh основного ОЗУ | Подготовленный тестовый знакогенератор |
| EB00h–EB86h основного ОЗУ | Рендер и его вспомогательные функции, 135 байт |
| F880h–F8C6h основного ОЗУ | Диспетчер и контекст, 71 байт |
| FFC0h–FFCBh | Шлюз, 12 байт; тот же BUFFERGATE, что в TEXTBEN |
| FFCCh–FFDFh | Общий буфер текста, 20 байт |

Рендер и шрифт находятся в основном ОЗУ во всех режимах. Меняется размещение вызывающей программы и два операнда CALL, алгоритм рисования остаётся тем же. Из страницы 0 используется общий шлюз с A = страница возврата (0), B = функция (0 — глиф C в HL, 1 — C байт буфера начиная с HL, 2 — прокрутка экрана). Диспетчер возвращает страницу, стек, регистры и флаги. Прерывания запрещены, шлюз нереентерабелен, тест работает только в MX. Строка буфера не пересекает правую границу экрана; неверная длина >20 ничего не выводит. Функции 3 и выше — пустой контрольный вызов.

Нативный вариант вызывает ту же функцию напрямую. Буферный вариант включает копирование текста в общий буфер: на строку из 48 символов три вызова по 20, 20 и 8 символов. Копирование выполняется и в нативном варианте, поэтому таблица отдельно показывает обе нативные базы сравнения.

## Запуск

Нужны текущие DOS.sys и 512-КБ `images/SystemRom_emu80_writable.bin`, отдельная установка Emu80 с MCP и моделями MX2. Из корня проекта:

```powershell
python scripts/emu80/benchmark-font8.py --runtime .local/monitor2-001
```

Сборка выполняется автоматически с `--i8080`. Можно отдельно вызвать `pwsh -NoProfile -File source-apps/fontbench/build.ps1`. Получаются `bin/FONT8.i80`, `F8DISP.i80`, `F8CHAR.i80`, `F8BUF.i80` и листинги/символы. Генерируемая `FONT8.entries.inc` передаёт адреса услуг диспетчеру без ручного дублирования адресов реализации.

Стенд проверяет владельца порта 19781, запускает собственный видимый Emu80, ждёт NC и использует отладчик для отдельного теста ABI. Существующий экземпляр не используется. Выбранный runtime сбрасывает тестовые flash-образы через `-ResetFlash` с сохранением прежних образов штатным сценарием. Во время теста штатный драйвер в общем окне заменён шлюзом, файловые вызовы запрещены. В конце восстанавливаются страница 0 и общее окно, собственный экземпляр закрывается также при ошибке. Память основного ОЗУ — временная память только этого изолированного тестового сеанса.

Три повтора каждой пары; `--repeats` меняет число повторов, `--rows 8 32 100` выбирает наборы строк. Строки различаются номером, чтобы ошибка прокрутки не скрылась повторяющимся рисунком. На 8 и 32 строках прокрутки нет, на 100 строках происходит 68 прокруток по восемь пикселей через штатный быстрый `bios_memcpy_bc_hl`. Последняя строка не вызывает лишней прокрутки. Цветовой атрибут во всём экране одинаков и не меняется.

Без прокрутки: нативно около 4708 символов/с, из страницы 0 посимвольно 2605, через буфер 3926. Буферный вызов из страницы 0 медленнее такого же нативного буферного цикла на 4,46%; относительно самого быстрого нативного посимвольного варианта добавка составляет 19,90%.

Цена общего шлюза с диспетчером: 343 такта на одиночный глиф, 348 на пакет и 363 на прокрутку. Это общий диспетчер с 20-байтным буфером, а не прежний специализированный 29-байтный шлюз с ценой 166 тактов. Стоимость переключений заметна относительно уже быстрого рендера.

Чистая запись восьми байт занимает **182 такта**: восемь чтений шрифта, восемь записей экрана, четырнадцать INR. У 8080 INR r требует пять тактов. Полный CALL `draw8`, включая вычисление адреса глифа, сохранение/возврат регистров и RET, требует **365 тактов**, или 182,5 мкс. Функция занимает **51 байт**, порты в ней не используются.

Отчёт, снимок и подготовленный шрифт: `docs/bench/font8-001/results.json`, `results.png`, `results.font.bin`. Все три повтора дали одинаковые такты. Каждый полный битмап сравнен с независимым Python-расчётом, в том числе при прокрутке. Проверяются SP, возврат нужной страницы, сохранность текста/кода и знакогенератора.

Проверены все 256 кодов, верхние/нижние и левые/правые крайние ячейки, нулевая и максимальная длина буфера, отказ для длины 21, сохранение AF/BC/DE/HL/SP. ## Сдвинутый 5×7 и сводное сравнение

`SHIFT.asm` сравнивает четыре рендера с одинаковым интерфейсом: символ C, общая позиция BIOS, сохранение AF/BC/DE/HL. MODE=0 вызывает настоящий `bios_printChar` C809h, MODE=1 использует готовые сдвиги штатного 5×7 с шагом шесть пикселей, MODE=2 непрозрачно рисует выровненный 8×8 с шагом восемь. MODE=3 вызывает настоящий C809h с экспериментальной заменой только пиксельного бэкенда. Варианты проверяются в отдельном стенде.

Предварительно подготовлены только четыре варианта буквы `A`, восемь строк каждый, включая пустую восьмую строку. Порядок фаз задаётся старой координатой X: 0, 2, 4, 6 пикселей относительно экранного байта. В первых двух случаях занята одна колонка, в остальных две. Данные двух колонок чередуются по строкам.

| Фаза | Адрес таблицы | Байтов на глиф | Сохраняемые маски экрана |
|---|---|---:|---|
| 0 | 3000h + код × 8 | 8 | 03h |
| 2 | 3800h + код × 8 | 8 | C0h |
| 4 | 4000h + код × 16 | 16 | F0h, 3Fh |
| 6 | 5000h + код × 16 | 16 | FCh, 0Fh |

Фактические подготовленные данные для `A` занимают **48 байт**. Стенд оставляет полное адресное окно 12 КБ, остальные глифы нулевые: индекс кода вычисляется так же, как для полного сдвинутого знакогенератора из 256 символов. Генерация данных выполняется на хосте до измерения. Область 3000h–5FFFh — временное размещение только этого изолированного стенда; он использует интегрированный DOS.sys с C000h, а не раздельный DOS4000.

`oneByte` и `twoBytes` — два отдельных полностью развёрнутых ядра. На строку выполняется `(экран AND сохраняемая_маска) OR готовый_битмап`. Вращений и сдвигов при рисовании нет. Соседние пиксели сохраняются. Чистая запись глифа, без адресации и перехода к продолжению:

| Ядро | Тактов 8080 | Чтений шрифта / экрана | Записей экрана |
|---|---:|---:|---:|
| 5×7, одна колонка | 270 | 8 / 8 | 8 |
| 5×7, две колонки | 585 | 16 / 16 | 16 |
| 8×8, одна колонка целиком | 182 | 8 / 0 | 8 |

При BATCH=1 вход принимает C=0..20 байт общего буфера FFCCh. Только печатные символы: CR/LF и другие управляющие коды не разбираются. Общие регистры сохраняются один раз на пакет. Внутри ускоренного цикла нет CALL/PUSH/POP, в том числе временных сохранений экранного адреса: DE указывает экран, HL — готовый глиф. Указатель текста хранится в операнде LDA; граница буфера — в операнде CPI. Рендер нереентерабелен, прерывания запрещены. Счётчик и проверка конца пакета остаются. Стандартный пакетный вариант продолжает вызывать C809h для каждого символа: он показывает цену существующего пути, а не переписанного стандартного BIOS.

### Методика и запуск

```powershell
python scripts/emu80/benchmark-shifted-font.py --runtime .local/monitor2-001
python source-apps/fontbench/check-shifted.py --ticks D:/path/to/z88dk-ticks.exe
```

По умолчанию три повтора, 8 и 24 строки по 48 букв `A`, без прокрутки. `--modes 0 1 2 3` выбирает рендеры, `--rows` — число строк, `--repeats` — повторы. `SHIFTBEN.asm` собирается для одиночного и пакетного вывода. В пакеты попадают только буквы, перенос строки вызывается отдельной услугой, одинаковой для трёх рендеров. Межстрочный шаг восемь пикселей, переносов после последней строки нет. Копирование текста в общий буфер входит в измерение; 48 символов разбиваются на пакеты 20+20+8.

Основное ОЗУ и страница 0 выполняют один и тот же код: меняются только адреса CALL. В обоих случаях рендер и знакогенераторы лежат в основном ОЗУ. Страница 0 вызывает общий шлюз 12 байт и диспетчер `SHIFTDISP`; под буфер остаётся 20 байт. Контекст сеанса, проверка владельца MCP, видимый запуск, восстановление страницы 0 и закрытие своего эмулятора вынесены в `scripts/emu80/benchmark-session.py`.

Перед измерением восстанавливаются KOI-8, штатный FONT.FNT и normalVideo, очищается экран, устанавливается исходная позиция. Приведение полиморфного штатного рендера к normalVideo выполняется вне таймера. В таблицу входит весь цикл программы, вычисление позиции/адресов, обработка границ пакетов и 23 вызова переноса строки. Подготовка таблиц и обмен с MCP не входят. Тест использует normalVideo; смена шрифта и рендер в инверсном режиме не являются реализованными услугами нового экспериментального пути.

Нативная пакетная обработка ускоряет сдвинутый 5×7 ещё на 3,15%, 8×8 — на 4,95%, уже с учётом заполнения общего буфера.

Три повтора каждого режима дали одинаковые такты. Стандартный и сдвинутый 5×7 совпали побайтно, 8×8 проверен по своему пиксельному эталону. Независимая CPU-проверка включает 98 случаев: четыре фазы, крайние ячейки, непустой фон, сохранение соседних пикселей и AF/BC/DE/HL/SP, пустой/полный пакет и отказ для длины 21. Такты трёх ядер измерены отдельно. Дизассемблирование проверяет отсутствие CALL/PUSH/POP во всём внутреннем пакетном цикле ускоренных вариантов. Это измерения моделей; физическое оборудование не проверялось.

### Оптимизация штатного рендера без кэша

`OPT_DRAW.asm` — экспериментальная замена только участка drawChar, вызываемого настоящим `bios_printChar`. Код, который разбирает управляющие символы, KOI-7/8, выбирает шрифт и принтер, рассчитывает позицию и сохраняет публичные регистры, остаётся штатным. Переносы и продвижение курсора обрабатывает прежний код. Чтение `bios_vars.inverse` сохраняет normalVideo и инверсию. Исходник и сборка DOS.sys этим тестом не меняются: стенд ставит временный JMP в память только своего эмулятора.

Циклы четырёх фаз полностью развёрнуты на восемь строк. В двухколоночных фазах строка шрифта читается и вращается один раз, её значение держится в E. Формула `(old XOR glyph) AND keep XOR glyph` объединяет её с экраном без временного стека и повторных вращений для второй колонки. Приращения источника и экранного адреса остаются 16-битными, как у старого бэкенда. Для инверсии байт глифа перед вращением XOR-ится с 3Fh.

Бэкенд занимает **549 байт** против **120 байт** прежней пиксельной части: рост 429 байт, дополнительного знакогенератора или кэша не требуется. Размещение автономного бэкенда — ED00h–EF24h, ниже аппаратной области STD. Результаты при 1152 символах:

| Режим | Прежний BIOS, с | Оптимизированный, с | Снижение времени |
|---|---:|---:|---:|
| Основная память, по символу | 0,875269 | 0,746389 | 14,72% |
| Страница 0, по символу | 1,077012 | 0,948132 | 11,97% |
| Основная память, пакет | 0,923725 | 0,794845 | 13,95% |
| Страница 0, пакет | 0,940428 | 0,811548 | 13,70% |

Пакет этого варианта по-прежнему вызывает полный BIOS для каждого символа; это оптимизированный штатный путь, а не сырой интерфейс с удалением проверок и посимвольного сохранения ABI. Варианты с готовыми сдвигами и 8×8 выше имеют отдельный сырой пакетный интерфейс, поэтому сохраняют больший выигрыш.

Запуск только этой проверки:

```powershell
python scripts/emu80/benchmark-shifted-font.py --runtime .local/monitor2-001 --modes 3 --report docs/bench/optimized-standard-001/results.json
python source-apps/fontbench/check-shifted.py --out docs/bench/optimized-standard-001/cpu
```

Три повтора всех четырёх размещений/вызовов совпали по тактам и битмапу. CPU-проверка расширена до **614 случаев**, включая все 224 печатных кода KOI-8 в обычном и инверсном режиме, четыре фазы и крайние позиции, KOI-7, альтернативный FONT_IT.FNT, непустой фон и сохранение регистров. Проверка инверсии и альтернативного шрифта выполнена также через шлюз на плоской CPU-модели; реальное переключение страниц и обычный вывод проверены отдельно в Emu80.
