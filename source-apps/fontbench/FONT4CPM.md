# Тестовый шрифт 4×8 из CP/M Syabr 0.1

`assets/system-rom/FONT4CPM.bin` — неизменённые 2048 байт по адресам 1300h–1AFFh тела CPM.RKS из комплекта syabr-cpm-0.1.zip. Шрифт расположен по строкам: байт `row*256+code`; оба полубайта одинаковы. Извлечение проверено по коду инициализации CP/M в 0F7Ch: он читает 1300h–1AFFh и разносит старшие/младшие полубайты в две таблицы. Перекодировка символов и изменение битмап не выполнялись.

SHA-256 исходного CPM.RKS: `0454012b35ea14e88480cb176df116696bff26bf8d50613ea2c716e7cae8ab93`. Комплект находится вне репозитория: `D:/Projects/RetroPC/Specialist/OS/CP-M/syabr-cpm-0.1.zip`. Иллюстрация порта, указанная пользователем: https://pic.maxiol.com/images2/1791817823.780858384.specialist202610121.png.

FONTBEN при сборке преобразует таблицу в 1024-байтный набор пар: каждая запись содержит восемь строк двух последовательных кодов, чётный код в старшем полубайте. При запуске из него вне измерения готовятся все три сравниваемых формата. Каждый использует одни и те же 256 глифов; это отдельный 4×8-шрифт, а не обрезанный FONT.FNT. Системный шрифт BIOS не заменяется.

Для быстрого RAW/DUP исходная раскладка CP/M по 256-байтным строкам восстановлена в рабочей таблице; её размер остаётся 2048 байт. Рендер повторяет приём BIOS CP/M в 0C64h–0CA6h: POP двух кодов, прямое индексирование строк и развёрнутая запись восьми байт с INC регистра старшей части указателя глифа. В отличие от CP/M, который держит две раздельные таблицы фаз, DUP сохраняет обе фазы в одном байте и объединяет полубайты без чтения экрана.
