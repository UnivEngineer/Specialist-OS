# DISKBEN — файловый и прямой доступ к дискам MXOS

В штатной банковой сборке DOS остаётся в собственной странице, memtop основной памяти равен 8BFFh. LOW/HIGH-буферы бенчмарка находятся в доступной программе памяти.

При запуске утилита включает KOI-8, сохраняя исходный режим. При обычном выходе восстанавливаются режим KOI и стек вызывающей программы.

`A:\BENCH\DiskBen\DiskBen.com` запускается с 0000h. Аргументы запуска и слова в интерактивных полях выделяет штатный `bios_argNext`. Недостающие параметры вводятся через `bios_input`, выход — `Press any key to exit` через `bios_getch`, после нажатия выводится перевод строки. Сборка входит в `build: OS`.

В штатной банковой системе B: использует общий CPM16. RAMDISK.COM подготавливает том, не устанавливая прежний отдельный резидент R4. Исторические алгоритмы сравниваются автономным COPYBEN; результаты DISKBEN включают текущую обвязку BIOS/DOS.

## Параметры

```text
DISKBEN H: -C:MAIN -M:RAW -V=0 -W=1 -S=8
DISKBEN B: -C:BANK -M:FILE -V=1 -W=3 -S=24
DISKBEN H: -C:ALL -W=0
DISKBEN H: -C:DOS -V=0 -W=1 -S=3
DISKBEN -?
```

| Аргумент | Значение |
|---|---|
| `A:`…`H:` | Тестируемый диск |
| `-M:RAW/FILE/ALL` | Прямой доступ / файловый API / оба; по умолчанию ALL |
| `-V=0/1/2` | Без дополнительной проверки / полное перечитывание и сравнение / посекторная проверка драйвером в RAW и FILE |
| `-F=0/1` | Обычное / псевдослучайное размещение кластеров; без ключа — интерактивный вопрос, Enter = 0 |
| `-W=0..9` | Число проходов записи с сопутствующим чтением; 0 — только чтение выбранным способом |
| `-S=1..24` | Размер тестового файла в КиБ (1024 байта); `-S=8` означает 8192 байта |
| `-C:MAIN` | Измеритель в основной памяти (DiskMain.dll) |
| `-C:DOS` | Измеритель в банке DOS (DiskDos.dll) |
| `-C:BANK` | Измеритель в отдельном EXEC-банке (DiskBank.dll) |
| `-C:ALL` | Пакет MAIN → DOS → BANK с общей таблицей скоростей |
| `-?` | Справка |

Порядок аргументов произвольный, регистр ключей и буквы диска не важен. Числа десятичные; дублирующиеся параметры, неизвестные ключи и значения вне диапазона отклоняются до выбора диска и начала тестов. Для пропущенных диска, исполнителя, проверки, числа проходов и размера остаётся интерактивный вопрос; отсутствие `-M:` выбирает оба способа доступа. Если явно задано `-W=0` или носитель доступен только для чтения, вопросы о проверке и размере файла не задаются: файл не создаётся. В этом режиме `-S` не меняет стандартный объём RAW-чтения: 8 КиБ для MAIN/BANK, 8 КиБ для DOS и общего пакета. Нажатие клавиши в конце результата сохраняется и при полностью заданных аргументах.

Технология и возможности берутся из B=FFh физического драйвера. Для записи выбираются число проходов 0–9 и размер 1–24 КиБ (Enter = 8). Размер задаёт число кластеров и объём расчёта скорости. Текущий формат: кластер = сектор = 256 байт; число кластеров равно КиБ × 4. FAT12/FAT32 не добавляются.

Режимы записи:

- 0: обычный B=1; завершение записи — штатные барьеры драйвера/DOS.
- 1: весь файл записывается B=1, затем читается и побайтово сравнивается с оригинальным буфером. Проверка реализована в приложении и не прерывает конвейер записи. Режим доступен также RAMD, без физического B=5.
- 2: посекторный RAW B=5, только при DISK_CAP_VERIFY. Запись каждого физического сектора завершается и проверяется до следующей. Для FILE WRITE банкового ядра проверяется готовый файл целиком, как в режиме 1; это не проверка каждого сектора FAT/каталога.

Режим 1 проверяет данные файла через DOS либо Raw после завершения всей записи. Оригинал остаётся в ОЗУ до завершения проверки. Оба варианта проверки входят в итог WRITE; VERIFY — часть WRITE, а не добавочное время.

## Расположение вызывающего кода

Если исполнитель не задан, появляется строка `Caller MAIN/DOS/BANK/ALL [MAIN]:`. Enter выбирает MAIN; допустимы четыре полных имени без учёта регистра, лишние слова отклоняются. -C:MAIN, -C:DOS, -C:BANK и -C:ALL выбирают исполнителя без этого вопроса. MAIN использует тот же DLL-измеритель, что столбец MAIN в ALL, с прямым локальным Raw. Старые -M/-D/-B/-A сохранены как совместимые варианты, а -C=0..2 — как прежний вариант -V=0..2. Повторное задание исполнителя или режима проверки отклоняется. В сводке указаны размещение и полный локальный буфер файла.

MAIN вводит параметры, затем загружает DLL через MODULE_LOAD и делает один MODULE_CALL на весь прогон. Настройки копируются из main до измерений; результаты пересылаются обратно до MODULE_UNLOAD. Время загрузки, пересылки настроек/результатов и вызова модуля исключено из замеров. Код, объект FILEHANDLE, FAT-буфер и буфер данных принадлежат странице модуля. Файловые запросы всех трёх сборок используют публичный MXOS_CALL, включая локальные обращения к DOS из её собственного банка. RAW после PREPARE вызывает локальный физический вход. HIGH/LOW различаются только для RAW в MAIN A:, где источник и назначение могут находиться по разные стороны ROM-окна.

DiskDos.dll имеет IMAGE_FLAG_DRIVER и занимает C000h–E9FFh: 10752 байта вместе со статическими данными, FAT-буфером и полным файловым буфером 8 КиБ (CA00h–E9FFh). MODULE_TARGET_DOS закрепляет за ней временную арену, заимствуя кадры BAT только при отсутствии активного BAT. Конфликтующая DOS-DLL или установка физического драйвера отклоняется загрузчиком; BAT не запускается до освобождения заимствованной области. RETAIN не применяется. DiskBank.dll использует те же адреса кода в отдельном EXEC-банке, DiskMain.dll располагается с 2000h в явно зарегистрированной свободной main-арене.

Измеритель создаёт настоящий DISKBEN.TMP через FILEHANDLE OPEN, записывает весь локальный буфер одним WRITE, выполняет FILEHANDLE FLUSH/CLOSE и повторно открывает файл для одного READ на весь буфер. Затем строит список физических секторов и выполняет RAW WRITE/READ. Удаление, построение списка, генерация шаблона и обычное сравнение прочитанных данных исключены из замеров. В режиме проверки файла побайтовое сравнение входит в WRITE и отдельно показано как VERIFY. Создание и выделение FAT-цепочки исключены из File WRITE; финальный flush включён; FLUSH также измеряется отдельно и выводится только при DISK_CAP_FLUSH. При нулевом числе проходов выполняются три чтения без создания файла: по 8 КиБ для MAIN/BANK, по 8 КиБ для DOS и общего пакета. FILE READ доступен, если на томе уже есть DISKBEN.TMP достаточного размера. При отсутствии файла таблица показывает для FILE READ прочерк. Поддерживаются те же MXOS-256 тома с одним сектором на кластер; MAIN/BANK поддерживают файл 1–24 КиБ, DOS — 1–8 КиБ. Для -D и -A выбранный больший размер ограничивается 8 КиБ с явным сообщением; вся таблица -A использует этот общий размер, указанный в сводке.

```text
A:\BENCH\DiskBen\DiskBen.com H: -M -C=0 -W=1 -S=8
A:\BENCH\DiskBen\DiskBen.com H: -B -C=0 -W=1 -S=8
A:\BENCH\DiskBen\DiskBen.com H: -D -C=0 -W=1 -S=8
```

## Пакет и совместный WRITE/VERIFY

Ключ `-A` последовательно запускает один и тот же DLL-измеритель в MAIN, DOS и BANK. Все результаты собираются до печати; в таблице рядом выводятся три скорости в КиБ/с для Raw READ, Raw WRITE, FILE READ, FILE WRITE и FILE WRITE + VERIFY. Каждая строка имеет одинаковую ширину подписи, каждое число — фиксированную ширину с двумя знаками после точки; поля разделены TAB. Внутри пакета сохраняется общий кэш DOS, принудительного охлаждения между размещениями нет.

В компактных режимах `-M/-B/-D/-A` с `-C=1` сначала фиксируется время обычного FILE WRITE, затем отдельно измеряются чтение готового файла и побайтовая проверка. Одна запись даёт сразу две скорости: FILE WRITE и FILE WRITE + VERIFY (сумма этих интервалов). Поэтому отдельный повтор всего теста без проверки не нужен. Обычные FILE READ и Raw READ/WRITE выполняются по одному разу за проход; RAW WRITE + VERIFY также измеряет отдельный полный проход чтения и сравнения; в MAIN A: эта дополнительная строка относится к LOW. Для отдельной физической посекторной проверки сохраняется `-C=2`. Удаление временного файла находится вне замеров.

```text
A:\BENCH\DiskBen\DiskBen.com H: -A -C=1 -W=3 -S=8
```

Без ключа исполнителя предлагается меню MAIN/DOS/BANK/ALL с MAIN по Enter. LOW/HIGH отдельно измеряются для RAW в MAIN A:. ROM использует только чтение. Для воспроизводимого FILE READ матричный прогон подготавливает в отдельном ROM-образе файл DISKBEN.TMP на 8 КиБ; такой образ не используется для проверки записи. Тестовые runtime и диски отделены от рабочих.

## Порядок операций

Каждый проход создаёт настоящий `DISKBEN.TMP` через `MXOS_DOS_FILEHANDLE` (OPEN/WRITE/FLUSH/CLOSE), измеряет чтение того же файла через DOS, затем прямые запись и чтение тех же кластеров. Удаление выполняется только после всех чтений и сравнений, вне замеров. File WRITE перезаписывает готовую цепочку и включает данные, обновление записи каталога и flush. Raw использует готовую FAT-цепочку; построение списка секторов вне замера.

Перед каждой измеряемой серией RAW выполняется PREPARE без передачи данных: завершается предыдущая запись и получаются локальные входы драйвера. Подготовка исключена из READ/WRITE и VERIFY. LBA и буферы подготовлены до серии; внутри физического цикла нет MXOS_CALL и обращений к FAT/каталогу. FILE READ/WRITE включают прикладной FILEHANDLE со всеми необходимыми метаданными. Посекторный режим -V=2 сохраняет цену каждого B=5 и его проверки.

Перед каждым проходом печатается `Pass i/N`, после удаления — `done`. Сводка показывает диск, метку, технологию, драйвер, режим, размер и кластеры. Существующий DISKBEN.TMP не заменяется: его надо удалить или переименовать. При ошибке делается попытка удалить только собственный временный файл. Все записи расходуют ресурс flash.

## LOW и прямой HIGH на A: (исторический контроллер)

Следующие подробности относятся к прежнему контроллеру, сохранённому в исходниках; штатное меню использует DLL-измеритель, описанный ниже. На A: измеряются READ LOW/HIGH и Raw WRITE LOW/HIGH. Для WRITE HIGH источник действительно находится в 8200h..8BFFh; подготовка порций из нижнего оригинала исключена из WRITE. Файловая запись DOS измеряется отдельно из LOW и HIGH. Для B:–H: остаются обычные READ и WRITE, без подписей Buffer LOW/HIGH.

LOW — полный буфер от 2000h до 7FFFh максимум (24 КиБ). Для чтения ROM в нижнюю память драйвер переключает ROM/RAM; текущий FlashSys переносит пары байтов через регистры. HIGH — прямое чтение в 8200h..8BFFh порциями до 2560 байт. ROM-источник и верхнее назначение одновременно видны CPU; FlashSys использует `bios_memcpy_bc_hl`. Дополнительной копии HIGH → LOW в замере нет.

Файловый HIGH читает описание через `bios_fileLoadInfo`, затем передаёт порции через `bios_fileStream` (A=2, BC=байты, DE=курсор). Raw читает те же секторы непосредственно драйвером. Порции сравниваются с оригинальным нижним буфером, после чего верхнее окно используется повторно. Сравнение исключено из READ. Так весь выбранный файл измеряется без размещения его поверх экрана, системных переменных или DOS. HIGH — потоковый верхний буфер; полный файл одним вызовом `bios_fileLoad2` в верхнее ОЗУ не загружается.

Полная проверка записи использует этот же верхний потоковый буфер. При ней побайтовое сравнение с сохранённым оригиналом включено во время VERIFY/WRITE. Перед чтением верхнее окно заполняется противоположными данными вне замера, чтобы старое содержимое не могло скрыть отсутствие реального чтения. Время VERIFY в сводке показывается отдельно для LOW и HIGH; оно включено в соответствующий WRITE.

## Вывод и flush

```text
Raw access: direct writing/reading of sectors
READ:  ... ms   ... KiB/s
WRITE: ... ms   ... KiB/s
VERIFY: ... ms (included in WRITE)
FLUSH: ... ms   ... times

File access: writing and reading file with DOS
READ:  ... ms   ... KiB/s
WRITE: ... ms   ... KiB/s
VERIFY: ... ms (included in WRITE)
FLUSH: ... ms   ... times
```

На A: сначала идут READ HIGH / READ LOW, затем WRITE HIGH / WRITE LOW. VERIFY показывается только для полной проверки файла. FLUSH — только при DISK_CAP_FLUSH. Между столбцами выводится TAB, поле времени дополнено до 8 знаков. Скорость — КиБ/с (1024 байта/с), время — мс с тремя знаками после точки.

Файловые операции вызываются через общий `MXOS_CALL MXOS_DOS_*`. В компактных режимах `-M/-D/-B/-A` физические серии используют полученные через `MXOS_DOS_RAW_IO B=RAW_OP_PREPARE` локальные входы; встроенный контроллер также получил PREPARE и локальный цикл без посекторного MXOS_CALL. Бенчмарк не изменяет переходы BIOS и не перехватывает внутренние обращения банковой DOS. Оба файловых варианта LOW/HIGH используют FILEHANDLE и выделяют кластеры по мере записи. FILEHANDLE FLUSH/CLOSE сохраняют состояние файла; режим проверки читает готовый файл целиком. Завершающий сброс входит в WRITE и отдельно измеряется как FLUSH. Raw выполняет один физический B=4 после всей серии при DISK_CAP_FLUSH; после каждого сектора B=4 не вызывается. Строка FLUSH выводится только для драйвера с DISK_CAP_FLUSH. B=5 завершает и проверяет отдельный физический сектор. Повторно прибавлять FLUSH к WRITE не нужно.

Для ROM или нулевого бюджета сохраняется отдельный старый тест физического чтения без TMP: 32 прохода по 32 секторам. Для зарезервированных Floppy/HDD остался случайный порядок этого чтения; реальных драйверов он не добавляет.

## Таймер и память

Настройка и чтение ВИ53 выполняются локально через общую библиотеку `source/include/timing-pit.inc`, включая компактные измерители `-M/-D/-B/-A`. Регистры таймера доступны во всех банках, обращений к BIOS/DOS для управления таймером нет. Чтение занимает 10 байт и 54 такта 8080 с RET, без входного CALL. Общая библиотека `source/include/timing.inc` содержит накопление U32 тиков, пересчёт в мс и десятичную печать, совместно с LLM80. CLK1 задаётся сборкой: 2 или 2,5 МГц. Между отсчётами должно быть меньше оборота канала 2 (8,39 с при 2 МГц). Цена локального таймера и накопления включена; печать, заполнение буферов, контрольное сравнение обычного READ и удаление исключены. Результаты компактных режимов, полученные до локального чтения ВИ53, включали неодинаковую стоимость межбанковых вызовов таймера и требуют повторного измерения для сравнения размещений.

Код ограничен 2000h. Полный исходный буфер — 2000h..7FFFh максимум, временный сектор FAT — 8000h..80FFh, верхнее окно — 8200h..8BFFh. SP=8FDFh; окно не пересекает резерв стека для B=5. Исходный нижний буфер не перезаписывается во время полной проверки или прямого HIGH-чтения.

Проверки: `scripts/emu80/check-diskbench-readback.py` и `scripts/emu80/benchmark-disks.py`. Измерения Emu80 не заменяют измерение платы. Матрица `docs/diskbench/matrix-001` содержит старый HIGH со staging; для прямого HIGH используются отчёты начиная с `matrix-002`.

Изолированная сборка для `docs/diskbench/cache-005` задаёт MAX_FILE_KIB=8, sectorBuffer=1600h, fatBuffer=FE00h, highBuffer=FB00h, HIGH_SECTORS=3. Файл занимает 1600h–35FFh, таблица слотов 1300h–15BFh, кэш 22 КиБ — 3600h–8DFFh. Верхнее окно и сектор FAT используют освобождённые FB00h–FEFFh. Это позволяет вместить файл 8 КиБ и всю FAT/root H: одновременно. В cache-005 измерены только 22 КиБ; прежние 1/4 КиБ взяты из cache-004, с явной оговоркой о различии размещения в сравнительном отчёте. Адреса проверяются ASSERT и сценарием; обычная сборка не меняет свои буферы.

Исправлено вычисление конца буфера после ввода размера: сравнение охватывает ровно файл, без лишнего сектора. Прежний I/O ERROR после успешного чтения возникал из-за сравнения этого лишнего сектора.

Предыдущая тестовая копия удаляется до замера. Все Raw/File используют
одинаковый шаблон и размер; Raw работает с цепочкой последней копии.
Полная проверка файла включается выбранным режимом, её время отдельно
показывается для LOW и HIGH и уже включено в соответствующий WRITE.

Raw HIGH A: использует одно отображение flash и новый bios_memcpy вместо
переключения страниц на каждой паре байтов нижнего буфера. Проверка в Emu80
при 2 МГц: прямой вызов драйвера с обвязкой — 12434 такта/сектор LOW,
5649 HIGH (40,2 / 88,5 КиБ/с). Поэтому 76 КиБ/с в полном Raw HIGH тесте
само по себе не означает ошибку измерения. Это эмуляторные результаты;
для реальной платы отдельно нужны измерения и проверка тактирования ВИ53.

Табуляция BIOS — фиксированный сдвиг на четыре символа. Подписи дополнены до кратной четырём длины, затем число TAB подобрано до общей колонки: значения свойств начинаются с колонки 24 (считая с нуля), поле времени — с колонки 16. Целая часть времени выравнивается вправо в поле шириной 8, поэтому десятичные точки стоят друг под другом.


С 07.11.2026 скорость выводится в `KiB/s` (1 КиБ = 1024 байта), как в исторических таблицах ченджлога. Размеры файлов и ёмкости уже были в КиБ. Сначала делится исходный числитель на тики, затем дважды делится остаток ×10; напечатанные миллисекунды в расчёте скорости не используются. Два знака округляются вниз. Константа `floor(CLK1/1024)` даёт относительную погрешность менее 0,017% при 2/2,5 МГц. У таблицы свойств обычный регистр (`Drive`, `Label`, `Sector (bytes)`), аппаратные обозначения ROM/RAM и имена драйверов сохранены. `python scripts/tests/check-diskbench-rate.py` проверяет форматтер и полный расчёт КиБ/с на свежих сборках для обеих частот.

В пакетном прогоне счётчик проходов подписан размещением измерителя: `MAIN: Pass 1/1`, `DOS:  Pass 1/1`, `BANK: Pass 1/1`. После `DOS:` стоят два пробела для выравнивания.


## Прямой RAW в MAIN, DOS и BANK

В компактных режимах список физических LBA строится и проверяется на границы до замера. Затем единственный PREPARE получает единый локальный вход драйвера для B=1/2/4/5 в странице измерителя; таймер запускается после подготовки. Внутри измеряемого RAW-цикла нет MXOS_CALL и обращений к FAT/каталогу. Локальный физический flush завершает весь пакет; следующая файловая операция вновь использует DOS. Контракт прямой серии и срок действия указателей описаны в [ABI памяти](../../source/mem/api.md#локальная-серия-raw).

Для MAIN A: дополнительно измеряются RAW READ/WRITE HIGH с буфером 8200h; LOW находится в нижней памяти самого DLL-измерителя. MAIN обращается прямо к bios_blockIO. В пакетной таблице A: показаны строки HIGH/LOW; HIGH имеет значение только в MAIN, остальные столбцы этой строки содержат прочерк. В DOS/BANK A: сохраняется межстраничный аппаратный мост. B: и H: работают локальными драйверами во всех трёх размещениях; одинаковый цикл больше не добавляет к BANK диспетчер DOS на каждом секторе.

Блок результата DLL занимает 60 байт: первые 48 сохраняют прежний формат (четыре записи по 10 байт и два VERIFY U32), +48 — RAW WRITE HIGH U32, +52 — RAW READ HIGH U32, +56 — время полного проверочного чтения и сравнения HIGH U32; дополнительные поля равны нулю вне MAIN A:. Измеритель по-прежнему передаёт только свой банк и указатель на результат, копирование результатов и MODULE_UNLOAD исключены из времени.

Историческая версия от 04.11.2026 (коммит 4a5d47d) также строила FAT-цепочку заранее и вызывала bios_diskDriver напрямую, с обёрткой локального таймера. Её высокий результат MAIN A: HIGH не был следствием посекторного запроса метаданных. Поздний компактный измеритель заменил физический CALL на MXOS_CALL RAW_IO и использовал единственный нижний буфер во всех размещениях, поэтому его MAIN A: READ нельзя было сравнивать с историческим HIGH.

## Прикладной файловый API

Все файловые измерения используют `MXOS_DOS_FILEHANDLE`, тот же API, который обслуживает `mxos_fread/mxos_fwrite`: OPEN, READ, WRITE, FLUSH и CLOSE. Общий переходник находится в file-handle.inc. DOS сама ведёт позицию, размер файла и выделение кластеров при записи; предварительного FILE_CREATE_PREPARE и ручного курсора FILESTREAM больше нет. Число реально переданных байтов проверяется после каждого запроса: ранний EOF и неполная запись завершают тест ошибкой. После flush/close дескриптор копируется из FILE_HANDLE для построения списка Raw вне замера; проверка существования имени до создания остаётся, чужой DISKBEN.TMP не перезаписывается.

Матрица выполняет по одному READ/WRITE на весь буфер в MAIN/DOS/BANK. Файл передаётся одним запросом FILEHANDLE, а внутреннее разбиение на секторы выполняет DOS. Одиночный MAIN-тест передаёт нижний буфер файла одним запросом, а HIGH — порциями до размера верхнего окна. Время C-обёрток SDK не включено: измеряется их общий системный FILEHANDLE. Raw по-прежнему обращается к локальным физическим драйверам по заранее собранному списку секторов.

Для DOS измеряется загрузка данных непосредственно в локальный буфер банка DOS, как при загрузке тела модуля/драйвера. Время загрузки самого измерителя по-прежнему исключено; проверка формата исполняемого контейнера, контрольная сумма и релокация не входят в этот файловый тест. MAIN-модуль резервирует буфер 2C00h–8BFFh внутри собственного образа, EXEC-модуль — 2000h–7FFFh в принадлежащем ему отдельном банке. DOS-буфер не выходит за арену DLL и не пересекает потоковые контексты BAT с D800h или служебный стек. Границы проверяет ассемблер. Временный список Raw-кластеров контроллера расположен по 8100h–81BFh между его FAT-буфером 8000h и верхним окном 8200h, чтобы освободить место для кода контроллера.

Результаты старого запуска без выбора исполнителя нельзя смешивать с MAIN DLL: прежний контроллер включал в Raw стоимость MXOS_CALL RAW_IO на каждом секторе. На A: это давало около 64/39 вместо 72/42 КиБ/с для MAIN DLL. Выбор MAIN из меню и -C:MAIN теперь запускают один и тот же измеритель. Встроенный контроллер сохранён в исходниках для совместимости; его физический цикл также переведён на локальный PREPARE.


## Непрерывные серии RAW и FILE

Ключи `-C:MAIN|DOS|BANK|ALL` задают размещение вызывающего кода, а независимые `-M:RAW|FILE|ALL` — способ доступа. Название FILE заменяет прежнее DOS в строках результатов; название столбца DOS по-прежнему означает банк исполнения. Без `-M:` выполняются оба способа. Старые короткие ключи исполнителя сохраняются для совместимости.

В DLL-измерителе таймер считывается на границах всей серии, без промежуточных отсчётов, заполнения или сравнения буфера на каждом секторе. RAW использует заранее построенный список LBA и стабильный буфер 256 байт; MAIN A: дополнительно использует верхний буфер 8200h. Подготовка шаблона и обычная проверка прочитанного выполняются вне READ/WRITE. После RAW READ проводится отдельное нетактуемое чтение и сравнение всех тестовых секторов. Это проверка корректности результата, а не дополнительный вклад в скорость READ.

FILE передаёт весь локальный буфер одним FILEHANDLE-запросом; OPEN готового файла, запись, FLUSH и CLOSE входят в FILE WRITE. Создание и выделение цепочки завершены до таймера. FILE READ включает OPEN, чтение всего буфера и CLOSE, а последующее сравнение исключено. При `-V=1` после WRITE отдельно измеряется полное чтение и побайтовое сравнение готового файла. WRITE + VERIFY — сумма времени записи и этого прохода; повторной записи для получения второй скорости нет. Подготовка буфера до проверки исключена из времени VERIFY.

`-V=2` выбирает B=5 и для RAW, и для FILEHANDLE. Перед запуском DLL DiskBen временно устанавливает настройку DOS_IO_VERIFY_FILES, а при обычном или ошибочном выходе восстанавливает прежнюю; `-V=0/1` временно отключают её, чтобы получить сопоставимые результаты. Проверяются полные физические блоки данных, включая собранный в кэше неполный сектор; FAT и каталог сохраняются обычным путём. В MAIN A: полная RAW-проверка при `-V=1` отдельно измеряется для HIGH и LOW. В обеих строках WRITE + VERIFY суммируются соответствующая запись и полное проверочное чтение со сравнением; для HIGH используется тот же верхний буфер 8200h. Проверка начинается после физического flush.

При наличии DISK_CAP_FLUSH границы финального flush измеряются дополнительно, чтобы показать его вклад; он включён в WRITE и не вызывается после каждого RAW-сектора. В обычном режиме непрерывный интервал должен укладываться в один период каскада ВИ53: при 2 МГц это 8,388608 с; увеличенный период разбросанного режима описан ниже. Сумма отдельных проходов хранится в U32; это не снимает ограничения на длительность одного интервала.

Полные сектора данных обходят кэш DOS. Общий кэш 8 КиБ содержит метаданные, а неполный сектор обслуживается отдельным слотом. Поэтому крупный файл сам по себе не гарантирует вытеснения кэша: повторная файловая проверка дорожает при большом рабочем наборе FAT, в том числе при сильной фрагментации. Файл 8 КиБ и ограниченный буфер DOS 8 КиБ не представляют нагрузку, гарантированно вытесняющую весь пул метаданных.


## Последовательное и случайное размещение

`-F=1` открывает собственный DISKBEN.TMP с FILE_MODE_SCATTER. Новый кластер ищется от псевдослучайной позиции по всему диапазону кластеров тома; занятые кластеры пропускаются штатным ограниченным поиском с возвратом к началу. Чужие файлы и их цепочки не переставляются, заполняющие файлы не нужны. На диске остаётся обычная совместимая FAT-цепочка; режим не меняет формат тома. При почти заполненном томе или попадании в занятую область распределение смещается к оставшимся свободным кластерам: это случайная подсказка поиска, а не обещание равномерной выборки свободных кластеров.

OPEN задаёт фиксированный seed ACE1h для LFSR; поэтому при одинаковой разметке и состоянии свободного места получается воспроизводимая цепочка. Подготовка кандидата, поиск, выделение и обновление FAT выполняются до FILE WRITE, вне замера. RAW затем использует тот же список физических секторов, собранный до замера. Разные прогоны на изменённом томе могут получить другую цепочку даже с тем же seed. При `-W=0` файл не создаётся и фрагментация не применяется.

Без `-F=` после размера файла задаётся вопрос `Allocation [0]: 0=sequential, 1=random:`. Прогресс имеет вид `MAIN: Pass 1/1  Allocation: random`; для обычного размещения остаётся строка Pass. Пример: `DISKBEN A: -C:MAIN -M:FILE -F=1 -V=2 -W=1 -S=8`.

В разбросанном режиме делитель канала 1 ВИ53 увеличен с 256 до 1024: шаг 512 мкс, один непрерывный интервал до 33,554432 с при 2 МГц. В статистику возвращаются нормализованные тики по 128 мкс, поэтому единицы времени и КиБ/с общие с обычным режимом. Это увеличивает допустимую длительность медленной фрагментированной записи без отсчётов внутри передачи; результат всё равно недостоверен, если отдельная операция превышает этот период. Увеличение числа проходов не удлиняет один измеряемый интервал.


## Подготовленный файл и полный буфер DOS

Перед измерением каждого прохода DiskBen создаёт DISKBEN.TMP, выполняет SEEK к последнему байту и записывает один байт. Штатный FILEHANDLE выделяет всю цепочку, включая случайное размещение при F=1. Затем CLOSE сохраняет каталог/FAT и завершает физический flush. Весь этап находится вне таймера. Содержимое промежутка не используется до полной перезаписи. Измеряемый WRITE открывает существующий файл с READ|WRITE без CREATE/TRUNCATE, передаёт весь буфер одним запросом и выполняет FLUSH/CLOSE. Удаление также исключено. Поэтому результат показывает перезапись готовой цепочки и не включает искусственный поиск свободных кластеров.

DOS-модуль теперь располагает полным буфером 8 КиБ (CA00h–E9FFh в текущей сборке). Для этого MODULE_TARGET_DOS временно занимает неактивную область BAT; загрузка большой DLL при активном BAT и запуск BAT при загруженной большой DLL отклоняются. Выгрузка возвращает область. При запуске из NC полный пакет MAIN/DOS/BANK использует одинаковый файл 8 КиБ; общий кэш метаданных остаётся 8 КиБ. Нельзя запускать этот DOS-вариант из активного BAT-сценария: его кадры должны сохраняться.

Названия sequential/random относятся к размещению цепочки: F=0 использует обычный последовательный поиск свободных кластеров, F=1 начинает поиск от псевдослучайных позиций. Передача в обоих случаях идёт по порядку файла; отдельные случайные seek-запросы FILEHANDLE не моделируются. На заполненном томе последовательный поиск может использовать дырки, а AT2MXF чередует чипы, поэтому физическая непрерывность F=0 не гарантируется.

Пакетный результат занимает 3×60 байт во временной области MAIN 2000h. MAIN-измеритель выполняется первым, а его результат копируется только после MODULE_UNLOAD; последующие DOS/BANK не используют эту область основной памяти. Это позволяет расширять счётчики, не занимая постоянное место в коде контроллера ниже 2000h.

В DLL-измерителях построение RAW-списка LBA повторно использует последний прочитанный сектор FAT в существующем fatBuffer. Метка действительна только внутри одного построения цепочки; переход к другому сектору FAT вызывает новое чтение.
