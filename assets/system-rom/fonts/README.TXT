Сменные шрифты MXOS
==================

Установка
---------

Файлы движков находятся в C:\FONTS. В NC нажмите Enter
на нужном .fnt или установите движок командой FONT:

  FONT 6x8/Rotate
  FONT 6x8/Fast
  FONT 6x8/Packed

Путь без диска отсчитывается от C:\FONTS. Разделители
/ и \ равнозначны. Расширение .fnt можно опустить.

Как движки рисуют
-----------------

Координата X определяет, в какие биты экранного байта
попадает строка глифа. Если она пересекает границу,
одна её часть идёт в левый байт, вторая в правый.
Смещение глифа внутри байта называется фазой.

Движок Rotate вычисляет сдвиги во время вывода. У 6x8
четыре глифа занимают 24 пикселя и дают три экранных
байта. Внутри такой группы движок пишет полные байты,
а на краях сохраняет пиксели соседей по маске. У 8x8
один выровненный глиф занимает целый байт на каждой
строке. Без выравнивания 8x8/Rotate сдвигает строки
глифов.

Движок Fast при установке заранее вычисляет сдвиги и
хранит готовые части глифов в ОЗУ. При выводе части
соседних глифов складываются побитовым OR. Так экономятся
такты за счёт дополнительных таблиц в MAIN. У 6x8/Fast
там пять таблиц по 2 КиБ, всего 10 КиБ. У 8x8/Fast три
фазы по две таблицы на каждую, всего 12 КиБ в MAIN.

Движок Packed тоже использует готовые фазы, но части для
соседних экранных байтов хранятся в разных полях одного
байта. Движок извлекает их масками. 6x8/Packed хранит
три таблицы по 2 КиБ, из них две в MAIN. У 8x8/Packed
три таблицы в MAIN, всего 6 КиБ.

4x8/Fast хранит старшие и младшие полубайты раздельно,
по 2 КиБ на таблицу. 4x8/Packed хранит один 2-КиБ
массив, повторяя растр глифа в обеих половинах байта.
4x8/Compact хранит растр двух соседних кодов в байте,
по одному глифу на полубайт. Занимает 1 КиБ исходных
данных и строит ещё 1 КиБ обратной таблицы в слоте.
Все три движка 4x8 используют шрифт CP/M Сябра.

Адресация таблиц
----------------

В быстрых движках таблица хранится по строкам растра.
Одна страница в 256 байт содержит одну строку у всех
256 глифов. Старший байт адреса выбирает строку и фазу,
младший - код глифа. Код можно сразу записать в L.
Для соседней страницы меняется только H. Адрес глифа
не приходится умножать на 8 или искать в таблице.

В фиксированном KOI-7R код занимает семь битов, 0..127.
В страницу вмещаются две половины по 128 глифов.
Бит 7 младшего байта выбирает половину. В зависимости
от таблицы в ней лежит другая строка растра или фаза.
Таблицы рассчитаны на 256 или 128 кодовых позиций.
Пустые коды тоже занимают место. Для меньшей таблицы
понадобится перевод кода в плотный индекс.

Профили KOI-7R: 6x8/K7Rotate, 6x8/K7Packed, 6x8/K7Hybrid.
У всех таблицы в верхнем слоте. K7Hybrid заранее
готовит фазы среднего байта четвёрки, остальные
сдвиги вычисляет при выводе. Благодаря этому он
помещается в верхний слот без резерва в MAIN. Для
возврата в KOI-8 установите обычный движок.

Вывод и память
--------------

Функция (вектор) bios_printChar печатает один символ.
Функция bios_printStringZ печатает строку текста,
обрабатываея CR/LF и другие управляющие коды. Функции
с Raw в названии игнорирует коды и рисует все символы
как глифы. Функция bios_printStringRawZ завершает печать,
встретив нулевой код (ASCII-Z строка). Функция
biosPrintStringRawLim выводит указанное число символов.

Шаг по Y - 10 пикселей. У ширифтов 8x8 и 6x8 координата X
задаётся с шагом два пикселя, у 4x8 округляется до границы
знакоместа.

У обычных движков KOI-8 и KOI-7R переключаются через
bios_setFontEncoding: A=0 выбирает KOI-8, иначе KOI-7R.
Перекодировки на лету нет, вместо этого физически
перестраиваются таблицы знакгенератора.

Резидентный слот D800h-EC7Fh содержит код и часть
таблиц. Дополнительные таблицы размещаются в MAIN.
Здесь memTop указан при отсутствии других резерваций.

Движок          MAIN, байт   memTop
-----------------------------------
6x8/Rotate               0    8BFFh
6x8/Packed            4096    7BFFh
6x8/Fast             10240    63FFh
8x8/Rotate               0    8BFFh
8x8/Packed            6144    73FFh
8x8/Fast             12288    5BFFh
4x8/Compact              0    8BFFh
4x8/Packed               0    8BFFh
4x8/Fast              2048    83FFh
6x8/K7Hybrid             0    8BFFh
6x8/K7Packed             0    8BFFh
6x8/K7Rotate             0    8BFFh

Смену резервации выполняет FONT.COM через MEM. Движок
при загрузке по умолчанию - 6x8/Rotate. NC учитывает
ширину шрифта и свободную память. Старые программы
могут не учитывать memTop, надо проверять совместимость.

Файлы и импорт
--------------

.fnt - движок со встроенным шрифтом.
.dll - временный инициализатор Init*.dll.
.pf  - плоский шрифт, 256 глифов по 8 байтов.
.pre - готовые таблицы для MAIN.

Штатные таблицы строятся при установке. Ключ -FILE
читает готовый .pre рядом с файлом .fnt.

  FONT 8x8/Rotate -IMPORT A:/MyFont.pf

Импорт устанавливает шрифт из 2048-байтного MyFont.pf.
Для 4x8 берутся младшие четыре бита каждой строки. Новый
комплект сохраняется на доступный RAM-диск, обычно B:.
Явно путь сохранения можно указать через -OUT B:/Custom.fnt.
Если записать файлы не удалось, шрифт остаётся установлен.

  FONT B:/Custom.fnt -FILE

Фиксированные модули KOI-7R поставляются с готовыми
таблицами в .fnt. Для них импорт недоступен.
