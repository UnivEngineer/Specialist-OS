# Входные данные системного ROM

В этом каталоге находятся негенерируемые входные файлы системного и flash- образов: шаблоны загрузочных секторов, AUTOEXEC/FORMAT, NC.EXT и шрифты.

Собираемые бинарники DOS и системных программ берутся из каталога `bin` согласно `scripts/images/manifests/A-System.txt`.

`FONT.FNT` и альтернативный `FONT_IT.FNT` — полные растровые шрифты KOI8-R по [RFC 1489](https://www.rfc-editor.org/rfc/rfc1489.txt): 256 глифов по 8 байтов, без заголовка. Строки глифа идут сверху вниз; шесть пикселей слева направо хранятся в битах 5…0 (`00xxxxxx`), то есть выровнены вправо внутри байта. В 80h–BFh находятся все 40 одинарных, двойных и смешанных рамочных символов, блоки, три плотности штриховки и математические знаки; ё=A3h, Ё=B3h, неразрывный пробел=9Ah. Ё/ё не вытесняют рамки. Начертания в 20h–7Fh и C0h–FFh сохраняются отдельно для каждого шрифта. Таблицы строк 00h–1Fh и 80h–BFh и воспроизводимое обновление обоих файлов: `python scripts/build/update-font-koi8.py --write`; без `--write` скрипт только сверяет файлы. `FONTKOI.FNT` остаётся отдельным компактным вариантом без диапазонов псевдографики и управляющих глифов.

В 00h–1Fh находятся видимые значки для Raw-вывода в стиле IBM PC; 00h имеет вид перечёркнутого нуля, 0Ah — компактной буквенной метки LF, 0Dh — CR. В метках LF/CR первая буква расположена сверху слева, вторая — снизу справа. Стандартные названия: LF (Line Feed, перевод строки) и CR (Carriage Return, возврат каретки); их отдельные Unicode-символы визуализации — ␊ U+240A и ␍ U+240D из [Control Pictures](https://www.unicode.org/charts/PDF/U2400.pdf). KOI8-R не задаёт печатные глифы управляющих кодов: эти рисунки — соглашение шрифта MXOS, а не изменение кодировки. Они видны при Raw-выводе; обычная обработка управляющих кодов BIOS сохраняется. Для вывода 00h в составе массива нужен Raw-вызов с явной длиной, поскольку нуль завершает ASCIIZ-строку.

Рамочные линии и блоки доходят до краёв ячейки 6×8. Для непрерывных вертикальных рамок строки нужно размещать с шагом 8 пикселей: штатный текстовый шаг BIOS 10 пикселей оставляет два пикселя между глифами. Изменение шрифта не меняет этот шаг. Знаки 93h/9Bh — верхняя и нижняя части высокого интеграла, которые ставятся друг над другом; 96h — квадратный корень. Кодировка определяет состав и позиции символов, но не конкретный рисунок пикселей.

Первичную подготовку B: выполняет RAMDISK.COM из AUTOEXEC: готовый том сохраняется, для неразмеченной памяти вызывается `A:\FORMAT.COM B: -R -Y`. FORMAT.BAT исключён из штатного манифеста и больше не запускается BIOS. Файл сценария сохранён как прежний ручной пример. Диск задаётся с двоеточием, `-R` включает особенности RAM-диска, `-Y` отключает запрос подтверждения. Без буквы диска FORMAT спрашивает её; без `-Y` сохраняется подтверждение. Системный A: форматировать запрещено при любых ключах.

NC.EXT передаёт RKS и EXE в `A:RUN.COM`; COM исполняется DOS. В образе COM/EXE имеют общий 16-байтный заголовок, RKS хранится со своим стандартным заголовком и суммой. Сменные ядра — `MONITOR2.MON` и `RAMFOS.MON`, SYS используется для DOS. Сырые бинарники и CPU/I80 служат входом сборщика, а не готовыми COM/EXE.

RAMDISK.COM — одноразовый установщик с флагом DRIVER, исполняемый по C000h в банке DOS. Он резервирует фиксированный пул через RAMLIMIT, монтирует готовый том либо размечает новую память через FORMAT, затем передаёт пул самой DOS через MEMORY/RAMDISK COMMIT. DLL, модульный handle и отдельный резидент не создаются; после RET область установщика доступна другим драйверам. RAMDISK.COM -P 4 резервирует четыре банка данных; вместе с банком DOS заняты пять из шестнадцати, одиннадцать остаются свободны. Дополнительный банк кода и резидентный слот DOS не требуются. Пул и содержимое B: сохраняются при тёплом Reset. Размер закреплённого пула фиксирован до холодного старта; динамических SHRINK/GROW и сжатия нет.
