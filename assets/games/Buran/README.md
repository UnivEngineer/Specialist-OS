# «Буран»

Космическая игра для «Специалиста» со статическими изображениями «Бурана» и спутников.

Три явно отличающихся платформенных варианта включены в **GAMES (Games2M) для пользовательской проверки**. Код не менялся. Все нагрузки загружаются с `0000h`; для STD используются RKS, для MX/RAMFOS — сырой EXE.

## Историческое название и конфликт имён

В одной из версий «Бурана» в меню действительно написано «Звёздные войны». Поэтому название и архивное имя `STARWARS.RKS` являются историческими, а не просто ошибкой именования файла.

Имя `STARWARS.RKS` встречается также у трёхмерной игры StarWars. По одному имени определить игру нельзя; для различения нужны происхождение и содержимое файла. Здесь сохранены варианты «Бурана», перечисленные в таблицах.

После пользовательского сравнения TP и GM убраны из рабочего каталога и GAMES. TP совпадает с SW без пяти хвостовых нулей; GM — архивная адаптация той же игры с прежним меню, изменениями вывода строк и кодировки. Их исходные файлы сохранены в `legacy`.

## Цвет, звук и статус проверки

У Lafan/RAMFOS-варианта найдены прямые обращения к MX-цвету `FFF8h`, RAMFOS-курсору `C63Eh` и каналам ВИ53 `FFECh–FFEEh`, например в участке `02FAh–0339h`. Это аппаратная адаптация «Бурана» с цветной графикой и таймерным звуковым кодом. Звучание ВИ53 этого конкретного архивного бинарника на оборудовании в текущем исследовании не проверялось. У этого варианта также остаются программные звуковые обращения к ВВ55.

Пользователь подтвердил, что играл в цветного «Бурана» на реальном «Специалисте» под MXOS. Это подтверждает совместимость цветной версии с MXOS на оборудовании; объявлять её несовместимой только по наличию вызовов RAMFOS неверно. Точный хеш исторически запускавшегося файла и версия MXOS не зафиксированы, поэтому это свидетельство пока не привязано побайтно к сохранённому `Buran-ramfos.exe`.

Остальные варианты имеют STD-обращения ВВ55 `FF00h–FF03h`. Полная приёмка всех сохранённых вариантов в текущем исследовании не выполнялась.

## Пользовательская проверка 02.11.2026

- `Buran.rks`: цветной, в логотипе «Звёздные войны», меню с перемещаемой плашкой, вход по пробелу. Работает в STD/MON.
- `Buran-SW.rks`: монохромный, в логотипе «Звёздные войны», меню с выбором цифрой, вход в игру работает.
- `Buran-TP.rks` и Germanovitsh-копия (`Buran-GM.rks` в манифесте): по наблюдению пользователя аналогичны SW. У TP все 5785 байт нагрузки совпадают с началом SW, отличаясь отсутствием пяти нулей в хвосте; GM имеет 189 замен и 59 дополнительных байт, включая изменения вывода строк и кодировки.
- `Buran-RF.exe`: цветной, звук выстрела есть, в текущей MXOS наблюдаются ошибки. Это не подтверждённая рабочая версия для текущей MXOS.

Для RF обнаружены CALL `C80Fh` с несовпадающим назначением, девять записей курсора в RAMFOS `C63Eh` вместо MXOS `8FFCh`, выход через `F800h` и запись в `F802h`. Подробный список адресов сохранён в локальном `docs/games/buran-abi-002/REPORT.md`. Бинарник пока не исправлялся.

## Аппаратная адресация

RAMFOS использует MX-карту: ВВ55 клавиатуры расположен по `FFE0h–FFE3h`. По `F800h` у RAMFOS находится таблица входов ОС (`JP init`), а не ВВ55. Только в аппаратном STD-режиме ВВ55 отображается в окне `F800h–FFFFh`.

В `Buran-ramfos.exe` сохранилась запись в `F802h` в звуковом цикле. Это STD-фрагмент внутри MX-адаптации; он не подтверждает другую аппаратную карту RAMFOS. Цикл пишет `20h` и `00h` 150 раз, оставляя `00h`. Если область находится в ПЗУ и записи игнорируются, дефект может быть незаметным; в записываемой памяти он портит код таблицы входов. Изолированная CPU-проверка с историческим RAMFOS в RAM изменила `JMP F92Ah` по `F800h` на `JMP 002Ah`. Это не отменяет остальных признаков RAMFOS-порта. Подробности: `docs/compat/ramfos-archive-scan-001/REPORT.md`.

## Воспроизведение контейнеров

Из корня репозитория:

```powershell
python -X utf8 scripts/games/package-buran.py
python -X utf8 scripts/games/package-buran.py --check
```

Сначала проверяются SHA-256 всех шести эталонов. Затем создаются или проверяются три платформенные копии: два обычных RKS и сырой RAMFOS EXE копируются без изменения нагрузки. Архивные TP и GM не публикуются и не восстанавливаются в рабочем каталоге. Код не патчится. Исторический EXE с лишним для нагрузки хвостом суммы сохранён только в `legacy`.

Проверены хеши, контейнеры и идентичность объявленных нагрузок. В GAMES включены платформенные копии; файлы `legacy` в образ не входят. Локальный отчёт: `docs/games/buran-package-001/`.
