# Измерение времени через ВИ53

Для измерения используйте прямой `CALL io_pitRead` из MAIN, DOS или EXEC. IO.SYS помещает одну и ту же реализацию в каждую исполняемую страницу. Отсчёт занимает 54 такта 8080 с RET, или 71 такт вместе с CALL. В коде приложения вызов занимает три байта. Достаточно подключить `mxos.inc` или `abi/timer.inc`.

| Вход IO.SYS             | Результат                                                                                                  |
| ----------------------- | ---------------------------------------------------------------------------------------------------------- |
| `io_pitRead` (F1B1h)    | HL = защёлкнутый убывающий счётчик 2, A = L. BC, DE и флаги сохранены.                                     |
| `io_pitGetPort` (F1BBh) | CF=0, HL = адрес канала 0 в памяти. Для профиля IN/OUT CF=1, H=0, L = порт канала 0. A, BC и DE сохранены. |

Регистры канала 1, канала 2 и управления идут подряд за каналом 0 в том же адресном пространстве. Для IN/OUT база четырёх последовательных портов лежит в диапазоне 00h–FCh. На «Специалисте-MX» используется адресация через память. Настройка для IN/OUT использует такой же контракт и явно подставляет номер порта в команду OUT. Чтение защёлкивает канал 2 командой 80h ВИ53 и возвращает два байта одного отсчёта.

Перед настройкой получите владение через `MXOS_DOS_TIMER` с A=TIMER_RAW. Освободите таймер через TIMER_RELEASE. Подготовьте таймер один раз перед измерением из `lib/timing-pit.inc`, разместив процедуры в доступном для записи коде приложения. DOS отдельно использует TIMER_CLOCK для режима 0 счётчика 2 и клавиатурного щелчка. [Владение ВИ53 и клавиатурный API](../../../source/mem/api.md#владение-ви53)

| Процедура настройки   | Действие                                                                               |
| --------------------- | -------------------------------------------------------------------------------------- |
| `pitTimerInit`        | Настроить делитель канала 1 на 256, счётчик 2 на режим 2 и выключить несущую канала 0. |
| `pitTimerInitDivisor` | Та же настройка с делителем HL.                                                        |
| `pitTimerWaitReady`   | Дождаться двух изменений счётчика 2 после настройки.                                   |
| `pitTimerBindWrites`  | Подготовить записи для собственного профиля, например звуковых эффектов.               |

`pitTimerInit` и `pitTimerInitDivisor` включают ожидание готовности. CF=1 означает тайм-аут, CF=0 разрешает брать первую отметку. При собственной настройке вызовите `pitTimerWaitReady` после записи обоих байтов канала 2, поскольку первое чтение может вернуть прежний счёт до фронта CLK. Для собственной конфигурации определите `TIMING_PIT_WRITES_ONLY`, чтобы подключить только привязку и записи `pitTimerWriteCh0`, `pitTimerWriteCh1`, `pitTimerWriteCh2` и `pitTimerWriteControl`. Эти вызовы передают A в аппаратный регистр и сохраняют регистры и флаги.

Каскад требует аппаратного соединения OUT1 с CLK2 и активных GATE1/GATE2. Частота тика равна CLK1, делённой на делитель канала 1. Для CLK1=2 МГц и делителя 256 период U16 составляет 8,388608 с. Интервал между соседними выборками должен быть короче периода счётчика.

`timing-counter.inc` накапливает модульные разности U16 в U32. Задайте `timer_read = io_pitRead` и переменные `v_elapsed`, `v_setup`, `v_last`. `timing.inc` добавляет пересчёт в миллисекунды и десятичный вывод. `timing-ms.inc` дополняет его печатью дробных миллисекунд. Два отсчёта на пакет распределяют стоимость измерителя между операциями, а отдельные отсчёты на сектор позволяют исключить заполнение и сравнение буферов.
