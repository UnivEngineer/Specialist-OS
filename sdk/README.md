# SDK MXOS для C

`include/mxos.h` и `src/mxos.c` открывают уже реализованные службы BIOS/DOS. Горячие функции sccz80 имеют короткие переходники в `src/mxos_z88dk.asm`: например, putch занимает четыре байта и передаёт управление BIOS без упаковки регистров. Для остальных вызовов есть общий мост `mxos_bios_call(MXOS_REGS*)`: пять 16-битных слов entry/AF/BC/DE/HL, sizeof=10; после вызова в них находятся выходные регистры и флаги. Адреса проверяются `scripts/tests/check-sdk-abi.py` по собранному mxos.inc.

| Группа | Обёртки |
|---|---|
| Память | memcpy/memmove с перекрытием, контрольная сумма Monitor-2, get/set memtop, освобождение модуля |
| Консоль | getch/getkey/keyscan, putch, puts без добавления перевода строки, readline с нулевым терминатором, очистка, координаты курсора, DEC/HEX |
| Строки | upper для KOI, сравнение N байт с учётом регистра или без него |
| Таймер | Инициализация и чтение штатного измерителя ВИ53 |
| Диски | Выбор диска, DISK_INFO и физическая ёмкость, логический сектор, flush и числовая ошибка |
| Файлы | Список FILE_INFO, stat, загрузка/сохранение целиком, удаление, переименование и копирование с явным запросом/буфером |
| Графика | Список объектов, инверсия и перенос прямоугольника; нужен загруженный DOSMOD |

Префикс всех функций таблицы — `mxos_`; точные прототипы находятся в заголовке. FILE_DESCRIPTOR/FILE_INFO/DISK_INFO/FILE_COPY_REQUEST представлены массивами 32/16/48/80 байт с фиксированными смещениями из mxos.inc. Буфер списка должен иметь capacity×16+1 байт для завершающего FFh. Полная загрузка файла требует заранее проверенного размера и достаточного буфера; для потокового доступа используется интерфейс ниже.

Консольные getch/putch/puts/readline обращаются непосредственно к BIOS. Стандартные stdin/stdout/stderr будут реализованы выше SDK, вместе с CLI, наследованием потоков и перенаправлением. Файловый backend ниже предоставляет операции над конкретным открытым файлом; глобальных стандартных потоков в нём нет. Будущий CLI сможет назначать stdout файлу для команды `DISKBEN.EXE -H > B:RESULT-H.TXT`; сейчас такого синтаксиса и режима DISKBEN ещё нет.

## Файловый backend

`include/mxos_file.h` и `src/mxos_file.c` — основа файлового backend для собственной stdlib. `MXOS_FILE` содержит только 64 байта двоичного ABI; выравнивание структур компилятора не влияет на раскладку. Требуются 8-битный char, 16-битные unsigned short/указатели и 32-битный long. Объект выделяет вызывающий; адаптер не использует malloc и скрытую таблицу открытых файлов DOS.

В начале программы вызвать `mxos_dos_init()` и проверить нулевой код DOS. Программа/heap должны оставаться ниже memtop, при загруженном модуле — не выше 7FFFh; стек наследуется от DOS. Системный стек занимает 479 байт; крупные объекты и буферы удобно размещать в статической памяти или heap. Затем доступны open/read/write/seek/flush/close, fread/fwrite, fgetc/fputc, ftell, feof/ferror/clearerr. Полный контракт ядра и раскладка FILE_HANDLE приведены в [описании DOSMOD](../source/dosmod/README.md).

```c
#include "mxos_file.h"

MXOS_FILE file;
char buffer[128];

/* После успешного mxos_dos_init(): */
if (mxos_fopen(&file, "B:EDITOR.CFG", "w+b") == 0) {
    mxos_fwrite("OPTION=1\r\n", 1, 10, &file);
    mxos_fseek(&file, 0, MXOS_SEEK_SET);
    mxos_fread(buffer, 1, sizeof(buffer), &file);
    if (mxos_fclose(&file) != 0) {
        /* Проверить mxos_ferror(&file), повторить flush/close после устранения ошибки. */
    }
}
```

Режимы: r, w, a, r+, w+, a+, необязательный b в любом порядке с +. Имена — точные 8.3 в KOI-8, необязательный префикс A:–H:, без префикса используется текущий диск DOS. Пути и каталоги пока не реализованы. Преобразования CR/LF нет. CREATE/TRUNCATE выполняются при открытии; READ/WRITE передают байты, fread/fwrite возвращают количество целых элементов. Произведение size×count должно помещаться в 16 бит; непрерывный буфер должен помещаться в доступной памяти.

Ошибки числовые: `mxos_ferror` возвращает код DOS, EOF хранится отдельно. Указатель после частичного чтения/записи продвигается на фактически переданные байты. `mxos_ftell` возвращает unsigned 32-битную позицию; при подключении к stdlib с signed long её нужно проверять на представимость. FOPEN здесь принимает адрес готового объекта и возвращает 0/−1; собственная stdlib может выдавать FILE* из своего пула и устанавливать errno. Текстов ошибок в ядре нет.

Для другого компилятора реализовать `mxos_bios_call` и три файловых переходника: `mxos_file_call(MXOS_FILE*)` передаёт указатель в HL, байт bytes[63] в A и вызывает C8D5h; `mxos_dos_init()` вызывает C8D8h; `mxos_current_drive()` вызывает C842h с E=0. Возвращаемое A преобразуется в unsigned char согласно соглашению компилятора. В `src/mxos_file_z88dk.asm` есть готовый мост sccz80 `__z88dk_fastcall`, состоящий только из команд 8080.

Проверка `python scripts/tests/check-file-stdlib.py --z88dk <каталог z88dk>` компилирует backend и `tests/file-stdio.c` с `-clib=8080`, затем запускает машинный код с настоящим DOS/DOSMOD и моделью блочного драйвера. Проверяются память, флаги регистрового моста, клавиатурные обёртки, вывод, курсор, строки, memtop, файловые службы и файловый backend. Профиль +cpm используется только для выбора 8080-компилятора и арифметической библиотеки; собственный CRT не вызывает BDOS CP/M. Это проверка CPU, не реального оборудования.
