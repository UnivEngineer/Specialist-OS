# SDK MXOS для C

Новый `mxos_call(MXOS_CALL*)` обращается к общему входу F800h. Структура содержит пять слов: operation, HL, DE, BC, AF; operation=(группа<<8)|номер. Она предназначена для родных групп BIOS/DOS, использующих регистровый пакет. Имена `MXOS_BIOS_*`/`MXOS_DOS_*` генерируются из `source/bios/syscalls.json` в `include/mxos_syscall_ids.h`. Файловый мост `mxos_file_call` уже использует регистровый адаптер F806h с номером `MXOS_DOS_FILEHANDLE`. Остальные старые именованные входы пока доступны параллельно для поэтапной миграции. C-обёртка возвращает AF как 16-битное слово, включая CF/код A при отказе диспетчера, когда сам пакет не изменяется. Группа BDOS пока зарезервирована и возвращает UNSUPPORTED; работа CP/M предполагает отдельное сменное ядро.

Старый mxos_bios_call с MXOS_BIOS_ABI_RAMD_DRIVER относится к прежним переключаемым шаблонам RAMD. В штатной системе окно принадлежит MEM: для межбанкового обмена используйте FAR API, для диска — секторные службы. Не устанавливайте исторические BYTE/R3/USER-шаблоны поверх MEM.

`include/mxos.h` и `src/mxos.c` открывают уже реализованные службы BIOS/DOS. Горячие функции sccz80 имеют короткие переходники в `src/mxos_z88dk.asm`: консольные функции используют банковый регистровый вход F806h без упаковки полного пакета. Для остальных вызовов есть общий мост `mxos_bios_call(MXOS_REGS*)`: пять 16-битных слов entry/AF/BC/DE/HL, sizeof=10; после вызова в них находятся выходные регистры и флаги. Адреса проверяются `scripts/tests/check-sdk-abi.py` по собранному mxos.inc.

| Группа | Обёртки |
|---|---|
| Память | memcpy/memmove с перекрытием, контрольная сумма Monitor-2, get/set memtop, освобождение модуля |
| Консоль | getch/getkey/keyscan, putch, puts без добавления перевода строки, readline с нулевым терминатором, очистка, координаты курсора, DEC/HEX |
| Строки | upper для KOI, сравнение N байт с учётом регистра или без него |
| Таймер | Инициализация и чтение штатного измерителя ВИ53 |
| Диски | Выбор диска, DISK_INFO и физическая ёмкость, логический сектор, flush и числовая ошибка |
| Файлы | Список FILE_INFO, stat, загрузка/сохранение целиком, удаление, переименование и копирование с явным запросом/буфером |
| Графика | Список объектов, инверсия и перенос прямоугольника через BIOS |

Префикс всех функций таблицы — `mxos_`; точные прототипы находятся в заголовке. FILE_DESCRIPTOR/FILE_INFO/DISK_INFO/FILE_COPY_REQUEST представлены массивами 32/16/48/86 байта с фиксированными смещениями из mxos.inc. Буфер списка должен иметь capacity×16+1 байт для завершающего FFh. Полная загрузка файла требует заранее проверенного размера и достаточного буфера; для потокового доступа используется интерфейс ниже.

Консольные getch/putch/puts/readline обращаются непосредственно к BIOS. Стандартные stdin/stdout/stderr будут реализованы выше SDK, вместе с CLI, наследованием потоков и перенаправлением. Файловый backend ниже предоставляет операции над конкретным открытым файлом; глобальных стандартных потоков в нём нет. Будущий CLI сможет назначать stdout файлу для команды `DISKBEN.EXE -H > B:RESULT-H.TXT`; сейчас такого синтаксиса и режима DISKBEN ещё нет.

## Файловый backend

Первое API каталогов: `MXOS_MAX_PATH=128`, `MXOS_PATH` содержит массив `bytes[128]`. `mxos_chdir(path.bytes)` принимает весь буфер с завершающим 0, с необязательным префиксом диска; длина строки до 127 байт. Диск выбирается через `mxos_drive_select`. Поддерживаются абсолютные/относительные пути, `/`, `\`, . и ..; ошибка не меняет текущий каталог. `mxos_directory_get` возвращает компактный контекст — кластер, `mxos_directory_set` восстанавливает ранее полученный контекст на том же томе. Для строкового пути используется mxos_getcwd. `mxos_directory_list` имеет контракт file_list, но включает каталоги и записи . / ... Полный ABI — [DOS](../source/dos/README.md#каталоги-первый-этап).

Буфер пути принадлежит программе; удобно объявить `static MXOS_PATH path = { "/Almaz/MXOS" };`. После успешного `mxos_chdir(path.bytes)` можно открывать файлы этого каталога через `mxos_fopen(&file, "ALMAZ2MX.EXE", "rb")`. Сам fopen пока не разбирает вложенный путь. mkdir/rmdir и расширение заполненного каталога относятся к следующему этапу.

`include/mxos_file.h` и `src/mxos_file.c` — основа файлового backend для собственной stdlib. `MXOS_FILE` содержит только 64 байта двоичного ABI; выравнивание структур компилятора не влияет на раскладку. Требуются 8-битный char, 16-битные unsigned short/указатели и 32-битный long. Объект выделяет вызывающий; адаптер не использует malloc и скрытую таблицу открытых файлов DOS.

В начале программы вызвать `mxos_dos_init()` и проверить нулевой код DOS. Программа/heap должны оставаться ниже memtop, в штатной системе — не выше 8BFFh; стек наследуется от DOS. Системный стек занимает 479 байт; крупные объекты и буферы удобно размещать в статической памяти или heap. Затем доступны open/read/write/seek/flush/close, fread/fwrite, fgetc/fputc, ftell, feof/ferror/clearerr. Полный контракт ядра и раскладка FILE_HANDLE приведены в [описании DOS](../source/dos/README.md#открытые-файлы).

```c
#include "mxos_file.h"

MXOS_FILE file;
char buffer[128];

/* После успешного mxos_dos_init(): */
if (mxos_fopen(&file, "B:EDITOR.CFG", "w+b") == 0) {
    mxos_fwrite("OPTION=1\r\n", 1, 10, &file);
    mxos_fseek(&file, 0, MXOS_SEEK_SET);
    mxos_fread(buffer, 1, sizeof(buffer), &file);
    if (mxos_fclose(&file) != 0) {
        /* Проверить mxos_ferror(&file), повторить flush/close после устранения ошибки. */
    }
}
```

Режимы: r, w, a, r+, w+, a+, необязательный b в любом порядке с +. Имена — точные 8.3 в KOI-8, необязательный префикс A:–H:, без префикса используется текущий диск DOS. Каталог выбирается через mxos_chdir; вложенный путь в самом fopen пока не разбирается. Преобразования CR/LF нет. CREATE/TRUNCATE выполняются при открытии; READ/WRITE передают байты, fread/fwrite возвращают количество целых элементов. Произведение size×count должно помещаться в 16 бит; непрерывный буфер должен помещаться в доступной памяти.

Ошибки числовые: `mxos_ferror` возвращает код DOS, EOF хранится отдельно. Указатель после частичного чтения/записи продвигается на фактически переданные байты. `mxos_ftell` возвращает unsigned 32-битную позицию; при подключении к stdlib с signed long её нужно проверять на представимость. FOPEN здесь принимает адрес готового объекта и возвращает 0/−1; собственная stdlib может выдавать FILE* из своего пула и устанавливать errno. Текстов ошибок в ядре нет.

Для другого компилятора реализовать `mxos_bios_call` и три файловых переходника: `mxos_file_call(MXOS_FILE*)` передаёт указатель в HL, байт bytes[63] в A и выполняет CALL F806h / DW MXOS_DOS_FILEHANDLE; `mxos_dos_init()` вызывает C8D8h; `mxos_current_drive()` вызывает C842h с E=0. Возвращаемое A преобразуется в unsigned char согласно соглашению компилятора. В `src/mxos_file_z88dk.asm` есть готовый мост sccz80 `__z88dk_fastcall`, состоящий только из команд 8080.

Проверка `python scripts/tests/check-file-stdlib.py --z88dk <каталог z88dk>` компилирует backend и `tests/file-stdio.c` с `-clib=8080`, затем запускает машинный код с настоящим BIOS/DOS и моделью блочного драйвера. Проверяются память, флаги регистрового моста, клавиатурные обёртки, вывод, курсор, строки, memtop, файловые службы и файловый backend. Профиль +cpm используется только для выбора 8080-компилятора и арифметической библиотеки; собственный CRT не вызывает BDOS CP/M. Это проверка CPU, не реального оборудования. На текущей карте этот старый стенд останавливается в check-file-handle.py на устаревших границах 7FE0h/8000h; его успешное прохождение сейчас не подтверждено. Новые heap/runtime проверяются отдельными check-near-heap.py и scripts/emu80/check-memory-lifecycle.py.

`mxos_getcwd` заполняет MAX_PATH-буфер абсолютным путём с `\`; `mxos_chdir` допускает префикс диска и оба разделителя. MXOS_COPY_REQUEST теперь занимает 86 байт: слова по смещениям 80 и 82 — каталоги источника и назначения (0 — корень).

`mxos_file_getattr`/`mxos_file_setattr` используют существующий ABI C857h для файлов и каталогов: изменяются R/H/S/A, DIR сохраняется. `mxos_file_move` принимает тот же запрос, что COPY; внутри одного тома переносит запись без копирования данных. Обёртки входят в вызывающую C-программу, а не в DOS.

FILE_COPY_REQUEST.onExists (слово по смещению 84) — необязательный адрес обработчика в соглашении 8080: HL=запрос, A=0 пропуск / A=1 замена / A=2 Yes to all / A=3 No to all, CF=0; CF=1 отказ. Значение 0 сохраняет неинтерактивный отказ EXISTS. Это адрес машинной процедуры, а не обычный указатель на C-функцию; C-клиент обнуляет поле либо предоставляет ASM-переходник.

## FAR-копирование MEM

mxos_memcpy_far(MXOS_FAR_COPY*) вызывает локальную точку F80Fh одинаково в main и исполняемом банке, без DOS. Пакет 8 байт содержит FAR-источник, FAR-приёмник и длину; код 0 означает main, 1…16 — банки ДОЗУ. Возвращается слово AF: CF в младшем байте, код ошибки в старшем. Нулевой размер разрешён, граница диапазона — FF00h, перекрытие запрещено контрактом. Это не malloc: владение памятью и сохранность кода/стека обеспечивает вызывающий. Профиль аппаратного окна после копирования не восстанавливается немедленно; службы MEM переключают его при необходимости. Прочие исторические C-обёртки с прямыми Cxxx-вызовами пока предназначены для main; наличие FAR-копии не делает весь SDK готовым для банковой загрузки.

## Печать из банка и main

`mxos_printString_bank(const char *text)` печатает локальную ASCIIZ: из банка через скрытый цикл Window20, из main нативно. `mxos_printString_main(mxos_u16 address)` явно задаёт адрес ASCIIZ в main и передаёт в BIOS только регистры, без пересылки текста. Буфер main должен оставаться действительным до возврата. ASM-эквиваленты — `MXOS_CALL MXOS_BIOS_PRINT_STRING_BANK` и `MXOS_CALL MXOS_BIOS_PRINT_STRING_MAIN`, адрес в HL. Прежние PRINT_STRING и mxos_puts_local сохраняются.

## Аллокатор и операции памяти

Закреплённый регистровый контракт, ошибки, границы и правила владения: [публичный ABI MEM](../source/mem/api.md). Подключение mxos_far.c добавляет malloc/free/realloc FAR, регистрацию main-арены и GET/PUT; эти обёртки входят в программу, не в ядро. Все номера MEM_OP и ошибки продублированы в mxos.h и сверяются с ASM. Размер MXOS_FAR_ADDRESS — 3 байта, MXOS_FAR_COPY — 8 байт. Вызовы возвращают AF; проверять MXOS_CF до использования результата.

Перед FAR-выделением в main нужно передать собственный диапазон mxos_main_arena; локальная C-куча не должна использовать эти байты. Лимит FAR-реестра — 32 блока, один блок не пересекает банк. FILE_EXEC очищает временные выделения MAIN/BANK при RET, а зарегистрированные резиденты сохраняются при Reset. Прямые вызовы вне загрузчика требуют явного управления сроком жизни. mxos_fill_far, mxos_calloc_far и mxos_memory_query дают заполнение, выделение с обнулением и статистику. RAMDISK.COM -P 4 резервирует и подготавливает фиксированные банки, затем передаёт их DOS через MEMORY/RAMDISK COMMIT; после закрепления размер не меняется.

## Загружаемые модули

mxos_module_load(path, MXOS_MODULE_MAIN/MXOS_MODULE_BANK/MXOS_MODULE_DOS, &handle), mxos_module_call(handle, &regs) и mxos_module_unload(handle) находятся в дополнительном src/mxos_module.c. Это обёртки трёх штатных DOS-операций 0227h…0229h; код входит в вызывающую программу. MXOS_MODULE_REGS содержит ровно 8 байт HL/DE/BC/AF. Не подменять его прежним 10-байтным MXOS_REGS с полем entry.

module_call возвращает AF статуса API; AF самого модуля, в том числе CF, находится в regs.af. NEAR-параметры регистров не преобразуются; FAR-адреса общих объектов передаются по соглашению модуля. Перед загрузкой в main нужно зарегистрировать собственную свободную арену. Ошибки HANDLE/ACTIVE обозначают устаревший handle и активный модуль. Выгрузка освобождает образ, дочерние модули и FAR-блоки текущего модуля; MAIN-приложения FILE_EXEC имеют отдельные временные теги; прямые вызовы вне загрузчика сохраняют контекст банка. Полный контракт и ASM-пример: [api.md](../source/mem/api.md). FILE_EXEC запускает банковое приложение через тот же механизм; RUN делегирует нативные контейнеры DOS.


MXOS_DOS_FILE_EXEC_NATIVE (022Ah) — явный путь с аргументами в локальном HL, без PATH/CLI/ассоциаций. Доступен через обычный MXOS_CALL/mxos_call; AF возвращает статус загрузки/вызова. MXOS_IMAGE_FLAG_MAIN=04h, DRIVER=01h, BANK=02h описывают заголовок контейнера; это взаимоисключающие признаки. Flags=0 оставляет совместимость неподтверждённой. Для ASM задать IMAGE_FLAGS, для своего C-упаковщика передать flags при формировании контейнера. RUN запускает подтверждённый контейнер без меню через FILE_EXEC_NATIVE; неизвестный COM/EXE предлагает выбор режима.


Обычный MXOS_DOS_FILE_EXEC сначала применяет нативные MAIN/DRIVER/BANK найденного COM/EXE и только для flags=0 обращается к CLI.EXT. FILE_EXEC_NATIVE остаётся явным путём без поиска и ассоциаций.

## NEAR stdlib и старт C-программы

Добавьте src/mxos_heap.c и src/mxos_stdlib.c. Явный mxos_heap_init(&mxos_default_heap, begin, bytes) задаёт принадлежащий программе диапазон. Локальная куча работает в любой исполняемой странице, не переключает банки и не использует FAR-реестр. Отдельные MXOS_HEAP подходят для внутренних куч ядра. sizeof(void*) остаётся 2, FAR-адрес передаётся явно. Не превращайте NEAR NULL в {home_page,0}: нулевой FAR всегда {0,0}.

Для самостоятельного приложения sccz80 используйте -crt0=sdk/runtime/crt0, -clib=8080, -compiler=sccz80, -zorg=256. CRT обнуляет BSS и автоматически выделяет остаток своей страницы под NEAR-кучу; символы mxos_args и mxos_home_page объявлены в mxos_runtime.h. Он рассчитан на main(void), обычный RET и не инициализирует stdio/C++/atexit. Для DLL и резидентного повторного входа используйте собственный CRT и явную арену. Пример воспроизводимой сборки MAIN/BANK — scripts/tests/build-memory-runtime.py, пример stdlib — sdk/tests/heap.c.

Консольные обёртки putch/puts/getch/getkey/keyscan, курсор и uppercase теперь используют F806h и одинаково работают в MAIN/BANK. Низкоуровневый mxos_bios_call и исторические Cxxx-обёртки остаются явным main-интерфейсом; для файлов в BANK используйте mxos_file.h и mxos_call. Наличие локального malloc не делает произвольную стороннюю библиотеку банково-совместимой.

## Сохраняемые сервисы

mxos_resident_retain(key) отделяет текущий BANK-модуль или DOS-модуль резидентного слота от вызвавшей программы. Ключ ненулевой и уникальный. mxos_resident_find/next позволяют найти и перечислить сохранённые handle. mxos_resident_restore вызывает вход с A=1; mxos_resident_close вызывает A=2 и выгружает только после успешного callback; mxos_resident_kill удаляет без callback. Код/данные и дочерние ресурсы резидента сохраняются при тёплом сбросе, CPU-контекст не сохраняется. MAIN-арены, MAIN-блоки, MAIN-модули и DOS-DLL резиденту и его потомкам запрещены. RETAIN нужно вызвать до загрузки дочерних модулей. Фиксированный пул B: принадлежит самой DOS, а не резиденту; модульного handle у RAM-диска нет.

## DLL в банке DOS

`mxos_module_load(path, MXOS_MODULE_DOS, &handle)` загружает DLL с DRIVER-флагом в один из двух слотов DOS по адресу из заголовка: резидентный 7800h–7BFFh (1 КиБ) либо временный C000h–D7FFh (6 КиБ, общий с инициализаторами). Вызов и выгрузка выполняются прежними mxos_module_call/unload; MXOS_MODULE_REGS остаётся локальным для контроллера, указатели внутри пакета автоматически не переводятся. Повторная загрузка в занятый слот даёт ACTIVE; только временная DLL также блокирует DRIVER-установщики. Стек общий с DOS. RETAIN разрешён только в резидентном слоте: такая служба переживает завершение владельца и Reset; незарегистрированные модули освобождаются. Полный контракт — [source/mem/api.md](../source/mem/api.md).

```c
mxos_u16 handle, af, unload_af;
MXOS_MODULE_REGS regs = {0, 0, 0, 0}; /* HL, DE, BC, AF модуля */
af = mxos_module_load("B:\\DOSMOD.DLL", MXOS_MODULE_DOS, &handle);
if (!(af & MXOS_CF)) {
    af = mxos_module_call(handle, &regs);
    /* af — статус API, regs.af — результат самого модуля. */
    unload_af = mxos_module_unload(handle); /* Также после ошибки вызова. */
}
```

Значение `MXOS_MODULE_DOS=2` выбирает размещение и не является FAR-кодом банка: DOS имеет FAR-код 1. Код DLL должен обращаться к BIOS/DOS через MXOS_CALL; адреса BIOS C000h/C800h в банке DOS обозначают память арены. Отдельной NEAR-кучи загрузчик DOS-DLL не создаёт. Диск для измерений следует выбирать после загрузки DLL, поскольку файловый загрузчик может изменить выбранный диск.

## Владение RAM-диском

`mxos_ramdisk_status(&pages, &state)` вызывает MEMORY/RAMDISK (A=14, C=0): pages — число банков пула, state — 0 не закреплён, 1 владелец DOS, 2 исторический модульный владелец. `mxos_ramdisk_commit()` (C=1) передаёт подготовленный пул DOS; разрешён только из DRIVER-инициализатора, повторно проверяет геометрию B: и не форматирует том. При ошибке владелец не меняется. Штатный RAMDISK.COM выполняет передачу после подготовки тома и завершается без резидентного кода. Изменение размера закреплённого пула пока запрещено. Обёртки находятся в src/mxos_far.c.

GET32/PUT32 доступны через `mxos_get32_far(bank, offset, &value)` и `mxos_put32_far(bank, offset, value)`: MEM ABI 1.1, флаг `MXOS_MEM_CAP_DWORD`. Обёртки вызывают локальные входы F7A8h/F7ABh без DOS; результат — слово AF. На ошибке GET выходное значение C не изменяется. Четыре байта little-endian должны полностью лежать ниже FF00h.

Измерительный таймер исключён из BIOS/MXOS_CALL API. ASM-программы включают source/include/timing-pit.inc и вызывают локальные pitTimerInit/pitTimerRead.

Умножение, деление и деление на два больше не предоставляются BIOS/MXOS_CALL; C использует локальную арифметику компилятора, ASM — source/include/math.inc с выбором MATH_SUB/MATH_DIV2/MATH_MUL/MATH_DIV. Для выбора раскладки шрифта доступна регистровая служба MXOS_BIOS_SET_FONT_ENCODING (A=0 KOI8, иначе KOI7); рендер не следит за прямыми записями режима.
