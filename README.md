# MXOS2 — операционная система для «Специалиста-MX/MX2»

## От Commander к MXOS2

Commander написал **Константин Юденцов в 1992 году** как альтернативную RAMFOS операционную систему для «Специалиста-МХ». Она объединяла файловую систему, RAM-диск и двухпанельную оболочку в духе Norton Commander. Позднее **vinxru** дизассемблировал и доработал Commander: появились цветной интерфейс, поддержка большего объёма ДОЗУ и другие исправления; эта версия получила название **MXOS**. История оригинала, описание его устройства и обсуждение дальнейших доработок собраны fifan в теме [«ОС для Специалиста_МХ: Commander/MXOS» на ZX-PK.ru](https://zx-pk.ru/threads/26630-os-dlya-spetsialista_mkh-commander-mxos.html).

Этот репозиторий продолжает работу над MXOS; история его доработок ведётся с 2022 года. Исходная идея — объединить файловую систему и оболочку MXOS с возможностью запускать программы RAMFOS и классического «Специалиста». Современная ветвь, MXOS2, получила разделённые BIOS/DOS, банковую память, консоль, почти стандартную FAT16 с вложенными каталогами, записываемые flash-накопители и средства разработки новых программ. Подробная история — в [CHANGELOG.md](CHANGELOG.md).

## Как устроена система

MXOS2 работает на "Специалисте-MX2" с процессором КР580ВМ80А / Intel 8080 и совместимых; базовая частота — 2 МГц. Основной интерфейс — файловый менеджер NC, рядом с ним доступна консоль CLI. Команды, пути и файловые операции у них общие.

| Компонент | Назначение |
|---|---|
| [BIOS.SYS](source/bios/README.md) и [IO.SYS](source/io/README.md) | Клавиатура, экран, текст и графика, аппаратный обмен и переходники системных вызовов. |
| [DOS.SYS](source/dos/README.md) | Файлы и каталоги, кэш дисков, загрузка программ, команды и BAT-сценарии; работает в отдельном банке ДОЗУ. |
| [MEM.SYS](source/mem/README.md) | Межбанковый обмен, выделение памяти и загрузка модулей. |
| [NC.COM](source/nc/README.md) | Нортон-подобный менеджер. Две файловые панели, диалоги операций и командная строка. |
| [CLI.COM](source/cli/README.md) | Командная консоль с редактированием и историей команд. |
| [RUN.COM](source/run/README.md) | Выбор среды для старых программ: MX, STD, Monitor-2 или RAMFOS. |

В штатной карте приложениям основной памяти доступна область `0000h–8BFFh` — 35 КиБ. Подэкранные системные переменные — ровно те, что используются в "Мониторе-2". BIOS, стек, межбанковые переходники  и новые переменные находятся в системной области `C000h-FFBFh` и не отнимают место у программ. Текущая банковая сборка требует как минимум одного банка ДОЗУ 64 КиБ для DOS, ещё четыре банка резервируются под RAM-диск 256 КиБ, остальное остаётся новым банковым программам. Это всё настраивается в AUTOEXEC.BAT.

### Память, диски и файлы

Диски обозначаются буквами `A:`–`H:`. **A:** — системная ROM/flash, установленная на плате компьютера, **B:** — RAM-диск, **H:** — внешний ROM/flash-диск, подключаемый через вторую ВВ55 (порт программатора). Остальные буквы требуют соответствующих драйверов. Содержимое **B:** сохраняется при обычном тёплом Reset, но теряется при отключении питания.

Имена файлов и каталогов имеют формат **8.3**, например `Readme.txt`, длинных имён нет. Поддерживаются абсолютные и относительные пути, `.` и `..`, разделители `\` и `/`. Текст системы и русские имена используют KOI8-R, поддерживаются строчные и прописные буквы. Файловые операции к регистру нечувствительны. Каждый диск помнит свой текущий каталог. Длина пути или команды — до 127 байт.

DOS поддерживает FAT16 и логические секторы 128/256/512 байт; малые системные и RAM/flash-тома используют расширения **MXOS-128/256**. Это ещё не полная совместимость с произвольными FAT-носителями: нет FAT12, разбора MBR и драйверов стандартных дискет/SD; ёмкость ограничена 16-битным номером логического сектора. FORMAT и сборщик штатных образов создают MXOS-256. Вложенные каталоги, копирование и перенос деревьев уже работают, но заполненный подкаталог пока не расширяется. NC показывает до 255 записей каталога; для полного списка используйте `DIR`.

## Работа в NC

После загрузки открываются две панели. Активная панель определяет текущие диск и каталог для команд; противоположная по умолчанию задаёт назначение копирования и перемещения файлов. Панели могут показывать разные каталоги одного диска. Внизу расположены командная строка и подсказки функциональных клавиш.

NC подстраивается под установленный шрифт: 4×8 даёт три колонки файлов на панель, 6×8 — две, 8×8 — одну с размером или `<DIR>` справа. Шрифт можно сменить командой `FONT Cpm4`, `FONT Rotate` или `FONT Fast8`; после возврата обновляются панели, диалоги, строка команды и подсказки клавиш. Длинные пути сокращаются по целым каталогам, например `A:\Folder\...\File.txt`, без изменения самого пути. При любом шрифте статус показывает имя файла и размер, а путь — заголовок панели. Для `..` статус поясняет переход к родителю; пункт `\` пока скрыт. Режим F3 сохраняется после возврата из программ и CLI. При запуске NC восстанавливает KOI-8.

| Клавиша | Действие |
|---|---|
| ↑ / ↓ | Перемещение по файлам, в том числе при набранной команде. |
| ← / →, Home, End | При пустой строке — перемещение по файлам; при набранной команде — перемещение текстового курсора. |
| Tab | Переключение активной панели. |
| Enter | Открыть каталог или запустить выбранный файл; файл без действия для его расширения игнорируется. При введённой команде — выполнить её. |
| `..` в списке | Перейти к родительскому каталогу и выделить покинутую папку в обновлённом списке. Для перехода в корень наберите `CD /`. |
| F1 / F2 | Выбрать диск левой / правой панели. |
| Shift+F1 / Shift+F2 | Сортировка соответствующей панели: по имени, расширению или без сортировки. |
| F3 | Информация о диске активной панели на противоположной панели. |
| F4 | Открыть выбранный файл в текстовом редакторе EDIT.COM. |
| Shift+F4 | Открыть новый пустой документ в EDIT.COM. |
| F5 | Копировать файл или дерево каталогов. |
| F6 | Переместить файл или каталог. |
| Shift+F6 | Переименовать выбранный файл или каталог на текущей панели. |
| F7 | Создать каталог. |
| F8 | Удалить файл или пустой каталог. |
| Shift-F10 | Exit на втором уровне подсказок: переход в консоль CLI. |
| Ctrl+Enter | Добавить полный путь выбранного файла и пробел в командную строку. |
| Backspace | Удалить символ слева от текстового курсора. |
| Escape | Очистить командную строку или отменить диалог. |

На клавиатуре «Специалиста» роль Ctrl выполняет «ПС». Во время набора команды ↑/↓ продолжают перемещать выделение панели, сохраняя текст команды, позицию текстового курсора и прокрутку строки. Можно выбрать файл, добавить его путь через Ctrl+Enter, выбрать другой файл и снова нажать Ctrl+Enter. Влево/вправо редактируют положение курсора, Home/End перемещают его к началу/концу команды. Для удаления слева используйте Backspace; отдельное удаление справа по Delete пока не поддерживается. Удержание Shift показывает второй набор подсказок функциональных клавиш. Магнитофонные операции в панелях пока не реализованы.

В диалоге выбора диска можно нажать его букву: A/a, B/b и т. д. Диалог сразу закрывается, панель переключается на выбранный доступный диск. Для запуска по Enter поддерживаются COM/EXE/BAT и расширения с ассоциацией в `A:\CLI.EXT`; для остальных файлов панели и выделение остаются без изменений. F4 открывает выбранный файл в редакторе независимо от ассоциации.

При запуске NC последовательно читает `A:\NC.CFG` и `B:\NC-STATE.CFG`: второй файл переопределяет одноимённые настройки первого без пересборки. NC сохраняет в него пути панелей, выбранные имена, прокрутку, сортировку и режимы F3. Штатные настройки: каталоги белые; COM/EXE/RKS/MON/FNT светло-зелёные; BAT/CFG светло-красные; TXT голубые; архивы светло-пурпурные; остальные Hidden/System тёмно-серые; остальные файлы белые. Сначала применяется цвет расширения из `FileColorUser` (последнее правило выигрывает), затем `FileColorSys` для Hidden/System, затем `FileColorDef`. Каталоги всегда белые. CLI.EXT по-прежнему определяет запуск, независимо от цветов.

После закрытия диалога NC восстанавливает изображение и цвета под ним. Отмена не перерисовывает панели; после файловой операции обновляется только затронутый список.

При совпадении имён копирование предлагает **Yes**, **Yes to all**, **No**, **No to all**; по умолчанию выбрано No. Клавиши Y/N/A/S выбирают соответствующий ответ, Escape пропускает файл. Решение «для всех» действует только до конца текущей операции. Существующие каталоги объединяются, совпадающие файлы проверяются отдельно. При ошибке уже скопированные файлы сохраняются: операция не откатывается целиком.

## CLI и команды

Нажатие Shift-F10 в NC или ввод `CLI` запускает консоль; физическая F10 без Shift также принимается. Команда `NC` или `EXIT` возвращает менеджер. Стрелки вверх/вниз в CLI перебирают последние 32 команды; историю можно редактировать. Она сохраняется между запусками консоли в `B:\CLI.HST`, если B: доступен. После внешней программы консоль продолжает текущий экран; для очистки служит `CLS`.

AUTOEXEC устанавливает Fast12K, после чего запускается банковый `NC.COM` с `NC_CORE.DLL` и `UI_GFX.DLL`. Штатный `EDIT.COM` тоже банковый. MAIN-профили доступны для сравнения как `NC_MN.COM` и `EDIT_MN.COM`. Команда EXIT в CLI возвращает предыдущий профиль NC. [Описание сборки и размещения](source/nc/BANKED.md).

Вызванная из истории команда редактируется обычным образом: ←/→ перемещают курсор, Home/End переходят к началу/концу, Backspace удаляет символ слева, ввод вставляет символы в позицию курсора. Enter выполняет отредактированную команду, Escape очищает строку. Удаление справа по Delete пока не поддерживается.

Эти команды работают и в CLI, и в строке NC, и в BAT. Квадратные скобки в таблице обозначают необязательный аргумент. Команды и пути нечувствительны к регистру.

| Команда | Назначение и пример |
|---|---|
| `DIR [путь/маска] [-S]` | Список каталога; -S обходит дерево: `DIR H:\`, `DIR B:\WORK`. |
| `CD`, `CHDIR [путь]` | Сменить каталог и при необходимости диск: `CD H:\GAMES`. Без аргумента — показать текущий путь. |
| `PWD` | Показать текущий абсолютный путь. |
| `A:` … `H:` | Перейти на диск в его сохранённый текущий каталог. |
| `MD`, `MKDIR путь` | Создать дерево недостающих каталогов: `MD B:\WORK\NEW`. |
| `RD`, `RMDIR путь` | Удалить пустой каталог: `RD B:\EMPTY`. |
| `COPY источник назначение` | Копировать файл или дерево: `COPY A:\README.TXT B:\WORK`. |
| `MOVE источник назначение` | Перенести файл или каталог: `MOVE B:\WORK\NOTE.TXT B:\NOTE.TXT`. Внутри тома данные не копируются; между томами источник удаляется после копирования. |
| `REN`, `RENAME источник имя` | Переименовать файл или каталог на месте: `REN B:\NOTE.TXT NOTES.TXT`. |
| `DEL`, `ERASE путь` | Удалить файл или пустой каталог: `DEL B:\NOTES.TXT`. |
| `ATTRIB [+-R] [+-H] [+-S] [+-A] путь` | Посмотреть или изменить атрибуты: `ATTRIB +R B:\WORK\README.TXT`. R — только чтение, H — скрытый, S — системный, A — архивный. |
| `TYPE файл` | Вывести содержимое: `TYPE A:\AUTOEXEC.BAT`. Байты и окончания строк не преобразуются. |
| `PATH [каталоги]` | Путь поиска программ: `PATH A:\;A:\DRIVERS;B:\TOOLS`. Без аргумента — показать, `PATH ;` — очистить. |
| `CLS` | Очистить экран. |
| `ECHO текст`, `REM текст` | Вывести сообщение / комментарий в сценарии. |
| `HELP` | Показать список команд. |

`DIR H:` показывает **текущий каталог H:**, а `DIR H:\` — **корень H:**, не меняя текущий каталог приглашения. `CD H:\GAMES` сразу меняет и диск, и каталог; отдельный ключ `/D` не нужен. Рекурсивное удаление пока отсутствует; маски источника поддерживают DIR и COPY/MOVE. Файлы R/S защищены от удаления; для замены файла с R сначала нужно снять этот атрибут. REN и перенос внутри тома не заменяют существующее имя.

Например, чтобы создать рабочий каталог и скопировать туда руководство:

```text
MD B:\WORK
COPY A:\README.TXT B:\WORK
CD B:\WORK
DIR
EDIT README.TXT
```


Команды DIR и COPY/MOVE поддерживают маски последнего компонента пути: `DIR B:\BENCH\*.COM`, `COPY B:\DATA\*.TXT B:\BACKUP` (каталог назначения уже должен существовать). `DIR B:\BENCH\*.COM -S` обходит дерево и выводит полные пути. DEL/ERASE удаляют файлы и пустые каталоги; удаление непустого дерева пока не реализовано. Парсер и BAT остаются в DOS, перечисление и копирование используют лениво загружаемые ENUM.DLL и FILEOPS.DLL в разных областях памяти.

`MKDIR Games/Almaz-2/MXOS` создаёт недостающие уровни каталогов; тот же путь можно ввести в диалоге F7 NC.

## Запуск программ и утилиты

Программу можно выбрать в NC и нажать Enter либо ввести её имя с аргументами. Без расширения DOS ищет `COM`, затем `EXE`, затем `BAT`, затем программу по файловым ассоциациям в `CLI.EXT`. Сначала ищет в текущем каталоге, затем в `PATH`. Начальный PATH — `A:\`. Явный диск или разделитель пути отключает поиск по PATH.

Система поддерживает собственный формат исполняемых файлов — COM и EXE. Они состоят из 16-байтного заголовка, содержащего сигнатуру, адрес загрузки, адрес запуска, длину, контрольные суммы и флаги, далее идёт машинный код программы. Программы с флагами MAIN, DRIVER или BANK исполняет DOS. Это не форматы DOS/Windows, а простое переименование сырого бинарника в COM не делает его программой MXOS2.

Для запуска старых программ и `RKS` используется лаунчер `RUN.COM`:

| Команда | Аппаратный режим | Среда выполнения |
|---|---|---|
| `RUN -MX H:\GAME.EXE` | MX | Ядро MXOS2 |
| `RUN -STD H:\GAME.EXE` | STD | Ядро MXOS2 |
| `RUN -RF H:\GAME.EXE` | MX | Сменное ядро `A:\RAMFOS.MON`. |
| `RUN -MON H:\GAME.RKS` | STD | Сменное ядро `A:\MONITOR2.MON`. |
| `RUN -MON:CUSTOM.MON H:\GAME.RKS` | STD | Сменное ядро `A:\CUSTOM.MON`. |
| `RUN H:\GAME.EXE` | Интераактивно | Меню выбора среды и ядра для COM/EXE без флага подтверждённой совместимости. |

Сменное ядро — это сырой бинарник какого-либо исторического "Монитора" для "Специалиста", либо адаптированное ядро RAMFOS. По умолчанию в режиме `-MON` используется `MONITOR2.MON` — это "Монитор-2". Запуск `RKS` сделан через ассоциацию расширения `RKS` с `RUN` в `CLI.EXT`: Enter на файле в NC или ввод имени в командной строке запускает его подобно `EXE`/`COM`. Файловые службы в ядре `RAMFOS.MON` пока отключены. В планах — подключить их к файловым службам DOS.

Программы `EXE`/`COM` с флагом MAIN/DRIVER/BANK в заголовке всегда передаются нативному загрузчику. Но `EXE` также ассоциирован с `RUN` в `CLI.EXT`. Это сделано для того, чтобы запуск `EXE` без флага MAIN/DRIVER/BANK вызывал интерактивное меню выбора среды. Это предназначено для изучения совместимости старых программ и игр с MXOS и её режимами. Сборщик образов дисков в этом репозитории позволяет выставить флаги для программ, совместимость которых подтверждена, и таким образом превратить их в нативные `EXE`.

Для программ, несовместимых с ядром MXOS или "Монитором-2", всегда остаётся путь запуска через батник с таким содержимым:

```text
RUN GameRF.EXE -RF
```
```text
RUN Game580.RKS -MON:SP580
```

Ключ `-KOI7` переключает вывод текста BIOS в KOI-7. Выбор режима не гарантирует совместимость программы. Другие подробности и ограничения — в [руководстве RUN](source/run/README.md).

Текстовые файлы `TXT` ассоциированы с редактором [EDIT.COM](source/EDIT/README.md): `EDIT B:\WORK\NOTE.TXT` или F4 в NC. В комплект также входит [`DEBUG.COM`](source/debug/README.md) для просмотра памяти и отладки поверх MXOS.

## Драйверы и настройка

Устанавливаемые драйверы находятся в `A:\DRIVERS`; их можно запустить из NC или указать полным путём в `AUTOEXEC.BAT`. Установка драйвера внешнего диска не форматирует носитель. Число в имени драйвера — верхний предел ёмкости.

| Драйвер | Буква | Устройство |
|---|---|---|
| Встроенный | A: | Системная ПЗУ на 32-512 КиБ. |
| `AT512KS.COM` | A: | Системная flash на AT29C010A / C020 / C040A, 128-512 КиБ. |
| `AT2MX.COM` | H: | Внешняя плата Flash-диска MMX с 1–4 AT29C040A, до 2 МиБ; последовательная запись. |
| `AT2MXF.COM` | H: | Та же плата, запись распределяется между микросхемами для ускорения. |
| `ROM2M.COM` | H: | Та же плата, read-only, можно использовать обычные ПЗУ, до 2 МиБ. |
| `ROM64K.COM` | H: | Старая плата ROM-диска без защёлок, до 64 КиБ. |
| `RAMDISK.COM` | B: | RAM-диск из банков ДОЗУ, ключ `-P 4` — взять 4 банка (= 256 КиБ); том форматируется при холодном старте. |

Диск `A:`: флеш-драйвер с записью на 512 КиБ предназначен для ["Специалисте-MMX"](hardware\boards\mapper\mapper.pdf). Схема "Специалиста-MX" поддерживает до 48 КиБ системной ПЗУ, "Специалиста-MX2" — 32 КиБ; с ними работает встроенный в BIOS драйвер.

Диск `H:`: флеш-драйверы с записью предназначены для [платы MMX](hardware/boards/flash-disk/flash-disk.pdf). Совместимость с другими платами не гарантируется; варианты для платы HardwareMan пока не входят в комплект.

Подробности — в [описании драйверов](assets/system-rom/drivers/README.md) и в `A:\DRIVERS\README.TXT`.

### AUTOEXEC, PATH и ассоциации

При запуске BIOS выполняет `A:\AUTOEXEC.BAT`. Сначала A: доступен через встроенный драйвер только для чтения; сценарий устанавливает флеш-драйвер A:, драйвер H: и RAM-диск. Пример для системной флеш и внешнего флеш-диска MMX:

```text
A:\DRIVERS\AT512KS.COM
A:\DRIVERS\AT2MXF.COM
A:\DRIVERS\RAMDISK.COM -P 4
PATH A:\;A:\DRIVERS
```

Для ROM-диска H: вместо AT2MXF нужен соответствующий ROM-драйвер. Для RM-диска число после `-P` выбирайте по доступной ДОЗУ, оставляя отдельный банк для DOS и при необходимости банки для приложений. Размер B: фиксируется до холодного старта. При аппаратном сбросе `AUTOEXEC.BAT` выполняется снова, уже загруженные DOS и B: при штатном тёплом сбросе сохраняются. При повреждении DOS в её банке нужна холодная перезагрузка. Обычный возврат из программы заново `AUTOEXEC.BAT` не запускает.

BAT поддерживают команды и запуск других BAT с возвратом к родителю, до восьми уровней вложенности. `@` скрывает текущую исполняемую строку, `ECHO OFF`/`ECHO ON` переключают эхо команд. Ошибка останавливает цепочку и показывает файл, строку и код DOS. IF/GOTO/CALL, подстановка `%1`, перенаправления `>`/`<` и конвейеры пока не реализованы.

Файл `A:\CLI.EXT` задаёт ассоциации для обеих оболочек: расширение, пробел, команда. Штатный вариант:

```text
TXT A:\EDIT.COM
RKS A:\RUN.COM
EXE A:\RUN.COM
```

Нативные флаги COM/EXE имеют приоритет над ассоциациями. Изменения CLI.EXT учитываются при следующем запуске файла. Для постоянной настройки образа редактируйте [autoexec-сценарии](assets/system-rom) и [CLI.EXT](assets/system-rom/CLI.EXT), затем пересобирайте образ; на флеш-диске A: эти текстовые файлы можно менять в самой системе. Системные тексты на носителе должны сохранять подходящую кодировку KOI8-R.

[FORMAT.COM](source/format/README.md) создаёт новую файловую систему и уничтожает прежний каталог: например, `FORMAT B: -R` форматирует RAM-диск с подтверждением, `FORMAT H:` — внешний флеш-диск. Ключ `-Y` убирает подтверждение. Форматирование A: запрещено. Для обычной загрузки ручной FORMAT не нужен: новую память B: подготавливает `RAMDISK.СOM`.

## Возможности для новых программ

Приложения можно писать на ассемблере 8080 или C с [SDK MXOS](sdk/README.md). Источник адресов, структур и констант — [source/include/mxos.inc](source/include/mxos.inc); вызовы BIOS/DOS доступны через общий ABI. Система предоставляет:

- клавиатурный ввод, текст KOI-7/KOI8-R, курсор, цвет, окна и операции с экранными прямоугольниками;
- файлы и каталоги, открытие/чтение/запись/позиционирование/закрытие файлов, атрибуты и дисковые службы;
- обычную память приложения, C-функции malloc/free/calloc/realloc и [FAR API](source/mem/api.md) для выделения и обмена данными между банками;
- MAIN-программы в основном ОЗУ, BANK-программы в отдельном банке, одноразовые DRIVER-установщики и загружаемые DLL-модули.

Примеры и прикладные программы находятся в [source-apps](source-apps/README.md). Для ASM используется SjASMPlus с `--i8080`: Z80-only команды недопустимы. Программа соблюдает системный предел памяти; при штатном RET временные банки, модули и FAR-ресурсы освобождаются. Прямой запуск DLL как команды не поддерживается. Многозадачности и автоматического сохранения образа вызывающей MAIN-программы нет; обычные стандартные потоки C и их перенаправление пока не предоставляются.

Сборка выдаёт CPU/I80, а сборщик образа формирует готовый COM/EXE/DLL с заголовком. Тип запуска задаётся через `IMAGE_FLAGS`. При добавлении программы укажите её в манифесте образа; формат упаковки описан в [документации сборщика](scripts/images/README.md).

## Репозиторий и сборка

| Каталог | Содержимое |
|---|---|
| `source/` | BIOS, DOS, MEM, IO, загрузчик, оболочки, системные утилиты и драйверы. |
| `source-apps/`, `sdk/` | Прикладные программы, примеры и C SDK. |
| `assets/` | Исходные игры, внешние программы, шрифты и системные тексты. |
| `scripts/build/`, `scripts/images/` | Сборка компонентов, упаковка образов и манифесты их состава. |
| `scripts/emu80/` | Подготовка и запуск Emu80. |
| `source-emulators/emu80/` | Собственные аппаратные модели Emu80. |
| `hardware/` | Схемы и платы DipTrace, PDF/XML и проекты панелей. |
| `bin/`, `images/` | Генерируемые бинарники, символы, листинги и образы накопителей. |

Основная среда сборки — Windows, PowerShell и Python 3; SjASMPlus находится в `tasm/`. Для C-программ нужен z88dk согласно инструкции SDK. ASM/INC хранятся в UTF-8 без BOM; тексты для самого "Специалиста" могут быть в KOI8-R. Эмулятор устанавливается отдельно от репозитория.

Для параллельной работы с сетевой копией выполните `powershell.exe -NoProfile -File scripts/build/new-local-workspace.ps1` и откройте выведенный путь к workspace. Сценарий создаёт отдельный Git-клон текущего коммита в `%LOCALAPPDATA%\Specialist-OS\workspaces`. Рабочие правки перенесите в локальную копию перед проверкой. Запускайте сборку из неё. Для тестов на одном ПК выбирайте разные порты в задаче `run: Emu80 H-Flash2M (MCP slot, no build)`. У каждого порта свой локальный runtime, настройки и рабочие диски. [Подготовка слотов Emu80](scripts/emu80/README.md).

Откройте [Specialist-OS.code-workspace](Specialist-OS.code-workspace) в VS Code. В меню `Ctrl+Shift+B` доступны `build: all` для системы, игр и автономных тестов и задачи запуска Emu80. Для сборки только системных компонентов выполните `powershell.exe -NoProfile -File scripts/build/build-project.ps1 OS`. Для подготовки образа из готовых компонентов вызовите `powershell.exe -NoProfile -File scripts/images/build-image.ps1 SystemEmuWritable`, `Games64k` или `Games2M`.

Состав A: задаёт [A-System.txt](scripts/images/manifests/A-System.txt), внешнего H: — манифесты в [scripts/images/manifests](scripts/images/manifests). Бинарники и листинги попадают в `bin/`, образы — в `images/`; эти результаты не отслеживаются Git. Размещение BIOS/DOS рассчитывает сборщик, вручную править `bin/System.layout.inc` не нужно.

## Запуск в эмуляторе

Для текущей MXOS2 используйте **Emu80 с аппаратными моделями проекта** и профиль **H-Flash2M**. Установка обычного Emu80 4.0.571 и подготовка собственной сборки описаны в [scripts/emu80/README.md](scripts/emu80/README.md). Переменная `SPECIALIST_EMU80_DIR` должна указывать на каталог этой установки с `Emu80qt.exe`.

| Задача VS Code | Поведение |
|---|---|
| `run: Emu80 H-Flash2M` | Собрать систему и игры, напрямую заменить рабочие A: и H: новыми образами; запустить эмулятор. |
| `run: Emu80 H-Flash2M (no build)` | Без пересборки обновить A: при изменении готового системного образа, сохранить рабочий H: и запустить эмулятор. |

Штатный профиль предоставляет системную flash A: на 512 КиБ, внешний flash-диск H: на 2 МиБ и 16 банков ДОЗУ. После первого запуска проверьте появление NC, диски через F1/F2 и информацию через F3. Вариант **no build** запускает готовый образ: обновляет A: при изменении сборки и сохраняет рабочий H:. Если сборка не менялась, изменения на A: тоже сохраняются. Резервные копии образов не создаются.

Задача `run: Emu80 H-ROM64k (no build)` загружает ранее собранный 64-КиБ образ `SystemRom_emulator.bin`. Текущей MXOS2 требуется линейный образ от 128 КиБ. Отдельные профили [RAMFOS](source/ramfos/README.md) и [CP/M](source/cpm/README.md) запускают самостоятельные системы.

## Прошивка и запуск на реальном железе

Нужен «Специалист-MX/MX2/MMX» или совместимая машина с подходящей схемой переключения памяти, теневой системной областью, достаточной ДОЗУ и системной ROM/flash. Текущая банковая сборка использует линейный системный образ от 128 КиБ; прежнего системного ПЗУ 64 КиБ недостаточно. Для штатной конфигурации AUTOEXEC нужны пять банков ДОЗУ; для двух банков заранее задайте RAMDISK `-P 1`. Схемы и сведения о ревизиях плат находятся в [hardware](hardware/README.md).

1. Выберите драйверы и размер RAM-диска в `assets/system-rom/autoexec.hardware.bat` под свою плату. Выполните `build: all`, затем `powershell.exe -NoProfile -File scripts/images/build-image.ps1 SystemHardware 512`, указав ёмкость системного чипа в КиБ. Результат — `images/SystemRom_128K.bin`, `SystemRom_256K.bin` или `SystemRom_512K.bin`.
2. Сохраните прежнюю прошивку программатором. Запишите соответствующий полный образ в системную микросхему с начала адресного пространства и выполните проверку чтением. Устанавливайте микросхему при выключенном питании; положение перемычек чтения/записи определяется схемой конкретной платы.
3. Для четырёхчиповой платы флеш-диска соберите Games2M и прошейте `images/FlashDisk_chip1_512K.bin` … `FlashDisk_chip4_512K.bin` в соответствующие чипы по порядку. Для ROM-диска на 64 КиБ соберите Games64k и прошейте `images/FlashDisk_64K.bin`.
4. Включите машину или выполните аппаратный сброс. Загрузчик установит системные компоненты, AUTOEXEC подключит накопители и подготовит B:, затем откроется NC. Проверьте A:/B:/H:, фактические ёмкости и доступность файлов. Для проверки записи используйте копию небольшого файла на предназначенном для записи диске.

BOOT, BIOS, IO, MEM, DOS и шрифт занимают фиксированные слоты системного образа: обновляйте их пересборкой и прошивкой целого образа. Простое копирование новых SYS на A: не заменяет эту процедуру. Проверка в эмуляторе не подтверждает аппаратные тайминги и запись flash на конкретной плате; не все игры из коллекции проверены на совместимость.

Краткая памятка доступна и на машине: `A:\README.TXT`, открыть через `EDIT A:\README.TXT` или F4 в NC. История возможностей и исправлений — в [CHANGELOG.md](CHANGELOG.md).
