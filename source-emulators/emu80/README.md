# Расширения Emu80 для «Специалиста-MX2»

Здесь хранятся собственные исходники аппаратных моделей для Emu80 и патчи
их подключения к upstream. Полный upstream и готовая установка находятся
снаружи репозитория. Профиль и скрипты запуска: `scripts/emu80/`.

`SpecialistMx2VideoRam` разделяет MX-защёлку цвета и STD-цвет от ВВ55.
Штатный `SpecVideoRam::setCurColor` обновляет также текущий MX-цвет;
при прямом подключении клавиатурного ВВ55 это давало чёрные области после
опроса клавиатуры. Модель проекта сохраняет MX-защёлку независимо, а в STD
оставляет штатное преобразование 4/8 цветов. Записи STD-регистра F7F8h
не меняют сохранённый MX-цвет. Переключение режима не уничтожает защёлку.
Это исправление интеграции совмещённого MX/STD-профиля, не изменение палитры.
В сборке проекта модель применяется также к ROM-профилю без flash-диска.

`At29Flash` моделирует AT29C040A: 512 КБ, страницы записи по 256 байт,
буфер загрузки с интервалом 150 мкс, программирование 10 мс, DATA polling
DQ7 и переключение DQ6, Software Data Protection и software ID.
Адрес фиксируется по спаду /WE, данные — по фронту. Незагруженные байты
программируемой страницы становятся FFh. Время берётся из часов эмулятора.

`SpecialistFlashDisk` подключает четыре независимых чипа к второму ВВ55
по схеме `hardware/boards/flash-disk/`: порт A — данные, B — младший адрес
и вход прозрачной ИР22; C0–C2 — A16–A18, C3–C4 — номер чипа,
C5 — STB, C6 — /WR, C7 — /RD. Учтены направления портов и дешифратор ИД14.
Это модель внешнего диска H:, а не системной ПЗУ A:.

`SpecialistSystemFlash` использует ту же модель AT29C040A для A:.
`AddrSpaceMapper` отображает 16 страниц по 32 КБ на один линейный образ
512 КБ; номер MX-страницы задаётся D0–D3 регистра FFFEh. Сброс начинается
с MX-страницы 0. STD-окно показывает страницу 0; точная конфигурация
перемычек для других прошивок требует отдельной проверки по железу.
`readOnly = yes` моделирует запрещённую запись через J4. Данные хранятся
в `system-flash.bin`, защита SDP — в `system-flash.bin.sdp`.
Не завершённый до отключения питания цикл программирования не форсируется.

Свойства: `image` — существующий образ, `chipCount` — 1–4 (по умолчанию 4),
`readOnly` — yes/no. Размер образа — ровно `chipCount * 524288` байт.
Завершённые страницы сохраняются в образ, состояние SDP — рядом в `.bin.sdp`
(один байт 0/1 на чип). При выключении незавершённое программирование
не форсируется. Сброс CPU сохраняет состояние микросхем.

Не реализованы AT29C010A/C020, chip erase, boot-block lock, аналоговые
характеристики и все варианты некорректных командных последовательностей.
Ошибка открытия файла отражается в `ioError`; API PalFile upstream
не возвращает результат каждой записи, поэтому полная диагностика ошибок
хостового накопителя не гарантируется. Это не проверка записи на железе.

Сборка: [scripts/emu80/README.md](../../scripts/emu80/README.md).
`apply-upstream.py` регистрирует класс в ObjectFactory и добавляет исходники
в qmake и Code::Blocks для зафиксированного upstream.

Проверка чипа без Emu80:

```sh
g++ -std=c++11 -Wall -Wextra -pedantic -O2 At29Flash.cpp test-at29.cpp -o test-at29
./test-at29
```

Интеграционные тесты выполняют бинарники драйверов на CPU Emu80 через MCP.
Проверены FlashChk, FlashFst, исторический Flash.asm и FlashSys: чтение,
запись и сохранение после перезапуска. J4 также проверена в режиме запрета.
Эмуляторная проверка не подтверждает временные параметры реального маппера.

Это расширение исходников Emu80 со сборкой исполняемого файла, а не DLL
с API старого EMU. Код должен соответствовать GPL-3.0 upstream; собственный
код общего ядра должен оставаться совместимым с C++11.
