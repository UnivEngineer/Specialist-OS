# Сборка образов

`build-image.ps1` собирает системный ROM и flash-образы.

Все манифесты `manifests/*.txt` используют один формат:

```text
@label SYSTEM ROM

# Имя на диске    Путь относительно assets                    Адрес RAW
Almaz2.exe        games/Almaz-2/Almaz2.exe
Almaz2MX.exe      games/Almaz-2/Almaz2-mx-optimized.exe
ALM2OPT.RKS       games/Almaz-2/Almaz2-optimized.rks
DOS.SYS           ../bin/DOS.sys                               0xC000 RS
AUTOEXEC.BAT      {AUTOEXEC}                                   0x8000
```

Каждый манифест содержит ровно одну директиву `@label` с меткой тома:
`@label SYSTEM ROM`, `@label ROM DISK 64` или `@label FLASH DISK`.
Метка задаётся без кавычек, может содержать пробелы и занимает 1–11 ASCII-символов.
Сборщик дополняет её справа пробелами до 11 байт в BPB. Пустая, слишком длинная,
повторная или содержащая запрещённые FAT символы метка приводит к ошибке.
Неизвестные директивы также отклоняются. В PowerShell-сценарии меток больше нет.

Столбцы файлов разделяются пробелами или табуляцией. Пустые строки и строки,
начинающиеся с `#`, пропускаются. Имя на диске должно помещаться в FAT 8.3;
исходный файл может иметь длинное имя. Пробелы внутри имён и путей не поддерживаются.
Все пути отсчитываются от `assets`; результаты сборки доступны через `../bin/`.

Формат определяется по расширению исходного файла: `.rks` либо RAW.
Для RKS адрес и длина полезной нагрузки читаются из заголовка; третий столбец
не указывается. Для RAW адрес по умолчанию равен нулю; явный адрес задаётся
десятичным числом или с префиксом `0x`. `{AUTOEXEC}` заменяется на
`system-rom/autoexec.emu.bat` или `system-rom/autoexec.hardware.bat`.
Необязательный четвёртый столбец RAW задаёт атрибуты: `R` — read-only,
`S` — системный, `RS` — оба. Если адрес не нужен, укажите `0`.
Без столбца атрибуты равны нулю.

`SystemRom.txt` задаёт системный состав и метку обычных системных образов.
`Ramfos.txt` задаёт дополнение и метку объединённого образа `SystemRamfos`;
метка базового `SystemRom.txt` для него не используется.
`FlashDisk-emulator.txt` и `FlashDisk.txt` задают flash-диски 64 КБ и 2 МБ.
Порядок строк определяет порядок каталога и кластеров.

В `Games2M` кластеры файлов чередуются между четырьмя чипами по 512 КБ.
Преобразования физических адресов нет: порядок задаётся обычными FAT-цепочками,
поэтому образ читается Flash и FlashFst. Загрузочный сектор, FAT и корневой
каталог занимают непрерывную область на чипе 0. Системные образы и `Games64k`
сохраняют линейное размещение. Ячейки FAT за концом области данных помечаются
занятыми; свободное место не теряется из-за обхода границы чипа.

Проверка собранных четырёх частей: `python -X utf8 scripts/images/check-interleave.py`.
Она сравнивает полезную нагрузку всех файлов с манифестом, проверяет цепочки,
отсутствие общих кластеров и распределение по чипам. Отчёт находится в
`docs/flash/interleave-001/image.json`.

В линейных системных образах встроенный ROM-драйвер теперь читает все банки.
Ограничение первой 32-КБ страницы проверяется только для DOS.SYS: оно нужно
начальному загрузчику. FONT, FORMAT, FLASHSYS.COM, AUTOEXEC и NC могут
размещаться в остальных банках. Прежний порядок файлов сохранён.


Для 64-КБ MX2-образа STD-половина содержит 32764 байта данных после
четырёхбайтного входа. Размер Boot/FAT/корня из этой половины повторно
не вычитается: иначе хвост последнего файла молча обрезался. Последний
логический сектор доступен не целиком и помечается bad (FFF7h), чтобы
файл не попал в недоступные четыре байта и CHKDSK не считал его потерянным.
Проверка всех полезных нагрузок по системному манифесту:

```powershell
python -B scripts/images/check-system-rom.py --image images/SystemRom_emulator.bin --mx2
python -B scripts/images/check-system-rom.py --image images/SystemRom_emu80_writable.bin --autoexec emu-writable
```
