# Сборка образов

`build-image.ps1` собирает системный ROM и flash-образы.

Все манифесты `manifests/*.txt` используют один формат:

```text
@label SYSTEM ROM

# Имя на диске    Путь относительно assets                    Адрес RAW
NC.COM            ../bin/NC.cpu
RUN.COM           ../bin/RUN.cpu
E.EXE             ../bin/E.cpu
DOS.SYS           ../bin/DOS.sys                               0xC000 RS
AUTOEXEC.BAT      {AUTOEXEC}                                   0x8000
```

Каждый манифест содержит ровно одну директиву `@label` с меткой тома:
`@label SYSTEM ROM`, `@label ROM DISK 64` или `@label FLASH DISK`.
Метка задаётся без кавычек, может содержать пробелы и занимает 1–11 ASCII-символов.
Сборщик дополняет её справа пробелами до 11 байт в BPB. Пустая, слишком длинная,
повторная или содержащая запрещённые FAT символы метка приводит к ошибке.
Неизвестные директивы также отклоняются. В PowerShell-сценарии меток больше нет.

Столбцы файлов разделяются пробелами или табуляцией. Пустые строки и строки,
начинающиеся с `#`, пропускаются. Имя на диске должно помещаться в FAT 8.3;
исходный файл может иметь длинное имя. Пробелы внутри имён и путей не поддерживаются.
Все пути отсчитываются от `assets`; результаты сборки доступны через `../bin/`.

Формат результата задаётся расширением имени в первом столбце. COM и EXE получают одинаковый 16-байтный заголовок MXOS2 с адресами и штатными контрольными суммами. RKS сохраняет стандартный контейнер с четырёхбайтным заголовком и двухбайтной суммой в конце. SYS, MON и остальные файлы копируются без упаковки; RAMFOS.MON — сырой образ двух областей ядра.

Источник может быть RKS, новым COM/EXE, старым сырым EXE/BIN либо CPU/I80. CPU при наличии соседнего I80 содержит два шестнадцатеричных числа ASCII: адрес загрузки и адрес входа; машинный код находится в I80. CPU без I80 означает сырой образ с загрузкой и входом 0000h. Для старого RAW EXE/BIN адрес задаётся третьим столбцом (по умолчанию 0). RKS не может представить отличный от загрузки адрес входа: такое преобразование отклоняется. Проверки и преобразования выполняет `executable.ps1`; неизвестный/повреждённый RKS не исправляется молча.

Поле DIR_FileSize содержит точную длину N, включая заголовок и сумму контейнера. Бывшее расширение MXOS в байтах 12h–13h удалено: это стандартное поле даты последнего доступа, сборщик записывает ноль. Адреса загрузки находятся только внутри исполняемого файла. Это подготовка записи каталога к FAT16, а не утверждение полной стандартности текущего тома: геометрия, свободные записи FFh и самоссылка конца цепочки ещё требуют отдельного перехода.

`{AUTOEXEC}` заменяется выбранным `system-rom/autoexec.*.bat`. После смены формата нужно пересобрать все образы; старые внутренние тома не поддерживаются.

Необязательный четвёртый столбец RAW задаёт атрибуты: `R` — read-only,
`S` — системный, `RS` — оба. Если адрес не нужен, укажите `0`.
Без столбца атрибуты равны нулю.

`A-System.txt` задаёт системный состав и метку обычных системных образов.
`A-RAMFOS.txt` задаёт дополнение и метку объединённого образа `SystemRamfos`;
метка базового `A-System.txt` для него не используется.
`H-ROM64k.txt` задаёт ROM-диск H: на 64 КБ, а `H-Games2M.txt` — flash-диск H: на 2 МБ.
Порядок строк определяет порядок каталога и кластеров.

В `Games2M` кластеры файлов чередуются между четырьмя чипами по 512 КБ.
Преобразования физических адресов нет: порядок задаётся обычными FAT-цепочками,
поэтому образ читается Flash и FlashFst. Загрузочный сектор, FAT и корневой
каталог занимают непрерывную область на чипе 0. Системные образы и `Games64k`
сохраняют линейное размещение. Ячейки FAT за концом области данных помечаются
занятыми; свободное место не теряется из-за обхода границы чипа.

Проверка собранных четырёх частей: `python -X utf8 scripts/images/check-interleave.py`.
Она сравнивает полезную нагрузку всех файлов с манифестом, проверяет цепочки,
отсутствие общих кластеров и распределение по чипам. Отчёт находится в
`docs/flash/interleave-001/image.json`.

В линейных системных образах встроенный ROM-драйвер теперь читает все банки.
Ограничение первой 32-КБ страницы проверяется только для DOS.SYS: оно нужно
начальному загрузчику. FONT, FORMAT, FLASHSYS.COM, AUTOEXEC и NC могут
размещаться в остальных банках. Прежний порядок файлов сохранён.


Для 64-КБ MX2-образа STD-половина содержит 32764 байта данных после
четырёхбайтного входа. Размер Boot/FAT/корня из этой половины повторно
не вычитается: иначе хвост последнего файла молча обрезался. Последний
логический сектор доступен не целиком и помечается bad (FFF7h), чтобы
файл не попал в недоступные четыре байта и CHKDSK не считал его потерянным.
Проверка всех полезных нагрузок по системному манифесту:

```powershell
python -B scripts/images/check-system-rom.py --image images/SystemRom_emulator.bin --mx2
python -B scripts/images/check-system-rom.py --image images/SystemRom_emu80_writable.bin --autoexec emu-writable
```


Сборщик целиком работает на Windows PowerShell 5.1 и штатном .NET. `executable.ps1` подключается в тот же процесс и преобразует COM/EXE/RKS напрямую в байтовые массивы. Python, C#, внешние процессы, JSON-запросы и base64 для сборки образов не требуются. `executable.py` остаётся независимым эталоном для Python-проверок и исследовательских утилит, но сборщик его не вызывает.

Сумма bios_calcCS вычисляется через сумму байтов штатным LINQ без побайтового цикла PowerShell. Уже проверенный контейнер подходящего формата сохраняется без повторной упаковки. Проверки длины, адресов и сумм сохранены; кэша с устаревающими результатами нет.

Секторы пишутся непосредственно из подготовленных массивов; общий FFh-буфер дополняет только неполный хвост. В локальном замере 03.11.2026 медиана трёх запусков: Games2M — 0,86 с, SystemEmuWritable — 0,38 с, включая запуск PowerShell. Четыре чипа Games2M совпали с прежним сборщиком побайтно; системный образ совпал с вариантом на эталонном Python-конвертере при одинаковых входах. Проверена сборка при отсутствии Python в PATH.

Проверки: `scripts/tests/check-executable-ps.py` сравнивает 204 случая конвертации с независимым эталоном, включая Unicode-пути, отдельный вход, предельные размеры и повреждённые контейнеры. Подробный локальный отчёт — docs/build/image-ps-001/.
