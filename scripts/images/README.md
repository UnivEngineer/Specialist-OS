# Сборка образов

## Специалист-MX с одним банком ДОЗУ

Из корня проекта запустите `powershell.exe -NoProfile -File scripts/build/build-project.ps1 MX`. Команда готовит три линейных образа ПЗУ, системную дискету и загрузочную внешнюю flash.

| Файл в `images/`                                     | Назначение |
| ---------------------------------------------------- | -------- |
| `C-ROM-48k-MX-System.bin`, `C-ROM-32k-MX-System.bin` | Том MXOS-256 на 128 или 192 блока. Сброс переходит к BOOT.SYS по 0600h. Рядом с ним в каталоге C: хранятся BIOS.SYS, 8×8 ROTATE.FNT, IO.SYS и MEM.SYS. |
| `C-ROM-2k-MX-boot.bin`                                | Образ для одной К573РФ2/5. Старт с 0000h, без FAT и заставки. |
| `A-Flash-1M-MX-System.bin`                            | Загрузочная flash для Emu80. Суффиксы `-chip1` и `-chip2` обозначают части по 512 КиБ для прошивки. |
| `C-ROM-32k-MX-RAMFOS.bin`                            | Самостоятельный RAMFOS с родным ROM-каталогом и Monitor2.SYS. Отдельная цель `MxRamfos32`. |
| `A-Floppy-720k-MX-System.img`                        | Загрузочная дискета DD 720 КиБ, привод 0. DOS монтирует её как системный том A:. |

LBA 0 содержит BPB FAT12. В LBA 1 находится заголовок `MXB1` для дискеты или `MXF1` для flash, число секторов следующей ступени и её 16-битная сумма. Загрузчик читает эту ступень с LBA 2 в MAIN с 3000h и после проверки суммы передаёт управление на 8000h. Дисковая ступень устанавливает BIOS, IO, MEM и шрифт, затем читает следующие сектора DOS. Сумму Monitor-2 каждого сектора DOS она проверяет перед копированием в банк 0. При отказе flash загрузчик проверяет дискету. При отказе дискеты у верхнего края выводится битмапа `Please insert boot disk or ROM card, and press Reset.` и процессор ждёт сброса. BPB резервирует всю загрузочную область перед первой FAT.

Для старта с комплектом из ПЗУ 32/48 КиБ соберите `scripts/images/build-image.ps1 MxFloppy -MxUseRomBundle`. Эта команда создаёт `A-Floppy-720k-MX-ROM-Bundle.img` и `A-Flash-1M-MX-ROM-Bundle.bin` с частями для двух чипов. Обычные образы содержат собственный комплект BIOS. При любом Reset выбор повторяется. DOS с совпадающим идентификатором остаётся в своём банке.

Загрузочный носитель остаётся на A:. Внешняя flash монтируется только для чтения. Встроенная команда `SYSROM C:` в `A:\AUTOEXEC.BAT` подключает ПЗУ только для чтения. Без команды C: скрыт, а ввести её можно и позднее из NC или CLI.

Один образ дискеты используется в Emu80 и на MX. `AUTOEXEC.BAT` вызывает `ROM64KX.COM -LETTER H`. Без носителя драйвер регистрирует H: с нулевой ёмкостью, загрузка продолжается, а обращение к H: возвращает `No media`.

Единственный дополнительный банк занимает DOS. Резидентный драйвер ВГ93 доступен до исполнения `A:\AUTOEXEC.BAT`. Сценарий, MAIN- и банковые варианты NC и EDIT, игры, шрифты и дополнительные драйверы — обычные файлы на дискете. Для обновления системных секторов запишите образ целиком. [Манифест дискеты](../../assets/A-Floppy-720k-MX-System.txt)

Для Emu80 выберите **Build and run Emu80 MX ROM + floppy**. Задача собирает и развёртывает системное ПЗУ, дискету Emu80 и ROM-диск H:. Обычный запуск включает звук ВИ53 и монитор ленты. Для ПЗУ 32 КиБ вызовите `scripts/emu80/run-profile.ps1 'MX ROM + floppy' -RomKiB 32`. Параметр `-RomKiB 2` выбирает минимальное ПЗУ, `-ExternalFlash` подключает загрузочную flash вместо игрового ROM-диска, а `-Mute` отключает звук.

## Системные образы MX2

Системный манифест явно перечисляет BOOT.SYS, BIOS.SYS, IO.SYS, MEM.SYS и DOS.SYS. Сборщик проверяет обязательные записи и фиксированные ROM-позиции, не добавляя скрытых файлов. Директива `@bootfont FONTS/6x8/Rotate.fnt` выбирает самодостаточный загрузочный движок со встроенным шрифтом; можно выбрать Compact.fnt. Для разовой сборки SystemEmuWritable/SystemHardware тот же выбор задаётся параметром `-BootFont`. Движки с нижним пререндером устанавливаются после старта через FONT.

`build-image.ps1` собирает системный ROM и flash-образы. Проверка актуальности учитывает выбранный манифест, входные файлы и их I80, параметры и готовые образы. Для принудительной упаковки передайте `-Force`. `scripts/emu80/seed-flash.ps1` использует ту же проверку для четырёх chip-файлов. Малые тома используют явно обозначенный формат MXOS-256 (OEM `MXOS256 `): сектор/кластер 256 байт, одна 16-битная FAT, стандартные маркеры EOC FFF8h–FFFFh, E5h для удаления и 00h для конца каталога. FAT[0]=FFF8h при Media=F8h. Метка корня совпадает с BPB и занимает одну из записей каталога. Это расширение для малых носителей, а не стандартная FAT16. После перехода образы требуется пересобрать; байты старых образов на месте не исправляются.

Манифесты лежат прямо в [assets](../../assets) и используют общий формат.

Первый столбец теперь допускает путь из компонентов 8.3 с `/` или `\`. `nest-fat-image.py` строит цепочки подкаталогов и записи . / .., сохраняя уже выделенные цепочки файлов. Исходные файлы assets при этом не перемещаются. Общий путь ограничен MAX_PATH=128 с учётом начального разделителя и завершающего нуля. Штатный [H-Flash-2M-Games.txt](../../assets/H-Flash-2M-Games.txt) использует вложенные каталоги.

Свой манифест для Games2M можно передать через `-ManifestFile` сценарию `scripts/images/build-image.ps1`. Она создаёт chip-файлы с именем переданного манифеста и отдельный полный образ `bin/nested-Games2M.bin` для проверок. Полный образ и четыре файла микросхем называются по манифесту. Параметр ManifestFile пока применяется только к Games2M. Независимый обход штатного образа выполняет `python scripts/tests/check-nested-image.py`. Для своего образа передайте проверке тот же путь к манифесту. Проверка файлов через DOS в собственном видимом Emu80: `python scripts/emu80/check-directories.py --runtime <свой runtime>`.

`powershell.exe -NoProfile -File scripts/images/build-image.ps1 Floppy720` создаёт `images/A-Floppy-720k-Programs.img` по манифесту [A-Floppy-720k-Programs.txt](../../assets/A-Floppy-720k-Programs.txt). Это линейный образ дискеты на 720 КиБ (80 цилиндров, 2 стороны, 9 секторов по 512 байт), с двумя копиями FAT12, кластерами по 1024 байта и 112 записями корня. На дискете размещён каталог игр `GAMES`. Для замера дисковода запустите `H:\BENCH\DISKBEN\DISKBEN.COM A:` из образа Games2M.

```text
@label SYSTEM ROM

# Имя на диске    Путь относительно assets                    Адрес RAW
NC.COM            ../bin/NC_DOS.cpu
RUN.COM           ../bin/RUN.cpu
EDIT.EXE             ../bin/EDIT.cpu
DOS.SYS           ../bin/DOS.sys                               0xC000 RS
AUTOEXEC.BAT      {AUTOEXEC}                                   0x8000
```

Каждый манифест содержит ровно одну директиву `@label` с меткой тома: `@label SYSTEM ROM`, `@label ROM DISK 64` или `@label FLASH DISK`. Метка задаётся без кавычек, может содержать пробелы и занимает 1–11 ASCII-символов. Сборщик дополняет её справа пробелами до 11 байт в BPB. Пустая, слишком длинная, повторная или содержащая запрещённые FAT символы метка приводит к ошибке. Неизвестные директивы также отклоняются. В PowerShell-сценарии меток больше нет.

Столбцы файлов разделяются пробелами или табуляцией. Пустые строки и строки, начинающиеся с `#`, пропускаются. Имя на диске должно помещаться в FAT 8.3; исходный файл может иметь длинное имя. Пробелы внутри имён и путей не поддерживаются. Все пути отсчитываются от `assets`; результаты сборки доступны через `../bin/`.

Формат результата задаётся расширением имени в первом столбце. COM и EXE получают одинаковый 32-байтный заголовок v2 MXOS2 с адресами и штатными контрольными суммами. RKS сохраняет стандартный контейнер с четырёхбайтным заголовком и двухбайтной суммой в конце. SYS, MON и остальные файлы копируются без упаковки; RAMFOS.MON — сырой образ двух областей ядра.

Источник может быть RKS, новым COM/EXE, старым сырым EXE/BIN либо CPU/I80. CPU при наличии соседнего I80 — текстовый сопроводительный файл: первая строка содержит шестнадцатеричный адрес загрузки, вторая — адрес входа, третья — имя монитора. I80 содержит машинный код. Для собственных программ используется `mxos2.mon`: это метка MXOS2 для сборщика, при отсутствии FLAGS она означает MAIN. Для классических программ можно явно указать `mon2.mon` либо настоящее имя требуемого монитора. После третьей строки допускаются дополнительные строки `KEY=VALUE`; сейчас в заголовок переносится FLAGS, прочие поля возвращаются разборщиком как метаданные и пока не влияют на бинарный контейнер. Повтор ключа и строка без `=` отвергаются. Двухстрочный исходный CPU без монитора остаётся допустимым, но перед дополнительными полями монитор обязателен. CPU без I80 означает сырой образ с загрузкой и входом 0000h. Для старого RAW EXE/BIN адрес задаётся третьим столбцом (по умолчанию 0). RKS не может представить отличный от загрузки адрес входа: такое преобразование отклоняется. Проверки и преобразования выполняет `executable.ps1`; неизвестный/повреждённый RKS не исправляется молча.

Поле DIR_FileSize содержит точную длину N, включая заголовок и сумму контейнера. Бывшее расширение MXOS в байтах 12h–13h удалено: это стандартное поле даты последнего доступа, сборщик записывает ноль. Адреса загрузки находятся только внутри исполняемого файла. Это подготовка записи каталога к FAT16, а не утверждение полной стандартности текущего тома: геометрия MXOS-256 отличается от стандартной FAT16; логические секторы 512 байт и стандартные типы томов ещё не реализованы.

`{AUTOEXEC}` заменяется выбранным `system-rom/autoexec.*.bat`. После смены формата нужно пересобрать все образы; старые внутренние тома не поддерживаются.

Необязательный четвёртый столбец RAW задаёт атрибуты: `R` — read-only, `S` — системный, `RS` — оба. Если адрес не нужен, укажите `0`. Без столбца атрибуты равны нулю.

`C-Flash-512k-MMX-System.txt` задаёт системный состав и метку обычных системных образов. `C-Flash-512k-MMX-RAMFOS-Tests.txt` задаёт дополнение и метку объединённого образа `SystemRamfos`; цель собирает линейный образ `images/C-Flash-512k-MMX-RAMFOS-Tests.bin` на 512 КиБ для flash-профиля Emu80. На C: в каталоге `TESTS/LAFAN` лежат Penx и Trs_MX для запуска через `RUN -RF`. `H-ROM-64k-Games.txt` задаёт ROM-диск H: на 64 КБ, а `H-Flash-2M-Games.txt` — flash-диск H: на 2 МБ. Порядок строк определяет порядок каталога и кластеров.

Для целевого EXE из `games/` сборщик ищет точный исходный путь в [catalog.csv](../../assets/games/catalog.csv) и использует `RunMode`. `MX`, `STD`, `MON`, `RF` и `AUTO` записываются в поле MODE заголовка v2 как рекомендации. При явном вызове RUN режим выбирается ключом или в меню. `NATIVE` требует флаг MAIN во входном CPU/I80 или EXE и сохраняет его декларацию памяти. Адреса, нагрузка и имена на диске определяются источником и манифестом. Изменения реестра учитываются при проверке актуальности образа с такими EXE.

В `Games2M` кластеры файлов чередуются между четырьмя чипами по 512 КБ. Преобразования физических адресов нет: порядок задаётся обычными FAT-цепочками, поэтому образ читается Flash и FlashFst. Загрузочный сектор, FAT и корневой каталог занимают непрерывную область на чипе 0. Системные образы и `Games64k` сохраняют линейное размещение. Ячейки FAT за концом области данных помечаются занятыми; свободное место не теряется из-за обхода границы чипа.

Проверка собранных четырёх частей: `python -X utf8 scripts/images/check-interleave.py`. Она сравнивает полезную нагрузку всех файлов с манифестом, проверяет цепочки, отсутствие общих кластеров и распределение по чипам. Отчёт находится в `docs/flash/interleave-001/image.json`.

В линейных системных образах встроенный ROM-драйвер теперь читает все банки. Ограничение первой 32-КБ страницы проверяется только для DOS.SYS: оно нужно начальному загрузчику. FONT, FORMAT, AT512KS.COM, AUTOEXEC и NC могут размещаться в остальных банках. Прежний порядок файлов сохранён.


Для 64-КБ MX2-образа STD-половина содержит 32764 байта данных после четырёхбайтного входа. Размер Boot/FAT/корня из этой половины повторно не вычитается: иначе хвост последнего файла молча обрезался. Последний логический сектор доступен не целиком и помечается bad (FFF7h), чтобы файл не попал в недоступные четыре байта и CHKDSK не считал его потерянным. Проверка всех полезных нагрузок по системному манифесту:

```powershell
python -B scripts/images/check-system-rom.py --image images/C-ROM-64k-MMX-System-Emu80.bin --mx2
python -B scripts/images/check-system-rom.py --image images/C-Flash-512k-MMX-System-Emu80.bin --autoexec emu-writable
```


Преобразование исполняемых файлов работает в Windows PowerShell 5.1 на штатном .NET. `executable.ps1` подключается в тот же процесс и преобразует COM/EXE/RKS напрямую в байтовые массивы. Для проверки зависимостей, раскладки вложенных каталогов и упаковки самостоятельного RAMFOS сборщик вызывает Python. `executable.py` остаётся независимым эталоном для Python-проверок и исследовательских утилит, но сборщик его не вызывает.

Сумма bios_calcCS вычисляется через сумму байтов штатным LINQ без побайтового цикла PowerShell. Уже проверенный контейнер подходящего формата сохраняется без повторной упаковки. Проверки длины, адресов и сумм сохранены; кэша с устаревающими результатами нет.

Секторы пишутся непосредственно из подготовленных массивов; общий FFh-буфер дополняет только неполный хвост. В локальном замере 03.11.2026 медиана трёх запусков: Games2M — 0,86 с, SystemEmuWritable — 0,38 с, включая запуск PowerShell. Четыре чипа Games2M совпали с прежним сборщиком побайтно; системный образ совпал с вариантом на эталонном Python-конвертере при одинаковых входах.

Проверки: `scripts/tests/check-executable-ps.py` сравнивает 204 случая конвертации с независимым эталоном, включая Unicode-пути, отдельный вход, предельные размеры и повреждённые контейнеры. Подробный локальный отчёт — docs/build/image-ps-001/.

Навигация по вложенным каталогам образа H: доступна в NC: Enter открывает каталог, `..` возвращает выше, CD/CHDIR работают из командной строки. Для повторного просмотра подготовленного отдельного тестового runtime можно запустить `powershell.exe -NoProfile -File scripts/emu80/run.ps1 -EmulatorDirectory .local/monitor2-001 -Flash -Mute`; без -ResetFlash этот запуск сохраняет его текущий H:.

Модули `.DLL` упаковываются из CPU/I80 так же, как COM/EXE: стандартный заголовок MXOS v2 на 32 байта с адресами и контрольными суммами. При входном DLL заголовок проверяется и повторно не добавляется. Расширение DLL предназначено для moduleLoad/moduleCall; обычный FILE_EXEC такие файлы не запускает.


Флаги контейнера задаются в главном ASM после INCLUDE mxos.inc: `IMAGE_FLAGS = IMAGE_FLAG_BANK` (02h) для обязательного отдельного EXEC-банка либо `IMAGE_FLAGS = IMAGE_FLAG_DRIVER` (01h) для инициализатора в банке DOS, либо `IMAGE_FLAGS = IMAGE_FLAG_MAIN` (04h) для явно подтверждённой совместимости с main/MXOS BIOS. Без IMAGE_FLAGS получается 00h: совместимость не подтверждена. Любые сочетания этих флагов запрещены. build-if-needed.ps1 извлекает символ IMAGE_FLAGS из .sym и записывает строкой FLAGS=xx после mxos2.mon в .cpu; сборщик образа переносит его в байт 05h заголовка COM/EXE/DLL и вычисляет сумму. Сам машинный .i80 заголовка не содержит. При собственной упаковке нужно явно передать тот же flags контейнерному сборщику.

DLL с BANK загружается только через moduleLoad с MODULE_TARGET_BANK. DLL с MAIN допускает только MODULE_TARGET_MAIN. Нейтральная DLL с flags=0 допускает оба размещения. Банковые COM/EXE запускает нативный FILE_EXEC DOS с выделением EXEC-банка и освобождением ресурсов после RET. RUN передаёт контейнеры с MAIN/DRIVER/BANK нативному загрузчику DOS через FILE_EXEC_NATIVE, обходя ассоциации; COM/EXE без признака показывают меню совместимости, если режим не задан ключом. RKS флагов размещения не имеет.


При обычном FILE_EXEC ядро проверяет найденный COM/EXE до CLI.EXT. Штатная CLI.EXT задаёт ассоциации RUN для RKS и MON. Контейнеры COM/EXE с корректным заголовком запускаются загрузчиком DOS.

Все COM штатного A-System имеют явный тип запуска. Историческое тело Test-MX.COM не меняется: source-apps/test-mx/TESTMX.asm включает его через INCBIN и задаёт IMAGE_FLAGS=IMAGE_FLAG_MAIN; в манифест поступает полученная CPU/I80-пара. RAMDISK.COM имеет DRIVER и собирается к исключающей верхней границе арены DOS C9D8h; его старый main-установщик исключён из штатного бинарника.


Пример расширенного CPU (значения адресов и FLAGS — шестнадцатеричные):

```text
0100
0100
mxos2.mon
FLAGS=02
NOTE=Banked application
```

Emu80 SpecMxFileLoader читает только первые три значения и игнорирует последующие поля. Пустая третья строка перед полями небезопасна: эмулятор читает значения через пробельный разделитель и примет первый ключ за имя монитора. Сам `mxos2.mon` не является встроенной командой эмулятора: без соответствующего файла он сообщает о незагруженном мониторе. Текущий COM/EXE/DLL/FNT v2 имеет заголовок 32 байта. Имя произвольного монитора в нём не хранится; поле MODE хранит рекомендуемую среду MX/STD/MON/RF. Явный ключ RUN и аргументы можно закрепить в BAT.


В проверенной MCP-сборке Emu80 4.0.575 найдено отдельное ограничение SpecMxFileLoader: файл монитора с адресом в имени (например, monC000.mon) записывается в mapper page 1 — RAM-диск, хотя затем исполняется page 0 — MAIN. Это не исправляется дополнительными CPU-полями; перед прямым запуском через внешний файл монитора требуется исправление загрузчика эмулятора. Проверка формата и фактического размещения: scripts/emu80/check-cpu-descriptor.py, собственный видимый экземпляр с выключенным звуком.

## Сборка из готовых бинарников

Для системной flash MMX на 512 КиБ выполните `powershell -NoProfile -File scripts/images/build-image.ps1 SystemHardware 512 -Prebuilt`. Получится `images/C-Flash-512k-MMX-System.bin`. В комплекте нужны сборщик образов (PowerShell и Python), манифест, входные файлы из `assets/` и готовые файлы из `bin/`. Берите системные модули, загрузчик, начальный шрифт и описание `bin/bootstrap/boot-set.json` из одной сборки. Состав прикладных программ и текст AUTOEXEC можно менять перед упаковкой. Полный системный манифест рассчитан на 512 КиБ. Для чипа 128 или 256 КиБ сократите состав. В MMX установщик `C:\DRIVERS\AT512KS.COM -LETTER C` включает запись на уже доступной загрузочной flash.

Тот же ключ работает с целями `MxFloppy`, `MxRom32`, `MxRom48` и `MxRamfos32`. Они используют готовые загрузочные сектора и двоичные компоненты своего профиля. Имена образов следуют именам манифестов. Вариант для эмулятора с отдельным AUTOEXEC получает суффикс `-Emu80`, а части внешней flash получают суффиксы `-chip1` … `-chip4` в порядке прошивки.
