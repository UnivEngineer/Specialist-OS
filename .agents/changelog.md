# Журнал и подготовка коммита

В техническом журнале `docs/CHANGELOG.md` фиксируй изменения поведения и API/ABI, существенные детали реализации и ссылки на замеры. Если файла в рабочей копии ещё нет, создай его. Для рабочих материалов компонента используй подкаталог `docs/`. Там остаются промежуточные варианты, подробности проверок и отчёты объёмом, соответствующим задаче.

При подготовке коммита сверь записи после последней отметки с итоговым diff относительно предыдущего коммита. Обнови корневой `CHANGELOG.MD`: дата — заголовок второго уровня, название компонента — третьего. Опиши возможности, команды, ограничения, условия применения, изменения API/ABI и значимые результаты измерений. В конце технического журнала отметь, по какую запись разобраны заметки, и сохрани сами записи. Заголовок и описание коммита пиши по-английски.

В Git включай публичный ченджлог. Локальные материалы в `docs/` остаются игнорируемыми, без принудительного добавления или изменения правил Git. При переносе обновляй входящие ссылки и относительные пути самого документа. Перенос существующих TODO и отчётов из других каталогов или снятие уже отслеживаемых файлов с учёта требуют отдельного задания. README и постоянную документацию сохраняй в принятых местах.
