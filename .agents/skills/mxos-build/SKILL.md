# Сборка и проверка Specialist-OS

Пути команд отсчитываются от корня репозитория. При параллельной работе с сетевой копией создай собственный локальный checkout через `scripts/build/new-local-workspace.ps1`. Сценарий клонирует коммит текущей ветки. До проверки перенеси нужные незакоммиченные правки, собирай в локальных `bin/`, `images/` и каталогах компонентов.

## Выбор проверки

1. После изменения ASM/INC собери компонент его штатным сценарием. При изменении ABI, карты памяти, DOS, драйвера или системной программы выполни `scripts/build/build-project.ps1 OS`. Для полной сборки системы, игр и автономных тестов служит `scripts/build/build-all.ps1`.
2. Проверь ошибки и предупреждения SjASMPlus (в задачах VS Code — `$errmatcher-sjasmplus`). По листингу проверь адреса, размеры секций, пересечения ORG_PAD, свободные промежутки и конец разрешённой области. Для общих функций NC/EDIT проверь затронутые профили MAIN и EXEC.
3. Если изменился состав системного ROM, после компонентов собери `scripts/images/build-image.ps1 SystemEmuWritable`. Для MMX результат — `images/C-Flash-512k-MMX-System-Emu80.bin`. Внешний диск собирают цели Games64k/Games2M, цель Games2M создаёт полный образ для Emu80 и четыре файла микросхем. Остальные цели и манифесты — в [описании сборщика образов](../../../scripts/images/README.md).
4. Проверь изменённый сценарий ASM/INC в Emu80, включая загрузку ОС, NC и доступ к дискам. Для общего MMX-профиля используй MMX Flash + floppy и системную flash 512 КиБ. Для драйвера дополнительно проверь чтение, запись, границы носителя и ошибочные параметры. Перед запуском открой [mxos-emu80](../mxos-emu80/SKILL.md).

## Сценарии компонентов

Из каталога обычного компонента: `powershell.exe -NoProfile -File ..\..\scripts\build\build-if-needed.ps1 <имя-без-расширения> <расширение> <адрес>`. Фактические имена исходников, адреса и специальные сборщики — в [build-project.ps1](../../../scripts/build/build-project.ps1). В workspace сохраняй `Build all` и задачи запуска Emu80. Компоненты и образы собирай их сценариями. Базовый вызов: `sjasmplus.exe --i8080 -Wno-rdlow --lst=<file>.lst --raw=<file>.<ext> <file>.asm`. Бинарник и листинг попадают в `bin/`. Упаковщик создаёт из CPU/I80 файл по имени в манифесте. Фиксированные образы используют 32-байтный заголовок v2. Для перемещаемых DLL и установщиков DRIVER сборщик передаёт размер тела, вид поправок и выравнивание, а упаковщик создаёт заголовок v3 и таблицу в конце файла. [Формат и пример сборки](../../../scripts/images/README.md)

При изменении составной сборки используй `scripts/build/build_cache.py` или его `python_build`. Через `--asm` передай входной исходник либо каталог одной цели: кэш сам раскрывает INCLUDE/INCBIN. Через `--input` укажи остальные входы, включая JSON и символы компоновщика. Объяви все результаты, в том числе оставляемые без перезаписи, через `--output` и `--scan-output`, команду — после `--`. Используй общий кэш без отдельных файлов состояния и проверок актуальности. Пересборка — `-Force` в PowerShell или `--force` в Python.

Для BIOS/DOS штатный [компоновщик](../../../scripts/build/build-bios-dos.py) измеряет блоки, размещает их вокруг C000h/C800h и генерирует `bin/System.layout.inc` и `bin/System.layout.json`. BIOS.sys начинается с C000h, IO.sys с F000h, DOS.sys в банке с 0100h. Меняй входы компоновки. При добавлении INCLUDE сохраняй цепочки исполнения через `chain`, копируемые драйверы и таблицы должны оставаться целыми. `pack-dos.py` — библиотека размещателя, `build-dos4000.ps1` вызывает парную сборку. Monitor-2 должен побайтно воспроизводить `source/monitor2/originals/Monitor2.mon`.

Меняй исходники, конфигурацию или генератор. Образы, листинги (.lst, .fix.lst), list.tmp, выходные программы и служебные каталоги Visual Studio — результаты сборки. Внешние игры, эталоны и другие входные бинарники проекта сохраняй.
