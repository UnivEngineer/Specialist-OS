# Файловые драйверы томов DOS

Подготовлено разделение файловых операций и физических блоков. Алгоритмы
существующего формата остались прежними; стандартная FAT16 и файловый драйвер
RAMFOS ещё не реализованы. Подробный [аудит FAT16](../../docs/FAT16-status.md)
содержит ограничения и очередность следующих изменений.

## Три уровня

1. Прежние файловые точки DOS вызывают диспетчер из `volume.inc`.
2. Для каждой буквы A:–H: отдельно регистрируются файловая таблица и контекст.
   По умолчанию все буквы используют `fatVolumeDriver` — старый формат MXOS.
3. Физический драйвер выбирается прежним способом через `bios_installDriver`
   и `bios_diskDriver`. Регистрация файловой системы его не заменяет.

`fileSelectDrive` выбирает обе таблицы и вызывает mount файлового драйвера.
При повторном выборе той же буквы автоматического mount нет; для этого
предназначен отдельный вызов. Модуль использует физический ABI для блоков,
а не вызывает внутренние FAT-процедуры DOS.

## Регистрация и срок жизни

| Вход | Контракт |
|---|---|
| `bios_installVolume`, C890h | A=0…7, HL=таблица, DE=контекст (или 0). BC/DE/HL сохраняются. CF=1 при неверном индексе, заголовке или нулевом обработчике. Для активной буквы возвращается результат mount; регистрация при его отказе уже выполнена. |
| `bios_getVolume`, C893h | A=0…7 → HL=таблица, DE=контекст; BC сохраняется. CF=1 при неверном индексе. Диск не переключается. |
| `bios_mountVolume`, C896h | Повторно монтирует текущий том. BC/DE/HL сохраняются, AF возвращается от mount. |
| `bios_flushVolume`, C899h | Вызывает flush текущего тома; AF и остальные выходы определяет обработчик. CF=1 означает отказ. |

Таблица: `DB "FS",1,15`, затем 15 ненулевых адресов `DW`, всего 34 байта.
Ошибочный или неподдерживаемый вызов должен иметь настоящий обработчик отказа.
Версия и число обработчиков проверяются при регистрации; адреса и срок жизни
памяти гарантирует загрузившая модуль программа. Таблица не копируется.

Модуль и его контекст должны переживать вызовы NC и пользовательских программ.
Буфер копирования NC `0000h–7FFFh` для постоянного размещения не подходит.
В этой подготовке нет распределителя памяти и автоматической загрузки модулей.
После подмены ядра и возврата в MXOS модули/контексты регистрируются заново:
указывать на затёртый код прежнего ядра нельзя.

Перед заменой активного драйвера или сменой тома вызывающая сторона должна
закрыть операции и вызвать flush. Переключение пока сбрасывает старый секторный
кэш; его исторические ошибки записи перечислены в аудите. Это ещё не гарантия
безопасного сброса данных при ошибке устройства.

## Таблица обработчиков версии 1

Смещения считаются от первого слова после четырёхбайтного заголовка.
Файловые обработчики получают исходные регистры и флаги; их результат
возвращается вызывающей программе без преобразования.

| Смещение | Константа | Прежний контракт |
|---:|---|---|
| 0 | `VOL_MOUNT` | Монтировать текущий том; CF=1 при отказе. Входные регистры не заданы. |
| 2 | `VOL_LIST` | `bios_fileList` |
| 4 | `VOL_CREATE` | `bios_fileCreate` |
| 6 | `VOL_LOAD` | `bios_fileLoad` |
| 8 | `VOL_DELETE` | `bios_fileDelete` |
| 10 | `VOL_RENAME` | `bios_fileRename` |
| 12 | `VOL_STAT` | `bios_fileLoadInfo` |
| 14 | `VOL_LOAD_ADDRESS` | `bios_fileGetSetAddr` |
| 16 | `VOL_ATTRIBUTES` | `bios_fileGetSetAttr` |
| 18 | `VOL_LOAD_AT` | `bios_fileLoad2` |
| 20 | `VOL_FREE_SPACE` | `bios_getDriveFreeSpace` |
| 22 | `VOL_PREPARE_NAME` | `bios_fileNamePrepare`, но префикс `X:` уже обработан DOS |
| 24 | `VOL_CREATE_PREPARE` | `bios_fileCreatePrepare` |
| 26 | `VOL_TRANSFER_LEGACY` | `bios_fileTransfer`, пока привязанный к кластерам |
| 28 | `VOL_FLUSH` | Сохранить изменения; CF=1 при отказе |

Контекст можно получить через публичный `bios_getVolume`, предварительно
узнав текущую букву через `bios_fileGetSetDrive`. Внутренние переменные DOS
не являются адресами публичного ABI. Mount не обращается к файловой системе
повторно через собственные публичные файловые точки.

Диспетчер не реентерабелен: он меняет адрес своего перехода. Вызовов DOS из
прерываний и параллельного переключения тома быть не должно. Основной путь
обёртка + диспетчер занимает 167 тактов 8080 (около 83,5 мкс при 2 МГц),
без времени обработчика и исходного публичного JP. Общий диспетчер — 22 байта.

## Что требуется до подключения RAMFOS

Версия 1 сохраняет `FILE_DESCRIPTOR`/`FILE_INFO`, имена 8+3, размер N−1 и
кластерный поток C88Dh. RAMFOS имеет собственный формат и имена 9+3; полной
совместимости средствами этой таблицы ещё нет.

Нужен общий байтовый поток open/read/write/close/abort с 32-битной длиной и
непрозрачным состоянием файла. После перевода F5 на этот интерфейс модуль
RAMFOS сможет реализовать файловые операции своим обходом каталога и данных,
не изображая FAT-цепочки. Формат общих сведений о томе тоже нужно отделить
от FAT-геометрии `DISK_INFO`; сейчас это историческая структура.

FORMAT пока работает напрямую с блоками старого FAT-формата. До установки
настоящего модуля RAMFOS надо добавить выбор или запрет форматировщика по
типу тома, чтобы FORMAT не мог затереть чужую файловую систему.

Отдельно нужны резервирование страниц, общая таблица логических/физических
страниц для MXOS и RAMFOS, проверки всех границ и исключение flash из
доступных RAMFOS устройств. Само разделение таблиц страниц не резервирует.

## Проверка без запуска ОС

Собрать DOSChecked с дополнительными символами из `source/dos`:

```powershell
../../tasm/sjasmplus.exe --i8080 -Wno-rdlow --sym=../../bin/DOS-volume.sym --raw=../../bin/DOS-volume-test.sys DOSChecked.asm
```

Затем из корня выполнить `python -X utf8 scripts/tests/check-volume.py`.
Проверка исполняет машинный код диспетчера в узкой модели команд 8080, подменяя
файловые и аппаратные обработчики. Она проверяет регистры/флаги старых входов,
регистрацию, контекст, выбор тома, mount/flush и отклонение ошибочных таблиц.
Она не проверяет работу всей ОС, FAT или настоящего накопителя.
