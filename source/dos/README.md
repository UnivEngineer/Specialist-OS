# Файловое ядро DOS

DOS.SYS исполняется с 0100h в физической странице ДОЗУ 0 (FAR page=1). Первые 100h оставлены под будущие векторы/обработчики по модели CP/M. Образ непрерывный: код и инициализированные данные идут до kernelEnd, без промежутка перед бывшим расширением C500h. Основной исходник — DOS.asm, состав — layout.json. Рабочие буферы задаются адресами и в DOS.SYS не записываются.

В dos/ находятся FAT, каталоги и пути, файловые операции, внутренний fatStream и публичный FILEHANDLE, загрузка программ, локальные физические службы DOS и адаптеры запросов чужих страниц kernel-*.inc. Парсер и диспетчер команд находятся в cli.inc/commands.inc; каталог cli/ содержит консольный интерфейс и часть общих включаемых обработчиков. Весь аппаратный BIOS, рендер и графика находятся в [bios/](../bios/README.md), транспорт и хвосты — в [MEM](../mem/transport.md), общие локально компилируемые примитивы — в [common/](../common/README.md). DOSMOD удалён: его файловые функции связаны с DOS, графические — с BIOS.

## Дисковый кэш

Единый пул кэша CE00h–EDFFh объёмом 8 КиБ распределяется между всеми дисками по потребности, без квот и ограничения двумя активными томами. Сектор 128/256/512 байт занимает 1/2/4 соседние выровненные гранулы по 128 байт; один диск может занять весь пул. Таблица и буферы не входят в DOS.SYS. Восьмибайтный описатель головы содержит LBA, адрес данных, слово reference, dirty и tag. В tag младшие три бита задают диск, следующие два — sectorShift−7; 80h..BFh обозначают продолжение с индексом головы, FFh — свободную гранулу. Пересекающиеся головы вытесняются целиком, включая все продолжения.

Вытеснение использует CLOCK: попадание устанавливает reference=1, проход указателя даёт такой голове второй шанс и сбрасывает reference; голова с reference=0 может быть вытеснена. Полный поиск минимального возраста и счётчик времени для каждого попадания не нужны. Перед поиском проверяется последний слот вместе с меткой диска/геометрии; основная таблица просматривается только по индексам, допустимым для размера искомого сектора. Верхняя оценка LBA позволяет сразу отвергать заведомо отсутствующие потоковые сектора. Оценка хранится отдельно для каждого диска, чтобы высокие LBA загруженных программ одного носителя не замедляли прямое чтение другого; после вытеснения она может оставаться завышенной, что влияет только на скорость.

Неполные файловые сектора используют отдельный общий 512-байтный буфер с собственными tag и dirty. Сначала проверяется общий пул, чтобы не создавать две копии одного сектора. При переходе к неполному сектору другого диска прежняя чистая копия может быть заменена; закреплённого буфера на каждый диск нет. Полные сектора передаются напрямую, если в кэше нет более новой копии.

Смена диска сначала сохраняет dirty прежним драйвером; при отказе диск не переключается. Чистые строки всех дисков остаются в общем пуле. Общий признак dirty позволяет не обходить таблицу при переключениях, если изменений нет; для единственной dirty-строки хранится прямой указатель, и flush также обходится без сканирования. Явное перемонтирование после FORMAT/RAW-записи и замена драйвера/ФС инвалидируют только строки соответствующего диска, включая неактивный. Смена размера сектора также инвалидирует его строки. После внешней смены носителя обязателен явный mount. BPB читается в независимый буфер, не повреждая сохранённые строки.

### Измерение кэша

Штатный DISKBEN проверяет последовательную передачу данных: увеличение файла главным образом увеличивает прямой обмен полными секторами и длину цепочки FAT, а не рабочий набор кэша. Для проверки его заполнения и вытеснения используется `python scripts/tests/benchmark-dos-cache-pressure.py --report docs/diskbench/cache-pressure`: он исполняет штатный код DOS в модели Intel 8080 с синтетическим 256-байтным драйвером. Режимы включают рабочие наборы одного, двух и трёх дисков, неравномерное распределение, переполнение общего объёма, повтор одного сектора и запись с переключениями дисков. Прогрев исключён из измерения; сохраняются такты, число запросов, чтений и записей драйвера. Это изолированная оценка кэша, без стоимости монтирования, файлового поиска и реального носителя. Для сравнения иной сборки доступны `--kernel путь/KERNEL.bin` и соответствующий KERNEL.sym рядом. Полные файловые операции отдельно измеряет `scripts/emu80/benchmark-dos-cache.py` через процедуры DISKBEN в собственном видимом Emu80 без звука.

## Потоковые BAT

BAT открывается один раз через внутренний FILE_HANDLE и читается пачками по 512 байт. Размер сценария не ограничен прежним 6-КиБ буфером; позиция файла и смещение начала строки имеют 32 бита. Вложенный запуск BAT возвращается к следующей строке родителя. Восемь кадров по 720 байт занимают область B500h–CB7Fh: каждый хранит FILE_HANDLE, команду, позицию/остаток буфера, номер строки, её файловое смещение и собственную пачку чтения. COM/EXE в main не затирают эти данные. Программный возврат в оболочку сбрасывает оставшиеся контексты BAT.

Допускается восемь одновременно активных BAT и до 65535 строк в каждом. Командная строка ограничена MAX_PATH−1 (127 байт); переполнение, NUL в тексте, ошибка I/O или команды прерывают выполнение с кодом DOS. Диагностика `BAT ERROR.BAT line 3: error 2` указывает виновный сценарий и строку и печатается один раз при раскрутке вложенных вызовов. CR, LF и CRLF считаются переводом строки; последняя строка без перевода также выполняется. Байт FFh больше не служит маркером EOF. `@` и ECHO ON/OFF сохраняются; подстановка `%1`, CALL и GOTO не добавлялись.

## Сборка и вызовы

`powershell.exe -NoProfile -File scripts/build/build-project.ps1 OS` собирает BIOS/DOS совместно через scripts/build/build-bios-dos.py. BIOS размещается вокруг фиксированных C000h/C800h, DOS собирается последовательно с 0100h. scripts/build/build-banked-dos.py создаёт тот же DOS отдельно для стендов. DOS.native.sys с 4000h — вспомогательный линковочный образ и CPU-модель, в штатную систему не загружается.

В основной памяти приложения располагаются до memtop=8BFFh независимо от DOS. Публичные C800h/F800h/F806h сохраняются; локальная таблица DOS начинается с 0100h, банковый диспетчер — с 015Dh. Исходные NEAR-указатели относятся к странице приложения; их обслуживают kernel-*.inc, а не FAT через чужие адреса. Полные секторы могут идти непосредственно в main через локальные службы A:/B:/H:, частичные — через кэш DOS. Буферизованный путь остаётся для других банков и неподдержанных геометрий.

## Текущее состояние FAT16, 05.11.2026

Слой логических секторов поддерживает 128/256/512 байт поверх физических блоков 128/256/512 байт, если логический сектор не меньше физического. Малые тома с секторами 128/256 байт требуют OEM-сигнатуры `MXOS128 `/`MXOS256 ` и остаются расширениями MXOS. Стандартный FAT16 распознаётся по геометрии 512-байтного сектора, сигнатуре 55h AAh и числу кластеров 4085–65524, а не по строке `FAT16`. Поддерживаются одна или две FAT, несколько резервных секторов и многосекторные кластеры размером до 32768 байт. Адресация ограничена 16-битным LBA и 16-битной физической ёмкостью драйвера; разделы пока не поддерживаются.

При монтировании проверяются BPB_Media и первые две служебные ячейки FAT; неправильный BPB даёт DOS_ERR_UNSUPPORTED, повреждённый заголовок FAT — DOS_ERR_CORRUPT, отказ чтения — DOS_ERR_IO. Старшие два бита FAT[1] принимаются как флаги clean/error, а не как часть обязательного значения FFFFh. Их обновление при записи пока не реализовано. Ненулевой FstClusHI у найденного файла отклоняется в обеих сборках ядра.

Корень имеет фиксированный размер и общий ограниченный курсор; подкаталог обходит тот же код по цепочке кластеров. При замене маркера конца 00h создание файла переносит его на следующую запись, в том числе через границу сектора; содержимое после прежнего конца не считается файлами. Повторное использование E5h сохраняет следующие живые записи. Первое API каталогов описано ниже; LFN пока нет. Форматирование и сборщик образов по-прежнему создают малые MXOS-256; стандартное форматирование FAT16 — отдельный следующий шаг. COM/EXE хранят адрес загрузки в собственном заголовке, стандартные поля FAT для адреса больше не используются.

## Каталоги: первый этап

`MXOS_DOS_DIRECTORY` через MXCALL находится в резидентном ядре: общий обход нужен также загрузке и сохранению файлов. A выбирает операцию, CF/A возвращают числовой статус DOS; AF/BC/DE/HL считаются разрушенными. Служба поддерживает пока только встроенный FAT-том. Корень обозначается кластером 0. Для каждого диска сохраняется свой текущий каталог; после замены носителя сохранённые номера каталогов недействительны.

| A | Операция | Параметры и результат |
|---|---|---|
| 0 `DIR_OP_GET` | Получить текущий каталог | DE=кластер, 0 для корня |
| 1 `DIR_OP_SET` | Восстановить контекст | DE=номер каталога, ранее полученный GET на этом томе; это не проверка произвольного кластера на принадлежность каталогу |
| 2 `DIR_OP_CHDIR` | Перейти по пути | HL=полный буфер `MAX_PATH` байт с ASCIIZ-путём; буфер не изменяется |
| 3 `DIR_OP_LIST` | Список файлов и каталогов | HL=буфер FILE_INFO, DE=ёмкость, BC=начальный индекс; DE=общее число записей, как у fileList; . и .. включаются |
| 4 `DIR_OP_GETCWD` | Текстовый путь | HL=MAX_PATH-буфер, ASCIIZ |
| 5 `DIR_OP_COMMAND` | CD/CHDIR | HL=команда; A=FFh/CF=0, если не распознана |
| 6 `DIR_OP_RESOLVED` | Временный контекст имени | DE=каталог, разрешённый последним fileNamePrepare; не восстанавливает сохранённый CWD |

`MAX_PATH=128` включает завершающий 0. Буфер выделяет вызывающая программа; в DOS нет массива строк путей для каждого диска. Максимальная длина строки — 127 байт. Путь без начального разделителя относительный, `/` или `\` в начале выбирает корень; разделители равнозначны, поддерживаются `.` и `..`. Компоненты имеют формат 8.3, длинное имя, запрещённый символ и отсутствие терминатора возвращают DOS_ERR_ARGUMENT, отсутствующий компонент — DOS_ERR_NOT_FOUND, обычный файл вместо каталога — DOS_ERR_ACCESS. Допускается префикс диска, например H:\Almaz\STD. При отказе CHDIR сохраняются прежние диск и каталог.

После CHDIR обычные компактные файловые операции и FileHandle работают в выбранном каталоге; они используют общий обход, без второго алгоритма поиска/создания. Прежний fileList выдаёт только файлы; NC использует DIR_OP_LIST с каталогами. Общий обход ограничен числом кластеров тома, BAD/недопустимая ссылка и цикл возвращают DOS_ERR_CORRUPT. Открытый FileHandle сохраняет сектор и смещение своей записи и может закрываться после смены текущего каталога.

Системные NC.COM, шрифт и CLI.EXT открываются из корня A: независимо от пользовательского каталога. Подготовка имени принимает явный корень `A:\ИМЯ.EXT`, не меняя сохранённый текущий каталог диска; fileNamePrepare разбирает также вложенный полный путь, сохраняя исходную строку и возвращая HL у разделителя после имени. CF сообщает ошибку пути; вызывающий обязан проверить CF до файловой операции. Временный контекст родителя действует до выбора диска или вызова MXOS_DOS_DIRECTORY; DIR_OP_RESOLVED позволяет получить его без сброса. FORMAT после записи перемонтирует том и выбирает корень.

MKDIR/RMDIR реализованы в DOS. При заполнении подкаталога DOS добавляет нулевой кластер к его FAT-цепочке; корень остаётся фиксированным и возвращает DOS_ERR_DIR_FULL. C SDK предоставляет MAX_PATH-буфер, CHDIR и список; `fopen` принимает полный или относительный путь через OPEN_PATH.

GETCWD (A=4, HL=буфер MAX_PATH) возвращает абсолютный ASCIIZ-путь с буквой диска и обратными косыми чертами, например `H:\Almaz\STD`. Реализация находится в DOS и восстанавливает имена по цепочке `..`, не меняя текущий каталог. Неумещающийся путь возвращает DOS_ERR_ARGUMENT. Буфер при ошибке не содержит гарантированного полного пути.

COMMAND (A=5, HL=строка команды) обрабатывает CD и CHDIR через тот же CHDIR; без аргумента печатает текущий путь. A=FFh, CF=0 означает неизвестную встроенную команду; иначе A/CF задают статус DOS. Сервис используется NC и fileExec, поэтому доступен BAT через файловое ядро DOS. Расположение BAT не меняет рабочий каталог команд; сценарий должен выполнить CD либо использовать абсолютные пути. Самостоятельный CLI.COM использует тот же обработчик.

Для файлов и каталогов действует единый формат 8.3: восемь символов имени и необязательные три символа расширения; 11 подряд не допускаются. Входные пути допускают оба разделителя `/` и `\`, включая смешанные пути. GETCWD, NC и поставляемые BAT формируют `\`. EXE, COM, SYS и BAT сохраняют привычные расширения; это не обещание двоичной совместимости с MS-DOS.

FILE_COPY_REQUEST занимает 86 байт: sourceDirectory по смещению 80 и destinationDirectory по смещению 82 — 16-битные контексты каталогов соответствующих дисков, 0 означает корень. Они обязательны и позволяют копировать между двумя каталогами одного диска. Поле onExists по смещению 84 содержит адрес обработчика совпадений (0 — отказ EXISTS). Обработчик получает A=FAR-банк DOS и HL=адрес FILE_DESCRIPTOR назначения; общий переходник source/common/copyConfirmLocal.inc копирует дескриптор на локальный стек перед вызовом диалога. Обработчик возвращает A=0 для пропуска, A=1 для замены, A=2 для Yes to all или A=3 для No to all, CF=0; CF=1 отменяет операцию. Обработчик может выводить интерфейс и читать клавиатуру, но не вызывает файловые службы DOS/CLI. Все программы и C-запросы необходимо пересобрать с текущим mxos.inc/SDK.

## Ошибки файловых операций

CF=1 означает отказ. Прежние результаты A отдельных вызовов сохранены; подробную причину возвращает `MXOS_DOS_GET_ERROR` через MXCALL: A=код, CF=1 при ненулевом коде, BC/DE/HL сохраняются. Чтение причины её не сбрасывает. Новая операция через диспетчер томов сбрасывает прежнюю причину; успешный возврат очищает её. При копировании причина сохраняется через очистку назначения и восстановление диска. Ядро не печатает обязательное сообщение и не спрашивает о повторе: это политика NC/CLI.

| Код | Константа | Причина |
|---:|---|---|
| 0 | — | Успех |
| 1 | DOS_ERR_IO | Отказ физического чтения/записи/барьера |
| 2 | DOS_ERR_NOT_FOUND | Файл не найден |
| 3 | DOS_ERR_EXISTS | Назначение существует |
| 4 | DOS_ERR_FULL | Недостаточно кластеров |
| 5 | DOS_ERR_DIR_FULL | Корневой каталог заполнен |
| 6 | DOS_ERR_ACCESS | Запрещено атрибутами |
| 7 | DOS_ERR_ARGUMENT | Недопустимый аргумент |
| 8 | DOS_ERR_CORRUPT | Недопустимая цепочка кластеров |
| 9 | DOS_ERR_NO_DRIVER | Нет физического драйвера |
| 10 | DOS_ERR_UNSUPPORTED | Неподдерживаемый/некорректный формат тома |
| 11 | DOS_ERR_BAD_IMAGE | Некорректный исполняемый образ (DOS4000) |
| 12 | DOS_ERR_CANCELLED | Операция отменена |
| 13 | DOS_ERR_WRITE_PROTECTED | Драйвер тома сообщает, что запись недоступна |

Пользовательские сообщения DOS хранит `A:\ERRORS.DAT`. Сборщик образа создаёт его через [build-error-strings.py](../../scripts/build/build-error-strings.py). В начале 14 записей по три байта, индексированных кодом DOS. Каждая содержит 16-битное смещение от начала файла в little-endian и однобайтную длину (1–31). Затем идут строки ASCII без NUL. Код 0 используется для неизвестных ошибок. `dosErrorText` из [errors.inc](../include/errors.inc) принимает код в A, возвращает в HL указатель на локальную строку с NUL и сохраняет BC/DE. Файл открывается только при выводе сообщения. При ошибке чтения программа показывает числовой код, например `DOS error 01h`.

Dirty-флаг кэша снимается только после успешной записи; неудачное вытеснение не загружает другой сектор поверх несохранённого. Неудачный flush запрещает переключение диска; повторный flush может завершить запись. Это не журналирование: уже записанные секторы не откатываются. Курсор корня/подкаталога общий для поиска, списка и создания; корень ограничен точным числом записей и корректно работает с неполным последним сектором. Обычный список и поиск файлов пропускают LFN, метки и каталоги; MXOS_DOS_DIRECTORY предоставляет CHDIR и список с каталогами. Счётчик свободных кластеров не включает резерв и запас FAT. `MXOS_DOS_FILE_GET_SET_ATTR`: C=1 устанавливает атрибуты из B; A возвращает атрибуты, CF сообщает ошибку сохранения. DEBUG и очистка копии используют тот же контракт.

## Команды, BAT и общие файловые операции

Парсер и исполнитель BAT резидентны в DOS; CLI.COM и NC используют их через MXCALL. Сценарии читаются порциями, состояние вложенного BAT хранится в собственном кадре; выполняемые программы не затирают буфер сценария. Подробности — в разделе «Потоковые BAT» выше и [CLI](../cli/README.md).

Метаданные, каталоги, перечисление, COPY/MOVE/DEL/MKDIR и запуск программ имеют отдельные операции группы DOS. Они не являются альтернативными интерфейсами чтения/записи файла: данные передаются через FILEHANDLE. Действующие номера операций и структуры определены в mxos.inc и syscall-ids.inc; адреса реализаций не являются ABI. COPY/MOVE и рекурсивные операции выполняет FILEOPS, перечисление с масками — ENUM; интерфейс и подтверждения принадлежат вызывающей программе.

## Общие ассоциации файлов

MXOS_DOS_FILE_ASSOCIATION ищет расширение в системном CLI.EXT независимо от оболочки. Формат строки — расширение, пробел, команда и перевод строки; регистр расширения не учитывается. Результат применяется исполнителем команд до запуска совместимого приложения через RUN. COM/EXE с корректным нативным заголовком и флагами MAIN/BANK/DOS запускаются ядром напрямую; ассоциация используется для нераспознанного нативного контейнера.

## Файловый слой и физические драйверы

DOS использует встроенное FAT-ядро. Реестр физических драйверов A:–H: хранит службы блокового обмена, геометрию и описание носителя; он не является таблицей файловых операций. FILEHANDLE, каталоги и метаданные используют общие FAT-примитивы. Таблица альтернативных файловых систем, её регистрация и контексты удалены: реальных реализаций кроме FAT в репозитории не было, а FILEHANDLE и каталоги их не поддерживали.

Создание записи и предварительное выделение цепочки — общий внутренний примитив FILEHANDLE, MKDIR и FILEOPS. Он не пишет тело файла. Старые whole-file reader/writer, зарезервированные обработчики адреса загрузки в FAT и внешний CREATE_PREPARE удалены. Целые файлы читают и записывают библиотечные обёртки FILEHANDLE. Монтаж/сброс тома и регистрация физических драйверов сохранены; байты существующих носителей этим рефакторингом не меняются.

## Передача данных и запуск контейнеров

FILEHANDLE ограничивает чтение размером файла, сохраняет частичный результат при отказе и позволяет повторить передачу. FLUSH/CLOSE завершают запись данных, метаданных и физические барьеры. Полная проверка записи в DISKBEN выполняется на уровне приложения; драйверная проверка B=5 остаётся отдельной посекторной операцией.

COM и EXE используют общий 32-байтный заголовок v2 с адресами загрузки/входа, размером, флагами исполнения и контрольными суммами. Нативный загрузчик DOS обслуживает MAIN/BANK/DOS; RKS и режимы совместимости принадлежат RUN. Точный размер файла хранится в DIR_FileSize. Сам формат контейнера не означает совместимости с MS-DOS; см. [RUN](../run/README.md).

## Поиск системных команд

Исполнитель DOS разбирает аргументы, встроенные команды и пути, ищет программы по текущим правилам PATH и запускает их без зависимости от NC. CLI.COM, NC и BAT используют одну реализацию; правила и примеры приведены в [CLI](../cli/README.md). После загрузки отдельной программы исходный рабочий каталог сохраняется для её относительных аргументов.

## Внутренний поток FAT

`fatStream` — закрытый примитив ядра и FILEOPS: обход цепочки, неполные сектора и пакетные полные секторы. Отдельного публичного FILESTREAM и JMP C8D2h больше нет. Для чтения и записи приложения используют только MXOS_DOS_FILEHANDLE; внутренний курсор остаётся частью FILE_HANDLE.

## Логические секторы (04.11.2026)

Файловые функции получают геометрию из BPB. Поддерживаются логические
секторы 128/256/512 байт и кластеры из нескольких секторов (степень двойки,
до 32768 байт на кластер). Физический блок задаётся отдельно при установке
драйвера. Логический сектор может равняться блоку либо состоять из нескольких
блоков; сектор меньше аппаратного блока отвергается, скрытого RMW нет.
Существующие драйверы и образы остаются 256-байтными.

Физический драйвер и его геометрия регистрируются через службу DOS. Метаданные B=3 берутся из реестра; B=1/2 передают аппаратный блок, B=4 выполняет барьер. Секторный слой переводит логический LBA в аппаратные блоки. RAW-доступ требует предварительного FLUSH и перемонтирования после внешней записи, чтобы не оставлять несогласованные копии в кэше. Размер и доступность RAW-буфера обеспечивает вызывающий.

Общий кэш занимает 8192 байта; неполные секторы используют отдельный буфер 512 байт. Полные выровненные сектора идут напрямую, если нет более новой копии в кэше. При попадании используется актуальная копия, включая грязную. Запись и CLOSE сохраняют метаданные и выполняют необходимые барьеры.

Для малых нестандартных томов требуются OEM-метки `MXOS128 ` / `MXOS256 `.
512-байтный том требует подписи 55AA и числа кластеров FAT16, поддерживается
одна или две FAT с зеркалированием записи. Старые образы не преобразуются.
Свободная запись FAT — 0000h; BAD — FFF7h; EOC — FFF8h..FFFFh (при создании
записывается FFFFh). Ссылки 0001h и FFF0h..FFF6h не являются кластерами данных.
Полное чтение обычного файла и загрузка образа проверяют конец цепочки;
Внутренний fatStream не знает размера файла; FILEHANDLE ограничивает чтение размером из каталога.

Что ещё требуется для полноценной совместимости с MS FAT16:

- 32-битные LBA/ёмкости и смещения разделов: сейчас максимум 65535 логических
  секторов, TotSec32 принимается только при нулевом старшем слове; MBR не разбирается.
- Политика корректных дат/времени, clean-shutdown/hard-error флаги FAT[1],
  проверки восстановления после отказа питания и совместимости с внешним fsck.
- Форматирование стандартных носителей: FORMAT пока создаёт прежний MXOS-256.
  Реальные драйверы дискет/SD и отдельный вариант AT29C010 с блоком 128 байт
  пока не реализованы; новый секторный слой проверен с моделями таких драйверов.
- Секторы 1024/2048/4096 байт, допускаемые FAT, пока не поддерживаются.

FAT12 для малых стандартных носителей — отдельный следующий этап, не часть
этого изменения. KOI-8 в именах остаётся соглашением MXOS; кодировка имён
при обмене с DOS/Windows требует отдельного решения. LFN не реализован,
его записи пропускаются; отсутствие LFN само по себе не мешает FAT16 с 8.3.

RKS принадлежит RUN: он разбирает заголовок и хвост, а общее тело загружается через FILEHANDLE. Для открытия разрешённого имени без повторного разбора пути используется OPEN_AT с явно сохранённым родителем.

Ускорение после локализации регрессии (04.11.2026): внутренние поиски,
перечисление и выбор свободной записи корня получают сектор один раз и
проходят его записи по указателю. Во время такого прохода между двумя
fatDirNext нельзя выполнять другие операции с секторным кэшем; это
внутренний контракт трёх циклов DOS, отдельного публичного итератора нет.
На границе сектора адрес заново берётся из кэша. Точный предел RootEntCnt
и неполный последний сектор, фильтры 00h/E5h/LFN/меток сохранены.

## Открытые файлы

`MXOS_CALL MXOS_DOS_FILEHANDLE`: A — операция, HL — адрес 64-байтного FILE_HANDLE. AF/BC/DE/HL разрушаются; CF=1 и A=код DOS при ошибке, A=0/CF=0 при успехе. Все остальные входы и результаты находятся в объекте вызывающей программы. Вызовы нереентерабельны; активным остаётся диск файла. Реализация обслуживает встроенное FAT-ядро.

| Смещение | Размер | Поле |
|---|---:|---|
| 0 | 32 | Копия FILE_DESCRIPTOR; до OPEN задаются первые 11 байт имени 8.3 с пробелами, байты KOI-8 сохраняются |
| 32 | 4 | Текущая позиция, little-endian |
| 36 | 4 | Внутренний курсор «кластер + смещение» |
| 40 | 1 | Диск 0–7 |
| 41 | 1 | Режим: READ=1, WRITE=2, CREATE=4, TRUNCATE=8, APPEND=16 |
| 42 | 1 | Состояние: 46h — открыт, 0 — закрыт |
| 43 | 1 | Накопленный код ошибки; очистить явно, как clearerr |
| 44 | 1 | EOF; SEEK и clearerr сбрасывают |
| 45 | 4 | Внутренние сектор и смещение записи каталога |
| 49 | 2 | NEAR-адрес буфера READ/WRITE либо ASCIIZ-пути OPEN_PATH |
| 51 | 2 | На входе число байтов; на выходе фактически передано, включая частичный отказ |
| 53 | 4 | Signed int32 смещение SEEK; рабочее поле изменяется вызовом |
| 57 | 1 | Начало SEEK: SET=0, CUR=1, END=2 |
| 58 | 5 | Внутреннее состояние цепочки, резерв и действительность курсора |
| 63 | 1 | Код операции для C-переходника; процессорный ABI принимает его в A |

Перед OPEN обнулить объект и заполнить имя, диск и режим. Повторный OPEN открытого объекта запрещён; CLOSE при ошибке оставляет его открытым для повторной попытки. Нельзя одновременно изменять один файл через несколько объектов, удалять/переименовывать открытый файл, менять его том или извлекать носитель. Дескрипторы разных файлов можно чередовать; постоянные данные каждого находятся в самом FILE_HANDLE, а не в общем кэше.

| A | Операция | Поведение |
|---:|---|---|
| 0 | OPEN | Открыть; CREATE разрешает новый файл, TRUNCATE обнуляет существующий, WRITE проверяет Read-only |
| 1 | READ | Не читает за размер файла; короткое чтение/чтение за EOF выставляет EOF без ошибки |
| 2 | WRITE | Перезапись и расширение с выделением кластеров; APPEND перед каждым непустым запросом выбирает конец |
| 3 | SEEK | 32-битный SET/CUR/END, отрицательная итоговая позиция и переполнение отвергаются; само перемещение не выделяет кластеров |
| 4 | FLUSH | Сохранить данные/FAT, затем первый кластер и размер в каталоге, выполнить физические барьеры |
| 5 | CLOSE | FLUSH для записи и закрытие только при успехе |
| 6 | OPTIONS | Политика проверяющей записи и распределения кластеров |
| 7 | OPEN_PATH | Полный/относительный ASCIIZ-путь в FH_BUFFER, режим в FH_MODE |
| 8 | OPEN_AT | Имя 8.3, FH_DRIVE и кластер родителя в младшем слове FH_SEEK |

Внешние объекты и буферы должны заканчиваться не выше начала банкового сегмента IO.SYS (F040h); внутри этого диапазона вызывающий отвечает за владение памятью. Нулевой READ/WRITE не обращается к буферу. Буфер и объект не пересекаются; буфер не должен захватывать активные кадры BIOS/DOS. Размер запроса ограничен 16 битами и непрерывной доступной памятью, размер и позиция файла — 32 битами. Фактическая ёмкость тома по-прежнему ограничена нынешним 16-битным LBA.

После SEEK за EOF запись выделяет промежуточные кластеры; содержимое промежутка не определено, как допускает интерфейс C. Это не POSIX-гарантия нулевого заполнения. Незаписанные выделения при заполнении тома освобождаются; частично переданные данные и позиция сохраняются. Аппаратные ошибки не обеспечивают транзакционный откат. Размер публикуется при FLUSH/CLOSE, поэтому CLOSE обязателен и его результат нужно проверять.

Курсор сохраняется между последовательными запросами. После SEEK цепочка проходится от начала; обход ограничен числом кластеров тома. Повреждённая/BAD/циклическая цепочка возвращает `DOS_ERR_CORRUPT`. Полный файл проверяется на корректный EOC. Секторный перенос использует общий fatStream, без повторной проверки буферов на каждом кластере; выделение использует штатные подсказки распределителя.

Адаптер C находится в [sdk](../../sdk/README.md). Проверки ядра: `scripts/emu80/check-banked-kernel.py`, `check-driver-registry.py`, `check-bootstrap.py`; CPU-проверки открытых файлов и SDK: `scripts/tests/check-file-handle.py` и `check-file-stdlib.py`.

Общие команды, QUERY, MOVE и атрибуты описаны в [документации CLI](../cli/README.md). Интерфейсные циклы CLI.COM и NC остаются обычными загружаемыми программами.

Графическая библиотека находится в source/include/ui.inc и включается непосредственно в программу MAIN или MAIN DLL. NC использует локальные процедуры uiDraw, uiInverseRect, uiToolbar и uiCopyRect.

Подтверждение замены и наблюдение за изменениями передаются обработчиками приложения: строки диалогов и тексты ошибок в модуль не включены. Контракты `CLI_OP_COMMAND`, `CLI_OP_OBSERVER` и время жизни обработчиков описаны в [CLI](../cli/README.md).

## Службы DOS-DLL

Единая арена 9800h–B4FFh имеет 7424 байта. ENUM начинается с 9800h, FILEOPS — с A000h, установщики прижаты к B500h; это адреса согласованной сборки, а не публичные входы. MODULE_LOAD регистрирует заявленный интервал кода и рабочей памяти из заголовка. MANAGED допускает вытеснение только неактивных CACHEABLE DLL и внутреннего кэша; активная операция, её активные потомки и закреплённая DLL защищены. Непересекающиеся службы сосуществуют. Выше арены находятся кадры BAT, кэш и стек; данные кэша больше не разделяют арену.

## Прямые полные секторы

Загрузчик и C stdio используют этот путь автоматически, без RAW_IO B=6 в приложении. Нативный RUN передаёт управление FILE_EXEC_NATIVE; FILE_EXEC/MODULE_LOAD задают kdPage банком назначения, устанавливают EXEC-профиль до чтения тела и включают kdFarActive. imageLoad читает через fatStream, полные секторы доходят через ksSector/klBlock до локального драйвера. Заголовок контейнера и неполные края остаются обычными частичными чтениями. Контрольная сумма считается в банке назначения. RKS-путь RUN также использует FILEHANDLE.

mxos_fread/mxos_fwrite проходят через FILEHANDLE → fileHandle → fatStream. Внешний адаптер переносит объект FILE_HANDLE и параметры, а полные секторы данных передаёт прямо в буфер вызывающего банка; неполные фрагменты обслуживает частичный кэш DOS. Для DOS-клиента используется локальный поток. FAT, каталог, распределение кластеров, права, длина файла и обработка ошибок остаются обязанностью файлового ядра.

Файловый путь ещё сохраняет диспетчеризацию: DOS ведёт цепочку, но обычные блоки B: и чтение A: в DOS/BANK или нижнюю MAIN передаёт напрямую через bankCopySector. Callback на каждый сектор для этих маршрутов не нужен; COPY остаётся активным между секторами, включая локальное чтение метаданных DOS. Чтение A: в верхнюю MAIN сохраняет callback ради более быстрого отображённого memcpy; запись A:, проверяющая запись B: и клиентский обмен H: пока также используют callback. Поэтому устранение секторного staging не делает fread/fwrite равными прямому RAW-циклу по заранее подготовленному списку. RAW_IO B=6 предназначен именно для доверенной физической серии; обходить через него файловые операции приложения не требуется.

Для текущих физических драйверов A:/B:/H: полные 256-байтные блоки RAW_IO, SECTOR_IO, FILEHANDLE и файловой загрузки передаются непосредственно в память MAIN/DOS/EXEC-клиента. Логический сектор 512 байт поверх 256-байтного драйвера разбивается на два прямых физических обмена. Объекты запросов, курсоры и метаданные остаются в DOS; содержимое полных клиентских секторов не проходит через KD_DATA. Геометрия берётся из BPB и реестра драйверов, формат тома не меняется.

Для A: чтение идёт локальным CPM16 из ROM-окна, запись — через MAINIO прямо из банка инициатора; B: использует FAR-копирование с банком RAM-диска; H: выполняет установленную копию ROM/FLASH/FLASHFST в банке клиента. У каждой страницы своя отметка установки H:. Новый профиль EXEC и замена драйвера заставляют обновить копию. Незавершённые записи FlashFst завершаются при передаче устройства другой копии и перед освобождением банкового модуля.

Неполный сектор остаётся в кэше DOS для сохранения остальных байтов. Если последующий полный обмен встречает изменённую частичную копию, она сначала сохраняется, затем инвалидируется; полный сектор передаётся напрямую. B=5 выполняет запись, чтение и сравнение с временным буфером на стеке соответствующего клиента, требуя не менее 320 свободных байт стека. Для FAT/каталогов и копирования файлов средствами самой DOS её память является собственным буфером операции.


## Проверка FILEHANDLE и размещение кластеров

FILE_MODE_VERIFY (20h) требует посекторной записи с проверкой B=5 для данных данного файла. Флаг требует WRITE; если физический драйвер не сообщает DISK_CAP_VERIFY, OPEN возвращает DOS_ERR_UNSUPPORTED до создания или усечения файла. Проверка выполняется сразу после записи полного физического блока. Неполный логический сектор сначала собирается в отдельном слоте кэша, затем сохраняется и проверяется целиком; dirty очищается только при успехе. Ошибка B=5 возвращается как ошибка I/O, а не как успешная отложенная запись. FAT, каталог и другие метаданные эта настройка не переводит в B=5.

Общая настройка DOS_IO_VERIFY_FILES (бит 0) включает тот же путь для всех запросов WRITE через FILEHANDLE на драйверах с DISK_CAP_VERIFY, включая уже открытые файлы. Для остальных драйверов сохраняется обычная запись. По умолчанию настройка выключена; она хранится в DOS до перезагрузки ядра и не записывается на диск. Внутренние загрузчики задают собственную политику проверяющей записи. Отдельный CONFIG.SYS, команда AUTOEXEC и ключ установщика драйвера пока не добавлены.

Настройка доступна через существующий ABI MXOS_DOS_FILEHANDLE, A=FILE_OP_OPTIONS (6), HL=64-байтный FILE_HANDLE. FH_ORIGIN=0 читает текущие флаги в FH_COUNT, FH_ORIGIN=1 обменивает FH_COUNT на прежние флаги. Установить можно только бит DOS_IO_VERIFY_FILES; неизвестные биты и команды отклоняются без изменения настройки. Открытый файл, корректный FH_DRIVE или смонтированный том для OPTIONS не требуются; объект по-прежнему должен находиться в допустимой памяти вызывающего. Вызов из MAIN/EXEC переносит весь объект обычным банковым переходником.

```asm
    ld a,1
    ld (options+FH_ORIGIN),a
    ld hl,DOS_IO_VERIFY_FILES ; 0 отключает общую проверку
    ld (options+FH_COUNT),hl
    ld hl,options
    ld a,FILE_OP_OPTIONS
    MXOS_CALL MXOS_DOS_FILEHANDLE
    ; При CF=0 FH_COUNT содержит прежнюю настройку для восстановления.
options: DS FILE_HANDLE,0
```

FILE_MODE_SCATTER (40h) разрешён только с WRITE и меняет поиск новых кластеров данного файла: LFSR выбирает начальную позицию, после чего общий распределитель ищет свободную запись FAT. Занятые кластеры не перезаписываются, полный том возвращает обычную ошибку FULL. FH_ALLOC_SEED (60..61) хранит состояние LFSR, OPEN начинает с ACE1h. Размер FILE_HANDLE остаётся 64 байта: использованы прежние два резервных байта. Существующая цепочка и формат FAT не меняются; стандартные номера кластеров, EOC и записи каталога сохраняются. В текущем формате поддерживаются FAT16 и явные расширения MXOS для 128/256-байтных секторов; FAT12 этим изменением не добавляется.


## Расширенная временная DOS-DLL

При v_batDepth=0 временная DLL может заимствовать B500h–CB7Fh и занимать диапазон вплоть до CB80h. Пока DLL владеет этой памятью, BAT не запускается. RETAIN разрешён только без заимствования BAT. Таблица кэша CC00h–CDFFh, сам кэш CE00h–EDFFh и стек EE00h–F03Fh в арену никогда не входят. Буфер проверки записи находится в 8B00h–8BFFh отдельно от неполного сектора 8900h–8AFFh.

## Получение списка каталога

DIR_OP_LIST выполняется одним запросом клиента. Общий FAT-курсор загружает сектор каталога один раз и обходит его записи по указателю; корень ограничен остатком RootEntCnt, подкаталог — геометрией и проверенной цепочкой кластеров. FILE_INFO собираются в DOS-пачке KD_DATA на 4096 байт. Полные пачки и последняя пачка с FFh передаются клиенту через kdStore / bankCopyFar; для панели из 255 записей весь результат помещается в одну пачку 4081 байт. Прямого чтения FAT-записей в буфер NC и внешнего запроса на каждый файл нет.

Skip и ёмкость списка обслуживаются убывающими счётчиками без сравнения пары U16 для каждой записи; после исчерпания ёмкости обход продолжается для возврата полного числа записей. Ёмкость 0 возвращает только FFh и общий счётчик. Копирование компактного описателя развёрнуто, преобразование первого 05h в E5h и формат FILE_INFO сохранены. Эти изменения не меняют формат FAT, фильтрацию, порядок записей и банковый протокол.


## Пакетный обмен полными секторами

FILEHANDLE и внутренние загрузчики, использующие общий fatStream, собирают список полных 256-байтных секторов перед физическим обменом. DOS_IO_BATCH_SECTORS в mxos.inc выбирает 16, 32 или 64 сектора, по умолчанию 32 (8 КиБ). FAT обходится штатным курсором, с прежней проверкой кластеров и согласованием изменённых строк кэша; новый формат цепочки или отдельный обход FAT не вводится. Подготовка остаётся частью времени файловой операции.

Пакет и временный курсор занимают 8C00h–8C97h в банке DOS. Заголовок содержит диск, физическую операцию 1/2/5, NEAR-адрес буфера и число секторов; далее идут слова LBA. Поля адресов и LBA little-endian. MEM_BATCH_ENTRY — внутренний доверенный вход: он получает A=банк пакета, DE=его адрес, BC=размер 6+2*N, возвращает BC=число успешно переданных секторов и CF/A=ошибку. Исполнитель копирует список на свой локальный стек и проходит по нему через LOCAL_BLOCK_ENTRY. Для клиента MAIN/EXEC нужен один bankCall на пачку, для буфера DOS вызов локальный. Драйвер H: и владелец конвейера выбираются один раз перед пачкой; промежуточный FLUSH не добавляется.

Для чтения A: в нижнюю MAIN и банки, а также чтения/обычной записи B:, последовательные LBA склеиваются в один CPM32-перенос. Разрывы цепочки, границы 32-КиБ окна A: и 64-КиБ страницы B: разделяют участки. Верхняя MAIN сохраняет отображённый near-путь A:. Проверяющая запись B=5 выполняется локально по секторам через единый вход драйвера.

Неполный сектор, геометрия с логическими секторами больше 256 байт и остальные устройства сохраняют прежний путь. При ошибке передачи DOS восстанавливает курсор до фактически переданного префикса, повторно проходя только его метаданные без повторного физического обмена. Ошибка FAT после подготовленных секторов возвращается после передачи этого корректного префикса. FAT и каталог сбрасываются существующим механизмом завершения операции; пакетизация не меняет формат носителя и правила сохранения метаданных.


FILEHANDLE передаёт запрос READ/WRITE общему потоку целиком, а не обрезает его до одного кластера. При WRITE подготовка пачки расширяет цепочку штатным распределителем, включая FILE_MODE_SCATTER; размер файла публикуется по фактически записанным данным. При частичном отказе неиспользованный новый хвост освобождается, записанный префикс остаётся, курсор помечается для повторного поиска. Неполный последний сектор сохраняет прежний путь через отдельный буфер кэша. Новый буфер в MAIN для этой оптимизации не выделяется.

## Подготовка файлового обмена и обход каталогов

Список LBA для пачки FILEHANDLE строится прямым проходом по FAT-цепочке, без повторного входа в общий потоковый обработчик для каждого сектора. Курсор и число выполненных байтов фиксируются после обмена; ошибка планирования или физического драйвера сохраняет частичное выполнение. Неполные сектора и неподходящая геометрия используют обычный потоковый путь. Грязная копия сектора в кэше сохраняется перед прямым обменом и инвалидируется.

Общий обход каталога используется списком файлов и поиском имени: фильтрация выполняется внутри загруженного сектора, а глобальный курсор обновляется при выдаче записи или переходе к следующему сектору. Поиск сначала сравнивает первую букву, затем полное имя 8.3 без учёта регистра. Сохраняются обработка 00h/Е5h/05h, атрибутов, границ фиксированного корня и FAT-цепочки подкаталога. Счётчик корня означает число ещё не загруженных записей; оставшиеся записи текущего сектора учитываются отдельно.

В дополнение к последнему сектору кэш помнит четыре недавно найденных заголовка. Это только ускоритель поиска: при каждом обращении проверяются фактические LBA и метка диска/размера сектора. После вытеснения или инвалидации старый указатель не считается попаданием; при промахе выполняется полный поиск по кэшу. Формат тома и политика сброса не меняются.

## Загружаемый FILEOPS

COPY, междисковый MOVE и обход дерева находятся в FILEOPS.DLL. Прежние синхронные вызовы сохранены; публичный FILEOPS позволяет выполнять операцию шагами с подтверждением и отменой, а NC рисует прогресс самостоятельно. В DOS остаются примитивы файлов/каталогов, метаданный MOVE внутри тома, диспетчер и проверка пересечений. Общий кэш модулей не вытесняет активный код. После kernelEnd оставлен резерв роста 512–1024 байта до буфера 7000h; службы и установщики используют общую арену 9800h–B4FFh. Реестр драйверов и кэш подготовленного H: находятся вне арены.

## Резидентные команды и загружаемое перечисление

Парсер, диспетчер коротких команд и чтение BAT остаются в DOS. COMMAND.DLL не загружается: AUTOEXEC и каждая следующая строка сценария доступны без вытеснения парсера. CLI.COM содержит интерфейс ввода в MAIN. COPY/MOVE вызывают общий FILEOPS, MKDIR создаёт недостающие префиксы через FILEOPS; создание одного каталога и изменение текущего каталога остаются примитивами DOS. Отдельные COPY.COM/DIR.COM/MKDIR.COM для этих команд не нужны.

DIR и COPY/MOVE с маской используют общий ENUM.DLL через публичный пакетный API MXOS_DOS_ENUMERATE. ENUM собран с 9000h, FILEOPS — с 9800h в общей арене 9800h–B4FFh, поэтому активный курсор не мешает копированию очередного совпавшего файла. Маски * и ? применяются к последнему компоненту; DIR с -S обходит дерево и выводит полные пути. Для COPY/MOVE с маской назначением служит существующий каталог. DEL/ERASE рекурсивно удаляют файлы и каталоги через общий FILEOPS; текущий каталог и его предки защищены. Подробный контракт и ограничения — [ENUM.DLL](../enumerate/README.md).

## Единый файловый интерфейс

Публичный обмен данными выполняется только через FILEHANDLE: OPEN=0, READ=1, WRITE=2, SEEK=3, FLUSH=4, CLOSE=5, OPTIONS=6, OPEN_PATH=7, OPEN_AT=8. OPEN_PATH получает ASCIIZ-путь в FH_BUFFER; OPEN_AT — имя 8.3, FH_DRIVE и кластер родителя в младшем слове FH_SEEK. После открытия чтение и запись больше не разрешают путь заново. Все NEAR-адреса принадлежат памяти вызывающего. Короткие пути читаются только до NUL, максимум 127 байт.

Загрузку и сохранение целого файла выполняют библиотечные обёртки [file-io.inc](../include/file-io.inc), в C SDK — mxos_file_read_all/mxos_file_write_all. FILE_PATH_IO — только локальный библиотечный запрос, не системный пакет. Редактор, DEBUG, CLI, NC, FONT, RUN и SortBen переведены на единый механизм. RUN сохраняет родительский каталог в запросе окончательной загрузки тела: чтение префикса и переключение накопителя не меняют источник.

Исторические файловые JMP MXOS и отдельные FILE_CREATE/FILE_LOAD/FILE_LOAD2/IMAGE_OPEN/FILESTREAM/FILE_LOAD_PATH/FILE_SAVE_PATH удалены из публичного ABI. Монитор-2-совместимые аппаратные точки BIOS сохранены. Метаданные, каталоги, перечисление, файловые операции и запуск приложений остаются отдельными службами; внутренние функции FAT и загрузчика не являются альтернативным публичным интерфейсом чтения/записи.
