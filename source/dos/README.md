# Файловые драйверы томов DOS

С 02.11.2026 штатный DOS использует встроенный побайтовый RAM-драйвер
с секторным адаптером. Быстрый R4 вынесен в отдельный
[RAMD.COM](../ramd/README.md), который запускается из штатного AUTOEXEC
и регистрирует драйвер B: и шаблон общего окна. Ручная установка также
доступна. C86Fh сохраняет сервисный
байтовый режим B=1 и восстанавливает установленный режим через B=0;
B=2 регистрирует резидентный 32-байтный шаблон по адресу HL.

Эксперимент с переносом стека под переменные BIOS отменён 01.11.2026.
Восстановлен `SP=DC00h` при `RAMD_BUFFERED=1` (стек `DA82h–DBFFh`)
и `SP=FFC0h` при `RAMD_BUFFERED=0` (стек `FF82h–FFBFh`). Начальный
`bios_getMemTop` снова возвращает `8FDEh`. Стек в верхней области сам по
себе не обеспечивает совместимость с STD: аппаратные сервисы и доступность
системных компонентов требуют отдельной проверки.

Подготовлено разделение файловых операций и физических блоков. Алгоритмы
существующего формата остались прежними; стандартная FAT16 и файловый драйвер
RAMFOS ещё не реализованы. Подробный [аудит FAT16](../../docs/FAT16-status.md)
содержит ограничения и очередность следующих изменений.

## Размещение кода и старый ABI

Старые фиксированные входы теперь содержат короткие JP на реализации;
таблица C800h также обращается непосредственно к реализациям. Внутренние
метки свободно перемещаются. C009h сохраняет установку SP до запуска ядра,
а соседние C18Fh/C190h сохраняют шестибайтную процедуру задержки: два JP
там не помещаются, изменение цикла нарушило бы прежние тайминги.
Таблица перехвата магнитофона C377h–C388h сохранена целиком.

`build: dos` и `build: OS` автоматически вызывают
`scripts/build/pack-dos.py` (нужен Python). Сначала SjASMPlus измеряет
блоки из `source/dos/layout.json`, затем размещатель заполняет свободные
окна между входами ABI, а остаток размещает за таблицей C800h. Для каждого
окна подбирается точная сумма размеров целых блоков; глобальный минимум
для всех окон этим алгоритмом не гарантируется. Порядок воспроизводим.

Генерируются `bin/DOS.layout.inc` и `bin/DOS.layout.json`; их не следует
редактировать. Окончательную сборку выполняет тот же SjASMPlus с `--i8080`:
все адреса разрешаются заново, готовый бинарник не патчится. Изменения
исходников, вложенных INCLUDE, манифеста и параметров автоматически
вызывают новое измерение. Повторная сборка без изменений пропускается.

Цепочки с переходом исполнения между файлами явно отмечены `chain`.
Размещатель сравнивает два плана: целые цепочки и разделённые части с
трёхбайтными обходными JP. Выбирается меньший образ; при равенстве —
меньше переходов. Разрывы допускаются только между отмеченными INCLUDE,
а не внутри произвольных инструкций, таблиц или копируемого RAM-драйвера.
Такой JP позволяет продолжить реализацию за старой заглушкой ABI.

Ассемблер проверяет адрес и длину заглушек, реальные размеры всех блоков,
границы окон и место под обходные JP. Таблица клавиатуры обязана целиком
находиться в одной 256-байтной странице: её индекс вычисляется без переноса
в старший байт. Копируемые драйверные блоки остаются неделимыми и сохраняют
собственные проверки длины и фиксированных точек входа.

Для отдельной конфигурации используется собственный комплект артефактов:

```powershell
python scripts/build/pack-dos.py --output bin/DOS-unchecked.sys --define=DISK_DRIVER_CHECKED=0
python scripts/build/pack-dos.py --output bin/DOS-split.sys --chains split
```

`--chains split` принудительно проверяет обходные переходы; штатный режим
`auto` в текущей сборке выбрал целые блоки. Итог: 6618 байт вместо 6624,
конец D9DAh, до DA00h свободно 38 байт. Основной выигрыш этого изменения —
автоматическое использование окон и независимость реализаций от старых адресов.
Там, где тело заменено новой заглушкой, вызов через старый адрес добавляет
10 тактов. Уже существовавшие переходы не удлинились; таблица C800h и
внутренние вызовы обращаются к телам напрямую. Для getch и printString
убраны прежние лишние JP.

Проверки: `scripts/tests/check-dos-layout.py` (включая намеренно ошибочные
сборки) и `scripts/emu80/check-dos-packing.py`. Отчёт:
`docs/dos/packing-001/RESULTS.md`.

## Три уровня

1. Прежние файловые точки DOS вызывают диспетчер из `volume.inc`.
2. Для каждой буквы A:–H: отдельно регистрируются файловая таблица и контекст.
   По умолчанию все буквы используют `fatVolumeDriver` — старый формат MXOS.
3. Физический драйвер выбирается прежним способом через `bios_installDriver`
   и `bios_diskDriver`. Регистрация файловой системы его не заменяет.

`fileSelectDrive` выбирает обе таблицы и вызывает mount файлового драйвера.
При повторном выборе той же буквы автоматического mount нет; для этого
предназначен отдельный вызов. Модуль использует физический ABI для блоков,
а не вызывает внутренние FAT-процедуры DOS.

## Регистрация и срок жизни

| Вход | Контракт |
|---|---|
| `bios_installVolume`, C890h | A=0…7, HL=таблица, DE=контекст (или 0). BC/DE/HL сохраняются. CF=1 при неверном индексе, заголовке или нулевом обработчике. Для активной буквы возвращается результат mount; регистрация при его отказе уже выполнена. |
| `bios_getVolume`, C893h | A=0…7 → HL=таблица, DE=контекст; BC сохраняется. CF=1 при неверном индексе. Диск не переключается. |
| `bios_mountVolume`, C896h | Повторно монтирует текущий том. BC/DE/HL сохраняются, AF возвращается от mount. |
| `bios_flushVolume`, C899h | Вызывает flush текущего тома; AF и остальные выходы определяет обработчик. CF=1 означает отказ. |

Таблица: `DB "FS",1,15`, затем 15 ненулевых адресов `DW`, всего 34 байта.
Ошибочный или неподдерживаемый вызов должен иметь настоящий обработчик отказа.
Версия и число обработчиков проверяются при регистрации; адреса и срок жизни
памяти гарантирует загрузившая модуль программа. Таблица не копируется.

Модуль и его контекст должны переживать вызовы NC и пользовательских программ.
Буфер копирования NC `0000h–7FFFh` для постоянного размещения не подходит.
В этой подготовке нет распределителя памяти и автоматической загрузки модулей.
После подмены ядра и возврата в MXOS модули/контексты регистрируются заново:
указывать на затёртый код прежнего ядра нельзя.

Перед заменой активного драйвера или сменой тома вызывающая сторона должна
закрыть операции и вызвать flush. Переключение пока сбрасывает старый секторный
кэш; его исторические ошибки записи перечислены в аудите. Это ещё не гарантия
безопасного сброса данных при ошибке устройства.

## Таблица обработчиков версии 1

Смещения считаются от первого слова после четырёхбайтного заголовка.
Файловые обработчики получают исходные регистры и флаги; их результат
возвращается вызывающей программе без преобразования.

| Смещение | Константа | Прежний контракт |
|---:|---|---|
| 0 | `VOL_MOUNT` | Монтировать текущий том; CF=1 при отказе. Входные регистры не заданы. |
| 2 | `VOL_LIST` | `bios_fileList` |
| 4 | `VOL_CREATE` | `bios_fileCreate` |
| 6 | `VOL_LOAD` | `bios_fileLoad` |
| 8 | `VOL_DELETE` | `bios_fileDelete` |
| 10 | `VOL_RENAME` | `bios_fileRename` |
| 12 | `VOL_STAT` | `bios_fileLoadInfo` |
| 14 | `VOL_LOAD_ADDRESS` | `bios_fileGetSetAddr` |
| 16 | `VOL_ATTRIBUTES` | `bios_fileGetSetAttr` |
| 18 | `VOL_LOAD_AT` | `bios_fileLoad2` |
| 20 | `VOL_FREE_SPACE` | `bios_getDriveFreeSpace` |
| 22 | `VOL_PREPARE_NAME` | `bios_fileNamePrepare`, но префикс `X:` уже обработан DOS |
| 24 | `VOL_CREATE_PREPARE` | `bios_fileCreatePrepare` |
| 26 | `VOL_TRANSFER_LEGACY` | `bios_fileTransfer`, пока привязанный к кластерам |
| 28 | `VOL_FLUSH` | Сохранить изменения; CF=1 при отказе |

Контекст можно получить через публичный `bios_getVolume`, предварительно
узнав текущую букву через `bios_fileGetSetDrive`. Внутренние переменные DOS
не являются адресами публичного ABI. Mount не обращается к файловой системе
повторно через собственные публичные файловые точки.

Диспетчер не реентерабелен: он меняет адрес своего перехода. Вызовов DOS из
прерываний и параллельного переключения тома быть не должно. Основной путь
обёртка + диспетчер занимает 167 тактов 8080 (около 83,5 мкс при 2 МГц),
без времени обработчика и исходного публичного JP. Общий диспетчер — 22 байта.

## Что требуется до подключения RAMFOS

Версия 1 сохраняет `FILE_DESCRIPTOR`/`FILE_INFO`, имена 8+3, размер N−1 и
кластерный поток C88Dh. RAMFOS имеет собственный формат и имена 9+3; полной
совместимости средствами этой таблицы ещё нет.

Нужен общий байтовый поток open/read/write/close/abort с 32-битной длиной и
непрозрачным состоянием файла. После перевода F5 на этот интерфейс модуль
RAMFOS сможет реализовать файловые операции своим обходом каталога и данных,
не изображая FAT-цепочки. Формат общих сведений о томе тоже нужно отделить
от FAT-геометрии `DISK_INFO`; сейчас это историческая структура.

FORMAT пока работает напрямую с блоками старого FAT-формата. До установки
настоящего модуля RAMFOS надо добавить выбор или запрет форматировщика по
типу тома, чтобы FORMAT не мог затереть чужую файловую систему.

Отдельно нужны резервирование страниц, общая таблица логических/физических
страниц для MXOS и RAMFOS, проверки всех границ и исключение flash из
доступных RAMFOS устройств. Само разделение таблиц страниц не резервирует.

## Выбор встроенного дискового драйвера

Единственный сборочный вход — `DOS.asm`. Константа `DISK_DRIVER_CHECKED`
в `source/include/mxos.inc` выбирает условный INCLUDE физического ROM/RAM-драйвера:

- `1` (по умолчанию): `driverChecked.inc`, результат операций в CF и проверка аргументов.
- `0`: прежний `driver.inc`, с сохранением исторического поведения флагов.

Проверочный драйвер не читает RAM повторно после записи. Независимая настройка
`RAMD_BUFFERED` выбирает алгоритм блочного обмена:

- `1` (по умолчанию): R4, прямой перенос четырёх байтов через BC/DE и POP/PUSH,
  общее окно 32 байта и копии 77 байтов кода в хвостах страниц.
- `0`: исторический блочный драйвер с переключением страницы на каждом байте.

Имя настройки `RAMD_BUFFERED` и параметр сборки `Buffered` сохранены;
промежуточного буфера данных в R4 нет. Сервисный побайтовый драйвер остаётся
для установки хвостовых копий и записи меток. Обе константы переопределяются ключами
ассемблера `-DDISK_DRIVER_CHECKED=0/1` и `-DRAMD_BUFFERED=0/1`.

Собрать DOS с дополнительными символами из `source/dos`:


Затем из корня выполнить `python -X utf8 scripts/tests/check-volume.py`.
Проверка исполняет машинный код диспетчера в узкой модели команд 8080, подменяя

## Копирование памяти

Вход C42Dh и внутренний `memmove_bc_hl` используют общий движок
`source/dos/move8080.inc`: HL — начало, DE — конец исключительно,
BC — назначение. Направление выбирается сравнением начала назначения и
источника; перекрытие обрабатывается в обе стороны, пустой диапазон допустим.
Внутренний вход сохраняет BC/DE/HL, C42Dh сохраняет DE и возвращает
HL=исходный конец, BC=конец назначения. DEBUG T переводит включительный конец
в этот контракт. Редактор строки явно включает терминатор в перенос.

Пара байтов передаётся через DE: POP при движении вперёд, PUSH при движении
назад. SP временно служит указателем данных; прерывания запрещены системным
контрактом. Движок не реентерабелен; источник/назначение не должны затрагивать
активный стек или выполняемый код. Диапазоны не должны оборачиваться через
0000h; конец 10000h представляется DE=0, полный блок 64 КБ не поддерживается.
[Проверка и такты](../../docs/chkdsk/RESULTS.md).

## Распределение кластеров по flash-чипам

Физический B=3 возвращает DE=число секторов, HL=DISK_INFO и BC=шаг
распределения по чипам в секторах. Обычные драйверы возвращают BC=0;
FlashFst — 2048. Ненулевой шаг также объявляет B=4: дождаться всех отложенных
записей с CF=0/1, сохранив BC/DE/HL. Эти поля не записываются в BPB.

При mount DOS сохраняет шаг в DISK_INFO.allocationStep и вычисляет
DISK_INFO.dataClusters. Для 256-байтных односекторных кластеров следующий
поиск начинается на следующем чипе; после последнего чипа адрес внутри
первого увеличивается. Если предпочтительный участок занят, выполняется
ограниченный полный обход с возвратом к кластеру 2. Для остальных геометрий
сохраняется линейное выделение. Цепочка остаётся обычной FAT-цепочкой,
читаемой Flash и FlashFst без смены формата.

Завершение файловой записи, изменения метаданных и flush ждёт физический
барьер. Это не повторное чтение и сравнение данных. FAT и корневой каталог
не перемещаются. B=1 не сравнивает данные; Flash, FlashFst и FlashSys
предоставляют B=5 для синхронной записи с чтением и сравнением сектора.
DATA polling остаётся обязательным.

## Встроенное чтение больших системных ROM

При назначении от `8000h` ROM подключается один раз, сектор передаётся
существующим `bios_memcpy_bc_hl` (`C42Dh`), затем возвращается RAM.
Для нижнего назначения MX-банки читаются парами через регистры: 94 такта
на два байта вместо прежних 65 тактов на байт. Входные регистры сохранены;
стек и исполняемый код должны оставаться в верхней памяти.

Старая STD-половина 64-КБ MX2-образа также использует быстрый верхний путь,
с восстановлением режима и цвета. Её нижнее чтение и последний неполный
сектор `7F04h..8003h` оставлены на прежнем побайтовом пути. Последний сектор
по-прежнему зарезервирован сборщиком и не используется для файлов.

Вспомогательный код занимает 35 байт. Его текущие адреса, как и размещение
строк, выбираются автоматически по `layout.json`. Штатный DOS занимает
**6618 байт**, конец `D9DAh`, запас до `DA00h` — 38 байт.
Фиксированные адреса ABI не изменены.
Проверка: `scripts/emu80/check-native-mapped-read.py`, отчёт
`docs/flash/native-read-001/RESULTS.md`.

Встроенный A: читает линейные системные тома 128/256/512 КБ без FlashSys.
Для DE=номера 256-байтного сектора банк равен DE >> 7, адрес внутри окна —
(E & 7Fh) << 8. Банк передаётся в FFFEh перед копированием в верхнее
назначение либо перед каждой парой при нижнем назначении; затем
восстанавливается основное ОЗУ.

Для 64-КБ MX2-образа при ROM_64K=1 сохраняется старая раскладка MX/STD
с четырёхбайтным входом STD. Линейный путь выбирается по BPB тома от 128 КБ.
Запись на A: во встроенном драйвере запрещена; её предоставляет FlashSys.
Начальный загрузчик всё ещё требует DOS.SYS в первой 32-КБ странице,
поскольку копирует ядро до запуска файлового драйвера. Остальные файлы,
включая FLASHSYS.COM и AUTOEXEC, могут находиться выше 64 КБ.

Проверка: `scripts/emu80/check-rom-banks.py` в отдельном Emu80-flash-test.
Проверены оба варианта встроенного драйвера (Checked и без обёртки),
все границы банков до 512 КБ и холодная загрузка после переноса FONT,
FORMAT.BAT/COM, FLASHSYS.COM и AUTOEXEC в верхние банки. Отчёты находятся
в `docs/rom-banks/`; эмуляторная проверка не подтверждает работу на плате.

## Описание физического драйвера и запись с проверкой

`bios_diskDriver`, B=0FFh возвращает CF=0 и HL на две ASCII-строки:
`имя,0,описание,0`. Имя не длиннее 22 символов, описание — 30.
Дополнительно B возвращает DISK_TECH_ROM ('O'), DISK_TECH_RAM ('R') или
DISK_TECH_FLASH ('F'); C содержит DISK_CAP_READ=01h, WRITE=02h,
VERIFY=04h (B=5), FLUSH=08h (B=4). Указатель действителен до замены драйвера;
NC запрашивает его при рисовании инфо-панели. CF=1 или HL=0 означает
отсутствие описания и сведений о возможностях. Значения DISK_TECH_FLOPPY
('D') и DISK_TECH_HDD ('H') зарезервированы для будущих драйверов механических
накопителей; физические драйверы этим не добавлены. Встроенный драйвер
различает ROM и RAM; ROM.COM, Flash, FlashFst и FlashSys содержат свои строки.

Flash-драйверы принимают B=5 с теми же DE/HL, что B=1. Общий сервис
`bios_diskWriteChecked` (C89Fh; BC=адрес драйвера) вызывает B=1 и B=2,
затем сравнивает все 256 байт. Для FlashFst чтение ждёт программируемый чип;
B=5 синхронен и сохраняет BC/DE/HL. При ошибке CF=1, diskWriteErr=1.
Старый макрос DISK_WRITE_VERIFY заменён явным выбором функции во время работы.

Временный сектор занимает 256 байт стека, постоянный буфер DOS не добавлен.
Для B=5 вызывающая сторона должна обеспечить не менее 320 свободных байт
стека. DISKBEN устанавливает SP=8FDFh. Маленький исторический стек сам по
себе не подходит для B=5: программа должна предоставить свой стек.

Возможности B=FFh описывают протокол драйвера, а не разрешение /WE конкретной
микросхемы: состояние J4 таким запросом не определяется. Встроенный драйвер
возвращает ROM/READ для A: и RAM/READ|WRITE для RAM-дисков (имя RAMD,
описание Per-byte либо Legacy; установленный RAMD.COM возвращает R4 banked). Flash/FlashSys
возвращают FLASH/READ|WRITE|VERIFY, FlashFst добавляет FLUSH, ROM.COM
возвращает ROM/READ. Расширение занимает по три байта во внешних драйверах;
обработчик встроенного по-прежнему помещается в фиксированный промежуток.


Общая прикладная библиотека `source/include/timing.inc` также содержит
`ticks_to_ms` и `print_number`, перенесённые из LLM80. `ticks_to_ms` принимает
HL — адрес U32 тиков, сохраняет исходное число и записывает целые миллисекунды
в `v_number` (округление вниз). Регистры и флаги разрушаются. При 2 МГц
пересчёт равен ticks×16/125, при 2,5 МГц — ticks×64/625. Как и прежний код LLM80,
масштабирование использует U32: вход ограничен `TIMING_MAX_TICKS`, то есть
268435455 или 67108863 соответственно. Память и код принадлежат приложению,
новых точек резидентного ABI для форматирования не добавлено.

Для включения нужны `PIT_HZ`, буфер `DECIMAL` на 11 байт и callback
`timing_print` (HL — строка). `print_number` переводит U32 из `v_number`
в десятичный текст и разрушает рабочее число. Необязательный
`TIMING_NUMBER_WIDTH` дополняет поле пробелами слева; при ненулевой ширине
нужен callback `timing_printChar` (A — символ). DISKBEN использует ширину 8,
LLM80 сохраняет вывод без дополнения. `bios_strToHex` выполняет обратную
задачу разбора шестнадцатеричного текста и для пересчёта времени не нужен.


## Потоковая передача и физический flush

`bios_fileTransfer` (C88Dh) принимает HL — буфер, DE — первый кластер,
B=1 запись / B=2 чтение, C — число 256-байтных кластеров (0 означает 256).
BC сохраняется, HL продвигается на C×256, DE возвращает следующий кластер,
CF сообщает ошибку. В текущем формате один сектор на кластер. При B=2
барьера B=4 нет; это позволяет читать файл непосредственно в ограниченное
верхнее окно порциями без копирования из окна в нижнюю память.

При B=1 `fatFileTransferClusters` завершает переданную партию одним
`fatFlushPhysical`; в секторном цикле B=4 не вызывается. Обычный
`bios_fileCreate` после этого сохраняет кэш FAT/каталога и вызывает
`fatFinishWrite` с ещё одним барьером. У FlashFst получается два B=4 на файл.
NC передаёт данные партиями до 32 КиБ, поэтому его потоковые записи завершаются
барьером после партии, а не после каждого сектора.

Полная проверка файла в DISKBEN выполняется на уровне приложения: сначала
обычная запись B=1 и штатное завершение, затем чтение через DOS/Raw в верхнее
окно и побайтовое сравнение с исходным буфером. Физическая B=5 остаётся
самостоятельной посекторной операцией и проверяет также метаданные, если
вызывающая сторона использует её для FAT/каталога.

## Эксперимент с размером кэша

По умолчанию кэш остаётся FB00h–FEFFh (4 сектора). Для изолированных сборок
`FAT_CACHE_ADDR` и `FAT_CACHE_SIZE` можно задать ассемблеру; необязательная
`FAT_CACHE_TABLE_ADDR` переносит таблицу слотов из DOS. Адреса и объём должны
согласовываться с программой: эти параметры не резервируют память через
`bios_getMemTop`. Рабочий профиль ими не переопределяется.

Опыт `scripts/emu80/benchmark-cache.py` использует 88 слотов в 2800h–7FFFh,
таблицу 2400h–26BFh, payload DISKBEN 2000h–23FFh, верхнее окно 8200h–8DFFh.
Это вмещает FAT (64 сектора) и root (24 сектора) H: целиком. Для числа слотов
больше 32 смещение в таблице вычисляется в 16 битах. Поиск остаётся линейным.

Измерительная сборка `FAT_CACHE_BENCH_SAMPLE` добавляет трёхбайтный callback
`cacheBenchmarkSample` (по умолчанию RET). Только в тестовом runtime он
перенаправляется на `timer_sample` DISKBEN. Это даёт частые отсчёты даже
при долгом обходе FAT без физических обращений, исключая потерю оборотов
канала 2 ВИ53. Одинаковый callback включается в обе сравниваемые сборки;
его стоимость входит в время. В обычном ядре callback отсутствует.

Вытеснение сохраняет грязный сектор через `saveSectorFromCache`. Завершение
создания/удаления файла принудительно вызывает `saveSectorCache`, затем
физический барьер; `bios_flushVolume` (C899h) также выполняет обе операции.
Один только B=4 физического драйвера кэша FAT/каталога не касается.
