# Файловое ядро DOS

DOS.SYS исполняется с 0100h в физическом банке ДОЗУ 0, FAR-страница 1. Резидентное ядро обслуживает FAT12/FAT16, файловые дескрипторы, каталоги, драйверы, нативную загрузку контейнеров и команды, включая BAT. Межбанковый обмен реализуют адаптеры `kernel-*.inc` и [MEM](../mem/transport.md). Экран, клавиатура и аппаратура относятся к [BIOS](../bios/README.md) и IO.SYS.

## Сборка и вызовы

`powershell.exe -NoProfile -File scripts/build/build-project.ps1 OS` собирает систему. [build-bios-dos.py](../../scripts/build/build-bios-dos.py) компонует BIOS.SYS с C000h, IO.SYS с F000h и DOS.SYS с 0100h. Ядро собирается из [DOS.asm](DOS.asm) и списка блоков [layout.json](layout.json). Для стендов отдельную сборку банкового ядра создаёт [build-banked-dos.py](../../scripts/build/build-banked-dos.py).

Приложение вызывает `MXOS_CALL` через регистровый вход F806h либо передаёт пакет в F800h. Номера служб объявлены в [syscall-ids.inc](../include/syscall-ids.inc), структуры и флаги — в [mxos.inc](../include/mxos.inc). Адреса внутри DOS.SYS вычисляются при сборке. NEAR-указатели публичных запросов относятся к странице клиента. В MAIN обычная память приложения ограничена адресом 8BFFh, возможность занять диапазон дополнительно зависит от текущего владельца. Контракт C описан в [SDK](../../sdk/README.md).

## Размещение в странице DOS

Диапазоны приведены включительно. Размер образа и конец блока переменных зависят от сборки. Их точные границы содержат `bin/System.layout.json` и `bin/banked/KERNEL.layout.json`. Холодный старт переносит шаблон и обнуляет остальные переменные. Области переменных и рабочих буферов размещены за образом и отсутствуют в DOS.SYS. Тёплый вход сохраняет окружение и состояние томов.

| Область | Назначение |

| 0000h–00FFh | Резерв перед образом |

| `kernelEnd`–7C7Fh | Резерв до блока переменных |
| 7C80h–81FFh | Переменные DOS и резерв |
| 8200h–8AFFh | Общий буфер обмена, файловых операций и выдачи списка. Его последние 128 байт занимают рабочую строку BAT |
| 8B00h–8BFFh | Командная строка DOS, контекст и заголовок загрузчика |
| 8C00h–8DFFh | Реестры FAR-выделений и DLL, сохранённый FONT, проверка выгрузки |
| 8E00h–8EFFh | Локальный FILE_HANDLE/пакет и путь клиента |
| 8F00h–93FFh | Реестр физических драйверов, сохранённая служба ВВ55 и переменные локального BIOS |

| 9B00h–C9D7h | Арена DLL, установщиков, службы дисковода и вытесняемого окна BAT |

## Тома и физические драйверы

Штатные буквы — A: для дисковода, B: для RAM-диска, C: для системного ПЗУ/flash и H: для внешнего ROM/flash. Установщики принимают `-LETTER`. Код, которому важна архитектура носителя, запрашивает его тип в `B` и маску `DISK_CAP_*` в `C` через `MXOS_DOS_RAW_IO` с B=FFh. В `HL` возвращаются имя и описание из реестра. Встроенная FAT обрабатывает все смонтированные тома. Переключение драйвера и выбор FAT выполняются на разных уровнях. Установленный драйвер остаётся в списке дисков при отсутствии носителя, в том числе при нулевой физической ёмкости. [Реестр и RAW ABI](../mem/api.md#получение-имени-и-описания-накопителя)

| Формат | Условия распознавания |
|---|---|
| FAT12 | Логический сектор 512 байт, подпись 55h AAh, до 4084 кластеров |
| FAT16 | Логический сектор 512 байт, подпись 55h AAh, 4085–65524 кластеров при допустимой ёмкости тома |
| MXOS128 / MXOS256 | Сектор 128 / 256 байт и OEM-метка `MXOS128 ` / `MXOS256 `. Используется 16-битная FAT, включая малые тома |

Поддерживаются одна или две FAT, несколько резервных секторов и кластер до 32768 байт из числа секторов, равного степени двойки. Логический сектор состоит из одного или нескольких физических блоков. Меньший логический сектор и не помещающиеся в 16-битную адресацию LBA отклоняются. Верхняя половина TotSec32 должна быть нулевой, если используется это поле. DOS монтирует том с начала устройства, разметку MBR пока не читает.

При монтировании DOS сверяет размер таблицы с числом кластеров, проверяет BPB_Media и заголовок FAT. Неподдерживаемая геометрия возвращает `DOS_ERR_UNSUPPORTED`, неверный заголовок FAT — `DOS_ERR_CORRUPT`, отказ чтения — `DOS_ERR_IO`. Недоступный носитель и нераспознанный формат ROM/flash дают `DOS_ERR_NO_MEDIA`; причина сохраняется при повторных файловых запросах к выбранному тому. Биты clean/error в FAT16 принимаются, ядро их не обновляет. Ячейки FAT12 хранятся упакованными. Ядро сохраняет соседний полубайт и получает оба сектора до изменения пересекающей границу записи. При наличии второй FAT изменения зеркалируются. [Реализация FAT12](fat12.inc)

`FORMAT A:` в штатной раскладке создаёт дискетный FAT12 на 720 КиБ, а FORMAT для 256-байтных блоков — MXOS256. Перед извлечением дискеты закройте файлы и переключитесь на другой том, проверив сброс. При повторном выборе тома DOS перечитывает BPB. После внешней записи RAW перемонтируйте том через `MXOS_DOS_MOUNT_VOLUME` и восстановите рабочий каталог. [Геометрия и параметры FORMAT](../format/README.md)

## Дисковый кэш

Единый пул кэша CE00h–EDFFh объёмом 8 КиБ распределяется между всеми дисками по потребности, без квот и ограничения двумя активными томами. Сектор 128/256/512 байт занимает 1/2/4 соседние выровненные гранулы по 128 байт; один диск может занять весь пул. Таблица и буферы не входят в DOS.SYS. Восьмибайтный описатель головы содержит LBA, адрес данных, слово reference, dirty и tag. В tag младшие три бита задают диск, следующие два — sectorShift−7; 80h..BFh обозначают продолжение с индексом головы, FFh — свободную гранулу. Пересекающиеся головы вытесняются целиком, включая все продолжения.

Вытеснение использует CLOCK: попадание устанавливает reference=1, проход указателя даёт такой голове второй шанс и сбрасывает reference; голова с reference=0 может быть вытеснена. Полный поиск минимального возраста и счётчик времени для каждого попадания не нужны. Перед поиском проверяется последний слот вместе с меткой диска/геометрии; основная таблица просматривается только по индексам, допустимым для размера искомого сектора. Верхняя оценка LBA позволяет сразу отвергать заведомо отсутствующие потоковые сектора. Оценка хранится отдельно для каждого диска, чтобы высокие LBA загруженных программ одного носителя не замедляли прямое чтение другого; после вытеснения она может оставаться завышенной, что влияет только на скорость.

Неполные файловые сектора используют отдельный общий 512-байтный буфер с собственными tag и dirty. Сначала проверяется общий пул, чтобы не создавать две копии одного сектора. При переходе к неполному сектору другого диска прежняя чистая копия может быть заменена; закреплённого буфера на каждый диск нет. Полные сектора передаются напрямую, если в кэше нет более новой копии.

Смена диска сначала сохраняет dirty прежним драйвером; при отказе диск не переключается. Чистые строки всех дисков остаются в общем пуле. Общий признак dirty позволяет не обходить таблицу при переключениях, если изменений нет; для единственной dirty-строки хранится прямой указатель, и flush также обходится без сканирования. Явное перемонтирование после FORMAT/RAW-записи и замена драйвера инвалидируют только строки соответствующего диска, включая неактивный. Смена размера сектора также инвалидирует его строки. После внешней записи перемонтируйте том. Для дисковода DOS также сбрасывает кэш и перечитывает BPB при повторном выборе после переключения на другой диск. BPB читается в независимый буфер, не повреждая сохранённые строки.

### Измерение кэша

Штатный DISKBEN проверяет последовательную передачу данных: увеличение файла главным образом увеличивает прямой обмен полными секторами и длину цепочки FAT, а не рабочий набор кэша. Для проверки его заполнения и вытеснения используется `python scripts/tests/benchmark-dos-cache-pressure.py --report docs/diskbench/cache-pressure`: он исполняет штатный код DOS в модели Intel 8080 с синтетическим 256-байтным драйвером. Режимы включают рабочие наборы одного, двух и трёх дисков, неравномерное распределение, переполнение общего объёма, повтор одного сектора и запись с переключениями дисков. Прогрев исключён из измерения; сохраняются такты, число запросов, чтений и записей драйвера. Это изолированная оценка кэша, без стоимости монтирования, файлового поиска и реального носителя. Для сравнения иной сборки доступны `--kernel путь/KERNEL.bin` и соответствующий KERNEL.sym рядом. Полные файловые операции отдельно измеряет `scripts/emu80/benchmark-dos-cache.py` через процедуры DISKBEN в собственном видимом Emu80 без звука.

## Открытые файлы

`MXOS_CALL MXOS_DOS_FILEHANDLE`: A — операция, HL — адрес 64-байтного FILE_HANDLE. AF/BC/DE/HL разрушаются; При CF=1 регистр A содержит код DOS. При CF=0 операция успешна. Правила чтения сохранённого кода описаны в разделе [ошибок](#ошибки-файловых-операций). Все остальные входы и результаты находятся в объекте вызывающей программы. Вызовы нереентерабельны; активным остаётся диск файла. Реализация обслуживает встроенное FAT-ядро.

| Смещение | Размер | Поле |
|---|---:|---|
| 0 | 32 | Копия FILE_DESCRIPTOR; до OPEN задаются первые 11 байт имени 8.3 с пробелами, байты KOI-8 сохраняются |
| 32 | 4 | Текущая позиция, little-endian |
| 36 | 4 | Внутренний курсор «кластер + смещение» |
| 40 | 1 | Диск 0–7 |
| 41 | 1 | Режим: READ=1, WRITE=2, CREATE=4, TRUNCATE=8, APPEND=16, VERIFY=32, SCATTER=64 |
| 42 | 1 | Состояние: 46h — открыт, 0 — закрыт |
| 43 | 1 | Последняя ошибка объекта из общей шкалы DOS_ERR_*. Успешная операция его не сбрасывает, см. clearerr |
| 44 | 1 | EOF; SEEK и clearerr сбрасывают |
| 45 | 4 | Внутренние сектор и смещение записи каталога |
| 49 | 2 | NEAR-адрес буфера READ/WRITE либо ASCIIZ-пути OPEN_PATH |
| 51 | 2 | На входе число байтов; на выходе фактически передано, включая частичный отказ |
| 53 | 4 | Signed int32 смещение SEEK; рабочее поле изменяется вызовом |
| 57 | 1 | Начало SEEK: SET=0, CUR=1, END=2 |
| 58 | 5 | Предыдущий кластер, состояние LFSR и действительность курсора |
| 63 | 1 | Код операции для C-переходника; процессорный ABI принимает его в A |

Перед OPEN обнулить объект и заполнить имя, диск и режим. Повторный OPEN открытого объекта запрещён; CLOSE при ошибке оставляет его открытым для повторной попытки. Нельзя одновременно изменять один файл через несколько объектов, удалять/переименовывать открытый файл, менять его том или извлекать носитель. Дескрипторы разных файлов можно чередовать; постоянные данные каждого находятся в самом FILE_HANDLE, а не в общем кэше.

| A | Операция | Поведение |
|---:|---|---|
| 0 | OPEN | Открыть; CREATE разрешает новый файл, TRUNCATE обнуляет существующий, WRITE проверяет Read-only |
| 1 | READ | Не читает за размер файла; короткое чтение/чтение за EOF выставляет EOF без ошибки |
| 2 | WRITE | Перезапись и расширение с выделением кластеров; APPEND перед каждым непустым запросом выбирает конец |
| 3 | SEEK | 32-битный SET/CUR/END, отрицательная итоговая позиция и переполнение отвергаются; само перемещение не выделяет кластеров |
| 4 | FLUSH | Сохранить данные/FAT, затем первый кластер и размер в каталоге, выполнить физические барьеры |
| 5 | CLOSE | FLUSH для записи и закрытие только при успехе |
| 6 | OPTIONS | Чтение или обмен общих флагов записи. SCATTER задаётся в FH_MODE |
| 7 | OPEN_PATH | Полный/относительный ASCIIZ-путь в FH_BUFFER, режим в FH_MODE |
| 8 | OPEN_AT | Имя 8.3, FH_DRIVE и кластер родителя в младшем слове FH_SEEK |

Внешние объекты и буферы должны заканчиваться не выше начала банкового сегмента IO.SYS (F040h); внутри этого диапазона вызывающий отвечает за владение памятью. Нулевой READ/WRITE не обращается к буферу. Буфер и объект не пересекаются; буфер не должен захватывать активные кадры BIOS/DOS. Размер запроса ограничен 16 битами и непрерывной доступной памятью, размер и позиция файла — 32 битами. Фактическая ёмкость тома по-прежнему ограничена нынешним 16-битным LBA.

После SEEK за EOF запись выделяет промежуточные кластеры; содержимое промежутка не определено, как допускает интерфейс C. Это не POSIX-гарантия нулевого заполнения. Незаписанные выделения при заполнении тома освобождаются; частично переданные данные и позиция сохраняются. Аппаратные ошибки не обеспечивают транзакционный откат. Размер публикуется при FLUSH/CLOSE, поэтому CLOSE обязателен и его результат нужно проверять.

Курсор сохраняется между последовательными запросами. После SEEK цепочка проходится от начала; обход ограничен числом кластеров тома. Повреждённая/BAD/циклическая цепочка возвращает `DOS_ERR_CORRUPT`. Полный файл проверяется на корректный EOC. Секторный перенос использует общий fatStream, без повторной проверки буферов на каждом кластере; выделение использует штатные подсказки распределителя.

## Ошибки файловых операций

`CF=1` означает отказ. `MXOS_DOS_FILEHANDLE` возвращает `DOS_ERR_*` в `A` и сохраняет причину файловой операции в `FH_ERROR` доступного объекта. Если диспетчер отклонил запрос до файловой операции, например из-за недопустимого адреса, используйте возвращённый `A`. `FH_ERROR` может сохранять более ранний код. EOF отмечается в `FH_EOF`, фактическое число байтов возвращается в `FH_COUNT`. Короткое чтение у EOF считается успехом.

`fatStream` — внутренний поток FAT для FILEHANDLE и загрузчиков. Он использует общий статус DOS. Приложения получают эти ошибки через публичный FILEHANDLE. Для служб, возвращающих подробную причину отдельно, `MXOS_DOS_GET_ERROR` (0218h) выдаёт её в `A` и устанавливает CF при ненулевом коде. Чтение не сбрасывает причину. Сохраните нужный код до CLOSE, переключения тома или иной файловой операции.

| Код | Константа | Сообщение |
|---:|---|---|
| 0 | — | Успех. Индекс 0 в справочнике содержит запасное `Unknown error` |
| 1 | `DOS_ERR_IO` | Disk input/output error |
| 2 | `DOS_ERR_NOT_FOUND` | File or path not found |
| 3 | `DOS_ERR_EXISTS` | Destination already exists |
| 4 | `DOS_ERR_FULL` | Disk is full |
| 5 | `DOS_ERR_DIR_FULL` | Directory is full |
| 6 | `DOS_ERR_ACCESS` | Access denied |
| 7 | `DOS_ERR_ARGUMENT` | Invalid argument |
| 8 | `DOS_ERR_CORRUPT` | File system is corrupted |
| 9 | `DOS_ERR_NO_DRIVER` | Disk driver is not installed |
| 10 | `DOS_ERR_UNSUPPORTED` | Operation is not supported |
| 11 | `DOS_ERR_BAD_IMAGE` | Invalid executable file |
| 12 | `DOS_ERR_CANCELLED` | Operation cancelled |
| 13 | `DOS_ERR_WRITE_PROTECTED` | Disk is write-protected |
| 14 | `DOS_ERR_NO_MEDIA` | No media |

[errors.inc](../include/errors.inc) принимает код в `A` и возвращает `HL` с локальной ASCIIZ-строкой до следующего вызова. BC и DE сохраняются. Модуль использует собственный рабочий дескриптор `flHandle` из [file-io.inc](../include/file-io.inc). Для вывода сохранённой ошибки передайте в `dosErrorText` значение `FH_ERROR`.

```asm
    ld a,(fileObject+FH_ERROR)
    or a
    ret z
    call dosErrorText
    MXOS_CALL MXOS_BIOS_PRINT_STRING
```

Сообщения хранятся в `DOS\ERRORS.DAT` загрузочного диска (C: в MMX, A: в MX). Каждая из 15 индексных записей содержит 16-битное little-endian смещение от начала файла и однобайтную длину от 1 до 31. Затем идут строки ASCII без NUL. Сборщик сверяет имена текстов с `DOS_ERR_*` в `mxos.inc` и записывает индекс в порядке фактических кодов. При недоступном справочнике или неизвестном коде `dosErrorText` возвращает числовое сообщение вида `DOS error 04h`. [Сборщик справочника](../../scripts/build/build-error-strings.py)

## Каталоги

`MXOS_DOS_DIRECTORY` (021Ch) выбирает операцию по `A` и сообщает статус DOS через CF/A. Корень обозначается кластером 0. Для каждого диска хранится текущий каталог. Путь — ASCIIZ до 127 байт, с нулём не более `MAX_PATH` (128 байт). Допустимы `/` и `\`, смешанные разделители, префикс диска, `.` и `..`. Имена 8.3 сравниваются без учёта регистра; LFN-записи пропускаются. KOI-8 в именах остаётся соглашением MXOS.

Банковый диспетчер читает пути и команды через 32-байтное окно MEM. Источник прочитан до терминатора включительно в пределах `MAX_PATH` и доступной области клиента (до FC00h в MAIN, до F800h в EXEC). Для путей, CLI и регистрации шрифта терминатор — ноль, для FILE_EXEC — любой байт ниже 20h. Отсутствие терминатора в пределах области возвращает `DOS_ERR_ARGUMENT`. Двоичные дескрипторы передаются по длине структуры или полей запроса без поиска терминатора.

| A | Операция | Параметры и результат |
|---:|---|---|
| 0 | `DIR_OP_GET` | DE получает кластер текущего каталога |
| 1 | `DIR_OP_SET` | DE — контекст, ранее полученный на том же томе |
| 2 | `DIR_OP_CHDIR` | HL — путь. При отказе прежний диск и каталог сохраняются |
| 3 | `DIR_OP_LIST` | HL — массив FILE_INFO, DE — ёмкость в записях, BC — индекс пропуска. Выход DE — полное число записей. В список входят каталоги, `.` и `..` |
| 4 | `DIR_OP_GETCWD` | HL — буфер MAX_PATH для абсолютного ASCIIZ-пути. Банковый диспетчер записывает путь с нулём, оставляя хвост буфера прежним |
| 5 | `DIR_OP_COMMAND` | HL — команда CD/CHDIR. A=FFh, CF=0, если команда не распознана |
| 6 | `DIR_OP_RESOLVED` | DE получает временный контекст последнего разрешения имени |
| 7 | `DIR_OP_MKDIR` | HL — путь нового каталога |
| 8 | `DIR_OP_RMDIR` | HL — путь удаляемого пустого каталога |

Поиск имени и перечисление используют общий обход FAT, ограниченный числом кластеров тома. Корень ограничен числом записей из BPB. При расширении подкаталога DOS добавляет нулевой кластер. Заполненный корень возвращает `DOS_ERR_DIR_FULL`. Результат списка заканчивается FFh и выдаётся через буфер DOS несколькими пачками при необходимости. `MXOS_DOS_FILE_LIST` выдаёт список файлов, NC получает каталоги через DIR_OP_LIST. Механизм работы с масками и рекурсией описан в [ENUM.DLL](../enumerate/README.md).

## Проверка FILEHANDLE и размещение кластеров

FILE_MODE_VERIFY (20h) требует посекторной записи с проверкой B=5 для данных данного файла. Флаг требует WRITE; если физический драйвер не сообщает DISK_CAP_VERIFY, OPEN возвращает DOS_ERR_UNSUPPORTED до создания или усечения файла. Проверка выполняется сразу после записи полного физического блока. Неполный логический сектор сначала собирается в отдельном слоте кэша, затем сохраняется и проверяется целиком; dirty очищается только при успехе. Ошибка B=5 возвращается как ошибка I/O, а не как успешная отложенная запись. FAT, каталог и другие метаданные эта настройка не переводит в B=5.

Общая настройка DOS_IO_VERIFY_FILES (бит 0) включает тот же путь для всех запросов WRITE через FILEHANDLE на драйверах с DISK_CAP_VERIFY, включая уже открытые файлы. Для остальных драйверов сохраняется обычная запись. По умолчанию настройка выключена и хранится в состоянии DOS. Внутренние загрузчики задают собственную политику проверяющей записи.

Настройка доступна через существующий ABI MXOS_DOS_FILEHANDLE, A=FILE_OP_OPTIONS (6), HL=64-байтный FILE_HANDLE. FH_ORIGIN=0 читает текущие флаги в FH_COUNT, FH_ORIGIN=1 обменивает FH_COUNT на прежние флаги. Установить можно только бит DOS_IO_VERIFY_FILES; неизвестные биты и команды отклоняются без изменения настройки. Открытый файл, корректный FH_DRIVE или смонтированный том для OPTIONS не требуются; объект по-прежнему должен находиться в допустимой памяти вызывающего. Вызов из MAIN/EXEC переносит весь объект обычным банковым переходником.

```asm
    ld a,1
    ld (options+FH_ORIGIN),a
    ld hl,DOS_IO_VERIFY_FILES ; 0 отключает общую проверку
    ld (options+FH_COUNT),hl
    ld hl,options
    ld a,FILE_OP_OPTIONS
    MXOS_CALL MXOS_DOS_FILEHANDLE
    ; При CF=0 FH_COUNT содержит прежнюю настройку для восстановления.
options: DS FILE_HANDLE,0
```

FILE_MODE_SCATTER (40h) разрешён только с WRITE и меняет поиск новых кластеров данного файла: распределитель проверяет до 15 кандидатов LFSR и при первом свободном кластере выделяет его. Если все заняты, шестнадцатая позиция начинает ограниченный полный обход FAT. Занятые кластеры не перезаписываются, полный том возвращает обычную ошибку FULL. FH_ALLOC_SEED (60..61) хранит состояние LFSR, OPEN начинает с ACE1h. Этот поиск действует и для FAT12, и для FAT16, включая MXOS с секторами 128/256 байт.

## Полные секторы и физический обмен

FILEHANDLE ограничивает чтение размером файла, а поток FAT ведёт курсор и строит серии LBA. По умолчанию серия вмещает до 32 полных физических 256-байтных блоков; `DOS_IO_BATCH_SECTORS` задаёт предел сборки. Подготовка списка входит в файловую операцию. Пакет расположен по `DOS_IO_BATCH_ADDR` (9700h). Полные блоки подходящих драйверов идут напрямую между носителем и буфером клиента. Неполные секторы и неподходящая для серии геометрия используют секторный или буферизованный обмен. При ошибке передачи позиция и число байтов соответствуют выполненному префиксу.

Системный драйвер использует отображённое окно, RAM-диск — банковый перенос, внешние ROM/flash через ВВ55 — локальную копию драйвера. Незавершённый конвейер AT2MXF сбрасывается при смене обслуживающей копии и перед освобождением банкового модуля. RAW_IO B=6 готовит доверенный локальный физический маршрут. Приложение, которое пишет через RAW, отвечает за предварительный сброс, согласование кэша и сохранность метаданных. [Транспорт и пакетный режим](../mem/transport.md#подготовка-cpm32-и-пакетный-режим)

## Потоковые BAT

DOS находит файл один раз по имени в каталоге запуска. Каждый уровень хранит диск, начальный кластер, размер и 32-битное смещение для продолжения. Имя 8.3, номер и смещение строки нужны для диагностики. Все уровни делят один рабочий FILE_HANDLE и одно 128-байтное окно. Строка команды занимает последние 128 байт общего буфера копирования DOS до передачи парсеру CLI.

Если BAT больше окна и целиком помещается в свободный непрерывный интервал арены DOS, ядро читает его одним файловым запросом. При поиске проверяются установщик, обе службы и реестр DLL. Загрузка пересекающегося образа или вход в дочерний BAT освобождает окно и сохраняет позицию первого непрочитанного байта. Родитель продолжает чтение порциями по 128 байт с этой позиции. При последовательных чтениях FILE_HANDLE сохраняет курсор FAT между порциями. Программный возврат в оболочку сбрасывает кадры и окно.

Допускается восемь одновременно активных BAT и до 65535 строк в каждом. Повторный вход в активный сценарий запрещён по диску и первому кластеру, включая циклы через другие BAT. Удаление или замена активного сценария возвращает DOS_ERR_ACCESS до изменения записи каталога и FAT. Дочерний сценарий можно удалить после его завершения. Вызов уже удалённого дочернего файла из BAT возвращает DOS_ERR_NOT_FOUND. Командная строка ограничена MAX_PATH−1 (127 байт); переполнение, NUL в тексте, ошибка I/O или команды прерывают выполнение с кодом DOS. Диагностика `BAT ERROR.BAT line 3: error 2` указывает виновный сценарий и строку и печатается один раз при раскрутке вложенных вызовов. CR, LF и CRLF считаются переводом строки; последняя строка без перевода также выполняется. Байт FFh больше не служит маркером EOF. `@` и ECHO ON/OFF сохраняются; подстановка `%1`, CALL и GOTO не добавлялись.

## Программы, команды и арена

Штатные системные команды и библиотеки находятся в `C:\DOS`, драйверы — в `C:\DRIVERS`, шрифты — в `C:\FONTS`. NC, CLI.COM и BAT используют общий резидентный парсер. Правила путей, ассоциаций и запуска команд описаны в [CLI](../cli/README.md). Нативные программы с фиксированной базой используют 32-байтный заголовок v2. Для перемещаемых DLL и установщиков DRIVER предусмотрен вариант v3 с 40-байтным заголовком. RKS и сменные среды обслуживает [RUN](../run/README.md).

[COPY, MOVE и рекурсивное удаление](../fileops/README.md) используют FILEOPS.DLL и его пошаговую службу `MXOS_DOS_FILEOPS`. MOVE внутри одного тома меняет метаданные. `MXOS_DOS_ENUMERATE` вызывает [ENUM.DLL](../enumerate/README.md) для масок и рекурсивного обхода. Ядро загружает эти модули по потребности. `FILEOPS_JOB.error` при состоянии FAILED также содержит код из таблицы DOS.

Арена DOS занимает [9B00h, C9D8h). Загрузчик выбирает свободный интервал сверху для ENUM, FILEOPS, перемещаемых DOS-DLL и установщиков. Активный курсор ENUM и транзакция FILEOPS закрепляют их интервалы. Резидент ВГ93 получает собственный интервал до смены службы. При старте с дискеты MX bootstrap помещает начальный резидент по 9D00h. DOS проверяет пересечения фактических интервалов из заголовков, защищает активные и закреплённые службы и может освободить пересекающееся окно BAT или вытесняемый неактивный модуль по его политике загрузки. [Контракт модулей](../mem/api.md#загрузка-и-синхронный-вызов-модулей)

## Проверка изменений FAT

Геометрию получайте из BPB или структуры тома. Проверьте соответствие стандартных FAT12/FAT16 спецификации и явно учтите отклонения существующих форматов MXOS. Сохраняйте поддержку 256-байтных физических блоков RAM/AT29C040A и дискет A: FAT12 720 КиБ с 512-байтными секторами. Для изменений формата используйте версию, BPB или явный флаг совместимости. Для образов, где адрес загрузки исторически хранится в записи каталога, документируйте точные байты расширения и сохраняйте их. Остальные поля стандартного тома должны соответствовать спецификации.

- При изменении монтирования и записи сверьте поля BPB, резервные секторы, число FAT, размер и семантику корня, media descriptor и little-endian. Корень FAT12/16 занимает фиксированную область. Проверьте нумерацию кластеров, свободные, reserved, bad и end-of-chain значения, выделение и усечение цепочки, размер файла, удаление записи и метку тома.
- Для упакованной FAT12 проверьте чтение и запись чётной и нечётной ячейки с сохранением соседнего полубайта. Для файлов проверьте пустой файл, ровно один кластер, размеры на границах сектора и кластера, последний свободный кластер, заполненный корень и том, повреждённую и циклическую цепочки.
- Для физических драйверов проверьте чтение и запись через границу 64-КиБ страницы RAM-диска и переключение страниц flash. Логический сектор и физический блок обмена могут различаться.
