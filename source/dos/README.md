# Файловое ядро DOS

DOS.SYS исполняется с 0100h в физической странице ДОЗУ 0 (FAR page=1). Первые 100h оставлены под будущие векторы/обработчики по модели CP/M. Образ непрерывный: код и инициализированные данные идут до kernelEnd, без промежутка перед бывшим расширением C500h. Основной исходник — DOS.asm, состав — layout.json. Рабочие буферы задаются адресами и в DOS.SYS не записываются.

В dos/ находятся FAT, каталоги и пути, файловые операции, FileStream/FileHandle, загрузка программ, локальные физические службы DOS и адаптеры запросов чужих страниц kernel-*.inc. Общий обработчик команд включается из cli/. Весь аппаратный BIOS, рендер и графика находятся в [bios/](../bios/README.md), транспорт и хвосты — в [bootstrap/](../mem/transport.md), общие локально компилируемые примитивы — в [common/](../common/README.md). DOSMOD удалён: его файловые функции связаны с DOS, графические — с BIOS.

Это объём кода с инициализированными данными, а не размер всех занятых DOS буферов. Перед уплотнением файл содержал 14292 байта заполнения между основным кодом и расширением.

## Дисковый кэш

Область 9000h–BFFFh в банке DOS предназначена для кэша и буферов. Единый пул 8 КиБ распределяется между всеми дисками по потребности, без квот и ограничения двумя активными томами. Сектор 128/256/512 байт занимает 1/2/4 соседние выровненные гранулы по 128 байт; один диск может занять весь пул. Таблица и буферы не входят в DOS.SYS. Восьмибайтный описатель головы содержит LBA, адрес данных, слово reference, dirty и tag. В tag младшие три бита задают диск, следующие два — sectorShift−7; 80h..BFh обозначают продолжение с индексом головы, FFh — свободную гранулу. Пересекающиеся головы вытесняются целиком, включая все продолжения.

Вытеснение использует CLOCK: попадание устанавливает reference=1, проход указателя даёт такой голове второй шанс и сбрасывает reference; голова с reference=0 может быть вытеснена. Полный поиск минимального возраста и счётчик времени для каждого попадания не нужны. Перед поиском проверяется последний слот вместе с меткой диска/геометрии; основная таблица просматривается только по индексам, допустимым для размера искомого сектора. Верхняя оценка LBA позволяет сразу отвергать заведомо отсутствующие потоковые сектора. Оценка хранится отдельно для каждого диска, чтобы высокие LBA загруженных программ одного носителя не замедляли прямое чтение другого; после вытеснения она может оставаться завышенной, что влияет только на скорость.

Неполные файловые сектора используют отдельный общий 512-байтный буфер с собственными tag и dirty. Сначала проверяется общий пул, чтобы не создавать две копии одного сектора. При переходе к неполному сектору другого диска прежняя чистая копия может быть заменена; закреплённого буфера на каждый диск нет. Полные сектора передаются напрямую, если в кэше нет более новой копии.

Смена диска сначала сохраняет dirty прежним драйвером; при отказе диск не переключается. Чистые строки всех дисков остаются в общем пуле. Общий признак dirty позволяет не обходить таблицу при переключениях, если изменений нет; для единственной dirty-строки хранится прямой указатель, и flush также обходится без сканирования. Явное перемонтирование после FORMAT/RAW-записи и замена драйвера/ФС инвалидируют только строки соответствующего диска, включая неактивный. Смена размера сектора также инвалидирует его строки. После внешней смены носителя обязателен явный mount. BPB читается в независимый буфер, не повреждая сохранённые строки.

### Измерение кэша

Штатный DISKBEN проверяет последовательную передачу данных: увеличение файла главным образом увеличивает прямой обмен полными секторами и длину цепочки FAT, а не рабочий набор кэша. Для проверки его заполнения и вытеснения используется `python scripts/tests/benchmark-dos-cache-pressure.py --report docs/diskbench/cache-pressure`: он исполняет штатный код DOS в модели Intel 8080 с синтетическим 256-байтным драйвером. Режимы включают рабочие наборы одного, двух и трёх дисков, неравномерное распределение, переполнение общего объёма, повтор одного сектора и запись с переключениями дисков. Прогрев исключён из измерения; сохраняются такты, число запросов, чтений и записей драйвера. Это изолированная оценка кэша, без стоимости монтирования, файлового поиска и реального носителя. Для сравнения иной сборки доступны `--kernel путь/KERNEL.bin` и соответствующий KERNEL.sym рядом. Полные файловые операции отдельно измеряет `scripts/emu80/benchmark-dos-cache.py` через процедуры DISKBEN в собственном видимом Emu80 без звука.

## Потоковые BAT

BAT открывается один раз через внутренний FILE_HANDLE и читается пачками по 512 байт. Размер сценария не ограничен прежним 6-КиБ буфером; позиция файла и смещение начала строки имеют 32 бита. Вложенный запуск BAT возвращается к следующей строке родителя. Восемь кадров по 768 байт занимают прежнюю область D800h–EFFFh: каждый хранит FILE_HANDLE, команду, позицию/остаток буфера, номер строки, её файловое смещение и собственную пачку чтения. COM/EXE в main не затирают эти данные. Программный возврат в оболочку сбрасывает оставшиеся контексты BAT.

Допускается восемь одновременно активных BAT и до 65535 строк в каждом. Командная строка ограничена MAX_PATH−1 (127 байт); переполнение, NUL в тексте, ошибка I/O или команды прерывают выполнение с кодом DOS. Диагностика `BAT ERROR.BAT line 3: error 2` указывает виновный сценарий и строку и печатается один раз при раскрутке вложенных вызовов. CR, LF и CRLF считаются переводом строки; последняя строка без перевода также выполняется. Байт FFh больше не служит маркером EOF. `@` и ECHO ON/OFF сохраняются; подстановка `%1`, CALL и GOTO не добавлялись.

## Сборка и вызовы

`powershell.exe -NoProfile -File scripts/build/build-project.ps1 OS` собирает BIOS/DOS совместно через scripts/build/build-bios-dos.py. BIOS размещается вокруг фиксированных C000h/C800h, DOS собирается последовательно с 0100h. scripts/build/build-banked-dos.py создаёт тот же DOS отдельно для стендов. DOS.native.sys с 4000h — вспомогательный линковочный образ и CPU-модель, в штатную систему не загружается.

В основной памяти приложения располагаются до memtop=8BFFh независимо от DOS. Публичные C800h/F800h/F806h сохраняются; локальная таблица DOS начинается с 0100h, банковый диспетчер — с 015Dh. Исходные NEAR-указатели относятся к странице приложения; их обслуживают kernel-*.inc, а не FAT через чужие адреса. Полные секторы могут идти непосредственно в main через локальные службы A:/B:/H:, частичные — через кэш DOS. Буферизованный путь остаётся для других банков и неподдержанных геометрий.

## Текущее состояние FAT16, 05.11.2026

Слой логических секторов поддерживает 128/256/512 байт поверх физических блоков 128/256/512 байт, если логический сектор не меньше физического. Малые тома с секторами 128/256 байт требуют OEM-сигнатуры `MXOS128 `/`MXOS256 ` и остаются расширениями MXOS. Стандартный FAT16 распознаётся по геометрии 512-байтного сектора, сигнатуре 55h AAh и числу кластеров 4085–65524, а не по строке `FAT16`. Поддерживаются одна или две FAT, несколько резервных секторов и многосекторные кластеры размером до 32768 байт. Адресация ограничена 16-битным LBA и 16-битной физической ёмкостью драйвера; разделы пока не поддерживаются.

При монтировании проверяются BPB_Media и первые две служебные ячейки FAT; неправильный BPB даёт DOS_ERR_UNSUPPORTED, повреждённый заголовок FAT — DOS_ERR_CORRUPT, отказ чтения — DOS_ERR_IO. Старшие два бита FAT[1] принимаются как флаги clean/error, а не как часть обязательного значения FFFFh. Их обновление при записи пока не реализовано. Ненулевой FstClusHI у найденного файла отклоняется в обеих сборках ядра.

Корень имеет фиксированный размер и общий ограниченный курсор; подкаталог обходит тот же код по цепочке кластеров. При замене маркера конца 00h создание файла переносит его на следующую запись, в том числе через границу сектора; содержимое после прежнего конца не считается файлами. Повторное использование E5h сохраняет следующие живые записи. Первое API каталогов описано ниже; LFN пока нет. Форматирование и сборщик образов по-прежнему создают малые MXOS-256; стандартное форматирование FAT16 — отдельный следующий шаг. COM/EXE хранят адрес загрузки в собственном заголовке, стандартные поля FAT для адреса больше не используются.

## Каталоги: первый этап

`bios_directory` (C8DEh) находится в резидентном ядре: общий обход нужен также загрузке и сохранению файлов. A выбирает операцию, CF/A возвращают числовой статус DOS; AF/BC/DE/HL считаются разрушенными. Служба поддерживает пока только встроенный FAT-том. Корень обозначается кластером 0. Для каждого диска сохраняется свой текущий каталог; после замены носителя сохранённые номера каталогов недействительны.

| A | Операция | Параметры и результат |
|---|---|---|
| 0 `DIR_OP_GET` | Получить текущий каталог | DE=кластер, 0 для корня |
| 1 `DIR_OP_SET` | Восстановить контекст | DE=номер каталога, ранее полученный GET на этом томе; это не проверка произвольного кластера на принадлежность каталогу |
| 2 `DIR_OP_CHDIR` | Перейти по пути | HL=полный буфер `MAX_PATH` байт с ASCIIZ-путём; буфер не изменяется |
| 3 `DIR_OP_LIST` | Список файлов и каталогов | HL=буфер FILE_INFO, DE=ёмкость, BC=начальный индекс; DE=общее число записей, как у fileList; . и .. включаются |
| 4 `DIR_OP_GETCWD` | Текстовый путь | HL=MAX_PATH-буфер, ASCIIZ, нужен DOSMOD |
| 5 `DIR_OP_COMMAND` | CD/CHDIR | HL=команда; A=FFh/CF=0, если не распознана |
| 6 `DIR_OP_RESOLVED` | Временный контекст имени | DE=каталог, разрешённый последним fileNamePrepare; не восстанавливает сохранённый CWD |

`MAX_PATH=128` включает завершающий 0. Буфер выделяет вызывающая программа; в DOS нет массива строк путей для каждого диска. Максимальная длина строки — 127 байт. Путь без начального разделителя относительный, `/` или `\` в начале выбирает корень; разделители равнозначны, поддерживаются `.` и `..`. Компоненты имеют формат 8.3, длинное имя, запрещённый символ и отсутствие терминатора возвращают DOS_ERR_ARGUMENT, отсутствующий компонент — DOS_ERR_NOT_FOUND, обычный файл вместо каталога — DOS_ERR_ACCESS. Допускается префикс диска, например H:\Almaz\STD. При отказе CHDIR сохраняются прежние диск и каталог.

После CHDIR обычные компактные файловые операции и FileHandle работают в выбранном каталоге; они используют общий обход, без второго алгоритма поиска/создания. Прежний fileList выдаёт только файлы; NC использует DIR_OP_LIST с каталогами. Общий обход ограничен числом кластеров тома, BAD/недопустимая ссылка и цикл возвращают DOS_ERR_CORRUPT. Открытый FileHandle сохраняет сектор и смещение своей записи и может закрываться после смены текущего каталога.

Системные NC.COM, шрифт и CLI.EXT открываются из корня A: независимо от пользовательского каталога. Подготовка имени принимает явный корень `A:\ИМЯ.EXT`, не меняя сохранённый текущий каталог диска; fileNamePrepare разбирает также вложенный полный путь, сохраняя исходную строку и возвращая HL у разделителя после имени. CF сообщает ошибку пути; вызывающий обязан проверить CF до файловой операции. Временный контекст родителя действует до выбора диска или вызова bios_directory; DIR_OP_RESOLVED позволяет получить его без сброса. FORMAT после записи перемонтирует том и выбирает корень.

MKDIR/RMDIR реализованы в DOS. При заполнении подкаталога DOS добавляет нулевой кластер к его FAT-цепочке; корень остаётся фиксированным и возвращает DOS_ERR_DIR_FULL. C SDK предоставляет MAX_PATH-буфер, CHDIR и список; `fopen` пока принимает имя 8.3 в выбранном каталоге, без вложенного пути.

GETCWD (A=4, HL=буфер MAX_PATH) возвращает абсолютный ASCIIZ-путь с буквой диска и обратными косыми чертами, например `H:\Almaz\STD`. Реализация находится в DOS и восстанавливает имена по цепочке `..`, не меняя текущий каталог. Неумещающийся путь возвращает DOS_ERR_ARGUMENT. Буфер при ошибке не содержит гарантированного полного пути.

COMMAND (A=5, HL=строка команды) обрабатывает CD и CHDIR через тот же CHDIR; без аргумента печатает текущий путь. A=FFh, CF=0 означает неизвестную встроенную команду; иначе A/CF задают статус DOS. Сервис используется NC и fileExec, поэтому доступен BAT через файловое ядро DOS. Расположение BAT не меняет рабочий каталог команд; сценарий должен выполнить CD либо использовать абсолютные пути. Самостоятельный CLI.COM использует тот же обработчик.

Для файлов и каталогов действует единый формат 8.3: восемь символов имени и необязательные три символа расширения; 11 подряд не допускаются. Входные пути допускают оба разделителя `/` и `\`, включая смешанные пути. GETCWD, NC и поставляемые BAT формируют `\`. EXE, COM, SYS и BAT сохраняют привычные расширения; это не обещание двоичной совместимости с MS-DOS.

FILE_COPY_REQUEST занимает 86 байт: sourceDirectory по смещению 80 и destinationDirectory по смещению 82 — 16-битные контексты каталогов соответствующих дисков, 0 означает корень. Они обязательны и позволяют копировать между двумя каталогами одного диска. Поле onExists по смещению 84 содержит адрес обработчика совпадений (0 — отказ EXISTS). Обработчик получает HL=запрос, возвращает A=0 для пропуска, A=1 для замены, A=2 для Yes to all или A=3 для No to all, CF=0; CF=1 отменяет операцию. Обработчик может выводить интерфейс и читать клавиатуру, но не вызывает файловые службы DOS/CLI. Все программы и C-запросы необходимо пересобрать с текущим mxos.inc/SDK.

## Ошибки файловых операций

CF=1 означает отказ. Прежние результаты A отдельных вызовов сохранены; подробную причину возвращает `bios_getError` (C8C9h): A=код, CF=1 при ненулевом коде, BC/DE/HL сохраняются. Чтение причины её не сбрасывает. Новая операция через диспетчер томов сбрасывает прежнюю причину; успешный возврат очищает её. При копировании причина сохраняется через очистку назначения и восстановление диска. Ядро не печатает обязательное сообщение и не спрашивает о повторе: это политика NC/CLI.

| Код | Константа | Причина |
|---:|---|---|
| 0 | — | Успех |
| 1 | DOS_ERR_IO | Отказ физического чтения/записи/барьера |
| 2 | DOS_ERR_NOT_FOUND | Файл не найден |
| 3 | DOS_ERR_EXISTS | Назначение существует |
| 4 | DOS_ERR_FULL | Недостаточно кластеров |
| 5 | DOS_ERR_DIR_FULL | Корневой каталог заполнен |
| 6 | DOS_ERR_ACCESS | Запрещено атрибутами |
| 7 | DOS_ERR_ARGUMENT | Недопустимый аргумент |
| 8 | DOS_ERR_CORRUPT | Недопустимая цепочка кластеров |
| 9 | DOS_ERR_NO_DRIVER | Нет физического драйвера |
| 10 | DOS_ERR_UNSUPPORTED | Неподдерживаемый/некорректный формат тома |
| 11 | DOS_ERR_BAD_IMAGE | Некорректный исполняемый образ (DOS4000) |

Dirty-флаг кэша снимается только после успешной записи; неудачное вытеснение не загружает другой сектор поверх несохранённого. Неудачный flush запрещает переключение диска; повторный flush может завершить запись. Это не журналирование: уже записанные секторы не откатываются. Курсор корня/подкаталога общий для поиска, списка и создания; корень ограничен точным числом записей и корректно работает с неполным последним сектором. Обычный список и поиск файлов пропускают LFN, метки и каталоги; bios_directory предоставляет CHDIR и список с каталогами. Счётчик свободных кластеров не включает резерв и запас FAT. `bios_fileGetSetAttr`: C=1 устанавливает атрибуты из B; A возвращает атрибуты, CF сообщает ошибку сохранения. DEBUG и очистка копии используют тот же контракт.

## Исторические карты и драйверы

Следующие записи описывают систему до общего MEM. Штатный RAM-диск теперь использует фиксированный пул во владении DOS и общий транспорт; одноразовый RAMDISK.COM подготавливает том и передаёт пул ядру; R3/R4 и селектор старых окон поверх MEM не устанавливаются. Актуальные карты находятся в начале документа, API памяти и резидентов — в [MEM API](../mem/api.md).

С 03.11.2026 карта расширена: DOS — C000h–DFFFh (8 КиБ), строка — E000h–E081h, стек — E082h–E1FFh (SP=E200h), шрифт — E200h–E9FFh. Верхние утилиты занимают EA00h–F3FFh, E.COM загружается по 0000h. FLASHSYS — F400h–F53Fh, RAMD — F540h–F5FFh, внешний драйвер — F600h–F7FFh; в STD файловые операции не выполняются. Кэш остаётся FB00h–FEFFh. Точки входа DOS сохранены; адреса из ранних записей ниже относятся к истории.

С 02.11.2026 в DOS перенесён [графический модуль](ui/README.md) с отдельными входами C8A8h–C8B1h: окна, инверсия, строка F-клавиш и копирование прямоугольника битмапа через штатный memcpy. DOS получил область до DBFFh; командная строка DC00h–DC81h, стек DC82h–DDFFh (SP=DE00h). Резиденты FLASHSYS/RAMD занимают DE00h–DFFFh, внешний драйвер E000h–E1FFh, шрифт E200h–E9FFh, верхние утилиты начинаются с EA00h, NC.COM загружается по 0000h вместе с собственными буферами. Размеры командной строки и стека сохранены. Приведённые ниже записи о прежней карте относятся к истории; действующие адреса задаёт `source/include/mxos.inc`.

До установки внешнего [RAMDISK.COM](../ramdisk/README.md) DOS обслуживает RAM-диск встроенным блочным драйвером R3, целиком помещающимся в общее 32-байтное окно. Поэтому первоначальный FORMAT.BAT не использует побайтовый секторный адаптер. Штатный AUTOEXEC затем устанавливает быстрый R4; ручная установка также доступна.

ABI C86Fh сохраняет все регистры и флаги: `RAMD_DRIVER_RESTORE=0` восстанавливает обычный шаблон, `BYTE=1` временно включает побайтовый доступ, `REGISTER=2` регистрирует резидентный 32-байтный шаблон HL без изменения текущего окна, `BLOCK=3` временно выбирает встроенный R3, `USER=4` применяет зарегистрированный шаблон. До регистрации RESTORE и USER выбирают R3. BYTE и BLOCK не отменяют регистрацию R4; после сервисных обращений перед секторными операциями требуется RESTORE. Регистрация физического драйвера накопителя через C860h остаётся отдельной операцией.

Эксперимент с переносом стека под переменные BIOS отменён 01.11.2026. После переноса графики и NC использовался стек `DC82h–DDFFh`, `SP=DE00h`. Прежний стек у `FFC0h` в STD недоступен. Начальный `bios_getMemTop` возвращает `8FDEh`.

## Командная строка и BAT

Командная строка `CMD_LINE` принадлежит DOS и используется NC. BAT исполняет резидентный код DOS: перед каждой строкой он заново читает метаданные и весь сценарий в нижний временный буфер, затем передаёт команду общему загрузчику. Этот буфер может быть затёрт внешней программой. Полноценного CLI, встроенных команд DIR/COPY/RENAME/DELETE/CD и сохранённого файлового контекста сценария пока нет. Первое API подкаталогов уже доступно, но само по себе не добавляет команды CD/DIR в строку NC.

## Общие файловые операции NC и CLI

После `bios_argNext` размещена плотная группа JMP. Старые адреса сохранены; переименование и удаление повторно используют существующий диспетчер тома. Сервисы не зависят от NC и не выводят его диалоги.

| Адрес | Вход | Параметры и результат |
|---|---|---|
| C8BAh | bios_fileSelectDrive | A=диск 0..7; BC/DE/HL сохраняются, CF=ошибка выбора/монтирования |
| C8BDh | bios_fileRenameOnDrive | HL=старое, DE=новое компактное имя на текущем диске; CF=ошибка |
| C8C0h | bios_fileDeleteOnDrive | HL=компактное имя на текущем диске; CF=ошибка; R/S защищены ядром |
| C8C3h | bios_fileCopy | HL=FILE_COPY_REQUEST; CF=0,A=0 — готово; CF=1,A=1 — ошибка, A=2 — назначение существует |
| C8C6h | bios_fileGetDrives | HL=буфер, BC=его ёмкость в байтах (не менее 8); B=число номеров 0..7, CF=ошибка |

`fileSelectDrive` не маскирует ошибочный номер выше 7. Он сохраняет прежнюю семантику выбора тома: при отказе монтирования выбранный диск может измениться. Копирование и перечисление дисков восстанавливают исходный диск перед возвратом. Переименование сохраняет прежнюю политику замены назначения; копирование никогда не заменяет существующий файл, включая тот же источник и другое написание регистра его имени. `fileNamePrepare` C85Ah остаётся общим сервисом преобразования текстового имени в компактное 8.3.

`FILE_COPY_REQUEST` занимает 76 байт в обычном ОЗУ вызывающей программы:

| Смещение | Поле | Размер |
|---:|---|---:|
| 0 | buffer — 0 во внешнем запросе; локальный адрес внутри DOS | 2 |
| 2 | bufferSize — 0 во внешнем запросе; локальная ёмкость внутри DOS | 2 |
| 4 | sourceDrive | 1 |
| 5 | destinationDrive | 1 |
| 6 | source — полный дескриптор; до вызова достаточно первых 11 байт имени | 32 |
| 38 | destination — дескриптор назначения; до вызова достаточно имени | 32 |
| 70 | sourceCluster — рабочее поле DOS | 2 |
| 72 | destinationCluster — рабочее поле DOS | 2 |
| 74 | blocksLeft — рабочее поле DOS | 2 |

DOS заполняет метаданные источника, переносит их в назначение и изменяет рабочие поля запроса. Во внешнем FILE_COPY_REQUEST поля buffer и bufferSize не используются: вызывающий задаёт нули, банковый адаптер подставляет собственный KD_DATA и KD_CHUNK (4096 байт), а при возврате и в обработчике подтверждения выдаёт нули. Запрос и адрес обработчика проверяются на доступность в памяти клиента. Внутренний fileCopy по-прежнему получает локальный буфер с ёмкостью не менее 256 байт; этот буфер принадлежит DOS и не пересекается с запросом.

Например, после заполнения имён и номеров дисков вызов из COM выглядит так:

```asm
        ld      hl, 0
        ld      (copyRequest.buffer), hl
        ld      (copyRequest.bufferSize), hl
        ld      hl, copyRequest
        call    bios_fileCopy
        jp c,   operationFailed
        ; Продолжение программы, затем RET.

; Области выделены после кода вызывающей программы.
copyRequest FILE_COPY_REQUEST
myBuffer    BLOCK 1024
```

Источник и назначение могут находиться на разных дисках. Перенос использует `fileCreatePrepare` и общий `fatStream`, переключая том один раз на чтение и один на запись порции. Размер файла сохраняется точно; пустой файл не получает кластер. При ошибке после создания DOS пытается удалить незавершённое назначение, предварительно сняв у него унаследованную защиту R/S. Невозможность очистки при отказе носителя остаётся ошибкой вызова. Все перечисленные файловые сервисы требуют режима MX и не реентерабельны. AF/BC/DE/HL разрушаются копированием и перечислением; остальные контракты переименования/удаления соответствуют прежним входам.

Проверки: `scripts/tests/check-file-operations.py`, `scripts/emu80/check-file-operations.py --runtime <свой-runtime>`. Отчёт с проверкой F5/F6/F8 и выбора диска через клавиатуру: `docs/dos/file-ops-004/report.md`.

## Общие ассоциации файлов

`bios_fileAssociation` (`C8B4h`) ищет запись в системном `A:CLI.EXT` независимо от NC. Вход: HL — три байта расширения, DE — временный буфер, BC — ёмкость. Буфер выровнен на 256 байт, ёмкость ненулевая и кратна 256; весь диапазон находится в обычном ОЗУ и не пересекается с кодом/данными вызывающего, расширением, стеком и DOS. Размер проверяется до чтения: N должен быть меньше ёмкости, оставляя место для FF после точных данных. CF=0 возвращает HL на команду до CR/FF внутри буфера; CF=1 означает отсутствие записи или ошибку. AF/BC/DE/HL и флаги разрушаются; исходный диск восстанавливается во всех случаях.

Формат строки — три байта расширения, пробел, команда и CR; регистр расширения не учитывается. Последняя строка может заканчиваться концом файла. Некорректный разделитель и пустая команда пропускаются. Временный результат нужно перенести в общую системную `CMD_LINE` до загрузки COM, которая затирает нижнее ОЗУ. Постоянный буфер или кэш под CLI.EXT не выделен. Будущий CLI сможет передать собственную свободную область, а NC передаёт свой буфер копирования после кода.

Все новые входы добавлены плотными JMP в таблицу C800h: C8A8h/C8ABh/C8AEh/C8B1h — графика, C8B4h — ассоциации, C8B7h — обход аргументов. Адреса реализаций не являются ABI. Командная строка NC остаётся общей с DOS по DC00h. При загрузке системного COM запрещено попадание в DOS, командную строку и стек C000h–DDFFh.

Проверки: `python scripts/tests/check-file-association.py`, `python scripts/tests/check-ui-abi.py`, `python scripts/tests/check-dos-layout.py`. NC по 0000h, его файловые операции и переход в редактор по TXT проверяются отдельно в видимом Flash-профиле Emu80.

## Три уровня

1. Прежние файловые точки DOS вызывают диспетчер из `volume.inc`.
2. Для каждой буквы A:–H: отдельно регистрируются файловая таблица и контекст. По умолчанию все буквы используют `fatVolumeDriver` — старый формат MXOS.
3. Физический драйвер выбирается прежним способом через `bios_installDriver` и `bios_diskDriver`. Регистрация файловой системы его не заменяет.

`fileSelectDrive` выбирает обе таблицы и вызывает mount файлового драйвера. При повторном выборе той же буквы автоматического mount нет; для этого предназначен отдельный вызов. Модуль использует физический ABI для блоков, а не вызывает внутренние FAT-процедуры DOS.

## Регистрация и срок жизни

| Вход | Контракт |
|---|---|
| `bios_installVolume`, C890h | A=0…7, HL=таблица, DE=контекст (или 0). BC/DE/HL сохраняются. CF=1 при неверном индексе, заголовке или нулевом обработчике. Для активной буквы возвращается результат mount; регистрация при его отказе уже выполнена. |
| `bios_getVolume`, C893h | A=0…7 → HL=таблица, DE=контекст; BC сохраняется. CF=1 при неверном индексе. Диск не переключается. |
| `bios_mountVolume`, C896h | Повторно монтирует текущий том. BC/DE/HL сохраняются, AF возвращается от mount. |
| `bios_flushVolume`, C899h | Вызывает flush текущего тома; AF и остальные выходы определяет обработчик. CF=1 означает отказ. |

Таблица: `DB "FS",1,15`, затем 15 ненулевых адресов `DW`, всего 34 байта. Ошибочный или неподдерживаемый вызов должен иметь настоящий обработчик отказа. Версия и число обработчиков проверяются при регистрации; адреса и срок жизни памяти гарантирует загрузившая модуль программа. Таблица не копируется.

Модуль и его контекст должны переживать вызовы NC и пользовательских программ. Буфер копирования NC `0000h–7FFFh` для постоянного размещения не подходит. В этой подготовке нет распределителя памяти и автоматической загрузки модулей. После подмены ядра и возврата в MXOS модули/контексты регистрируются заново: указывать на затёртый код прежнего ядра нельзя.

Перед заменой активного драйвера или сменой тома вызывающая сторона должна закрыть операции и вызвать flush. Переключение пока сбрасывает старый секторный кэш; его исторические ошибки записи перечислены в аудите. Это ещё не гарантия безопасного сброса данных при ошибке устройства.

## Что требуется до подключения RAMFOS

Версия 1 сохраняет `FILE_DESCRIPTOR`/`FILE_INFO`, имена 8+3, точный размер N ; кластерный поток C88Dh удалён. RAMFOS имеет собственный формат и имена 9+3; полной совместимости средствами этой таблицы ещё нет.

Нужен общий байтовый поток open/read/write/close/abort с 32-битной длиной и непрозрачным состоянием файла. После перевода F5 на этот интерфейс модуль RAMFOS сможет реализовать файловые операции своим обходом каталога и данных, не изображая FAT-цепочки. Формат общих сведений о томе тоже нужно отделить от FAT-геометрии `DISK_INFO`; сейчас это историческая структура.

FORMAT пока работает напрямую с блоками старого FAT-формата. До установки настоящего модуля RAMFOS надо добавить выбор или запрет форматировщика по типу тома, чтобы FORMAT не мог затереть чужую файловую систему.

Отдельно нужны резервирование страниц, общая таблица логических/физических страниц для MXOS и RAMFOS, проверки всех границ и исключение flash из доступных RAMFOS устройств. Само разделение таблиц страниц не резервирует.

## Потоковая передача и физический flush

Кластерный перенос удалён. C88Dh зарезервирован и возвращает числовой DOS_ERR_UNSUPPORTED; остальные адреса ABI сохранены. Все программы используют байтовый FileStream C8D2h, запись завершается явным bios_flushVolume.

При B=1 `fatFileTransferClusters` завершает переданную партию одним `fatFlushPhysical`; в секторном цикле B=4 не вызывается. Обычный `bios_fileCreate` после этого сохраняет кэш FAT/каталога и вызывает `fatFinishWrite` с ещё одним барьером. У FlashFst получается два B=4 на файл. NC передаёт данные партиями до 32 КиБ, поэтому его потоковые записи завершаются барьером после партии, а не после каждого сектора.

Полная проверка файла в DISKBEN выполняется на уровне приложения: сначала обычная запись B=1 и штатное завершение, затем чтение через DOS/Raw в верхнее окно и побайтовое сравнение с исходным буфером. Физическая B=5 остаётся самостоятельной посекторной операцией и проверяет также метаданные, если вызывающая сторона использует её для FAT/каталога.

## COM/EXE и точные размеры файлов, 02.11.2026

DOS непосредственно исполняет COM с 16-байтным заголовком: адреса загрузки и входа, ненулевой размер, штатные суммы нагрузки и заголовка. EXE использует тот же контейнер, но исполняется через CLI.EXT и RUN.COM; DOS не запускает его скрытно. RKS передаётся тому же RUN с сохранением стандартного контейнера. Подробности — в [описании RUN](../run/README.md).

В записи каталога DIR_FileSize хранится точный N вместо N−1; 12h–13h снова дата доступа. Адреса загрузки из FAT удалены. C845h принимает HL=дескриптор, DE=исходный буфер; нулевой файл создаётся без кластера. Полная стандартность FAT16 этим изменением не достигается; внутренние образы требуют пересборки.

`bios_imageOpen` (C854h) открывает только родной COM/EXE MXOS: HL=дескриптор, выход HL=вход, DE=загрузка, BC=длина тела. `bios_fileLoad` (C848h) читает подготовленное тело в DE и проверяет сумму. Контекст внутренний, действителен до следующей файловой операции. RKS и другие внешние контейнеры обрабатывает RUN через общие файловые функции.

C848h (`bios_fileLoad`): DE=адрес назначения. Переносит остаток первого сектора, читает полные секторы тела прямо по месту через общий FileStream, копирует последний точный хвост из кэша. Для COM/EXE проверяет тело и возвращает HL=вход, CF=ошибка. Заголовок COM/EXE и секторное заполнение не записываются в программу. Экран и нижнее ОЗУ не используются как промежуточный контейнер. Пара C854h/C848h использует существующий временный дескриптор DOS; между вызовами нельзя выполнять другую файловую операцию или менять том. Прямой клиент C848h отвечает за допустимый диапазон назначения и отсутствие пересечения с DOS, стеком и кэшем.

Верхний COM-драйвер для F600h–F7FFh — отдельный случай: DOS читает только тело в нижнее ОЗУ, восстанавливает исходный том, затем копирует тело по месту и запускает установщик. Иначе чтение могло бы затереть ещё используемый драйвер.

`bios_calcCS` сохраняет алгоритм и регистровый результат Monitor-2, включая флаги. Цикл развёрнут по четыре байта, сравнения встроены и выполняются на границах блоков; хвост обрабатывается скалярно. Последняя копия тела блока общая со скалярным путём: 54 байта вместо экспериментальных 64. На CPU 8080 2 МГц 8 КиБ проверяются примерно за 0,212 с, 24 КиБ — за 0,628 с; это модель CPU, без чтения диска.

## Короткие системные команды

Имя команды без диска и расширения исполняется как `A:ИМЯ.COM`, без поиска BAT/EXE и без перебора дисков. Полный путь и расширение по-прежнему задаются явно. Это правило действует в bios_fileExec, поэтому доступно из NC, BAT и других клиентов DOS.

Для короткой команды DOS сохраняет исходный том, читает COM с A:, проверяет его тело, затем восстанавливает том до входа. Таким образом, `run BUDI-RF.exe` с H: открывает A:RUN.COM, а RUN ищет игру на H:. При отказе исходный том тоже восстанавливается. Аргументы в CMD_LINE не переписываются и передаются в прежнем виде.

Чтобы сохранить размер ядра, имена команды и BAT занимают по 11 байт, а временные хвосты дескрипторов перекрываются с последующими буферами. Полная независимая запись найденного файла остаётся в v_tmpFileDescr. BAT заново читает метаданные перед каждой строкой. Копирование атрибутов идёт вперёд в более низкие адреса, поэтому перекрытие безопасно. Также устранены повторное вычисление адреса поля размера в сыром загрузчике и ненужное промежуточное сохранение размера при создании файла.

NC перед исполнением выбирает диск активной панели: вывод противоположного каталога больше не определяет диск относительных аргументов. Проверено из A:, H: и B:, а также двумя строками BAT. Совокупный машинный код DOS+NC вырос на 1 байт: DOS 6656→6646, NC 3997→4008; число занятых ими секторов образа не изменилось.


## Поток FileStream (MXOS2, C8D2h)

`bios_fileStream` использует общий секторный движок DOS. Это низкоуровневый доступ к уже выделенной цепочке активного FAT-тома, основа будущего API открытых файлов. Редактор и DEBUG пока не переведены на него.

| Параметр | Вход | Выход |
|---|---|---|
| A | 1 — запись, 2 — чтение | Код DOS, 0 при успехе |
| DE | Адрес `FILE_STREAM_CURSOR` | Сохранён |
| HL | Адрес буфера | Адрес первого непереданного байта |
| BC | Число байтов, 0 означает пустую передачу | Фактически передано |
| CF | — | 1 при ошибке, причина также в `bios_getError` |

Курсор занимает четыре байта у вызывающей программы: слово `cluster`, затем слово `offset`, оба little-endian. Начальное состояние — первый кластер файла и смещение 0. После вызова курсор сохраняет позицию продолжения, в том числе при частичном отказе. Смещение, равное размеру кластера, означает отложенный переход по FAT после ошибки чтения цепочки; повторный вызов повторяет переход. Курсор относится к конкретному тому: перед продолжением нужен тот же том.

Буфер и курсор должны быть доступны для записи, не пересекаться между собой, с DOS/кэшем и не переходить через конец адресного пространства. Размер буфера должен быть не меньше входного BC. Вызов нереентерабелен; обычный режим DOS — с запрещёнными прерываниями. Программа ограничивает передачу длиной файла сама: этот примитив не проверяет атрибуты, не выделяет кластеры и не обновляет размер в каталоге. Запись может остаться в кэше; для сохранения на носителе обязателен `bios_flushVolume` с проверкой ошибки. Переданные байты при отказе не откатываются. Это не готовые `fopen/fread/fwrite/fclose` и не обработчик стороннего драйвера тома.

Проверка ABI на модели CPU 8080: `python scripts/tests/check-fat-repair.py --stream-only`. Проверяются переход между кластерами, продолжение, запись/flush, частичный отказ и повтор, некорректные параметры и нулевая длина. Общий переход на логические секторы ещё проходит отдельную интеграционную проверку.


## Логические секторы (04.11.2026)

Файловые функции получают геометрию из BPB. Поддерживаются логические
секторы 128/256/512 байт и кластеры из нескольких секторов (степень двойки,
до 32768 байт на кластер). Физический блок задаётся отдельно при установке
драйвера. Логический сектор может равняться блоку либо состоять из нескольких
блоков; сектор меньше аппаратного блока отвергается, скрытого RMW нет.
Существующие драйверы и образы остаются 256-байтными.

| Вход ABI | Контракт |
|---|---|
| `bios_installBlockDriver`, C8CCh | A=диск 0..7, HL=драйвер, C=7/8/9 для физического блока 128/256/512; выход HL=DISK_INFO, BC/DE сохранены, CF=ошибка |
| `bios_sectorIO`, C8CFh | B=1 запись/2 чтение, DE=логический LBA, HL=буфер полного сектора; BC/DE/HL сохранены, CF=ошибка |
| `bios_fileStream`, C8D2h | Поблочная передача с байтовой позицией, контракт выше |

Прежний `bios_installDriver` устанавливает физический блок 256 байт.
Перед заменой драйвера вызывающая программа сохраняет старый том через
`bios_flushVolume`, после замены вызывает `bios_mountVolume`. Физический B=3
возвращает DE=число аппаратных блоков, BC=подсказка чередования/барьера записи;
B=1/2 передаёт ровно один аппаратный блок с сохранением BC/DE/HL.
Встроенный загрузочный ROM-драйвер — историческое исключение: его ёмкость
берётся из 256-байтного BPB после чтения нулевого блока. Новые драйверы
должны сообщать физическую ёмкость независимо от монтирования файловой системы.
При объединении блоков чередование отключается, но барьер B=4 сохраняется.

`bios_sectorIO` проверяет номер сектора и режим; размер и доступность буфера
обеспечивает вызывающая программа. Это сырой доступ: перед ним надо сохранить
файловый кэш, после внешней записи перемонтировать том. Обычные программы
используют файловые функции, чтобы не нарушать согласованность кэша.

Кэш данных остаётся 1024 байта: 8/4/2 строки; таблица описаний рассчитана на
8 строк. Полные выровненные секторы FileStream читает прямо в буфер, если их
нет в кэше. При попадании используется актуальная копия, включая грязную.
Крайние части секторов и полная запись при попадании в кэш проходят через кэш. Полная запись при промахе идёт прямо из буфера. Копирование файла
использует точное число байтов последней партии и явно сохраняет результат.

Для малых нестандартных томов требуются OEM-метки `MXOS128 ` / `MXOS256 `.
512-байтный том требует подписи 55AA и числа кластеров FAT16, поддерживается
одна или две FAT с зеркалированием записи. Старые образы не преобразуются.
Свободная запись FAT — 0000h; BAD — FFF7h; EOC — FFF8h..FFFFh (при создании
записывается FFFFh). Ссылки 0001h и FFF0h..FFF6h не являются кластерами данных.
Полное чтение обычного файла и загрузка образа проверяют конец цепочки;
FileStream сам не знает размера файла, который ограничивает вызывающий код.

Что ещё требуется для полноценной совместимости с MS FAT16:

- 32-битные LBA/ёмкости и смещения разделов: сейчас максимум 65535 логических
  секторов, TotSec32 принимается только при нулевом старшем слове; MBR не разбирается.
- Политика корректных дат/времени, clean-shutdown/hard-error флаги FAT[1],
  проверки восстановления после отказа питания и совместимости с внешним fsck.
- Форматирование стандартных носителей: FORMAT пока создаёт прежний MXOS-256.
  Реальные драйверы дискет/SD и отдельный вариант AT29C010 с блоком 128 байт
  пока не реализованы; новый секторный слой проверен с моделями таких драйверов.
- Секторы 1024/2048/4096 байт, допускаемые FAT, пока не поддерживаются.

FAT12 для малых стандартных носителей — отдельный следующий этап, не часть
этого изменения. KOI-8 в именах остаётся соглашением MXOS; кодировка имён
при обмене с DOS/Windows требует отдельного решения. LFN не реализован,
его записи пропускаются; отсутствие LFN само по себе не мешает FAT16 с 8.3.

Проверки: `check-fat-repair.py --logical-only`, `--stream-only`, основной
набор и банковый вариант DOS; `check-image-stream.py`, `check-run-bridge.py`,
проверки размещения и собственный видимый Emu80. Это модели CPU/эмулятор,
не проверка физических 128/512-байтных носителей.


`bios_fileCreatePrepare` (C88Ah): HL указывает на FILE_DESCRIPTOR с точной
32-битной длиной. Число кластеров теперь вычисляет ядро по геометрии тома;
переданный DE не задаёт число кластеров. Кластерного переноса больше нет; используйте FileStream.


Полные секторы FileStream передаёт напрямую между буфером и драйвером,
если соответствующего сектора нет в кэше. При попадании используется
актуальная копия, включая грязную; частичная запись сохраняет остальные
байты через кэш. Окончательный flush остаётся обязательным: он завершает
метаданные, частичные/попавшие в кэш записи и физический барьер драйвера.


RKS полностью принадлежит RUN: ядро не разбирает его заголовок, не читает
специальный хвост и не возвращает RKS-контекст. Для системных утилит
FileStream также допускает их собственные буферы и курсор в F000h–F5FFh;
DOS, драйверы и кэш в разрешённые диапазоны не входят.


Ускорение после локализации регрессии (04.11.2026): внутренние поиски,
перечисление и выбор свободной записи корня получают сектор один раз и
проходят его записи по указателю. Во время такого прохода между двумя
fatDirNext нельзя выполнять другие операции с секторным кэшем; это
внутренний контракт трёх циклов DOS, отдельного публичного итератора нет.
На границе сектора адрес заново берётся из кэша. Точный предел RootEntCnt
и неполный последний сектор, фильтры 00h/E5h/LFN/меток сохранены.

## Открытые файлы

`bios_fileHandle`: A — операция, HL — адрес 64-байтного FILE_HANDLE. AF/BC/DE/HL разрушаются; CF=1 и A=код DOS при ошибке, A=0/CF=0 при успехе. Все остальные входы и результаты находятся в объекте вызывающей программы. Вызовы нереентерабельны; активным остаётся диск файла. Реализация обслуживает FAT, сторонний драйвер тома получает `DOS_ERR_UNSUPPORTED`.

| Смещение | Размер | Поле |
|---|---:|---|
| 0 | 32 | Копия FILE_DESCRIPTOR; до OPEN задаются первые 11 байт имени 8.3 с пробелами, байты KOI-8 сохраняются |
| 32 | 4 | Текущая позиция, little-endian |
| 36 | 4 | Внутренний курсор «кластер + смещение» |
| 40 | 1 | Диск 0–7 |
| 41 | 1 | Режим: READ=1, WRITE=2, CREATE=4, TRUNCATE=8, APPEND=16 |
| 42 | 1 | Состояние: 46h — открыт, 0 — закрыт |
| 43 | 1 | Накопленный код ошибки; очистить явно, как clearerr |
| 44 | 1 | EOF; SEEK и clearerr сбрасывают |
| 45 | 4 | Внутренние сектор и смещение записи каталога |
| 49 | 2 | Адрес буфера для READ/WRITE |
| 51 | 2 | На входе число байтов; на выходе фактически передано, включая частичный отказ |
| 53 | 4 | Signed int32 смещение SEEK; рабочее поле изменяется вызовом |
| 57 | 1 | Начало SEEK: SET=0, CUR=1, END=2 |
| 58 | 5 | Внутреннее состояние цепочки, резерв и действительность курсора |
| 63 | 1 | Код операции для C-переходника; процессорный ABI принимает его в A |

Перед OPEN обнулить объект и заполнить имя, диск и режим. Повторный OPEN открытого объекта запрещён; CLOSE при ошибке оставляет его открытым для повторной попытки. Нельзя одновременно изменять один файл через несколько объектов, удалять/переименовывать открытый файл, менять его том или извлекать носитель. Дескрипторы разных файлов можно чередовать; постоянные данные каждого находятся в самом FILE_HANDLE, а не в общем кэше.

| A | Операция | Поведение |
|---:|---|---|
| 0 | OPEN | Открыть; CREATE разрешает новый файл, TRUNCATE обнуляет существующий, WRITE проверяет Read-only |
| 1 | READ | Не читает за размер файла; короткое чтение/чтение за EOF выставляет EOF без ошибки |
| 2 | WRITE | Перезапись и расширение с выделением кластеров; APPEND перед каждым непустым запросом выбирает конец |
| 3 | SEEK | 32-битный SET/CUR/END, отрицательная итоговая позиция и переполнение отвергаются; само перемещение не выделяет кластеров |
| 4 | FLUSH | Сохранить данные/FAT, затем первый кластер и размер в каталоге, выполнить физические барьеры |
| 5 | CLOSE | FLUSH для записи и закрытие только при успехе |

Разрешены буферы/объекты в прикладном ОЗУ до memtop, в принадлежащих вызывающему кадрах системного стека и в допустимом резидентном окне RUN. Буфер и объект не пересекаются; буфер не должен захватывать активные кадры BIOS/DOS. Размер запроса ограничен 16 битами и непрерывной доступной памятью, размер и позиция файла — 32 битами. Фактическая ёмкость тома по-прежнему ограничена нынешним 16-битным LBA.

После SEEK за EOF запись выделяет промежуточные кластеры; содержимое промежутка не определено, как допускает интерфейс C. Это не POSIX-гарантия нулевого заполнения. Незаписанные выделения при заполнении тома освобождаются; частично переданные данные и позиция сохраняются. Аппаратные ошибки не обеспечивают транзакционный откат. Размер публикуется при FLUSH/CLOSE, поэтому CLOSE обязателен и его результат нужно проверять.

Курсор сохраняется между последовательными запросами. После SEEK цепочка проходится от начала; обход ограничен числом кластеров тома. Повреждённая/BAD/циклическая цепочка возвращает `DOS_ERR_CORRUPT`. Полный файл проверяется на корректный EOC. Секторный перенос использует общий fatStream, без повторной проверки буферов на каждом кластере; выделение использует штатные подсказки распределителя.

Адаптер C находится в [sdk](../../sdk/README.md). Проверки ядра: `scripts/emu80/check-banked-kernel.py`, `check-driver-registry.py`, `check-bootstrap.py`; CPU-проверки открытых файлов и SDK: `scripts/tests/check-file-handle.py` и `check-file-stdlib.py`.

Общие команды, QUERY, MOVE и атрибуты описаны в [документации CLI](../cli/README.md). Интерфейсные циклы CLI.COM и NC остаются обычными загружаемыми программами.

Графическая библиотека находится в source/include/ui.inc и включается непосредственно в программу MAIN или MAIN DLL. NC использует локальные процедуры uiDraw, uiInverseRect, uiToolbar и uiCopyRect.

Подтверждение замены и наблюдение за изменениями передаются обработчиками приложения: строки диалогов и тексты ошибок в модуль не включены. Контракты `CLI_OP_COMMAND`, `CLI_OP_OBSERVER` и время жизни обработчиков описаны в [CLI](../cli/README.md).

## Службы DOS-DLL

MODULE_LOAD поддерживает MODULE_TARGET_DOS=2: DLL с IMAGE_FLAG_DRIVER занимает резидентный слот DOS_SERVICE_ADDR..DOS_SERVICE_END−1 (1 КиБ) либо временную арену DOS_BANK_DRIVER_ADDR..DOS_BANK_DRIVER_END−1 (6 КиБ) вместе со статическими буферами. По одному модулю на слот; слот определяется адресом тела. Её MODULE_CALL исполняется в существующем контексте DOS, локальные RAW/файловые вызовы используют эту же память, BIOS доступен через MXOS_CALL. Повторная загрузка в занятый слот возвращает ACTIVE до копирования тела. Только временная арена конфликтует с DRIVER-инициализаторами, резидентная служба им не мешает. Выгрузка и очистка владельца освобождают арену, FAR-блоки и дочерние модули; хвост MEM и назначение DOS не меняются. Временная арена не поддерживает RETAIN; для резидентного слота RETAIN разрешён, код и ресурсы сохраняются при Reset независимо от установщиков драйверов. Контракт и пример контроллера — в source/mem/api.md.

## Прямые полные секторы

Загрузчик и C stdio используют этот путь автоматически, без RAW_IO B=6 в приложении. Нативный RUN передаёт управление FILE_EXEC_NATIVE; FILE_EXEC/MODULE_LOAD задают kdPage банком назначения, устанавливают EXEC-профиль до чтения тела и включают kdFarActive. imageLoad читает через fatStream, полные секторы доходят через ksSector/klBlock до локального драйвера. Заголовок контейнера и неполные края остаются обычными частичными чтениями. Контрольная сумма считается в банке назначения. RKS-путь RUN также использует FileStream.

mxos_fread/mxos_fwrite проходят через FILEHANDLE → fileHandle → fatStream. Внешний адаптер переносит объект FILE_HANDLE и параметры, а полные секторы данных передаёт прямо в буфер вызывающего банка; неполные фрагменты обслуживает частичный кэш DOS. Для DOS-клиента используется локальный поток. FAT, каталог, распределение кластеров, права, длина файла и обработка ошибок остаются обязанностью файлового ядра.

Файловый путь ещё сохраняет диспетчеризацию: DOS ведёт цепочку и для полных блоков внешнего клиента делает callback локальному обработчику. Поэтому устранение секторного staging не делает fread/fwrite равными прямому RAW-циклу по заранее подготовленному списку. RAW_IO B=6 предназначен именно для доверенной физической серии; обходить через него файловые операции приложения не требуется.

Для текущих физических драйверов A:/B:/H: полные 256-байтные блоки RAW_IO, SECTOR_IO, FILESTREAM, FILEHANDLE и файловой загрузки передаются непосредственно в память MAIN/DOS/EXEC-клиента. Логический сектор 512 байт поверх 256-байтного драйвера разбивается на два прямых физических обмена. Объекты запросов, курсоры и метаданные остаются в DOS; содержимое полных клиентских секторов не проходит через KD_DATA. Геометрия берётся из BPB и реестра драйверов, формат тома не меняется.

Для A: чтение идёт локальным CPM16 из ROM-окна, запись — через MAINIO прямо из банка инициатора; B: использует FAR-копирование с банком RAM-диска; H: выполняет установленную копию ROM/FLASH/FLASHFST в банке клиента. У каждой страницы своя отметка установки H:. Новый профиль EXEC и замена драйвера заставляют обновить копию. Незавершённые записи FlashFst завершаются при передаче устройства другой копии и перед освобождением банкового модуля.

Неполный сектор остаётся в кэше DOS для сохранения остальных байтов. Если последующий полный обмен встречает изменённую частичную копию, она сначала сохраняется, затем инвалидируется; полный сектор передаётся напрямую. B=5 выполняет запись, чтение и сравнение с временным буфером на стеке соответствующего клиента, требуя не менее 320 свободных байт стека. Для FAT/каталогов и копирования файлов средствами самой DOS её память является собственным буфером операции.


## Проверка FILEHANDLE и размещение кластеров

FILE_MODE_VERIFY (20h) требует посекторной записи с проверкой B=5 для данных данного файла. Флаг требует WRITE; если физический драйвер не сообщает DISK_CAP_VERIFY, OPEN возвращает DOS_ERR_UNSUPPORTED до создания или усечения файла. Проверка выполняется сразу после записи полного физического блока. Неполный логический сектор сначала собирается в отдельном слоте кэша, затем сохраняется и проверяется целиком; dirty очищается только при успехе. Ошибка B=5 возвращается как ошибка I/O, а не как успешная отложенная запись. FAT, каталог и другие метаданные эта настройка не переводит в B=5.

Общая настройка DOS_IO_VERIFY_FILES (бит 0) включает тот же путь для всех запросов WRITE через FILEHANDLE на драйверах с DISK_CAP_VERIFY, включая уже открытые файлы. Для остальных драйверов сохраняется обычная запись. По умолчанию настройка выключена; она хранится в DOS до перезагрузки ядра и не записывается на диск. FileStream и прежние файловые API этой настройкой не меняются. Отдельный CONFIG.SYS, команда AUTOEXEC и ключ установщика драйвера пока не добавлены.

Настройка доступна через существующий ABI bios_fileHandle / MXOS_DOS_FILEHANDLE, A=FILE_OP_OPTIONS (6), HL=64-байтный FILE_HANDLE. FH_ORIGIN=0 читает текущие флаги в FH_COUNT, FH_ORIGIN=1 обменивает FH_COUNT на прежние флаги. Установить можно только бит DOS_IO_VERIFY_FILES; неизвестные биты и команды отклоняются без изменения настройки. Открытый файл, корректный FH_DRIVE или смонтированный том для OPTIONS не требуются; объект по-прежнему должен находиться в допустимой памяти вызывающего. Вызов из MAIN/EXEC переносит весь объект обычным банковым переходником.

```asm
    ld a,1
    ld (options+FH_ORIGIN),a
    ld hl,DOS_IO_VERIFY_FILES ; 0 отключает общую проверку
    ld (options+FH_COUNT),hl
    ld hl,options
    ld a,FILE_OP_OPTIONS
    MXOS_CALL MXOS_DOS_FILEHANDLE
    ; При CF=0 FH_COUNT содержит прежнюю настройку для восстановления.
options: DS FILE_HANDLE,0
```

FILE_MODE_SCATTER (40h) разрешён только с WRITE и меняет поиск новых кластеров данного файла: LFSR выбирает начальную позицию, после чего общий распределитель ищет свободную запись FAT. Занятые кластеры не перезаписываются, полный том возвращает обычную ошибку FULL. FH_ALLOC_SEED (60..61) хранит состояние LFSR, OPEN начинает с ACE1h. Размер FILE_HANDLE остаётся 64 байта: использованы прежние два резервных байта. Существующая цепочка и формат FAT не меняются; стандартные номера кластеров, EOC и записи каталога сохраняются. В текущем формате поддерживаются FAT16 и явные расширения MXOS для 128/256-байтных секторов; FAT12 этим изменением не добавляется.


## Расширенная временная DOS-DLL

Установщики драйверов сохраняют прежний предел C000h–D7FFh, 6 КиБ. MODULE_TARGET_DOS может загрузить временную DLL до F000h (C000h–EFFFh, 12 КиБ), если v_batDepth=0. Часть D800h–EFFFh заимствуется у неактивных кадров BAT. Владение областью сохраняется на всё время загрузки DLL, а не только на MODULE_CALL. Пока область занята, запуск BAT возвращает DOS_ERR_ACCESS; при активном BAT загрузка такой DLL возвращает MEM_ERROR_ACTIVE. MODULE_UNLOAD, освобождение владельца и Reset снимают блокировку. Режим RETAIN для временной DOS-DLL по-прежнему запрещён; обычная DLL до D800h может сосуществовать с активными BAT. Дисковый кэш, служебный стек F000h–F3FFh и транспорт не перемещаются.

Проверяющая запись B=5 в DOS, включая локальную серию MEM, читает сектор в DOS_VERIFY_BUFFER (B600h–B6FFh), выделенный из резерва буферов. Он не пересекает буфер неполного логического сектора B400h–B5FFh: тот может содержать исходные данные для сравнения в любой из двух половин. Буфер проверки временный, не кэшируется и занят только на время синхронного запроса. EXEC/BANK сохраняет локальный стековый буфер; MAIN использует общий BIOS_TEMP_BUFFER.

## Получение списка каталога

DIR_OP_LIST выполняется одним запросом клиента. Общий FAT-курсор загружает сектор каталога один раз и обходит его записи по указателю; корень ограничен остатком RootEntCnt, подкаталог — геометрией и проверенной цепочкой кластеров. FILE_INFO собираются в DOS-пачке KD_DATA на 4096 байт. Полные пачки и последняя пачка с FFh передаются клиенту через kdStore / bankCopyFar; для панели из 255 записей весь результат помещается в одну пачку 4081 байт. Прямого чтения FAT-записей в буфер NC и внешнего запроса на каждый файл нет.

Skip и ёмкость списка обслуживаются убывающими счётчиками без сравнения пары U16 для каждой записи; после исчерпания ёмкости обход продолжается для возврата полного числа записей. Ёмкость 0 возвращает только FFh и общий счётчик. Копирование компактного описателя развёрнуто, преобразование первого 05h в E5h и формат FILE_INFO сохранены. Эти изменения не меняют формат FAT, фильтрацию, порядок записей и банковый протокол.
