# UI_GFX.DLL

Общий графический исполнитель в MAIN. До загрузки модуля клиент регистрирует приёмный буфер в MAIN. В GFX_BIND он передаёт его начало в HL и длину в BC (1–3072 байта). Ответ возвращает адрес 18-байтного результата в HL и базу DLL в DE. Результат принадлежит загруженному экземпляру и действителен до его выгрузки. Затем он привязывает DLL через MODULE_SCOPE и отправляет команды через MX_QUEUE_DLL. DLL копирует пакет в MAIN одним FAR-вызовом и исполняет записи. Формат регистров и встроенных данных описан в [abi.inc](abi.inc).

Клиент подготавливает текст, прямоугольники и палитры, выбирает области для перерисовки и передаёт адреса своих буферов. Например, копирование цветной области получает исходные цвета строк прямо в команде. Сохранение снимка получает адрес буфера пикселей. Для восстановления клиент передаёт либо одну палитру, либо дескриптор с сериями цветов. Просмотрщик справки также принимает буфер пикселей и палитру от вызывающей программы.

`GFX_TEXT_ROWS` выводит строки через `printStringRawLim`. `GFX_PSEUDO_ROWS` выводит через `printStringRawPseudo` несколько строк одинаковой ширины с шагом 10 пикселей по Y. Начальные координаты берутся из записи команды. Знакоместа передаются в пакете или читаются из кэша клиента в MAIN. `GFX_TEXT_PSEUDO` выводит одну строку или её часть из пакета.

Загрузчик выбирает свободное место для кода и служебных данных по заголовку v3 и применяет WORD16-поправки при холодной загрузке. При повторной активации привязка буфера сбрасывается. NC_CORE и EDITCORE регистрируют свои рабочие диапазоны с 3380h через MEM_OP_MAINREGISTER и освобождают их после выхода из области рисования. Сборка системы создаёт DLL для системного образа.
