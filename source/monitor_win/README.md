# Оконный монитор

`MONWIN.MON` — сменное STD-ядро C000h–DFFFh, 8192 байта. Запуск собственной командной среды: `RUN MONWIN.MON`; в NC также работает Enter по файлу благодаря общей ассоциации `MON A:\RUN.COM` в CLI.EXT. Это отдельный монитор, не движок Fast8 для MXOS.

`MONWIN.asm` — сборочный исходник SjASMPlus `--i8080`, восстановленный из имеющегося дизассемблированного листинга. Он воспроизводит ROM побайтно; числовые адреса и неизвестные данные сохранены. `originals/monitor_win.asm` — исходный полученный листинг, а не авторский ассемблерный текст. `originals/monitor_win.rom` — неизменённый эталон. Оба перенесены из `D:/Projects/RetroPC/Specialist/MySoft/Monitor-windows/`. SHA-256 ROM: `841a6db4bc330aa43514bcba98c02afd92db13f98670b435788adb6135bd7bac`.

Монитор входит в сборку системы. Для отдельной сборки выполните из этой папки:

```powershell
powershell.exe -NoProfile -File ../../scripts/build/build-if-needed.ps1 MONWIN mon 0xC000
```

Каждая сборка, включая up-to-date, проверяет побайтное соответствие ROM эталону, включая исторический шрифт D800h–DFFFh. Результат — `bin/MONWIN.mon`, системный путь — `A:\MONWIN.MON`. Исходный монитор использует плоские глифы по восемь байтов. Современный `FONT 8x8/Fast8` использует исправленный вариант KOI8-R из `assets/system-rom/fonts/8x8/Win8.pf`, транспонирует его в восемь 256-байтных страниц и имеет другой рендерер.

Вход C000h запускает старый загрузчик. RUN входит в собственный монитор через C800h после копирования и переключения в STD; этот вход инициализирует его окна и переменные. После замены ядра службы MXOS недоступны. Для возвращения используется системная перезагрузка, не RET в прежний RUN. Наличие файла MON не означает поддержку любого монитора: RUN проверяет известные размеры и структуру входов.
