# Файловый менеджер NC

Shift+F3 или F9 открывает справку из `C:\DOS\NC.HLP`. Стрелки листают по строке, Ctrl+вверх/вниз — по странице, Home/End — к началу и концу. Enter и Esc закрывают окно.

Штатный `C:\DOS\NC.COM` загружает банковый `NC_CORE.DLL` с общим движком `UI_GFX.DLL`. Из тех же исходников собирается тестовый MAIN-профиль `C:\DOS\NC_MN.COM`, для которого подходит шрифт Rotate. F10 переходит в CLI. Команда EXIT возвращается в предыдущий профиль, а явный запуск NC выбирает банковый. В банковом профиле Ctrl-F10 освобождает резидент. Разделение памяти, ABI и условия сравнения описаны в [BANKED.md](BANKED.md).

При запуске NC сразу печатает в консоли версию и копирайт `Commander 3.0 (C) Omsk/SPb 1992-2026`, без пустой строки перед ними. Пока эта строка видна, загружаются настройки и состояние, читаются и сортируются каталоги обеих панелей, восстанавливаются выбранные имена, прокрутка и пути. Только затем рисуются тулбар, приглашение, рамки и списки: первый кадр использует подготовленные данные без повторного чтения каталогов и сортировки, включая файловый контекст панели F3. Запрос свободного места для F3 по-прежнему выполняется после вывода панелей.

Каталоги поддерживаются через bios_directory DOS. Enter открывает выбранный каталог, `..` возвращает к родителю и выделяет покинутую папку; `/` и `\` принимаются в командах CD/CHDIR. Две панели сохраняют независимые контексты даже на одном диске. Заголовки и приглашение имеют вид `H:\Almaz\STD`; приглашение завершается `>`. Заголовок сокращает длинный путь по целым компонентам: `A:\...\RAMFOS\Almaz-2.exe`. Полный путь сохраняется в MAX_PATH-буфере. При сокращении по возможности сохраняется и первый каталог: `A:\Folder\...\File.txt`; приглашение использует тот же алгоритм с ограничением 24 знака. Ввод команды прокручивается в пределах строки и не перечитывает каталог при каждом символе. Пока видимое окно не сдвигается, ввод и удаление меняют только один знак; при сдвиге обновляется текст команды без очистки приглашения. Заголовки Name убраны; обычная панель показывает 19 строк в колонке. При 4×8 колонок три (57 записей), при 6×8 — две (38), при 8×8 — одна (19) с размером файла или `<DIR>` справа. При любом шрифте статус показывает имя и размер одним вызовом текстового рендера. Путь доступен в заголовке. Для `..` выводится `Go to parent dir`. Пункт `\` пока скрыт: при запросе подкаталога NC использует BC=1 и пропускает запись FAT `.`, не переставляя строки кэша; код её прежнего преобразования в пункт корня оставлен закомментированным.

Enter/F4/Ctrl+Enter формируют абсолютный путь к выбранному файлу. Предел общей команды — 127 байт; превышающая его добавка не вставляется частично. Копирование по F5 по умолчанию использует каталог противоположной панели, в том числе на том же диске. Текстовый буфер диалога имеет MAX_PATH байт; видимая область вмещает 36/24/18 знаков для 4/6/8 пикселей и прокручивается. F7 создаёт каталог, F8 удаляет пустой каталог. F6 перемещает файл в каталог противоположной панели; внутри тома меняются только записи каталога, без копирования содержимого.

Состояние панелей сохраняется в текстовом B:\NC-STATE.CFG тем же синтаксисом, что настройки C:\DOS\NC.CFG. При запуске применяются встроенные значения, затем C:\DOS\NC.CFG, затем B:\NC-STATE.CFG; каждый присутствующий корректный параметр заменяет прежнее значение, отсутствующие параметры его сохраняют. NC записывает только активную панель, пути, сортировки, F3, выбранные имена и начало прокрутки. Кластеры и номера выбранных записей в файл не попадают: пути разрешаются заново через DOS, имена ищутся в актуальных индексах, прокрутка подстраивается под видимость. Активная панель всегда файловая. Запись выполняется только перед внешней программой и выходом в CLI; навигация и тихие команды состояние на диск не пишут. Ошибки B: отключают сохранение до следующего запуска NC; отсутствие файла при первом запуске считается нормальным. Прежний бинарный NCSTATE.TMP больше не читается, переходников для него нет.


NC использует резидентные графические службы BIOS через штатный ABI. Данные COPY/MOVE переносятся внутри банка DOS; клиентский буфер данных NC не выделяет.

В MAIN-профиле код, состояние, два слота каталогов, индексные таблицы и графические буферы размещаются в MAIN. Постоянная рабочая область `[vars,FILE_CACHE_A)` объявлена как BSS в заголовке NC_MN.COM; там же указан минимальный размер кучи для каталогов. Размер общего пула выбирается при запуске по доступному memTop с учётом шрифта. Каждая панель занимает место по фактическому числу записей. При смене каталога соседний список уплотняется, а новый читается в освободившийся хвост. На каждый каталог оставляется минимум одной колонки и действует предел в 255 записей. Две панели с одинаковым каталогом используют один список. Диапазон `[FILE_CACHE_A,ncMemoryEnd)` выделяется штатными MEMORY/ARENA и ALLOC. DOS учитывает образ и выделенный блок при загрузке DLL и освобождает при замене/завершении приложения. Буферы не входят в файл NC_MN.COM. В банковом профиле большие буферы находятся в EXEC, а полный рабочий диапазон MAIN-движка объявлен в заголовке UI_GFX.DLL. Точные границы находятся в bin/NC.sym и bin/UI_GFX.sym.


NC включает локальную библиотеку [ui.inc](../include/ui.inc) для окон, инверсии выделения, копирования прямоугольников; тулбар NC рисует самостоятельно через установленный движок. Сначала файл подключается для макросов, затем с DEFINE UI_IMPLEMENTATION — для процедур и рабочих данных. Библиотека не зависит от state и может включаться в программу MAIN или её DLL.

Общие примитивы графики находятся в [ui.inc](../include/ui.inc); байтовый и попиксельный API описаны в [UI.md](../include/UI.md). Окна панелей и диалогов сохраняют быстрый байтовый путь. Кнопки дисков используют пиксельную инверсию с одинаковым отступом в одно знакоместо от видимого рисунка буквы с обеих сторон и в один пиксель сверху и снизу. В 4×8/6×8 учитывается пустой левый столбец; для 8×8 общий пустой столбец определяется по установленным буквам A–H, поэтому перенос пустого столбца при правке шрифта не требует правки NC.

В сведениях драйвера подписи `Label`, `Driver` и `Type` выровнены вправо, значения начинаются на общей границе экранного байта. Значения выводятся через `ncPrintTextLim` с фиксированным пределом 36/21/15 знаков для 4/6/8 пикселей и обрезаются без переноса; внутри используется `bios_printStringRawLim`. Только жёлтое описание переносится на следующие строки. Весь блок ограничен шестью строками и центрируется между разделителем и нижней рамкой. Переход между каталогами одного диска не перерисовывает открытую инфопанель; смена диска обновляет её.

Окно подтверждения перезаписи размещает Yes, All, No и Skip в четырёх равномерно разнесённых ячейках. Положение надписей учитывает сетку установленного шрифта; пиксельные рамки строятся вокруг фактического положения текста с симметричными полями и учётом пустого столбца глифа. Выделение инвертирует только внутреннюю область, сохраняя контур. Начальный ответ остаётся No.

Штатная сборка включает `NC_BITMAP_SCROLL=1` для всех трёх размеров шрифта. При прокрутке на 1–19 файлов (1–20 при `FULL_PANELS=1`) NC переносит сохраняемый битмап одной, двух или трёх колонок, включая строки на их общих границах, общим стековым `uiCopyTextRect` из [ui-text-rect.inc](../include/ui-text-rect.inc). В каждой ячейке высотой 10 пикселей развёрнутый цикл переносит восемь строк глифа, пропуская пустые строки 0 и 9. Вперёд источник читается через POP, назад назначение записывается через PUSH; направление выбирается один раз на прямоугольник, SP сохраняется и восстанавливается один раз. Повторных вызовов общего memcpy для каждого байтового столбца нет. Код требует запрещённых прерываний и одинакового пустого фона пропускаемых строк. Печатаются только вновь появившиеся строки. В 6×8 при шаге на один файл за край окна старый курсор остаётся на месте: его строка исключается из источника копирования, соседнее имя восстанавливается обычным текстом, а новое имя печатается сразу инверсным поверх прежнего выделения. В 4×8 и 8×8 старый курсор снимается перед переносом, новый рисуется после новых строк. Большие переходы, в том числе дальние Home/End, используют полную текстовую перерисовку.

Выделение сохраняет битовую инверсию экранной памяти и видно на чёрно-белом дисплее. Ввод команды, Backspace, Escape и Ctrl+Enter не снимают и повторно не рисуют выделение панели.

В 6×8 файловое выделение имеет сплошной инверсный отступ шириной один пиксель справа от 12 знаков: крайний байт содержит только пустое поле, и для него сочетаются цвет выделения и обычный синий фон. В 4×8/8×8 выделение ограничено полными байтами текста и не заходит в байт рамки. Белая кромка не рисуется; цвета текста и рамок независимы. Это учитывает общий атрибут всего экранного байта без чтения цветового регистра. Текущий цвет NC хранится программно и восстанавливается после рисования отступа.

При `NC_FILE_COLORS=1` цветной копировщик переносит атрибуты из таблицы строк вместе с битмапом. Сборочный вариант `NC_FILE_COLORS=0` использует один неизменный цвет файлов; заголовки, рамки и строка сведений в переносимую область не входят. `NC_BITMAP_SCROLL=0` сохраняет обычный текстовый путь перерисовки.

Проверяемый пример отдельной текстовой сборки из корня репозитория: `tasm/sjasmplus.exe --i8080 -Wno-rdlow -DNC_BITMAP_SCROLL=0 --raw=bin/NC-text.i80 --sym=bin/NC-text.sym --lst=bin/NC-text.lst source/nc/NC.asm`. Штатная сборка выполняется через `scripts/build/build-project.ps1 OS` и использует битмап-режим. Не подменяйте обычные результаты вариантами с другими define.

При расчёте адреса буфера копирования исключайте перекрытие образа NC по 0000h. Для штатной проверки графики MMX достаточно системной flash 512 КиБ.

NC_MN.COM — MAIN-программа с загрузкой и входом 0000h (NC_LOAD_ADDR). Код, строки, встроенные малые буферы, метаданные общего кэша и 16 байт состояния входят в бинарник. Рабочие переменные, три слота каталогов по 4081 байту и индексные таблицы находятся за ним без включения в файл. Каждый слот хранит до 255 записей FILE_INFO по 16 байт и FF-терминатор. Состояние панелей сохраняется в B:\NC-STATE.CFG. Актуальные адреса задаёт bin/NC.sym.

Видимый список — указатель vars.fileListPtr внутрь собственной 256-байтной индексной таблицы панели. FILE_INFO берётся из назначенного панели общего слота; две панели могут ссылаться на один каталог с разными режимами сортировки. Сами записи не копируются и не переставляются. В каждом общем слоте сохраняется ещё одна 256-байтная таблица последнего использованного режима. Попадание каталога восстанавливает готовый индекс; если сохранён другой режим, индекс строится заново. Пустой каталог, FF-терминатор и предел 255 записей обрабатываются так же, как при обычном чтении.

В F3 строка `MAIN max` показывает верхнюю границу непрерывной памяти для новой MAIN-программы с сохранением текущего шрифта. Банковый NC учитывает, что его графическая DLL может быть вытеснена после выхода из области вызова. Другие закреплённые ресурсы могут уменьшить доступный диапазон. Строка Font показывает имя установленного файла шрифта без расширения и размер его резерва в MAIN. Поддерживаются пользовательские имена длиной до восьми символов. Для программы, запрашивающей всю MAIN, DOS может временно поставить Rotate и восстановить выбранный профиль при возврате.

NC использует установленный шрифтовый движок и не вызывает FONT_RENDER ни при запуске, ни перед внешней программой, ни при выходе. memTop и резервациями шрифтов управляет FONT/MEM. При старте NC проверяет memTop до обращения к рабочим буферам: фиксированные индексы и сортировочные страницы расположены перед тремя каталожными кэшами, ёмкость каждого кэша выбирается по оставшейся памяти (минимум 32, предел индекса 255 записей). Точная вместимость зависит от текущего размера NC и memTop; её показывает scripts/tests/check-app-memtop.py. При 63FFh минимальный набор текущей сборки уже не помещается. Показываются первые записи каталога до этой границы, полный счётчик DOS ограничивается ёмкостью перед сортировкой. Если не помещается даже минимальный набор, NC показывает текущий и требуемый MEMTOP, ждёт Enter и выбирает CLI вместо повторного запуска NC. Состояние движка и его пререндер не изменяются.

Командная строка общая с DOS: vars.cmdLine = CMD_LINE; её актуальный адрес задаёт mxos.inc. Она находится в системной области и сохраняется при загрузке COM в нижнее ОЗУ. NC использует первые MAX_PATH байт, полный размер системного буфера — 130 байт.

`CLI.EXT` — системный файл C:\DOS. Ассоциации разрешает DOS/CLI при запуске команды через `bios_fileExec`; NC передаёт полный путь и аргументы в общей командной строке. Перед запуском выбранного файла по Enter NC проверяет расширение: COM, EXE и BAT запускаются непосредственно, для остальных требуется ассоциация, найденная сервисом DOS. Если её нет, панели, выделение и командная строка сохраняются без перерисовки. Для проверки используется временный буфер ключей сортировки; собственного разбора таблицы ассоциаций в NC нет. Введённые вручную команды и запуск редактора по F4 обрабатываются как прежде.

Запуск внешней программы передаётся DOS хвостовым переходом. NC может быть затёрт уже при проверке контейнера. При обычном завершении программы или ошибке запуска DOS заново загружает NC. Графика ui.inc включается в NC локально; другие MAIN-программы и DLL включают собственную копию библиотеки.

Основной профиль проверки — системный Flash 512 КБ. F10 выходит в самостоятельный CLI, команда NC возвращает панели. Общие команды и ассоциации описаны в [документации CLI](../cli/README.md).

CPU-стенд общего кэша: `python scripts/tests/check-nc-catalog.py`. Ключ `--prepare-only` готовит входные образы без запуска CPU-стенда. Проверяются общий список и независимые индексы, полный ключ диск/кластер, закрепление H:\, выбор вытесняемого слота, восстановление сортировки, точные и томовые уведомления и отказ от сохранения ошибок чтения.

Проверка выделения: `python scripts/tests/check-nc-cursor.py`. Проверяется отсутствие инверсий при вводе и совпадение битмапа после прокрутки с полной перерисовкой и инверсией. Ключ `--variant NC-full`, `NC-text` или `NC-full-text` выбирает отдельно собранный вариант. Цветная проверка Emu80: `docs/nc/cursor-006/report.md`.

Файловые операции вызывает новый блок ABI DOS C8BAh–C8C6h: выбор диска, переименование, удаление, копирование и перечисление дисков. Переименование и удаление используют уже существующие реализации ядра. NC содержит диалоги и подготовку имён; циклы переноса данных, выделение и очистка назначения находятся в DOS. Проверка защиты удаления также выполняется DOS; NC после отказа выбирает подходящее сообщение.

Для F5/F6 NC передаёт vars.copyRequest (86 байт): имена, диски, каталоги и обработчик подтверждения замены. Поля buffer и bufferSize равны нулю. Банковый адаптер DOS использует собственный KD_DATA размером KD_CHUNK (2304 байта). Внутри одного тома MOVE переносит запись без данных; между томами действует COPY с последующим удалением.

Маркер сокращения задан строкой `pathOmissionMark` в NC.asm (по умолчанию `...`). PATH_OMISSION_LENGTH, PATH_PREFIX_LENGTH и PATH_RESERVED_LENGTH вычисляются через разность меток; при замене маркера вручную менять длины не нужно. Это только экранное представление, в файловые вызовы передаётся полный путь.

Первый пункт вложенного каталога `\` открывает корень диска; это экранное представление записи FAT `.`, сама файловая система и команда `CD .` сохраняют стандартный смысл текущего каталога. `..` открывает родителя. Каталоги помечаются `<DIR>` в статусной строке. Путь на рамке выводится белым. Приглашение обновляется до перерисовки панелей и не меняется при выборе другого файла. Введённый путь, как и Enter на файле, разрешается через DOS-сервис CLI.EXT; аргументы сохраняются, переполнение общей строки не допускается. Самостоятельный CLI.COM использует тот же сервис команд DOS и общий исходник редактора строки.

Строка NC и диалоги используют общий исходник редактора lineedit.inc. Стрелки вверх/вниз перемещают выделение панели и при набранной команде, сохраняя её текст, позицию текстового курсора и прокрутку строки; Ctrl+Enter добавляет полный путь к выбранному файлу и пробел. Стрелки влево/вправо при непустой строке перемещают текстовый курсор. Backspace удаляет символ слева. Команды без вывода не очищают экран; после DIR и других команд с выводом восстанавливаются панели и тулбар. Верх панели очищается от Y=0, горизонтальные линии и углы находятся на Y=4/6. Заголовки и статусные строки белые.

Тулбар рисуется установленным шрифтом через BIOS: сначала поля с разными цветами выводятся на экран, затем сохраняются 48×9 байт битмапа. Обычный набор и Shift имеют независимые ленивые снимки, всего 864 байта рабочего ОЗУ вне бинарника NC_MN.COM. При повторном выводе копируется снимок и восстанавливаются известные цвета полей; чтение атрибутов и внутреннего формата шрифта не требуется. При каждом входе в NC оба снимка инвалидируются, даже если геометрия шрифта не изменилась. Для 4×8 подписи развёрнуты, для 6×8 и 8×8 сокращены; Shift-F10 обозначен `Ex`.

Переход в каталог через Enter, CD в командной строке и команды выбора диска A:/H: при фактическом изменении диска или каталога обновляют только активную файловую панель. Каталог, кэш, положение выбора и битмап другой файловой панели сохраняются. Если другая панель показывает информацию о диске, её данные обновляются только при смене диска. Команды с экранным выводом по-прежнему требуют восстановления обеих панелей.

При совпадении файлов NC показывает четыре выровненные кнопки Yes, Yes to all, No и No to all. По умолчанию выбран No; стрелки влево/вправо и Tab меняют выбор, Enter подтверждает. Y/N/A/S выбирают Yes/No/Yes to all/No to all напрямую, Escape означает No. Ответ to all действует только до конца текущей операции, включая все подкаталоги; следующая операция снова спрашивает. При копировании дерева существующие каталоги объединяются, каждый совпадающий файл запрашивается отдельно. Диалоги F5/F6/F8 и запуск F4 блокируются на служебных элементах `\` и `..`. Тексты ошибок DOS читаются из `DOS\ERRORS.DAT` загрузочного диска через общий `source/include/errors.inc`.

NC ведёт общие маски панелей: `ncDirtyMask` (изменился каталог, нужен новый список) и `ncDamageMask` (окно закрыло изображение, достаточно кэша). Биты 0/1 обозначают левую/правую панели. DOSMOD уведомляет о затронутых диске и каталоге через `CLI_OP_OBSERVER`; тихие команды и действия F-клавиш используют один механизм. Команда записи на B: не перерисовывает открытые A:/H:, а запись в другой каталог того же диска не перечитывает текущий. При переименовании/переносе каталога уведомление охватывает том, поскольку меняются пути потомков. Наблюдатель отключается перед запуском другой программы и выходом из NC. Тот же наблюдатель отменяет сохранённые каталоги и индексы даже для папок, которые сейчас не открыты ни на одной панели; при точном уведомлении отменяется только соответствующий кластер, при томовом — все слоты этого диска.

## Обновление панелей и кэш путей

Каждая панель хранит полный путь в собственном буфере MAX_PATH. Ключ кэша — диск и кластер каталога. Заголовок, приглашение и построение имени выбранного файла используют этот кэш: GETCWD нужен один раз при переходе в новый каталог. При уведомлении о файловом изменении пути панелей соответствующего диска инвалидируются, в том числе для переименования родительского каталога. Кэш не занимает память DOS. Общий кэш списков имеет тот же ключ — диск и кластер каталога; его метаданные и обработка уведомлений находятся в catalogCache.inc.

При переходе в каталог рамка сохраняется, имена фиксированной ширины печатаются поверх прежних. NC помнит прежнее число занятых строк отдельно для каждой из двух колонок каждой панели. Локальная функция clearColumnTail очищает только разность между новой и прежней высотой списка; при росте списка очистка не нужна. Пустое место между именем и расширением печатается пробелом, чтобы убрать прежний разделитель каталога. Полная отрисовка сохраняется для первоначального экрана, смены режима информационной панели и восстановления повреждённых диалогом или консольным выводом областей.

## Порядок полной перерисовки

При первом показе NC и полном восстановлении обеих панелей используется общий fullRedraw: сначала область обеих панелей заливается синим, затем рисуются обе рамки, затем заголовки и статусные строки файловых панелей либо содержимое информационной панели, и только после этого выводятся списки файлов. Рамки рисуются без повторной заливки внутренней области. Активная файловая панель готовит метаданные первой. В самом конце запрашивается свободное место и дописывается одно число инфопанели. После завершения сохраняются прежние активная панель, каталог и положение выбора.

При повреждении обеих панелей диалогом или консольным выводом используется тот же порядок; действительные списки повторно берутся из кэшей. Навигация и тихие команды по-прежнему обновляют только затронутую панель без заливки: печать поверх прежних строк и очистка освободившегося хвоста не менялись.

Геометрия читается из `FONT_ENGINE_HEADER+5/+6` при входе в MAIN NC; шаг строки BIOS остаётся 10 пикселей. Тогда же `ncMemoryInit` перечитывает memTop и рассчитывает вместимость трёх каталогов. Имена собираются как 8 + разделитель + 3 и печатаются через `bios_printStringReal`. Начала колонок в пикселях: 8/72/136 для 4×8, 8/104 для 6×8, 8 для 8×8. Ширина байтового выделения — 48/80/176 пикселей. В 4×8 все 12 символов имени занимают ровно 6 экранных байтов, без частичного хвоста. Заголовок пути остаётся компактным, без пробельного хвоста. Статус, диалоги, информационная панель и командная строка ограничены доступной шириной; общий Lineedit сам учитывает ширину установленного шрифта. Битмап-прокрутка работает во всех раскладках, полная перерисовка по индексам используется для больших переходов и очистки пустых хвостов.

F3 показывает объём MAIN и доступный программам диапазон MAIN до memTop, объём и количество страниц BANK RAM, число зарезервированных страниц (DOS + пул RAMDISK) и оставшихся вне этого пула страниц. Данные диска — полный физический объём и свободные кластеры в КиБ; число файлов текущего каталога не выдаётся за счётчик всего диска. При `DOS_ERR_NO_MEDIA` инфопанель показывает `No media` вместо чисел, а файловая панель показывает ту же надпись под заголовком диска. Числа выровнены вправо в поле X=8..55, подписи начинаются на X=64: разные цвета не делят один экранный байт. Ниже выводятся метка тома, имя драйвера, тип накопителя и отдельная жёлтая строка описания без префикса. Блоки памяти, диска и драйвера имеют отступы сверху и снизу; блок драйвера центрируется с учётом переносов. Все быстрые сведения и оба файловых списка при полном восстановлении рисуются до запроса свободного места. После ответа DOS обновляется только числовое поле свободного объёма. Длинные значения метки и имени драйвера переносятся на следующую строку; описание занимает одну строку и ограничено шириной панели.

Shift-F1 и Shift-F2 открывают диалог сортировки над левой и правой панелью соответственно; обычные F1/F2 выбирают диск. Диалог предлагает `[ ] Unsorted`, `[ ] Name` и `[ ] Extension`; `[x]` отмечает действующий режим. Стрелки и Tab перемещают выделение, Enter или пробел применяют выбор, Escape отменяет. Для новой панели по умолчанию действует сортировка по расширению, затем по имени; сохранённый выбор панели имеет приоритет.

При сортировке по имени ключи — имя и расширение; при сортировке по расширению — расширение и имя. Сравнение использует штатное приведение KOI-8 к верхнему регистру. Служебный пункт `..` стоит первым, затем каталоги, затем файлы; каталоги сортируются по тем же двум ключам. При равных ключах сохраняется порядок исходных записей. Смена режима сохраняет выбранный файл и восстанавливает только затронутую панель из кэша, без чтения каталога. Таблица строится стабильной LSD radix-сортировкой байтовых индексов; сами FILE_INFO не переставляются. При чтении старого 12-байтного NCSTATE.TMP контексты панелей сохраняются, оба режима сортировки устанавливаются в Extension; 16-байтный файл сохраняет также режим F3 каждой панели.

Регрессионный CPU-стенд `scripts/tests/check-nc-sort.py` проверяет оба режима сортировки и Unsorted, независимость панелей, неизменность записей кэша, выбор FILE_INFO, пустой список и границы до 255 записей. `--prepare-only` готовит 60 входных образов памяти без запуска CPU-стенда.

Общий кэш содержит три каталога с выбором по давности использования. Каталог соседней панели не вытесняется; успешно прочитанный корень H: закреплён до уведомления об изменении. Поэтому при переходах по вложенным папкам корень остаётся доступен без нового DIR_OP_LIST. При возврате меняется ссылка панели на слот и восстанавливаются 256 байт индексов; полный список FILE_INFO не копируется. Дополнительные данные относительно прежних двух кэшей занимают 4849 байт: один каталог 4081 байт и три сохранённых индекса по 256 байт. Ошибка чтения не делает слот действительным. Кэш очищается при запуске нового NC, поэтому изменения внешних программ, перед которыми наблюдатель отключается, не остаются незамеченными после возврата в оболочку.

В выборе диска каждая строка из максимум четырёх букв центрируется отдельно по горизонтали. Одна строка центрируется по вертикали под заголовком; при пяти–восьми дисках две строки располагаются симметрично относительно того же центра. Положение выделения рассчитывается той же функцией, что и положение букв. Пробельного заполнения после последней буквы нет.

## Рабочие ключи сортировки

NC_SORT_KEYS содержит 11 нормализованных разрядов имени/расширения и разряд ранга, каждый в отдельном выровненном массиве на 256 байт. Подготовка выполняет штатный KOI-8 upperCase один раз для каждого байта. Ключи общие для обоих режимов; меняется только порядок проходов 8+3 или 3+8. Ранг идёт старшим разрядом, исходный порядок равных ключей сохраняется стабильными проходами. Режим без сортировки возвращает исходный индекс без подготовки ключей.

Radix пропускает постоянные разряды, очищает и суммирует только диапазон фактических значений min..max, строит гистограмму последовательным чтением разряда и чередует исходную индексную таблицу с временным буфером. Единственное итоговое копирование требуется, если результат оказался во временном буфере. Индексы панелей выровнены на 256 байт. Ключи занимают 3072 байта, счётчики и временный индекс — ещё 512 байт; область не сохраняется в кэше каталогов и используется только при перестроении индекса.

В NC остаётся только рабочий radix. Shell, вставки, quicksort, слияние, их компараторы и независимая копия radix перенесены в [SortBench](../../source-apps/sortbench/README.md). В составе NC сравнительных методов и переключателя NC_SORT_RADIX больше нет.

Тихая команда, не изменившая видимый каталог, сохраняет и битмап панели, и её выделение. Уведомление об изменении вложенного/другого каталога не отменяет кэш пути панели. При изменении видимого списка или появлении диалога выделение снимается перед необходимой перерисовкой. Навигация на границе списка также не инвертирует неизменившееся выделение.

После команды NC сравнивает фактическую пару диск/каталог DOS с прежним контекстом активной панели. Повторные `H:\` в корне, `H:` в той же сохранённой папке и `CD .` не перечитывают список, не перерисовывают панели и не сбрасывают выбранный файл или прокрутку. Переход в другой каталог или на другой диск обновляет панель как обычно; уведомления о настоящих изменениях файлов обрабатываются независимо.

Цвета расширений и начальная сортировка задаются в [NC.CFG](../../assets/system-rom/NC.CFG); формат описан ниже в разделе настроек.

Таблица `vars.rowColors` хранит базовые цвета отображённых ячеек: три колонки на каждую панель, всего 114 байт при высоте 19 строк (120 при FULL_PANELS). При прокрутке `uiCopyTextRectColors` переносит битмап и таблицу в безопасном для перекрытия направлении. Выделение меняет только цветовые атрибуты, поэтому битмап прежней выделенной строки можно переносить с её обычным цветом. Одноцветные группы используют пакетный стековый перенос; при частом чередовании цвета выбираются внутри развёрнутого цикла. Копируются восемь строк глифов, пустые межстрочные поля остаются на месте; аппаратный регистр цвета не читается. Для монохромного варианта соберите NC с `ENABLE_COLOR=0`: он использует пиксельную инверсию. Общий контракт находится в [UI.md](../include/UI.md).

В банковом профиле основной цикл и каталог находятся в EXEC. При выводе имени CORE передаёт обычный цвет ячейки вместе с текстом, а UI_GFX сохраняет его в MAIN. При прокрутке CORE отправляет одну команду со списком прямоугольников. UI_GFX переносит их битмапы и цвета из своей таблицы. Копия таблицы в EXEC обслуживает выделение и снимки модальных окон.

Для сравнительной сборки `NC_FILE_COLORS=0` отключает раскраску и цветной перенос, сохраняя обычные цвета интерфейса; штатное значение равно ENABLE_COLOR. Это сборочный переключатель, меню настройки палитры пока нет.

Диалоги выбора диска, сортировки, копирования, перемещения, переименования, удаления, создания каталога, подтверждения перезаписи, ошибок и прогресса сохраняют область под собой через общий `uiBitmapSaveColors` и восстанавливают её при закрытии. Рамки, цветные имена, сведения F3 и инверсное выделение возвращаются без перерисовки обеих панелей. После настоящей файловой операции отдельно обновляется только затронутый список; после смены сортировки — список из кэша. При замене одного окна другим прежний снимок сначала восстанавливается. Сортировка начинается только после закрытия снимка, поскольку он использует те же временные 4096 байт, что ключи radix: до 2560 байт битмапа и 1536 байт серий цветов, без постоянного экранного буфера и без увеличения NC.COM на размер снимка. Кэш тулбара также захватывается общим `uiBitmapSave`.

Цветовой callback NC использует таблицу ячеек и известные зоны рамок/чисел F3; текущие модальные окна находятся в Y=80…159 и не закрывают метаданные драйвера. Для окна за пределами этой области или при нехватке места для снимка сохраняется полный путь восстановления панелей. Консольный экран также восстанавливается обычной перерисовкой. Вместимость каталогов зависит от текущего размера NC и memTop; точные границы публикуются в bin/NC.sym. Минимум для запуска — 32 записи на каталог; если они не помещаются, NC предлагает перейти в CLI.

При каждом входе Start NC явно вызывает bios_setFontEncoding с A=0 до инициализации интерфейса и проверки памяти: KOI-8 восстанавливается также после программ, оставивших KOI7. Приглашение и команда выводятся без предварительного стирания всей строки; хвост поля команды заполняется пробелами в том же проходе. Первый символ и Ctrl+Enter не перерисовывают приглашение.

## Настройки NC.CFG

Цвета файлов задаются в `C:\DOS\NC.CFG` и перечитываются при каждом запуске NC без пересборки. Штатные настройки: каталоги белые; COM/EXE/RKS/MON/FNT светло-зелёные; BAT/CFG светло-красные; TXT голубые; архивы светло-пурпурные; остальные Hidden/System тёмно-серые; остальные файлы белые. Сначала применяется последнее заданное правило расширения из `FileColorUser`, затем `FileColorSys` для Hidden/System, затем `FileColorDef`. Каталоги всегда белые. CLI.EXT по-прежнему определяет запуск, независимо от цветов.

```text
# Colorful file types
FileColorUser LightGreen exe com rks mon fnt
FileColorUser LightRed bat cfg
FileColorUser LightCyan txt
FileColorSys DarkGray
FileColorDef White
DefaultSortMode 2
DefaultLeftDrive A:
DefaultRightDrive H:
```

Имена параметров, цветов и расширений нечувствительны к регистру. Пробелы и табуляция разделяют слова; комментарии начинаются с `#`, строки разделяются CR, LF или CRLF. Значение можно заключить в двойные кавычки; обратный слэш внутри них остаётся обычным символом пути. Расширения указываются без точки, длиной 1–3 знака. Поддерживаются до 32 правил расширений и файл до 2047 байт; лишние правила и неизвестные/некорректные параметры пропускаются. Если конфигурация отсутствует или не читается, работают встроенные цвета и сортировка по расширению. Файлы дополняют или переопределяют встроенные правила по расширению. Повторное расширение заменяет его цвет, не занимая ещё одну запись; это работает и при заполненной таблице. Доступны Black, Blue, Green, Cyan, Red, Magenta, Brown, LightGray, DarkGray, LightBlue, LightGreen, LightCyan, LightRed, LightMagenta, Yellow, White. Фон файлов остаётся синим.

`DefaultSortMode`: 0 — порядок диска, 1 — имя, затем расширение, 2 — расширение, затем имя. Это начальное значение обеих панелей; сохранённые режимы из B:\NC-STATE.CFG имеют приоритет. Изменения NC.CFG применяются при следующем запуске NC, в том числе после возврата из программы.

`DefaultLeftDrive` и `DefaultRightDrive` выбирают корневые каталоги панелей при запуске без сохранённого состояния. Допустимы буквы A–H с двоеточием или без него. Для отсутствующего драйвера действует встроенный выбор: C: слева, H: справа, либо B: справа, если H: недоступен. Сохранённые пути из `B:\NC-STATE.CFG` имеют приоритет.

При переходе к непосредственному родителю через `..` или `CD ..` NC ищет покинутую папку по имени и расширению в актуальной индексной таблице, проверяя атрибут каталога. Прокрутка подстраивается, чтобы выделение было видно при любом размере шрифта. Изменение порядка или состава родительского каталога не привязывает курсор к прежнему номеру записи.


F5/F6 перед копированием дерева подсчитывает файлы, байты и необходимое место с учётом новых каталогов. Cancel/Escape прекращает только подсчёт, Abort отменяет всю операцию. При пропуске подсчёта скрыты полоса и проценты, но остаются фактические байты и путь; во время переноса Escape действует как Abort. Окно появляется только для длительной операции, обновляется не чаще четырёх раз в секунду и сохраняет размер между фазами. F8 после подтверждения рекурсивно удаляет выбранный каталог; отмена не восстанавливает уже удалённое. Корень, текущий каталог и его предки защищены.

## Текстовое состояние NC-STATE.CFG

Автоматически создаваемый скрытый файл B:\NC-STATE.CFG читается общим парсером после C:\DOS\NC.CFG. Машинная запись использует прописные ключи и CRLF, ручная правка принимает любой регистр и CR/LF/CRLF. Пример:

```text
ActivePanel 0
LeftPath C:\FONTS\6x8
LeftSort 1
LeftInfo 0
LeftSelected Rotate.fnt
LeftFirst 0
RightPath H:\
RightSort 2
RightInfo 1
RightSelected ZOO.RKS
RightFirst 180
```

ActivePanel: 0 слева, 1 справа. LeftPath/RightPath — абсолютный путь до каталога с диском. LeftSort/RightSort: 0 порядок диска, 1 имя, 2 расширение. LeftInfo/RightInfo: 0 файловая панель, 1 F3; у активной панели F3 принудительно выключается. LeftSelected/RightSelected — имя и расширение 8.3 выбранного элемента, без пути; пустое значение отменяет сохранённое выделение. Имя с начальным `#` автоматически записывается в двойных кавычках, чтобы не стать комментарием. LeftFirst/RightFirst — десятичное начало прокрутки 0–255. Оно ограничивается текущим списком и геометрией шрифта. Если выбранного имени больше нет, выбирается первый элемент. Недоступный путь игнорируется, сохраняя настройки предыдущего слоя.

Эти ключи допустимы и в C:\DOS\NC.CFG; B:\NC-STATE.CFG переопределяет только присутствующие ключи. Вручную можно также добавить туда параметры цветов, но очередное автоматическое сохранение запишет только поля состояния панелей. Проверки: `python scripts/tests/check-nc-config.py`, `python scripts/tests/check-nc-text-state.py`, `python scripts/tests/check-nc-parent-selection.py`; интерфейсный прогон `python scripts/emu80/check-nc-info.py --no-build --text-state`.


Модальные сообщения используют полные английские фразы обычным регистром. Заголовок и обычный, не инверсный путь центрируются; окно ошибки закрывается кнопкой OK [Enter] или Escape. Все кнопки ввода, подтверждения и прогресса рисует общий UI_BUTTON: рамка, центрированная подпись, клавиша и единая палитра выбранного состояния, совпадающая с подписями тулбара. В подтверждении перезаписи стрелки ходят по двум строкам, Tab — по порядку; Y/N/A/S выбирают ответ непосредственно.

Окна ошибок, ввода, удаления, перезаписи, прогресса и выбора диска используют общий [модальный компонент UI](../include/UI.md): программа задаёт высоту основного поля и список кнопок с сеткой, а компонент рассчитывает рамку, отступы, разделители и очищает старое содержимое при смене стадии. В подтверждении удаления полный путь выводится обычным центрированным текстом, без поля редактирования. У 8×8 подписи перезаписи сокращены до Yes, All, No и Skip all с прежними клавишами Y/A/N/S.

Подготовка и перенос используют одинаковое расположение счётчиков Files/Size и текущего пути. Во время переноса показаны завершено/всего, полоса и процент в заголовке. Неизвестный объём (удаление или пропущенный подсчёт) обозначается индикатором активности без ложного процента. После ответа на перезапись окно восстанавливается до продолжения файловой операции.

Выбор диска использует компактный вариант общего шаблона, целиком поверх соответствующей панели; подписи дисков остаются кнопками с рамками. Окно сортировки также находится над своей панелью. Чекбоксы режимов — графические квадраты 8×8 с отметкой, одинаковые при всех шрифтах; курсор выбирает пункт, Enter/Space применяют режим.
