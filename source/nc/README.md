# Файловый менеджер NC

Карта от 04.11.2026: общая командная строка находится по FA00h, стек DOS — под экраном, SP=8FDFh. Буфер копирования NC заканчивается перед 8C00h, оставляя переходники запуска и стек неприкосновенными. Графический ABI остаётся в DOS.


NC вызывает общий графический модуль DOS для окон, инверсии выделения и строки F1–F8. Оконные списки и обработчики клавиш остаются в NC; модуль не зависит от `state`. ABI описан в [документации модуля DOS](../dos/ui/README.md).

Штатная сборка включает `NC_BITMAP_SCROLL=1`. При прокрутке на 1–18 файлов (1–20 при `FULL_PANELS=1`) NC переносит сохраняемый битмап двух колонок, включая строки на их общей границе, через `bios_uiCopyRect` и штатный быстрый `bios_memcpy_bc_hl`. При шаге на один файл за край окна старый курсор остаётся на месте. Его строка исключается из источника копирования; соседнее имя восстанавливается обычным текстом, а новое имя печатается сразу инверсным поверх прежнего выделения. В остальных случаях старый курсор снимается, новый рисуется сразу после первой новой строки; оставшиеся новые строки идут в прежнем направлении. Большие переходы, в том числе дальние Home/End, используют полную текстовую перерисовку.

Выделение сохраняет битовую инверсию экранной памяти и видно на чёрно-белом дисплее. Ввод команды, Backspace, Escape и Ctrl+Enter не снимают и повторно не рисуют выделение панели.

Битмап-режим требует одного неизменного атрибута `COLOR_FILE` на всей области файлов. Цвета заголовков, рамки и строки сведений в неё не входят. Если появятся разные цвета файлов или маркировка строк, выбирайте `NC_BITMAP_SCROLL=0`: старый текстовый путь сохранён и также рисует курсор после первой строки. Флаг задаётся перед сборкой; переключение не требует изменения DOS.

Проверяемый пример отдельной текстовой сборки из корня репозитория: `tasm/sjasmplus.exe --i8080 -Wno-rdlow -DNC_BITMAP_SCROLL=0 --raw=bin/NC-text.i80 --sym=bin/NC-text.sym --lst=bin/NC-text.lst source/nc/NC.asm`. Штатная сборка выполняется через `build: OS` и использует битмап-режим. Не подменяйте обычные результаты вариантами с другими define.

NC.COM — обычная программа с загрузкой и входом `0000h` (`NC_LOAD_ADDR`). Файл NC.i80 содержит 4033 байта кода, строк и начальных данных. Рабочие переменные и малые буферы занимают ещё 127 байт. Два кэша каталогов по 4081 байту располагаются по `1040h–2030h` и `2031h–3021h`. Каждый хранит до 255 компактных 16-байтных записей и FF-терминатор. Общая сохранённая копия 12 байт состояния панели остаётся в зарезервированном секторе RAM-диска для возврата в NC.

Видимый список — указатель `vars.fileListPtr` внутрь кэша активной панели. Прокрутка и переключение панелей повторно не вызывают `bios_fileList` и не копируют дескрипторы. Каталог читается с начала один раз при первой загрузке панели; полная перерисовка после файловых операций, выбора диска или обновления инвалидирует её кэш. Смена диска также проверяется по тегу кэша. При возврате из программы оба кэша создаются заново. Индексы NC остаются 8-разрядными: показываются первые 255 файлов, если каталог больше; текущий H: с корнем на 192 записи помещается целиком.

Потоковый буфер `3100h–8EFFh` занимает 94 сектора, 24064 байта (23,5 КиБ). Он общий для копирования и временного чтения ассоциаций, не пересекается с кэшами и не загружается с диска вместе с NC.COM. Размеры и границы вычисляются при сборке. Итого NC с буферами резервирует `0000h–8EFFh`, 36608 байт, из которых 222 байта — выравнивание. До переменных BIOS остаётся 223 байта. Прежнее ограничение пула копирования концом 8000h снято; используется обычное ОЗУ до 8EFFh.

Командная строка общая с DOS: `vars.cmdLine = CMD_LINE = E140h`. Она находится в системной области и сохраняется, пока загрузчик COM затирает нижнее ОЗУ. NC использует первые 60 байт для редактора строки; DOS сохраняет полный прежний размер своего буфера — 130 байт.

`NC.EXT` — системный файл A:. Поиск выполняет общий `bios_fileAssociation` (`C8B4h`): NC передаёт три байта расширения и временный буфер после своих кэшей, затем переносит найденную команду в общую системную строку. Буфер не является постоянной таблицей и не должен переживать запуск программы. Размер проверяется в DOS до чтения, FF-терминатор добавляется явно. Во время копирования файлов этот же буфер используется для данных; операции не вложены. Код разбора ассоциаций в NC отсутствует.

Запуск внешней программы передаётся DOS хвостовым переходом. NC может быть затёрт уже при проверке контейнера. При обычном завершении программы или ошибке запуска DOS заново загружает NC. Графический модуль остаётся в DOS и доступен программам независимо от NC.

Основной профиль проверки — системный Flash 512 КБ. Резидентный CLI DOS для всей файловой работы без NC и перевод редактора на общий графический ABI — следующие этапы.

Проверка кэшей: `python scripts/tests/check-nc-cache.py`. Покрываются раздельные каталоги панелей, попадание без перечитывания, обновление после инвалидации, смена диска, пустой каталог, границы 255 записей и выбор окна. Текущий отчёт замеров: `docs/nc/cache-005/report.md`.

Проверка выделения: `python scripts/tests/check-nc-cursor.py`. Проверяется отсутствие инверсий при вводе и совпадение битмапа после прокрутки с полной перерисовкой и инверсией. Ключ `--variant NC-full`, `NC-text` или `NC-full-text` выбирает отдельно собранный вариант. Цветная проверка Emu80: `docs/nc/cursor-006/report.md`.

Файловые операции вызывает новый блок ABI DOS C8BAh–C8C6h: выбор диска, переименование, удаление, копирование и перечисление дисков. Переименование и удаление используют уже существующие реализации ядра. NC содержит диалоги и подготовку имён; циклы переноса данных, выделение и очистка назначения находятся в DOS. Проверка защиты удаления также выполняется DOS; NC после отказа выбирает подходящее сообщение.

Для F5 NC передаёт `vars.copyRequest` (76 байт): имена и номера дисков, адрес COPY_BUFFER и его размер в байтах. `vars.tempFileDescr` переиспользует поле destination этой структуры для F6. У DOS нет неявного буфера по 0000h или фиксированному адресу NC. Полный контракт — в [документации DOS](../dos/README.md).
