# Файловый менеджер NC

Каталоги поддерживаются через bios_directory DOS. Enter открывает выбранный каталог, `..` возвращает к родителю; `/` и `\` принимаются в командах CD/CHDIR. Две панели сохраняют независимые контексты даже на одном диске. Заголовки и приглашение имеют вид `H:\Almaz\STD`; приглашение завершается `>`. Заголовок и статусная строка сокращают длинный путь по целым компонентам: `A:\...\RAMFOS\Almaz-2.exe`. Полный путь сохраняется в MAX_PATH-буфере. В приглашении показывается хвост длинного пути. Ввод команды прокручивается в пределах строки и не перечитывает каталог при каждом символе. Пока видимое окно не сдвигается, ввод и удаление меняют только один знак; при сдвиге обновляется текст команды без очистки приглашения. Заголовки Name убраны; обычная панель показывает 19 строк в каждой из двух колонок (38 записей).

Enter/F4/Ctrl+Enter формируют абсолютный путь к выбранному файлу. Предел общей команды — 127 байт; превышающая его добавка не вставляется частично. Копирование по F5 по умолчанию использует каталог противоположной панели, в том числе на том же диске. Текстовый буфер диалога имеет MAX_PATH байт; видимая область из 24 знаков прокручивается. F7 создаёт каталог, F8 удаляет пустой каталог. F6 перемещает файл в каталог противоположной панели; внутри тома меняются только записи каталога, без копирования содержимого.

14-байтный NC_STATE сохраняется в B:\NCSTATE.TMP с меткой 5Bh. Вместо восстанавливаемых счётчиков файлов и режима информационных панелей хранятся два 16-битных контекста каталогов. При старой метке панели начинают с корня. Запись выполняется только перед запуском внешней программы и выходом в CLI; навигация, выбор диска и тихие команды меняют состояние только в памяти NC. Ошибки B: отключают сохранение до следующего запуска NC.


NC использует резидентные графические службы BIOS через штатный ABI. Данные COPY/MOVE переносятся внутри банка DOS; клиентский буфер данных NC не выделяет.

Код, состояние, рабочие переменные, три общих слота каталогов и индексные таблицы NC размещаются в основной памяти ниже APP_MEMORY_END (8C00h). Пререндер шрифта не резервируется; свободна область от NC_END до APP_MEMORY_END. Точные границы находятся в bin/NC.sym.


NC включает локальную библиотеку [ui.inc](../include/ui.inc) для окон, инверсии выделения, копирования прямоугольников и строки F1–F8. Сначала файл подключается для макросов, затем с DEFINE UI_IMPLEMENTATION — для процедур и рабочих данных. Библиотека не зависит от state и может включаться в программу MAIN или её DLL.

Штатная сборка включает `NC_BITMAP_SCROLL=1`. При прокрутке на 1–19 файлов (1–20 при `FULL_PANELS=1`) NC переносит сохраняемый битмап двух колонок, включая строки на их общей границе, через `uiCopyRect` и штатный быстрый `bios_memcpy_bc_hl`. При шаге на один файл за край окна старый курсор остаётся на месте. Его строка исключается из источника копирования; соседнее имя восстанавливается обычным текстом, а новое имя печатается сразу инверсным поверх прежнего выделения. В остальных случаях старый курсор снимается, новый рисуется сразу после первой новой строки; оставшиеся новые строки идут в прежнем направлении. Большие переходы, в том числе дальние Home/End, используют полную текстовую перерисовку.

Выделение сохраняет битовую инверсию экранной памяти и видно на чёрно-белом дисплее. Ввод команды, Backspace, Escape и Ctrl+Enter не снимают и повторно не рисуют выделение панели.

Битмап-режим требует одного неизменного атрибута `COLOR_FILE` на всей области файлов. Цвета заголовков, рамки и строки сведений в неё не входят. Если появятся разные цвета файлов или маркировка строк, выбирайте `NC_BITMAP_SCROLL=0`: старый текстовый путь сохранён и также рисует курсор после первой строки. Флаг задаётся перед сборкой; переключение не требует изменения DOS.

Проверяемый пример отдельной текстовой сборки из корня репозитория: `tasm/sjasmplus.exe --i8080 -Wno-rdlow -DNC_BITMAP_SCROLL=0 --raw=bin/NC-text.i80 --sym=bin/NC-text.sym --lst=bin/NC-text.lst source/nc/NC.asm`. Штатная сборка выполняется через `build: OS` и использует битмап-режим. Не подменяйте обычные результаты вариантами с другими define.

NC.COM — обычная программа с загрузкой и входом 0000h (NC_LOAD_ADDR). Код, строки, встроенные малые буферы, метаданные общего кэша и 14 байт состояния входят в бинарник. Рабочие переменные, три слота каталогов по 4081 байту и индексные таблицы находятся за ним без включения в файл. Каждый слот хранит до 255 записей FILE_INFO по 16 байт и FF-терминатор. Состояние панелей сохраняется в B:\NCSTATE.TMP. Актуальные адреса задаёт bin/NC.sym.

Видимый список — указатель vars.fileListPtr внутрь собственной 256-байтной индексной таблицы панели. FILE_INFO берётся из назначенного панели общего слота; две панели могут ссылаться на один каталог с разными режимами сортировки. Сами записи не копируются и не переставляются. В каждом общем слоте сохраняется ещё одна 256-байтная таблица последнего использованного режима. Попадание каталога восстанавливает готовый индекс; если сохранён другой режим, индекс строится заново. Пустой каталог, FF-терминатор и предел 255 записей обрабатываются так же, как при обычном чтении.

NC использует обычный пакетный рендерер BIOS без пререндера. При запуске, перед внешней программой и выходом в CLI вызывается FONT_RENDER DISABLE; BUILD не вызывается, буфер на 10 КиБ не выделяется. Освобождённая основная память доступна для рабочих буферов NC; memTop не меняется.

Командная строка общая с DOS: vars.cmdLine = CMD_LINE; её актуальный адрес задаёт mxos.inc. Она находится в системной области и сохраняется при загрузке COM в нижнее ОЗУ. NC использует первые MAX_PATH байт, полный размер системного буфера — 130 байт.

`CLI.EXT` — системный файл A:. Ассоциации разрешает DOS/CLI при запуске команды через `bios_fileExec`; NC передаёт полный путь и аргументы в общей командной строке. Буфер таблицы принадлежит DOSMOD, код разбора ассоциаций в NC отсутствует.

Запуск внешней программы передаётся DOS хвостовым переходом. NC может быть затёрт уже при проверке контейнера. При обычном завершении программы или ошибке запуска DOS заново загружает NC. Графика ui.inc включается в NC локально; другие MAIN-программы и DLL включают собственную копию библиотеки.

Основной профиль проверки — системный Flash 512 КБ. F10 выходит в самостоятельный CLI, команда NC возвращает панели. Общие команды и ассоциации описаны в [документации CLI](../cli/README.md).

CPU-стенд общего кэша: `python scripts/tests/check-nc-catalog.py`. Ключ `--prepare-only` готовит входные образы без запуска CPU-стенда. Проверяются общий список и независимые индексы, полный ключ диск/кластер, закрепление H:\, выбор вытесняемого слота, восстановление сортировки, точные и томовые уведомления и отказ от сохранения ошибок чтения.

Проверка выделения: `python scripts/tests/check-nc-cursor.py`. Проверяется отсутствие инверсий при вводе и совпадение битмапа после прокрутки с полной перерисовкой и инверсией. Ключ `--variant NC-full`, `NC-text` или `NC-full-text` выбирает отдельно собранный вариант. Цветная проверка Emu80: `docs/nc/cursor-006/report.md`.

Файловые операции вызывает новый блок ABI DOS C8BAh–C8C6h: выбор диска, переименование, удаление, копирование и перечисление дисков. Переименование и удаление используют уже существующие реализации ядра. NC содержит диалоги и подготовку имён; циклы переноса данных, выделение и очистка назначения находятся в DOS. Проверка защиты удаления также выполняется DOS; NC после отказа выбирает подходящее сообщение.

Для F5/F6 NC передаёт vars.copyRequest (86 байт): имена, диски, каталоги и обработчик подтверждения замены. Поля buffer и bufferSize равны нулю. Банковый адаптер DOS использует собственный KD_DATA размером KD_CHUNK (4096 байт). Внутри одного тома MOVE переносит запись без данных; между томами действует COPY с последующим удалением.

Маркер сокращения задан строкой `pathOmissionMark` в NC.asm (по умолчанию `...`). PATH_OMISSION_LENGTH, PATH_PREFIX_LENGTH и PATH_RESERVED_LENGTH вычисляются через разность меток; при замене маркера вручную менять длины не нужно. Это только экранное представление, в файловые вызовы передаётся полный путь.

Первый пункт вложенного каталога `\` открывает корень диска; это экранное представление записи FAT `.`, сама файловая система и команда `CD .` сохраняют стандартный смысл текущего каталога. `..` открывает родителя. Каталоги помечаются `<DIR>` в статусной строке. Путь на рамке выводится белым. Приглашение обновляется до перерисовки панелей и не меняется при выборе другого файла. Введённый путь, как и Enter на файле, разрешается через DOS-сервис CLI.EXT; аргументы сохраняются, переполнение общей строки не допускается. Самостоятельный CLI.COM использует тот же сервис команд DOS и общий исходник редактора строки.

Строка NC и диалоги используют общий исходник редактора lineedit.inc. При пустой строке стрелки работают с панелью; при непустой — с текстом. Backspace удаляет символ слева. Команды без вывода не очищают экран; после DIR и других команд с выводом восстанавливаются панели и тулбар. Верх панели очищается от Y=0, горизонтальные линии и углы находятся на Y=4/6. Заголовки и статусные строки белые.

Тулбар задаётся полями UI_TOOLBAR_FIELD из ui.inc. Основная ячейка занимает 48 пикселей: 16 под F-клавишу и 32 под подпись. Во втором наборе при удержании Shift последние ячейки занимают 40 пикселей для F7 MD и 56 для F10 Exit; F10 показан только во втором наборе. Все поля имеют высоту 9 пикселей (Y=247..255). Локальная библиотека рисует их поверх прежнего тулбара сразу с окончательными битмапом и цветом, без промежуточного стирания и экранной инверсии. Битмап подписей остаётся инверсным для чёрно-белого дисплея. Отдельного обходного рисования F10 нет.

Переход в каталог через Enter, CD в командной строке и команды выбора диска A:/H: перечитывают и перерисовывают только активную файловую панель. Каталог, кэш, положение выбора и битмап другой файловой панели сохраняются. Если другая панель показывает информацию о диске, её данные обновляются. Команды с экранным выводом по-прежнему требуют восстановления обеих панелей.

При совпадении файлов NC показывает четыре выровненные кнопки Yes, Yes to all, No и No to all. По умолчанию выбран No; стрелки влево/вправо и Tab меняют выбор, Enter подтверждает. Y/N/A/S выбирают Yes/No/Yes to all/No to all напрямую, Escape означает No. Ответ to all действует только до конца текущей операции, включая все подкаталоги; следующая операция снова спрашивает. При копировании дерева существующие каталоги объединяются, каждый совпадающий файл запрашивается отдельно. Диалоги F5/F6/F8 и запуск F4 блокируются на служебных элементах `\` и `..`. Тексты ошибок подключаются из общего `source/include/errors.inc`, в ядре остаются только коды.

NC ведёт общие маски панелей: `ncDirtyMask` (изменился каталог, нужен новый список) и `ncDamageMask` (окно закрыло изображение, достаточно кэша). Биты 0/1 обозначают левую/правую панели. DOSMOD уведомляет о затронутых диске и каталоге через `CLI_OP_OBSERVER`; тихие команды и действия F-клавиш используют один механизм. Команда записи на B: не перерисовывает открытые A:/H:, а запись в другой каталог того же диска не перечитывает текущий. При переименовании/переносе каталога уведомление охватывает том, поскольку меняются пути потомков. Наблюдатель отключается перед запуском другой программы и выходом из NC. Тот же наблюдатель отменяет сохранённые каталоги и индексы даже для папок, которые сейчас не открыты ни на одной панели; при точном уведомлении отменяется только соответствующий кластер, при томовом — все слоты этого диска.

## Обновление панелей и кэш путей

Каждая панель хранит полный путь в собственном буфере MAX_PATH. Ключ кэша — диск и кластер каталога. Заголовок, приглашение и построение имени выбранного файла используют этот кэш: GETCWD нужен один раз при переходе в новый каталог. При уведомлении о файловом изменении пути панелей соответствующего диска инвалидируются, в том числе для переименования родительского каталога. Кэш не занимает память DOS. Общий кэш списков имеет тот же ключ — диск и кластер каталога; его метаданные и обработка уведомлений находятся в catalogCache.inc.

При переходе в каталог рамка сохраняется, имена фиксированной ширины печатаются поверх прежних. NC помнит прежнее число занятых строк отдельно для каждой из двух колонок каждой панели. Локальная функция clearColumnTail очищает только разность между новой и прежней высотой списка; при росте списка очистка не нужна. Пустое место между именем и расширением печатается пробелом, чтобы убрать прежний разделитель каталога. Полная отрисовка сохраняется для первоначального экрана, смены режима информационной панели и восстановления повреждённых диалогом или консольным выводом областей.

## Порядок полной перерисовки

При первом показе NC и полном восстановлении обеих панелей используется общий fullRedraw: сначала область обеих панелей заливается синим, затем рисуются обе рамки, затем заголовки и статусные строки файловых панелей либо содержимое информационной панели, и только после этого выводятся списки файлов. Рамки рисуются без повторной заливки внутренней области. Активная файловая панель готовит метаданные первой, чтобы информационная панель получила её актуальный счётчик файлов. После завершения сохраняются прежние активная панель, каталог и положение выбора.

При повреждении обеих панелей диалогом или консольным выводом используется тот же порядок; действительные списки повторно берутся из кэшей. Навигация и тихие команды по-прежнему обновляют только затронутую панель без заливки: печать поверх прежних строк и очистка освободившегося хвоста не менялись.

Поля NC выводятся через `bios_printStringReal` (C8EDh): поле имени 8 + разделитель + 3 собирается в одну строку из 12 знаков. Начала колонок — X=8/104 пикселя относительно панели; текст занимает 72 пикселя, оставляя 8 пикселей до левой границы ячейки и 16 до правой. Байтовые прямоугольники выделения и прокрутки сохранены. Заголовок пути выводится компактной строкой длиной до 28 знаков без пробельного заполнения, чтобы сохранить рамку. Путь в статусе занимает 20 знаков, размер или `<DIR>` — 8; эти поля дополняются пробелами. Поле ввода диалога начинается с X=120 и занимает 24 знака. Общий Lineedit включает пакетный вывод только для NC через `LINEEDIT_BATCH`; управляющие коды очистки экрана, переноса строки и Backspace остаются на обычном ABI BIOS.

Shift-F1 и Shift-F2 открывают диалог сортировки над левой и правой панелью соответственно; обычные F1/F2 выбирают диск. Диалог предлагает `[ ] Unsorted`, `[ ] Name` и `[ ] Extension`; `[x]` отмечает действующий режим. Стрелки и Tab перемещают выделение, Enter или пробел применяют выбор, Escape отменяет. Для новой панели по умолчанию действует сортировка по расширению, затем по имени; сохранённый выбор панели имеет приоритет.

При сортировке по имени ключи — имя и расширение; при сортировке по расширению — расширение и имя. Сравнение использует штатное приведение KOI-8 к верхнему регистру. Служебные пункты `\` и `..` стоят первыми, затем каталоги, затем файлы; каталоги сортируются по тем же двум ключам. При равных ключах сохраняется порядок исходных записей. Смена режима сохраняет выбранный файл и восстанавливает только затронутую панель из кэша, без чтения каталога. Таблица строится стабильной LSD radix-сортировкой байтовых индексов; сами FILE_INFO не переставляются. При чтении старого 12-байтного NCSTATE.TMP контексты панелей сохраняются, оба режима сортировки устанавливаются в Extension; новый 14-байтный файл сохраняет отдельный режим каждой панели.

Регрессионный CPU-стенд `scripts/tests/check-nc-sort.py` проверяет оба режима сортировки и Unsorted, независимость панелей, неизменность записей кэша, выбор FILE_INFO, пустой список и границы до 255 записей. `--prepare-only` готовит 60 входных образов памяти без запуска CPU-стенда.

Общий кэш содержит три каталога с выбором по давности использования. Каталог соседней панели не вытесняется; успешно прочитанный корень H: закреплён до уведомления об изменении. Поэтому при переходах по вложенным папкам корень остаётся доступен без нового DIR_OP_LIST. При возврате меняется ссылка панели на слот и восстанавливаются 256 байт индексов; полный список FILE_INFO не копируется. Дополнительные данные относительно прежних двух кэшей занимают 4849 байт: один каталог 4081 байт и три сохранённых индекса по 256 байт. Ошибка чтения не делает слот действительным. Кэш очищается при запуске нового NC, поэтому изменения внешних программ, перед которыми наблюдатель отключается, не остаются незамеченными после возврата в оболочку.

В выборе диска каждая строка из максимум четырёх букв центрируется отдельно по горизонтали. Одна строка центрируется по вертикали под заголовком; при пяти–восьми дисках две строки располагаются симметрично относительно того же центра. Положение выделения рассчитывается той же функцией, что и положение букв. Пробельного заполнения после последней буквы нет.

## Рабочие ключи сортировки

NC_SORT_KEYS содержит 11 нормализованных разрядов имени/расширения и разряд ранга, каждый в отдельном выровненном массиве на 256 байт. Подготовка выполняет штатный KOI-8 upperCase один раз для каждого байта. Ключи общие для обоих режимов; меняется только порядок проходов 8+3 или 3+8. Ранг идёт старшим разрядом, исходный порядок равных ключей сохраняется стабильными проходами. Режим без сортировки возвращает исходный индекс без подготовки ключей.

Radix пропускает постоянные разряды, очищает и суммирует только диапазон фактических значений min..max, строит гистограмму последовательным чтением разряда и чередует исходную индексную таблицу с временным буфером. Единственное итоговое копирование требуется, если результат оказался во временном буфере. Индексы панелей выровнены на 256 байт. Ключи занимают 3072 байта, счётчики и временный индекс — ещё 512 байт; область не сохраняется в кэше каталогов и используется только при перестроении индекса.

В NC остаётся только рабочий radix. Shell, вставки, quicksort, слияние, их компараторы и независимая копия radix перенесены в [SortBench](../../source-apps/sortbench/README.md). В составе NC сравнительных методов и переключателя NC_SORT_RADIX больше нет.
