# Файловый менеджер NC

Каталоги поддерживаются через bios_directory DOS. Enter открывает выбранный каталог, `..` возвращает к родителю; `/` и `\` принимаются в командах CD/CHDIR. Две панели сохраняют независимые контексты даже на одном диске. Заголовки и приглашение имеют вид `H:\Almaz\STD`; приглашение завершается `>`. Заголовок и статусная строка сокращают длинный путь по целым компонентам: `A:\...\RAMFOS\Almaz-2.exe`. Полный путь сохраняется в MAX_PATH-буфере. В приглашении показывается хвост длинного пути. Ввод команды прокручивается в пределах строки и не перечитывает каталог при каждом символе. Пока видимое окно не сдвигается, ввод и удаление меняют только один знак; при сдвиге обновляется текст команды без очистки приглашения. Заголовки Name убраны; обычная панель показывает 19 строк в каждой из двух колонок (38 записей).

Enter/F4/Ctrl+Enter формируют абсолютный путь к выбранному файлу. Предел общей команды — 127 байт; превышающая его добавка не вставляется частично. Копирование по F5 по умолчанию использует каталог противоположной панели, в том числе на том же диске. Текстовый буфер диалога имеет MAX_PATH байт; видимая область из 23 знаков прокручивается. F7 создаёт каталог, F8 удаляет пустой каталог. F6 перемещает файл в каталог противоположной панели; внутри тома меняются только записи каталога, без копирования содержимого.

12-байтный NC_STATE сохранён по прежнему адресу в хвосте RAM-диска, версия метки изменена на 5Bh. Вместо восстанавливаемых счётчиков файлов и режима информационных панелей хранятся два 16-битных контекста каталогов. При старой метке панели начинают с корня. Текстовые пути восстанавливаются через GETCWD, не занимая место в системных постоянных данных.


NC загружает `A:DOSMOD.COM` через C8D8h до первого графического обращения. Сам модуль занимает 6800h–8BFFh, а штатный memtop равен 67FFh. Размер буфера копирования ограничивается текущим memtop; окно модуля не входит в буферы NC. Фиксированные графические адреса BIOS сохранены как шлюзы в модуль.

Карта от 04.11.2026: общая командная строка находится по FA00h, стек DOS — под экраном, SP=8FDFh. Буфер копирования NC заканчивается перед 6800h, оставляя переходники запуска и стек неприкосновенными. Графический ABI остаётся в DOS.


NC вызывает общий графический модуль DOS для окон, инверсии выделения и строки F1–F8. Оконные списки и обработчики клавиш остаются в NC; модуль не зависит от `state`. ABI описан в [документации модуля DOS](../dos/ui/README.md).

Штатная сборка включает `NC_BITMAP_SCROLL=1`. При прокрутке на 1–19 файлов (1–20 при `FULL_PANELS=1`) NC переносит сохраняемый битмап двух колонок, включая строки на их общей границе, через `bios_uiCopyRect` и штатный быстрый `bios_memcpy_bc_hl`. При шаге на один файл за край окна старый курсор остаётся на месте. Его строка исключается из источника копирования; соседнее имя восстанавливается обычным текстом, а новое имя печатается сразу инверсным поверх прежнего выделения. В остальных случаях старый курсор снимается, новый рисуется сразу после первой новой строки; оставшиеся новые строки идут в прежнем направлении. Большие переходы, в том числе дальние Home/End, используют полную текстовую перерисовку.

Выделение сохраняет битовую инверсию экранной памяти и видно на чёрно-белом дисплее. Ввод команды, Backspace, Escape и Ctrl+Enter не снимают и повторно не рисуют выделение панели.

Битмап-режим требует одного неизменного атрибута `COLOR_FILE` на всей области файлов. Цвета заголовков, рамки и строки сведений в неё не входят. Если появятся разные цвета файлов или маркировка строк, выбирайте `NC_BITMAP_SCROLL=0`: старый текстовый путь сохранён и также рисует курсор после первой строки. Флаг задаётся перед сборкой; переключение не требует изменения DOS.

Проверяемый пример отдельной текстовой сборки из корня репозитория: `tasm/sjasmplus.exe --i8080 -Wno-rdlow -DNC_BITMAP_SCROLL=0 --raw=bin/NC-text.i80 --sym=bin/NC-text.sym --lst=bin/NC-text.lst source/nc/NC.asm`. Штатная сборка выполняется через `build: OS` и использует битмап-режим. Не подменяйте обычные результаты вариантами с другими define.

NC.COM — обычная программа с загрузкой и входом `0000h` (`NC_LOAD_ADDR`). На 05.11.2026 NC.i80 содержит 6948 байт кода, строк и начальных данных; рабочие переменные и малые буферы — ещё 632 байта. Два кэша каталогов по 4081 байту находятся по `1D9Ch–2D8Ch` и `2D8Dh–3D7Dh`. Каждый хранит до 255 компактных записей по 16 байт и FF-терминатор. 12 байт состояния панелей сохраняются в хвосте RAM-диска.

Видимый список — указатель `vars.fileListPtr` внутрь кэша активной панели. Прокрутка и переключение панелей повторно не вызывают `bios_fileList` и не копируют дескрипторы. Каталог читается с начала один раз при первой загрузке панели; изменение видимого каталога, выбор диска или принудительное обновление инвалидируют только нужный кэш. Смена диска также проверяется по тегу кэша. При возврате из программы оба кэша создаются заново. Индексы NC остаются 8-разрядными: показываются первые 255 файлов, если каталог больше; текущий H: с корнем на 192 записи помещается целиком.

Потоковый буфер `3E00h–66FFh` занимает 10496 байта; фактическая ёмкость дополнительно ограничена memtop. NC с буферами занимает нижние 26368 байт, включая 130 байт выравнивания. DOSMOD начинается с 6700h; его область не используется как буфер.

Командная строка общая с DOS: `vars.cmdLine = CMD_LINE = FA00h`. Она находится в системной области и сохраняется, пока загрузчик COM затирает нижнее ОЗУ. NC использует первые MAX_PATH байт для редактора строки; DOS сохраняет полный прежний размер своего буфера — 130 байт.

`CLI.EXT` — системный файл A:. Ассоциации разрешает DOS/CLI при запуске команды через `bios_fileExec`; NC передаёт полный путь и аргументы в общей командной строке. Буфер таблицы принадлежит DOSMOD, код разбора ассоциаций в NC отсутствует.

Запуск внешней программы передаётся DOS хвостовым переходом. NC может быть затёрт уже при проверке контейнера. При обычном завершении программы или ошибке запуска DOS заново загружает NC. Графический модуль остаётся в DOS и доступен программам независимо от NC.

Основной профиль проверки — системный Flash 512 КБ. F10 выходит в самостоятельный CLI, команда NC возвращает панели. Общие команды и ассоциации описаны в [документации CLI](../cli/README.md).

Проверка кэшей: `python scripts/tests/check-nc-cache.py`. Покрываются раздельные каталоги панелей, попадание без перечитывания, обновление после инвалидации, смена диска, пустой каталог, границы 255 записей и выбор окна. Текущий отчёт замеров: `docs/nc/cache-005/report.md`.

Проверка выделения: `python scripts/tests/check-nc-cursor.py`. Проверяется отсутствие инверсий при вводе и совпадение битмапа после прокрутки с полной перерисовкой и инверсией. Ключ `--variant NC-full`, `NC-text` или `NC-full-text` выбирает отдельно собранный вариант. Цветная проверка Emu80: `docs/nc/cursor-006/report.md`.

Файловые операции вызывает новый блок ABI DOS C8BAh–C8C6h: выбор диска, переименование, удаление, копирование и перечисление дисков. Переименование и удаление используют уже существующие реализации ядра. NC содержит диалоги и подготовку имён; циклы переноса данных, выделение и очистка назначения находятся в DOS. Проверка защиты удаления также выполняется DOS; NC после отказа выбирает подходящее сообщение.

Для F5/F6 NC передаёт vars.copyRequest (84 байта): имена, диски, каталоги, адрес COPY_BUFFER и его размер. Внутри одного тома MOVE не использует буфер данных; между томами действует COPY с последующим удалением. Неявного буфера поверх кода NC нет.

Маркер сокращения задан строкой `pathOmissionMark` в NC.asm (по умолчанию `...`). PATH_OMISSION_LENGTH, PATH_PREFIX_LENGTH и PATH_RESERVED_LENGTH вычисляются через разность меток; при замене маркера вручную менять длины не нужно. Это только экранное представление, в файловые вызовы передаётся полный путь.

Первый пункт вложенного каталога `\` открывает корень диска; это экранное представление записи FAT `.`, сама файловая система и команда `CD .` сохраняют стандартный смысл текущего каталога. `..` открывает родителя. Каталоги помечаются `<DIR>` в статусной строке. Путь на рамке выводится белым. Приглашение обновляется до перерисовки панелей и не меняется при выборе другого файла. Введённый путь, как и Enter на файле, разрешается через DOS-сервис CLI.EXT; аргументы сохраняются, переполнение общей строки не допускается. Самостоятельный CLI.COM использует тот же сервис команд DOS и общий исходник редактора строки.

Строка NC и диалоги используют общий исходник редактора lineedit.inc. При пустой строке стрелки работают с панелью; при непустой — с текстом. Backspace удаляет символ слева. Команды без вывода не очищают экран; после DIR и других команд с выводом восстанавливаются панели и тулбар. Верх панели очищается от Y=0, горизонтальные линии и углы находятся на Y=4/6. Заголовки и статусные строки белые.

Тулбар задаётся полями UI_TOOLBAR_FIELD из ui.inc. Основная ячейка занимает 48 пикселей: 16 под F-клавишу и 32 под подпись. Во втором наборе при удержании Shift последние ячейки занимают 40 пикселей для F7 MD и 56 для F10 Exit; F10 показан только во втором наборе. Все поля имеют высоту 9 пикселей (Y=247..255). DOSMOD рисует их поверх прежнего тулбара сразу с окончательными битмапом и цветом, без промежуточного стирания и экранной инверсии. Битмап подписей остаётся инверсным для чёрно-белого дисплея. Отдельного обходного рисования F10 нет.

Переход в каталог через Enter, CD в командной строке и команды выбора диска A:/H: перечитывают и перерисовывают только активную файловую панель. Каталог, кэш, положение выбора и битмап другой файловой панели сохраняются. Если другая панель показывает информацию о диске, её данные обновляются. Команды с экранным выводом по-прежнему требуют восстановления обеих панелей.

При совпадении файлов NC показывает четыре выровненные кнопки Yes, Yes to all, No и No to all. По умолчанию выбран No; стрелки влево/вправо и Tab меняют выбор, Enter подтверждает. Y/N/A/S выбирают Yes/No/Yes to all/No to all напрямую, Escape означает No. Ответ to all действует только до конца текущей операции, включая все подкаталоги; следующая операция снова спрашивает. При копировании дерева существующие каталоги объединяются, каждый совпадающий файл запрашивается отдельно. Диалоги F5/F6/F8 и запуск F4 блокируются на служебных элементах `\` и `..`. Тексты ошибок подключаются из общего `source/include/errors.inc`, в ядре остаются только коды.

NC ведёт общие маски панелей: `ncDirtyMask` (изменился каталог, нужен новый список) и `ncDamageMask` (окно закрыло изображение, достаточно кэша). Биты 0/1 обозначают левую/правую панели. DOSMOD уведомляет о затронутых диске и каталоге через `CLI_OP_OBSERVER`; тихие команды и действия F-клавиш используют один механизм. Команда записи на B: не перерисовывает открытые A:/H:, а запись в другой каталог того же диска не перечитывает текущий. При переименовании/переносе каталога уведомление охватывает том, поскольку меняются пути потомков. Наблюдатель отключается перед запуском другой программы и выходом из NC.
