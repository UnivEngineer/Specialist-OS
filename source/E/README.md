# E.COM — текстовый редактор

Разбор текущей реализации на 24.10.2026. Историческая инструкция находится в
[главном README](../../README.md), запись от 11.02.2022. Ниже описан код с
`STANDARD_EDITOR = 0`, а расхождения отделены от предполагаемых исправлений.

## Исходники и сборка

`E.asm` задаёт конфигурацию, карту памяти и порядок включения модулей:

| Файл | Назначение |
|---|---|
| `startup.inc` | Вход, данные сеанса, обнаружение конца текста, цикл состояния |
| `keyboard.inc` | Диспетчер клавиш, таблицы обычных и Esc-команд |
| `edit.inc` | Буфер редактируемой строки, вставка/удаление символов, сдвиг текста |
| `blocks.inc` | Табуляция, страницы, выделение и удаление строк |
| `tape.inc` | Исторический формат ленты, чтение, запись и проверка |
| `search.inc` | Поиск, соединение/разбиение строк, копирование/перенос выделения |
| `screen.inc` | Примитивы памяти, курсор, прокрутка и строка состояния |
| `files.inc` | Дисковые операции, имя файла, дескриптор |
| `entry.inc` | F4–F6, вход с аргументом, проверка размера файла |

Модули включаются последовательно; между некоторыми процедурами есть проход
без перехода. Менять порядок `INCLUDE` без анализа этих связей нельзя.
Внутренние адресные метки заменены смысловыми именами; клавиатурные обработчики
и существующие именованные точки сохранены.

Из корня репозитория:

```powershell
powershell.exe -NoProfile -File scripts/build/build-project.ps1 OS
```

Исторические `E-orig.asm` и `E-orig.0xD000.COM` находятся в `originals/`.
В ASM переименованы 226 внутренних символов; для общих участков использованы
те же имена, что и в текущем редакторе. Машинный код, данные и адреса сохранены,
эталонный COM не изменён. Эти файлы не участвуют в штатной сборке. Чтобы собрать
оригинал, находясь в `source/E`, и сохранить его старый относительный INCLUDE:

```powershell
../../tasm/sjasmplus.exe --i8080 -Wno-rdlow --inc=. --raw=../../bin/E-original.com originals/E-orig.asm
```

Эта команда воспроизводит приложенный исторический COM побайтно.

## Управление и уточнения исторической инструкции

| Клавиша | Действие по коду |
|---|---|
| F1 | Переключить вставку/замену; первоначальное значение — замена |
| F2 / F3 | Перелистать вверх/вниз на 22 строки, с ограничением по документу |
| F4 | Открыть дисковый файл вместо текста |
| F5 | Сохранить текст на диск, включая завершающий `0FFh` |
| F6 | Добавить дисковый файл поверх маркера конца документа |
| F7 | Запросить образец и искать после верхней видимой строки |
| F8 | Отменить незавершённое редактирование текущей строки |
| ← / → / ↑ / ↓ | Переместить курсор; переходы по вертикали ограничены текстом |
| Shift+← / Shift+→ | Перейти через пробелы и слово в пределах строки |
| Del | Удалить символ в позиции курсора со сдвигом хвоста строки |
| Enter | Вставить строку ниже; перенести отступ из начальных пробелов |
| Tab / Shift+Tab | Следующая/предыдущая позиция табуляции, без вставки байта Tab |
| Home / End (ПС) | Начало строки / позиция после последнего непробельного символа |
| СТР | Немедленный выход в оболочку без сохранения на диск и подтверждения |

Сетка Tab задана `t_tabSteps = 4, 5, 8`: позиции с нуля — **4, 9, 17, 25,
33, 41, 49, 57**, затем ограничение столбцом 62. Это специальная сетка,
а не меняющийся случайно шаг. Shift опрашивается непосредственно через бит 1
порта `IO_KEYB_B`. Эти же модифицированные стрелки в старой инструкции отсутствуют.

Экран содержит 24 строки текста, страницы перекрываются на две строки.
F8 работает, пока изменения находятся в буфере строки; после ухода со строки
или команды, вызывающей `commitLineEdit`, прежнюю строку восстановить нельзя.
СТР также вызывает `commitLineEdit`: диск не обновляется, но текст в ОЗУ
может уже содержать последние изменения.

| Последовательность | Действие по коду |
|---|---|
| Esc, Home | Перейти к началу документа |
| Esc, End | Показать последнюю страницу, используя проход к концу и F2 |
| Esc, L | Начать/расширить выделение целыми строками |
| Esc, U | Снять выделение |
| Esc, C / M / D | Копировать ниже текущей строки / перенести / удалить выделение |
| Esc, S | Разбить строку в позиции курсора |
| Esc, J | Объединить текущую и следующую строки, соединяя через пробел |
| Esc, N | Очистить документ; подтверждение только заглавной латинской `Y` |
| Esc, O | Историческая запись текста на ленту с именем |
| Esc, I | Историческая загрузка текста с ленты |
| Esc, V | **Проверить** текст по записи на ленте; это не другой формат загрузки |
| Esc, G | Историческая загрузка с ленты в конец текста |

Esc отпускается перед второй клавишей. Буквенные команды сравниваются с
заглавными латинскими кодами, преобразования регистра в редакторе нет.
Esc, V сравнивает байты, затем проверяет сумму; совпавшие байты записываются
обратно теми же значениями. При ошибке выводится `MISTAKE.`.

Магнитофон сознательно вынесен из DOS; штатная работа с лентой — через отдельно
загружаемую `TAPE.COM`. Приведённые Esc-команды описывают сохранённые старые
обработчики E. Они требуют действующих магнитофонных точек BIOS; их наличие
в таблице клавиш само по себе не означает установку драйвера.

### Поиск и файлы

F7 начинает поиск со строки **после верхней строки страницы** (`v_topLine`),
а не с позиции курсора (`v_currentLine`). Образец — до 14 символов. Enter в
первом запросе повторяет предыдущий образец. Регистр учитывается. Найденная
строка становится верхней строкой страницы. При неудаче — четыре сигнала и
переход в начало документа. Алгоритм не возвращается к следующему возможному
началу после частичного совпадения: например, может пропустить `AAB` в `AAAB`.

В текущем варианте поле имени имеет **16 символов**, а не исторические 9;
`A:NAME1234.TXT` помещается. Однако из `FILE_NAME_HISTORY` восстанавливаются только первые
10 байтов, хотя после запроса в него сохраняются все 16: восстановление
длинного имени осталось несогласованным.
Enter принимает показанное имя, первый печатный символ начинает ввод нового,
← стирает предыдущий символ, СТР отменяет запрос. Достижение предела длины
уводит из запроса в перерисовку редактора, а не просто игнорирует лишний символ.
При запуске с аргументом имя не копируется в этот буфер — замечание старого
README об отсутствии подставленного имени остаётся справедливым.

Текст начинается с `01800h`, верхняя граница — `08500h` (27904 байта).
Перед открытием проверяется размер меньше 27904, включая старшее слово поля
размера. Файлы от 27904 байтов отвергаются с `OUT OF MEMORY`.
Строки разделяет `0Dh`, документ завершает `0FFh`; первый нулевой байт при
просмотре превращается в `0FFh`. Преобразования LF/CRLF нет, сохранение не
удаляет маркер. Произвольный современный текстовый файл поэтому не равнозначен
документу внутреннего формата E. Символ KOI-8 с кодом `0FFh` (Ъ) внутри текста
невозможен. Сканирование не останавливается по размеру загруженного файла или
по верхней границе, если нет `00h`/`0FFh`.

Большинство переменных лежит **в образе самой программы**, а не под экраном.
Под экраном объявлены 11 байтов `editor_vars` с `08F80h`; текст и сохранённое
имя также находятся вне загружаемого образа. Сохранность текста между запусками
зависит от использования этих участков другими программами, а не гарантируется
редактором.

## Самомодификация и обнаруженные дефекты

Адреса ниже относятся к текущей сборке с размещением E по `0E800h`.
В исходниках места записи в инструкции отмечены словом «САМОМОДИФИКАЦИЯ».

| Место | Что изменяется |
|---|---|
| `smc_entryDispatch` | Операнд первого `JP`: первый запуск обрабатывает аргумент, последующие идут в `beginSession` |
| `beginSession` → `smc_resetSessionStack+1` | Значение SP сеанса внутри `LD SP,nn` |
| `saveCursor` → `smc_restoreCursor+1` | Координаты курсора внутри `LD HL,nn` |
| `insertScreenRow` → `smc_scrollPairCount+1` | Число копируемых пар байтов внутри `LD A,n` |
| `clearTextViewport` → `smc_restoreClearStack+1` | SP перед временным использованием стека для очистки экрана |
| `beginLineEdit` | Первые 64 байта с `startupBannerAndLineBuffer`, `0E80Ah–0E849h`, становятся буфером строки |
| `readAndCompareTapeName` | Имя с ленты без ограничения длины записывается с `smc_sessionTarget+1`, то есть с `0E81Ah`, поверх операнда и стартового кода |

Самая опасная связь: `restartAfterLoad` находится **внутри буфера строки**.
F4 и F6 после загрузки переходят на эту метку даже после того, как
`beginLineEdit` заполнил область пробелами/текстом. То есть после начала
редактирования путь открытия файла может исполнять текст вместо команд.
Это следует непосредственно из адресов и записей в памяти; интерактивный
сценарий в emu в рамках этого разбора не проверялся.

В F6 есть ещё два независимых дефекта. Ветви нехватки общего места после
`PUSH HL` не снимают сохранённый указатель: завершение обработки ошибки может
использовать его как адрес возврата. Кроме того, суммарная проверка использует
размер файла, тогда как DOS передаёт целые 256-байтные секторы; запас для
последнего сектора и перенос при 16-битном сложении не проверяются.

`keyHandler_F3_2` действительно недостижим из основного ввода: код `02h` уже
перехвачен обработчиком PageDown. Другая скрытая точка — второй `JP` по
`0E803h`, ведущий в `resumeAtTextPointer` с указателем в HL. Он не является
второй пользовательской командой F3.

## Предложение реализации без изменения инструкций

Следующий вариант **предложен, но не включён** в рефакторинг:

1. Выделить явную рабочую область, например `01700h–017FFh`, перед текстом.
   В ней поместятся отдельный 64-байтный буфер строки, ограниченный буфер имени
   ленты, 17-байтное сохранённое имя файла и состояние. Диапазон нужно закрепить
   в локальной карте памяти E; он не должен захватывать экран или стек.
2. Заменить патч первого JP проверкой байтовой переменной первого входа.
   Переменную инициализировать нулём при загрузке образа, а не полагаться на
   прежнее содержимое рабочей памяти. Это позволяет сохранить повторный вход
   по `0E800h` и отдельный вход `0E803h`.
3. Хранить курсор, SP сеанса, SP очистки и счётчик прокрутки в данных.
   Для восстановления SP использовать `LD HL,(savedSP)` / `LD SP,HL` —
   это допустимые 8080-команды LHLD/SPHL.
4. Для `resetSessionStack` отдельно сохранить снятый адрес возврата, загрузить
   SP через HL, затем вернуть адрес в HL и выполнить `JP (HL)`. Так сохранятся
   BC, DE, AF и флаги прежнего контракта; наивная замена через DE его нарушает.
5. После F4/F6 идти в постоянную процедуру переинициализации просмотра.
   Удалить связи со стартовой заставкой и буфером строки; все ошибочные ветви
   F6 должны балансировать стек. Границы проверять по фактическому объёму
   секторной передачи, а конец текста ограничивать загруженным размером.

Цена отдельных замен на 8080: `LD HL,nn` → `LD HL,(nn)` занимает те же 3 байта
кода и добавляет 6 тактов чтения; данные курсора требуют 2 байта.
`LD A,n` → `LD A,(nn)` добавляет 1 байт кода, 1 байт данных и 6 тактов на
экранный столбец — 288 тактов (144 мкс при 2 МГц) на 48 столбцов.
Это не требует Z80-инструкций или нового DOS ABI. Итоговый размер всего
варианта нужно измерять после реализации, учитывая удалённый стартовый код.

## Проверка рефакторинга

Переименованы 218 внутренних символов, код разбит на девять модулей.
Поведение, адреса и расположение данных сохранены, включая описанные дефекты.
Размер `bin/E.com` до и после — **3758 байтов**, диапазон `0E800h–0F6ADh`.
SHA-256 в обоих случаях:

```text
8462715ac758be086aba2d0938e5f95a59051becd3267b0556d5670fb3018366
```

Дополнительно собраны все четыре комбинации `NEW_MEMORY_MAP = 0/1` и
`STANDARD_EDITOR = 0/1`: каждая побайтно совпала со своей сборкой до
рефакторинга. Сравнены адреса всех прежних символов с учётом переименования:
505 символов в текущем варианте, 506 в варианте STANDARD_EDITOR.

Использован SjASMPlus `--i8080 -Wno-rdlow`, ошибок и предупреждений нет.
Проверены листинг, сборка OS и подготовка листингов для emu. Пересобранный
`images/SystemRom_emulator.bin` также сохранил прежний SHA-256.
Изменения поведения и аппаратные проверки в эту работу не входят.
