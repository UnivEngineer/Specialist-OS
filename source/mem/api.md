# Публичный ABI памяти и печати MXOS

Этот документ закрепляет контракт MEM ABI 1.3. Номера операций, адреса и структуры задаются в `source/include/mxos.inc`; номера BIOS/DOS генерируются из `source/bios/syscalls.json` в ASM- и C-заголовки. Внутренние адреса обработчиков, раскладки профилей окна и реестра выделений не являются API приложения. Примеры ниже используют только инструкции 8080.

## Адреса и контекст

FAR-адрес — `{bank:byte, offset:word}`, little-endian, 3 байта. Код 0 означает main, 1…16 — физические банки ДОЗУ 0…15; `{0,0}` — nullptr. NEAR-адрес — обычный 16-битный адрес в банке вызывающей программы. Переход в DOS не меняет смысл указателей приложения: файловый/памятный сервис получает исходный банк отдельно от банка своего исполнения.

| Точка | Назначение |
|---|---|
| F800h / mx_call | B=группа, C=номер, DE → локальный MX_REGS |
| F806h / mx_callRegs | CALL с последующим DW номера функции; параметры в регистрах |
| F809h / mx_queueBind | HL → локальный flush-callback, 0 отключает; AF разрушается |
| F80Ch / mx_queueFlush | Явный flush; все регистры и флаги сохраняются |
| F80Fh / mx_memcpyFar | HL → локальный пакет MEM_COPY_REQUEST |
| F812h / mx_memInfo | Версия, возможности, банк исполнения |
| F815h / mx_memory | A=операция памяти, параметры по таблице ниже |
| F818h / mx_routeCall | HL=handle DLL внутри MODULE_SCOPE, DE → локальный MX_REGS. Результаты в AF/BC/DE/HL |

MX_REGS занимает 8 байт: HL, DE, BC, AF; каждое поле — слово little-endian (для AF сначала F, затем A). F800h принимает пакет в памяти исходного банка; при нормальном вызове возвращает результат и в регистрах CPU, и в пакете. При отказе транспорта до выполнения операции CF=1, пакет не изменяется. F806h сохраняет входные регистры в локальном кадре для чтения DW операции, но не записывает результат обратно во временный пакет: результат возвращается непосредственно в AF/BC/DE/HL. После DW продолжается код программы. Номер операции не отнимает регистр у вызываемой функции.

F80Fh/F812h/F815h локальны: DOS для них не вызывается. Перед использованием должен быть установлен полный профиль MEM и корректный локальный стек. Банк данных содержит только хвост копировщика: вызывать из него F800h/F815h нельзя. Нативный FILE_EXEC и RUN запускают BANK-программы через описанный ниже модульный загрузчик; он устанавливает профиль EXEC и локальный стек.

Банк исполнения и SP восстанавливаются после каждого вызова. Требуются выключенные IRQ. Собственный код, стек, запросы и системные области нельзя перекрывать данными; аппаратной защиты нет. API переноса/GET/PUT проверяет диапазон, но не принадлежность адресов выделенному блоку. Ограничение `<FF00h` не разрешает затирать MEM, драйверы, экран или DOS внутри этого диапазона.

## Перенос и скалярный доступ

MEM_COPY_REQUEST занимает 8 байт: sourceBank (+0, byte), sourceOffset (+1, word), destinationBank (+3, byte), destinationOffset (+4, word), count (+6, word). Пакет находится в памяти инициатора и должен оставаться действительным до возврата.

| Вызов | Вход | Успешный результат | Сохраняется |
|---|---|---|---|
| F80Fh memcpy_far | HL → MEM_COPY_REQUEST | A=0, CF=0 | BC, DE, HL |
| F815h MOVE, A=0 | HL → MEM_COPY_REQUEST | A=0, CF=0 | BC, DE, HL |
| F815h GET8, A=1 | B=банк, HL=адрес | DE=байт, D=0; A=0, CF=0 | BC, HL |
| F815h GET16, A=2 | B=банк, HL=адрес | DE=слово; A=0, CF=0 | BC, HL |
| F815h PUT8, A=3 | B=банк, HL=адрес, E=байт | A=0, CF=0 | BC, HL, DE |
| F815h PUT16, A=4 | B=банк, HL=адрес, DE=слово | A=0, CF=0 | BC, HL, DE |

memcpy требует отсутствия перекрытия; memmove/MOVE допускает его. Нулевой count возвращает успех без проверки банков и диапазонов. При ненулевом count все байты должны лежать ниже FF00h, исключающий конец может быть равен FF00h. Перенос через 10000h запрещён. Для GET/PUT8/16 банк и диапазон обеспечивает программа: горячий путь их не проверяет. Последний допустимый адрес слова — FEFEh, байта — FEFFh. При ошибке содержимое назначения не меняется, DE при ошибке GET не определён; BC/HL сохранены.

При совпадении обоих банков с банком исполнения используется установленный локальный стековый memcpy/memmove (в main — bios_memcpy_bc_hl, в DOS — тот же скомпилированный движок). Межбанковый memcpy использует CPM32, включая остаток без чтения за концом. MOVE внутри другого банка выполняет направленный цикл в окне, между разными банками — CPM32. Установка нулевого локального обработчика выключает локальное ускорение, сохраняя корректность.

F812h возвращает HL=0103h, A=FAR-код исполнения, B=число банков ДОЗУ, C=назначение банка (DATA=0, EXEC=1, DOS=2), DE=возможности, CF=0. DE bit0=перенос FAR, bit1=ленивое окно, bit2=F815h операции памяти, bit3=публичные операции модулей DOS, bit4=аллокатор DOS с FILL/QUERY и управлением пулом RAM-диска, bit5=очередь команд. Остальные флаги не определены.

## Аллокатор DOS

`MXOS_DOS_MEMORY = 0226h`: группа B=2, номер C=26h. Вход через F800h/F806h; A=MEM_OP_* в регистровом пакете. Операции 1…4 GET/PUT имеют тот же контракт, что локальный F815h. MOVE=0 и PRINT=5 здесь не поддерживаются: использовать локальные точки MEM/BIOS. Неописанные операции возвращают DOS_ERR_UNSUPPORTED.

| A | Операция | Вход | Успешный результат |
|---:|---|---|---|
| 6 | ALLOC | B=банк либо FFh (любой DATA), HL=байты | B:HL=FAR-адрес, DE=запрошенный размер, A=0, CF=0 |
| 7 | FREE | B:HL=точный адрес начала блока | A=0, CF=0; остальные регистры не определены |
| 8 | REALLOC | B:HL=блок, DE=новый размер | B:HL=новый адрес, DE=новый размер, A=0, CF=0 |
| 9 | ARENA | B=0, HL=начало свободной main-области, DE=байты | A=0, CF=0; остальные регистры не определены |
| 10 | RAMLIMIT | B=число банков RAM-диска | CF=0; остальные регистры не определены |
| 11 | FILL | B=банк, HL=адрес, DE=байты, C=значение | A=0, CF=0; остальные регистры разрушены |
| 12 | QUERY | B=конкретный банк | HL=свободные байты, DE=наибольший промежуток, B=банк, C=свободные записи; A=0, CF=0 |
| 13 | DISKCLAIM (исторический) | Текущий зарегистрированный резидент | Закрепляет пул за резидентом; штатный RAMDISK не использует |
| 14 | RAMDISK | C=0 STATUS, C=1 COMMIT | B=число банков пула, C=состояние владельца; A=0, CF=0 |
| 15 | RESIDENT | B=0 QUERY / 1 REPLACE, C=системный слот, HL=байты, DE=защищённый конец | HL=адрес, DE=размер, BC=memTop; A=0, CF=0 |
| 16 | MAINCLAIM | HL=начало, BC=байты | Освобождает перекрывающиеся неактивные MAIN-модули; A=0, CF=0 |
| 17 | MAINREGISTER | B=0, HL=ненулевое начало MAIN-буфера, DE=байты | B=0, HL=начало, DE=байты, A=0, CF=0 |
| 18 | MAINRETIRE | Нет | Снимает регистрацию образа и блоков текущего MAIN-приложения, A=0 и CF=0 |

MAINRETIRE используется перед передачей управления через системный стек без возврата в вызывающее приложение. Например, NC_MN освобождает свои диапазоны перед запуском DOS-лаунчера, которому может понадобиться DLL в MAIN. Операция разрешена вне контекста DLL.

MAINREGISTER регистрирует уже размещённый буфер с точными границами, включая нечётные адреса. Содержимое не меняется; операция не ищет место, не перемещает и не выгружает модули, не меняет арену ARENA. Начало и размер должны быть ненулевыми, весь диапазон должен находиться ниже системного предела MAIN с учётом установленного шрифта. Пересечение с любой существующей записью, включая собственную, возвращает MEM_ERROR_ACTIVE; неверные границы — MEM_ERROR_RANGE, заполненный реестр — MEM_ERROR_NOMEM. При отказе реестр не меняется. Статические данные/BSS, уже объявленные в заголовке исполняемого образа, повторно регистрировать нельзя.

Буфер получает обычного владельца текущего приложения или модуля. FREE с B=0 и HL=начало освобождает регистрацию; RET приложения и выгрузка модуля освобождают её автоматически. Чужие буферы учитываются при публикации memTop и проверке размещения исполняемых образов. MODULE_LOAD не может затереть живой буфер вызывающего приложения. FILE_EXEC при замене MAIN-программы освобождает все её блоки, даже если новый образ пересекает только зарегистрированный хвост, а не код. Буфер EXEC-резидента остаётся занятым до явного освобождения или выгрузки владельца: регистрация сама по себе не обещает его сохранения при запуске несовместимой MAIN-программы.

В C SDK операция доступна как `mxos_main_register(start, bytes)` из `mxos_far.c`; освобождение — `mxos_free_far` с адресом `{0, start}`. Динамическую память с выбором адреса по-прежнему выделяют через ARENA/ALLOC. MAINCLAIM лишь подготавливает диапазон и не заменяет MAINREGISTER.

Для обычной программы предпочтительны существующие механизмы: постоянные буферы объявляются в BSS/рабочем диапазоне заголовка, динамические выделяются через ARENA/ALLOC. Например, NC.COM описывает состояние, индексы и графический scratch как BSS, указывает MIN_HEAP для минимальной вместимости каталогов, а при запуске выделяет каталоги одним блоком по фактическому memTop. MAINREGISTER для этого не требуется; его отличие — закрепление уже существующего буфера с точным адресом, без изменения арены и содержимого.

Реестр в DOS вмещает 32 одновременно выделенных блока, запись занимает 6 байт `{bank,offset,size,owner}`; заголовков внутри самих блоков нет. Поиск первого подходящего промежутка, выравнивание начала 2 байта. Размер 16-битный, блок целиком помещается в одном банке. Запрошенные байты не инициализируются. ALLOC(0) возвращает `{0,0}`, DE=0, не резервируя запись. FREE(nullptr) успешен. При освобождении блок не обнуляется.

REALLOC(nullptr,n) эквивалентен ALLOC(ANY,n), REALLOC(p,0) освобождает и возвращает nullptr. Уменьшение сохраняет адрес. При увеличении сначала резервируется новый блок, затем копируются прежние байты и освобождается старый; при любой ошибке старый блок и данные остаются действительными. Рост main-блока остаётся в main, рост DATA-блока может перенести его в другой свободный DATA-банк. Содержимое добавленной области не определено. При ошибке значения выходных адресных регистров не использовать; C-обёртка оставляет переданный FAR-адрес прежним.

ALLOC в main разрешён только после ARENA: начало не ниже 0100h, исключающий конец не выше 8C00h. Регистрация — доверенная передача собственного диапазона, не поиск памяти поверх кода. Локальная C-куча не должна раздавать эти же байты. Арену нельзя менять, пока у текущего владельца есть main-блоки; чужие блоки остаются занятыми и исключаются при поиске. MAIN-приложения, запущенные FILE_EXEC/FILE_EXEC_NATIVE, получают временные теги 20h–27h по глубине вызова (до восьми); вложенные запуски сохраняют прежние owner/арену. RET освобождает блоки и дочерние модули приложения, затем восстанавливает контекст родителя. Теги повторно используются только после очистки; это идентичность живого вызова, не долговечный PID и не защита от устаревшего сырого FAR-указателя. Модули используют приватные теги 80h–87h. Вызовы вне загрузчика сохраняют прежний контекст банка; их автор сам освобождает временные блоки. Выделения системного владельца DOS сохраняются при тёплом входе.

До подготовки RAMDISK весь не-DOS пул зарезервирован для B:. Одноразовый RAMDISK.COM с флагом DRIVER выбирает размер через RAMLIMIT, проверяет разметку или вызывает FORMAT для пустой памяти и передаёт готовый пул самой DOS через RAMDISK/COMMIT. Модульный handle, резидентный процесс и FAR-запись для пула не создаются. COMMIT разрешён только во время DRIVER-инициализации; DOS повторно проверяет сектор 256 байт и геометрию B: перед сменой владельца. STATUS доступен из любого контекста и не меняет пул. Повторный COMMIT для того же пула DOS допустим; чужой модульный владелец не подменяется. При ошибке прежнее владение сохраняется. Пул исключён из DATA/EXEC-выделений и сохраняется при Reset независимо от завершения установщика. -P 4 означает четыре банка данных плюс DOS: из шестнадцати свободны одиннадцать. Нужны минимум два банка ДОЗУ. Без -P закреплённый пул сохраняет прежний размер; повторный запуск проверяет разметку без форматирования. Изменение размера запрещено до холодной загрузки DOS. SHRINK/GROW и вызов установщика по запросу DOS пока не реализованы. Исторический DISKCLAIM=13 оставлен совместимым, но штатный RAMDISK его не использует.

## Печать

| Операция | HL | Выполнение |
|---|---|---|
| MXOS_BIOS_PRINT_STRING / PRINT_STRING_BANK = 0107h | ASCIIZ в банке инициатора | Из main нативно, из банка через Window20 |
| MXOS_BIOS_PRINT_STRING_MAIN = 0124h | ASCIIZ в main | Нативный bios_printString в main, передаются только регистры |
| F815h, A=5 (PRINT) | Локальная ASCIIZ | Тот же автоматический выбор main/Window20 без упаковки MX_REGS |

Во всех случаях HL возвращается на завершающем нуле, BC/DE сохранены. BIOS PRINT_STRING/PRINT_STRING_MAIN сохраняют AF при успешной печати. Прямой F815h PRINT возвращает CF=0; остальные флаги не сохраняются (A занят кодом операции). Строка включает управляющие коды, как обычный bios_printString. Для Window20 валидность строки обеспечивает программа; проверка границ в горячем цикле отсутствует. Строки идут через COMMAND, отдельного профиля TEXT нет. PRINT_STRING_MAIN принимает явный main-адрес без проверки владения или поиска конца буфера; срок жизни строки обеспечивает программа. Номер банка в HL закодировать нельзя: отдельная операция MAIN задаёт его однозначно.

Window20 автоматически разбивает строку на порции до 20 байт и печатает непосредственно из аппаратного окна, без промежуточного main-блока. Порция копируется без предварительного поиска NUL: соответствующий строковый рендерер сам находит терминатор в пределах порции. После строкового вызова TEXT остаётся активным; последующий PRINT_CHAR/PRINT_CHAR_RAW использует его без восстановления COMMAND. При другом активном протоколе посимвольный вызов идёт через COMMAND.

```asm
    ld hl,localText
    MXOS_CALL MXOS_BIOS_PRINT_STRING_BANK
    ld hl,mainBufferAddress
    MXOS_CALL MXOS_BIOS_PRINT_STRING_MAIN
```

## Резидентная память системных модулей

`MXOS_DOS_MEMORY`, A=`MEM_OP_RESIDENT` (15): B=0 запрашивает слот, B=1 заменяет его резервацию. C=идентификатор 0–3; `MEM_RESIDENT_FONT` (0) принадлежит установленному шрифтовому движку. Для замены HL=размер, кратный 256, DE=исключающий конец защищённой рабочей памяти установщика и его вызывающих компонентов. HL=0 освобождает слот. Это доверенный системный интерфейс, не обычный malloc приложения. Идентификаторы закреплены за службами; посторонняя программа не должна освобождать их блоки. Владелец обязан прекратить использование старого блока перед его освобождением и не вызывать рендер между заменой резервации и установкой подготовленного движка.

При успехе CF=0, A=0, HL=адрес блока (0 для пустого), DE=его размер, BC=включительная граница memTop. Остальные регистры и флаги разрушены. Ошибка CF=1 с кодом MEM_ERROR_RANGE/NOMEM/OWNER не меняет прежнюю резервацию. Ненулевой размер округлять должен вызывающий; невыравненный размер отклоняется. Резервация не очищает и не переносит данные. Замена может изменить адрес блока, поэтому установщик подготавливает новые данные и переподключает движок до следующего использования.

Новый блок размещается ниже остальных системных блоков. Старые блоки других слотов не перемещаются. При освобождении верхнего блока может остаться промежуток: memTop остаётся ниже самого нижнего занятого системного блока и повышается после его освобождения. MEM отклоняет пересечение с зарегистрированными MAIN-выделениями и указанной защищённой памятью. Выдача MAIN-блоков, QUERY и загрузка MAIN-модулей учитывают резидентную границу, включая восстановленные арены родительских программ. Прикладной SET_MEM_TOP исторически остаётся простым присваиванием; он не освобождает системные блоки и не отменяет границу менеджера.

Резервации принадлежат системным службам, переживают appLeave/moduleWarm и программный возврат в оболочку. Освобождение выполняется явно той же службой. При восстановлении BIOS через Bootstrap они сбрасываются, поскольку стандартный движок и его раскладка загружены заново. memTop публикуется через скалярный банковый SET_MEM_TOP; GET_MEM_TOP также доступен из BANK.

## Состояние шрифтового модуля

`MXOS_BIOS_FONT_RENDER` (0125h), A=0: CF=0, A=0/1 (вращения/пререндер), HL=нижний буфер, BC=размер нижнего буфера, DE=верхний шрифт. Старый BUILD 10-КиБ таблицы больше не поддерживается. DISABLE успешен только для Rotate; для Packed6K требуется смена всего комплекта через FONT. Подробности — [шрифтовые модули](../font/README.md).

## Ошибки и ленивое окно

| Код A при CF=1 | Значение |
|---|---|
| E0h | Недопустимый FAR-код банка |
| E1h | Нет места в стеке/допустимой глубины вложенного перехода |
| E2h | Недопустимая операция F815h или диапазон адресов |
| E3h | Нет подходящего блока либо свободной записи реестра |
| E4h | Неверный адрес/владелец FREE или модуля, занятый RAM-диском банк, недоступная арена/изменение разметки |
| E5h | Нулевой, неизвестный или уже выгруженный дескриптор модуля |
| E6h | Попытка вызова или выгрузки активного модуля |

Ошибки внешнего DOS/BIOS диспетчера (неподдержанная функция, неверный MX_REGS, занятость обработчика) используют DOS_ERR_* из общего заголовка. RAMLIMIT дополнительно может вернуть ошибку физического чтения B:. Флаги кроме оговорённых CF и сохранённого AF не являются результатом API.

32-байтное окно принадлежит MEM; приложение не сохраняет и не восстанавливает его самостоятельно. После memcpy_far, GET/PUT и прямой Window20 может оставаться профиль COPY, SCALAR, LOCAL или TEXT. Повторная операция использует нужный профиль; COMMAND восстанавливается только при необходимости вызова/возврата. Локальный стековый перенос не меняет профиль. Это гарантированное ленивое поведение, но коды профилей и их внутренние адреса не входят в публичный контракт.

## C SDK

`MXOS_FAR_ADDRESS` — 3 байта, `MXOS_FAR_COPY` — 8 байт. Использовать заголовок mxos.h; обёртки аллокатора и scalar находятся в дополнительном mxos_far.c, регистровый мост — в mxos_z88dk.asm и входят в вызывающую программу. Функции памяти возвращают слово AF: CF в младшем байте, код A в старшем. Указатель-результат malloc изменяется только при успехе, realloc сохраняет прежний адрес при ошибке, free обнуляет адрес при успехе. Нормальные void* и malloc локальной C-кучи этим API не заменяются. Старые SDK-функции с прямыми Cxxx-вызовами рассчитаны на main; банковые программы используют явно поддержанные F8xx-точки.

## Загрузка и синхронный вызов модулей

| Номер MXOS_CALL | Операция | Вход | Успешный результат |
|---|---|---|---|
| 0226h / MXOS_DOS_MODULE_LOAD | moduleLoad | HL → путь MAX_PATH в банке инициатора, A=0 main, A=1 новый EXEC-банк, A=2 арена DOS | HL=непрозрачный ненулевой handle, A=0, CF=0 |
| 0227h / MXOS_DOS_MODULE_CALL | moduleCall | HL=handle, DE → локальный MX_REGS (8 байт) | A=0, CF=0; регистры модуля записаны в MX_REGS |
| 0228h / MXOS_DOS_MODULE_UNLOAD | moduleUnload | HL=handle | A=0, CF=0; handle больше не действителен |

BC/DE и неоговорённые результаты самих API-вызовов не определены. AF модуля, включая CF, возвращается в его MX_REGS и не смешивается со статусом moduleCall: модуль может вернуть CF=1 при успешной диспетчеризации. При отказе входа или проверки MX_REGS его исходные байты сохраняются. Пакет MX_REGS находится именно в банке программы, вызывающей moduleCall, проверяется до входа и не пересылается как NEAR-указатель в чужую память. Он должен целиком заканчиваться не выше IO_BANK_KEYS (F040h), без оборота адреса. Сам модуль начинает исполнение с AF/BC/DE/HL из пакета, а заканчивает обычным RET с результатами в этих регистрах. Изменение SP или MX-режима, аппаратного окна либо переход на C000h/C800h вместо RET не входит в контракт модуля.

Используется тот же 32-байтный контейнер COM/EXE/DLL/FNT версии 2, что RUN: сигнатура CD 20 4D 58 02, флаги 0, IMAGE_FLAG_BANK=02h, IMAGE_FLAG_MAIN=04h либо IMAGE_FLAG_DRIVER=01h для DOS-DLL, фиксированные адреса загрузки и входа, длина и две штатные суммы calcCS. Для модулей используется расширение DLL: обычный FILE_EXEC их не запускает, загрузка выполняется через MODULE_LOAD. Размещение в main, EXEC-банке или арене DOS явно задаёт A; оно не определяется расширением. Флаг IMAGE_FLAG_BANK требует MODULE_TARGET_BANK; загрузка такого модуля в main отвергается до записи тела. IMAGE_FLAG_MAIN требует MODULE_TARGET_MAIN. При флагах 0 DLL остаётся нейтральной только между MAIN/BANK. IMAGE_FLAG_DRIVER требует MODULE_TARGET_DOS; этот target, в свою очередь, требует DRIVER-флага. Старые имена COM/EXE остаются допустимыми для MODULE_LOAD. RKS и сменные ядра не допускаются. Вход должен лежать внутри тела; релокаций нет; отдельная BSS и полный рабочий диапазон задаются в заголовке и не обнуляются загрузчиком. Файловый поиск, чтение и проверка сумм выполняются DOS через существующий imageOpen/imageLoad; загрузчик не запускает CLI/RUN и не выбирает ассоциации. Сумма тела считается при чтении с носителя, без повторного прохода после пересылки.

Для A=0 main загрузчик резервирует точный declared interval [memoryBegin,memoryEnd), включая BSS и рабочие области ниже load. Предварительная регистрация ARENA для статического образа не нужна. Конфликты проверяются до записи тела по EXCLUSIVE/PRESERVE/MANAGED; активного MAIN-родителя MODULE_LOAD не перезаписывает. Модуль вызывается на служебном стеке BIOS (256 байт суммарно, 64 байта запаса MEM), совместно с вложенными службами BIOS. Транспорт доверяет программе глубину вызовов и использование стека; большой отдельный MAIN-стек не предоставляется. Загрузчик проверяет заявленный размер стека при подготовке образа.

Для A=1 менеджер резервирует целиком свободный DATA-банк, устанавливает полный профиль MEM и отдельный служебный стек 576 байт. Полный диапазон кода/данных вместе с minHeap должны заканчиваться не выше начала стека EE00h; стек занимает EE00h–F03Fh, далее расположен банковый сегмент клавиатуры IO.SYS, полный MEM начинается F1C0h. DOS, диапазон B: и банки хотя бы с одним чужим блоком не рассматриваются. Ни номер банка, ни адрес входа/стека пользователь не выбирает через handle. Прямой FREE резервирования образа запрещён; оно освобождается только через moduleUnload. При выгрузке банк снова получает назначение DATA, хвост копировщика остаётся доступным. Полный хвост пока не уплотнён для 62-КиБ приложений CP/M.

Для A=MODULE_TARGET_DOS (2) код исполняется в физическом банке ДОЗУ 0, FAR-код DOS_IO_PAGE=1. Target — селектор размещения, а не FAR-номер банка. Диапазон [memoryBegin,memoryEnd) обязан целиком лежать в единой арене 9800h–B4FFh; расширение в B500h–CB7Fh допускается только при отсутствии активного BAT. Вход находится внутри тела. Реестр хранит точные start/end каждого образа без округления и фиксированных слотов: несколько непересекающихся DOS-DLL могут сосуществовать. MEM, кэш, ядро DOS и служебный стек не входят в образ DLL; отдельная локальная куча DOS для него не выделяется.

Пересечение с загруженной DLL или активным установщиком возвращает MEM_ERROR_ACTIVE до записи тела. Пересечение с неактивным кэшем FILEOPS вытесняет только FILEOPS; при активной файловой операции её код закреплён до CLOSE. Непересекающиеся интервалы независимы. DRIVER-установщики собираются от верхней границы B500h: load=end−size, адрес берётся из заголовка COM. Ранее установленные физические службы продолжают работать. Локальный RAW и файловый MXOS_CALL из DOS-DLL используют её банк и локальные буферы; BIOS доступен через MXOS_CALL. C000h/C800h в банке DOS не являются BIOS. MODULE_CALL использует служебный стек DOS EE00h–F03Fh с вложенными кадрами возврата; возвращается обычным RET.

DOS-DLL владеет FAR-выделениями и дочерними модулями по обычным правилам; moduleUnload освобождает их и резерв арены, сохраняя назначение банка DOS. Отказ загрузки после резервирования также освобождает интервал. RETAIN разрешён для DOS-DLL вне заимствованных кадров BAT: служба отделяется от владельца и сохраняет код, handle и ресурсы при Reset. RETAIN для тела, выходящего за B500h, запрещён с MEM_ERROR_OWNER (E4h). Зарегистрированный BANK-резидент и его потомки не могут загрузить DOS-DLL; доступ к DOS-слотам остаётся ограничен обычными временными владельцами при загрузке. Возврат в оболочку, завершение приложения и Reset освобождают обычную DOS-DLL вместе с владельцем. Для сохраняемой службы доступны BANK + RETAIN либо DOS + RETAIN в арене DOS вне буфера BAT. Это не фоновые потоки: вход вызывается синхронно.

Одновременно допускаются 8 модулей; резерв MAIN/BANK-образа также занимает одну из 32 записей общего FAR-аллокатора. DOS-DLL занимает запись модуля и отдельный резерв арены, без записи FAR-аллокатора. 16-битные handle выдаются последовательно, не переиспользуются до перезагрузки DOS: старый handle не обозначит другой модуль после unload/load. После 65535 успешных загрузок дальнейшая загрузка возвращает E3h до новой сессии DOS. Нулевой/неизвестный/устаревший handle даёт E5h, активный — E6h, чужой владелец — E4h. Занятость/недопустимость main-диапазона даёт E2h либо E3h (нет подходящего блока), отсутствие целого свободного банка или записи — E3h, неверный контейнер — DOS_ERR_BAD_IMAGE; файловые ошибки сохраняют коды DOS. Отказы освобождают уже зарезервированную память и установленный контекст; чужие области не изменяются. Повторные последовательные вызовы сохраняют данные тела модуля. Рекурсивный вход в уже активный handle запрещён, вложенный вызов другого загруженного модуля разрешён.

При moduleCall исходный банк и SP сохраняет MEM. Состояние внешнего DOS-запроса находится в локальном стековом кадре; модуль может выполнять MXOS_CALL BIOS/DOS и вызывать дочерние модули. Аллокатор помечает новые блоки приватным тегом текущего модуля. moduleUnload освобождает образ, собственные блоки, дочерние модули и зарегистрированную им main-арену. Активный модуль выгружать нельзя. RETAIN отделяет BANK-модуль от родителя и делает самостоятельным сервисом: его handle доступен другим владельцам через RESIDENT. Перед RETAIN нельзя иметь main-арену или main-блоки; зарегистрированному резиденту ARENA запрещена, поскольку основную память заменяет следующая программа. Общего share/transfer API для обычных блоков нет. Низкоуровневые операции остаются доверенными: аппаратной защиты от записи в чужую память нет.

Reset и возврат в оболочку через C000h/C800h отбрасывают стеки приложений: DOS освобождает временные модули и выделения, отменяет main-арену, но сохраняет зарегистрированные BANK-резиденты и DOS-службы вне буфера BAT, их дочерние модули и FAR-блоки, системные блоки DOS, счётчик handle и RAM-диск. Обычный RET из moduleCall ресурсы не освобождает. Нативный FILE_EXEC запускает BANK через модульный механизм и после RET освобождает временный образ; зарегистрированный резидент остаётся. DE у BANK-приложения содержит NEAR-аргументы в нижней части служебного стека F000h, стек ограничен снизу F0C0h. A=0, BC=0, HL=0; входные флаги не определены. FILE_EXEC возвращает CF/A статуса загрузки/вызова, а не результат main. RUN передаёт MAIN/DRIVER/BANK этому загрузчику через FILE_EXEC_NATIVE. Вытеснения, фоновых потоков и восстановления PC после Reset нет: повторная активация резидента — явный вызов его входа.

NEAR внутри AF/BC/DE/HL не преобразуется. Например, если соглашение модуля принимает B=FAR-код и HL=смещение общей структуры, приложение передаёт именно такую пару, а модуль использует GET/PUT или memcpy_far. Нельзя передавать main-адрес в HL и ожидать автоматического доступа к main из банка; для текста есть явный PRINT_STRING_MAIN. Вызов произвольного адреса ядра не предоставляется. Код в банке DOS допускается только в явно загруженной DOS-DLL или одноразовом DRIVER-инициализаторе, в пределах выделенной им арены.

```asm
    ld hl,modulePath          ; MAX_PATH байт, например 'B:\BANKMOD.DLL',0
    ld a,MODULE_TARGET_BANK
    MXOS_CALL MXOS_DOS_MODULE_LOAD
    jp c,error
    ld (moduleHandle),hl
    ld de,moduleRegs          ; HL, DE, BC, AF в памяти текущей программы
    MXOS_CALL MXOS_DOS_MODULE_CALL
    jp c,error
    ; AF результата модуля находится в moduleRegs+6.
    ld hl,(moduleHandle)
    MXOS_CALL MXOS_DOS_MODULE_UNLOAD
    jp c,error
moduleHandle: DW 0
moduleRegs: DW 01234h,02345h,03456h,0
modulePath: DB 'B:',05Ch,'BANKMOD.DLL',0
    DS MAX_PATH-($-modulePath),0
```

Пример main-контроллера измерений в DOS; имя DLL передаётся как обычный путь, а внутренние адреса ядра ему не нужны:

```asm
    ld hl,dosModulePath
    ld a,MODULE_TARGET_DOS
    MXOS_CALL MXOS_DOS_MODULE_LOAD
    jp c,error
    ld (dosModuleHandle),hl
    ld de,dosModuleRegs       ; Локальный MX_REGS контроллера в main.
    MXOS_CALL MXOS_DOS_MODULE_CALL
    jp c,unloadAfterError
    ld hl,(dosModuleHandle)
    MXOS_CALL MXOS_DOS_MODULE_UNLOAD
    jp c,error
    ; Продолжение контроллера.
```

Тело такой DLL собирается с `IMAGE_FLAGS = IMAGE_FLAG_DRIVER`, `ORG DOS_BANK_DRIVER_ADDR`, например с собственным `sectorBuffer: DS 512,0` и циклом `MXOS_CALL MXOS_DOS_RAW_IO` или FILEHANDLE. Вход заканчивается RET; переменные dosModulePath/dosModuleRegs/dosModuleHandle находятся у контроллера, а sectorBuffer — внутри DLL. Сборщик контейнера сохраняет флаг из ASM; смена расширения COM на DLL сама по себе флаг не устанавливает. В C контроллер использует `mxos_module_load(path, MXOS_MODULE_DOS, &handle)`, прежние mxos_module_call/unload. DISKBEN может вынести таймер и весь измеряемый цикл в такую DLL: граница main↔DOS пересекается при одном moduleCall, а не на каждом секторе. Диск для измерений нужно выбирать после MODULE_LOAD: файловый загрузчик может изменить выбранный диск. Сам DISKBEN этим расширением ещё не переводится.

C-обёртки находятся в sdk/src/mxos_module.c. `MXOS_MODULE_REGS` — точные 8 байт HL/DE/BC/AF, тогда как прежний `MXOS_REGS` имеет 10 байт и дополнительное поле entry для прямого BIOS-моста; это разные структуры. module_load изменяет handle-результат только при успехе. Передавать в API внутренние адреса MEM, сохранять аппаратное окно или вручную устанавливать хвосты не требуется.


## Нативный запуск без ассоциаций

MXOS_DOS_FILE_EXEC_NATIVE=022Ah принимает HL → локальная строка явного пути COM/EXE с аргументами, до MAX_PATH. Возвращает CF/A статуса, банк и SP вызывающей стороны сохраняются при обычном RET. Поиск PATH, встроенные команды CLI и ассоциации не применяются; файловый инициализатор DRIVER и отдельный BANK выбираются тем же штатным загрузчиком, что FILE_EXEC. Для main память родителя не резервируется: если приложение затирает вызывающий код, продолжение должно находиться вне его диапазона либо завершать работу через C000h/C800h. RUN использует для этого защищённый переходник. FILE_EXEC сохраняет CLI/PATH, но сначала проверяет заголовок найденного COM/EXE: MAIN/DRIVER/BANK исполняются до ассоциаций, flags=0 передаётся обработчику CLI.EXT. При отсутствии ассоциации сохраняется прежний прямой запуск. Повреждённые заголовки, неизвестные и несовместимые флаги дают DOS_ERR_BAD_IMAGE. Флаг MAIN=04h явно подтверждает main/MXOS-совместимость; flags=0 не означает такого подтверждения для RUN. Сочетания MAIN/DRIVER/BANK запрещены. DLL напрямую не запускаются.

Основные имена текстового API: PRINT_CHAR, PRINT_CHAR_RAW, PRINT_STRING_Z, PRINT_STRING_RAW_Z и PRINT_STRING_RAW_LIM. Старые имена PRINT_CHAR_REAL/PRINT_STRING/PRINT_STRING_REAL оставлены как псевдонимы для исходников проекта; Raw теперь выводит управляющие коды как глифы.

| API | MAIN ABI | MXOS_CALL | Вход и завершение |
|---|---:|---:|---|
| printChar | C809h | 0102h | C=код, управляющие коды обрабатываются |
| printCharRaw | C869h | 0114h | A=код; все 00h–FFh являются глифами |
| printStringZ | C818h | 0107h | HL=ASCIZ, управляющие коды обрабатываются |
| printStringRawZ | C8EDh | 0126h | HL=ASCIZ, 01h–FFh являются глифами, 00h завершает |
| printStringRawLim | C8F0h | 0128h | HL=массив, BC=длина; все 00h–FFh являются глифами |
| printStringRawPseudo | C8F6h | 012Dh | HL=массив, BC=длина; дополняет псевдографику KOI8-R до 10 пикселей |

Оба посимвольных входа сохраняют AF/BC/DE/HL, строковые — AF/BC/DE. Строки возвращают HL на терминаторе либо на исключающем конце заданного массива. После достижения правого края курсор переносится на следующую строку. Raw не изменяет состояние ESC. Для явно переданного main-указателя из банка есть PRINT_STRING_Z_MAIN=0124h, PRINT_STRING_RAW_Z_MAIN=0127h и PRINT_STRING_RAW_LIM_MAIN=0129h. Обычные строковые MXOS_CALL из BANK работают с NEAR-источником через Win20.

PRINT_STRING_RAW_PSEUDO из BANK принимает NEAR-указатель и сам передаёт BC байт порциями до 20 байт. Нулевые байты рисуются как глифы. При BC=0 экран и курсор сохраняются.

### TEXT_PRINT, 012Ah

HL указывает на TEXT_PRINT_REQUEST в банке клиента: `{kind:byte, method:byte, source:word, count:word, buffer:word, capacity:word}`. kind=0/1/2 выбирает StringZ/RawZ/RawLim. method=1 использует общий 256-байтный буфер BIOS, совместно используемый дисковыми драйверами; method=2 использует main-буфер программы. Для method=2 buffer — явный main-адрес, capacity — размер порции, предоставленный программой через ARENA/ALLOC. Поле source — NEAR-адрес текста в вызывающем банке, count — доступное число байт (для Z включает терминатор, для Lim является точной длиной). Нулевой count ничего не печатает.

Один MXOS_CALL автоматически копирует и печатает все порции. Для Z нет предварительного поиска конца: после копирования ставится защитный NUL за порцией, а рендерер прекращает обработку на настоящем терминаторе или границе порции. Поэтому пользовательский буфер для Z должен иметь capacity+1 доступных байтов; для Lim записываются только capacity байт. Проверка диапазона оставляет один защитный байт и для Lim. Копирование, переключения и рендер входят в вызов. CF=0/A=0 означает успех, HL — исходный адрес терминатора либо конец массива; CF=1/A=ARGUMENT — неверный пакет или диапазон. Память не выделяется и не освобождается внутри TEXT_PRINT; программа сохраняет владение своим буфером до окончания вызова.

## Заполнение и диагностика

FILL проверяет банк и весь диапазон до первой записи; при нулевой длине возвращает успех без проверки адреса. Использует PUT8 и удваивающиеся неперекрывающиеся копии уже заполненного префикса. Максимальный исключающий конец FF00h; это не разрешение перезаписывать защищённые области внутри диапазона. QUERY возвращает доступные для аллокатора промежутки конкретного банка с учётом двухбайтового выравнивания; main описывает текущую арену и требует её владельца. Для DOS/банков RAM-диска и целиком занятого EXEC-банка свободный объём равен нулю. Количество свободных записей относится ко всему реестру; при нуле записей ненулевой свободный объём ещё не означает успешный ALLOC.

## Резиденты — MXOS_DOS_RESIDENT (022Ah)

| A | Операция | Вход | Результат |
|---:|---|---|---|
| 0 | RETAIN | DE=ненулевой уникальный ключ, вызов из текущего BANK-модуля или DOS-модуля вне заимствованного буфера BAT | CF=0, модуль отделён от родителя и сохраняется при Reset |
| 1 | FIND | DE=ключ | HL=handle либо 0; при совпадении B=следующий индекс, C=банк, DE=ключ |
| 2 | ENUM | B=начальный индекс 0…7 | HL=следующий handle, B=следующий индекс, C=банк, DE=ключ; HL=0 и B=8 в конце |
| 3 | SHELL_SET | DE=ключ банковой оболочки либо 0 для NC_MN | CF/A=статус. Выбор NC/CLI по SET_SHELL сохраняется отдельно |
| 4 | SHELL_RESUME | Нет | RESTORE: A=1, остальные регистры нулевые. Возвращает CF/A модуля. При отсутствии резидента CF=1, A=0, в HL выбранный ключ |
| 5 | DIRECTORY_EPOCH | B=0 | HL=младшее слово, DE=старшее слово общего 32-битного поколения изменений |
| 5 | DIRECTORY_EPOCH | B=FEh, HL=NEAR буфер 32 байта | Восемь little-endian 32-битных поколений дисков A:..H: |
| 6 | RELEASE | Из текущего модуля | Снять собственный ключ и передать модуль DOS; физическая выгрузка после RET |

Возврат оболочки выполняется системным диспетчером на свежем стеке, без сохранённого указателя в MAIN-загрузчик. SHELL_SET получает ключ BANK-резидента, а нулевой ключ выбирает NC_MN. Если резидент отсутствует, SHELL_RESUME возвращает CF=1, A=0 и выбранный ключ в HL. После вызова резидента DOS делает автоматический MODULE_UNLOAD A=1: сохранённый резидент остаётся, снявший ключ освобождается. RELEASE не освобождает исполняемый код непосредственно и не является заменой CLOSE из внешней программы. Для другого неактивного резидента используется обычный MODULE_UNLOAD либо кооперативный CLOSE SDK.

После RETAIN разрешены отслеживаемые временные MAIN-арены и дочерние MAIN-DLL, например графический бэкенд NC. Это не делает их системными резервами: пересечение нового MAIN-образа с кодом или BSS освобождает неактивную DLL целиком, а активная DLL запрещает загрузку с ACTIVE. Непересекающийся CLI её сохраняет. Неизвестные MAIN-программы и верхние пусковые утилиты требуют освобождения MAIN-модулей и отменяют поколения всех дисков; скрытые обращения legacy вне объявленных диапазонов не защищены аппаратно. Первичная регистрация RETAIN по-прежнему требует отсутствия MAIN-ресурсов и потомков. Публикуемый BIOS memTop дополнительно ограничивается началом самой нижней MAIN-DLL; после её загрузки/освобождения он пересчитывается. Размер системного резерва FONT не меняется; явные FAR-арены могут использовать свободные промежутки с учётом таблицы выделений.

Поколения увеличиваются перед попыткой изменения, включая частично неудачную запись, и сохраняются после отключения временного наблюдателя CLI. Глобальное поколение и поколения дисков переполняются по модулю 2^32. Они не заменяют точные уведомления по каталогу во время активности приложения. Напрямую меняющий носитель внешний код требует консервативной отмены кэша.

Запись резидента использует существующий модульный handle, не отдельный указатель на код. При RETAIN повторный/занятый ключ возвращает OWNER, main-размещение — RANGE. FIND/ENUM не вызывают программу. MODULE_CALL передаёт её собственный пакет регистров; MODULE_UNLOAD — явное принудительное удаление неактивного сервиса и его ресурсов. Для исторического DISKCLAIM выгрузка резидента-владельца запрещена (ACTIVE). Штатный RAM-диск принадлежит DOS и не имеет модульного handle. Внутренний вариант MODULE_UNLOAD A=1 применяется загрузчиком после RET и сохраняет резидента; приложения для явной выгрузки передают A=0.

Соглашение SDK для входа резидента: A=0 — начальная инициализация, A=1 — RESTORE, A=2 — CLOSE. RESTORE сам восстанавливает прикладной интерфейс; CLOSE сохраняет данные и возвращает CF=1 при отказе. mxos_resident_close вызывает CLOSE и только при успехе MODULE_UNLOAD; mxos_resident_kill вызывает MODULE_UNLOAD без callback. Это кооперативный контракт, без таймаута зависшего обработчика. Штатный RAM-диск не использует эти callbacks: его пул принадлежит DOS.

## Локальная C-куча

sdk/src/mxos_heap.c реализует локальные кучи с двухбайтовым выравниванием, четырёхбайтовыми заголовками и объединением соседних свободных блоков. sdk/src/mxos_stdlib.c подключает стандартные malloc/free/realloc/calloc к mxos_default_heap. Отдельные MXOS_HEAP позволяют ядру или библиотеке использовать тот же аллокатор с собственной ареной. Куча не обращается к DOS и не выдаёт чужую страницу при нехватке. Нулевое выделение возвращает NULL, free(NULL) ничего не делает, realloc(p,0) освобождает блок, отказ роста сохраняет прежние данные, calloc проверяет переполнение произведения.

sdk/runtime/crt0.asm — старт sccz80 для самостоятельного MAIN/BANK-приложения: обнуляет BSS, сохраняет аргументы и home-page, инициализирует кучу от конца BSS до memTop+1 в main или F000h в BANK. Стек остаётся предоставленным загрузчиком. Этот CRT не предназначен для MAIN-DLL, разделяющей память с родителем, или для повторного RESTORE резидента: таким модулям нужен собственный вход и явные границы MXOS_HEAP. Конструкторы C++, стандартные потоки и аtexit этим минимальным CRT не реализуются. Поддержка обычных C++ new/delete требует выбранного C++-компилятора и отдельного runtime.

Резидент регистрируется до загрузки дочерних модулей; RETAIN при существующих потомках возвращает OWNER. После регистрации разрешены отслеживаемые MAIN-ресурсы, но их срок жизни отличается от кода EXEC-резидента: MAIN-DLL может быть выгружена при пересечении с новой программой, и её handle нужно проверять при RESTORE. Собственный зарегистрированный MAIN-буфер резидента остаётся занятым до FREE или выгрузки владельца и может препятствовать запуску пересекающегося образа. Долговременные данные храните в EXEC; восстанавливаемые MAIN-буферы удобно передавать во владение дочерней MAIN-DLL.


## Передача RAM-диска DOS

MEMORY A=14, C=MEM_RAMDISK_STATUS (0) возвращает B=число банков пула и C=состояние: 0 — пул ещё не закреплён, 1 — принадлежит DOS, 2 — закреплён за историческим модульным резидентом. D=1 означает, что bootstrap обнаружил потерю первых восьми байтов кода хвоста MEM по FF04h в первом банке B: до переустановки хвостов; D=0 — такой потери не обнаружено, E=0. Признак сохраняется до успешного COMMIT, в том числе после Reset незавершённой установки. STATUS не изменяет пул.

C=MEM_RAMDISK_COMMIT (1) разрешён только во время исполнения DRIVER-инициализатора. Требуются ненулевой пул и владелец 0 либо DOS; перед закреплением повторно проверяется геометрия B:. Операция не форматирует том и не меняет его данные, записывает владельца DOS_IO_PAGE и возвращает состояние как STATUS. Повторный COMMIT для DOS допустим; чужой владелец или вызов вне инициализатора возвращает OWNER. Неверный подрежим или пустой пул возвращает RANGE; ошибки проверки тома передаются вызывающему. Реестр модулей и записи FAR-аллокаций не расходуются.


## Локальная серия RAW

`MXOS_DOS_RAW_IO`, B=`RAW_OP_PREPARE` (6; в C `MXOS_RAW_PREPARE`) подготавливает прямую серию для выбранного A:/B:/H: при размере физического блока 256 байт. Вызов выполняет flush тома, завершает прежнего владельца конвейера H: и устанавливает исполняемую копию H: в локальный хвост клиента, если она ещё не установлена. Успех: CF=0, A=0, HL=единый NEAR-вход операций 1/2/4/5, DE=0, B=8 (log2 размера блока), C=номер диска. Ошибка: CF=1, A=код DOS; указатели не использовать. Геометрия и возможности запрашиваются заранее обычными B=3/FFh. Неподдерживаемая геометрия/устройство дают UNSUPPORTED.

Перед локальным CALL передать B=1 (запись), 2 (чтение) либо 5 (запись с проверкой), C=полученный диск, DE=физический LBA, HL=буфер 256 байт в своей странице; A=C. B=5 использует тот же вход и выполняет проверку в странице буфера: MAIN использует общий временный буфер BIOS, DOS — DOS_VERIFY_BUFFER, BANK требует не менее 320 байт свободного стека. BC/DE/HL сохраняются; AF разрушен, CF=ошибка физического обмена. Физический B=4 разрешён только при DISK_CAP_FLUSH; он вызывается через обычный полученный вход после всего пакета. Встроенный A: не рекламирует DISK_CAP_FLUSH. Локальные ошибки не обновляют GET_ERROR DOS: проверять возвращённый CF/A непосредственно.

Это доверенный низкоуровневый ABI: локальные вызовы не проверяют диапазон буфера, границы LBA, принадлежность данных файлу и права FAT. Список секторов следует построить и проверить до серии; у B: каждый блок с младшим байтом FFh недоступен. Прямые записи предназначены для секторов данных зарезервированного файла; нельзя обходить кэш FAT/каталога. Нельзя вызывать DOS, менять выбранный диск, заменять драйвер, освобождать BANK/DLL или переключать владельца устройства между PREPARE и последним физическим flush. После любого такого действия требуется новый PREPARE; полученный указатель не является долговременным handle. Самостоятельных параллельных пользователей физического устройства нет.

MAIN A: получает непосредственно bios_blockIO: ROM и верхний буфер доступны CPU одновременно. DOS/BANK A: получают локальный обработчик MEM: чтение выполняет CPM32 из физического ROM-окна прямо в свой банк, запись вызывает MAINIO с указанием исходной страницы буфера. B: использует локальный CPM32 в каждой странице, H: — локальную исполняемую копию в LOCAL_DRIVER_ADDR; каждый сектор B:/H: не пересекает DOS. Обычный MXOS_CALL RAW_IO остаётся проверяющим универсальным интерфейсом, который можно использовать без управления локальной серией.


Большая DOS-DLL, выходящая за B500h, заимствует неактивные кадры BAT до CB80h. Активный BAT препятствует загрузке такого модуля; загруженный модуль препятствует запуску BAT. Выгрузка возвращает область. Установщики DRIVER сохраняют исключающую верхнюю границу B500h. Это позволяет держать полный буфер DiskBen 8 КиБ в памяти за своим кодом без уменьшения дискового кэша.

Шрифт KOI7/KOI8 выбирается явно: `MXOS_CALL MXOS_BIOS_SET_FONT_ENCODING`, A=0 KOI8, иначе KOI7. AF/BC/DE/HL сохранены. Прямой вход MAIN — `bios_setFontEncoding`. Из банка менять bios_upper.koi7 напрямую нельзя. Арифметика подключается локально из include/math.inc, соответствующих служб умножения и деления BIOS больше нет.

### Описание системного накопителя A:

Существующий MXOS_DOS_DRIVER_REFRESH (0224h) принимает A=0 и HL=NEAR-адрес читаемого 64-байтного буфера клиента с именем и описанием, двумя ASCIIZ суммарно до 64 байт. DOS проверяет строки и копирует их в DOS_DRIVER_REGISTRY; исходная память после возврата не нужна. HL=0 выбирает встроенное описание ROM-SYS из DOS. Геометрия и возможности берутся у установленного физического обработчика A:, который для B=FFh теперь возвращает только BC и HL=0. Файловый RAW_IO B=FFh возвращает обычные две строки из реестра DOS. Новых служб и номеров вызовов не добавлено.

### Получение имени и описания накопителя

Физический BIOS/AT512KS B=FFh возвращает B=DISK_TECH_*, C=DISK_CAP_*, HL=0 и CF=0 при успехе. Строковых указателей у физического драйвера нет; HL=0 не означает отсутствие технологии и возможностей. Компактный локальный H: не реализует этот запрос. Для выбранного диска вызывайте MXOS_DOS_RAW_IO с B=FFh: при CF=0 B/C содержат технологию/возможности, HL — NEAR-адрес двух ASCIIZ-строк (имя, нуль, описание, нуль; вместе не более 64 байт). DOS берёт текст из собственного реестра и при межбанковом вызове создаёт локальную копию. Если текст требуется после следующих RAW_IO или замены драйвера, скопируйте его в свой буфер.

```asm
    ld a,0                         ; выбрать A:
    MXOS_CALL MXOS_DOS_FILE_SELECT_DRIVE
    ret c
    ld b,0FFh
    MXOS_CALL MXOS_DOS_RAW_IO
    ret c
    ; HL -> имя,0,описание,0; B=технология, C=возможности
```


GET/PUT8/16 используют только COMMAND: постоянный обработчик, общий для MAIN/DOS/EXEC/DATA, передаёт данные через регистры. После COPY/TEXT/LOCAL перед доступом восстанавливается окно COMMAND; при уже активном COMMAND окно не копируется. Успешный вызов оставляет COMMAND. Ошибочные параметры отклоняются до изменения профиля. Отдельных COPY-ветви и скалярных шаблонов нет. В DATA служебная область начинается с FED0h; аллокатор выдаёт только диапазон ниже неё. Общая граница проверок FF00h не разрешает затирать служебный код.

## Пошаговые файловые операции

`MXOS_DOS_FILEOPS` (022Bh): A=BEGIN/STEP/ANSWER/CANCEL/CLOSE/SKIP_PREPARE, HL=112-байтный FILEOPS_JOB в банке клиента. Код FILEOPS.DLL загружается DOS лениво, закрепляется на время одного задания и остаётся кэшированным после CLOSE. Буфер обмена 4 КиБ принадлежит DOS. Ошибки API возвращаются в CF/A, результат работы — в полях state/error; Обычный ответ обновляет 26-байтный заголовок состояния; request с текущими дескрипторами возвращается при CONFIRM. phase/known/total/required описывают подготовку, path — отдельный 128-байтный NEAR-буфер пути в банке клиента, указанный до BEGIN. NEAR-поля не становятся указателями на DOS. Подробный контракт — [FILEOPS](../fileops/README.md). C SDK: `mxos_fileops(operation, &job)`.

## Кэш файловых исполнителей

Парсер команд и чтение BAT постоянно находятся в DOS. ENUM.DLL загружается в единую арену с DOS_SERVICE_ADDR=9800h, FILEOPS.DLL — рядом с A000h в той же арене; они не перекрываются. Открытый ENUM_REQUEST закрепляет перечислитель до CLOSE; FILEOPS_JOB закрепляет копировщик до CLOSE. Любая другая DOS-DLL или установщик проверяется на точное пересечение с обоими интервалами. Неактивный кэш можно вытеснить, активный — нельзя. Публичный ABI перечисления описан в [source/enumerate/README.md](../enumerate/README.md).

## Освобождение кэширующих MAIN-модулей

`MXOS_DOS_MEMORY`, A=`MEM_OP_MAINCLAIM` (16), HL=начало, BC=число байт: освобождает неактивные MAIN-DLL, чей код или принадлежащий им блок BSS пересекается с диапазоном. Диапазон должен целиком лежать в 0000h–8BFFh; пустой запрос ничего не меняет. Сами данные не записываются и память вызывающему не выделяется. Системные резервы FONT сохраняются для частичного запроса; запрос всей MAIN переводит шрифт на верхний Rotate с восстановлением профиля перед оболочкой. При пересечении с активной DLL или её активными потомками возвращается CF=1, A=MEM_ERROR_ACTIVE. Все конфликты предварительно проверяются до освобождения объектов. После освобождения пересчитывается memTop. FONT и RUN используют запрос перед проверкой требуемой рабочей памяти; это позволяет освободить сохранённый рендер оболочки без выгрузки её EXEC-резидента.

Для необратимой передачи управления из MAIN-оболочки предусмотрен макрос `MXOS_EXEC returnAddress` в mxos.inc. В отличие от обычного `MXOS_CALL`, он не возвращается в код оболочки, который загружаемая программа может затереть. Пакет и адрес возврата остаются в системном стеке; обработчик возврата должен сбросить SP, как bios_reboot. CLI и оба профиля NC используют этот путь для запуска внешних программ.


## Контейнер v2 и политики памяти

COM/EXE/DLL/FNT используют общий 32-байтный заголовок v2; точная раскладка и константы находятся в mxos.inc, C-структура — MXOS_IMAGE_HEADER в SDK. Штатный загрузчик принимает только v2, преобразователи на хосте и EXE.COM умеют импортировать старые файлы. BSS задаёт размер статических данных после тела. Явные memoryBegin/memoryEnd описывают непрерывный полуоткрытый диапазон, включающий код, BSS, промежутки и рабочую память ниже адреса загрузки. Загрузчик резервирует его целиком, не обнуляя; C CRT инициализирует свой BSS. minHeap — требование к доступному непрерывному продолжению при загрузке, не отдельное выделение. stackBytes проверяется относительно имеющегося служебного стека; ноль означает штатный размер. Релокации нет.

Слова хранятся little-endian; смещения шестнадцатеричные.

| Смещение | Байт | Поле |
|---|---:|---|
| 00 | 5 | Сигнатура CD 20 4D 58 02 |
| 05 | 1 | Тип: 0, DOS=1, BANK=2 или MAIN=4 |
| 06 | 2 | Адрес загрузки тела |
| 08 | 2 | Вход внутри тела |
| 0A | 2 | Размер тела в файле |
| 0C | 2 | calcCS тела |
| 0E | 2 | BSS после тела; FFFFh — неизвестен |
| 10 | 2 | Начало занятого диапазона |
| 12 | 2 | Конец занятого диапазона, исключительно |
| 14 | 2 | Минимальный непрерывный запас кучи после диапазона |
| 16 | 1 | EXCLUSIVE=0, PRESERVE=1, MANAGED=2 |
| 17 | 1 | API: 0 — не заявлен, 2 — MXOS2 |
| 18 | 2 | Требуемый размер стека; 0 — штатный |
| 1A | 1 | AUTO=0, MX=1, STD=2, MON=3, RF=4 |
| 1B | 1 | Размер заголовка: 32 |
| 1C | 1 | Бит 0: CACHEABLE. Бит 1: REUSABLE, только вместе с CACHEABLE для DLL в MAIN |
| 1D | 1 | Резерв, ноль |
| 1E | 2 | calcCS первых 30 байт |

EXCLUSIVE освобождает прикладную MAIN для классической программы; BSS=FFFFh означает неизвестный объём и допускается только с этой политикой. PRESERVE отказывает при пересечении без вытеснения. MANAGED может освобождать только явно отмеченные CACHEABLE модули и внутренние кэши ENUM/FILEOPS. Активный код и предки активного модуля не вытесняются. DOS проверяет все пересечения до освобождения первого объекта; ошибка позднего чтения не возвращает уже вытесненный кэш. DOS-службы вне CACHEABLE закреплены до явной выгрузки. Установщики и DOS-DLL занимают точные интервалы общей арены 9800h–B4FFh; ENUM начинается с 9800h, FILEOPS с A000h, установщик прижат к B500h. При заимствовании неактивных кадров BAT верхний предел — CB80h.

MAIN DLL больше не требует временно перенастраивать глобальную ARENA для своей статической памяти: загрузчик резервирует её declared interval отдельно от динамических блоков. MAIN EXE/COM получают временного владельца и статическую запись, допускающую адрес 0000h. При разрушительной передаче FILE_EXEC старые MAIN-выделения заменяемой программы освобождаются; MODULE_LOAD не разрешает перезаписывать активного MAIN-родителя. memTop учитывает загруженные модули, чужие блоки и системные резервы; собственная статическая запись исполняемой MAIN-программы не уменьшает её memTop. Нативная программа явно выделяет динамические ресурсы через MEMORY API. Банковое приложение по-прежнему получает один целый свободный EXEC-банк; дополнительные FAR-блоки могут размещаться в других DATA-банках.

Символы ASM для сборщика CPU: IMAGE_FLAGS, IMAGE_BSS_SIZE, IMAGE_MEM_BEGIN, IMAGE_MEM_END, IMAGE_MIN_HEAP_SIZE, IMAGE_STACK_SIZE, IMAGE_MEMORY_POLICY, IMAGE_API, IMAGE_COMPAT_MODE, IMAGE_CACHEABLE. В CPU им соответствуют FLAGS, BSS, MEM_BEGIN, MEM_END, MIN_HEAP, STACK, POLICY, API, MODE, CACHEABLE; числа шестнадцатеричные. Например `IMAGE_BSS_SIZE = workspaceEnd-imageEnd` и `IMAGE_CACHEABLE = 1` объявляют хвост данных и разрешают вытеснять модуль. Значение `IMAGE_CACHEABLE = 3` включает повторное использование образа MAIN DLL. Поля не являются релокациями. Структуры SDK и сборщики используют ту же раскладку.

Для DLL с REUSABLE DOS вызывает её обычную точку входа с `A=MODULE_ACTIVATE` (F0h) и `C=0` после чтения образа либо `C=1` при повторном использовании. Обработчик заново инициализирует нужное ему состояние, не обращаясь к DOS. Флаг C в PSW означает отказ. При отказе от повторного использования DOS перечитывает DLL и пробует холодную инициализацию. При отказе холодной инициализации MODULE_LOAD возвращает ошибку.

Каждая из восьми записей реестра может хранить освобождённый образ MAIN DLL с REUSABLE. При выгрузке DOS освобождает память и обнуляет дескриптор. Запись со статусом vacant хранит прежний диапазон, диск, кластер файла и поколение изменений тома. MODULE_LOAD проверяет заголовок штатным способом и ищет совпадение по диску, кластеру и поколению. Если совпадения нет, он предпочитает пустую запись и использует vacant только при отсутствии пустых. При каждой успешной загрузке выдаётся новый дескриптор.

Пересекающееся выделение MAIN снимает признак vacant у всех затронутых образов. Эксклюзивный запуск и тёплый Reset сбрасывают все vacant-записи. DLL должна держать код и своё состояние в заявленном диапазоне, а клиенты должны регистрировать диапазоны записи в MAIN.

## Восстановление профиля FONT

MXOS_DOS_FONT_CONFIG (022Dh) предназначен установщику FONT и BIOS: A=0 REGISTER, HL=NEAR-строка команды до 128 байт; A=1 PREPARE, HL=NEAR-выходной буфер 128 байт, возвращает A=1 при подготовленной команде или A=0 при отсутствии работы; A=2 FINISH восстанавливает прежний дисковый контекст. CF/A обозначают ошибку. REGISTER при повторной установке возвращает B=1, не меняя сохранённую конфигурацию; обычная регистрация — B=0. Остальные регистры разрушены. Это доверенный системный интерфейс, не механизм изоляции.

DOS хранит команду выбора шрифта и дисковый контекст. Перед запуском на всю MAIN нижний пререндер освобождается и штатный Rotate загружается прямо в свой слот, без FAR-копии или отдельного прохода проверки. Перед возвращением в оболочку BIOS выполняет сохранённый FONT, восстанавливая выбранный движок и пререндер. Экспорт файлов при восстановлении пропускается. Аппаратный тёплый Reset сохраняет выбор в банке DOS и восстанавливает его после AUTOEXEC; явный FONT в AUTOEXEC задаёт новый профиль. Холодный старт после потери ОЗУ использует профиль bootstrap/AUTOEXEC. Ошибка штатной загрузки FONT остаётся видимой через обработчик загрузочных команд с ожиданием Enter. Сохранение содержимого рендера в отдельный банк и повторное чтение для верификации не выполняются.

## Очередь команд, MEM 1.3

F809h связывает один локальный flush-callback с текущим исполняемым банком, HL=адрес процедуры; HL=0 отключает очередь. Callback может разрушать регистры: MEM сохраняет AF/BC/DE/HL и локальный SP. F80Ch выполняет явный flush. Автосброс выполняется перед MXCALL (включая запрос результата), публичными memcpy_far/MOVE/GET/PUT и физическим COPY. Во время callback шлюз временно превращается в RET, поэтому отправка самой очереди не вызывает рекурсию; при отключённой очереди проверок callback нет.

ASM-менеджер — [command-queue.inc](../include/command-queue.inc). commandQueueInit получает HL=буфер, BC=ёмкость выделенной памяти от 3 байт без перехода через конец адресного пространства, DE=максимальный размер одной команды 3..255 для стандартного BIOS-получателя. Программа пишет непосредственно по указателю cqNext и передаёт конец записи в commandQueueCommit. Инвариант перед записью: свободно не меньше maxCommand байт. После commit выполняется flush, если остаток меньше maxCommand; так не нужен промежуточный пакет или предварительный вызов для каждой небольшой команды. Программа обязана соблюдать заявленный максимальный размер. Для более крупной записи commandQueueReserve(BC=точный размер) заранее проверяет вместимость и при необходимости отправляет старую пачку. Если запись вообще не помещается, возвращается CF=1/A=MEM_ERROR_RANGE без записи и без flush накопленных команд. commandQueueFlush — явный барьер, commandQueueClose отправляет хвост и снимает callback. Код callback и буфер должны жить до close; init не выделяет память.

Формат записи: opcode:byte, totalBytes:byte, registerMask:byte, выбранные слова HL/DE/BC/AF в этом порядке, затем inline-данные. Биты 0..3 mask выбирают передаваемые слова; отсутствующие регистры равны нулю. Бит 4 устанавливает HL на начало inline-данных уже в принимающем контексте. opcode=0 завершает выравнивающее заполнение; GETCH и другие запросы результата выполняются синхронно. Для SET_CURSOR_POS достаточно пяти байт: opcode, 5, 1, Y, X/2. Для PRINT_STRING_Z достаточно opcode, размер, 16, ASCIIZ. Номера BIOS берутся из штатной таблицы.

Стандартный отправитель вызывает MXOS_BIOS_COMMAND_BATCH (012Ch): A=FAR-код текущего банка, HL=начало потока в нём, BC=число байт, 1..256. Принимающий системный 272-байтный буфер защищён проверкой общей длины. Небольшая пачка до 20 байт передаётся прямо в COMMAND; более длинная одним CPM32-copy в MAIN и исполняется локально, без MXCALL для каждой записи. Порядок сохраняется; отката выполненных команд нет. Результаты отдельных команд не собираются. Не используйте в пачке обработчики, перезаписывающие принимающий буфер, и вызовы с необходимым немедленным результатом. Между получением указателя и commit нельзя вызывать API, способный сбросить очередь: незавершённая запись ещё не принадлежит пачке. Число/адреса команд, структура payload и указатели — контракт программы; повторных проверок и сумм каждой записи нет.

Если ёмкость позволяет, менеджер дополняет крупную пачку нулевым opcode до блока CPM32, не читая за выделенным буфером; короткий хвост 1..7 байт остаётся точным. Прямой writer должен сохранять корректные размеры своих записей. Для собственного сервиса/MAIN-DLL можно определить COMMAND_QUEUE_SEND: он получает A=банк источника, HL=пачка, BC=передаваемые байты. Тогда менеджер допускает любую выделенную локальную ёмкость и 16-битный максимальный размер команды, а поток отправляется точно, без нулевого заполнения. Резерв/commit/автосброс остаются общими; формат такого сервиса задаёт его получатель. Это не разрешение на вызовы произвольных адресов ядра: DLL по-прежнему вызывается по штатному handle.

C-менеджер — sdk/include/mxos_queue.h и sdk/src/mxos_queue.c: mxos_command_open, mxos_command_reserve, mxos_command_commit, mxos_command_close. Запись идёт прямо в q.next; общий явный барьер — mxos_queue_flush. Объект и буфер принадлежат приложению. Одновременно привязан один объект на банк; ошибки reserve не меняют уже накопленную пачку.

В ABI 1.2 из горячего MXCALL удалены проверки адреса MX_REGS, номера банка назначения, глубины и нижней границы стека; число функции должно быть допустимым для таблицы. Скалярный BIOS исполняется напрямую после однократной маршрутизации. Существующий F800h с явным MX_REGS сохраняет запись результата в пользовательский пакет; F806h её не делает. Проверки размещения загружаемых образов, выделения памяти, файловой системы и физических границ носителя этим не отменяются.

Пример ASM без промежуточного пакета:

```asm
    ld hl,queueBuffer
    ld bc,256
    ld de,32              ; резерв максимальной команды
    call commandQueueInit
    ld hl,(cqNext)
    ld (hl),MXOS_BIOS_SET_CURSOR_POS & 255
    inc hl
    ld (hl),5             ; размер всей записи
    inc hl
    ld (hl),1             ; передаём только HL
    inc hl
    ld (hl),40            ; Y
    inc hl
    ld (hl),10            ; X/2
    inc hl
    call commandQueueCommit
    call commandQueueFlush
    call commandQueueClose
; command-queue.inc включается один раз в тело программы.
; queueBuffer принадлежит её заявленному BSS/выделению памяти.
```

### Адресат, порядок исполнения и привязка DLL

Одна исходящая очередь принадлежит исполняющему банку. В ASM вызовите `commandQueueSelect` с A равным `MX_QUEUE_BIOS`, `MX_QUEUE_DOS` или `MX_QUEUE_DLL`. Для DLL передайте её handle в HL. В C используйте `mxos_command_select(q, target, handle)`. Изначально выбран BIOS. При смене адресата предыдущая пачка синхронно завершается. Повторный выбор того же адресата сохраняет накопленные команды.

| Получатель | Что получает | Что делает вызывающая сторона |
|---|---|---|
| BIOS, 012Ch | До 256 байт упакованных команд. Из банка до 20 байт проходят через COMMAND | Добавляет независимые операции печати и рисования. Читает состояние синхронно |
| DOS, 022Fh | До 256 байт того же формата. DOS копирует поток из фактического банка инициатора один раз и выполняет его в DOS | В этой версии разрешены FILE_SELECT_DRIVE, FLUSH_VOLUME и FILE_DELETE. Для DELETE передайте inline подготовленное DOS-имя в формате обычного ABI. Остальные операции доступны синхронным MXCALL |
| DLL внутри MODULE_SCOPE | A=FAR-код источника, HL=адрес потока в источнике, BC=точное число байт, DE=0 | Определяет формат с DLL. Для другого банка получатель читает FAR-поток или копирует его целиком в свой буфер. При одной странице читает его локально. Перед возвратом RET потребление потока должно закончиться |

Для BIOS и DOS менеджер ограничивает рабочую ёмкость меньшим из 256 и размера выделенного буфера. При выборе DLL доступна вся выделенная ёмкость. Для записи DLL крупнее обычного резерва сначала запросите её точную длину через reserve. Пачки DLL передаются без дополнения. Ошибки flush сохраняются в `cqError` / `q.error`. Пачка снимается с очереди после попытки доставки. DOS прекращает исполнение на первой ошибке, уже выполненные операции сохраняют эффект. DLL возвращает CF=1 и ненулевой A при ошибке. Проверяйте поле ошибки после барьера и очищайте его при обработке. Для операций, где нужен результат каждой записи или выборочное повторение, используйте синхронный API.

`MXOS_DOS_MODULE_SCOPE` (022Eh) принимает HL=handle загруженной DLL и DE=адрес процедуры контроллера в вызывающем банке. DOS разрешает handle, закрепляет модуль и вызывает контроллер на служебном стеке исходного банка. Помещайте большие локальные данные в BSS или кучу. Контроллер завершается обычным RET. Перед снятием привязки MEM отправляет его очередь, затем восстанавливает внешнюю привязку. Вложенная область может временно привязать другую DLL. Поля очереди принадлежат программе. Если вложенный контроллер сменил адресата очереди, внешний контроллер перед новой записью снова выбирает своего адресата. Попытка выгрузки активной DLL возвращает ACTIVE. После RET из области прямой вызов с прежним handle возвращает HANDLE, если внешняя область не связывает этот handle. Сам загруженный модуль живёт до MODULE_UNLOAD. MODULE_SCOPE возвращает собственный статус в CF/A. Контроллер сохраняет результаты своей работы у себя.

Внутри контроллера `mx_routeCall` принимает HL=привязанный handle, DE=локальный MX_REGS. MEM передаёт восемь байт регистров непосредственно получателю, возвращает AF/BC/DE/HL в CPU и сохраняет исходные SP и банк. Поля исходного пакета остаются входными. DLL может вложенно вызывать BIOS и DOS, а DOS учитывает её выделения на владельца DLL. Для единичного вызова с результатами в MX_REGS доступен MODULE_CALL.

```asm
    ld hl,(graphicsHandle)
    ld de,drawFrame
    MXOS_CALL MXOS_DOS_MODULE_SCOPE
    ret

drawFrame:
    ld hl,(graphicsHandle)
    ld a,MX_QUEUE_DLL
    call commandQueueSelect
    ret c
    ; Записать независимые команды в (cqNext), после каждой вызвать commit.
    ; Здесь можно явно завершить кадр и прочитать статус рисования.
    call commandQueueFlush
    ld a,(cqError)
    ld (drawError),a
    ret
```

Группируйте короткие операции одному адресату до следующей зависимости. Например, подготовьте данные из DOS, затем сформируйте всю видимую часть панели для графической DLL. Записывайте короткий текст рядом с командой и выполняйте один COPY для большого потока. Обычный синхронный MXCALL и mx_routeCall отправляют очередь перед запросом результата. Явный flush нужен перед непосредственным чтением изменённой памяти, прямым историческим входом BIOS или показом завершённого кадра. Память, на которую ссылаются отложенные команды, должна жить до завершения flush. Отключайте hook до освобождения его кода и буфера. Новый EXEC получает пустую привязку. При тёплом перезапуске MEM/DOS отбрасывают регистрации и очередь оставленного стека. В C привязку на время процедуры оформляет `mxos_module_scope(handle, controller)`. Внутри неё `mxos_route_call(handle, &input, &result)` принимает локальный MXOS_MODULE_REGS, сохраняет результаты в MXOS_REGS и оставляет input доступным для следующего вызова.

## Локальная клавиатура DOS/EXEC

В банке DOS и в каждом EXEC, выданном загрузчиком, доступен один и тот же сегмент платформенного IO.SYS. В MAIN для стандартного ввода используется BIOS. Приложение с фокусом ввода заводит один IO_KEY_STATE. DLL этого же банка может получить его NEAR-адрес. При смене банка новый владелец передаёт или явно выбирает режим KOI и фиксаторы. Код клавиши и флаг Ctrl возвращаются в регистрах.

| Вход ASM | Результат |
|---|---|
| io_bankGetCh (F040h), HL = состояние | Ждёт события. A = код, NZ, CF = Ctrl/ПС |
| io_bankKeyPoll (F043h), HL = состояние | Z и CF=0 при отсутствии события. При событии NZ, A = код, CF = Ctrl/ПС. F1 имеет код 00h |
| io_bankKeyScan (F046h) | Сырой код матрицы в A, FFh при отсутствии клавиши. Без декодирования и автоповтора |
| io_bankGetChCursor (F049h), HL = состояние | Ждёт события с мигающим курсором в текущей позиции BIOS. При возврате курсор скрыт. A = код, NZ, CF = Ctrl/ПС |
| io_bankKeyModifiers (F04Ch) | A = маска нажатых клавиш. Бит 0 — Shift, бит 1 — Ctrl/ПС. Z при нулевой маске |
| io_bankKeyShift (F04Fh) | A = 1, если Shift нажат, иначе A = 0 и Z |
| io_bankKeyTicks (F057h), HL = состояние | A = младшие 8 бит времени с шагом 32,768 мс при 2 МГц. BC, DE, HL сохраняются. При программном отсчёте единица зависит от частоты опроса |
| io_bankClockRead (F05Ah) | Для владельца TIMER_CLOCK в DOS/EXEC. HL = убывающий 16-битный счётчик с шагом 128 мкс при 2 МГц. Учитывает перезагрузку канала при щелчке в этом банке. BC и DE сохраняются |

Для банковых приложений рекомендуется локальный опрос IO с таймером. Перед входным циклом выполните `MXOS_KEY_BEGIN состояние`, при передаче ввода другому приложению и при выходе — `MXOS_KEY_END состояние`. Макросы меняют рабочие регистры. Если таймер занят или отсутствует тактирование, ввод продолжает работать с программным отсчётом и без щелчков. В MAIN исторический `bios_getch` по C803h использует программные задержки и писк через PC5. Из банка тот же режим доступен через `MXOS_CALL MXOS_BIOS_GETCH`. Он подходит для совместимости с играми, которые сами программируют ВИ53.

IO_KEY_STATE занимает 11 байт. Раскладка полей описана в mxos.inc. Первый повтор обычной клавиши назначается через 12 крупных тиков (около 393 мс), следующие через два (66 мс). Для стрелок на панели NC интервалы составляют восемь тиков и один тик. Курсор меняет видимость каждые 15 тиков (492 мс). Опрос доставляет одно созревшее событие, даже если обработчик долго рисовал. РУС/ЛАТ меняет фиксатор один раз до отпускания.

Для подсказок F-клавиш вызывайте `io_bankKeyShift` (C — `mxos_bank_key_shift()`). Он читает порт B один раз в штатном режиме ввода клавиатуры. Если нужны оба модификатора, `io_bankKeyModifiers` (C — `mxos_bank_key_modifiers()`) выбирает столбец ПС, читает обе клавиши одновременно и возвращает ВВ55 в режим 82h. Используйте маски `IO_KEY_MOD_SHIFT` и `IO_KEY_MOD_CTRL` (в C — `MXOS_KEY_MOD_SHIFT` и `MXOS_KEY_MOD_CTRL`). Оба входа работают непосредственно в вызывающем банке, в том числе при удержании обычной клавиши. Они сохраняют очередь, профиль аппаратного окна и состояние ввода, включая ожидающее нажатие и счётчик автоповтора.

При пустой матрице и между повторами банк опрашивает ВВ55 локально, сохраняя профиль аппаратного окна. Для разбора нажатия или повтора IO вызывает BIOS напрямую через MEM. Таблица матрицы и декодер KOI общие для MAIN, DOS и EXEC. Вариант с курсором сравнивает отметки времени в банке и обращается к BIOS при смене видимости. Если клавиша пришла при видимом курсоре, BIOS гасит его в том же вызове. Нулевая высота или бит 7 cursorCfg отключают курсор в этом варианте ожидания.

Клавиатурные входы сохраняют накопленную очередь. Перед ожиданием отправьте готовый кадр одним flush. Для собственного курсора или обработки Shift во время ожидания используйте io_bankKeyPoll в цикле приложения. В MAIN bios_getch вызывает обработчик, зарегистрированный через bios_setInputHook, синхронно из своего цикла ожидания. Банковые входы этот обработчик не вызывают.

В C откройте и закройте сеанс через mxos_bank_key_begin и mxos_bank_key_end. Во время сеанса используйте mxos_bank_getch, mxos_bank_getch_cursor или mxos_bank_key_poll с MXOS_KEY_STATE_INIT. Младший байт результата содержит код клавиши, MXOS_KEY_EVENT отмечает событие, MXOS_KEY_CTRL — модификатор.

```asm
inputState: IO_KEY_STATE
waitAfterDrawing:
    MXOS_KEY_BEGIN inputState
    call mx_queueFlush
    ld hl,inputState
    call io_bankGetChCursor
    push af
    MXOS_KEY_END inputState
    pop af
    ret
```


### Владение ВИ53

В MAIN, DOS и EXEC доступен `MXOS_CALL MXOS_DOS_TIMER` (021Ah). В A передаётся операция. CF=1 означает отказ. DOS связывает захват с текущим модулем или приложением. Для вызова вне этих контекстов используется банк инициатора.

| A | Действие |
|---|---|
| TIMER_RAW (0) | Занять ВИ53 для собственной настройки, например музыки. Конфигурацию задаёт вызывающий. |
| TIMER_CLOCK (1) | Занять ВИ53 и подготовить часы ввода. Канал 1 делит CLK на 256, канал 2 считает вниз, канал 0 готовит несущую 2 кГц. При отказе запуска часы освобождаются. |
| TIMER_RELEASE (2) | Освободить таймер. Повторный захват и освобождение чужого таймера возвращают ошибку владельца. |
| TIMER_QUERY (3) | Вернуть в A состояние владения. 0 — свободен, 1 — занят вызывающим, 2 — другим владельцем. |

Нативная программа захватывает таймер до настройки аппаратуры, в том числе перед собственным звуковым драйвером или `bios_beepTimer`. Завершение приложения, выгрузка DLL и тёплый сброс освобождают соответствующий захват. Перед запуском классической программы освободите таймер явно. Аппаратные записи игр в порты не проходят через DOS.

Свежему нажатию соответствует один импульс. Повтору удерживаемой клавиши отдельный импульс не назначается. Канал 2 в режиме 0 получает 64 тика (8,192 мс). Пока OUT2 низок, слышна несущая канала 0. При достижении нуля OUT2 поднимается и аппаратно глушит тон. Канал 2 продолжает декремент после нуля. Перед каждой перезагрузкой IO запоминает разницу между прежним логическим счётом и новым начальным значением. Поэтому отсчёт включает время звучания и последующей работы программы без опроса и без обработчика прерываний. Два показания io_bankClockRead можно вычитать по модулю 65536 на интервалах короче 8,389 с. Точность привязки щелчка ограничена тактом загрузки счётчика. Поправка принадлежит банку, который обслуживает клавиатуру. Для точных измерений с собственной настройкой и для долгих интервалов используйте отдельный сеанс TIMER_RAW.
