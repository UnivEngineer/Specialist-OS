# Публичный ABI памяти и печати MXOS

Этот документ закрепляет контракт MEM ABI 1.1. Номера операций, адреса и структуры задаются в `source/include/mxos.inc`; номера BIOS/DOS генерируются из `source/bios/syscalls.json` в ASM- и C-заголовки. Внутренние адреса обработчиков, раскладки профилей окна и реестра выделений не являются API приложения. Примеры ниже используют только инструкции 8080.

## Адреса и контекст

FAR-адрес — `{bank:byte, offset:word}`, little-endian, 3 байта. Код 0 означает main, 1…16 — физические банки ДОЗУ 0…15; `{0,0}` — nullptr. NEAR-адрес — обычный 16-битный адрес в банке вызывающей программы. Переход в DOS не меняет смысл указателей приложения: файловый/памятный сервис получает исходный банк отдельно от банка своего исполнения.

| Точка | Назначение |
|---|---|
| F7A8h / mx_get32 | A=FAR-банк, HL=адрес; результат BC:DE |
| F7ABh / mx_put32 | A=FAR-банк, HL=адрес, BC:DE=значение |
| F800h / mx_call | B=группа, C=номер, DE → локальный MX_REGS |
| F806h / mx_callRegs | CALL с последующим DW номера функции; параметры в регистрах |
| F80Fh / mx_memcpyFar | HL → локальный пакет MEM_COPY_REQUEST |
| F812h / mx_memInfo | Версия, возможности, банк исполнения |
| F815h / mx_memory | A=операция памяти, параметры по таблице ниже |

MX_REGS занимает 8 байт: HL, DE, BC, AF; каждое поле — слово little-endian (для AF сначала F, затем A). F800h принимает пакет в памяти исходного банка; при нормальном вызове возвращает результат и в регистрах CPU, и в пакете. При отказе транспорта до выполнения операции CF=1, пакет не изменяется. F806h формирует такой пакет на локальном стеке, после DW продолжается код программы. Номер операции не отнимает регистр у вызываемой функции.

F7A8h/F7ABh/F80Fh/F812h/F815h локальны: DOS для них не вызывается. Перед использованием должен быть установлен полный профиль MEM и корректный локальный стек. Банк данных содержит только хвост копировщика: вызывать из него F800h/F815h нельзя. Нативный FILE_EXEC и RUN запускают BANK-программы через описанный ниже модульный загрузчик; он устанавливает профиль EXEC и локальный стек.

Банк исполнения и SP восстанавливаются после каждого вызова. Требуются выключенные IRQ. Собственный код, стек, запросы и системные области нельзя перекрывать данными; аппаратной защиты нет. API переноса/GET/PUT проверяет диапазон, но не принадлежность адресов выделенному блоку. Ограничение `<FF00h` не разрешает затирать MEM, драйверы, экран или DOS внутри этого диапазона.

## Перенос и скалярный доступ

MEM_COPY_REQUEST занимает 8 байт: sourceBank (+0, byte), sourceOffset (+1, word), destinationBank (+3, byte), destinationOffset (+4, word), count (+6, word). Пакет находится в памяти инициатора и должен оставаться действительным до возврата.

| Вызов | Вход | Успешный результат | Сохраняется |
|---|---|---|---|
| F80Fh memcpy_far | HL → MEM_COPY_REQUEST | A=0, CF=0 | BC, DE, HL |
| F815h MOVE, A=0 | HL → MEM_COPY_REQUEST | A=0, CF=0 | BC, DE, HL |
| F815h GET8, A=1 | B=банк, HL=адрес | DE=байт, D=0; A=0, CF=0 | BC, HL |
| F815h GET16, A=2 | B=банк, HL=адрес | DE=слово; A=0, CF=0 | BC, HL |
| F815h PUT8, A=3 | B=банк, HL=адрес, E=байт | A=0, CF=0 | BC, HL, DE |
| F815h PUT16, A=4 | B=банк, HL=адрес, DE=слово | A=0, CF=0 | BC, HL, DE |
| F7A8h GET32 | A=банк, HL=адрес | BC:DE=двойное слово; A=0, CF=0 | HL |
| F7ABh PUT32 | A=банк, HL=адрес, BC:DE=двойное слово | A=0, CF=0 | BC, DE, HL |

memcpy требует отсутствия перекрытия; memmove/MOVE допускает его. Нулевой count возвращает успех без проверки банков и диапазонов. При ненулевом count все байты должны лежать ниже FF00h, исключающий конец может быть равен FF00h. Перенос через 10000h запрещён. Слово little-endian GET16/PUT16 проверяется целиком: последний допустимый адрес FEFEh. Байтовый доступ допускает FEFFh. При ошибке содержимое назначения не меняется, DE при ошибке GET не определён; BC/HL сохранены.

При совпадении обоих банков с банком исполнения используется установленный локальный стековый memcpy/memmove (в main — bios_memcpy_bc_hl, в DOS — тот же скомпилированный движок). Межбанковый memcpy использует CPM16, включая остаток без чтения за концом. MOVE внутри другого банка выполняет направленный цикл в окне, между разными банками — CPM16. Установка нулевого локального обработчика выключает локальное ускорение, сохраняя корректность.

F812h возвращает HL=0101h, A=FAR-код исполнения, B=число банков ДОЗУ, C=назначение банка (DATA=0, EXEC=1, DOS=2), DE=возможности, CF=0. DE bit0=перенос FAR, bit1=ленивое окно, bit2=F815h операции памяти, bit3=публичные операции модулей DOS, bit4=аллокатор DOS с FILL/QUERY и управлением пулом RAM-диска. DE bit5=локальные GET32/PUT32. Остальные флаги не определены.

GET32/PUT32 — отдельные фиксированные точки входа, а не новые коды F815h. BC:DE содержит значение little-endian: E — байт по HL, D — по HL+1, C — по HL+2, B — по HL+3. Все четыре адреса проверяются до обращения к целевой памяти; последний допустимый начальный адрес — FEFCh. При ошибке A=E0h (банк) либо E2h (диапазон), CF=1, BC/DE/HL сохранены; PUT не меняет целевые данные. Выравнивание не требуется. GET32/PUT32 используют профиль COPY, но каждый вызов пока устанавливает в окне собственный 27-байтный шаблон: это не гарантирует отсутствие затрат на подготовку окна.

## Аллокатор DOS

`MXOS_DOS_MEMORY = 0226h`: группа B=2, номер C=26h. Вход через F800h/F806h; A=MEM_OP_* в регистровом пакете. Операции 1…4 GET/PUT имеют тот же контракт, что локальный F815h. MOVE=0 и PRINT=5 здесь не поддерживаются: использовать локальные точки MEM/BIOS. Неописанные операции возвращают DOS_ERR_UNSUPPORTED.

| A | Операция | Вход | Успешный результат |
|---:|---|---|---|
| 6 | ALLOC | B=банк либо FFh (любой DATA), HL=байты | B:HL=FAR-адрес, DE=запрошенный размер, A=0, CF=0 |
| 7 | FREE | B:HL=точный адрес начала блока | A=0, CF=0; остальные регистры не определены |
| 8 | REALLOC | B:HL=блок, DE=новый размер | B:HL=новый адрес, DE=новый размер, A=0, CF=0 |
| 9 | ARENA | B=0, HL=начало свободной main-области, DE=байты | A=0, CF=0; остальные регистры не определены |
| 10 | RAMLIMIT | B=число банков RAM-диска | CF=0; остальные регистры не определены |
| 11 | FILL | B=банк, HL=адрес, DE=байты, C=значение | A=0, CF=0; остальные регистры разрушены |
| 12 | QUERY | B=конкретный банк | HL=свободные байты, DE=наибольший промежуток, B=банк, C=свободные записи; A=0, CF=0 |
| 13 | DISKCLAIM (исторический) | Текущий зарегистрированный резидент | Закрепляет пул за резидентом; штатный RAMDISK не использует |
| 14 | RAMDISK | C=0 STATUS, C=1 COMMIT | B=число банков пула, C=состояние владельца; A=0, CF=0 |

Реестр в DOS вмещает 32 одновременно выделенных блока, запись занимает 6 байт `{bank,offset,size,owner}`; заголовков внутри самих блоков нет. Поиск первого подходящего промежутка, выравнивание начала 2 байта. Размер 16-битный, блок целиком помещается в одном банке. Запрошенные байты не инициализируются. ALLOC(0) возвращает `{0,0}`, DE=0, не резервируя запись. FREE(nullptr) успешен. При освобождении блок не обнуляется.

REALLOC(nullptr,n) эквивалентен ALLOC(ANY,n), REALLOC(p,0) освобождает и возвращает nullptr. Уменьшение сохраняет адрес. При увеличении сначала резервируется новый блок, затем копируются прежние байты и освобождается старый; при любой ошибке старый блок и данные остаются действительными. Рост main-блока остаётся в main, рост DATA-блока может перенести его в другой свободный DATA-банк. Содержимое добавленной области не определено. При ошибке значения выходных адресных регистров не использовать; C-обёртка оставляет переданный FAR-адрес прежним.

ALLOC в main разрешён только после ARENA: начало не ниже 0100h, исключающий конец не выше 8C00h. Регистрация — доверенная передача собственного диапазона, не поиск памяти поверх кода. Локальная C-куча не должна раздавать эти же байты. Арену нельзя менять, пока у текущего владельца есть main-блоки; чужие блоки остаются занятыми и исключаются при поиске. MAIN-приложения, запущенные FILE_EXEC/FILE_EXEC_NATIVE, получают временные теги 20h–27h по глубине вызова (до восьми); вложенные запуски сохраняют прежние owner/арену. RET освобождает блоки и дочерние модули приложения, затем восстанавливает контекст родителя. Теги повторно используются только после очистки; это идентичность живого вызова, не долговечный PID и не защита от устаревшего сырого FAR-указателя. Модули используют приватные теги 80h–87h. Вызовы вне загрузчика сохраняют прежний контекст банка; их автор сам освобождает временные блоки. Выделения системного владельца DOS сохраняются при тёплом входе.

До подготовки RAMDISK весь не-DOS пул зарезервирован для B:. Одноразовый RAMDISK.COM с флагом DRIVER выбирает размер через RAMLIMIT, проверяет разметку или вызывает FORMAT для пустой памяти и передаёт готовый пул самой DOS через RAMDISK/COMMIT. Модульный handle, резидентный процесс и FAR-запись для пула не создаются. COMMIT разрешён только во время DRIVER-инициализации; DOS повторно проверяет сектор 256 байт и геометрию B: перед сменой владельца. STATUS доступен из любого контекста и не меняет пул. Повторный COMMIT для того же пула DOS допустим; чужой модульный владелец не подменяется. При ошибке прежнее владение сохраняется. Пул исключён из DATA/EXEC-выделений и сохраняется при Reset независимо от завершения установщика. -P 4 означает четыре банка данных плюс DOS: из шестнадцати свободны одиннадцать. Нужны минимум два банка ДОЗУ. Без -P закреплённый пул сохраняет прежний размер; повторный запуск проверяет разметку без форматирования. Изменение размера запрещено до холодной загрузки DOS. SHRINK/GROW и вызов установщика по запросу DOS пока не реализованы. Исторический DISKCLAIM=13 оставлен совместимым, но штатный RAMDISK его не использует.

## Печать

| Операция | HL | Выполнение |
|---|---|---|
| MXOS_BIOS_PRINT_STRING / PRINT_STRING_BANK = 0107h | ASCIIZ в банке инициатора | Из main нативно, из банка через Window20 |
| MXOS_BIOS_PRINT_STRING_MAIN = 0124h | ASCIIZ в main | Нативный bios_printString в main, передаются только регистры |
| F815h, A=5 (PRINT) | Локальная ASCIIZ | Тот же автоматический выбор main/Window20 без упаковки MX_REGS |

Во всех случаях HL возвращается на завершающем нуле, BC/DE сохранены. BIOS PRINT_STRING/PRINT_STRING_MAIN сохраняют AF при успешной печати. Прямой F815h PRINT возвращает CF=0; остальные флаги не сохраняются (A занят кодом операции). Строка включает управляющие коды, как обычный bios_printString. Для Window20 строка и нуль должны находиться ниже F800h; неверный диапазон возвращает ARGUMENT через BIOS ABI или E2h через F815h, уже напечатанный префикс не отменяется. PRINT_STRING_MAIN принимает явный main-адрес без проверки владения или поиска конца буфера; срок жизни строки обеспечивает программа. Номер банка в HL закодировать нельзя: отдельная операция MAIN задаёт его однозначно.

Window20 автоматически разбивает строку на порции до 20 байт и печатает непосредственно из аппаратного окна, без промежуточного main-блока. Порция копируется без предварительного поиска NUL: соответствующий строковый рендерер сам находит терминатор в пределах порции. После строкового вызова TEXT остаётся активным; последующий PRINT_CHAR/PRINT_CHAR_RAW использует его без восстановления COMMAND. При другом активном протоколе посимвольный вызов идёт через COMMAND.

```asm
    ld hl,localText
    MXOS_CALL MXOS_BIOS_PRINT_STRING_BANK
    ld hl,mainBufferAddress
    MXOS_CALL MXOS_BIOS_PRINT_STRING_MAIN
```

## Пререндер BIOS 6×8

MXOS_BIOS_FONT_RENDER (0125h) управляет тремя заранее сдвинутыми фазами. HL — явный адрес main-буфера даже из банковой программы. A=0 запрашивает состояние, A=1 строит и включает таблицу, A=2 отключает. При успехе CF=0, A=0/1 (непригоден/действует), HL — прикреплённый буфер, BC=10240, DE — физический адрес RAM-шрифта bios_upper.charGen. Остальные флаги разрушены; ошибка CF=1, A=DOS_ERR_ARGUMENT сохраняет прежнее состояние. Подробнее — [BIOS](../bios/README.md#fontrender-0125h).

Буфер должен принадлежать вызывающему, занимать 2800h байт и начинаться на границе 100h в 0100h–6400h. Его нельзя совмещать со шрифтом, кодом, стеком или запросами API. FONT_RENDER не заменяет ALLOC/FREE и не меняет memTop. Сначала программа получает блок через MEM либо резервирует принадлежащий ей диапазон; перед FREE или выгрузкой владельца обязательно отключает таблицу. Само отключение данные и выделение не освобождает. Контроль за сроком жизни остаётся у вызывающей программы.

## Ошибки и ленивое окно

| Код A при CF=1 | Значение |
|---|---|
| E0h | Недопустимый FAR-код банка |
| E1h | Нет места в стеке/допустимой глубины вложенного перехода |
| E2h | Недопустимая операция F815h или диапазон адресов |
| E3h | Нет подходящего блока либо свободной записи реестра |
| E4h | Неверный адрес/владелец FREE или модуля, занятый RAM-диском банк, недоступная арена/изменение разметки |
| E5h | Нулевой, неизвестный или уже выгруженный дескриптор модуля |
| E6h | Попытка вызова или выгрузки активного модуля |

Ошибки внешнего DOS/BIOS диспетчера (неподдержанная функция, неверный MX_REGS, занятость обработчика) используют DOS_ERR_* из общего заголовка. RAMLIMIT дополнительно может вернуть ошибку физического чтения B:. Флаги кроме оговорённых CF и сохранённого AF не являются результатом API.

32-байтное окно принадлежит MEM; приложение не сохраняет и не восстанавливает его самостоятельно. После memcpy_far, GET/PUT и прямой Window20 может оставаться профиль COPY, SCALAR, LOCAL или TEXT. Повторная операция использует нужный профиль; COMMAND восстанавливается только при необходимости вызова/возврата. Локальный стековый перенос не меняет профиль. Это гарантированное ленивое поведение, но коды профилей и их внутренние адреса не входят в публичный контракт.

## C SDK

`MXOS_FAR_ADDRESS` — 3 байта, `MXOS_FAR_COPY` — 8 байт. Использовать заголовок mxos.h; обёртки аллокатора и scalar находятся в дополнительном mxos_far.c, регистровый мост — в mxos_z88dk.asm и входят в вызывающую программу. Функции памяти возвращают слово AF: CF в младшем байте, код A в старшем. Указатель-результат malloc изменяется только при успехе, realloc сохраняет прежний адрес при ошибке, free обнуляет адрес при успехе. Нормальные void* и malloc локальной C-кучи этим API не заменяются. Старые SDK-функции с прямыми Cxxx-вызовами рассчитаны на main; банковые программы используют явно поддержанные F8xx-точки.

## Загрузка и синхронный вызов модулей

| Номер MXOS_CALL | Операция | Вход | Успешный результат |
|---|---|---|---|
| 0227h / MXOS_DOS_MODULE_LOAD | moduleLoad | HL → путь MAX_PATH в банке инициатора, A=0 main, A=1 новый EXEC-банк, A=2 арена DOS | HL=непрозрачный ненулевой handle, A=0, CF=0 |
| 0228h / MXOS_DOS_MODULE_CALL | moduleCall | HL=handle, DE → локальный MX_REGS (8 байт) | A=0, CF=0; регистры модуля записаны в MX_REGS |
| 0229h / MXOS_DOS_MODULE_UNLOAD | moduleUnload | HL=handle | A=0, CF=0; handle больше не действителен |

BC/DE и неоговорённые результаты самих API-вызовов не определены. AF модуля, включая CF, возвращается в его MX_REGS и не смешивается со статусом moduleCall: модуль может вернуть CF=1 при успешной диспетчеризации. При отказе входа или проверки MX_REGS его исходные байты сохраняются. Пакет MX_REGS находится именно в банке программы, вызывающей moduleCall, проверяется до входа и не пересылается как NEAR-указатель в чужую память. Он должен целиком заканчиваться не выше MEM_IMAGE_LOCAL_START (сейчас F400h), без оборота адреса. Сам модуль начинает исполнение с AF/BC/DE/HL из пакета, а заканчивает обычным RET с результатами в этих регистрах. Изменение SP или MX-режима, аппаратного окна либо переход на C000h/C800h вместо RET не входит в контракт модуля.

Используется тот же 16-байтный контейнер COM/EXE версии 1, что RUN: сигнатура CD 20 4D 58 01, флаги 0, IMAGE_FLAG_BANK=02h, IMAGE_FLAG_MAIN=04h либо IMAGE_FLAG_DRIVER=01h для DOS-DLL, фиксированные адреса загрузки и входа, длина и две штатные суммы calcCS. Для модулей используется расширение DLL: обычный FILE_EXEC их не запускает, загрузка выполняется через MODULE_LOAD. Размещение в main, EXEC-банке или арене DOS явно задаёт A; оно не определяется расширением. Флаг IMAGE_FLAG_BANK требует MODULE_TARGET_BANK; загрузка такого модуля в main отвергается до записи тела. IMAGE_FLAG_MAIN требует MODULE_TARGET_MAIN. При флагах 0 DLL остаётся нейтральной только между MAIN/BANK. IMAGE_FLAG_DRIVER требует MODULE_TARGET_DOS; этот target, в свою очередь, требует DRIVER-флага. Старые имена COM/EXE остаются допустимыми для MODULE_LOAD. RKS и сменные ядра не допускаются. Вход должен лежать внутри тела; релокаций и отдельной BSS нет (нулевые данные нужно включать в тело). Файловый поиск, чтение и проверка сумм выполняются DOS через существующий imageOpen/imageLoad; загрузчик не запускает CLI/RUN и не выбирает ассоциации. Сумма тела считается при чтении с носителя, без повторного прохода после пересылки.

Для A=0 main предварительно регистрируется собственная свободная ARENA. Менеджер резервирует точный диапазон [load,load+size) в ней, не сдвигает образ при конфликте и не пишет в код вызывающей программы вне объявленной арены. Main-модуль вызывается на служебном стеке BIOS (256 байт в текущей карте), отдельно от стека приложения. Он разделяет этот стек с вложенными службами BIOS; проверки MEM по глубине и нижней границе сохраняются. Отдельный большой main-стек в v1 не предоставляется.

Для A=1 менеджер резервирует целиком свободный DATA-банк, устанавливает полный профиль MEM и отдельный стек 1024 байта. Код/данные тела должны заканчиваться не выше начала стека F000h; стек занимает F000h–F3FFh, полный MEM начинается F400h. DOS, диапазон B: и банки хотя бы с одним чужим блоком не рассматриваются. Ни номер банка, ни адрес входа/стека пользователь не выбирает через handle. Прямой FREE резервирования образа запрещён; оно освобождается только через moduleUnload. При выгрузке банк снова получает назначение DATA, хвост копировщика остаётся доступным. Полный хвост пока не уплотнён для 62-КиБ приложений CP/M.

Для A=MODULE_TARGET_DOS (2) код исполняется в физическом банке ДОЗУ 0, FAR-код DOS_IO_PAGE=1. Target — селектор размещения, а не FAR-номер банка. Весь диапазон [load,load+size) обязан лежать целиком в одном из двух слотов: 7800h–7BFFh (DOS_SERVICE_ADDR/END, резидентный, 1 КиБ) либо C000h–EFFFh (DOS_BANK_DRIVER_ADDR/MODULE_END, временный, до 12 КиБ; участок от D800h разрешён только без активного BAT). Вход — внутри тела. По адресу загрузки выбирается слот, который целиком закрепляется за одной DLL; оба слота могут быть заняты одновременно. Только временная арена общая с инициализаторами драйверов. Код, статические данные и локальные буферы DLL должны помещаться туда; отдельной локальной кучи DOS API не выдаёт. MEM, кэш, ядро DOS и служебный стек не переустанавливаются и не входят в образ DLL.

Повторная загрузка в занятый слот возвращает MEM_ERROR_ACTIVE (E6h) до записи тела. Временная DOS-DLL блокирует FILE_EXEC/FILE_EXEC_NATIVE для DRIVER; работающий инициализатор блокирует временную DLL. Резидентный слот от этих конфликтов независим: инициализатор может загрузить службу в 7800h–7BFFh и затем освободить свою арену. Ранее установленные физические службы продолжают работать: локальный RAW и файловый MXOS_CALL из DOS-DLL используют банк DOS и её локальные буферы. Входы BIOS вызываются через MXOS_CALL; исторические адреса C000h/C800h в этом банке не обозначают BIOS. Модуль выполняется синхронно на общем служебном стеке DOS (F000h–F3FFh); бюджет 1024 байта делится с moduleCall и вложенными BIOS/DOS-вызовами. Сохраняются проверки глубины и нижней границы стека MEM, обычный RET возвращает пакет результатов инициатору.

DOS-DLL владеет FAR-выделениями и дочерними модулями по обычным правилам; moduleUnload освобождает их и резерв арены, сохраняя назначение банка DOS. Отказ загрузки после резервирования также освобождает слот. RETAIN разрешён для резидентного слота 7800h–7BFFh: служба отделяется от владельца и сохраняет код, handle и ресурсы при Reset. RETAIN во временной арене запрещён с MEM_ERROR_OWNER (E4h). Зарегистрированный BANK-резидент и его потомки не могут загрузить DOS-DLL; доступ к DOS-слотам остаётся ограничен обычными временными владельцами при загрузке. Возврат в оболочку, завершение приложения и Reset освобождают обычную DOS-DLL вместе с владельцем. Для сохраняемой службы доступны BANK + RETAIN либо DOS + RETAIN в резидентном слоте. Это не фоновые потоки: вход вызывается синхронно.

Одновременно допускаются 8 модулей; резерв MAIN/BANK-образа также занимает одну из 32 записей общего FAR-аллокатора. DOS-DLL занимает запись модуля и отдельный резерв арены, без записи FAR-аллокатора. 16-битные handle выдаются последовательно, не переиспользуются до перезагрузки DOS: старый handle не обозначит другой модуль после unload/load. После 65535 успешных загрузок дальнейшая загрузка возвращает E3h до новой сессии DOS. Нулевой/неизвестный/устаревший handle даёт E5h, активный — E6h, чужой владелец — E4h. Занятость/недопустимость main-диапазона даёт E2h либо E3h (нет подходящего блока), отсутствие целого свободного банка или записи — E3h, неверный контейнер — DOS_ERR_BAD_IMAGE; файловые ошибки сохраняют коды DOS. Отказы освобождают уже зарезервированную память и установленный контекст; чужие области не изменяются. Повторные последовательные вызовы сохраняют данные тела модуля. Рекурсивный вход в уже активный handle запрещён, вложенный вызов другого загруженного модуля разрешён.

При moduleCall исходный банк и SP сохраняет MEM. Состояние внешнего DOS-запроса находится в локальном стековом кадре; модуль может выполнять MXOS_CALL BIOS/DOS и вызывать дочерние модули. Аллокатор помечает новые блоки приватным тегом текущего модуля. moduleUnload освобождает образ, собственные блоки, дочерние модули и зарегистрированную им main-арену. Активный модуль выгружать нельзя. RETAIN отделяет BANK-модуль от родителя и делает самостоятельным сервисом: его handle доступен другим владельцам через RESIDENT. Перед RETAIN нельзя иметь main-арену или main-блоки; зарегистрированному резиденту ARENA запрещена, поскольку основную память заменяет следующая программа. Общего share/transfer API для обычных блоков нет. Низкоуровневые операции остаются доверенными: аппаратной защиты от записи в чужую память нет.

Reset и возврат в оболочку через C000h/C800h отбрасывают стеки приложений: DOS освобождает временные модули и выделения, отменяет main-арену, но сохраняет зарегистрированные BANK-резиденты и DOS-службы резидентного слота, их дочерние модули и FAR-блоки, системные блоки DOS, счётчик handle и RAM-диск. Обычный RET из moduleCall ресурсы не освобождает. Нативный FILE_EXEC запускает BANK через модульный механизм и после RET освобождает временный образ; зарегистрированный резидент остаётся. DE у BANK-приложения содержит NEAR-аргументы в нижней части служебного стека F000h, стек ограничен снизу F0C0h. A=0, BC=0, HL=0; входные флаги не определены. FILE_EXEC возвращает CF/A статуса загрузки/вызова, а не результат main. RUN передаёт MAIN/DRIVER/BANK этому загрузчику через FILE_EXEC_NATIVE. Вытеснения, фоновых потоков и восстановления PC после Reset нет: повторная активация резидента — явный вызов его входа.

NEAR внутри AF/BC/DE/HL не преобразуется. Например, если соглашение модуля принимает B=FAR-код и HL=смещение общей структуры, приложение передаёт именно такую пару, а модуль использует GET/PUT или memcpy_far. Нельзя передавать main-адрес в HL и ожидать автоматического доступа к main из банка; для текста есть явный PRINT_STRING_MAIN. Вызов произвольного адреса ядра не предоставляется. Код в банке DOS допускается только в явно загруженной DOS-DLL или одноразовом DRIVER-инициализаторе, в пределах выделенной им арены.

```asm
    ld hl,modulePath          ; MAX_PATH байт, например 'B:\BANKMOD.DLL',0
    ld a,MODULE_TARGET_BANK
    MXOS_CALL MXOS_DOS_MODULE_LOAD
    jp c,error
    ld (moduleHandle),hl
    ld de,moduleRegs          ; HL, DE, BC, AF в памяти текущей программы
    MXOS_CALL MXOS_DOS_MODULE_CALL
    jp c,error
    ; AF результата модуля находится в moduleRegs+6.
    ld hl,(moduleHandle)
    MXOS_CALL MXOS_DOS_MODULE_UNLOAD
    jp c,error
moduleHandle: DW 0
moduleRegs: DW 01234h,02345h,03456h,0
modulePath: DB 'B:',05Ch,'BANKMOD.DLL',0
    DS MAX_PATH-($-modulePath),0
```

Пример main-контроллера измерений в DOS; имя DLL передаётся как обычный путь, а внутренние адреса ядра ему не нужны:

```asm
    ld hl,dosModulePath
    ld a,MODULE_TARGET_DOS
    MXOS_CALL MXOS_DOS_MODULE_LOAD
    jp c,error
    ld (dosModuleHandle),hl
    ld de,dosModuleRegs       ; Локальный MX_REGS контроллера в main.
    MXOS_CALL MXOS_DOS_MODULE_CALL
    jp c,unloadAfterError
    ld hl,(dosModuleHandle)
    MXOS_CALL MXOS_DOS_MODULE_UNLOAD
    jp c,error
    ; Продолжение контроллера.
```

Тело такой DLL собирается с `IMAGE_FLAGS = IMAGE_FLAG_DRIVER`, `ORG DOS_BANK_DRIVER_ADDR`, например с собственным `sectorBuffer: DS 512,0` и циклом `MXOS_CALL MXOS_DOS_RAW_IO` или FILEHANDLE. Вход заканчивается RET; переменные dosModulePath/dosModuleRegs/dosModuleHandle находятся у контроллера, а sectorBuffer — внутри DLL. Сборщик контейнера сохраняет флаг из ASM; смена расширения COM на DLL сама по себе флаг не устанавливает. В C контроллер использует `mxos_module_load(path, MXOS_MODULE_DOS, &handle)`, прежние mxos_module_call/unload. DISKBEN может вынести таймер и весь измеряемый цикл в такую DLL: граница main↔DOS пересекается при одном moduleCall, а не на каждом секторе. Диск для измерений нужно выбирать после MODULE_LOAD: файловый загрузчик может изменить выбранный диск. Сам DISKBEN этим расширением ещё не переводится.

C-обёртки находятся в sdk/src/mxos_module.c. `MXOS_MODULE_REGS` — точные 8 байт HL/DE/BC/AF, тогда как прежний `MXOS_REGS` имеет 10 байт и дополнительное поле entry для прямого BIOS-моста; это разные структуры. module_load изменяет handle-результат только при успехе. Передавать в API внутренние адреса MEM, сохранять аппаратное окно или вручную устанавливать хвосты не требуется.


## Нативный запуск без ассоциаций

MXOS_DOS_FILE_EXEC_NATIVE=022Ah принимает HL → локальная строка явного пути COM/EXE с аргументами, до MAX_PATH. Возвращает CF/A статуса, банк и SP вызывающей стороны сохраняются при обычном RET. Поиск PATH, встроенные команды CLI и ассоциации не применяются; файловый инициализатор DRIVER и отдельный BANK выбираются тем же штатным загрузчиком, что FILE_EXEC. Для main память родителя не резервируется: если приложение затирает вызывающий код, продолжение должно находиться вне его диапазона либо завершать работу через C000h/C800h. RUN использует для этого защищённый переходник. FILE_EXEC сохраняет CLI/PATH, но сначала проверяет заголовок найденного COM/EXE: MAIN/DRIVER/BANK исполняются до ассоциаций, flags=0 передаётся обработчику CLI.EXT. При отсутствии ассоциации сохраняется прежний прямой запуск. Повреждённые заголовки, неизвестные и несовместимые флаги дают DOS_ERR_BAD_IMAGE. Флаг MAIN=04h явно подтверждает main/MXOS-совместимость; flags=0 не означает такого подтверждения для RUN. Сочетания MAIN/DRIVER/BANK запрещены. DLL напрямую не запускаются.

Основные имена текстового API: PRINT_CHAR, PRINT_CHAR_RAW, PRINT_STRING_Z, PRINT_STRING_RAW_Z и PRINT_STRING_RAW_LIM. Старые имена PRINT_CHAR_REAL/PRINT_STRING/PRINT_STRING_REAL оставлены как псевдонимы для исходников проекта; Raw теперь выводит управляющие коды как глифы.

| API | MAIN ABI | MXOS_CALL | Вход и завершение |
|---|---:|---:|---|
| printChar | C809h | 0102h | C=код, управляющие коды обрабатываются |
| printCharRaw | C869h | 0114h | A=код; все 00h–FFh являются глифами |
| printStringZ | C818h | 0107h | HL=ASCIZ, управляющие коды обрабатываются |
| printStringRawZ | C8EDh | 0126h | HL=ASCIZ, 01h–FFh являются глифами, 00h завершает |
| printStringRawLim | C8F0h | 0128h | HL=массив, BC=длина; все 00h–FFh являются глифами |

Оба посимвольных входа сохраняют AF/BC/DE/HL, строковые — AF/BC/DE. Строки возвращают HL на терминаторе либо на исключающем конце заданного массива. После достижения правого края курсор переносится на следующую строку. Raw не изменяет состояние ESC. Для явно переданного main-указателя из банка есть PRINT_STRING_Z_MAIN=0124h, PRINT_STRING_RAW_Z_MAIN=0127h и PRINT_STRING_RAW_LIM_MAIN=0129h. Обычные строковые MXOS_CALL из BANK работают с NEAR-источником через Win20.

### TEXT_PRINT, 012Ah

HL указывает на TEXT_PRINT_REQUEST в банке клиента: `{kind:byte, method:byte, source:word, count:word, buffer:word, capacity:word}`. kind=0/1/2 выбирает StringZ/RawZ/RawLim. method=1 использует общий 256-байтный буфер BIOS, совместно используемый дисковыми драйверами; method=2 использует main-буфер программы. Для method=2 buffer — явный main-адрес, capacity — размер порции, предоставленный программой через ARENA/ALLOC. Поле source — NEAR-адрес текста в вызывающем банке, count — доступное число байт (для Z включает терминатор, для Lim является точной длиной). Нулевой count ничего не печатает.

Один MXOS_CALL автоматически копирует и печатает все порции. Для Z нет предварительного поиска конца: после копирования ставится защитный NUL за порцией, а рендерер прекращает обработку на настоящем терминаторе или границе порции. Поэтому пользовательский буфер для Z должен иметь capacity+1 доступных байтов; для Lim записываются только capacity байт. Проверка диапазона оставляет один защитный байт и для Lim. Копирование, переключения и рендер входят в вызов. CF=0/A=0 означает успех, HL — исходный адрес терминатора либо конец массива; CF=1/A=ARGUMENT — неверный пакет или диапазон. Память не выделяется и не освобождается внутри TEXT_PRINT; программа сохраняет владение своим буфером до окончания вызова.

## Заполнение и диагностика

FILL проверяет банк и весь диапазон до первой записи; при нулевой длине возвращает успех без проверки адреса. Использует PUT8 и удваивающиеся неперекрывающиеся копии уже заполненного префикса. Максимальный исключающий конец FF00h; это не разрешение перезаписывать защищённые области внутри диапазона. QUERY возвращает доступные для аллокатора промежутки конкретного банка с учётом двухбайтового выравнивания; main описывает текущую арену и требует её владельца. Для DOS/банков RAM-диска и целиком занятого EXEC-банка свободный объём равен нулю. Количество свободных записей относится ко всему реестру; при нуле записей ненулевой свободный объём ещё не означает успешный ALLOC.

## Резиденты — MXOS_DOS_RESIDENT (022Bh)

| A | Операция | Вход | Результат |
|---:|---|---|---|
| 0 | RETAIN | DE=ненулевой уникальный ключ, вызов из текущего BANK-модуля или DOS-модуля резидентного слота | CF=0, модуль отделён от родителя и сохраняется при Reset |
| 1 | FIND | DE=ключ | HL=handle либо 0; при совпадении B=следующий индекс, C=банк, DE=ключ |
| 2 | ENUM | B=начальный индекс 0…7 | HL=следующий handle, B=следующий индекс, C=банк, DE=ключ; HL=0 и B=8 в конце |

Запись резидента использует существующий модульный handle, не отдельный указатель на код. При RETAIN повторный/занятый ключ возвращает OWNER, main-размещение — RANGE. FIND/ENUM не вызывают программу. MODULE_CALL передаёт её собственный пакет регистров; MODULE_UNLOAD — явное принудительное удаление неактивного сервиса и его ресурсов. Для исторического DISKCLAIM выгрузка резидента-владельца запрещена (ACTIVE). Штатный RAM-диск принадлежит DOS и не имеет модульного handle. Внутренний вариант MODULE_UNLOAD A=1 применяется загрузчиком после RET и сохраняет резидента; приложения для явной выгрузки передают A=0.

Соглашение SDK для входа резидента: A=0 — начальная инициализация, A=1 — RESTORE, A=2 — CLOSE. RESTORE сам восстанавливает прикладной интерфейс; CLOSE сохраняет данные и возвращает CF=1 при отказе. mxos_resident_close вызывает CLOSE и только при успехе MODULE_UNLOAD; mxos_resident_kill вызывает MODULE_UNLOAD без callback. Это кооперативный контракт, без таймаута зависшего обработчика. Штатный RAM-диск не использует эти callbacks: его пул принадлежит DOS.

## Локальная C-куча

sdk/src/mxos_heap.c реализует локальные кучи с двухбайтовым выравниванием, четырёхбайтовыми заголовками и объединением соседних свободных блоков. sdk/src/mxos_stdlib.c подключает стандартные malloc/free/realloc/calloc к mxos_default_heap. Отдельные MXOS_HEAP позволяют ядру или библиотеке использовать тот же аллокатор с собственной ареной. Куча не обращается к DOS и не выдаёт чужую страницу при нехватке. Нулевое выделение возвращает NULL, free(NULL) ничего не делает, realloc(p,0) освобождает блок, отказ роста сохраняет прежние данные, calloc проверяет переполнение произведения.

sdk/runtime/crt0.asm — старт sccz80 для самостоятельного MAIN/BANK-приложения: обнуляет BSS, сохраняет аргументы и home-page, инициализирует кучу от конца BSS до memTop+1 в main или F000h в BANK. Стек остаётся предоставленным загрузчиком. Этот CRT не предназначен для MAIN-DLL, разделяющей память с родителем, или для повторного RESTORE резидента: таким модулям нужен собственный вход и явные границы MXOS_HEAP. Конструкторы C++, стандартные потоки и аtexit этим минимальным CRT не реализуются. Поддержка обычных C++ new/delete требует выбранного C++-компилятора и отдельного runtime.

Резидент регистрируется до загрузки дочерних модулей; RETAIN при существующих потомках возвращает OWNER. После регистрации потомки могут быть только BANK-модулями; запрет MAIN-арены распространяется на всю цепочку владельцев. Это исключает сохранение ссылок на основную память, которую следующая MAIN-программа перезапишет.


## Передача RAM-диска DOS

MEMORY A=14, C=MEM_RAMDISK_STATUS (0) возвращает B=число банков пула и C=состояние: 0 — пул ещё не закреплён, 1 — принадлежит DOS, 2 — закреплён за историческим модульным резидентом. STATUS не изменяет пул.

C=MEM_RAMDISK_COMMIT (1) разрешён только во время исполнения DRIVER-инициализатора. Требуются ненулевой пул и владелец 0 либо DOS; перед закреплением повторно проверяется геометрия B:. Операция не форматирует том и не меняет его данные, записывает владельца DOS_IO_PAGE и возвращает состояние как STATUS. Повторный COMMIT для DOS допустим; чужой владелец или вызов вне инициализатора возвращает OWNER. Неверный подрежим или пустой пул возвращает RANGE; ошибки проверки тома передаются вызывающему. Реестр модулей и записи FAR-аллокаций не расходуются.


## Локальная серия RAW

`MXOS_DOS_RAW_IO`, B=`RAW_OP_PREPARE` (6; в C `MXOS_RAW_PREPARE`) подготавливает прямую серию для выбранного A:/B:/H: при размере физического блока 256 байт. Вызов выполняет flush тома, завершает прежнего владельца конвейера H: и устанавливает исполняемую копию H: в локальный хвост клиента, если она ещё не установлена. Успех: CF=0, A=0, HL=единый NEAR-вход операций 1/2/4/5, DE=0, B=8 (log2 размера блока), C=номер диска. Ошибка: CF=1, A=код DOS; указатели не использовать. Геометрия и возможности запрашиваются заранее обычными B=3/FFh. Неподдерживаемая геометрия/устройство дают UNSUPPORTED.

Перед локальным CALL передать B=1 (запись), 2 (чтение) либо 5 (запись с проверкой), C=полученный диск, DE=физический LBA, HL=буфер 256 байт в своей странице; A=C. B=5 использует тот же вход и выполняет проверку в странице буфера: MAIN использует общий временный буфер BIOS, DOS — DOS_VERIFY_BUFFER, BANK требует не менее 320 байт свободного стека. BC/DE/HL сохраняются; AF разрушен, CF=ошибка физического обмена. Физический B=4 разрешён только при DISK_CAP_FLUSH; он вызывается через обычный полученный вход после всего пакета. Встроенный A: не рекламирует DISK_CAP_FLUSH. Локальные ошибки не обновляют GET_ERROR DOS: проверять возвращённый CF/A непосредственно.

Это доверенный низкоуровневый ABI: локальные вызовы не проверяют диапазон буфера, границы LBA, принадлежность данных файлу и права FAT. Список секторов следует построить и проверить до серии; у B: каждый блок с младшим байтом FFh недоступен. Прямые записи предназначены для секторов данных зарезервированного файла; нельзя обходить кэш FAT/каталога. Нельзя вызывать DOS, менять выбранный диск, заменять драйвер, освобождать BANK/DLL или переключать владельца устройства между PREPARE и последним физическим flush. После любого такого действия требуется новый PREPARE; полученный указатель не является долговременным handle. Самостоятельных параллельных пользователей физического устройства нет.

MAIN A: получает непосредственно bios_blockIO: ROM и верхний буфер доступны CPU одновременно. DOS/BANK A: получают локальный обработчик MEM: чтение выполняет CPM16 из физического ROM-окна прямо в свой банк, запись вызывает MAINIO с указанием исходной страницы буфера. B: использует локальный CPM16 в каждой странице, H: — локальную исполняемую копию в LOCAL_DRIVER_ADDR; каждый сектор B:/H: не пересекает DOS. Обычный MXOS_CALL RAW_IO остаётся проверяющим универсальным интерфейсом, который можно использовать без управления локальной серией.


Большая DOS-DLL, выходящая за D800h, заимствует неактивные кадры BAT до F000h. Активный BAT препятствует загрузке такого модуля; загруженный модуль препятствует запуску BAT. Выгрузка возвращает область. Установщики DRIVER сохраняют предел D800h. Это позволяет держать полный буфер DiskBen 8 КиБ в CA00h–E9FFh без уменьшения дискового кэша.

Шрифт KOI7/KOI8 выбирается явно: `MXOS_CALL MXOS_BIOS_SET_FONT_ENCODING`, A=0 KOI8, иначе KOI7. AF/BC/DE/HL сохранены. Прямой вход MAIN — `bios_setFontEncoding`. Из банка менять bios_upper.koi7 напрямую нельзя. Арифметика подключается локально из include/math.inc, соответствующих служб умножения и деления BIOS больше нет.

### Описание системного накопителя A:

Существующий MXOS_DOS_DRIVER_REFRESH (0224h) принимает A=0 и HL=NEAR-адрес читаемого 64-байтного буфера клиента с именем и описанием, двумя ASCIIZ суммарно до 64 байт. DOS проверяет строки и копирует их в DOS_DRIVER_REGISTRY; исходная память после возврата не нужна. HL=0 выбирает встроенное описание ROM-SYS из DOS. Геометрия и возможности берутся у установленного физического обработчика A:, который для B=FFh теперь возвращает только BC и HL=0. Файловый RAW_IO B=FFh возвращает обычные две строки из реестра DOS. Новых служб и номеров вызовов не добавлено.

### Получение имени и описания накопителя

Физический BIOS/AT512KS B=FFh возвращает B=DISK_TECH_*, C=DISK_CAP_*, HL=0 и CF=0 при успехе. Строковых указателей у физического драйвера нет; HL=0 не означает отсутствие технологии и возможностей. Компактный локальный H: не реализует этот запрос. Для выбранного диска вызывайте MXOS_DOS_RAW_IO с B=FFh: при CF=0 B/C содержат технологию/возможности, HL — NEAR-адрес двух ASCIIZ-строк (имя, нуль, описание, нуль; вместе не более 64 байт). DOS берёт текст из собственного реестра и при межбанковом вызове создаёт локальную копию. Если текст требуется после следующих RAW_IO или замены драйвера, скопируйте его в свой буфер.

```asm
    ld a,0                         ; выбрать A:
    MXOS_CALL MXOS_DOS_FILE_SELECT_DRIVE
    ret c
    ld b,0FFh
    MXOS_CALL MXOS_DOS_RAW_IO
    ret c
    ; HL -> имя,0,описание,0; B=технология, C=возможности
```
