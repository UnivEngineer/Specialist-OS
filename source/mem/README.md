# MEM.SYS

Общий менеджер межбанковых вызовов и переноса данных. Исходники и самостоятельный установочный образ находятся в этом компоненте. Сборка: `python scripts/build/build-banked-transport.py`; результат `bin/MEM.sys`, промежуточные фрагменты и символы — `bin/banked/`. Полная сборка ОС включает этот шаг автоматически.

Подготовка CPM32 общая для memcpy_far и физических операций C:/B:. Все 32 байта аппаратного окна используются для данных, параметры продублированы в хвостах банков. Порции POP/SHLD и LHLD/PUSH поддерживают произвольное выравнивание, остаток 1–31 байт обрабатывается без чтения за границей. Для длины 256 байт есть короткая подготовка без деления, длинный запрос экономит повторную установку параметров. FILEHANDLE готовят до 16/32/64 LBA за пачку, по умолчанию 32. Неполные сектора используют кэш DOS. Внутренняя ревизия задаётся `MEM_RUNTIME_REVISION` в [mxos.inc](../include/mxos.inc).

| Назначение банка | Устанавливаемые службы | Доступная память |
|---|---|---|
| Данные (`MEM_BANK_DATA`) | Постоянный хвост COMMAND/CPM32 FE00h–FFBFh | 0000h–FDFFh: 65024 байт |
| Исполняемый (`MEM_BANK_EXEC`) | Локальные адаптеры, публичный ABI, транспорт, копировщик | Ниже EE00h. Выше находятся служебный стек, клавиатурный сегмент IO и MEM |
| DOS (`MEM_BANK_DOS`) | Тот же код, что в исполняемом банке | Своя карта DOS и служебный стек |

Основная память также получает полный код MEM. У неё своя карта BIOS, экрана и программ. Код CLIENT и TRANSPORT одинаков во всех полных профилях; LOCAL в MAIN устанавливается без банковых служб в слоте AT512KS. При установке различаются данные: FAR-код, owner/home, границы стека, назначение банка, указатель на локальный диспетчер основной памяти и физический обработчик A:. DOS определяется маршрутизатором по FAR-коду 1; отдельного варианта MEM для неё нет. Синхронный API модулей и нативный FILE_EXEC банковых COM/EXE используют этот же профиль: bootstrap устанавливает полный профиль в main/DOS, а в остальные обнаруженные банки — профиль данных; при загрузке приложения выбранный свободный банк получает полный профиль EXEC.

В банке данных нет отдельного стека и контекста приложения. Подготовка memcpy_far и возврат выполняются в банке-инициаторе. Установка параметров, полные порции и точный остаток используют одинаковые постоянные хвосты источника и приёмника. Из данных исключаются 448 байт хвоста FE00h–FFBFh, 32 байта общего окна и 32 байта регистров. RAMDISK использует первые 254 физических сектора банка. FORMAT помечает оба последних сектора значением FAT16 BAD (FFF7h). Секторы метаданных тома дополнительно уменьшают доступное место файлов.

MEM.SYS — плотный установочный контейнер, а не линейный образ всего диапазона F1C0h–FFFFh. Заголовок: ASCII `MXMM`, версия 1, число сегментов 4; далее четыре записи по шесть байт `{destination:word, size:word, offset:word}`, little-endian. Сегменты: LOCALBLOCK (F1C0h), CLIENT (F800h), TRANSPORT (FC00h), WINDOW (FFC0h). Смещения считаются от начала файла. Файл содержит 30 байт заголовка и плотные устанавливаемые сегменты; их размеры экспортирует сборка в bin/MEM.sym. Это сумма сегментов, а не непрерывный резерв 2 КиБ: полный профиль пока начинается с F1C0h; слот H: расширен до 576 байт переразмещением TEXT и служб A:. Незанятые слоты драйверов не хранятся и не перезаписываются. Последние 448 байт TRANSPORT образуют хвост с FE00h. Bootstrap и загрузчик модулей при смене DATA/EXEC устанавливают вариант прямого копирования и его вектор. WINDOW устанавливается один раз в физически общее окно.

Штатный bootstrap включает точную копию MEM.SYS и устанавливает её сегменты по экспортированным смещениям. Отдельный MEM.SYS также размещается в фиксированном ROM-слоте 7000h вместо прежнего TAIL.SYS. Пока это служебный установочный файл, его замена требует согласованной пересборки bootstrap и системного образа. Bootstrap сохраняет готовую DOS при Reset только при совпадении MEM_RUNTIME_REVISION: старое ядро с адресами прежнего внутреннего транспорта должно быть перезагружено. Обычный Reset с совместимой ревизией DOS не перезагружает. Проверка ревизии не является контролем целостности кода.

Точки таблицы F800h–F833h одинаковы в основной памяти и банках. CLIENT передаёт main-вызовы локальному диспетчеру BIOS, а банковые направляет в BIOS или DOS. Локальные BIOS-обработчики остаются в BIOS.SYS; принимающий адаптер BIOS и физический ROM-мост — в IO.SYS. Для C: в main вызывается bios_blockIO, в DOS — dosSystemDriver; обмен B: использует FAR-код текущего банка, H: — установленный локальный слот F9C0h.

При установке полного профиля надо задать bankPage, bankPageCount, bankOwner/home, bankDepth=0, bankServiceSP и bankStackFloor, а также MEM_BANK_KIND и MEM_LOCAL_SYSTEM. F80Fh обращается к ядру MEM напрямую. В main дополнительно задаётся MEM_NATIVE_CALL. Нельзя исполнять код полного профиля из банка данных. Стек и пользовательские буферы должны находиться ниже F1C0h. Инициализаторы драйверов устанавливают службы H: отдельно; MEM не дублирует аппаратную инициализацию.

Контракт приложений закреплён в [api.md](api.md), регистры, общее окно и вложенные кадры описаны в [transport.md](transport.md). Аллокатор FAR-блоков и загрузчик синхронных модулей реализованы в DOS. Нативный FILE_EXEC запускает BANK-приложение и освобождает его ресурсы после RET. Полноценные процессные идентификаторы ещё не реализованы, RUN остаётся лаунчером совместимости.

### Размещение DLL

| Параметр MODULE_LOAD | Размещение | Условия |
|---|---|---|
| `MODULE_TARGET_MAIN=0` | Свободный диапазон основной памяти | Загрузчик резервирует заявленный интервал кода и BSS |
| `MODULE_TARGET_BANK=1` | Отдельный свободный EXEC-банк | DOS, RAM-диск и чужие выделения исключены |
| `MODULE_TARGET_DOS=2` | Единая арена 9800h–C9D7h, общая с вытесняемым окном BAT | IMAGE_FLAG_DRIVER, точные непересекающиеся интервалы |

DOS-DLL использует служебный стек DOS на 576 байт. Кэшируемые ENUM и FILEOPS, загруженные DLL и установщик учитываются общим реестром пересечений; активный код не вытесняется. Установщики собираются от общей исключающей границы арены C9D8h. RETAIN допустим во всей арене. При пересечении загружаемого образа с буфером BAT ядро сохраняет позицию сценария. Файлы читаются DOS, переключение контекста выполняет MEM.

Так можно вынести измерительный цикл DiskBen в DOS-DLL: контроллер в main передаёт параметры одним MODULE_CALL, а RAW/файловые операции работают с локальными буферами банка DOS. Установка MEM и подмена аппаратного окна приложению не требуются. MX_REGS принадлежит вызывающей стороне; NEAR-адреса внутри него не преобразуются. Полный контракт и ASM-пример — в [api.md](api.md), проверочные модули — в [moduletest](../../source-apps/moduletest/README.md).

## Публичный ABI MEM 1.4

Одинаковые входы в main и исполняемых банках не требуют обращения к DOS:

| Вход | Входные параметры | Результат |
|---|---|---|
| F80Fh / mx_memcpyFar | HL → MEM_COPY_REQUEST, восемь байт | A=0, CF=0 при успехе; BC/DE/HL сохранены |
| F812h / mx_memInfo | Нет | HL=0104h (версия 1.4), DE=возможности, A=FAR-код исполнения, B=число банков ДОЗУ, C=назначение банка, CF=0 |
| F815h / mx_memory | A=операция, остальные параметры по [api.md](api.md) | Локальные операции MOVE, GET/PUT, PRINT без обращения к DOS |

MEM_COPY_REQUEST: sourceBank:byte, sourceOffset:word, destinationBank:byte, destinationOffset:word, count:word; слова little-endian, структура объявлена в mxos.inc. Нулевой размер ничего не проверяет и возвращает успех. Для ненулевого размера FAR-коды должны быть 0…число обнаруженных банков; диапазоны не должны переходить через 64 КиБ или включать FF00h и выше. E0h/CF=1 означает неверный банк, E2h/CF=1 — неверный диапазон; E1h зарезервирован для нехватки стека межбанкового вызова. Перекрытие не допускается, но отдельно не проверяется. Нельзя затирать собственный код, стек, пакет запроса или служебные области. Это перенос заданных адресов, без выделения памяти и проверки владельца. IRQ должны быть запрещены; атомарная петля не допускает callback.

Четырёхбайтные объекты, включая курсор FileStream, передаются через обычный FAR COPY. Отдельных системных входов и C-обёрток GET/PUT32 нет.

В C SDK есть MXOS_FAR_COPY (восемь байт для 8080) и mxos_memcpy_far(); функция возвращает AF как 16-битное слово. Структуры из sdk/include/mxos.h и source/include/mxos.inc должны совпадать побайтно. Нативный FILE_EXEC и RUN устанавливают полный профиль и локальный стек при загрузке BANK-программы. Ручная установка нужна только автономным стендам.

## Восстановление после записи в STD-порт в режиме MX

Классическая программа, рассчитанная на STD, может обращаться к клавиатурному порту FF00h–FF03h. Если её запустить в режиме MX, по этим адресам находится оперативная память с защитной сигнатурой MEM. Запись в такой «порт» повреждает сигнатуру; исполняемый код копировщика начинается с FF04h и от этой записи не страдает. Этот раздел описывает обнаружение и восстановление после такого повреждения.

При программном возврате через C000h/C800h BIOS сравнивает сигнатуру FF00h–FF03h основной памяти с теми же адресами в банке DOS. При отличии выводится `STD I/O write in MX mode. Press any key` с ожиданием клавиши. Сигнатура содержит `FF FF FF FF`: это состояние без клавиш при режиме ВВ55 82h и выходных регистрах A/C=FFh. Чтение FF03h (РУС) аппаратно не определено; FFh соответствует открытой шине в принятой модели Emu80. Другие направления портов, значения выходных регистров или вход магнитофона могут дать другое чтение настоящего ВВ55. Эталон сигнатуры берётся из банка DOS.

Затем BIOS восстанавливает код MEM основной памяти из банка DOS, включая локальный адаптер, CLIENT, транспорт и копировщик. Восстановление выполняется и при совпадении четырёх байтов сигнатуры. После копирования заново задаются контекст MAIN и локальные обработчики. Драйверные слоты и данные DOS сохраняются.

Проверка и восстановление не используют потенциально повреждённый FAR-копировщик: эталон читается временным кодом в физически общем окне. Требуются исправные BIOS и банк DOS, а также передача управления на C000h/C800h. Если программа зависла и не вернулась в BIOS, этот механизм сам по себе не запускается. Отличие сигнатуры обнаруживает повреждение, характерное для записи в STD-порт, но не доказывает его причину.

## Терминология транспорта

**Общее окно** занимает физические FFC0h–FFDFh. В штатном режиме все 32 байта служат временным буфером текущей операции. Переход между страницами выполняет постоянно установленный код банкового хвоста. Начальная загрузка и восстановление повреждённого MEM в MAIN используют временный переходник в окне до установки исправных хвостов.

В окне размещаются регистровые кадры, порции CPM32, текст и короткие пачки команд. Каждый вход задаёт раскладку своей операции. У окна нет постоянного профиля или метки. GET/PUT передают значение в регистрах и используют окно для селектора и тега команды.

## Локальные копии

При совпадении FAR-кодов F80Fh и F815h/A=0 выполняют локальный перенос с перекрытием в MAIN, DOS, EXEC или DATA. В другую страницу адреса и длина передаются в HL, DE и BC. После сброса очереди ни локальный, ни удалённый одностраничный перенос не меняет окно. Между разными страницами и для физических запросов драйверов используется CPM32.

## Операции памяти

Вход F815h/mx_memory принимает A=MEM_OP_*: MOVE=0 (HL → восьмибайтный пакет memcpy), GET8=1, GET16=2, PUT8=3, PUT16=4 (B=FAR-код, HL=смещение, DE=значение; GET возвращает DE), PRINT=5 (HL=локальная строка, результат HL на нуле). BC/HL GET/PUT сохраняются; слово little-endian целиком должно находиться ниже FF00h. MOVE разрешает перекрытие. Внутри удалённой страницы MOVE использует рабочий стек её хвоста. Между разными страницами действует CPM32. IRQ запрещены; аппаратной защиты памяти нет.

Стандартный банковый вызов BIOS PRINT_STRING печатает прямо из общего окна порциями до 32 байт. Отправитель ищет NUL при наполнении, передаёт точную длину без него и завершает пустой хвост без входа в MAIN. Вложенные обращения к DOS или MEM через банк во время печати запрещены.

MXOS_DOS_MEMORY использует тот же регистровый контракт GET/PUT, а также A=6 ALLOC (B=FAR-код или FFh — любой свободный банк данных, HL=размер; результат B:HL, DE=размер), A=7 FREE (B:HL), A=8 REALLOC (B:HL, DE=новый размер). Сжатие выполняется на месте, расширение — транзакционно с копированием; при ошибке прежний блок действителен. Нулевой ALLOC возвращает nullptr; REALLOC с нулём освобождает блок. Ошибки E3h — нехватка, E4h — неверное владение/освобождение. Размеры 16-битные, блок не пересекает банк; выравнивание два байта. Реестр 32 записей расположен в DOS по 7D00h, данные банков не содержат скрытых заголовков.

A=9 ARENA регистрирует доверенный свободный диапазон main (0100h…8C00h), принадлежащий текущему приложению. Запуски MAIN получают временного владельца и очищают его блоки при RET; вложенные вызовы восстанавливают родительскую арену. Модули имеют собственные теги. Тёплый вход удаляет временные ресурсы и сохраняет зарегистрированные резиденты. Сроки жизни, ограничения и контракты — в api.md.

A=10 RAMLIMIT выбирает фиксированный пул B:. A=14 RAMDISK с C=0 сообщает его размер и владельца, с C=1 передаёт подготовленный пул DOS из DRIVER-инициализатора. RAMDISK.COM -P 4 использует четыре банка данных и не оставляет резидентного кода. Владение и данные сохраняются при Reset; модульный handle не требуется. Исторический A=13 DISKCLAIM для модульного владельца остаётся совместимым. Изменение размера закреплённого пула и SHRINK/GROW пока не поддерживаются. A=11 FILL заполняет дальний диапазон, A=12 QUERY сообщает свободные байты, наибольший промежуток и свободные записи реестра.

## Явный выбор источника строки BIOS

`MXOS_CALL MXOS_BIOS_PRINT_STRING_BANK` (0107h, также `MXOS_BIOS_PRINT_STRING`) принимает HL на ASCIIZ в банке вызывающей программы. Из DOS или EXEC окно служит источником до возврата рендера. MAIN печатает локально.

`MXOS_CALL MXOS_BIOS_PRINT_STRING_MAIN` (0124h) принимает HL на ASCIIZ именно в основной памяти. Из банка передаётся только пакет регистров: BIOS вызывает штатный printString с этим main-адресом, без копирования текста. Банк вызывающей программы и его SP восстанавливаются. Для обоих вызовов HL возвращается на завершающем нуле, AF/BC/DE сохраняются согласно обычному printString. Выделение main-буфера, копирование в него и срок его жизни обеспечивает программа; FAR-пакет для этой функции не нужен, так как банк main задан самой операцией.


FILE_EXEC_NATIVE (022Ah) использует тот же загрузчик, обходя CLI/PATH/ассоциации. RUN передаёт ему подтверждённые MAIN/DRIVER/BANK; контейнеры COM/EXE с flags=0 без явного режима показывают меню. Подробный контракт и ограничения main-продолжения — в api.md.

## Локальные физические службы EXEC/DOS

Слоты относятся к MAIN, DOS и исполняемым EXEC-банкам. Банки данных RAM-диска получают только хвост копировщика, без полного клиентского профиля. Размеры ниже — по текущим листингам; конечные адреса исключающие там, где используются метки End.

| Область | Резерв | Содержимое |
|---|---:|---|
| F5C0h–F67Bh | 188 байт | Диспетчер C:/B:/H:, контекст, указатели и регистровый шлюз BIOS |
| F67Ch–F6BFh | 68 байт | Маршрут общего вызова и служебные переходы MEM |
| F6C0h–F7FFh | 320 байт | MAIN: AT512KS 282 байта; DOS/EXEC: службы A:, проверки и суммы 267 байт |
| F800h–F8B3h | 180 байт | Публичные входы MEM и диспетчер CLIENT |
| F8B4h–F992h | 223 байта | Строковый шлюз и рабочие поля |
| F993h–F9BFh | 45 байт | Вызов контроллера MODULE_SCOPE |
| F9C0h–FBFFh | 576 байт | Одна служба H:: ROM2MX 265, AT2MX 546 либо AT2MXF 570 байт |

В H:-слот копируется только служба обмена со своими переменными, а не COM с обнаружением чипов и установщиком. Свободно соответственно 311, 30 и 6 байт. DOS хранит также эталон переносимой службы в DOS_DRIVER_IMAGE; клиентские копии восстанавливаются из него. Слот расширен на 64 байта без увеличения полного защищённого хвоста; 68 байт нижнего резерва не примыкают к H: и не входят в его ёмкость.

C:/B: доступны сразу после установки полного MEM-профиля. H: устанавливается лениво при первом полном физическом обмене в соответствующей странице; это делают обычные RAW_IO, SECTOR_IO, FileStream, FileHandle и загрузчик, а также явный RAW_IO B=6. Последующие блоки используют ту же копию. Новый EXEC-профиль сбрасывает её маркер; замена H:-драйвера инвалидирует отметки всех страниц. Смена владельца конвейера FLASHFST сначала завершает прежнюю запись.

Прямое чтение A: из DOS/EXEC формирует физический ROM-селектор 80h..8Fh и запускает bankCopySector в своём банке. Для FILEHANDLE загрузчик и файловое ядро DOS могут сразу задать клиентский банк назначения: callback в клиент для каждого сектора не нужен. Исключение — верхняя MAIN, где сохраняется более быстрый отображённый memcpy. Вход в MAIN и перенос пятибайтового запроса для банкового чтения не нужны. CPM32 переносит 32 байта через общее окно и переключает ROM/банк клиента; секторного буфера в MAIN/DOS нет. Запись использует MAINIO: сектор переносится в общий буфер MAIN ED80h–EE7Fh, затем штатный AT29-драйвер загружает аппаратную страницу через memcpy и ожидает DATA polling. Код программирования не дублируется в банковых хвостах.

Эти слоты пока не являются универсальным загрузчиком произвольных драйверов: localBlock/klEligible явно выбирают C:/B:/H:, непосредственный обмен использует отдельные селекторы системного, RAM и внешнего накопителей. DOS возвращает селектор в C при RAW_OP_PREPARE, даже если физический драйвер смонтирован на другой букве. Драйвер дискеты располагается в DOS отдельной службой. Физические блоки 512 байт пока обслуживаются общим путём DOS; существующий прямой путь умеет логический сектор 512 байт поверх двух физических блоков 256 байт.

Службы EXEC/DOS размещаются в LOCAL по F6C0h–F7FFh. В MAIN этот слот занимает AT512KS; используются аппаратные обработчики BIOS. F6C0h — A: с локальным CPM32-чтением и переходом в MAIN для записи, F6C3h — проверяющая запись B=5 на локальном стеке, F6C6h — расчёт суммы в своём банке. Это внутренние входы MEM. H: лениво устанавливается по F9C0h–FBFFh; пользовательские операции памяти не могут менять этот слот.

Установочные сегменты LOCAL и CLIENT собираются вместе. В MAIN bootstrap и программное восстановление копируют BANK_MAIN_LOCAL_BYTES до слота AT512KS. Сегмент CLIENT установлен во всех исполняемых страницах. Программный возврат сохраняет AT512KS, Reset повторно запускает установщики AUTOEXEC. DATA получает резидентный хвост с FE00h, а RAM-диск резервирует два последних сектора.

Единый LOCAL_BLOCK_ENTRY принимает B=1/2/4/5; DOS и RAW-клиенты не выбирают отдельный проверяющий вход. В основной памяти MEM_LOCAL_CHECKED хранит внутренний адрес проверяющего цикла BIOS; его читает только локальный диспетчер, без межбанкового копирования. При прямом обмене блоком B: копирование сразу связывает банк носителя с банком клиента. Секторный буфер DOS для этих служб не нужен. Изменение состава общего хвоста сопровождается повышением MEM_RUNTIME_REVISION, чтобы Reset не оставлял несовместимое старое ядро.

Подтверждение замены COPY/MOVE не резервирует память в хвосте MEM. DOS передаёт обработчику A=FAR-банк DOS и HL=адрес FILE_DESCRIPTOR назначения. Общий переходник приложения `source/common/copyConfirmLocal.inc` копирует 32-байтный дескриптор на локальный стек через memcpy_far, затем вызывает диалог; пакет переноса занимает ещё 8 байт. Повторный вход в DOS из диалога запрещён. Переходник включается в приложение, а не в каждый банк MEM.

Место прежнего 32-байтного снимка используется регистровыми входами MEM. CPM32 может занять все 32 байта окна и оставить его следующей операции.


## Размещение CPM32 и скалярных служб

Полный MEM начинается с F1C0h. Подготовка CPM32 и пакетный вход расположены по F1C0h/F1C3h, мост A: по F240h. Код точного остатка установлен в резидентном хвосте DATA и исполняемых страниц. Стек DOS EE00h–F03Fh имеет 576 байт, служебный стек MAIN — 256 байт.

Постоянная часть CPM32 установлена по одинаковым адресам в MAIN, EXEC, DOS и DATA. В режиме ROM видна верхняя часть MAIN, поэтому ROM использует её экземпляр. DATA-профиль начинается по FE00h и укладывается в те же два зарезервированных физических сектора FE00h–FFFFh. FORMAT отмечает их как BAD, проверяемый RAW-вход DOS отвергает обмен с ними. FAR-аллокатор сверяет границу с MEM_DATA_LIMIT=FE00h. Старый RAM-диск без этого резерва нельзя обновлять записью поверх FE00h.

Bootstrap использует установочные сегменты MEM.SYS и проверку ревизии; старый RAM-диск нельзя обновлять записью расширенного DATA-хвоста поверх пользовательских данных. Проверки загрузки образа и ABI выполняются отдельно.

LOCAL_BLOCK_ENTRY после RAW_OP_PREPARE остаётся доверенным внутренним входом без повторной проверки LBA/буфера. Обходить защиту служебных секторов через него нельзя: вызывающая сторона обязана передавать только допустимые блоки. Защита FAT BAD и проверка штатного RAW-входа DOS независимы.

## Размеры хвостов MAIN/DOS/EXEC/DATA

Полный хвост MEM резервирует F1C0h–FFBFh: 3584 байта (3,5 КиБ), включая слоты A: (320 байт) и H: (576 байт), внутренние рабочие поля и промежутки. Этот резерв одинаков в MAIN, DOS и EXEC; свободный либо лениво устанавливаемый слот H: не возвращается приложению. У MAIN дополнительно установлен IO.SYS по F000h–F1AEh (431 байт); весь верхний резерв F000h–FFBFh равен 4032 байтам, включая 17 свободных байт между IO и MEM. В DOS/EXEC клавиатурный сегмент IO.SYS занимает отдельное окно F040h–F1BFh перед MEM. Служебный стек DOS EE00h–F03Fh (576 байт) учитывается отдельно.

DATA получает 448 установленных байт FE00h–FFBFh. Для FAR-данных остаётся 0000h–FDFFh (65024 байт), а FAT исключает целиком два последних физических сектора — 512 байт. В локальном хвосте находятся служебные процедуры и байт готовности EXEC. Аппаратное окно FFC0h–FFDFh представляет общие физические 32 байта. Регистры оборудования лежат по FFE0h–FFFFh.

В текущем H:-резиденте AT2MX развернуты оба пути записи ×8, AT2MXF — оба ×4; выровненное чтение ×8 и обычный путь чтения сохранены. Произвольный адрес буфера остаётся частью контракта; драйвер сам выбирает путь.

Одиночные символы поступают в mx_printChar и mx_printCharRaw через C и A соответственно. MEM переносит их в регистре и при необходимости устанавливает рабочий стек BIOS. Строки печатаются прямо из окна. Для короткой командной пачки MAIN копирует список на стек, чтобы отдельные команды могли выполнять вложенные вызовы.

Очередь команд MEM 1.3 использует прямую запись с резервом максимальной команды и commit после записи. Получатель выбирается во время работы. Пачка BIOS до 32 байт передаётся через окно и копируется на стек MAIN. Более длинная пачка передаётся через CPM32 в буфер MAIN. DOS исполняет файловые команды локально, DLL получает FAR-адрес потока прямым вызовом MEM. Автосброс перед синхронным API/COPY и явный flush сохраняют порядок. Интерфейс ASM находится в source/include/command-queue.inc, интерфейс C — в sdk/include/mxos_queue.h. Подробный контракт приведён в [api.md](api.md#очередь-команд-mem-13).
