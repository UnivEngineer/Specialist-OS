# MEM.SYS

Общий менеджер межбанковых вызовов и переноса данных. Исходники и самостоятельный установочный образ находятся в этом компоненте. Сборка: `python scripts/build/build-banked-transport.py`; результат `bin/MEM.sys`, промежуточные фрагменты и символы — `bin/banked/`. Полная сборка ОС включает этот шаг автоматически.

Подготовка CPM32 общая для memcpy_far и физических операций A:/B:. Все 32 байта аппаратного окна используются для данных; параметры продублированы в хвостах банков. Порции POP/SHLD и LHLD/PUSH поддерживают произвольное выравнивание, остаток 1–31 байт обрабатывается без чтения за границей. Для длины 256 байт есть короткая подготовка без деления; длинный запрос экономит повторную установку параметров. FILEHANDLE готовят до 16/32/64 LBA за пачку, по умолчанию 32. Неполные сектора используют кэш DOS. Внутренняя ревизия MEM — 53.

| Назначение банка | Устанавливаемые службы | Доступная память |
|---|---|---|
| Данные (`MEM_BANK_DATA`) | COMMAND FED0h–FEF8h и копировщик FF00h–FFBEh | 0000h–FECFh: 65232 байта |
| Исполняемый (`MEM_BANK_EXEC`) | Локальные адаптеры, публичный ABI, транспорт, копировщик | Ниже EE00h. Выше находятся служебный стек, клавиатурный сегмент IO и MEM |
| DOS (`MEM_BANK_DOS`) | Тот же код, что в исполняемом банке | Своя карта DOS и служебный стек |

Основная память также получает полный код MEM. У неё своя карта BIOS, экрана и программ. Код CLIENT и TRANSPORT одинаков во всех полных профилях; LOCAL в MAIN устанавливается без банковых служб в слоте AT512KS. При установке различаются данные: FAR-код, owner/home, границы стека, назначение банка, указатель на локальный диспетчер основной памяти и физический обработчик A:. DOS определяется маршрутизатором по FAR-коду 1; отдельного варианта MEM для неё нет. Синхронный API модулей и нативный FILE_EXEC банковых COM/EXE используют этот же профиль: bootstrap устанавливает полный профиль в main/DOS, а в остальные обнаруженные банки — профиль данных; при загрузке приложения выбранный свободный банк получает полный профиль EXEC.

В банке данных нет отдельного стека и контекста приложения; короткий COMMAND-вход обслуживает только GET/PUT8/16, без полного диспетчера. Подготовка memcpy_far и возврат выполняются в банке-инициаторе; внутри цикла работают одинаковые хвосты источника и приёмника. FED0h–FFFFh исключается из данных: 239 байт COMMAND/CPM32, байт резерва, 32 байта общего окна и 32 байта регистров. RAMDISK использует первые 254 физических сектора банка; FORMAT помечает оба последних сектора значением FAT16 BAD (FFF7h). Секторы метаданных тома дополнительно уменьшают доступное место файлов.

MEM.SYS — плотный установочный контейнер, а не линейный образ всего диапазона F1C0h–FFFFh. Заголовок: ASCII `MXMM`, версия 1, число сегментов 4; далее четыре записи по шесть байт `{destination:word, size:word, offset:word}`, little-endian. Сегменты: LOCALBLOCK (F1C0h), CLIENT (F800h), TRANSPORT (FC00h), WINDOW (FFC0h). Смещения считаются от начала файла. Файл содержит 30 байт заголовка и плотные устанавливаемые сегменты; их размеры экспортирует сборка в bin/MEM.sym. Это сумма сегментов, а не непрерывный резерв 2 КиБ: полный профиль пока начинается с F1C0h; слот H: расширен до 576 байт переразмещением TEXT и служб A:. Незанятые слоты драйверов не хранятся и не перезаписываются. Последние 239 байт TRANSPORT образуют профиль DATA с FED0h. WINDOW устанавливается один раз в физически общее окно.

Штатный bootstrap включает точную копию MEM.SYS и устанавливает её сегменты по экспортированным смещениям. Отдельный MEM.SYS также размещается в фиксированном ROM-слоте 7000h вместо прежнего TAIL.SYS. Пока это служебный установочный файл, его замена требует согласованной пересборки bootstrap и системного образа. Bootstrap сохраняет готовую DOS при Reset только при совпадении MEM_RUNTIME_REVISION: старое ядро с адресами прежнего внутреннего транспорта должно быть перезагружено. Обычный Reset с совместимой ревизией DOS не перезагружает. Проверка ревизии не является контролем целостности кода.

F800h/F803h/F806h/F809h/F80Ch/F80Fh/F812h/F815h/F818h одинаковы в основной памяти и банках. CLIENT передаёт main-вызовы локальному диспетчеру BIOS, а банковые направляет в BIOS или DOS. Локальные BIOS-обработчики остаются в BIOS.SYS; принимающий адаптер BIOS и физический ROM-мост — в IO.SYS. Для A: в main вызывается bios_blockIO, в DOS — dosSystemDriver; обмен B: использует FAR-код текущего банка, H: — установленный локальный слот F9C0h.

При установке полного профиля надо задать bankPage, bankPageCount, bankOwner/home, bankDepth=0, bankServiceSP и bankStackFloor, а также MEM_BANK_KIND, MEM_LOCAL_A и MEM_NEAR_COPY. В main дополнительно задаётся MEM_NATIVE_CALL. Нельзя исполнять код полного профиля из банка данных. Стек и пользовательские буферы должны находиться ниже F1C0h. Инициализаторы драйверов устанавливают службы H: отдельно; MEM не дублирует аппаратную инициализацию.

Закреплённый контракт для приложений: [api.md](api.md). Подробности регистров, общего окна и вложенных стековых кадров: [transport.md](transport.md). Ленивое переключение окна реализовано: после переноса остаётся профиль COPY, командный профиль восстанавливается только при следующем вызове или возврате. Аллокатор FAR-блоков и загрузчик синхронных модулей реализованы в DOS. moduleLoad/Call/Unload описаны в [api.md](api.md); нативный FILE_EXEC запускает BANK-приложение и освобождает его ресурсы после RET. Полноценные процессные идентификаторы ещё не реализованы, RUN остаётся лаунчером совместимости.

### Размещение DLL

| Параметр MODULE_LOAD | Размещение | Условия |
|---|---|---|
| `MODULE_TARGET_MAIN=0` | Свободный диапазон основной памяти | Загрузчик резервирует заявленный интервал кода и BSS |
| `MODULE_TARGET_BANK=1` | Отдельный свободный EXEC-банк | DOS, RAM-диск и чужие выделения исключены |
| `MODULE_TARGET_DOS=2` | Единая арена 9800h–B4FFh, до CB80h при заимствовании неактивного BAT | IMAGE_FLAG_DRIVER, точные непересекающиеся интервалы |

DOS-DLL использует служебный стек DOS на 576 байт. Кэшируемые ENUM и FILEOPS, загруженные DLL и установщик учитываются общим реестром пересечений; активный код не вытесняется. Установщики заканчиваются перед B500h. RETAIN разрешён, если модуль не занимает кадры BAT B500h–CB7Fh. Файлы читаются DOS, переключение контекста выполняет MEM.

Так можно вынести измерительный цикл DiskBen в DOS-DLL: контроллер в main передаёт параметры одним MODULE_CALL, а RAW/файловые операции работают с локальными буферами банка DOS. Установка MEM и подмена аппаратного окна приложению не требуются. MX_REGS принадлежит вызывающей стороне; NEAR-адреса внутри него не преобразуются. Полный контракт и ASM-пример — в [api.md](api.md), проверочные модули — в [moduletest](../../source-apps/moduletest/README.md).

## Публичный ABI MEM 1.3

Одинаковые входы в main и исполняемых банках не требуют обращения к DOS:

| Вход | Входные параметры | Результат |
|---|---|---|
| F80Fh / mx_memcpyFar | HL → MEM_COPY_REQUEST, восемь байт | A=0, CF=0 при успехе; BC/DE/HL сохранены |
| F812h / mx_memInfo | Нет | HL=0103h (версия 1.3), DE=возможности, A=FAR-код исполнения, B=число банков ДОЗУ, C=назначение банка, CF=0 |
| F815h / mx_memory | A=операция, остальные параметры по [api.md](api.md) | Локальные операции MOVE, GET/PUT, PRINT без обращения к DOS |

MEM_COPY_REQUEST: sourceBank:byte, sourceOffset:word, destinationBank:byte, destinationOffset:word, count:word; слова little-endian, структура объявлена в mxos.inc. Нулевой размер ничего не проверяет и возвращает успех. Для ненулевого размера FAR-коды должны быть 0…число обнаруженных банков; диапазоны не должны переходить через 64 КиБ или включать FF00h и выше. E0h/CF=1 означает неверный банк, E2h/CF=1 — неверный диапазон; E1h зарезервирован для нехватки стека межбанкового вызова. Перекрытие не допускается, но отдельно не проверяется. Нельзя затирать собственный код, стек, пакет запроса или служебные области. Это перенос заданных адресов, без выделения памяти и проверки владельца. IRQ должны быть запрещены; атомарная петля не допускает callback.

Четырёхбайтные объекты, включая курсор FileStream, передаются через обычный FAR COPY. Отдельных системных входов и C-обёрток GET/PUT32 нет.

В C SDK есть MXOS_FAR_COPY (восемь байт для 8080) и mxos_memcpy_far(); функция возвращает AF как 16-битное слово. Структуры из sdk/include/mxos.h и source/include/mxos.inc должны совпадать побайтно. Нативный FILE_EXEC и RUN устанавливают полный профиль и локальный стек при загрузке BANK-программы. Ручная установка нужна только автономным стендам.

## Восстановление после записи в STD-порт в режиме MX

Классическая программа, рассчитанная на STD, может обращаться к клавиатурному порту FF00h–FF03h. Если её запустить в режиме MX, по этим адресам находится оперативная память с защитной сигнатурой MEM. Запись в такой «порт» повреждает сигнатуру; исполняемый код копировщика начинается с FF04h и от этой записи не страдает. Этот раздел описывает обнаружение и восстановление после такого повреждения.

При программном возврате через C000h/C800h BIOS сравнивает сигнатуру FF00h–FF03h основной памяти с теми же адресами в банке DOS. При отличии выводится `STD I/O write in MX mode. Press any key` с ожиданием клавиши. Сигнатура содержит `FF FF FF FF`: это состояние без клавиш при режиме ВВ55 82h и выходных регистрах A/C=FFh. Чтение FF03h (РУС) аппаратно не определено; FFh соответствует открытой шине в принятой модели Emu80. Другие направления портов, значения выходных регистров или вход магнитофона могут дать другое чтение настоящего ВВ55. Эталон сигнатуры берётся из банка DOS.

Затем BIOS восстанавливает код MEM основной памяти из банка DOS: локальный адаптер, CLIENT, транспорт и копировщик, а также управляющий профиль общего окна. Восстановление выполняется и при совпадении сигнатуры: эта проверка не подтверждает целостность остальных процедур MEM. После копирования заново задаются контекст main и локальные обработчики. Драйверные слоты и данные DOS не перезагружаются.

Проверка и восстановление не используют потенциально повреждённый FAR-копировщик: эталон читается временным кодом в физически общем окне. Требуются исправные BIOS и банк DOS, а также передача управления на C000h/C800h. Если программа зависла и не вернулась в BIOS, этот механизм сам по себе не запускается. Отличие сигнатуры обнаруживает повреждение, характерное для записи в STD-порт, но не доказывает его причину.

## Терминология транспорта

**Транспорт** — вся система межбанковых вызовов и передачи данных MEM. **Общее окно** — физические 32 байта FFC0h–FFDFh, доступные при переключении банков. **Профиль окна** — текущая раскладка кода и данных в этих байтах. **MXOS_CALL** — интерфейс вызова BIOS/DOS; GET/PUT и memcpy — операции доступа к данным. Переключение банка, смена профиля и запись шаблона кода в окно — разные действия с разными затратами.

Окно переключается лениво между COMMAND, COPY и LOCAL. COMMAND теперь передаёт и регистровые кадры, и inline-строки/командные пачки до 20 байт; отдельный TEXT удалён. GET/PUT используют регистровую часть COMMAND. Числа профилей внутренние.

## Локальные копии

При совпадении обоих FAR-кодов с текущим банком memcpy_far вызывает штатный локальный стековый движок: bios_memcpy_bc_hl в main и уже скомпилированную в DOS memcpy_bc_hl в банке DOS. Локальный memmove использует тот же движок с поддержкой перекрытия. Указатель MEM_NEAR_COPY задаётся при установке/восстановлении контекста банка; нулевой указатель отключает ускорение. CPM32 обслуживает межбанковый перенос. Локальный путь не заменяет профиль физического окна.

## Операции памяти

Вход F815h/mx_memory принимает A=MEM_OP_*: MOVE=0 (HL → восьмибайтный пакет memcpy), GET8=1, GET16=2, PUT8=3, PUT16=4 (B=FAR-код, HL=смещение, DE=значение; GET возвращает DE), PRINT=5 (HL=локальная строка, результат HL на нуле). BC/HL GET/PUT сохраняются; слово little-endian целиком должно находиться ниже FF00h. MOVE разрешает перекрытие. При совпадении банка с текущим MOVE использует штатный стековый движок, в другом банке — цикл окна с нужным направлением. IRQ запрещены; аппаратной защиты памяти нет.

Стандартный банковый вызов BIOS PRINT_STRING также использует Window20. Печать из main остаётся нативной. Через окно передаются до 20 символов и завершающий ноль; профили COMMAND/COPY/LOCAL имеют единый канонический снимок командного окна. Автоматического выделения большого main-буфера нет: программа может явно выделить main-блок, скопировать туда текст и вызвать службу печати с явно заданным контекстом main. NEAR-указатель в обычном банковом PRINT_STRING всегда относится к вызывающему банку, даже если его числовой адрес совпадает с main-буфером.

MXOS_DOS_MEMORY использует тот же регистровый контракт GET/PUT, а также A=6 ALLOC (B=FAR-код или FFh — любой свободный банк данных, HL=размер; результат B:HL, DE=размер), A=7 FREE (B:HL), A=8 REALLOC (B:HL, DE=новый размер). Сжатие выполняется на месте, расширение — транзакционно с копированием; при ошибке прежний блок действителен. Нулевой ALLOC возвращает nullptr; REALLOC с нулём освобождает блок. Ошибки E3h — нехватка, E4h — неверное владение/освобождение. Размеры 16-битные, блок не пересекает банк; выравнивание два байта. Реестр 32 записей расположен в DOS по 7D00h, данные банков не содержат скрытых заголовков.

A=9 ARENA регистрирует доверенный свободный диапазон main (0100h…8C00h), принадлежащий текущему приложению. Запуски MAIN получают временного владельца и очищают его блоки при RET; вложенные вызовы восстанавливают родительскую арену. Модули имеют собственные теги. Тёплый вход удаляет временные ресурсы и сохраняет зарегистрированные резиденты. Сроки жизни, ограничения и контракты — в api.md.

A=10 RAMLIMIT выбирает фиксированный пул B:. A=14 RAMDISK с C=0 сообщает его размер и владельца, с C=1 передаёт подготовленный пул DOS из DRIVER-инициализатора. RAMDISK.COM -P 4 использует четыре банка данных и не оставляет резидентного кода. Владение и данные сохраняются при Reset; модульный handle не требуется. Исторический A=13 DISKCLAIM для модульного владельца остаётся совместимым. Изменение размера закреплённого пула и SHRINK/GROW пока не поддерживаются. A=11 FILL заполняет дальний диапазон, A=12 QUERY сообщает свободные байты, наибольший промежуток и свободные записи реестра.

## Явный выбор источника строки BIOS

`MXOS_CALL MXOS_BIOS_PRINT_STRING_BANK` (0107h, прежнее имя `MXOS_BIOS_PRINT_STRING` сохранено) принимает HL на ASCIIZ в банке вызывающей программы. В main печать нативная; из банка DOS/программы MEM скрыто передаёт порции до 20 байт через аппаратное окно и печатает непосредственно из него. Банк-источник не подменяется контекстом DOS.

`MXOS_CALL MXOS_BIOS_PRINT_STRING_MAIN` (012Fh) принимает HL на ASCIIZ именно в основной памяти. Из банка передаётся только пакет регистров: BIOS вызывает штатный printString с этим main-адресом, без копирования текста. Банк вызывающей программы и его SP восстанавливаются. Для обоих вызовов HL возвращается на завершающем нуле, AF/BC/DE сохраняются согласно обычному printString. Выделение main-буфера, копирование в него и срок его жизни обеспечивает программа; FAR-пакет для этой функции не нужен, так как банк main задан самой операцией.


FILE_EXEC_NATIVE (022Ah) использует тот же загрузчик, обходя CLI/PATH/ассоциации. RUN передаёт ему подтверждённые MAIN/DRIVER/BANK; контейнеры COM/EXE с flags=0 без явного режима показывают меню. Подробный контракт и ограничения main-продолжения — в api.md.

## Локальные физические службы EXEC/DOS

Слоты относятся к MAIN, DOS и исполняемым EXEC-банкам. Банки данных RAM-диска получают только хвост копировщика, без полного клиентского профиля. Размеры ниже — по текущим листингам; конечные адреса исключающие там, где используются метки End.

| Область | Резерв | Содержимое |
|---|---:|---|
| F5C0h–F67Bh | 188 байт | Диспетчер A:/B:/H:, контекст, указатели и снимок COMMAND |
| F67Ch–F6BFh | 68 байт | Непрерывный резерв MEM |
| F6C0h–F7FFh | 320 байт | MAIN: AT512KS 282 байта; DOS/EXEC: службы A:, проверки и суммы 267 байт |
| F800h–F8BFh | 192 байта | Публичные входы и диспетчер CLIENT, 4 байта резерва |
| F8C0h–F9BEh | 255 байт | Текстовый шлюз |
| F9BFh | 1 байт | Резерв перед H: |
| F9C0h–FBFFh | 576 байт | Одна служба H:: ROM2M 265, AT2MX 546 либо AT2MXF 570 байт |

В H:-слот копируется только служба обмена со своими переменными, а не COM с обнаружением чипов и установщиком. Свободно соответственно 311, 30 и 6 байт. DOS хранит также эталон переносимой службы в DOS_DRIVER_IMAGE; клиентские копии восстанавливаются из него. Слот расширен на 64 байта без увеличения полного защищённого хвоста; 68 байт нижнего резерва не примыкают к H: и не входят в его ёмкость.

A:/B: доступны сразу после установки полного MEM-профиля. H: устанавливается лениво при первом полном физическом обмене в соответствующей странице; это делают обычные RAW_IO, SECTOR_IO, FileStream, FileHandle и загрузчик, а также явный RAW_IO B=6. Последующие блоки используют ту же копию. Новый EXEC-профиль сбрасывает её маркер; замена H:-драйвера инвалидирует отметки всех страниц. Смена владельца конвейера FLASHFST сначала завершает прежнюю запись.

Прямое чтение A: из DOS/EXEC формирует физический ROM-селектор 80h..8Fh и запускает bankCopySector в своём банке. Для FILEHANDLE загрузчик и файловое ядро DOS могут сразу задать клиентский банк назначения: callback в клиент для каждого сектора не нужен, COPY остаётся активным на серии. Исключение — верхняя MAIN, где сохраняется более быстрый отображённый memcpy. Вход в MAIN и перенос пятибайтового запроса для банкового чтения не нужны. CPM32 переносит 32 байта через общее окно и переключает ROM/банк клиента; секторного буфера в MAIN/DOS нет. Запись использует MAINIO: сектор переносится в общий буфер MAIN ED80h–EE7Fh, затем штатный AT29-драйвер загружает аппаратную страницу через memcpy и ожидает DATA polling. Код программирования не дублируется в банковых хвостах.

Эти слоты пока не являются универсальным загрузчиком произвольных драйверов: localBlock/klEligible явно выбирают A:/B:/H:, установщик переносимой службы принимает только H: и блоки 256 байт. Для нового floppy-драйвера потребуются расширение реестра/диспетчера и решение о размещении кода: текущий единичный слот ограничен 576 байтами. Физические блоки 512 байт пока обслуживаются общим путём DOS; существующий прямой путь умеет логический сектор 512 байт поверх двух физических блоков 256 байт.

Службы EXEC/DOS размещаются в LOCAL по F6C0h–F7FFh. В MAIN этот слот занимает AT512KS; используются аппаратные обработчики BIOS. F6C0h — A: с локальным CPM32-чтением и переходом в MAIN для записи, F6C3h — проверяющая запись B=5 на локальном стеке, F6C6h — расчёт суммы в своём банке. Это внутренние входы MEM. H: лениво устанавливается по F9C0h–FBFFh; пользовательские операции памяти не могут менять этот слот.

LOCAL, CLIENT и TEXT собираются совместно с разрешением внутренних ссылок, затем сборщик разделяет результат на прежние установочные сегменты LOCAL и CLIENT. В MAIN bootstrap и программное восстановление копируют только BANK_MAIN_LOCAL_BYTES до слота AT512KS; CLIENT вместе с TEXT одинаков во всех полных профилях. Программный возврат сохраняет установленный AT512KS, Reset восстанавливает BIOS и повторно запускает установщики AUTOEXEC. Публичные адреса F800h–F815h, DATA-профиль FED0h–FFBEh и защита двух последних секторов RAM-диска не изменились.

Единый LOCAL_BLOCK_ENTRY принимает B=1/2/4/5; DOS и RAW-клиенты не выбирают отдельный проверяющий вход. В основной памяти MEM_LOCAL_CHECKED хранит внутренний адрес проверяющего цикла BIOS; его читает только локальный диспетчер, без межбанкового копирования. При прямом обмене блоком B: копирование сразу связывает банк носителя с банком клиента. Секторный буфер DOS для этих служб не нужен. Изменение состава общего хвоста сопровождается повышением MEM_RUNTIME_REVISION, чтобы Reset не оставлял несовместимое старое ядро.

Подтверждение замены COPY/MOVE не резервирует память в хвосте MEM. DOS передаёт обработчику A=FAR-банк DOS и HL=адрес FILE_DESCRIPTOR назначения. Общий переходник приложения `source/common/copyConfirmLocal.inc` копирует 32-байтный дескриптор на локальный стек через memcpy_far, затем вызывает диалог; пакет переноса занимает ещё 8 байт. Повторный вход в DOS из диалога запрещён. Переходник включается в приложение, а не в каждый банк MEM.

32-байтный MEM_COMMAND_SHADOW сохраняется: ленивый COPY/TEXT оставляет изменённое окно после возврата из вызова, поэтому снимок должен жить независимо от освобождённого стека. Неиспользуемое поле IO_VARIABLES.romSavedWindow удалено; IO_VARIABLES теперь занимает 64 байта, EFE0h–EFFFh свободны.


## Размещение CPM32 и скалярных служб

Полный MEM начинается с F1C0h; отдельная COPY-ветвь GET/PUT8/16 удалена. Подготовка CPM32 и пакетный вход сохраняют адреса F1C0h/F1C3h; мост A: — F240h, точный остаток — F340h, состояние — F377h–F37Fh. Вспомогательные циклы помещены в промежутки F335h и F360h. Маршрутизация текста находится с F380h, общая таблица операций — F3F8h; TEXT вынесен в F8C0h. Стек DOS EE00h–F03Fh имеет 576 байт. MAIN использует прежний служебный стек 256 байт.

Постоянный регистровый COMMAND-обработчик занимает FED0h–FEF8h и установлен по одинаковому адресу в MAIN/EXEC/DOS/DATA; исходный CPM32-хвост FF00h–FFBEh сохраняет размер 191 байт. Поэтому DATA-профиль занимает 239 байт с FED0h и требует защиты двух последних физических секторов FE00h–FFFFh. FORMAT отмечает оба как BAD, проверяемый RAW-вход DOS отвергает обмен с ними, FAR-аллокатор ограничивает полезный DATA-диапазон адресом FED0h. Это меняет резерв старого RAM-диска: его нельзя обновлять слепой установкой хвоста поверх FE00h, где могли находиться данные.

Bootstrap использует установочные сегменты MEM.SYS и проверку ревизии; старый RAM-диск нельзя обновлять записью расширенного DATA-хвоста поверх пользовательских данных. Проверки загрузки образа и ABI выполняются отдельно.

LOCAL_BLOCK_ENTRY после RAW_OP_PREPARE остаётся доверенным внутренним входом без повторной проверки LBA/буфера. Обходить защиту служебных секторов через него нельзя: вызывающая сторона обязана передавать только допустимые блоки. Защита FAT BAD и проверка штатного RAW-входа DOS независимы.

## Размеры хвостов MAIN/DOS/EXEC/DATA

Полный хвост MEM резервирует F1C0h–FFBFh: 3584 байта (3,5 КиБ), включая слоты A: (320 байт) и H: (576 байт), внутренние рабочие поля и промежутки. Этот резерв одинаков в MAIN, DOS и EXEC; свободный либо лениво устанавливаемый слот H: не возвращается приложению. У MAIN дополнительно установлен IO.SYS по F000h–F1BEh (447 байт); весь верхний резерв F000h–FFBFh равен 4032 байтам, включая один байт между IO и MEM. В DOS/EXEC клавиатурный сегмент IO.SYS занимает отдельное окно F040h–F1BFh перед MEM. Служебный стек DOS EE00h–F03Fh (576 байт) учитывается отдельно.

DATA содержит только COMMAND/CPM32: 239 установленных байт FED0h–FFBEh плюс один резервный байт FFBFh. Для FAR-данных остаётся 0000h–FECFh (65232 байта), а FAT исключает целиком два последних физических сектора — 512 байт. Аппаратное общее окно FFC0h–FFDFh (32 байта) и регистры FFE0h–FFFFh (32 байта) во все приведённые размеры RAM-хвостов не включены; окно физически общее, а не копия в каждом банке.

В текущем H:-резиденте AT2MX развернуты оба пути записи ×8, AT2MXF — оба ×4; выровненное чтение ×8 и обычный путь чтения сохранены. Произвольный адрес буфера остаётся частью контракта; драйвер сам выбирает путь.

Одиночные символы CHAR/CHAR_RAW при активном TEXT передаются через временное слово локального стека. Внутренний memSelect расположен выше F800h и не подходит как обычный источник строки. Это сохраняет проверку границ публичных строк и обработку управляющих символов, включая LF в BAT. Изменение устанавливаемого тела требует ревизии MEM 32.

Очередь команд MEM 1.3 использует прямую запись с резервом максимальной команды и commit после записи. Получатель выбирается во время работы. BIOS принимает короткие пачки через COMMAND и длинные через CPM32, DOS исполняет файловые команды локально, DLL получает FAR-адрес потока прямым вызовом MEM. Автосброс перед синхронным API/COPY и явный flush сохраняют порядок. ASM: source/include/command-queue.inc; C: sdk/include/mxos_queue.h. Подробный контракт — [api.md](api.md#очередь-команд-mem-13).
