# FORMAT.COM

Системный диск A: форматировать запрещено. FORMAT отказывает до подтверждения и доступа к драйверу, в том числе при -Y и интерактивном выборе A:. Возвращаются CF=1 и A=DOS_ERR_ACCESS. Поддерживаемые цели — B:–H:.

Готовность существующего тома не означает пропуск форматирования: команда намеренно создаёт новую разметку. -R задаёт особенности RAM-диска, -Y убирает вопрос о подтверждении. При тёплом Reset сама система пропускает FORMAT.BAT.

Сборка от 04.11.2026 загружается по 0000h. Единственный рабочий буфер — 1000h–10FFh (256 байт). FAT формируется по одному сектору: первые две записи служебные, свободные кластеры нулевые, хвосты страниц RAMD помечаются FFF7h, запас таблицы вне области данных — FFFFh. Корень записывается первым сектором с меткой тома и повторением нулевого буфера. Ошибка записи немедленно прерывает форматирование.

Это формат MXOS-256 с прежним пределом 8192 физических секторов. Секторный буфер устраняет зависимость расхода ОЗУ от размера FAT, но не означает реализацию стандартных FAT12/16 или 512-байтных логических секторов. Для будущих дискет и SD размер логического сектора и размер блока драйвера должны задаваться отдельно.

Проверки: scripts/tests/check-format-args.py и scripts/tests/check-format-stream.py (CPU 8080); загрузка и форматирование RAM-диска также проверены в собственном Emu80.

FORMAT записывает только загрузочный сектор, всю FAT и корневой каталог. Для тома 1 МиБ с текущей геометрией это 41 сектор по 256 байт: 1 + 32 + 8. Нулевая FAT тоже записывается на носитель: прежние цепочки файлов должны быть уничтожены. Область данных не очищается и не проверяется. После записи том перемонтируется, текущий каталог сбрасывается в корень.

Обнуление выровненного секторного буфера выполняется порциями по восемь байтов без 16-битного счётчика на каждый байт. Размер и выравнивание буфера проверяются при сборке. Возврат после запуска из NC включает отдельные расходы на повторную загрузку NC и восстановление панелей; они не входят в работу форматировщика.



Исправление скорости (04.11.2026): вместо ветвления для каждой FAT-записи
FORMAT обнуляет сектор и точечно отмечает FAT[0]/FAT[1], запас таблицы и
одну BAD-запись в подходящем секторе FAT. Алгоритм по-прежнему использует
единственный буфер 256 байт и пишет только boot/FAT/root, область данных
не очищается. Через логический секторный слой DOS форматирование не идёт:
используется прямой bios_diskDriver, B=1.

В модели CPU 8080 с одинаковым тестовым драйвером FORMAT -R для 1 МиБ
сократился с 1 699 637 до 774 216 тактов, для 2 МиБ — с 3 256 292 до
1 421 399 тактов. Это снижение времени на 54,4% и 56,3%, а не измерение
физического носителя. Измеряется весь вызов FORMAT, включая модель записи.
Команда сравнения: `python scripts/tests/check-format-stream.py --timings`;
`--binary-dir` задаёт каталог контрольных FORMAT.i80/FORMAT.sym/DOS.sys/DOS.sym.
