# RUN.COM — запуск COM, EXE и RKS

Проект `source/run/` заменяет LAUNCH и отдельный RAMRUN. Сборка создаёт `bin/RUN.cpu` с адресами и `bin/RUN.i80` с машинным кодом. Сборщик образа упаковывает их в `RUN.COM`. Ядро совместимости RAMFOS называется `RAMFOS.MON`; расширение SYS оставлено за DOS.

## Командная строка

```text
A:RUN.COM -MX H:GAME.COM
A:RUN.COM H:GAME.EXE -STD
A:RUN.COM H:GAME.RKS -RF аргументы
A:RUN.COM -MON H:GAME.RKS
A:RUN.COM -MON:Monitor2 H:GAME.EXE
A:RUN.COM H:GAME.EXE
```

Слова командной строки выделяет общий `bios_argNext` DOS (C8B7h). Ключ режима можно ставить до или после имени программы, в том числе между её аргументами; регистр ключа не важен. Например, `run GAME.EXE -STD` и `run -STD GAME.EXE` равнозначны. Ключи RUN исключаются из передаваемой строки, остальные аргументы после имени сохраняют порядок (не более 127 байт, разделители — одиночные пробелы). При нескольких ключах действует последний. Короткое имя `run` без диска и расширения DOS разрешает как `A:RUN.COM`. Исходный диск восстанавливается до входа в программу: с H: команда `run BUDI-RF.exe` берёт RUN с A:, а игру с H:. Это же правило действует для остальных COM и из BAT. Явные имена с диском или расширением сохраняют прежний смысл.

| Файл без ключа | Поведение |
|---|---|
| COM | MX |
| RKS | MON |
| EXE | Меню выбора MX, STD, RF, MON или MON с запросом имени ядра |

COM и EXE имеют одинаковый 16-байтный заголовок. DOS исполняет только COM; EXE и RKS передаются RUN через `NC.EXT`. Среда исполнения в заголовке не записывается. Для известных исключений подходят BAT с явным ключом.

## Среды

- MX сохраняет ядро MXOS2 и аппаратный режим. Программа получает DE со строкой аргументов; RET возвращает вызывающей стороне с восстановлением исходного KOI.
- STD оставляет ядро MXOS2, останавливает ВИ53, включает STD, нижнее ОЗУ, белый цвет и KOI-7. RET через нижний переходник возвращает MX и KOI-8.
- MON выполняет STD-подготовку и подменяет ядро на `A:MONITOR2.MON`. RET программы вызывает холодную загрузку MXOS2. Флаг KOI-7 MXOS после подмены не записывается: у Monitor-2 свои переменные.
- MON:имя использует указанный бинарник вместо Monitor-2. Без диска подставляется A:, без расширения — .MON. Сейчас требуется 4096 байт и совместимый пролог инициализации Monitor-2; выбор произвольного имени не означает поддержку любого ABI.
- RF загружает `A:RAMFOS.MON`, переносит обе области ядра и передаёт управление его адаптерному входу F85Ah. RET приводит к холодной загрузке MXOS2. Отдельный RAMRUN не вызывается. Файловый адаптер RAMFOS к FAT пока не реализован.

MON — сырой образ ядра без исполняемого контейнера. У RAMFOS последовательно хранятся C000h–D2FFh и F800h–FFDFh, всего 6880 байт. Правила их размещения принадлежат адаптеру RUN, а не файловому дескриптору.

## Загрузка и память

RUN вызывает общий секторный загрузчик DOS. Первый сектор читается в штатный секторный кэш; из него копируется до 240 байт тела COM/EXE либо до 252 байт RKS. Полные последующие секторы читаются прямо по адресу назначения, последний неполный — через кэш с копированием только точного хвоста. Проверяется одна штатная сумма тела. Для RKS сумма в конце файла проверяется RUN, включая случай её переноса через границу сектора. Для этого редкого чтения повторно используется первая, уже исполненная страница разборщика RUN; отдельный 256-байтный буфер не выделяется.

Нижняя программа размещается сразу по месту и может занимать память до 8FDEh включительно. В режиме MX экран загрузчиком не изменяется. RUN остаётся верхней утилитой EA00h–F3FFh; после разбора команды её первые 128 байт используются для аргументов, переходник размещается с EA80h. Эти области лежат ниже F000h и доступны в STD. Код переходника перемещаемый: внутренние адреса исправляются при установке по компактной таблице. Стек обычной программы наследуется от вызывающей стороны (штатный SP=E200h).

Только верхняя нагрузка, способная затереть RUN или старый DOS, временно читается телом с 0000h: MX допускает EA00h–F3FFh, RF — D300h–F7FFh. Для верхнего MX переходник/аргументы временно находятся по 8C00h/8E00h, стек переноса — 8F00h. Это исключение не резервирует нижние 768 байт для обычной нижней программы.

В MON/RF экран используется после загрузки и проверки тела: цвет 00h, очистка, затем чтение ядра с 9000h. Monitor-2 занимает 9000h–9FFFh, RAMFOS — 9000h–AADFh с секторным заполнением до AAFFh. Код подмены копируется с AB00h, временный стек — BF00h. Собственный копировальщик RUN не вызывает процедуры заменяемого DOS: развёртка по четыре байта, 135 тактов на полный блок при 2 МГц (без настройки/остатка).

Monitor-2 копируется в C000h–CFFFh; RAMFOS — в C000h–D2FFh и F800h–FFDFh. После подмены нет вызовов старого DOS. Инициализация Monitor-2 очищает экран, поэтому выполняется со стеком E200h и возвращается в короткий переходник EAxx; он ставит исторический стек монитора, передаёт DE со строкой аргументов и запускает программу. Её RET ведёт в холодный запуск ROM. RAMFOS сам ставит свой стек и обработчик возврата. В экранный код после инициализации ядер возврата нет.

## Проверки

`python scripts/tests/check-executable-v2.py` проверяет контейнеры на хосте. Его режим `--runtime` — отдельная проверка ABI с управлением отладчиком, не проверка интерфейса. Пользовательские команды и выбор пунктов проверяются через MCP `kbd_send`, без фокуса Windows и без записи команд в память. CPU-проверки: `scripts/tests/check-image-stream.py`, `check-run-bridge.py`, `check-checksum.py`. Материалы секторной загрузки — в локальном `docs/compat/sector-load-001/`.
