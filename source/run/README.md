# RUN.COM — запуск COM, EXE и RKS

В промежуточной компоновке BIOS/DOS от 06.11.2026 DOS находится в основной памяти по 4000h. RUN не освобождает её: нижняя программа должна помещаться до 4000h, а сменное ядро загружается через экранный буфер. Проверки отвергают пересечение с DOS. Это временное ограничение до банкового переноса; описания прежнего освобождения DOSMOD и больших диапазонов ниже относятся к старой компоновке.

С 04.11.2026 RUN.COM загружается по 0000h. Вход копирует завершающий этап в F000h–F515h (1302 байта), затем разбирает команду и показывает меню из нижней памяти. После начала загрузки нижнее тело может быть затёрто; верхний этап содержит необходимые данные и диагностику. Переходник MX/STD — 8C00h, аргументы — 8D00h; временный стек переходника 8F00h отделён от стека вызывающей стороны. Подмена Monitor-2/RAMFOS по-прежнему использует экранный буфер 9000h и переходник AB00h; продолжение после очистки экрана Monitor-2 находится по 8C00h. Приведённые ниже прежние адреса верхнего RUN являются историческими.


Проект `source/run/` заменяет LAUNCH и отдельный RAMRUN. Сборка создаёт `bin/RUN.cpu` с адресами и `bin/RUN.i80` с машинным кодом. Сборщик образа упаковывает их в `RUN.COM`. Ядро совместимости RAMFOS называется `RAMFOS.MON`; расширение SYS оставлено за DOS.

## Командная строка

Ключ `-KOI7` включает интерпретацию KOI-7 при выводе через BIOS перед входом в программу. Он независим от режима исполнения: `RUN Ball.exe -MX -KOI7` сохраняет MX и позволяет игре выводить строки в KOI-7. Ключ можно ставить до или после имени файла; он не передаётся приложению. Без него MX использует KOI-8; STD, как и прежде, включает KOI-7. При возврате через RET восстанавливается исходный KOI вызывающей программы. В MON/RF режим символов задаёт сменное ядро.

```text
A:RUN.COM -MX H:GAME.COM
A:RUN.COM H:GAME.EXE -STD
A:RUN.COM H:GAME.RKS -RF аргументы
A:RUN.COM -MON H:GAME.RKS
A:RUN.COM -MON:Monitor2 H:GAME.EXE
A:RUN.COM H:GAME.EXE
```

Слова командной строки выделяет общий `bios_argNext` DOS (C8B7h). Ключ режима можно ставить до или после имени программы, в том числе между её аргументами; регистр ключа не важен. Например, `run GAME.EXE -STD` и `run -STD GAME.EXE` равнозначны. Ключи RUN исключаются из передаваемой строки, остальные аргументы после имени сохраняют порядок (не более 127 байт, разделители — одиночные пробелы). При нескольких ключах действует последний. Короткое имя `run` без диска и расширения DOS разрешает как `A:RUN.COM`. Исходный диск восстанавливается до входа в программу: с H: команда `run BUDI-RF.exe` берёт RUN с A:, а игру с H:. Это же правило действует для остальных COM и из BAT. Явные имена с диском или расширением сохраняют прежний смысл.

| Файл без ключа | Поведение |
|---|---|
| COM | MX |
| RKS | MON |
| EXE | Меню выбора MX, STD, RF, MON или MON с запросом имени ядра |

COM и EXE имеют одинаковый 16-байтный заголовок. DOS исполняет только COM; EXE и RKS передаются RUN через `CLI.EXT`. Среда исполнения в заголовке не записывается. Для известных исключений подходят BAT с явным ключом.

## Среды

- MX сохраняет ядро MXOS2 и аппаратный режим. Программа получает DE со строкой аргументов; RET возвращает вызывающей стороне с восстановлением исходного KOI.
- STD оставляет ядро MXOS2, останавливает ВИ53, включает STD, нижнее ОЗУ, белый цвет и KOI-7. RET через нижний переходник возвращает MX и KOI-8.
- MON выполняет STD-подготовку и подменяет ядро на `A:MONITOR2.MON`. RET программы вызывает холодную загрузку MXOS2. Флаг KOI-7 MXOS после подмены не записывается: у Monitor-2 свои переменные.
- MON:имя использует указанный бинарник вместо Monitor-2. Без диска подставляется A:, без расширения — .MON. Сейчас требуется 4096 байт и совместимый пролог инициализации Monitor-2; выбор произвольного имени не означает поддержку любого ABI.
- RF загружает `A:RAMFOS.MON`, переносит обе области ядра и передаёт управление его адаптерному входу F85Ah. RET приводит к холодной загрузке MXOS2. Отдельный RAMRUN не вызывается. Файловый адаптер RAMFOS к FAT пока не реализован.

MON — сырой образ ядра без исполняемого контейнера. У RAMFOS последовательно хранятся C000h–D2FFh и F800h–FFDFh, всего 6880 байт. Правила их размещения принадлежат адаптеру RUN, а не файловому дескриптору.

## Загрузка и память

Весь файл RUN.COM загружается с 0000h. Разбор аргументов, меню, проверка заголовка и подготовка исполняются здесь; постоянного верхнего этапа F000h–F5FFh нет. RUN остаётся COM, формат контейнера не менялся.

Родной заголовок COM/EXE проверяется IMAGEOPEN; RUN получает ожидаемую сумму тела из его 16 байт. RKS разбирает только RUN: читает четыре байта начала/конца, проверяет диапазон и точное равенство size=body+6. Для окончательного чтения обоих форматов используется один MX_BIOS_FILEBODY с явными размерами header/tail: 16/0 и 4/2. Два байта хвоста RKS попадают в собственный буфер RUN; затем общий bios_calcCS проверяет тело. DOS предоставляет только обычный FileStream и не знает структуры RKS.

До чтения тела в 8D80h–8DAAh копируются 40 байт FILE_BODY_IO, ожидаемая сумма и прежний диск. Короткое 60-байтное продолжение работает с 8DB0h: загружает тело, восстанавливает диск, проверяет сумму и передаёт управление установленному переходнику. Поэтому приложение может загрузиться с 0000h и полностью затереть сам RUN. Ошибка до чтения тела выводится штатным RUN; ошибка после его затирания приводит в bootstrap, который восстанавливает BIOS/шрифт и возвращает оболочку, сохраняя готовую DOS и RAM-диск.

В MX/STD переходник установлен с 8C00h, аргументы — с 8D00h. Шрифт сохраняется; обычная программа наследует стек вызывающей стороны. Допускается также прямая загрузка верхней MX-программы в E500h–EAFFh: промежуточная копия тела с 0000h не нужна. Перед загрузкой верхней MX-утилиты RUN сокращает арену кэша до адреса её тела; при RET восстанавливает прежний конец.

В MON/RF ядро сначала читается в экранный буфер с 9000h, пока основной RUN и шрифт ещё доступны. Monitor-2 занимает 4096 байт, RAMFOS — 6880 байт. Только после успешного чтения/проверки ядра переходник подмены устанавливается на место шрифта с FONT_ADDR (D600h), а затем читается тело приложения. Дальше BIOS/DOS больше не нужны: собственный копировщик переносит Monitor-2 в C000h–CFFFh либо RAMFOS в C000h–D2FFh и F800h–FFDFh. Monitor-2 инициализируется с продолжением в 8C00h, поскольку очищает экран. Верхняя программа RF (D300h–F7FFh) сначала читается во временное нижнее ОЗУ, а переходник использует AB00h экрана: иначе тело могло бы затереть работающий BIOS или сам переходник в шрифте. После проверки выполняются только локальные копирования. Возврат MON/RF восстанавливает MXOS через bootstrap; этот запуск восстанавливает внешний шрифт, а готовая банковая DOS сохраняется.

## Проверки

`python scripts/tests/check-executable-v2.py` проверяет контейнеры на хосте. Его режим `--runtime` — отдельная проверка ABI с управлением отладчиком, не проверка интерфейса. Пользовательские команды и выбор пунктов проверяются через MCP `kbd_send`, без фокуса Windows и без записи команд в память. CPU-проверки: `scripts/tests/check-image-stream.py`, `check-run-bridge.py`, `check-file-body.py`, `check-checksum.py`. Материалы секторной загрузки — в локальном `docs/compat/sector-load-001/`.
