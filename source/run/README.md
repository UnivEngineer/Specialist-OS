# RUN 3

RUN запускает COM, EXE, RKS и самостоятельные образы мониторов. При обычном вызове DOS использует заголовок COM/EXE для выбора MAIN, BANK или DRIVER. DOS направляет в RUN файлы RKS и MON, COM/EXE с флагом 00h, а также MAIN с MODE=STD/MON/RF. DOS проверяет общие признаки заголовка. RUN читает имя монитора и проверяет совместимую нагрузку.

## Режимы

| Команда | Ядро и аппаратура | Возврат |
|---|---|---|
| `RUN H:GAME.EXE` или `RUN H:GAME.EXE -MX` | MXOS2, BIOS RAMFOS, аппаратура MX. Без ключей используется записанный MODE. AUTO выбирает резидентный RAMFOS. | Нативный COM/EXE возвращается в DOS. Совместимый COM/EXE и RKS возвращаются через C000h. |
| `RUN H:GAME.RKS -STD` | MXOS2, BIOS Monitor-2, аппаратура STD, KOI-7. | RET или JMP C000h возвращает MX и оболочку. |
| `RUN H:GAME.RKS -MON` | Полная подмена ядра штатным Monitor-2, аппаратура STD. | Reset. |
| `RUN H:GAME.RKS -MON:C:\DOS\CUSTOM.MON` | Полная подмена ядра указанным совместимым монитором, аппаратура STD. | Reset. |
| `RUN H:GAME.EXE -RF` | Полный RAMFOS из `C:\DOS\RAMFOS.MON`, аппаратура MX. | Reset. |

Параметры RUN можно ставить до и после имени программы. Регистр не важен. Из нескольких ключей выбора режима действует последний. Явный ключ имеет приоритет над MODE, при AUTO используется RAMFOS/MX. RUN передаёт остальные аргументы приложению в исходном порядке, до 127 байт с одиночным пробелом между словами. `-KOI7` задаёт кодировку BIOS MXOS2 для MX, ключи подмены оставляют кодировку сменному ядру. В режиме STD используется KOI-7. BANK и DRIVER требуют файловых служб MXOS2 и допускают только штатный запуск.

`-MON:файл` переопределяет назначенный монитор. Для имени без диска используется `C:\DOS\`, для имени без расширения добавляется `.MON`. Для запуска приложения подходят образы Monitor-2 с совместимым прологом инициализации, длиной 4096 байт. `RUN C:\DOS\MONWIN.MON` и другие команды с единственным файлом MON запускают собственную оболочку образа и поддерживают также штатный оконный монитор длиной 8192 байта. Полный RAMFOS содержит две области размером 6880 байт. Тело сменного ядра копируется без патчей.

## Заголовок и упаковка

У COM/EXE фиксированный 32-байтный заголовок v2. В байте 1Dh находится длина назначенного монитора, 0 для старых и обычных файлов. Имя занимает от 1 до 63 байт ASCII и идёт за телом, за ним следует 16-битная штатная контрольная сумма имени. Поле MODE содержит MON. Адрес тела, его размер и его контрольная сумма сохраняют прежний смысл. BANK, DRIVER, DLL, FNT и перемещаемый формат v3 не используют этот хвост.

Сборщик берёт имя из третьей строки пары CPU/I80. Имена `MONITOR2.MON` и `MON2.MON` распознаются автоматически. Для стороннего имени указывайте `MODE=MON`, файл должен быть доступен на гостевом томе. Сборщик сохраняет прежние эмуляторные имена как подсказку CPU, если нет явного назначения. Старые фиксированные контейнеры продолжают читаться. MODE=STD выбирает совместимый BIOS Monitor-2, MODE=MON без имени выбирает штатный Monitor-2, MODE=RF выбирает полный RAMFOS.

```text
1000
1000
C:\DOS\CUSTOM.MON
FLAGS=00
MODE=MON
```

## Загрузка и память

Для обычного COM/EXE RUN передаёт пакет FILE_EXEC_NATIVE через текущий служебный стек. DOS копирует командную строку в системную область до чтения тела, а возврат обрабатывает резидентный BIOS. Свободная память MAIN заканчивается на 8DFFh, границу снижают занятые системные резервы и текущая конфигурация шрифта. Стек имеет собственную область с 8E00h.

Для совместимого запуска RKS и для явных STD/MON/RF загрузчик временно занимает 8C00h–8DFFh и проверяет диапазон тела, заявленную память, стек и активных владельцев. Для RKS используются стандартные 4 байта заголовка, тело и 2 байта суммы. Для COM/EXE проверяется заголовок до чтения тела. Именованный хвост проверяется отдельно. Для обычного MX и STD аргументы передаются из системной строки, продолжение после RET — резидентный вход C000h.

Для полной подмены ядра его файл проверяется до передачи управления. Буфер ядра находится в скрытом экране с 9000h. Верхнее приложение RAMFOS с D300h–F7FFh читается во временную нижнюю область и переносится перед запуском. Код сменного ядра и его стек отделены от загружаемого приложения. RET ведёт в оболочку сменного ядра. Для восстановления MXOS2 после подмены нужен Reset.

Хостовые сценарии упаковки проверяются командами `python scripts/tests/check-executable-v2.py` и `python scripts/tests/check-executable-ps.py`. Проверка запуска выполняется через NC в видимом Emu80. Карту системы задаёт [system-layout.inc](../common/system-layout.inc).
