# Monitor-2

Самостоятельное ядро для STD-режима, загружаемое `RUN.COM -MON` по адресу
`C000h`. Это Monitor-2 из `assets/programs/Monitor2.mon`, а не отладчик
`source/debug/Debug.asm`. Размер — 4096 байт, диапазон `C000h–CFFFh`.

Исходник восстановлен из бинарника без изменения байтов:

- `Monitor2.asm` — адрес загрузки, порядок модулей и контроль границ;
- `loader.inc` — загрузчик, экран, клавиатура, магнитофон, таблица клавиатуры;
- `font.inc` — исторический знакогенератор `C500h–C7FFh`;
- `monitor.inc` — таблица входов `C800h`, команды монитора, строки;
- `originals/Monitor2.mon` — неизменяемый эталон, скопированный из проекта.

SHA-256 эталона:
`e8eabdee87cbbb679f0d6e7c30bcdb2e48a793fc0a7938d8d9411f8bcaa9555a`.
Существующий файл `assets/programs/Monitor2.mon` также сохранён без изменений.
Код представлен командами 8080 в синтаксисе SjASMPlus, данные — `DB`;
бинарник не подключается через `INCBIN`. Имена неизвестных переходов содержат
исторический адрес. Это дизассемблирование, а не найденный авторский исходник.

## Происхождение

В архиве `D:\Projects\RetroPC\Specialist` найдена побайтно идентичная копия:
`OS/RAMFOS-master/RomDisk/Monitor2.49152.sys`.
Верхние 2048 байт (`C800h–CFFFh`) точно совпадают с `monitor2_2.rom` из
`specialist-mx.org/Soft/monitor2_2.rar`; архив также содержит документ Word.
Варианты `monitor2_1.rar`, `monitor2_3.rar`, `col_monitor2.rar`,
`MySoft/Monitor-original/Combined.BIN`, ассемблерные тексты
`Soft/Lafan/LafanS2/Monitory/Moni_B2/` и дизассемблированный
`MySoft/Monitor-windows/monitor_win.asm` относятся к другим версиям.

## Сборка и проверка

Задача VS Code: **build: monitor2**. Из `source/monitor2`:

```powershell
powershell.exe -NoProfile -File ../../scripts/build/build-if-needed.ps1 Monitor2 mon 0xC000
```

Результат: `bin/Monitor2.mon`, `bin/Monitor2.lst`, `bin/Monitor2.sym`.
Компонент включён в `build: OS` и `build: all`; манифест системного ROM берёт
`MONITOR2.MON` из `bin/Monitor2.mon`.

Сборочный скрипт проверяет SHA-256 сохранённого эталона, затем длину и каждый
байт результата. Несовпадение даёт ошибку с ненулевым кодом завершения и
адресом первого отличия. Проверка выполняется также для `up-to-date`.
Для намеренного изменения Monitor-2 потребуется отдельно пересмотреть этот
контракт; перезаписывать оригинал для прохождения проверки нельзя.

Из корня проекта:

```powershell
python scripts/tests/check-monitor2-build.py
```

Тест проверяет совпадение, отказ при изменённом байте и укороченном бинарнике,
после чего восстанавливает результат. Для повторного дизассемблирования:
`python scripts/monitor2/disassemble.py`; генератор проверяет хеш эталона и
перезаписывает три `.inc`, поэтому перед запуском нужно сохранить их ручные
изменения.

## Особенности образа

Начало `C000h` уже содержит историческую адаптацию: извлечение адреса со стека,
запись A в `FFFFh`, установка SP и запись `03h` в STD-регистр `F7FAh`.
Начальные переменные `C473h–C493h` копируются в `8FDFh–8FFFh`;
этот диапазон одновременно содержит процедуру `C488h`.
Байты `C454h–C459h` сохранены как остаточные данные без установленного входа.
Обращения к ВВ55 остаются по `FF00h–FF03h`, таблица клавиатуры — `C4A0h`.
Таблица переходов и подэкранные переменные принадлежат Monitor-2 и не должны
подменяться определениями ABI MXOS. Запуск и возврат выполняет `source/run`.

Побайтное совпадение подтверждает сохранение существующего поведения;
оно не является новой проверкой магнитофона, таймингов или реальной платы.
