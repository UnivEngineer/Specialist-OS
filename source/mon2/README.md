# MON2.COM — монитор памяти MXOS

Разбор текущей реализации на 24.10.2026. Историческая инструкция находится в
[главном README](../../README.md), запись от 18.02.2022. `MON2.COM` с адресом
`0F100h` работает поверх DOS. Это **другая программа**, чем `MON2.MON`, который
`LAUNCH.COM` загружает по `0C000h` для запуска RKS в STD-режиме.

## Исходники и сборка

| Файл | Назначение |
|---|---|
| `mon2.asm` | Подключение ABI и порядок модулей |
| `state.inc` | Структуры переменных, буферы и размещение |
| `command.inc` | Приглашение, ввод и диспетчер директив |
| `disk.inc` | Выход, каталог, дисковые операции, ввод имени |
| `debug.inc` | Чтение ленты, снимок регистров, запуск и точка останова |
| `memory.inc` | Поиск, заполнение, копирование, сравнение, контрольная сумма, текстовый дамп |
| `input.inc` | Разбор команды и HEX-параметров |
| `console.inc` | Побайтовый редактор, HEX-ввод, пауза, HEX-дамп |
| `legacy.inc` | Неиспользуемый старый обмен и общий ввод строки |
| `vectors.inc` | Фиксированная таблица переходов `0F800h` |

Порядок включения сохраняет адреса и проходы между процедурами. Внутренние
`LBL*`, `SUB*`, `REF*` и адресные имена полей заменены осмысленными именами.
У полей без обращений в текущем коде оставлено явное обозначение `Reserved`;
назначение таких областей не выдумывалось. Метки директив и именованные
совместимые точки сохранены.

Из корня репозитория:

```powershell
powershell.exe -NoProfile -File scripts/build/build-project.ps1 OS
```

Исторические `mon2-orig.asm` и `mon2-orig.0xF100.com` находятся в `originals/`.
В ASM переименованы 145 внутренних символов; для общих участков использованы
те же имена, что и в текущем мониторе. Машинный код, данные и адреса сохранены,
эталонный COM не изменён. Из `source/mon2` оригинал собирается так:

```powershell
../../tasm/sjasmplus.exe --i8080 -Wno-rdlow --inc=. --raw=../../bin/mon2-original.com originals/mon2-orig.asm
```

Команда сохраняет работоспособность старого INCLUDE и побайтно воспроизводит
приложенный исторический COM. Оригинал не участвует в штатной сборке.

## Синтаксис и директивы

Форма команды: `D1000,10FF`, затем Enter. Все числа шестнадцатеричные,
без суффикса `h`, пробелов и префикса `0x`. Буквы директив и цифры A–F в
командной строке должны быть заглавными. Отсутствующий числовой параметр равен
нулю; значения длиннее четырёх HEX-цифр обрезаются до младших 16 бит.
Командная строка допускает 32 символа; запрос имени файла использует другой
предел — 13 символов, поэтому полное `A:12345678.TXT` из 14 символов не помещается.

В таблице `нач`, `кон`, `адр` — адреса, `байт` берётся из младшего байта
параметра. Для большинства блочных операций `кон` включается в обработку;
исключения и ошибки поиска S указаны отдельно.

| Команда | Действие |
|---|---|
| `Gадр[,стоп]` | Вызвать программу по адресу, необязательно установить одноразовый останов |
| `Dнач,кон` | HEX-дамп с выравниванием по 16 байтам и разделителем после восьмого байта |
| `Lнач,кон[,маска]` | Текстовый дамп по 16 байтов; ненулевая маска AND применяется перед фильтрацией |
| `Mадр` | Побайтовое редактирование памяти; второй параметр не ограничивает проход |
| `Tнач,кон,адр` | Копировать вперёд в новый адрес; опасно при перекрытии с назначением выше источника |
| `Fнач,кон,байт` | Заполнить память байтом |
| `Cнач,кон,адр` | Сравнить блоки; печатать различия: адрес, исходный байт и байт второго блока |
| `Sнач,кон,б1[,б2[,б3[,б4]]]` | Искать последовательность из 1–4 байтов, печатать адрес и контекст |
| `Nнач,кон,байт` | Вывести адреса и значения байтов, отличающихся от указанного |
| `X` | Показать снимок регистров последнего сработавшего останова |
| `Hчисло1,число2` | Напечатать сумму и разность по модулю 65536 |
| `Kнач,кон` | Рассчитать и напечатать контрольную сумму BIOS |
| `Wнач,кон` | Историческая запись блока на ленту без имени |
| `R[смещение]` | Историческое чтение с ленты через BIOS; числовой параметр передаётся в HL |
| `J` | Дождаться отпускания клавиши и выйти в оболочку |
| `?` | Вывести полученную часть каталога: имя, адрес загрузки, вычисленный конечный адрес |
| `Vадр` | Запросить имя и загрузить дисковый файл по указанному адресу |
| `U` | Запросить имя и загрузить файл по адресу из дескриптора |
| `Bнач,кон` | Запросить имя и записать блок в файл |
| `Aадр` | Запросить имя и установить адрес загрузки файла |
| `Q` | Запросить имя и вывести байт атрибутов |
| `Yбайт` | Запросить имя и установить младший байт атрибутов |
| `A:` … `H:` | Переключить диск; наличие драйвера отдельно здесь не проверяется |

У R точная семантика смещения зависит от установленного магнитофонного
обработчика: локального кода загрузки здесь нет. Магнитофон сознательно вынесен
из DOS, штатная утилита для работы с ним — отдельно загружаемая `TAPE.COM`.
Наличие W/R и векторов F806/F80C не устанавливает драйвер автоматически.

В M клавиша ↓ пропускает байт, ← возвращается к предыдущему, две HEX-цифры
записывают новый байт и передвигают адрес вперёд. Строчные a–f здесь принимаются
отдельным обработчиком, в отличие от командной строки. СТР возвращает
приглашение. Это редактор без защиты системной памяти и границ блока.

Дампы и длинные выводы проверяют СТР в контрольных точках: первое нажатие
позволяет остановить вывод, следующее СТР прекращает команду, другая клавиша
продолжает. Проверка не выполняется после каждого байта каждой директивы.

## Что уточнить по сравнению с исторической инструкцией

- `?` выводит **два адреса**, а не адрес и размер: второе число получается
  сложением адреса загрузки с 16-битным полем размера. Аналогично V и U.
  Формат размера DOS исторически неоднороден, поэтому это именно вычисленное
  значение кода, а не обещание стандартного включительного конца файла.
- `L` имеет третий параметр-маску, но после него пропускает только коды
  `20h–7Eh`. Кириллица KOI-8 заменяется точками; маска `7F` может сделать
  некоторые старшие коды видимыми как ASCII. Нулевая маска означает отсутствие
  маскирования, а не обнуление каждого байта.
- `S` принимает несколько отдельных HEX-байтов; строкового синтаксиса нет.
  После совпадения поиск продолжает с конца найденной последовательности,
  поэтому перекрывающиеся совпадения пропускает. Начало, равное `кон`,
  не проверяется; сравнение хвоста образца может выйти за `кон`.
  Число байтов свыше четырёх не отвергается и приводит к чтению соседних
  переменных вместо корректного образца.
- У `T` не всякое перекрытие портит результат. Копирование вперёд безопасно
  при назначении ниже источника и при совпадении адресов; опасен перекрывающийся
  блок назначения выше источника.
- `X` показывает сохранённые значения после сработавшего `G...,стоп`,
  а не регистры во время исполнения команды X. До первого останова поля
  не инициализируются. Надпись `M(HL)=` ошибочна: под ней печатается само
  сохранённое **HL**, а не байт памяти по HL. `PC=` — адрес установленного
  останова, `SP=` — SP перед выполнением RST.
- `G` запускает через CALL и косвенный `JP (HL)`, так что обычный RET программы
  возвращает приглашение. После останова продолжить программу с восстановлением
  регистров нельзя. Второй параметр `0000` означает отсутствие останова.
- Каталог читается одним вызовом `bios_fileList`; дозагрузки следующей части
  нет. При текущей карте памяти буфер ограничен 143 записями. Для больших
  каталогов нельзя считать показанный список полным.

### Дисковые ограничения, видимые в коде

`Dir_B` помещает в младшее слово размера `кон - нач`, без прибавления единицы,
а старшее слово 32-битного размера не обнуляет. Дескриптор по `0F900h` явно
не инициализируется целиком: там могут остаться прежние данные. Это сохранённый
код работы с историческим форматом, а не корректная универсальная реализация
длины файла. V/U также используют только младшее слово при показе адресов.

V/U не проверяют, попадёт ли загружаемый файл в экран, код монитора, стек,
кэш или аппаратную область. Чтение DOS полносекторное. Диапазоны нач/кон для
блочных операций не проверяются на порядок: при `нач > кон` обход может
пройти через `0FFFFh` и затронуть почти всё адресное пространство.

Ввод буквы диска обнаруживается через `bios_fileNamePrepare` и изменение
текущего диска **до разбора директивы**. В запросе имени файла буква диска
также может изменить текущий диск. Поэтому это не изолированный параметр
одной файловой операции.

## Самомодификация и останов без патча программы

MON2 не использует перезапись собственных операндов для хранения состояния,
в отличие от E. Существенная модификация исполняемого кода находится в
`installBreakpoint`:

1. Старый байт по адресу останова сохраняется в `BreakpointOriginalByte`;
   вместо него пишется `0FFh` — инструкция 8080 `RST 7`.
2. Три байта `0038h–003Ah` сохраняются в `SavedRst7Vector`, вместо них пишется
   `JP breakpointTrap`.
3. `breakpointTrap` сохраняет регистры, возвращает исходный байт и вектор,
   затем перезапускает командный цикл. Состояние программы для продолжения
   исполнения не восстанавливается.

Это стандартный принцип программной точки останова для 8080, а не скрытая
переменная в команде. Но реализация имеет ограничения: адрес должен быть
доступен для записи; правильность записи не проверяется; если программа
вернулась, не дойдя до останова, байт и вектор остаются изменёнными. Нельзя
ставить точку внутри `0038h–003Ah` или в коде/данных самого монитора.

Для произвольного неизменяемого бинарника прозрачный останов по адресу
**невозможен на базовом 8080** без аппаратной/эмуляторной поддержки либо
программной интерпретации. Практичные варианты:

- В отлаживаемых исходниках заранее размещать `CALL debugTrap` в выбранных
  местах. Обработчик сохраняет регистры и читает адрес возврата из стека;
  вектор RST и байты загруженной программы во время исполнения не меняются.
  Символ обработчика связывается при сборке, новый DOS ABI для этого не нужен.
- Для готовых бинарников использовать точки останова отладчика emu.
  На реальном оборудовании это требует соответствующего отладочного расширения.
- Сохранить RST-подход как отдельный режим отладки, но добавить флаг активного
  останова и общую очистку при обычном RET, рестарте, ошибке и выходе J.
  Это улучшит восстановление, хотя патч программы останется.

Всё это предложения; текущий механизм G при рефакторинге сохранён побайтно.

## Таблица F800h и остатки старого кода

Таблица `0F800h–0F835h` — локальные совместимые обёртки над точками DOS,
часть используется самим монитором. `0F821h` — заглушка RET с двумя NOP.
По `0F836h` начинается четырёхбайтная обёртка печати слова HL. Без внешнего
исторического источника происхождение ABI (Орион, Ramfos и т. п.) установить
по этому коду нельзя; совместимость с конкретной системой не заявляется.
Адреса таблицы при разбиении сохранены.

В `legacy.inc` остались недостижимые через именованные вызовы процедуры
старого обмена, использующие `0F0E5h–0F0E7h` как память. Это не текущие порты
ВВ55 по `0FFE4h–0FFE7h`. Удалять такие байты без проверки внешних прямых
вызовов и прежнего бинарного формата при этом разборе не стали.

## Проверка рефакторинга

Переименованы 83 внутренних символа, выделены девять модулей. Размер
`bin/mon2.com` до и после — **1850 байтов**, диапазон `0F100h–0F839h`.
Переход к `ORG_PAD0 0F800h` и таблица совместимости сохранены.
SHA-256 до и после:

```text
6d0a390e4980b139aa8827953de20f18efe56db97569011209272ee28c5a252e
```

Сравнены адреса всех 406 прежних символов, включая поля структур и BIOS ABI,
с учётом переименования: расхождений нет. При проверке старой карты памяти
`NEW_MEMORY_MAP = 0` обнаружена существовавшая **до рефакторинга** ошибка
сборки: `FILE_DESCRIPTOR_SIZE` не определён. Обе версии исходника дают одну
и ту же ошибку; эта неиспользуемая сейчас ветвь не исправлялась.

Использован SjASMPlus `--i8080 -Wno-rdlow`, текущий вариант собирается без
ошибок и предупреждений. Проверены листинг, сборка OS, подготовка листингов
для emu; пересобранный `images/SystemRom_emulator.bin` побайтно не изменился.
Разбор поведения статический: интерактивный прогон emu и реальное оборудование
не проверялись. Обнаруженные ограничения сохранены для отдельного исправления.
