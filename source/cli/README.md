# Командный интерпретатор MXOS

CLI.COM — самостоятельная консоль с загрузкой с 0000h. Общий обработчик команд находится в DOSMOD.COM и доступен консоли, NC и BAT. NC по F10 переключается в CLI с активными диском и каталогом; `CLI` в командной строке запускает ту же консоль. `NC` открывает панели, `EXIT` возвращает из CLI в NC. После обычного завершения внешней программы выбранная оболочка загружается заново; текущие каталоги, выбранный диск CLI и PATH сохраняются в DOS.

## Команды

| Команда | Назначение |
|---|---|
| DIR [путь] | Последовательный список файлов и каталогов без ограничения панели NC в 255 записей |
| CD, CHDIR [путь] | Смена каталога, включая диск в пути; без аргумента — текущий путь |
| PWD | Текущий абсолютный путь |
| A: … H: | Выбор диска с сохранённым для него каталогом |
| MD, MKDIR путь | Создание одного каталога с записями `.` и `..` |
| RD, RMDIR путь | Удаление пустого каталога; корень и текущий каталог защищены |
| COPY источник назначение | Копирование одного файла; назначением может быть существующий каталог |
| MOVE источник назначение | Внутри тома — перенос записи каталога без изменения FAT и данных; между томами — копирование и удаление источника |
| REN, RENAME источник имя | Переименование файла в том же каталоге; существующее назначение не перезаписывается |
| DEL, ERASE файл | Удаление файла с обычной проверкой атрибутов |
| ATTRIB [+-R] [+-H] [+-S] [+-A] путь | Чтение или изменение атрибутов файла/каталога; без масок — вывод RHSA |
| TYPE файл | Вывод точного содержимого файла через поток DOS |
| PATH [каталоги] | Список поиска через `;`; без аргумента — вывод, `PATH ;` — очистка |
| CLS | Явная очистка экрана |
| ECHO текст | Вывод текста |
| REM текст | Комментарий |
| HELP | Список команд |
| EXIT | Возврат из консоли в NC |

Имена файлов и каталогов — 8.3; пути до MAX_PATH=128 байт с нулевым терминатором. Оба разделителя `/` и `\` допустимы. `CD H:\Games` меняет и диск, и каталог; отдельного обязательного `/D`, как в cmd.exe, нет. COPY обходит вложенные каталоги, MOVE переносит каталог внутри тома изменением записей и `..`, а между томами копирует дерево и удаляет успешно перенесённые источники. Перенос и копирование в собственное поддерево запрещены. Эти операции не транзакционны: при ошибке уже созданные копии сохраняются. Создание родителей через `/P`, шаблоны `*`/`?`, рекурсивное DELETE и расширение заполненной кластерной цепочки каталога пока не реализованы. Ошибки возвращаются числовыми кодами DOS. COPY сохраняет атрибуты источника; защищённая копия также защищена от удаления.

## Поиск и ассоциации

Голое имя ищется в текущем каталоге, затем в каталогах PATH. В каждом каталоге проверяются COM, EXE, BAT в этом порядке. Явное расширение сохраняется, а голое `FORMAT.COM` также может быть найдено через PATH. Явно указанные диск или разделитель пути отключают поиск по PATH. Начальный PATH — `A:\`; собственное значение задаётся командой, например `PATH A:\;B:\TOOLS`, в том числе в AUTOEXEC.BAT. PATH хранится в отдельном 128-байтном буфере резидентного DOS и не читается с диска при поиске. Перезагрузка DOSMOD/CLI не сбрасывает его.

Системный файл `A:\CLI.EXT` заменяет NC.EXT. Формат: трёхбуквенное расширение, пробел и команда, завершённая CR или CR/LF. По умолчанию TXT вызывает E.COM, RKS и EXE — RUN.COM. Ассоциация имеет приоритет над прямым запуском. Если ассоциации для EXE нет, DOS выполняет его напрямую тем же загрузчиком и с теми же проверками заголовка, размеров и сумм, что COM. RKS остаётся контейнером RUN, ядро DOS его не разбирает. Содержимое CLI.EXT не кэшируется между командами; временный буфер модуля вмещает файл меньше 512 байт.

## ABI и память

`bios_cli=C8E1h`: A=операция, HL/DE=параметры. COMMAND=0 принимает строку команды, возвращает A=0/CF=0 при успехе, A=FFh/CF=0 для внешней команды, иначе CF=1/A=код DOS; B содержит бит 0 «есть вывод», бит 1 «выход из консоли» и бит 2 «команда CD или смена диска». COPY=1 принимает HL=FILE_COPY_REQUEST с явными адресом и размером буфера; RENAME=2 — HL/DE=короткие имена на текущем томе; DELETE=3 — HL=имя; MKDIR=4, CHDIR=5, RMDIR=6 — HL=путь MAX_PATH. MOVE=7 принимает FILE_COPY_REQUEST: при переносе внутри тома buffer/bufferSize не используются; между томами действуют проверки COPY. QUERY=8 разбирает команду без исполнения и возвращает те же биты B, A=FFh для внешней программы. Эти формы использует NC без сборки двух длинных путей в одну команду. Копирование сохраняет исторические значения A=FILE_OP_* и подробный код через bios_getError.

`bios_fileExec=C85Dh` выполняет встроенную команду либо общий поиск/ассоциацию и загрузку внешней программы. `bios_setShell=C8E4h`: A=0 выбирает NC, A=1 выбирает CLI и запоминает её текущий диск, A=2 возвращает сохранённый диск CLI. AF/BC/DE/HL разрушаются, если конкретный контракт не задаёт сохранение. Вызовы DOS не реентерабельны.

DOSMOD загружается с 6700h до 8BFFh; его прежний заголовок остаётся по 8000h и плотная таблица JMP — с 8010h. Код CLI и его временные буферы находятся перед заголовком. Штатный memtop с модулем — 66FFh. NC, E и DEBUG соблюдают эту границу. Стек и переходники не перемещены. Неродные программы могут явно освободить DOSMOD, как прежде. BAT читает временные данные только ниже 6700h; предел размера сценария — меньше 26 КБ. Полноценные IF/GOTO/CALL, вложенные BAT, параметры `%1` и перенаправления потоков ещё не добавлены.

CLI выводит KOI-8 и не очищает экран при перезагрузке после программы. Консольные утилиты продолжают вывод с текущей позиции, явно включают KOI-8 и восстанавливают прежний режим при обычном возврате. Очистка панелей при F10 выполняется NC; очистка экрана пользователем доступна через CLS.

`bios_fileGetSetAttr=C857h`: HL указывает на 11 байтов имени FAT 8.3 в текущем каталоге; C=0 читает атрибуты, C=1 записывает B. A возвращает итоговые атрибуты, CF=1 означает ошибку, подробный код доступен через bios_getError; BC/DE/HL сохраняются. Меняются R/H/S/A (маска 27h), признак каталога DIR сохраняется. VOLUME и зарезервированные биты 6/7 отклоняются. Перед вызовом с полным путём используйте fileNamePrepare. ATTRIB не поддерживает шаблоны и рекурсивный обход; при повторном указании одного бита действует последняя маска.

CLI.COM содержит приглашение, цикл ввода и отображение ошибок; он вызывает общий обработчик DOSMOD через ABI. Редактор `source/include/lineedit.inc` включается в CLI и NC при сборке, не занимает резидентную область DOS и не имеет фиксированной системной точки входа. Вставка, Backspace, Home/End, стрелки и горизонтальное окно работают одинаково в консоли и диалогах. В NC пустая строка оставляет стрелки панели; при непустой строке влево/вправо двигают текстовый курсор, вверх/вниз — к началу/концу текста. Escape в консоли очищает строку, в диалоге отменяет ввод.

NC предварительно вызывает QUERY: команды без вывода сохраняют панели и тулбар; CD и смена диска обновляют только активную файловую панель, а информационная панель при необходимости обновляется вслед за ней; DIR, TYPE, ECHO и другие команды с выводом временно скрывают панели. Внешние программы запускаются хвостовым переходом в DOS: они могут затереть NC, поэтому после завершения оболочка загружается заново. TYPE передаёт байты в BIOS без преобразования окончаний строк: LF переводит строку, CR возвращает курсор в её начало.

Повторный loadDosModule при установленном модуле не читает диск. Для повторной загрузки после использования его памяти требуется releaseDosModule. Обычные приложения соблюдают memtop; RUN освобождает модуль перед загрузкой несовместимой программы.

`DIR A:` выводит текущий каталог диска A:, сохраняя выбранные диск и каталог приглашения; `DIR A:\` явно выбирает корень. Один префикс `A:` допустим и в CD: он переключает на сохранённый текущий каталог этого диска.

Стрелки вверх/вниз в самостоятельном CLI перебирают историю последних 32 непустых команд, включая команды с ошибкой. Последовательные одинаковые команды занимают одну запись. При первом нажатии вверх сохраняется набираемый черновик; спуск ниже последней команды возвращает его. Вызванную команду можно редактировать обычными клавишами, Escape очищает строку и возвращает навигацию к концу истории. Буферы истории находятся в CLI.COM: 4096 байт записей MAX_PATH и 128 байт черновика, ядро DOS их не хранит. Перед внешней программой и EXIT история сохраняется в скрытый файл `B:\CLI.HST`, при загрузке CLI восстанавливается. На обычные встроенные команды запись истории на диск не выполняется. Если B: недоступен или заполнен, работа CLI продолжается с историей текущего запуска. Формат файла проверяется по сигнатуре, размеру, индексам и терминаторам строк.

При CLI_OP_COMMAND в DE передаётся адрес обработчика совпадений COPY (0 — возвращать EXISTS). CLI.COM и NC предоставляют свои обработчики Yes/No; внутренний исполнитель BAT использует 0. Совпадающие каталоги объединяются, решение о замене принимается для каждого файла. No оставляет назначение и источник без изменений, в том числе при MOVE между томами. Тексты DOS_ERR подключаются из `source/include/errors.inc` только в приложения.

`CLI_OP_OBSERVER=9`, HL=адрес обработчика или 0 для отключения, устанавливает наблюдатель изменений общих файловых операций DOSMOD. Перед возможной записью обработчик получает A=номер диска, DE=кластер каталога, C=0 для точного каталога либо C=1 для тома целиком (изменение пути каталога). В обработчике нельзя вызывать DOS/CLI. Он принадлежит приложению и должен быть отключён до его выгрузки; все регистры/флаги вокруг уведомления сохраняются модулем. После отказа I/O изменения могли быть частичными, поэтому уведомление консервативно выдаётся перед записью. Обычные чтения и ответ No не порождают уведомлений. Прямые резидентные файловые вызовы вне общего CLI этим наблюдателем не охватываются.

Единый префикс ключей системных программ — `-`, как в RUN и FORMAT; регистр ключей несущественен, `/` и `\` остаются разделителями пути. Для COPY/MOVE запланированы `-Y` (перезаписывать), `-N` (пропускать совпадения), `-I` (спрашивать). Эти ключи пока не разбираются; текущий интерактивный COPY/межтомовый MOVE использует Yes/No, а внутренний исполнитель BAT при конфликте возвращает EXISTS без перезаписи. REN и MOVE внутри тома пока отклоняют занятое имя.

Обработчик совпадений COPY теперь допускает A=2 (Yes to all) и A=3 (No to all), кроме A=0/1. Решение сохраняется только на время текущего запроса, включая всё дерево; новый запрос сбрасывает его. В CLI ответам соответствуют Y/N/A/S (Yes/No/All/Skip all). Режим No to all пропускает только уже существующие файлы: отсутствующие файлы продолжают копироваться.
