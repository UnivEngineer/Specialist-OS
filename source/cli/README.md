# Командный интерпретатор MXOS

CLI.COM — самостоятельная консоль с загрузкой с 0000h. Общий обработчик команд находится в DOS.SYS и доступен консоли, NC и BAT. NC по F10 переключается в CLI с активными диском и каталогом; `CLI` в командной строке запускает ту же консоль. `NC` открывает панели, `EXIT` возвращает из CLI в NC. После обычного завершения внешней программы выбранная оболочка загружается заново; текущие каталоги, выбранный диск CLI и PATH сохраняются в DOS.

## Команды

| Команда | Назначение |
|---|---|
| DIR [путь] | Последовательный список файлов и каталогов без ограничения панели NC в 255 записей |
| CD, CHDIR [путь] | Смена каталога, включая диск в пути; без аргумента — текущий путь |
| PWD | Текущий абсолютный путь |
| A: … H: | Выбор диска с сохранённым для него каталогом |
| A:\ … H:\ | Переход в корень диска; допускается также `/` вместо `\` |
| MD, MKDIR путь | Создание одного каталога с записями `.` и `..` |
| RD, RMDIR путь | Удаление пустого каталога; корень и текущий каталог защищены |
| COPY источник назначение | Копирование одного файла; назначением может быть существующий каталог |
| MOVE источник назначение | Внутри тома — перенос записи каталога без изменения FAT и данных; между томами — копирование и удаление источника |
| REN, RENAME источник имя | Переименование файла в том же каталоге; существующее назначение не перезаписывается |
| DEL, ERASE путь | Удаление файла или дерева с обычной проверкой атрибутов |
| ATTRIB [+-R] [+-H] [+-S] [+-A] путь | Чтение или изменение атрибутов файла/каталога; без масок — вывод RHSA |
| TYPE файл | Вывод точного содержимого файла через поток DOS |
| PATH [каталоги] | Список поиска через `;`; без аргумента — вывод, `PATH ;` — очистка |
| CLS | Явная очистка экрана |
| ECHO текст | Вывод текста |
| PAUSE | Приглашение и ожидание одной клавиши |
| REM текст | Комментарий |
| HELP | Список команд |
| EXIT | Возврат из консоли в NC |

Имена файлов и каталогов — 8.3; пути до MAX_PATH=128 байт с нулевым терминатором. Оба разделителя `/` и `\` допустимы. `CD H:\Games` меняет и диск, и каталог; отдельного обязательного `/D`, как в cmd.exe, нет. COPY обходит вложенные каталоги, MOVE переносит каталог внутри тома изменением записей и `..`, а между томами копирует дерево и удаляет успешно перенесённые источники. Перенос и копирование в собственное поддерево запрещены. Эти операции не транзакционны: при ошибке уже созданные копии сохраняются. MKDIR создаёт недостающих родителей, DIR и COPY/MOVE поддерживают маски последнего компонента. DEL/ERASE рекурсивно удаляют каталог; RD/RMDIR требует пустой каталог. Ошибки возвращаются числовыми кодами DOS. COPY сохраняет атрибуты источника; защищённая копия также защищена от удаления.

## Поиск и ассоциации

Голое имя ищется в текущем каталоге, затем в каталогах PATH. В каждом каталоге проверяются COM, EXE, BAT в этом порядке. Явное расширение сохраняется, а голое `FORMAT.COM` также может быть найдено через PATH. Явно указанные диск или разделитель пути отключают поиск по PATH. Начальный PATH — `C:\DOS`; собственное значение задаётся командой, например `PATH C:\DOS;B:\TOOLS`, в том числе в AUTOEXEC.BAT. PATH хранится в отдельном 128-байтном буфере резидентного DOS и не читается с диска при поиске. Перезагрузка DOS/CLI не сбрасывает его.

Системный файл `C:\DOS\CLI.EXT` задаёт команды по расширению. Формат строки — трёхбуквенное расширение, пробел, команда и CR или CR/LF. В штатном образе TXT вызывает EDIT.COM, RKS и MON вызывают RUN.COM, FNT вызывает FONT.COM. COM/EXE загружает DOS. Для совместимости с другой средой RUN вызывается явно. Повреждённые заголовки и недопустимые флаги дают ошибку формата.

Флаг IMAGE_FLAG_BANK выделяет отдельный EXEC-банк через механизм модулей. DE указывает на локальную строку аргументов. RET возвращает управление и освобождает банк, дочерние модули и собственные FAR-блоки приложения. Для программного запуска по точному имени существует FILE_EXEC_NATIVE. DLL загружаются через MODULE_LOAD и MODULE_CALL. RKS разбирает RUN. CLI.EXT читается заново между командами и должен быть меньше 512 байт.

## ABI и память

`MXOS_CALL MXOS_DOS_CLI`: A=операция, HL/DE=параметры. COMMAND=0 принимает строку команды, возвращает A=0/CF=0 при успехе, A=FFh/CF=0 для внешней команды, иначе CF=1/A=код DOS; B содержит бит 0 «есть вывод», бит 1 «выход из консоли» и бит 2 «команда CD или смена диска». COPY=1 принимает HL=FILE_COPY_REQUEST с явными адресом и размером буфера; RENAME=2 — HL/DE=короткие имена на текущем томе; DELETE=3 — HL=имя; MKDIR=4, CHDIR=5, RMDIR=6 — HL=путь MAX_PATH. MOVE=7 принимает FILE_COPY_REQUEST: при переносе внутри тома buffer/bufferSize не используются; между томами действуют проверки COPY. QUERY=8 разбирает команду без исполнения и возвращает те же биты B, A=FFh для внешней программы. Эти формы использует NC без сборки двух длинных путей в одну команду. Копирование сохраняет исторические значения A=FILE_OP_* и подробный код через bios_getError.

`bios_fileExec=C85Dh` выполняет встроенную команду либо общий поиск/ассоциацию и загрузку внешней программы. `MXOS_CALL MXOS_DOS_SET_SHELL`: A=0 выбирает NC, A=1 выбирает CLI и запоминает её текущий диск, A=2 возвращает сохранённый диск CLI, A=3 возвращает выбор оболочки в A (0=NC, 1=CLI). Выбор хранится в v_shell банка DOS и сохраняется при программном возврате C000h/C800h и аппаратном Reset. NC и CLI устанавливают его при запуске. AF/BC/DE/HL разрушаются, если конкретный контракт не задаёт сохранение. Вызовы DOS не реентерабельны.

Обработчик команд и буфер BAT расположены в странице DOS; CLI.COM и его редактор/история — в основной памяти. Программы соблюдают memtop=8BFFh. DOS читает BAT целиком в свободный интервал арены DLL или порциями через общее окно 128 байт. Вложенные BAT поддерживаются до восьми кадров и возвращаются к следующей строке родителя. IF/GOTO, параметры `%1` и перенаправления потоков ещё не добавлены.

На системном диске запустите `C:/TESTS/DOSTEST.BAT` из NC или CLI. Сценарий использует временный каталог `B:/DOSTEST` на RAM-диске. В нём он проверяет создание каталогов, COPY, REN, ATTRIB, DIR, MOVE и TYPE. Один и тот же файл выводится с движками KOI-7R и KOI-8. Первая пауза оставляет результаты на экране. Следующая клавиша запускает DEL и RD, после чего вторая пауза оставляет сообщение `DOS TEST OK`.


CLI выводит KOI-8 и не очищает экран при перезагрузке после программы. Консольные утилиты продолжают вывод с текущей позиции, явно включают KOI-8 и восстанавливают прежний режим при обычном возврате. Очистка панелей при F10 выполняется NC; очистка экрана пользователем доступна через CLS.

`bios_fileGetSetAttr=C857h`: HL указывает на 11 байтов имени FAT 8.3 в текущем каталоге; C=0 читает атрибуты, C=1 записывает B. A возвращает итоговые атрибуты, CF=1 означает ошибку, подробный код доступен через bios_getError; BC/DE/HL сохраняются. Меняются R/H/S/A (маска 27h), признак каталога DIR сохраняется. VOLUME и зарезервированные биты 6/7 отклоняются. Перед вызовом с полным путём используйте fileNamePrepare. ATTRIB не поддерживает шаблоны и рекурсивный обход; при повторном указании одного бита действует последняя маска. Ключи идут перед путём: `ATTRIB -RS file.txt` снимает R и S; `-R-S` и ключи после пути не допускаются. Изменение атрибутов — тихая команда общего движка DOS; чтение без ключей требует консольного вывода. QUERY проверяет тот же синтаксис, что исполнение, до выбора режима экрана NC.

CLI.COM содержит приглашение, цикл ввода и отображение ошибок; он вызывает общий обработчик DOS через ABI. Редактор `source/include/lineedit.inc` включается в CLI и NC при сборке, не занимает резидентную область DOS и не имеет фиксированной системной точки входа. Вставка, Backspace, Home/End, стрелки и горизонтальное окно работают одинаково в консоли и диалогах. Положение курсора и автоматическая ширина окна учитывают установленный шрифт 4×8, 6×8 или 8×8, в том числе при вызове команды из истории. Последняя ячейка экрана остаётся свободной, чтобы редактирование не вызывало перевод строки. В NC стрелки вверх/вниз перемещают выделение панели и при набранной команде; влево/вправо при непустой строке двигают текстовый курсор. Escape в консоли очищает строку, в диалоге отменяет ввод.

NC предварительно вызывает QUERY: команды без вывода сохраняют панели и тулбар; CD и смена диска обновляют активную файловую панель только при фактическом изменении диска или каталога, а информационная панель при необходимости обновляется вслед за ней; DIR, TYPE, ECHO и другие команды с выводом временно скрывают панели. Повторные `H:\` в корне и `H:` в той же сохранённой папке сохраняют выделение и прокрутку списка. Внешние программы запускаются хвостовым переходом в DOS: они могут затереть NC, поэтому после завершения оболочка загружается заново. TYPE передаёт байты в BIOS без преобразования окончаний строк: LF переводит строку, CR возвращает курсор в её начало.

DOS загружается bootstrap и остаётся резидентной в своём банке; приложению не нужны запросы загрузки/освобождения DOS. Устаревшие входы C8D8h/C8DBh удалены. При возврате программа передаёт управление C800h; при аппаратном Reset bootstrap восстанавливает BIOS и шрифт.

Программа может запустить другую через `HL=строка команды`, `MXOS_CALL MXOS_DOS_FILE_EXEC` (исторический вход `bios_fileExec`). DOS сохраняет собственные кадры и продолжение BAT в своём банке. Память вызывающей программы при этом не резервируется: вызываемый COM/EXE может её затереть. CALL с продолжением допустим только при согласованных непересекающихся областях; для замены себя другой программой используется `JMP bios_fileExec`, при согласованной замене программы в main. Это ещё не механизм независимых процессов или автоматического сохранения образа родителя.

`DIR A:` выводит текущий каталог диска A:, сохраняя выбранные диск и каталог приглашения; `DIR A:\` явно выбирает корень. Один префикс `A:` допустим и в CD: он переключает на сохранённый текущий каталог этого диска.

Стрелки вверх/вниз в самостоятельном CLI перебирают историю последних 32 непустых команд, включая команды с ошибкой. Последовательные одинаковые команды занимают одну запись. При первом нажатии вверх сохраняется набираемый черновик; спуск ниже последней команды возвращает его. Вызванную команду можно редактировать обычными клавишами, Escape очищает строку и возвращает навигацию к концу истории. Буферы истории находятся в CLI.COM: 4096 байт записей MAX_PATH и 128 байт черновика, ядро DOS их не хранит. Перед внешней программой и EXIT история сохраняется в скрытый файл `B:\CLI.HST`, при загрузке CLI восстанавливается. На обычные встроенные команды запись истории на диск не выполняется. Если B: недоступен или заполнен, работа CLI продолжается с историей текущего запуска. Формат файла проверяется по сигнатуре, размеру, индексам и терминаторам строк.

При CLI_OP_COMMAND в DE передаётся адрес обработчика совпадений COPY (0 — возвращать EXISTS). CLI.COM и NC предоставляют свои обработчики Yes/No; внутренний исполнитель BAT использует 0. Совпадающие каталоги объединяются, решение о замене принимается для каждого файла. No оставляет назначение и источник без изменений, в том числе при MOVE между томами. CLI читает сообщения DOS из `C:\DOS\ERRORS.DAT` через `source/include/errors.inc`. При отказе `FILE_EXEC` числовой код сохраняется до повторной загрузки CLI. Сама консоль однократно выводит сообщение перед следующим приглашением.

`CLI_OP_OBSERVER=9`, HL=адрес обработчика или 0 для отключения, устанавливает наблюдатель изменений общих файловых операций DOS. Перед возможной записью обработчик получает A=номер диска, DE=кластер каталога, C=0 для точного каталога либо C=1 для тома целиком (изменение пути каталога). В обработчике нельзя вызывать DOS/CLI. Он принадлежит приложению и должен быть отключён до его выгрузки; все регистры/флаги вокруг уведомления сохраняются модулем. После отказа I/O изменения могли быть частичными, поэтому уведомление консервативно выдаётся перед записью. Обычные чтения и ответ No не порождают уведомлений. Прямые резидентные файловые вызовы вне общего CLI этим наблюдателем не охватываются.

`CLI_OP_ASSOCIATION=10`, HL=расширение без точки, ASCIIZ в буфере MAX_PATH. Проверяет наличие записи в системном C:\DOS\CLI.EXT: CF=0 — найдена, CF=1 — отсутствует или ошибка чтения. Регистр букв не учитывается. Использует собственный 512-байтный буфер CLI, сохраняет текущий диск и не изменяет общую командную строку. При успехе DE указывает на начало команды внутри банка DOS. Команда заканчивается CR или FFh, указатель действителен до следующего обращения к CLI. NC вызывает эту операцию до снятия выделения файла и перехода в консоль.

Регистрация наблюдателя запоминает страницу клиента. Уведомление возвращается в неё через транспорт; A/DE/C скалярные, указателей в DOS обработчик не получает. Вложенный BIOS-вызов допустим, повторный DOS/CLI возвращает ACCESS. Структурные COPY/MOVE передают снимок FILE_COPY_REQUEST по клиентскому адресу; текстовый CLI_OP_COMMAND передаёт снимок в зарезервированном хвосте FB00h.

Единый префикс ключей системных программ — `-`, как в RUN и FORMAT; регистр ключей несущественен, `/` и `\` остаются разделителями пути. Для COPY/MOVE запланированы `-Y` (перезаписывать), `-N` (пропускать совпадения), `-I` (спрашивать). Эти ключи пока не разбираются; текущий интерактивный COPY/межтомовый MOVE использует Yes/No, а внутренний исполнитель BAT при конфликте возвращает EXISTS без перезаписи. REN и MOVE внутри тома пока отклоняют занятое имя.

Обработчик совпадений COPY теперь допускает A=2 (Yes to all) и A=3 (No to all), кроме A=0/1. Решение сохраняется только на время текущего запроса, включая всё дерево; новый запрос сбрасывает его. В CLI ответам соответствуют Y/N/A/S (Yes/No/All/Skip all). Режим No to all пропускает только уже существующие файлы: отсутствующие файлы продолжают копироваться.


BAT по умолчанию печатает исполняемые команды. Префикс `@` скрывает только текущую строку, `ECHO OFF` и `ECHO ON` управляют дальнейшим эхом; `ECHO текст` выводит сообщение. Ошибки сохранения истории отключают дисковое сохранение на время текущего CLI, но не историю в памяти.

Вложенные BAT делят общий дескриптор чтения. Каждый уровень хранит собственное 32-битное смещение. Вложенный BAT после завершения возвращается к родителю; поддерживается до восьми уровней. Ограничение размера сценария в 6 КиБ снято. Ошибки показывают имя BAT, номер строки и код DOS; длина одной команды ограничена 127 байтами. CR/LF/CRLF и последняя строка без перевода принимаются. Ошибка останавливает текущую цепочку BAT; CALL, GOTO и подстановка аргументов пока не реализованы.

## Парсер, исполнители и маски

Если DIR не находит совпадений, в том числе в пустом каталоге, выводится `No matching files`, но команда завершается успешно и BAT продолжается. Отсутствующий последний компонент без завершающего разделителя может означать маску без совпадений. Неверный родительский путь, например `DIR B:\ABSENT\*`, либо явно заданный отсутствующий каталог `DIR B:\ABSENT\`, возвращает настоящую ошибку и останавливает BAT.

Парсер команд и управление BAT остаются резидентными в DOS; COMMAND.DLL не используется. CLI.COM — интерфейс ввода/истории в MAIN. COPY/MOVE лениво подключают FILEOPS.DLL, DIR и раскрытие маски источника COPY/MOVE — общий ENUM.DLL. Модули занимают разные арены и могут оставаться в кэше одновременно. Маски не раскрываются общим токенизатором и не передаются обычной программе как готовый список файлов: их обрабатывает перечислитель по запросу команды.

`DIR B:\BENCH\*.COM` выводит совпадения текущего каталога, `DIR B:\BENCH\*.COM -S` — полные пути во всём дереве. `COPY B:\DATA\*.TXT B:\BACKUP` и MOVE с такой же маской требуют существующий каталог назначения. `*.*` включает имена без расширения, `?` соответствует одному символу. DEL/ERASE принимают файл или целое дерево, защищая текущий каталог и его предков; RD/RMDIR удаляет только пустой каталог. При ошибке или отмене уже удалённое не восстанавливается. Прикладные программы могут вызывать структурированные MXOS_DOS_ENUMERATE/FILEOPS, минуя командную строку; см. [ENUM](../enumerate/README.md) и [FILEOPS](../fileops/README.md).

MKDIR/MD создаёт недостающих родителей: `MKDIR Games/Almaz-2/MXOS`. Уже существующие каталоги допускаются, файл в любом компоненте вызывает отказ. F7 NC использует тот же обработчик FILEOPS. При частичной ошибке уже созданные родители сохраняются.
