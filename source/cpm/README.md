# CP/M 2.2 для Сябра: самостоятельный профиль Emu80

Задача VS Code **`run: Emu80 CP/M`** собирает системный ROM и запускает CP/M из внешнего комплекта `D:/Projects/RetroPC/Specialist/OS/CP-M/syabr-cpm-0.1.zip`. Нужна переменная `SPECIALIST_EMU80_DIR`, указывающая на Emu80 4.0.571 или новее. Это самостоятельная система; запуск через MXOS и файловый адаптер CP/M к MXOS не реализованы.

## Образы и запуск

```powershell
python -X utf8 scripts/images/build-cpm.py
python -X utf8 scripts/images/check-cpm.py
powershell.exe -NoProfile -File scripts/emu80/run-cpm.ps1
```

Отдельная задача сборки — **`image: CP/M`**. Другой ZIP задаётся параметром `--archive` сборщика. Архив должен содержать `CPM/CPM.RKS`, `CPM/CPM.DSK` и `CPM/README.TXT`. Обрабатывается известная раскладка: программа начинается с 0100h, диск имеет размер 8 МиБ. Заголовок и сумма RKS проверяются; тело CP/M и исходный диск не патчатся. Сборщик сохраняет хеши входов и результатов в `images/CPM-images.json`.

| Файл | Назначение |
|---|---|
| `images/CPM-system.bin` | 64-КБ MX2 ROM с автоматическим запуском CP/M |
| `images/CPM-seed.dsk` | Исходный диск A: из архива, 8 МиБ |
| `images/CPM-original.rks` | Неизменённый исходный RKS |
| `images/CPM-README.TXT` | Руководство автора комплекта |

Профиль разворачивается отдельно в `specialist-cpm/` внутри runtime. ВВ55-2 подключён к `RkSdController` с протоколом `spec`. Диск A: — рабочий файл `specialist-cpm/sdcard/CPM/CPM.DSK`: он копируется из seed только при первом запуске и затем сохраняет изменения. Повторная сборка и запуск задачи его не заменяют. Параметр `-ResetDisk` восстанавливает исходный A: с предварительным сохранением рабочей копии в соседний `.bak`.

Страница 0 ДОЗУ занята CP/M, страницы 1–7 — RAM-диском B: (446 КиБ). Остальные страницы модели не используются этим портом. B: сохраняется при сбросе внутри работающего эмулятора; между закрытием и новым запуском этого профиля автоматически не сохраняется. Диски MXOS и RAMFOS не подключаются. На A: уже есть штатные утилиты CP/M и демонстрации автора; состав см. в извлечённом руководстве.

## Загрузчик и ограничения

`romboot.asm` запускается из MX-страницы ROM без стека: сначала переносит тело RKS в верхнее ОЗУ, копирует небольшой переходник на 8000h, отключает ROM, переносит тело на 0100h и передаёт ему управление. Переходник доступен до и после переключения; низкое ОЗУ не записывается через включённый ROM. CP/M затем сама устанавливает своё окружение и банковые переходники.

Системная flash и внешний ROM-диск H: этому профилю не нужны. Перезапуск приводит снова в CP/M. Поддерживаются только программы 8080; наличие Z80-программ в сторонней библиотеке не означает возможности их исполнения. Для диагностики есть `-PrepareOnly`, `-Mute` и `-Mcp`; последние два отключают ВИ53 и мониторинг ленты. MCP требует отдельной совместимой сборки и свободного порта 19781. Подготовка профиля отклоняется, если этот runtime уже работает.
