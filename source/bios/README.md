# BIOS и DOS

Принимающий адаптер банковых вызовов находится в отдельном [IO.SYS](../io/README.md) по F000h; его размещение и служебный стек задаёт mxos.inc. Штатная DOS исполняется в банке ДОЗУ 0.

Сборка `scripts/build/build-project.ps1 OS` создаёт BIOS.sys с C000h в основной памяти IO.sys с F000h и DOS.sys с 0100h в ДОЗУ 0. Размещение рассчитывает scripts/build/build-bios-dos.py; карта результата — bin/System.layout.json. DOS.native.sys — только связанный основной вариант для CPU-тестов и разрешения ссылок, в системный образ он не включается.

BIOS содержит совместимые входы Монитора-2, клавиатуру, рендер текста, графику NC, заглушки ленты и физические драйверы. Уже загруженная программа может использовать эти службы без DOS. FAT, каталог, кэш, FileStream/FileHandle, загрузка файлов, ассоциации и общий обработчик CLI/NC/BAT находятся в DOS. Файловые точки C800h перенаправляются через банковый диспетчер DOS; прежний префикс `bios_` у публичных файловых вызовов сохранён.

## Загрузка

В системном ROM/flash фиксированы BOOT.SYS с 2000h, BIOS.SYS с 3000h, FONT.FNT с 5800h, IO.SYS с 6000h, MEM.SYS с 7000h и DOS.SYS с 8000h. Сборщик проверяет непрерывность и границы. Bootstrap всегда копирует BIOS в C000h, IO в F000h и шрифт в FONT_ADDR с транспонированием по строкам и читает флаг готовности в банке DOS. При нулевом флаге DOS копируется напрямую ROM → ДОЗУ 0, при установленном сохраняется. FAT для этого не нужен. Флаг не доказывает целостность образа; дополнительная контрольная сумма при перезапуске не вычисляется. BIOS, DOS и bootstrap обновляются согласованно.

При холодной загрузке выводится `BIOS 6.0`, после загрузки DOS — `DOS 2.0`. Повторное обращение к уже загруженному DOS не читает образ и не печатает версию. Системные образы используют расширенный bootstrap; прежний профиль ROM 64 КБ для этой компоновки не поддерживается.

После холодной инициализации BIOS запускает AUTOEXEC.BAT. До его выполнения A: обслуживает встроенный ROM-Sys только для чтения. Имена файлов внешних драйверов BIOS не знает: AT512KS.COM и остальные драйверы устанавливаются явными командами AUTOEXEC. RAMDISK.COM из AUTOEXEC проверяет B: и вызывает FORMAT только для неразмеченной памяти. Отдельного безусловного вызова FORMAT.BAT в BIOS нет.

Холодный запуск означает отсутствие готовой DOS: обычно это включение питания. Аппаратный Reset не очищает ОЗУ; при сохранённом флаге готовности выполняется тёплый запуск: BIOS восстанавливается со встроенным ROM-Sys, DOS и содержимое B: сохраняются. Реестр A: согласуется с ROM-Sys, затем AUTOEXEC выполняется заново и явно устанавливает выбранные драйверы. RAMDISK принимает готовый B: без повторного форматирования. Программные переходы на C000h/C800h отбрасывают стеки приложения и возвращаются в DOS, затем в выбранную оболочку, без bootstrap и переустановки драйверов. Первый вход C000h из самого bootstrap только завершает инициализацию BIOS. Обычный RET приложения продолжает вызвавший его загрузчик, в том числе BAT.

## Физический обмен

Физические службы ROM/FLASH/FLASHFST занимают один сменный слот FA00h–FB9Fh в DOS и main. Их одноразовые COM-инициализаторы загружаются в DOS:C000h–D7FFh и после установки освобождаются. BIOS сохраняет доступ к системному A: через маппер и принимает запросы DOS через MAINIO. B: использует общий банковый копировщик; внешние floppy и SD также будут исполняться в DOS. Прямые службы main уже используются для полных секторов; банковые приложения — следующий этап.

`bios_blockIO` (C8EAh): A — номер диска 0…7, B — 1 для записи или 2 для чтения, DE — линейный номер физического блока, HL — буфер. BC/DE/HL сохраняются, AF разрушается, CF означает ошибку. Размер блока определяется установленным драйвером. Страницу накопителя вычисляет драйвер, DOS передаёт линейный номер блока. Выбор текущего диска и каталога DOS не меняется; функция нереентерабельна, как существующие драйверы. Логический сектор FAT может состоять из нескольких физических блоков.

## Универсальный вход: текущий этап

`mx_call=F800h`: B=группа, C=номер функции. Родные группы BIOS/DOS используют регистровые пакеты MX_REGS. Группа BDOS 0 и вход mx_cpmCall=F803h зарезервированы и возвращают UNSUPPORTED: CP/M предполагается запускать подменой ядра, отдельный файловый адаптер ещё предстоит разработать.

Группы 1 (BIOS) и 2 (DOS) принимают DE на изменяемый пакет `MX_REGS`: HL, DE, BC, AF, четыре 16-битных слова. После исполнения пакет содержит результаты, которые также остаются в регистрах. Номер функции и адрес пакета могут разрушаться. Неподдерживаемая группа/номер либо незагруженная DOS возвращает CF=1/A=10 без изменения пакета; пакет, пересекающий FFC0h, отклоняется с A=7. Группа 3 зарезервирована для памяти, пока возвращает отказ. Реестр `syscalls.json` порождает одинаковые номера для ASM/C и внутренние таблицы; `python scripts/build/build-syscalls.py --check` проверяет согласованность.

Макрос `MXOS_CALL MXOS_DOS_FILEHANDLE` вызывает mx_callRegs=F806h, номер функции расположен после CALL. Регистры и флаги передаются без ручной упаковки. Bootstrap включает v_dosBanked после установки DOS, транспорта и стеков; исторические файловые JMP C800h также маршрутизируются в банк. NEAR-указатели относятся к вызывающей странице. Текст, графика и клавиатура основной программы выполняются локально в BIOS.

`bios_fileLoadPath=F809h` и `bios_fileSavePath=F80Ch` принимают HL на 40-байтный `FILE_PATH_IO`: слова path, buffer, count, actual, затем 32 байта рабочего FILE_DESCRIPTOR. Все указатели — NEAR вызывающей страницы: основной памяти при штатной загрузке, страницы клиента при включённом банковом маршруте. При загрузке count задаёт вместимость; слишком большой файл отклоняется до записи в буфер. При сохранении count задаёт точную длину; существующий обычный файл заменяется, защищённый файл или каталог — нет. actual содержит переданное число байт при успехе и ноль при ошибке корректно размещённого запроса. CF/A возвращает код DOS; файл с длиной больше 65535 байт не загружается целиком этой функцией. Сохранённые CWD дисков восстанавливаются; диск, указанный в пути, становится текущим. Путь и рабочий дескриптор не должны пересекаться с буфером. Аналогичные операции доступны как MXOS_DOS_FILE_LOAD_PATH/FILE_SAVE_PATH; C-структура называется MXOS_PATH_IO.

DOS загружается bootstrap и остаётся резидентной в своём банке; приложению не нужны запросы загрузки/освобождения DOS. Устаревшие входы C8D8h/C8DBh удалены. При возврате программа передаёт управление C800h; при аппаратном Reset bootstrap восстанавливает BIOS и шрифт.


В штатной банковой системе прямой bios_blockIO обслуживает только A:; обычные запросы B:/H: идут через MXOS_DOS_RAW_IO. Для подготовленной серии без межстраничного диспетчера предусмотрен RAW_IO B=RAW_OP_PREPARE (6), описанный в [ABI](../mem/api.md#локальная-серия-raw). Это исключает обращение старого физического RAM-драйвера к странице ядра. Физический B=3 возвращает геометрию; физический B=FFh у BIOS/A: возвращает B=DISK_TECH_*, C=DISK_CAP_*, HL=0, CF=0 при успехе. HL=0 здесь не означает отсутствие сведений BC. Имя и описание получают через MXOS_DOS_RAW_IO B=FFh: HL указывает на две ASCIIZ-строки из реестра DOS в памяти вызывающего, суммарно до 64 байт. Компактные локальные службы H: запросы геометрии/описания не обслуживают. RAW_IO выбранного диска поддерживает 1/2/3/4/5/6/FFh: запись, чтение, геометрию, flush, запись с проверкой, подготовку локальной серии, описание. Для межбанкового клиента DOS создаёт временную локальную копию результата; её нужно сохранить отдельно, если она требуется после следующих RAW_IO или смены драйвера.

После подготовки серии исторический вход C863h передаёт повторные B=1/2 непосредственно в локальный RAW-обработчик с исходными регистрами, без создания пакета MX_REGS. Первый запрос и прочие операции используют общий ABI. Проверка границ самостоятельного RAW-запроса и выдача GET_ERROR сохраняются; дисковый менеджер завершает серию при следующем входе в DOS. Физический A: в уже выбранном контексте BIOS вызывается без повторной установки и восстановления того же диска.

MXOS_DOS_DRIVER_INSTALL (0223h) принимает HL на DRIVER_INSTALL только из одноразового инициализатора в странице DOS. MXOS_DOS_DRIVER_REFRESH (0224h), A=0, HL=NEAR-адрес 64-байтного буфера клиента с двумя ASCIIZ-строками, обновляет реестр после установки системного драйвера в main. HL=0 выбирает описание ROM-SYS из DOS при Reset. Физический B=FFh BIOS возвращает BC с технологией/возможностями и HL=0; строки всех дисков предоставляет реестр DOS через RAW_IO B=FFh. CF/A — ошибка, остальные регистры разрушаются. Версия установочного дескриптора 1 обслуживает службы H:; [контракт и расположение](../flash/README.md). Прежний DRIVER_SELECT зарезервирован и возвращает UNSUPPORTED.

## Исходники

Аппаратные процедуры printChar/getch/beep/scroll, входы Монитора-2, драйверы основного BIOS находятся здесь. Локальная графическая библиотека находится в source/include/ui.inc. Каждый INCLUDE описан в layout.json; размещатель уплотняет BIOS вокруг фиксированных точек C000h/C800h. Общие локальные примитивы включаются из ../common/. В dos/ находятся только файловое ядро и его адаптеры; DOSMOD больше не используется. MAINBIOS.asm и MAINIO.asm находятся в source/io; первый принимает межбанковые вызовы BIOS, второй обслуживает прямой обмен A: с банком DOS.

## Внешний шрифт и переменные текста

Bootstrap читает полный линейный FONT.FNT из отдельного ROM-слота 5800h. Файл содержит 256 глифов по восемь байт, всего 2048 байт. В RAM он транспонируется в E400h–EBFFh: восемь 256-байтных страниц, младший байт адреса — код символа, старший выбирает строку глифа. Заголовка и таблицы диапазонов в этой области нет. FONTKOI.FNT остаётся отдельным экспериментальным форматом бенчмарка.

bios_upper.charGen хранит физический адрес RAM-шрифта. Штатный адрес выбирает построчное ядро; альтернативная линейная таблица из программы поддерживается одиночным развёрнутым путём. Значение FFFFh и копирование глифов из ПЗУ удалены. Поля состояния MXOS перенесены в BIOS_UPPER_VARIABLES; нижние 33 байта 8FDFh–8FFFh сохраняют расположение полей Монитора-2, включая отдельный monitorFont с историческим представлением адреса. Это соответствие структуры, а не обещание совместимости всех команд и точек входа другого ядра.

Остаток верхней арены EC00h–EC7Fh (128 байт) доступен через GLYPH_CACHE. Для экспериментального ограниченного кеша FONTBEN этого недостаточно, поэтому стенд использует собственный временный блок 2 КБ в 7E00h–85FFh, общий с буфером отчёта после измерений. Системный пререндер располагается отдельно в нижней памяти.

## Общий загрузчик тела

MXOS_BIOS_FILE_BODY (012Dh), HL=FILE_BODY_IO, работает в основной памяти. Первые 32 байта запроса — готовый FILE_DESCRIPTOR выбранного диска, затем buffer:word, header:byte, tail:byte, trailer:word, actual:word (всего 40 байт). Читается ровно size-header-tail байт, а не остаток кластера. При trailer=0 хвост пропускается; иначе tail байт читаются в отдельный буфер. Пустое тело допустимо. actual содержит число переданных байтов тела, включая частичный отказ; CF/A возвращают ошибку. Заголовок должен помещаться в первый кластер; файл больше 65535 байт отклоняется. Запрос, тело, хвост и стек должны сохранять код/контекст загрузки; пересечение приёмников с запросом и запись в область BIOS запрещены. Служба использует существующий FileStream DOS и не распознаёт COM/EXE/RKS и их суммы. Банковый NEAR-адаптер для этой BIOS-службы пока не реализован: из другого банка она возвращает UNSUPPORTED. C-структура — MXOS_BODY_IO.

RUN использует этот вход с header/tail=16/0 для COM/EXE и 4/2 для RKS. Проверка формата и контрольной суммы остаётся в RUN. Его меню/подготовка исполняются в нижнем ОЗУ; перед загрузкой тела параметры и 60-байтное продолжение устанавливаются в 8D80h–8DFFh. В MON/RF переходник подмены ядра занимает начало FONT_ADDR, когда вывод старого BIOS больше не нужен. Для верхней программы RF, способной перекрыть BIOS/шрифт, используются промежуточное тело в 0000h и экранный переходник AB00h. MX/STD сохраняют шрифт и используют переходник 8C00h. Область F000h–F5FFh больше не занята RUN.

Программные C000h/C800h проверяют четыре байта копировщика main по эталону банка DOS и всегда восстанавливают общий код MEM основной памяти. При повреждении выводится предупреждение с ожиданием клавиши. Например, STD-сборка Almaz2-8 пишет в FF02h/FF03h, которые при запуске RUN -MX являются ОЗУ, а не портами её цветного контроллера. Аппаратный Reset по-прежнему восстанавливает BIOS/IO через bootstrap. Точный размер BIOS задаёт bin/System.layout.json; полный построчный шрифт начинается с E400h, после него остаётся 128 байт верхней арены.

## Пакетный рендер 6×8

`bios_printString` и старый вход `bios_printStringOld` сохраняют AF/BC/DE один раз на строку. Выровненные четверки печатных символов записывают три полных экранных столбца без чтения фона. Основной путь вращает биты непосредственно при выводе; быстрый использует заранее построенные фазы 0/4/6, а исходную фазу 2 читает из шрифта. Указатели и параметры принадлежат BIOS, промежуточного пиксельного буфера нет. Короткие строки, невыровненные головы/хвосты и служебные коды проходят через полный фронтенд printChar с развёрнутым пиксельным ядром. Сохраняются KOI-7/8, инверсия, ESC, переносы и прокрутка; интерфейс printChar и printCharReal не меняется.

В BIOS перенесён только 6×8. Ядра 8×8, 4×8, ограниченный кеш и прочие варианты остаются в FONTBEN. Штатный полный FONT.FNT использует построчные пакетный и одиночный пути. Альтернативный линейный 256-символьный charGen обслуживается одиночным ядром без пререндера. Пререндер содержит все 256 кодов; исходный шрифт не копируется в его таблицы.


Одиночные `bios_printChar` / `bios_printCharRaw`, короткие строки и невыровненные начала/хвосты при валидном пререндере используют скалярный COLPRE. При отключённой или устаревшей таблице используются развёрнутые вращения. Полные выровненные четвёрки сохраняют отдельное пакетное ядро.

Генератор пререндера обрабатывает каждую из пяти плоскостей отдельным циклом: восемь страниц по 256 байтов. Выбор сдвига вынесен из побайтовой обработки; указатель назначения непрерывно проходит все 10 КиБ. Последние две плоскости строятся из готовых b>>2 и b<<2, поэтому для каждой из пяти плоскостей достаточно двух вращений или сложений. Размер генератора buildAll — 115 байт.

### FONT_RENDER, 0125h

Вызов: `MXOS_CALL MXOS_BIOS_FONT_RENDER`. HL всегда задаёт явный адрес основной памяти, в том числе при вызове из банка. Номера, размер и операции объявлены в mxos.inc и SDK.

| A на входе | Операция |
|---|---|
| FONT_RENDER_QUERY (0) | Запросить состояние |
| FONT_RENDER_BUILD (1) | Построить три фазы в буфере HL и включить их |
| FONT_RENDER_DISABLE (2) | Отключить пререндер |

При успехе CF=0, A=1, если пререндер соответствует текущему шрифту, иначе A=0; HL — адрес прикреплённого буфера (0 после отключения), BC=FONT_PRERENDER_BYTES (10240), DE — физический адрес текущего RAM-шрифта. Все остальные флаги разрушены. При неверной операции, альтернативном линейном шрифте, невыравненном или недопустимом буфере CF=1, A=DOS_ERR_ARGUMENT; прежнее состояние и данные пререндера сохраняются.

Буфер занимает 2800h байт, его начало кратно 100h и находится в диапазоне 0100h–6400h; исключающий конец не выше 8C00h. Пересечение с источником шрифта отклоняется. Пять построчных плоскостей по 0800h байт: b<<2, b>>2, b<<6, b>>4, b<<4; все значения ограничены байтом. Все восемь строк каждого глифа сохранены. Таблица не использует кеш-арену над экраном.

Память предоставляет вызывающая программа: например, выделяет отдельный выровненный блок через MEM из своей main-арены. BIOS не выделяет блок, не меняет memTop и не освобождает его. До FREE, выгрузки модуля или передачи этой памяти другой программе необходимо вызвать DISABLE. Старые программы сами этого API не вызывают; по умолчанию после загрузки и программного возврата работает путь с вращением. Автоматическое резервирование для запуска старых программ относится к RUN/DOS, а не к этому API.

Изменение charGen или эпохи GLYPH_CACHE делает старые фазы непригодными: вывод автоматически использует вращения, QUERY возвращает A=0. После замены битмап на том же адресе нужно повторить BUILD; для замены штатных битмап предусмотрено уведомление GLYPH_CACHE A=3. BIOS не загружает файл шрифта в этом вызове. Все операции и вывод требуют DI и не допускают повторного входа. Четверки держат два указателя на строки глифов в регистрах и пишут экран без чтения; одиночный вывод сохраняет соседние пиксели через чтение и маски.


### Прямой вывод строки из main

bios_printStringReal (C8EDh) принимает HL=ASCIIZ в основной памяти, сохраняет AF/BC/DE и возвращает HL на завершающем нуле. 00h завершает строку, 01h–1Fh выводятся как глифы; ESC-состояние не меняется. KOI-7 и инверсия действуют как при обычной печати. На выровненных группах автоматически работают четверки, края и короткие строки остаются посимвольными. Выровненные на 8 пикселей поля по 12 символов проходят тремя четверками.

Из main достаточно `ld hl,text` / `call bios_printStringReal`; общий диспетчер не нужен. MXOS_CALL MXOS_BIOS_PRINT_STRING_REAL принимает NEAR-строку вызывающей страницы, MXOS_BIOS_PRINT_STRING_REAL_MAIN — явный адрес main. Из банков текст передаёт штатный адаптер. Одиночный bios_printCharReal (C869h) принимает код в A и сохраняет AF/BC/DE/HL.

KOI-7/8 выбирается явно: `bios_setFontEncoding` (C8A2h) или `MXOS_CALL MXOS_BIOS_SET_FONT_ENCODING`, A=0 для KOI8, A!=0 для KOI7. Регистры и флаги сохраняются. Процедура один раз переставляет блоки 60h и E0h в восьми страницах штатного шрифта и действующем пререндере. В рендере нет проверок KOI и перекодирования глифов: все коды используют выбранные физические битмапы. Поле bios_upper.koi7 доступно только для чтения. ESC+( / ESC+) и Shift+РУС/LAT больше не переключают раскладку шрифта; RUN явно устанавливает и восстанавливает её. Для альтернативного линейного шрифта нужную раскладку готовит вызывающая программа.

Общий временный буфер A:/текста/UI занимает ED80h–EE8Fh (272 байта) перед BIOS_UPPER_VARIABLES. Физический сектор использует первые 256 байт, UI — до 261; оставшиеся 11 байт составляют запас. Полный шрифт расположен в E400h–EBFFh, затем до стека остаётся непрерывный резерв EC00h–EC7Fh (128 байт). Это не кэш: содержимое действительно только внутри одного нереентерабельного запроса. Сборщик ограничивает BIOS началом шрифта FONT_ADDR=E400h. Встроенный ROM-Sys и AT512KS читают в нижнюю MAIN через две memcpy (ROM → верхний буфер → нижнее ОЗУ); верхнее назначение читается напрямую. При программировании AT512KS сначала сохраняет нижний источник в том же буфере, а верхний источник доступен вместе с отображённым ROM. MAINIO предварительно переносит туда сектор из DOS/BANK. AT29C010 записывается двумя страницами по 128 байт, AT29C020/C040 — одной по 256 байт; после каждой страницы выполняется DATA polling.

Проверяющая запись B=5 в MAIN использует первые 256 байт общего временного буфера вместо стека. Служебный стек BIOS сокращён до 256 байт; непрерывный резерв после шрифта составляет 128 байт. Источник B=5 должен сохраняться на время вызова и не пересекать зарезервированный временный буфер BIOS. Локальная проверка DOS использует DOS_VERIFY_BUFFER, а BANK — стек своей страницы; к буферу MAIN они не обращаются.

Пять текущих вариантов текстового вывода и банковые способы передачи описаны в [публичном ABI MEM](../mem/api.md#textprint-012ah). Raw-символ не проверяет NUL; RawZ проверяет только терминатор; RawLim обрабатывает ровно BC байт, включая нули.

RawLim хранит общий 16-битный остаток в BC. Пакетный цикл получает квоту до 64 четверок (256 байт) и использует один 8-битный счётчик в операнде инструкции; проверки значений кодов в этом пути отсутствуют. Один и тот же код обслуживает MAIN, Win20, Far256 и пользовательские буферы. После пакета BC уменьшается на фактически потреблённое число байтов; невыровненные головы, хвосты и альтернативные линейные шрифты обслуживаются скалярным путём. Публичные адреса, 16-битная длина BC и сохранение регистров не меняются.

Графические процедуры NC вынесены в source/include/ui.inc. Программы включают их локально либо помещают в собственную MAIN DLL. UI-входы BIOS и MXOS_CALL удалены.

Для обычного и инверсного пакетного вывода 6×8 используются отдельные ядра: обычное не содержит NOP, инверсное выполняет CPL после объединения частей глифов. Выбор входа выполняется один раз на пакет. Измерительный таймер исключён из BIOS API; программы включают source/include/timing-pit.inc локально.

При активном валидном FONT_RENDER посимвольный printChar/printCharRaw, а также головы и хвосты строк используют те же плоскости сдвигов, что четвёрки. Нулевая фаза читается из исходного шрифта. При отключении пререндера, смене эпохи или линейном альтернативном шрифте выбираются вращения. Линейная и построчная раскладки теперь используют одно скалярное ядро с переключаемым шагом указателя INC HL/INC H; переключение шага выполняется при смене раскладки. Это освобождает место для скалярного пререндера без перемещения шрифта.

Арифметика умножения, деления и деления на два подключается локально из source/include/math.inc. Эти публичные входы BIOS и MXOS_CALL удалены. Вычитание bios_sub_hl_de (C87Eh) и историческое сравнение HL/DE (C427h) сохранены. Детектор BIOS/bootstrap определяет физические банки ДОЗУ; на холодном старте BIOS выводит их число и объём. Геометрию B: задаёт драйвер/реестр DOS, встроенный резервный драйвер BIOS сообщает размер только A:.

Скалярный COLPRE рисует каждый столбец глифа целиком, затем соседний, если он нужен. HL указывает на единственный столбец битмапа, DE — на экран, B — на маску сохранения фона. Восемь строк развёрнуты (DUP 7 и последняя строка без продвижения), INC H выбирает следующую строку глифа. Для второго столбца исходные HL/DE сохраняются на стеке один раз, затем INC D переводит экранный указатель вправо на 256 байт. Временного пиксельного буфера и SMC-слияний строк нет. Обычный и инверсный циклы раздельные; инверсный добавляет XOR только по маске шести пикселей глифа. Обычный курсорный путь встроен, редкий перенос перед рисованием сохраняет прежнее поведение. Используются существующие пять плоскостей (10 КиБ), генератор и API FONT_RENDER не менялись.
