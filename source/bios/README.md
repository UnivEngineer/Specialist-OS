# BIOS и DOS

Принимающий адаптер банковых вызовов входит в BIOS.SYS по DA00h; его размещение и отдельный служебный стек задаёт mxos.inc. Клиент F800h/F806h и поддержанные службы описаны в [README транспорта](../banked/README.md#вызовы-bios-из-банка). Штатная DOS исполняется в физической странице ДОЗУ 0.

Сборка `scripts/build/build-project.ps1 OS` создаёт BIOS.sys с C000h в основной памяти и DOS.sys с 4000h в ДОЗУ 0. Размещение рассчитывает scripts/build/build-bios-dos.py; карта результата — bin/System.layout.json. DOS.native.sys — только связанный основной вариант для CPU-тестов и разрешения ссылок, в системный образ он не включается.

BIOS содержит совместимые входы Монитора-2, клавиатуру, рендер текста, компактный шрифт, графику NC, заглушки ленты и физические драйверы. Уже загруженная программа может использовать эти службы без DOS. FAT, каталог, кэш, FileStream/FileHandle, загрузка файлов, ассоциации и общий обработчик CLI/NC/BAT находятся в DOS. Файловые точки C800h перенаправляются через банковый диспетчер DOS; прежний префикс `bios_` у публичных файловых вызовов сохранён.

## Загрузка

В системном ROM/flash фиксированы BOOT.SYS с 2000h, BIOS.SYS с 3000h, TAIL.SYS с 6000h и DOS.SYS с 8000h. Сборщик проверяет непрерывность и границы. Bootstrap всегда копирует BIOS в C000h и читает флаг готовности в банке DOS. При нулевом флаге DOS копируется напрямую ROM → ДОЗУ 0, при установленном сохраняется. FAT для этого не нужен. Флаг не доказывает целостность образа; дополнительная контрольная сумма при перезапуске не вычисляется. BIOS, DOS и bootstrap обновляются согласованно.

При холодной загрузке выводится `BIOS 6.0`, после загрузки DOS — `DOS 2.0`. Повторное обращение к уже загруженному DOS не читает образ и не печатает версию. Системные образы используют расширенный bootstrap; прежний профиль ROM 64 КБ для этой компоновки не поддерживается.

После холодной инициализации BIOS запускает FLASHSYS.COM и AUTOEXEC.BAT. RAMD.COM из AUTOEXEC проверяет B: и вызывает FORMAT только для неразмеченной памяти. Отдельного безусловного вызова FORMAT.BAT в BIOS нет.

Холодный запуск означает отсутствие готовой DOS: обычно это включение питания. Аппаратный Reset не очищает ОЗУ; при сохранённом флаге готовности выполняется тёплый запуск: BIOS и драйвер A: в main восстанавливаются, DOS, её драйверы и B: сохраняются, FORMAT/AUTOEXEC не повторяются. Программные переходы на C000h/C800h отбрасывают стеки приложения и возвращаются в DOS, затем в выбранную оболочку, без bootstrap и переустановки драйверов. Первый вход C000h из самого bootstrap только завершает инициализацию BIOS. Обычный RET приложения продолжает вызвавший его загрузчик, в том числе BAT.

## Физический обмен

Физические драйверы H: размещены в странице DOS: обычный flash с 9000h, ROM с 9400h, быстрый flash с 9600h. BIOS сохраняет доступ к системному A: через маппер и принимает запросы DOS через MAINIO. B: использует общий банковый копировщик; внешние floppy и SD также будут исполняться в DOS. Прямые драйверы в хвостах клиентов пока не устанавливаются.

`bios_blockIO` (C8EAh): A — номер диска 0…7, B — 1 для записи или 2 для чтения, DE — линейный номер физического блока, HL — буфер. BC/DE/HL сохраняются, AF разрушается, CF означает ошибку. Размер блока определяется установленным драйвером. Страницу накопителя вычисляет драйвер, DOS передаёт линейный номер блока. Выбор текущего диска и каталога DOS не меняется; функция нереентерабельна, как существующие драйверы. Логический сектор FAT может состоять из нескольких физических блоков.

## Универсальный вход: текущий этап

`mx_call=F800h`: B=группа, C=номер функции. Группа 0 следует регистрам BDOS CP/M; реализованы функции 1, 2, 6, 9, 11, 12, 14, 25, 26. Файловый FCB-адаптер и профиль запуска CP/M ещё не реализованы. Функция 12 возвращает 0022h как выбранную версию соглашений, а не версию продукта BIOS. Реализованные BDOS-вызовы возвращают A=L, B=H. `mx_cpmCall=F803h` предварительно устанавливает B=0; CALL 0005h поверх программ MXOS автоматически не устанавливается.

Группы 1 (BIOS) и 2 (DOS) принимают DE на изменяемый пакет `MX_REGS`: HL, DE, BC, AF, четыре 16-битных слова. После исполнения пакет содержит результаты, которые также остаются в регистрах. Номер функции и адрес пакета могут разрушаться. Неподдерживаемая группа/номер либо незагруженная DOS возвращает CF=1/A=10 без изменения пакета; пакет, пересекающий FFC0h, отклоняется с A=7. Группа 3 зарезервирована для памяти, пока возвращает отказ. Реестр `syscalls.json` порождает одинаковые номера для ASM/C и внутренние таблицы; `python scripts/build/build-syscalls.py --check` проверяет согласованность.

Макрос `MXCALL MX_DOS_FILEHANDLE` вызывает mx_callRegs=F806h, номер функции расположен после CALL. Регистры и флаги передаются без ручной упаковки. Bootstrap включает v_dosBanked после установки DOS, транспорта и стеков; исторические файловые JMP C800h также маршрутизируются в банк. NEAR-указатели относятся к вызывающей странице. Текст, графика и клавиатура основной программы выполняются локально в BIOS.

`bios_fileLoadPath=F809h` и `bios_fileSavePath=F80Ch` принимают HL на 40-байтный `FILE_PATH_IO`: слова path, buffer, count, actual, затем 32 байта рабочего FILE_DESCRIPTOR. Все указатели — NEAR вызывающей страницы: основной памяти при штатной загрузке, страницы клиента при включённом банковом маршруте. При загрузке count задаёт вместимость; слишком большой файл отклоняется до записи в буфер. При сохранении count задаёт точную длину; существующий обычный файл заменяется, защищённый файл или каталог — нет. actual содержит переданное число байт при успехе и ноль при ошибке корректно размещённого запроса. CF/A возвращает код DOS; файл с длиной больше 65535 байт не загружается целиком этой функцией. Сохранённые CWD дисков восстанавливаются; диск, указанный в пути, становится текущим. Путь и рабочий дескриптор не должны пересекаться с буфером. Аналогичные операции доступны как MX_DOS_FILELOADPATH/FILESAVEPATH; C-структура называется MXOS_PATH_IO.

Верхние драйверы и командная строка остаются по адресам из `mxos.inc`. `bios_loadDosModule` теперь обеспечивает наличие DOS; `bios_releaseDosModule` сохраняет DOS и ограничение memtop, возвращая успех. Освободить исполняющийся файловый сервис ради загрузки клиента нельзя. Пока DOS в основной памяти, проверяются небольшие игры ниже 4000h; загрузка поверх DOS отклоняется. DISKBEN использует меньшие буферы, прежний CHKDSK с большими верхними буферами сообщает о нехватке памяти. Это ограничения промежуточной компоновки до банкового переноса.


В штатной банковой системе прямой bios_blockIO обслуживает только A:; запросы B:/H: идут через MX_DOS_RAWIO. Это исключает обращение старого физического RAM-драйвера к странице ядра. B=3 и FFh возвращают соответственно геометрию и две ASCIIZ-строки имени/описания. RAWIO выбранного диска поддерживает 1/2/3/4/5/FFh: запись, чтение, геометрию, flush, запись с проверкой, описание. Копии геометрии и строк main находятся в отдельных областях E900h/E940h до следующего соответствующего запроса.

После подготовки серии исторический вход C863h передаёт повторные B=1/2 непосредственно в локальный RAW-обработчик с исходными регистрами, без создания пакета MX_REGS. Первый запрос и прочие операции используют общий ABI. Проверка границ самостоятельного RAW-запроса и выдача GETERROR сохраняются; дисковый менеджер завершает серию при следующем входе в DOS. Физический A: в уже выбранном контексте BIOS вызывается без повторной установки и восстановления того же диска.

MX_DOS_DRIVERINSTALL (0224h) принимает HL на DRIVER_INSTALL только из одноразового инициализатора в странице DOS. MX_DOS_DRIVERREFRESH (0225h), A=0, обновляет реестр после установки системного драйвера в main. CF/A — ошибка, остальные регистры разрушаются. Версия установочного дескриптора 1 обслуживает службы H:; [контракт и расположение](../flash/README.md). Прежний DRIVERSELECT зарезервирован и возвращает UNSUPPORTED.
