# BIOS и DOS

Принимающий адаптер банковых вызовов находится в отдельном [IO.SYS](../io/README.md) по F000h; его размещение и служебный стек задаёт mxos.inc. Штатная DOS исполняется в банке ДОЗУ 0.

Сборка `scripts/build/build-project.ps1 OS` создаёт BIOS.sys с C000h в основной памяти IO.sys с F000h и DOS.sys с 0100h в ДОЗУ 0. Размещение рассчитывает scripts/build/build-bios-dos.py; карта результата — bin/System.layout.json. DOS.native.sys — только связанный основной вариант для CPU-тестов и разрешения ссылок, в системный образ он не включается.

BIOS содержит совместимые входы Монитора-2, клавиатуру, рендер текста, графику NC, заглушки ленты и физические драйверы. Уже загруженная программа может использовать эти службы без DOS. FAT, каталог, кэш, FileStream/FileHandle, загрузка файлов, ассоциации и общий обработчик CLI/NC/BAT находятся в DOS. Файловые точки C800h перенаправляются через банковый диспетчер DOS; прежний префикс `bios_` у публичных файловых вызовов сохранён.

## Загрузка

В системном ROM/flash фиксированы BOOT.SYS с 2000h, BIOS.SYS с 3000h, FONTKOI.FNT с 5800h, IO.SYS с 6000h, MEM.SYS с 7000h и DOS.SYS с 8000h. Сборщик проверяет непрерывность и границы. Bootstrap всегда копирует BIOS в C000h, IO в F000h и непрерывный шрифт в D660h и читает флаг готовности в банке DOS. При нулевом флаге DOS копируется напрямую ROM → ДОЗУ 0, при установленном сохраняется. FAT для этого не нужен. Флаг не доказывает целостность образа; дополнительная контрольная сумма при перезапуске не вычисляется. BIOS, DOS и bootstrap обновляются согласованно.

При холодной загрузке выводится `BIOS 6.0`, после загрузки DOS — `DOS 2.0`. Повторное обращение к уже загруженному DOS не читает образ и не печатает версию. Системные образы используют расширенный bootstrap; прежний профиль ROM 64 КБ для этой компоновки не поддерживается.

После холодной инициализации BIOS запускает FLASHSYS.COM и AUTOEXEC.BAT. RAMDISK.COM из AUTOEXEC проверяет B: и вызывает FORMAT только для неразмеченной памяти. Отдельного безусловного вызова FORMAT.BAT в BIOS нет.

Холодный запуск означает отсутствие готовой DOS: обычно это включение питания. Аппаратный Reset не очищает ОЗУ; при сохранённом флаге готовности выполняется тёплый запуск: BIOS и драйвер A: в main восстанавливаются, DOS, её драйверы и B: сохраняются, FORMAT/AUTOEXEC не повторяются. Программные переходы на C000h/C800h отбрасывают стеки приложения и возвращаются в DOS, затем в выбранную оболочку, без bootstrap и переустановки драйверов. Первый вход C000h из самого bootstrap только завершает инициализацию BIOS. Обычный RET приложения продолжает вызвавший его загрузчик, в том числе BAT.

## Физический обмен

Физические службы ROM/FLASH/FLASHFST занимают один сменный слот FA00h–FB9Fh в DOS и main. Их одноразовые COM-инициализаторы загружаются в DOS:9000h–BFFFh и после установки освобождаются. BIOS сохраняет доступ к системному A: через маппер и принимает запросы DOS через MAINIO. B: использует общий банковый копировщик; внешние floppy и SD также будут исполняться в DOS. Прямые службы main уже используются для полных секторов; банковые приложения — следующий этап.

`bios_blockIO` (C8EAh): A — номер диска 0…7, B — 1 для записи или 2 для чтения, DE — линейный номер физического блока, HL — буфер. BC/DE/HL сохраняются, AF разрушается, CF означает ошибку. Размер блока определяется установленным драйвером. Страницу накопителя вычисляет драйвер, DOS передаёт линейный номер блока. Выбор текущего диска и каталога DOS не меняется; функция нереентерабельна, как существующие драйверы. Логический сектор FAT может состоять из нескольких физических блоков.

## Универсальный вход: текущий этап

`mx_call=F800h`: B=группа, C=номер функции. Родные группы BIOS/DOS используют регистровые пакеты MX_REGS. Группа BDOS 0 и вход mx_cpmCall=F803h зарезервированы и возвращают UNSUPPORTED: CP/M предполагается запускать подменой ядра, отдельный файловый адаптер ещё предстоит разработать.

Группы 1 (BIOS) и 2 (DOS) принимают DE на изменяемый пакет `MX_REGS`: HL, DE, BC, AF, четыре 16-битных слова. После исполнения пакет содержит результаты, которые также остаются в регистрах. Номер функции и адрес пакета могут разрушаться. Неподдерживаемая группа/номер либо незагруженная DOS возвращает CF=1/A=10 без изменения пакета; пакет, пересекающий FFC0h, отклоняется с A=7. Группа 3 зарезервирована для памяти, пока возвращает отказ. Реестр `syscalls.json` порождает одинаковые номера для ASM/C и внутренние таблицы; `python scripts/build/build-syscalls.py --check` проверяет согласованность.

Макрос `MXCALL MX_DOS_FILEHANDLE` вызывает mx_callRegs=F806h, номер функции расположен после CALL. Регистры и флаги передаются без ручной упаковки. Bootstrap включает v_dosBanked после установки DOS, транспорта и стеков; исторические файловые JMP C800h также маршрутизируются в банк. NEAR-указатели относятся к вызывающей странице. Текст, графика и клавиатура основной программы выполняются локально в BIOS.

`bios_fileLoadPath=F809h` и `bios_fileSavePath=F80Ch` принимают HL на 40-байтный `FILE_PATH_IO`: слова path, buffer, count, actual, затем 32 байта рабочего FILE_DESCRIPTOR. Все указатели — NEAR вызывающей страницы: основной памяти при штатной загрузке, страницы клиента при включённом банковом маршруте. При загрузке count задаёт вместимость; слишком большой файл отклоняется до записи в буфер. При сохранении count задаёт точную длину; существующий обычный файл заменяется, защищённый файл или каталог — нет. actual содержит переданное число байт при успехе и ноль при ошибке корректно размещённого запроса. CF/A возвращает код DOS; файл с длиной больше 65535 байт не загружается целиком этой функцией. Сохранённые CWD дисков восстанавливаются; диск, указанный в пути, становится текущим. Путь и рабочий дескриптор не должны пересекаться с буфером. Аналогичные операции доступны как MX_DOS_FILELOADPATH/FILESAVEPATH; C-структура называется MXOS_PATH_IO.

Верхние драйверы и командная строка остаются по адресам из mxos.inc. bios_loadDosModule обеспечивает наличие DOS, а bios_releaseDosModule возвращает успех, сохраняя резидентную банковую DOS. Программы основной памяти могут занимать область 0000h–8BFFh; код DOS в эту область не входит. Программный возврат сохраняет DOS и возвращает выбранную оболочку; аппаратный Reset восстанавливает BIOS и шрифт через bootstrap.


В штатной банковой системе прямой bios_blockIO обслуживает только A:; запросы B:/H: идут через MX_DOS_RAWIO. Это исключает обращение старого физического RAM-драйвера к странице ядра. B=3 и FFh возвращают соответственно геометрию и две ASCIIZ-строки имени/описания. RAWIO выбранного диска поддерживает 1/2/3/4/5/FFh: запись, чтение, геометрию, flush, запись с проверкой, описание. Копии геометрии и строк main входят в BIOS_UPPER_VARIABLES и действительны до следующего соответствующего запроса.

После подготовки серии исторический вход C863h передаёт повторные B=1/2 непосредственно в локальный RAW-обработчик с исходными регистрами, без создания пакета MX_REGS. Первый запрос и прочие операции используют общий ABI. Проверка границ самостоятельного RAW-запроса и выдача GETERROR сохраняются; дисковый менеджер завершает серию при следующем входе в DOS. Физический A: в уже выбранном контексте BIOS вызывается без повторной установки и восстановления того же диска.

MX_DOS_DRIVERINSTALL (0224h) принимает HL на DRIVER_INSTALL только из одноразового инициализатора в странице DOS. MX_DOS_DRIVERREFRESH (0225h), A=0, обновляет реестр после установки системного драйвера в main. CF/A — ошибка, остальные регистры разрушаются. Версия установочного дескриптора 1 обслуживает службы H:; [контракт и расположение](../flash/README.md). Прежний DRIVERSELECT зарезервирован и возвращает UNSUPPORTED.

## Исходники

Аппаратные процедуры printChar/getch/beep/scroll, входы Монитора-2, драйверы основного BIOS и графика ui/ находятся здесь. Каждый INCLUDE описан в layout.json; размещатель уплотняет BIOS вокруг фиксированных точек C000h/C800h. Общие локальные примитивы включаются из ../common/. В dos/ находятся только файловое ядро и его адаптеры; DOSMOD больше не используется. MAINBIOS.asm и MAINIO.asm находятся в source/io; первый принимает межбанковые вызовы BIOS, второй обслуживает прямой обмен A: с банком DOS.

## Внешний шрифт и сменный рендер

Битмапы шрифта в BIOS.SYS не встроены. Bootstrap при каждом аппаратном Reset читает отдельный FONTKOI.FNT из фиксированного слота системного образа 5800h, до первого вывода BIOS. Файл загружается подряд с FONT_ADDR=D660h и остаётся доступным в STD. Штатный файл занимает 1328 байт: заголовок MXFN, пять диапазонов по 32 символа (20h–7Fh, C0h–FFh), затем ё/Ё. Полный исходный FONT.FNT сохранён.

build-compact-font.py сохраняет существующие пользовательские битмапы; --force заново создаёт файл из полного FONT.FNT. Старые файлы без заголовка автоматически оборачиваются в MXFN. Фиксированный ROM-слот допускает файл до 2048 байт; больший шрифт потребует согласованного изменения слотов bootstrap.

Заголовок версии 1 имеет 32 байта; все слова little-endian, смещения отсчитываются от начала файла. Нулевое смещение диапазона означает отсутствие глифов; вместо отсутствующего символа выводится пробел.

| Смещение | Размер | Поле |
|---|---:|---|
| 0 | 4 | Сигнатура MXFN |
| 4 | 1 | Версия, 1 |
| 5–8 | 4 | Ширина, высота, шаг X, шаг Y; сейчас 6, 8, 6, 10 |
| 9 | 1 | Упаковка, сейчас 0 — восемь байт на глиф |
| 10 | 2 | Полный размер файла |
| 12 | 16 | Восемь смещений диапазонов 00h, 20h, …, E0h |
| 28 | 2 | Смещение ё (A3h) |
| 30 | 2 | Смещение Ё (B3h) |

Упакованный 4x8 требует отдельной реализации рендера и значения упаковки; текущая сборка такой файл отклоняет. Таблица допускает сокращённый KOI7 и раздельное хранение ё/Ё без подмены пробела или 7Fh.

Остаток арены после файла отдан кэшу: сейчас DB90h–EB8Fh, 4096 байт. MX_BIOS_GLYPHCACHE: A=0 возвращает HL=начало, DE=исключающий конец, BC=ёмкость, A=эпоха; A=1 принимает HL=новый конец и возвращает DE=прежний; A=2 восстанавливает полный конец; A=3 пересчитывает начало после замены шрифта. CF/A сообщает ошибку. Расширение и неизменная граница сохраняют кэш; сужение консервативно сбрасывает индекс. Верхняя утилита сохраняет старую границу, сокращает арену перед загрузкой и восстанавливает при возврате. Загрузчики DOS и RUN делают это для штатной области E500h–EAFFh. Сам ускоренный рендер с кэшем — следующий этап; сейчас работают базовый рендер, резерв и управление его границами.

## Общий загрузчик тела

MX_BIOS_FILEBODY (012Dh), HL=FILE_BODY_IO, работает в основной памяти. Первые 32 байта запроса — готовый FILE_DESCRIPTOR выбранного диска, затем buffer:word, header:byte, tail:byte, trailer:word, actual:word (всего 40 байт). Читается ровно size-header-tail байт, а не остаток кластера. При trailer=0 хвост пропускается; иначе tail байт читаются в отдельный буфер. Пустое тело допустимо. actual содержит число переданных байтов тела, включая частичный отказ; CF/A возвращают ошибку. Заголовок должен помещаться в первый кластер; файл больше 65535 байт отклоняется. Запрос, тело, хвост и стек должны сохранять код/контекст загрузки; пересечение приёмников с запросом и запись в область BIOS запрещены. Служба использует существующий FileStream DOS и не распознаёт COM/EXE/RKS и их суммы. Банковый NEAR-адаптер для этой BIOS-службы пока не реализован: из другого банка она возвращает UNSUPPORTED. C-структура — MXOS_BODY_IO.

RUN использует этот вход с header/tail=16/0 для COM/EXE и 4/2 для RKS. Проверка формата и контрольной суммы остаётся в RUN. Его меню/подготовка исполняются в нижнем ОЗУ; перед загрузкой тела параметры и 60-байтное продолжение устанавливаются в 8D80h–8DFFh. В MON/RF переходник подмены ядра занимает начало FONT_ADDR, когда вывод старого BIOS больше не нужен. Для верхней программы RF, способной перекрыть BIOS/шрифт, используются промежуточное тело в 0000h и экранный переходник AB00h. MX/STD сохраняют шрифт и используют переходник 8C00h. Область F000h–F5FFh больше не занята RUN.

Программные C000h/C800h проверяют четыре байта копировщика main по эталону банка DOS и всегда восстанавливают общий код MEM основной памяти. При повреждении выводится предупреждение с ожиданием клавиши. Например, STD-сборка Almaz2-8 пишет в FF02h/FF03h, которые при запуске RUN -MX являются ОЗУ, а не портами её цветного контроллера. Аппаратный Reset по-прежнему восстанавливает BIOS/IO через bootstrap. Для восстановления и диагностики BIOS занимает C000h–D64Fh; внешний шрифт начинается с D660h, после него доступно 4096 байт кэша глифов.
