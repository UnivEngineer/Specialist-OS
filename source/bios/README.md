# BIOS и DOS

Принимающий адаптер банковых вызовов находится в отдельном [IO.SYS](../io/README.md) по F000h; его размещение и служебный стек задаёт [карта системной памяти](../common/system-layout.inc). Штатная DOS исполняется в банке ДОЗУ 0.

Сборка `scripts/build/build-project.ps1 OS` создаёт BIOS.sys с C000h в основной памяти IO.sys с F000h и DOS.sys с 0100h в ДОЗУ 0. Размещение рассчитывает scripts/build/build-bios-dos.py; карта результата — bin/System.layout.json. DOS.native.sys — только связанный основной вариант для CPU-тестов и разрешения ссылок, в системный образ он не включается.

BIOS содержит входы RAMFOS и Монитора-2, клавиатуру, рендер текста, графику NC и физические драйверы. Уже загруженная программа может использовать местные службы без DOS. FAT, каталог, кэш, FileStream/FileHandle, загрузка файлов, ассоциации и общий обработчик CLI/NC/BAT доступны через системные вызовы DOS. Имена `bios_*` соответствуют нативному ABI RAMFOS, имена `mon2_*` — историческому ABI Монитора-2. [Заголовок SDK](../../sdk/asm/abi/bios.inc)

При установке и возврате в штатную оболочку выбирается RAMFOS. RAMFOS устанавливает 31 JMP по C800h–C85Ch и использует ВВ55 в режиме MX. MON2 устанавливает исторические C800h–C835h, заполняет хвост RET и настраивает вызовы ВВ55 для STD. Входы Монитора-2 в C000h–C4FFh доступны в обоих режимах. Для их переменных 8FDFh–8FFFh заголовок объявляет `MON2_VARIABLES` и `mon2_vars`. Расширения MXOS используют MEM и существующий шлюз системных вызовов.

`MXOS_BIOS_PROFILE` (012Fh) принимает A=1 для RAMFOS, 2 для MON2, FFh для запроса. При успехе возвращает прежний профиль в A и CF=0, при неизвестном коде возвращает `DOS_ERR_ARGUMENT` и CF=1. BC, DE, HL сохраняются. Для запуска STD запрос профиля выполняется через MEM до смены аппаратного режима. Новый профиль использует те же установленные векторы печати C037h и C438h. Выбор кодировки доступен через `MXOS_BIOS_SET_FONT_ENCODING`.

## Загрузка

Оболочку необязательно запускать из AUTOEXEC: по умолчанию BIOS выбирает `C:\DOS\NC.COM`; режим CLI выбирается при выходе из NC. Если выбранный образ не загрузился, BIOS однократно пробует вторую стандартную оболочку NC/CLI. При отказе обеих появляется `Shell path: ` — обычный строковый ввод BIOS с запросом пути к нативной оболочке, например `B:\NC.COM`. Неверный путь возвращает к этому запросу, без бесконечного автоповтора. Это аварийный ввод имени файла; команды DIR/COPY здесь не интерпретируются. Его код находится в резидентном хвосте IO.SYS, поэтому не требует работоспособного кода оболочки в MAIN. BIOS, IO и DOS должны быть установлены bootstrap; отсутствие этих системных компонентов данным механизмом не исправляется.

В системном ROM/flash фиксированы BOOT.SYS с 2000h, BIOS.SYS с 3000h, FONT.PF с 5800h, IO.SYS с 6000h, MEM.SYS с 7000h и DOS.SYS с 8000h. Сборщик проверяет непрерывность и границы. Bootstrap всегда копирует BIOS в C000h, IO в F000h и шрифт в FONT_ADDR с транспонированием по строкам и читает флаг готовности в банке DOS. При нулевом флаге DOS копируется напрямую ROM → ДОЗУ 0, при установленном сохраняется. FAT для этого не нужен. Флаг не доказывает целостность образа; дополнительная контрольная сумма при перезапуске не вычисляется. BIOS, DOS и bootstrap обновляются согласованно. Временная ступень BOOT.SYS выполняет начальную настройку BIOS и DOS до AUTOEXEC. Первый вход по C000h выбирает эту процедуру по одноразовому адресу, при следующих входах C000h возвращает оболочку.

При холодной загрузке и аппаратном Reset выводятся `BIOS 6.1` и `DOS 3.1`, даже если готовая DOS сохраняется в своём банке. Программный возврат из приложения в оболочку не читает образ и не печатает версии. Системные образы используют расширенный bootstrap; прежний профиль ROM 64 КБ для этой компоновки не поддерживается.

После холодной инициализации BIOS запускает AUTOEXEC.BAT. До его выполнения C: обслуживает встроенный ROM512KS только для чтения. Имена файлов внешних драйверов BIOS не знает: AT512KS.COM и остальные драйверы устанавливаются явными командами AUTOEXEC. RAMDISK.COM из AUTOEXEC проверяет B: и вызывает FORMAT только для неразмеченной памяти. Отдельного безусловного вызова FORMAT.BAT в BIOS нет.

Холодный запуск означает отсутствие готовой DOS: обычно это включение питания. Аппаратный Reset не очищает ОЗУ; при сохранённом флаге готовности выполняется тёплый запуск: BIOS восстанавливается со встроенным ROM512KS, DOS и содержимое B: сохраняются. Реестр C: согласуется с ROM512KS, затем AUTOEXEC выполняется заново и явно устанавливает выбранные драйверы. RAMDISK принимает готовый B: без повторного форматирования. Программный возврат через C000h, MON2 C800h или RAMFOS F800h отбрасывает стек приложения и возвращает DOS, затем выбранную оболочку, без bootstrap и переустановки драйверов. При выходе из STD резидентный BIOS переключает маппер в MX прежде, чем обращаться к верхним службам. Первый вход C000h из самого bootstrap только завершает инициализацию BIOS. Обычный RET приложения продолжает вызвавший его загрузчик, в том числе BAT.

## Физический обмен

Физические службы ROM/FLASH/FLASHFST занимают один сменный слот FA00h–FBFFh в DOS и main. Их одноразовые COM-инициализаторы загружаются в DOS:C000h–D7FFh и после установки освобождаются. BIOS сохраняет доступ к системному C: через маппер и принимает запросы DOS через MAINIO. B: использует общий банковый копировщик; внешние floppy и SD также будут исполняться в DOS. Прямые службы main уже используются для полных секторов; банковые приложения — следующий этап.

`MXOS_BIOS_BLOCK_IO` принимает A=номер диска 0…7, B=1 для записи или 2 для чтения, DE=линейный номер физического блока, HL=буфер. BC/DE/HL сохраняются, AF разрушается, CF означает ошибку. Размер блока определяется установленным драйвером. Страницу накопителя вычисляет драйвер, DOS передаёт линейный номер блока. Выбор текущего диска и каталога DOS сохраняется. Функция нереентерабельна, как существующие драйверы. Логический сектор FAT может состоять из нескольких физических блоков.

## Совместимые службы RAMFOS

F800h–F85Fh содержит 32 самостоятельных JMP, сохраняющих назначение при смене профиля C800h. Среди них F800h для возврата в DOS и F85Ah для запуска процедуры по HL со строкой параметров в DE и безопасным адресом возврата в BIOS. Файловый диалог возвращает отмену, операции с файлами возвращают A=1 и CF=1. Выбор типа файла сразу возвращает управление. Нативные операции с файлами доступны через DOS SDK.

C800h инициализирует клавиатуру и состояние экрана, настраивает ВИ53 с делителями 1510h, 4E20h и 10h. C84Eh очищает экран и возвращает курсор к началу. C83Ch задаёт строку в H и колонку в L, C81Eh их возвращает. В C63Eh хранится историческое слово курсора с вертикальной координатой в младшем байте. Службы печати используют текущий шрифт и синхронизируют курсор. C821h находит символ по пикселям в текущей ячейке и возвращает FFh при отсутствии подходящего глифа. C82Dh управляет нижней строкой. C848h использует ВИ53, C851h с параметрами из C64Eh использует PC5 ВВ55.

C812h возвращает A=FFh и ZF=0 при готовом символе, A=0 и ZF=1 при его отсутствии. Считанный код лежит в однобайтовой очереди до C803h. C81Bh возвращает декодированный код текущей клавиши или FFh. Задержку, повтор и звук блокирующего ввода задаёт драйвер MXOS через PC5. Слово C64Ch доступно для прямого чтения и записи, характерный звук автоповтора RAMFOS через это слово доступен при запуске полного ядра.

C830h/F830h возвращает верхний доступный адрес приложения. C833h/F833h задаёт верхнюю границу, ограниченную 8DFFh и текущей границей MEM. F836h/F839h читают и пишут один байт нижней MAIN (A=0), включая верхний разрешённый адрес. Отказ возвращает A=1 и CF=1, чтение также возвращает C=FFh. Системный стек, переменные Монитора-2 и страницы ДОЗУ закрыты для этих вызовов.

Профиль RAMFOS использует поведение исторической сборки без принтера. Вызовы C83Fh, C842h и C857h возвращаются без вывода. RAMFOS использует собственный формат кассеты, а штатный TAPE.COM работает как самостоятельная программа. В профиле кассетное чтение через C806h/F806h и C824h возвращает A=3Fh и CF=1, запись через C80Ch/F80Ch и C827h возвращается без вывода. C85Ah переключает три набора параметров в C65Fh–C66Bh. Для магнитофонных вызовов RAMFOS используйте полный запуск с ключом `-RF`.

## Универсальный вход: текущий этап

`mx_callPacket=F860h` принимает B=группа, C=номер функции и DE=адрес MX_REGS. Восемь выделенных функций экрана и границы памяти вызываются отдельными адресами F87Bh–F890h. Прежние номера этих функций и группа BDOS возвращают DOS_ERR_UNSUPPORTED. Исторические JMP Монитора-2 доступны напрямую из MAIN. [Контракты и адреса](../mem/api.md)

Группы 1 (BIOS) и 2 (DOS) принимают DE на изменяемый пакет `MX_REGS`: HL, DE, BC, AF, четыре 16-битных слова. После исполнения пакет содержит результаты, которые также остаются в регистрах. Номер функции и адрес пакета могут разрушаться. Неподдерживаемая группа/номер либо незагруженная DOS возвращает CF=1/A=10 без изменения пакета; пакет, пересекающий FFC0h, отклоняется с A=7. Группа 3 зарезервирована для памяти, пока возвращает отказ. Реестр `syscalls.json` порождает одинаковые номера для ASM/C и внутренние таблицы; `python scripts/build/build-syscalls.py --check` проверяет согласованность.

Макрос `MXOS_CALL_REGS MXOS_DOS_FILEHANDLE` вызывает mx_callRegs=F866h, номер функции расположен после CALL. Регистры и флаги передаются без ручной упаковки. Bootstrap включает v_dosBanked после установки DOS, транспорта и стеков. Файловые операции нативного BIOS маршрутизируются в банк. NEAR-указатели относятся к вызывающей странице. Текст, графика и клавиатура основной программы выполняются локально в BIOS.

`bios_fileLoadPath=F869h` и `bios_fileSavePath=F86Ch` принимают HL на 40-байтный `FILE_PATH_IO`: слова path, buffer, count, actual, затем 32 байта рабочего FILE_DESCRIPTOR. Все указатели — NEAR вызывающей страницы: основной памяти при штатной загрузке, страницы клиента при включённом банковом маршруте. При загрузке count задаёт вместимость; слишком большой файл отклоняется до записи в буфер. При сохранении count задаёт точную длину; существующий обычный файл заменяется, защищённый файл или каталог — нет. actual содержит переданное число байт при успехе и ноль при ошибке корректно размещённого запроса. CF/A возвращает код DOS; файл с длиной больше 65535 байт не загружается целиком этой функцией. Сохранённые CWD дисков восстанавливаются; диск, указанный в пути, становится текущим. Путь и рабочий дескриптор не должны пересекаться с буфером. Аналогичные операции доступны как MXOS_DOS_FILE_LOAD_PATH/FILE_SAVE_PATH; C-структура называется MXOS_PATH_IO.

DOS загружается bootstrap и остаётся резидентной в своём банке. Для программного возврата из RAMFOS/MX предусмотрен `bios_reboot` по F800h. При аппаратном Reset bootstrap восстанавливает BIOS и шрифт.


В штатной банковой системе прямой bios_blockIO обслуживает только C:; обычные запросы B:/H: идут через MXOS_DOS_RAW_IO. Для подготовленной серии без межстраничного диспетчера предусмотрен RAW_IO B=RAW_OP_PREPARE (6), описанный в [ABI](../mem/api.md#локальная-серия-raw). Это исключает обращение старого физического RAM-драйвера к странице ядра. Физический B=3 возвращает геометрию; физический B=FFh у BIOS/C: возвращает B=DISK_TECH_*, C=DISK_CAP_*, HL=0, CF=0 при успехе. HL=0 здесь не означает отсутствие сведений BC. Имя и описание получают через MXOS_DOS_RAW_IO B=FFh: HL указывает на две ASCIIZ-строки из реестра DOS в памяти вызывающего, суммарно до 64 байт. Компактные локальные службы H: запросы геометрии/описания не обслуживают. RAW_IO выбранного диска поддерживает 1/2/3/4/5/6/FFh: запись, чтение, геометрию, flush, запись с проверкой, подготовку локальной серии, описание. Для межбанкового клиента DOS создаёт временную локальную копию результата; её нужно сохранить отдельно, если она требуется после следующих RAW_IO или смены драйвера.

После подготовки серии `MXOS_BIOS_DISK_DRIVER` передаёт повторные B=1/2 непосредственно в локальный RAW-обработчик с исходными регистрами. Проверка границ самостоятельного RAW-запроса и выдача GET_ERROR сохраняются. Дисковый менеджер завершает серию при следующем входе в DOS. Физический A: в уже выбранном контексте BIOS вызывается без повторной установки и восстановления того же диска.

MXOS_DOS_DRIVER_INSTALL (0223h) принимает HL на DRIVER_INSTALL только из одноразового инициализатора в странице DOS. MXOS_DOS_DRIVER_REFRESH (0224h), A=0, HL=NEAR-адрес 64-байтного буфера клиента с двумя ASCIIZ-строками, обновляет реестр после установки системного драйвера в main. HL=0 выбирает описание ROM512KS из DOS при Reset. Физический B=FFh BIOS возвращает BC с технологией/возможностями и HL=0; строки всех дисков предоставляет реестр DOS через RAW_IO B=FFh. CF/A — ошибка, остальные регистры разрушаются. Версия установочного дескриптора 1 обслуживает службы H:; [контракт и расположение](../flash/README.md).

## Исходники

Здесь находятся входы Монитора-2, вывод через шрифтовый движок, декодирование клавиатуры, восстановление оболочки и драйверы BIOS. Размещатель уплотняет блоки layout.json вокруг фиксированных входов C000h–C4FFh и C800h. Локальная графическая библиотека находится в sdk/asm/lib/ui.inc, общие примитивы включаются из ../common/. В MX аппаратный опрос клавиатуры и звук работают из IO.SYS. Для STD BIOS собирает тот же аппаратный код ниже D800h, где он доступен при отображении портов вместо верхнего ОЗУ. [Аппаратный ввод-вывод](../io/README.md)

## Внешний шрифт и переменные текста

Bootstrap читает полный линейный FONT.PF из отдельного ROM-слота 5800h. Файл содержит 256 глифов по восемь байт, всего 2048 байт. В RAM он транспонируется в E400h–EBFFh: восемь 256-байтных страниц, младший байт адреса — код символа, старший выбирает строку глифа. Заголовка и таблицы диапазонов в этой области нет. FONTKOI.PF остаётся отдельным экспериментальным форматом бенчмарка.

bios_upper.charGen хранит физический адрес RAM-шрифта. Штатный адрес выбирает построчное ядро; альтернативная линейная таблица из программы поддерживается одиночным развёрнутым путём. Значение FFFFh и копирование глифов из ПЗУ удалены. Поля состояния MXOS перенесены в BIOS_UPPER_VARIABLES; нижние 33 байта 8FDFh–8FFFh сохраняют расположение полей Монитора-2, включая отдельный monitorFont с историческим представлением адреса. Это соответствие структуры, а не обещание совместимости всех команд и точек входа другого ядра.

GLYPH_CACHE предоставляет остаток верхней арены от конца установленного модуля до EC80h. Размер остатка зависит от установленного движка. Для экспериментального ограниченного кеша FONTBEN этого недостаточно, поэтому стенд использует собственный временный блок 2 КБ в 7E00h–85FFh, общий с буфером отчёта после измерений. Системный пререндер располагается отдельно в нижней памяти.

## Общий загрузчик тела

MXOS_BIOS_FILE_BODY (012Dh), HL=FILE_BODY_IO, работает в основной памяти. Первые 32 байта запроса — готовый FILE_DESCRIPTOR выбранного диска, затем buffer:word, header:byte, tail:byte, trailer:word, actual:word (всего 40 байт). Читается ровно size-header-tail байт, а не остаток кластера. При trailer=0 хвост пропускается; иначе tail байт читаются в отдельный буфер. Пустое тело допустимо. actual содержит число переданных байтов тела, включая частичный отказ; CF/A возвращают ошибку. Заголовок должен помещаться в первый кластер; файл больше 65535 байт отклоняется. Запрос, тело, хвост и стек должны сохранять код/контекст загрузки; пересечение приёмников с запросом и запись в область BIOS запрещены. Служба использует существующий FileStream DOS и не распознаёт COM/EXE/RKS и их суммы. Банковый NEAR-адаптер для этой BIOS-службы пока не реализован: из другого банка она возвращает UNSUPPORTED. C-структура — MXOS_BODY_IO.

RUN использует этот вход с header/tail=16/0 для COM/EXE и 4/2 для RKS. Проверка формата и контрольной суммы остаётся в RUN. Его меню/подготовка исполняются в нижнем ОЗУ; перед загрузкой тела параметры и 60-байтное продолжение устанавливаются в 8D80h–8DFFh. В MON/RF переходник подмены ядра занимает начало FONT_ADDR, когда вывод старого BIOS больше не нужен. Для верхней программы RF, способной перекрыть BIOS/шрифт, используются промежуточное тело в 0000h и экранный переходник AB00h. MX/STD сохраняют шрифт и используют переходник 8C00h. Область F000h–F5FFh больше не занята RUN.

Программный возврат через C000h проверяет четыре байта копировщика MAIN по эталону банка DOS и восстанавливает общий код MEM и накладки BIOS в основной памяти. При повреждении выводится предупреждение с ожиданием клавиши. Например, STD-сборка Almaz2-8 пишет в FF02h/FF03h, которые в режиме MX отображаются на ОЗУ. Аппаратный Reset восстанавливает BIOS/IO через bootstrap. Точный размер BIOS задаёт bin/System.layout.json. Полный построчный шрифт начинается с E400h, после него остаётся 128 байт верхней арены.

## Пакетный рендер 6×8

`bios_printString` и `mon2_printStringOld` сохраняют AF/BC/DE один раз на строку. Выровненные четвёрки печатных символов записывают три полных экранных столбца без чтения фона. Основной путь вращает биты непосредственно при выводе, а быстрый использует заранее построенные фазы 0/4/6 и читает исходную фазу 2 из шрифта. Указатели и параметры принадлежат BIOS. Короткие строки, края невыровненных групп и служебные коды проходят через обработчик printChar с развёрнутым пиксельным ядром. Действуют KOI-7/8, инверсия, ESC, переносы и прокрутка.

В BIOS перенесён только 6×8. Ядра 8×8, 4×8, ограниченный кеш и прочие варианты остаются в FONTBEN. Штатный полный FONT.PF использует построчные пакетный и одиночный пути. Альтернативный линейный 256-символьный charGen обслуживается одиночным ядром без пререндера. Пререндер содержит все 256 кодов; исходный шрифт не копируется в его таблицы.


Одиночные `bios_printChar` и `FONT_ENGINE_RAW`, короткие строки и края невыровненных групп при валидном пререндере используют скалярный COLPRE. При отключённой или устаревшей таблице используются развёрнутые вращения. Полные выровненные четвёрки сохраняют отдельное пакетное ядро.

Генератор пререндера обрабатывает каждую из пяти плоскостей отдельным циклом: восемь страниц по 256 байтов. Выбор сдвига вынесен из побайтовой обработки; указатель назначения непрерывно проходит все 10 КиБ. Последние две плоскости строятся из готовых b>>2 и b<<2, поэтому для каждой из пяти плоскостей достаточно двух вращений или сложений. Размер генератора buildAll — 115 байт.

### Сменный шрифтовый модуль

Пиксельные ядра и строковый цикл занимают слот D800h–EC7Fh. Bootstrap устанавливает `C:\FONTS\6x8\Rotate.fnt` со встроенным готовым шрифтом. `FONT_ENGINE_INIT` (D800h) вызывает подготовленный модуль и перенаправляет исторические точки C037h и C438h прямо в реализации. Внутренние вызовы и MXCALL используют эти точки и входы активного FNT. [Контракт шрифтов](../font/README.md)

FONT_RENDER (0125h) пока служит запросом состояния установленного модуля: A=0 возвращает A=0/1 (вращения/пререндер), HL=нижние плоскости, BC=их размер, DE=адрес верхнего шрифта, CF=0. Старый BUILD 10-КиБ таблицы больше не поддерживается и возвращает DOS_ERR_UNSUPPORTED; режим теперь принадлежит модулю. DISABLE для Rotate — пустая успешная операция, для Packed6K возвращает DOS_ERR_UNSUPPORTED: его нельзя отключить, оставив упакованный шрифт без соответствующего ядра. Переключение комплектов выполняется загрузчиком FONT. FONT резервирует нижние ресурсы через MEM_OP_RESIDENT и подготавливает их до установки. Для Packed6K это 4096 байт под memTop; Rotate освобождает резервацию шрифтового слота.

### Прямой вывод строки из main

`FONT_ENGINE_RAWZ` принимает HL=ASCIIZ в основной памяти, сохраняет AF/BC/DE и возвращает HL на завершающем нуле. 00h завершает строку, 01h–1Fh выводятся как глифы. ESC-состояние сохраняется. KOI-7 и инверсия действуют как при обычной печати. Выровненные группы проходят четвёрками, края и короткие строки выводятся посимвольно.

Из MAIN доступны прямые входы FNT. MXOS_CALL_REGS MXOS_BIOS_PRINT_STRING_RAW_Z принимает NEAR-строку вызывающей страницы. MXOS_BIOS_PRINT_STRING_RAW_Z_MAIN принимает явный адрес MAIN. Из банков текст передаёт штатный адаптер. Одиночный `FONT_ENGINE_RAW` принимает код в A и сохраняет AF/BC/DE/HL.

Кодировку выбирают через `FONT_ENGINE_ENCODING` (D812h) или `MXOS_CALL_REGS MXOS_BIOS_SET_FONT_ENCODING`. A=0 выбирает KOI8, A!=0 выбирает KOI-7R. Регистры и флаги сохраняются. При смене кодировки движок меняет местами глифы 60h–7Eh и E0h–FEh, включая действующий пререндер. В KOI-7R вывод DEL (7Fh) стирает знакоместо. Возврат в KOI8 восстанавливает прежний глиф 7Fh. Глиф Ъ на FFh сохраняется в обеих кодировках. Поле bios_upper.koi7 доступно только для чтения. RUN явно устанавливает кодировку. Для альтернативного линейного шрифта нужную раскладку готовит вызывающая программа.

Общий временный буфер C:/UI занимает ED80h–EE8Fh (272 байта) перед BIOS_UPPER_VARIABLES. Физический сектор использует первые 256 байт, UI — до 261; оставшиеся 11 байт составляют запас. Полный шрифт расположен в E400h–EBFFh, за шрифтом располагается часть кода RawPseudo. Общий временный буфер действителен внутри одного нереентерабельного запроса. Встроенный ROM512KS и AT512KS читают в нижнюю MAIN через две memcpy (ROM → верхний буфер → нижнее ОЗУ); верхнее назначение читается напрямую. При программировании AT512KS сначала сохраняет нижний источник в том же буфере, а верхний источник доступен вместе с отображённым ROM. MAINIO предварительно переносит туда сектор из DOS/BANK. AT29C010 записывается двумя страницами по 128 байт, AT29C020/C040 — одной по 256 байт; после каждой страницы выполняется DATA polling.

Проверяющая запись B=5 в MAIN использует первые 256 байт общего временного буфера вместо стека. Служебный стек BIOS занимает 256 байт. Источник B=5 должен сохраняться на время вызова и не пересекать зарезервированный временный буфер BIOS. Локальная проверка DOS использует DOS_VERIFY_BUFFER, а BANK — стек своей страницы; к буферу MAIN они не обращаются.

Текстовые входы и банковые способы передачи описаны в [публичном ABI MEM](../mem/api.md#печать-из-буфера-в-main). Raw-символ принимает любой байт. RawZ проверяет только терминатор. RawLim и RawPseudo обрабатывают ровно BC байт, включая нули. RawPseudo дополняет крайними рядами знакоместа только псевдографику KOI8-R.

При банковой Z или RAW_Z MEM проверяет каждый байт при заполнении окна до первого NUL. Штатный Z печатает точную длину через D830h, указанный по D81Eh, RAW_Z — через D80Fh. Перехваченный вектор и старый FNT1 без счётного Z обслуживаются соответствующей ASCIIZ-службой. Полная порция из 32 ненулевых байтов разбивается для неё на 31+1 в том же окне за один вход в MAIN. Во время печати из окна допустимы локальные экранные операции. Занимать окно и вызывать DOS или MEM через банк до возврата запрещено. Командные пачки используют отдельный путь с копией списка. [Протокол транспорта](../mem/transport.md#вызовы-bios-из-банка)

PRINT_STRING_LIM доступен через MXOS_CALL_REGS 012Eh. HL указывает на буфер, BC задаёт точную длину. Все байты, включая 00h, проходят обычную обработку управляющих кодов. При BC=0 длина пуста. Вход сохраняет AF/BC/DE и возвращает HL за обработанными байтами. При штатном C037h проверяется указатель D81Eh на D830h. Перехваченный C037h обслуживается совместимым посимвольным циклом.

RawLim хранит общий 16-битный остаток в BC. Пакетный цикл получает квоту до 64 четверок (256 байт) и использует один 8-битный счётчик в операнде инструкции. Один и тот же код обслуживает MAIN, порции через 32-байтное окно и буферы программ в MAIN. После пакета BC уменьшается на фактически потреблённое число байтов. Невыровненные головы, хвосты и альтернативные линейные шрифты обслуживаются скалярным путём.

Графические процедуры NC вынесены в sdk/asm/lib/ui.inc. Программы включают их локально либо помещают в собственную MAIN DLL. UI-входы BIOS и MXOS_CALL_REGS удалены.

Для обычного и инверсного пакетного вывода 6×8 используются отдельные ядра: обычное не содержит NOP, инверсное выполняет CPL после объединения частей глифов. Выбор входа выполняется один раз на пакет. Измерительный таймер читается через локальный вход IO.SYS. [Интерфейс измерительного таймера](../../sdk/asm/lib/timing.md)

При активном валидном FONT_RENDER посимвольный printChar/printCharRaw, а также головы и хвосты строк используют те же плоскости сдвигов, что четвёрки. Нулевая фаза читается из исходного шрифта. При отключении пререндера, смене эпохи или линейном альтернативном шрифте выбираются вращения. Линейная и построчная раскладки теперь используют одно скалярное ядро с переключаемым шагом указателя INC HL/INC H; переключение шага выполняется при смене раскладки. Это освобождает место для скалярного пререндера без перемещения шрифта.

Арифметика умножения, деления и деления на два подключается локально из sdk/asm/lib/math.inc. Вычитание HL–DE доступно через `MXOS_BIOS_SUB_HL_DE`, историческое сравнение HL/DE выполняют `mon2_cmp_hl_de` (C427h) и `bios_cmp_hl_de` (C854h). Детектор BIOS/bootstrap определяет физические банки ДОЗУ. На холодном старте BIOS выводит их число и объём. Геометрию B: задаёт драйвер из реестра DOS.

Скалярный COLPRE рисует каждый столбец глифа целиком, затем соседний, если он нужен. HL указывает на единственный столбец битмапа, DE — на экран, B — на маску сохранения фона. Восемь строк развёрнуты (DUP 7 и последняя строка без продвижения), INC H выбирает следующую строку глифа. Для второго столбца исходные HL/DE сохраняются на стеке один раз, затем INC D переводит экранный указатель вправо на 256 байт. Временного пиксельного буфера и SMC-слияний строк нет. Обычный и инверсный циклы раздельные; инверсный добавляет XOR только по маске шести пикселей глифа. Обычный курсорный путь встроен, редкий перенос перед рисованием сохраняет прежнее поведение. Используются существующие пять плоскостей (10 КиБ), генератор и API FONT_RENDER не менялись.

Мигающий текстовый курсор использует ширину из `FONT_ENGINE_HEADER+5`: 4, 6 или 8 пикселей. Для 4×8/8×8 его X округляется так же, как у установленного движка; высота и вертикальное положение по-прежнему задаются `cursorCfg`. На правом краю пустая вторая часть маски не записывается за пределами видеопамяти.

В KOI-8 клавиатура разделяет язык и регистр: обычная РУС/ЛАТ меняет только bit0 bios_vars.keyLocks (LAT/RUS), Shift меняет регистр букв и знаки цифрового ряда, Shift+РУС/ЛАТ переключает фиксатор регистра (bit7). Состояние языка не зависит от Shift. Для KOI-7 сохранены прежнее преобразование возвращаемых кодов и переключение фиксатора регистра клавишей РУС/ЛАТ; физическую раскладку знакогенератора по-прежнему меняет только явный setFontEncoding.
