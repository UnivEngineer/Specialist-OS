# RAMD.COM — быстрый драйвер RAM-диска

Текущая схема (05.11.2026): до AUTOEXEC работает встроенный блочный R3; RAMD.COM устанавливает R4 по F740h–F7FFh и хвосты FF00h. C86Fh поддерживает RESTORE=0, BYTE=1, REGISTER=2, BLOCK=3, USER=4; имена `RAMD_DRIVER_*` объявлены в mxos.inc. BYTE/BLOCK временно меняют только общее окно и не отменяют зарегистрированный шаблон R4. Перед возвратом к файловым/секторным операциям вызывается RESTORE. До REGISTER обычный и пользовательский выбор возвращают встроенный R3. Физическая регистрация B: независима от выбора окна. Ниже сохранены сведения об установщике и история размещений.

С 03.11.2026 резидент RAMD.COM размещён в F540h–F5FFh, хвосты остаются по FF00h; драйвер вызывается только в MX. Установщик по-прежнему загружается с 0000h. Адреса берутся из mxos.inc; прежние размещения ниже относятся к истории.

Текущий резидент RAMD занимает DF40h–DFFFh; его адрес задаёт `RAMD_RESIDENT_ADDR` в `source/include/mxos.inc`. Хвосты FF00h–FFAFh, общее окно FFC0h–FFDFh и контракт драйвера сохранены. Ниже сохранена история предыдущей карты.

Штатный DOS обслуживает B: через встроенный блочный R3. Быстрый R4 устанавливается командой `A:\RAMD.COM`, включённой в штатные AUTOEXEC после драйвера H:. Ручной запуск из NC или командной строки также допустим. Загрузка COM — с **0000h**.

Установщик сбрасывает кэш текущего тома, копирует резидент и хвосты через встроенный байтовый ABI, затем регистрирует физический драйвер B: через `bios_installDriver`. Повторная установка допустима, в том числе с самого B:. Проверочного чтения после установки нет. Форматирование и очистка диска не выполняются, секторы xxFFh остаются служебными bad-секторами.

| Область | Назначение |
|---|---|
| DD40h–DDFFh | резерв 192 байта под физический драйвер B: |
| FF00h–FF4Ch каждой RAM-страницы | 77 байт неизменяемого кода R4 |
| FF00h–FFAEh основной RAM | тот же код, входы и 32-байтный шаблон общего окна; всего 175 байт |
| FFC0h–FFDFh | прежнее общее окно 32 байта, переключается DOS |
| FFB0h–FFBBh страницы 0 | состояние NC, не затрагивается установщиком |

FLASHSYS ограничен областью DC00h–DD3Fh, FLASH/FLASHFST/ROM — DE00h–DFFFh. Они могут работать одновременно с RAMD. Ассемблер проверяет границы. Установщик и исходные копии из нижней памяти после возврата больше не нужны.

## Сервисный байтовый режим

Точка `bios_setRAMDDriver` (C86Fh) сохраняет все регистры и флаги:

- B=0: восстановить обычный режим; до установки RAMD.COM это блочный R3.
- B=1: включить встроенные байтовые FFC0h/FFD0h для метаданных и установки кода.
- B=2, HL=адрес резидентного 32-байтного шаблона: зарегистрировать обычный режим.
- B=3: временно выбрать встроенный блочный R3, сохранив регистрацию R4.
- B=4: применить зарегистрированный шаблон; до регистрации — R3.

RAMD.COM регистрирует шаблон FF8Fh. NC и DOS после сервисных обращений восстанавливают его через B=0. Резидентный R4 принимает секторные B=1/2, B=3 (физическая ёмкость и DISK_INFO) и B=FFh (описание `RAMD / R4 banked`, технология RAM, возможности READ|WRITE). Результат чтения/записи — CF, A/BC/DE/HL и стек сохраняются. Страницы вне диска, сектор xxFFh и буфер выше FE00h отклоняются. При отказе записи устанавливается diskWriteErr.

Прерывания запрещены контрактом MXOS: R4 временно использует SP для данных. Сервисные прямые обращения FFC0h/FFD0h требуют явного выбора B=1; секторные операции программ должны идти через `bios_diskDriver` (C863h).

## Ручное сравнение в DISKBEN

1. Загрузить DOS из ROM с пропуском AUTOEXEC (удерживать Shift при старте), запустить DISKBEN на B:. Драйвер — `RAMD / R3`.
2. Вернуться в NC, запустить `A:RAMD.COM`.
3. Повторить DISKBEN на B: с теми же параметрами. Драйвер — `RAMD / R4 banked`.

Обычный тёплый вход C800h/C000h сохраняет установленный резидент, как flash. Повторная загрузка DOS.SYS из ROM возвращает встроенный R3 до выполнения AUTOEXEC, который снова устанавливает R4. Переключатель сборки встроенных реализаций не требуется: байтовый и блочный шаблоны присутствуют одновременно. Карта памяти берётся из mxos.inc.

Сборка — `build: ramd` либо `build: OS`. Проверка на изолированном Emu80:

```powershell
python -X utf8 scripts/emu80/check-ramd-modes.py --runtime D:/Projects/RetroPC/Specialist/Emulator/Emu80-flash-test
```

Сценарий запускает собственный видимый эмулятор с выключенным звуком, проверяет холодный старт, выбор шаблонов, границы секторного обмена, сохранение регистров и содержимого B: при аппаратном сбросе. Занятый чужим процессом MCP-порт не используется. После проверки собственный экземпляр закрывается. Результаты эмулятора не заменяют проверку на реальной машине.
