# RAMD.COM — быстрый драйвер RAM-диска

С 03.11.2026 резидент RAMD.COM размещён в F540h–F5FFh, хвосты остаются по FF00h; драйвер вызывается только в MX. Установщик по-прежнему загружается с 0000h. Адреса берутся из mxos.inc; прежние размещения ниже относятся к истории.

Текущий резидент RAMD занимает DF40h–DFFFh; его адрес задаёт `RAMD_RESIDENT_ADDR` в `source/include/mxos.inc`. Хвосты FF00h–FFAFh, общее окно FFC0h–FFDFh и контракт драйвера сохранены. Ниже сохранена история предыдущей карты.

Штатный DOS обслуживает B: через встроенные побайтовые процедуры. Быстрый
R4 устанавливается командой `A:RAMD.COM`, включённой в штатные AUTOEXEC
после драйвера H:. Ручной запуск из NC или командной строки также допустим.
Загрузка COM — с **0000h**.

Установщик сбрасывает кэш текущего тома, копирует резидент и хвосты через
встроенный байтовый ABI, затем регистрирует физический драйвер B: через
`bios_installDriver`. Повторная установка допустима, в том числе с самого B:.
Проверочного чтения после установки нет. Форматирование и очистка диска
не выполняются, секторы xxFFh остаются служебными bad-секторами.

| Область | Назначение |
|---|---|
| DD40h–DDFFh | резерв 192 байта под физический драйвер B: |
| FF00h–FF4Ch каждой RAM-страницы | 77 байт неизменяемого кода R4 |
| FF00h–FFAEh основной RAM | тот же код, входы и 32-байтный шаблон общего окна; всего 175 байт |
| FFC0h–FFDFh | прежнее общее окно 32 байта, переключается DOS |
| FFB0h–FFBBh страницы 0 | состояние NC, не затрагивается установщиком |

FLASHSYS ограничен областью DC00h–DD3Fh, FLASH/FLASHFST/ROM — DE00h–DFFFh.
Они могут работать одновременно с RAMD. Ассемблер проверяет границы.
Установщик и исходные копии из нижней памяти после возврата больше не нужны.

## Сервисный байтовый режим

Точка `bios_setRAMDDriver` (C86Fh) сохраняет все регистры и флаги:

- B=0: восстановить обычный режим; до установки RAMD.COM это байтовый драйвер.
- B=1: включить встроенные байтовые FFC0h/FFD0h для метаданных и установки кода.
- B=2, HL=адрес резидентного 32-байтного шаблона: зарегистрировать обычный режим.

RAMD.COM регистрирует шаблон FF8Fh. NC и DOS после сервисных обращений
восстанавливают его через B=0. Резидентный R4 принимает секторные B=1/2,
B=3 (физическая ёмкость и DISK_INFO) и B=FFh (описание `RAMD / R4 banked`,
технология RAM, возможности READ|WRITE). Результат чтения/записи — CF,
A/BC/DE/HL и стек сохраняются. Страницы вне диска, сектор xxFFh и буфер
выше FE00h отклоняются. При отказе записи устанавливается diskWriteErr.

Прерывания запрещены контрактом MXOS: R4 временно использует SP для данных.
Сервисные прямые обращения FFC0h/FFD0h требуют явного выбора B=1;
секторные операции программ должны идти через `bios_diskDriver` (C863h).

## Ручное сравнение в DISKBEN

1. Загрузить DOS из ROM с пропуском AUTOEXEC (удерживать Shift при старте),
   запустить DISKBEN на B:. Драйвер — `RAMD / Per-byte`.
2. Вернуться в NC, запустить `A:RAMD.COM`.
3. Повторить DISKBEN на B: с теми же параметрами. Драйвер — `RAMD / R4 banked`.

Обычный тёплый вход C800h/C000h сохраняет установленный резидент, как flash.
Повторная загрузка DOS.SYS из ROM возвращает исходный встроенный драйвер
до выполнения AUTOEXEC, который снова устанавливает R4.
DOS содержит только минимальный побайтовый доступ и секторный адаптер.
Быстрый драйвер устанавливается отдельной программой RAMD.COM.
Переключатель встроенных реализаций удалён; карта памяти едина:
командная строка DC00h–DC81h, стек DC82h–DDFFh, SP=DE00h.

Сборка — `build: ramd` либо `build: OS`. Проверка на изолированном Emu80:

```powershell
python -X utf8 scripts/emu80/check-ramd-module.py --runtime D:/Projects/RetroPC/Specialist/Emulator/Emu80-flash-test
```

Сценарий изменяет только тестовую установку и форматирует её B: в конце.
Результаты эмулятора не заменяют проверку на реальной машине.
