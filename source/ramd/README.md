# RAMD.COM и драйвер RAM-диска

В штатной банковой системе RAMD.COM — программа подготовки B:, запускаемая в основной памяти с 0000h. Она проверяет существующий том и при отсутствии узнаваемой разметки запускает FORMAT.COM; собственного форматировщика в ней нет. Физический драйвер B: встроен в DOS и использует общий CPM16 через внутренний секторный вход bankCopySector. Физическая страница ДОЗУ 0 занята DOS; данные B: начинаются со страницы 1.

Сохранённые ниже реализации установщика CP/M/R4 относятся к прежней небанковой системе. Штатный вход теперь сразу переходит в BankInstall; RAMD_USE_CPM не выбирает алгоритм банкового B: и не меняет его транспорт. Общие хвосты и окно нельзя заменять старым установщиком. Альтернативные драйверные COM и единый реестр установки ещё не реализованы.

## Исторический установщик


В штатной банковой системе B: обслуживается из DOS общим R4 memcpy_far, с резервированием физической страницы 0 под DOS. RAMD.COM проверяет доступность оставшихся страниц, заново монтирует B: и не заменяет общий аппаратный шлюз. Если том корректный, файлы сохраняются. Если формат не распознан и boot-сектор не содержит признаков прежней разметки, RAMD передаёт управление `A:\FORMAT.COM B: -R -Y`. При ошибке чтения, повреждённой FAT либо узнаваемом заголовке с неверными параметрами автоматического форматирования нет. Сообщение содержит числовой код ошибки.

Защита от повторного форматирования использует монтирование DOS. Для неподдерживаемого boot-сектора дополнительно проверяются начало OEM `MX`, начало типа `FA`, расширенная сигнатура 29h и правдоподобный размер сектора 128/256/512. Эти признаки заставляют оставить носитель без изменений и потребовать явный FORMAT. Это консервативное распознавание старой разметки, не проверка всех каталогов и файлов как в CHKDSK.

AUTOEXEC содержит обычный вызов `A:\RAMD.COM`; отдельный FORMAT.BAT в штатном образе не нужен. FORMAT запускается через `JMP bios_fileExec`: обе программы загружаются по 0000h, поэтому FORMAT заменяет RAMD. Возврат идёт через сохранённый загрузчик DOS, и AUTOEXEC продолжается. Обычная повторная установка сохраняет выбор диска; FORMAT может оставить B: текущим, как при явном запуске этой команды.

Описанные ниже самостоятельные варианты CP/M/R4 относятся к исторической системе без банковой DOS; они не устанавливаются поверх общего транспорта.

Историческая реализация использует секторную адаптацию копировщика Syabr CP/M 0.1 с 16-байтным буфером. Прежний R4 сохранён в `r4.inc`. Переключатель `RAMD_USE_CPM` в `RAMD.asm`: 1 — CP/M (по умолчанию), 0 — R4. Его можно переопределить ассемблеру через `-DRAMD_USE_CPM=0`, без изменения исходника. Оба варианта имеют одинаковый внешний ABI и устанавливаются из AUTOEXEC командой `A:\RAMD.COM`.

До установки RAMD.COM работает встроенный блочный драйвер BIOS. Он используется, в частности, для первоначального форматирования. Установщик делает flush, выбирает встроенный побайтовый режим, копирует резидент и хвосты, затем регистрирует физический драйвер B: и 32-байтный шаблон. Повторная установка допустима, включая загрузку с B:. Форматирование и очистка данных при установке не выполняются.

| Область | CP/M | R4 |
|---|---|---|
| F740h–F7FFh | Резидент и адаптер, 184 байта | Резидент, 137 байт |
| FF00h в основной RAM | Код и неизменяемый шаблон, 167 байт | Код, входы и шаблон, 175 байт |
| FF00h в страницах ДОЗУ | Код, 135 байт | Код, 77 байт |
| FFC0h–FFDFh | Полностью рабочее окно драйвера | Полностью рабочее окно драйвера |

FFB0h–FFBBh и FFBEh–FFBFh не затрагиваются. Адреса резидентов и оборудования берутся из `source/include/mxos.inc`. Верхние области недоступны в STD; драйвер работает только в MX. Установщик загружается с 0000h. Исходный CP/M-копировщик сохранён отдельно в `source-apps/copybench/CPMCOPY.asm`; рабочий драйвер не зависит от бенчмарка.

## ABI

Физический драйвер принимает B=1 (запись), B=2 (чтение), DE=номер 256-байтного сектора, HL=буфер основной памяти. A/BC/DE/HL и SP сохраняются, CF сообщает результат. B=3 возвращает DE=ёмкость в секторах, HL=DISK_INFO, BC=0. B=FFh возвращает сведения `RAMD / CP/M16` либо `RAMD / R4 banked`, технологию RAM и возможности READ|WRITE. Недопустимы страницы за пределами обнаруженного диска, служебные секторы xxFFh и буферы выше FE00h. При отказе записи устанавливается `bios_vars.diskWriteErr`.

Секторный обработчик вызывает резидентные входы непосредственно: `cpmInitRead/cpmInitWrite` либо `regInitRead/regInitWrite`. FFC0h/FFD0h не являются входами установленного драйвера; всё окно доступно для его кода, данных и состояния. Секторные обращения программ выполняются через `bios_diskDriver` (C863h). SP и main восстанавливаются, внешний секторный ABI сохраняет регистры. Прерывания должны быть запрещены: оба алгоритма используют SP для данных.

CP/M использует непрерывный буфер FFC0h–FFCFh. FFD0h/FFD2h — адреса, FFD4h — число порций (16 на сектор), FFD6h/FFD7h — страницы (FFh означает main), FFD9h — SP. Восстановление окна после сектора не требуется, его прежнее содержимое не сохраняется. R4 сохраняет переходы, необходимые для переключения страниц и продолжения переноса, но исторические входные JMP чтения/записи удалены. Зафиксированные исторические варианты в copybench не изменены.

`bios_setRAMDDriver` (C86Fh) сохраняет все регистры и флаги: B=0 RESTORE — зарегистрированный шаблон либо встроенный блочный; B=1 BYTE — сервисный побайтовый; B=2 REGISTER, HL=резидентный шаблон — зарегистрировать без немедленной установки; B=3 BLOCK — встроенный блочный; B=4 USER — зарегистрированный шаблон. BYTE/BLOCK не отменяют регистрацию. После сервисного доступа вызывается RESTORE. USER не гарантирует низкоуровневые входы чтения/записи в окне. Их ABI определён только для BYTE/BLOCK. Шаблон регистрируется по FF87h для CP/M и FF8Fh для R4; вызывающим программам следует пользоваться ABI, а не этими внутренними адресами.

## Сборка и проверка

Штатная сборка — `build: ramd` либо `build: OS`. Отдельный R4 можно собрать из source/ramd:

```powershell
../../tasm/sjasmplus.exe --i8080 -Wno-rdlow -DRAMD_USE_CPM=0 --raw=../../bin/RAMD-R4.i80 --sym=../../bin/RAMD-R4.sym --lst=../../bin/RAMD-R4.lst RAMD.asm
```

Проверка собственного видимого эмулятора без звука: `python scripts/emu80/check-ramd-modes.py --compare-r4 --report docs/drivers/ramd-new`. Вариант R4 для сравнения должен быть предварительно собран приведённой командой. Тест проверяет cold boot, выбор шаблонов, чтение/запись, границы страниц, невыровненные и верхние буферы, защитные байты, сохранение регистров, ошибки и данные после аппаратного сброса. Замеры относятся к Emu80, не к физическому оборудованию.
