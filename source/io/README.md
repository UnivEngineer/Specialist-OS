# IO.SYS

Файл содержит два сегмента MX. Bootstrap загружает MAIN в F000h–F1BFh и DOS в F040h–F1BFh. При выдаче EXEC загрузчик копирует второй сегмент вместе с локальными службами MEM. DATA получает только хвост MEM. Сегменты IO.SYS линкуются вместе с BIOS.SYS и DOS.SYS через scripts/build/build-bios-dos.py. Итоговые адреса и размеры находятся в bin/System.layout.json, схема памяти — в source/common/system-layout.inc.

Сегмент MAIN начинается с F000h. Его размер и конец приведены в bin/System.layout.json. Отдельно расположены локальный физический вход F5C0h, публичные JMP F860h, слот AT512KS.COM F6C0h–F7FFh (320 байт) и общий слот ROM/FLASH/FLASHFST F9C0h–FBFFh (576 байт). Файловые запросы используют MXCALL. Смещения принимающего адаптера описаны рядом с его исходником. [Адаптер MAIN](main-bios-gate.inc)

| Исходник          | Назначение                                                                |
|-------------------|---------------------------------------------------------------------------|
| KEYBANK.asm       | Матрица, удержание, клавиатурный щелчок и срок мигания в DOS/EXEC          |
| main-bios-gate.inc | Адаптация межбанковых вызовов BIOS и передача пакетов в MAIN                |
| key-scan.inc      | Опрос аппаратной матрицы в MAIN                                           |
| main-ppi.inc      | Режимы ВВ55, программный звук PC5 и сброс звука в MAIN                     |
| beep-timer.inc    | Аппаратный звук ВИ53 с входом RAMFOS по C848h                              |
| pit-tail.inc      | Локальное чтение ВИ53 и запрос адреса регистров в MAIN, DOS и EXEC         |
| input-clock.inc   | Настройка часов клавиатуры и несущей щелчка в MAIN                        |
| MAINIO.asm        | Прямой обмен системного ROM/AT29C flash A: с банком инициатора             |
| fileBody.inc      | Загрузка тела файла с заданным размером заголовка и хвоста                |
| raw-local.inc     | Прямые серии RAW в основной памяти, инициализация локального контекста MEM |
| glyphCache.inc    | Управление резервом кэша глифов и инициализация IO_VARIABLES                |

В MX аппаратный цикл матрицы, чтение Ctrl/ПС и программный звук PC5 исполняются в IO.SYS. STD отображает порты вместо верхнего ОЗУ, поэтому тот же исходный опрос и звук собираются с адресами портов FF00h–FF03h в резидентный BIOS. Исторические C254h и C25Ah устанавливают режим ВВ55, возвращают A=82h и A=91h и сохраняют BC, DE, HL и флаги. C170h ведёт к программному звуку текущего профиля. C848h в профиле RAMFOS настраивает аппаратный звук ВИ53. Загрузчик устанавливает IO.SYS до передачи управления BIOS.

В DOS и EXEC KEYBANK обслуживает матрицу, повтор и щелчок локально и обращается в MAIN для декодирования событий и вывода курсора. Раскладка состояния и примеры приведены в [публичном API](../mem/api.md#локальная-клавиатура-dosexec).

Обработка регистровых пакетов, таблица режимов, совместимый посимвольный вывод и восстановление оболочки входят в BIOS. Принимающий адаптер линкуется вместе с ними и сохраняет вход F014h для совместимого вывода.

Оба сегмента содержат одинаковые 15 байт с F1B1h. `io_pitRead` защёлкивает счётчик 2 за 71 такт 8080 вместе с CALL и RET. `io_pitGetPort` возвращает базу регистров для однократной настройки. При захвате TIMER_CLOCK DOS резервирует устройство и вызывает настройку через частный вход F006h в MAIN. При тайм-ауте DOS снимает резерв. Отсчёты, повтор и щелчок работают локально в банке. Измерители настраивают свой делитель в приложении и читают готовый отсчёт напрямую. [Интерфейс измерительного таймера](../../sdk/asm/lib/timing.md)

A: читается через физический профиль CPM16 прямо из аппаратного ROM-окна в банк инициатора (DOS или EXEC); обычный MEM-клиент запускает это копирование в своём банке, без запроса к MAIN. MAINIO сохраняет вариант чтения для внутреннего физического интерфейса. Запись AT29C сначала переносит полный сектор из банка инициатора в общий буфер MAIN ED80h–EE7Fh, затем вызывает штатный драйвер A:. Драйвер загружает страницу flash быстрым memcpy при подключённом ROM и ожидает DATA polling. AT29C010 программируется двумя частями по 128 байт; AT29C020/C040 — одной частью 256 байт. Перед обменом проверяются границы носителя и буфера. Для записи больше не требуется временная подмена аппаратного окна; стек и маппер восстанавливает обычный драйвер. Профиль ROM-копирования является внутренним привилегированным механизмом, а не новым FAR-кодом приложения.

Физический мост mainBlockIO расположен с F240h; точный размер задаёт bin/System.layout.json. Он принимает запрос A: из DOS или EXEC-банка: `{operation, block:word, buffer:word}`, банк буфера совпадает с банком запроса и определяется транспортом. Чтение полных блоков идёт прямо в память этого банка; запись использует только верхний буфер MAIN, без транзитного секторного буфера DOS. Для MAIN сохраняется локальный физический драйвер. Кэш FAT/каталога и неполные фрагменты по-прежнему принадлежат DOS.

Общая временная область BIOS_TEMP_BUFFER размером 272 байта обслуживает физический сектор A: и длинные графические списки. BIOS_DISK_BUFFER и BIOS_BANK_IO_BUFFER — её псевдонимы. Эти синхронные операции разделяют буфер и выполняются последовательно. Обычные банковые Z и RAW_Z печатаются прямо из 32-байтного окна MEM. Короткие пачки до 32 байт копируются из окна на стек MAIN и допускают вложенные вызовы отдельных команд. Рабочие данные IO описаны в IO_VARIABLES и очищаются при установке входов BIOS.

Ниже F000h размещены служебный стек EC80h–ED7Fh, буфер ED80h–EE8Fh, BIOS_UPPER_VARIABLES EE90h–EF9Fh и IO_VARIABLES EFA0h–EFDBh. Общая арена шрифта и кэша заканчивается перед стеком. Границы кэша и формат файла MXFN описаны в [документации BIOS](../bios/README.md#внешний-шрифт-и-сменный-рендер).

Таблицы адресов обработчиков общего системного вызова находятся в BIOS.SYS рядом с диспетчером и не относятся к CP/M. Адаптер BDOS удалён; группа 0 и зарезервированный вход F863h возвращают UNSUPPORTED. Будущая CP/M использует сменное ядро и отдельный проект адаптации к DOS.

Общие публичные входы, локальные физические адаптеры и транспорт относятся к [MEM.SYS](../mem/README.md). Таблица JMP MXOS2 начинается с F860h. Диапазон F800h–F85Fh в MAIN принадлежит таблице RAMFOS.

Загрузчик тела fileBody.inc использует FILEHANDLE OPEN_AT/SEEK/READ/CLOSE и явный родительский каталог из FILE_BODY_IO.parent. Его временный 64-байтный handle занимает BIOS_TEMP_BUFFER+128 только на время синхронной загрузки; код и запрос не могут быть затёрты телом.
