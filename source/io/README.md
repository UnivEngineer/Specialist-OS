# IO.SYS

Отдельный образ служб основной памяти, не нужных в STD. Bootstrap загружает его из системного ROM в F000h до запуска BIOS. IO.SYS не входит в BIOS.SYS и не требует релокации при инициализации. Оба образа линкуются совместно через scripts/build/build-bios-dos.py; итоговые адреса и размеры находятся в bin/System.layout.json, схема памяти — в source/include/mxos.inc.

Текущий файл занимает 1829 байт, F000h–F724h, без внутренних слотов драйверов. Отдельно расположены локальный физический вход F740h, публичные JMP F800h, слот FLASHSYS.COM F8C0h–F9FFh (320 байт) и общий слот ROM/FLASH/FLASHFST FA00h–FB9Fh (416 байт). Публичные адреса ABI не изменены; адреса внутренних служб перенесены согласованно в main и банке DOS. Подробная внутренняя карта находится в начале [MAINBIOS.asm](MAINBIOS.asm).

| Исходник | Назначение |
|---|---|
| MAINBIOS.asm | Адаптация вызовов BIOS из банков, передача строк и списков UI |
| MAINIO.asm | Прямой обмен системного ROM/AT29C flash A: с банком DOS |
| legacy-files.inc | Генерируемые переходники исторических файловых JMP в DOS |
| fileBody.inc | Загрузка тела файла с заданным размером заголовка и хвоста |
| raw-local.inc | Прямые серии RAW в основной памяти, инициализация локального контекста MEM |
| glyphCache.inc | Управление резервом кэша глифов и инициализация IO_VARIABLES |

A: читается через физический профиль CPM16 прямо из аппаратного ROM-окна в банк DOS. Запись AT29C загружает данные из банка DOS регистровыми порциями R4 прямо во внутренний буфер чипа, затем ожидает DATA polling. AT29C010 программируется двумя частями по 128 байт; AT29C020/C040 — одной частью 256 байт. Перед обменом проверяются границы носителя и буфера. Аппаратное окно и локальный SP восстанавливаются. Профиль ROM-копирования является внутренним привилегированным механизмом, а не новым FAR-кодом приложения.

Физический мост mainBlockIO расположен с F240h (сейчас 507 байт). Он не распознаёт метаданные: принимает любые физические запросы A:, чей буфер находится в DOS, а также возвращает геометрию и описание установленного драйвера. При прямом чтении полного файла в main его блоки передаются локальным драйвером; через мост идут обращения к кэшу FAT/каталога и неполным фрагментам в банке DOS. Поэтому результат профиля «только метаданные» относится к конкретному чтению файла полными блоками, а не к ограничению возможностей моста.

Буфер BIOS_BANK_IO_BUFFER размером 261 байт обслуживает только строки и графические списки банковых клиентов; сектор A: в нём не размещается. Рабочие данные IO описаны единой плотной IO_VARIABLES, размещённой отдельно от образа кода в основной памяти. Очищаются при установке входов BIOS; бессмысленные байты BSS в IO.SYS не сохраняются.

Ниже F000h размещены служебный стек EB90h–ED8Fh, буфер ED90h–EE94h, BIOS_UPPER_VARIABLES EEA0h–EF9Fh и IO_VARIABLES EFA0h–EFFFh. Общая арена шрифта и кэша заканчивается перед стеком. Границы кэша и формат файла MXFN описаны в [документации BIOS](../bios/README.md#внешний-шрифт-и-сменный-рендер).

Таблицы адресов обработчиков общего системного вызова находятся в BIOS.SYS рядом с диспетчером и не относятся к CP/M. Адаптер BDOS удалён; группа 0 и зарезервированный вход F803h возвращают UNSUPPORTED. Будущая CP/M использует сменное ядро и отдельный проект адаптации к DOS.

Общие публичные входы, локальные физические адаптеры и транспорт относятся к [MEM.SYS](../mem/README.md). IO.SYS больше не устанавливает собственную таблицу JMP на F800h.
