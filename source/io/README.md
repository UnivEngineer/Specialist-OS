# IO.SYS

Отдельный образ служб основной памяти, не нужных в STD. Bootstrap загружает его из системного ROM в F000h до запуска BIOS. IO.SYS не входит в BIOS.SYS и не требует релокации при инициализации. Оба образа линкуются совместно через scripts/build/build-bios-dos.py; итоговые адреса и размеры находятся в bin/System.layout.json, схема памяти — в source/include/mxos.inc.

IO.SYS начинается с F000h; его размер и конец приведены в bin/System.layout.json, внутренние слоты драйверов в файл не входят. Отдельно расположены локальный физический вход F740h, публичные JMP F800h, слот AT512KS.COM F8C0h–F9FFh (320 байт) и общий слот ROM/FLASH/FLASHFST FA00h–FB9Fh (416 байт). Публичные адреса ABI не изменены; адреса внутренних служб перенесены согласованно в main и банке DOS. Подробная внутренняя карта находится в начале [MAINBIOS.asm](MAINBIOS.asm).

| Исходник | Назначение |
|---|---|
| MAINBIOS.asm | Адаптация вызовов BIOS из банков, передача строк и списков UI |
| MAINIO.asm | Прямой обмен системного ROM/AT29C flash A: с банком инициатора |
| legacy-files.inc | Генерируемые переходники исторических файловых JMP в DOS |
| fileBody.inc | Загрузка тела файла с заданным размером заголовка и хвоста |
| raw-local.inc | Прямые серии RAW в основной памяти, инициализация локального контекста MEM |
| glyphCache.inc | Управление резервом кэша глифов и инициализация IO_VARIABLES |

A: читается через физический профиль CPM16 прямо из аппаратного ROM-окна в банк инициатора (DOS или EXEC); обычный MEM-клиент запускает это копирование в своём банке, без запроса к MAIN. MAINIO сохраняет вариант чтения для внутреннего физического интерфейса. Запись AT29C сначала переносит полный сектор из банка инициатора в общий буфер MAIN ED80h–EE7Fh, затем вызывает штатный драйвер A:. Драйвер загружает страницу flash быстрым memcpy при подключённом ROM и ожидает DATA polling. AT29C010 программируется двумя частями по 128 байт; AT29C020/C040 — одной частью 256 байт. Перед обменом проверяются границы носителя и буфера. Для записи больше не требуется временная подмена аппаратного окна; стек и маппер восстанавливает обычный драйвер. Профиль ROM-копирования является внутренним привилегированным механизмом, а не новым FAR-кодом приложения.

Физический мост mainBlockIO расположен с F240h; точный размер задаёт bin/System.layout.json. Он принимает запрос A: из DOS или EXEC-банка: `{operation, block:word, buffer:word}`, банк буфера совпадает с банком запроса и определяется транспортом. Чтение полных блоков идёт прямо в память этого банка; запись использует только верхний буфер MAIN, без транзитного секторного буфера DOS. Для MAIN сохраняется локальный физический драйвер. Кэш FAT/каталога и неполные фрагменты по-прежнему принадлежат DOS.

Общая временная область BIOS_TEMP_BUFFER размером 272 байта обслуживает физический сектор A: и строки/графические списки банковых клиентов. BIOS_DISK_BUFFER и BIOS_BANK_IO_BUFFER — её псевдонимы. Текст/UI используют до 261 байта, сектор — 256; эти синхронные нереентерабельные операции не вложены друг в друга. Рабочие данные IO описаны единой плотной IO_VARIABLES, размещённой отдельно от образа кода в основной памяти. Очищаются при установке входов BIOS; бессмысленные байты BSS в IO.SYS не сохраняются.

Ниже F000h размещены служебный стек EB90h–ED8Fh, буфер ED90h–EE94h, BIOS_UPPER_VARIABLES EEA0h–EF9Fh и IO_VARIABLES EFA0h–EFFFh. Общая арена шрифта и кэша заканчивается перед стеком. Границы кэша и формат файла MXFN описаны в [документации BIOS](../bios/README.md#внешний-шрифт-и-сменный-рендер).

Таблицы адресов обработчиков общего системного вызова находятся в BIOS.SYS рядом с диспетчером и не относятся к CP/M. Адаптер BDOS удалён; группа 0 и зарезервированный вход F803h возвращают UNSUPPORTED. Будущая CP/M использует сменное ядро и отдельный проект адаптации к DOS.

Общие публичные входы, локальные физические адаптеры и транспорт относятся к [MEM.SYS](../mem/README.md). IO.SYS больше не устанавливает собственную таблицу JMP на F800h.
