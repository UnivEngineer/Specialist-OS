# Начальный загрузчик MXOS

## Загрузка на оригинальном MX

Системное ПЗУ 32/48 КиБ использует MXOS-256. Вектор сброса указывает на первый кластер файла BOOT.SYS с заставкой по 0600h. Второй сектор хранит точки возврата по 0103h и 0106h. В корне C: также лежат BIOS.SYS, 8×8 ROTATE.FNT, IO.SYS и MEM.SYS. Вторая ступень при каждом Reset выбирает один комплект целиком. Если внешний образ поставляет BIOS, шрифт, IO и MEM берутся из него. При пустом слоте BIOS загрузчик копирует весь совместимый комплект C: по смещениям из служебного сектора ПЗУ. Вариант 2 КиБ начинает исполнение с 0000h и использует ту же вторую ступень без файловой системы и заставки. Обе версии сначала очищают экран.

Bootstrap проверяет внешнюю flash ВВ55 в первых двух гнёздах, затем дисковод 0. Обе версии системы размещают BIOS, IO, MEM, рабочий шрифт и ядро DOS в зарезервированных секторах загрузочного носителя. Flash содержит образ FAT12 с сигнатурой MXF1, дискета использует MXB1. Системный образ с комплектом C: собирается командой `scripts/images/build-image.ps1 MxFloppy -MxUseRomBundle`. При тёплом Reset выбранный комплект ставится снова. Если ядро готово и идентификатор сборки, источник BIOS и тип загрузочного носителя совпадают, DOS и его драйвер остаются в банке. Иначе выполняется полная загрузка ядра с проверкой каждого сектора. Повреждение данных BIOS или DOS приводит к отказу от носителя. В конце поиска загрузчик выводит готовую битмапу и останавливается до сброса.

`SECTOR.asm` восстанавливает исторический 256-байтный `boot-system.bin` побайтно. JMP по адресу 0000h пропускает заголовок FAT12/16 с расширенным BPB: его длина 3Eh (62 байта). Это загрузочный сектор тома, а не первый сектор таблицы FAT. Оригинальный бинарный шаблон сохранён.

Штатный загрузочный сектор (`SECTOR.asm`, `STAGED_BOOT`) сначала очищает экран 9000h–BFFFh стековыми записями, затем копирует BOOT.SYS из ROM-слота 2000h по 8000h и передаёт ему управление. Длина копии берётся из готового BOOT.SYS при сборке.

BOOTBANK.asm — штатный BOOT.SYS банковой системы. До копирования системных файлов он выводит курсивный логотип «Специалист MX²»: белые буквы и красную надстрочную цифру 2. Исторический bitmap 368×39 взят побайтно из `RAMFOS-master/logo.inc` (vinxru, 2013); собственный вывод не зависит от BIOS и шрифтового модуля. Сборщик `scripts/build/build-boot-splash.py` разделяет рисунок на две монохромные части, удаляет пустые верхние и нижние строки и сжимает белую надпись RLE отдельно по каждому байтовому столбцу. Надстрочная цифра 2 хранится отдельным маленьким несжатым битмапом. Цвет задаётся явно перед каждой частью; таблицы атрибутов нет. Пакет RLE содержит управляющий байт: 00h–7Fh задают 1–128 следующих литералов, 80h–FFh — 1–128 повторов следующего байта; пакеты не пересекают границу столбца. Исходный `splash.bin` сохранён без изменений; подготовленные данные и геометрия генерируются в `bin/bootstrap/`. Затем он загружает BIOS.SYS в main с C000h, IO.SYS с F000h. Модуль, выбранный директивой `@bootfont` в системном манифесте (по умолчанию `FONTS/6x8/Rotate.fnt`), читает из слота 4800h: пропускает 32-байтный заголовок и переносит готовое тело по D800h. Шрифт уже встроен в модуль в готовом формате; его адрес и длина зависят от движка. Bootstrap не преобразует шрифт и копирует реальный размер выбранного модуля. До первого вывода BIOS вызывает `FONT_ENGINE_INIT` (D800h), устанавливая прямые входы движка. Стек SP=8FDFh. Временное тело bootstrap исполняется с 8000h и должно заканчиваться не выше STACK_BOTTOM=8E00h. При холодном старте оно может занимать ещё не используемую область RUN 8C00h–8DFFh; стек не затрагивается. MEM.SYS читается отдельно из ROM-слота 7000h, не включается в BOOT.SYS: ограничение относится к временной копии в RAM, а не к размеру загрузочного сектора. Файловые службы DOS для загрузки шрифта не нужны.

| Файл | Фиксированный адрес в системном ROM |
|---|---:|
| BOOT.SYS | 2000h |
| BIOS.SYS | 3000h |
| Модуль из @bootfont | 4800h (тело после 32-байтного заголовка, с 4820h) |
| IO.SYS | 6000h |
| MEM.SYS | 7000h |
| DOS.SYS | 8000h |

До восстановления хвостов bootstrap читает из первого банка B: восемь неизменяемых байтов развёртки CPM32 по FF0Eh–FF15h и сравнивает их с установочным образом. Временная побайтовая процедура использует общее окно как рабочую память и читает сигнатуру напрямую из DATA, без атрибутов окна. Несовпадение означает потерю состояния ОЗУ. DOS загружается заново, а RAMDISK получает признак новой памяти через MEMORY/RAMDISK STATUS (D=1). Случайные байты первого сектора больше не препятствуют первоначальному выбору размера и форматированию B:. Признак сбрасывается только после успешного COMMIT и сохраняется при Reset незавершённой установки.

Далее bootstrap проверяет флаг готовности DOS и совместимость MEM_RUNTIME_REVISION в банке ДОЗУ 0. При холодном старте он прямо копирует DOS.SYS из ROM в этот банк по 0100h; при сохранённой готовности и совместимой ревизии оставляет DOS, её кэш, драйверы и RAM-диск. Устанавливает транспорт и клиентские хвосты и передаёт управление BIOS. BIOS сохраняет экран с логотипом и выводит диагностику сверху; заставка остаётся на время запуска до перерисовки оболочки. Каждое аппаратное Reset заново загружает BIOS, IO и шрифт. Программный возврат на C000h/C800h обрабатывается BIOS без повторного bootstrap. Старые BOOT.asm и legacy-unpacker.asm оставлены для исторических вариантов; BOOTBANK.asm задаёт текущий путь.

Размеры экспортирует scripts/build/build-bootstrap.py; физические слоты гарантирует scripts/images/build-image.ps1. Переполнение слота, конфликт с метаданными или недопустимый диапазон прекращает сборку. Обновление этих файлов обычными файловыми командами не заменяет пересборку ROM. Bootstrap включает точный установочный образ MEM.SYS и использует его сегменты; отдельный MEM.SYS также помещается в фиксированный слот системного диска.

Проверка: python scripts/emu80/check-bootstrap.py --report docs/banked/bootstrap-new. Она проверяет холодный старт, Reset с сохранением DOS и B:, восстановление шрифта и возвраты в NC/CLI. Эмулятор запускается видимым, без звука и закрывается после проверки. Старые измерения bootprobe относятся к этапу подготовки переноса и не описывают штатную загрузку.

## Межбанковый транспорт

Общий код вынесен в [source/mem](../mem/README.md), собираемый в MEM.SYS. Bootstrap устанавливает полный профиль в main и DOS и минимальный копировщик в банки данных. Протокол и кадры возврата описаны в [transport.md](../mem/transport.md). IO.SYS содержит два последовательных сегмента. При каждом Reset bootstrap ставит первый в MAIN с F000h и второй в банк DOS с F040h. MODULE_LOAD использует установленную копию в DOS при подготовке EXEC. Слоты физических драйверов заполняются их инициализаторами.

При несовпадении ревизии транспорта DOS загружается заново: её внутренние адреса нельзя использовать с другим MEM. Это дешёвая проверка версии, не контрольная сумма исполняемой памяти. После обычного Reset с той же ревизией DOS сохраняется. Сигнатура FF00h–FF03h и восстановление после STD-записи в MX сейчас обрабатываются BIOS при C000h/C800h; автоматический переход из этой проверки в bootstrap ещё не подключён.


BOOT.SYS исполняет временную копию загрузчика с 8000h, но больше не содержит копию MEM.SYS: сегменты читаются из штатного ROM-слота 7000h. Это устраняет переполнение временной области без переноса стека или экрана. Все файлы системы должны пересобираться совместно.


Выбор шрифтового движка задаётся строкой `@bootfont FONTS/8x8/Rotate.fnt` или `@bootfont FONTS/6x8/Rotate.fnt` в `assets/C-Flash-512k-MMX-System.txt`. Для разовой сборки системного образа предусмотрен ключ `-BootFont` у `scripts/images/build-image.ps1`. Требуется самодостаточный движок без резервации MAIN; Fast12K/Packed6K сборщик отклоняет, их устанавливают через FONT после запуска MEM/DOS. BOOT.SYS и MEM.SYS теперь являются обычными явными строками манифеста; сборщик только проверяет их наличие и фиксированные позиции.
