# Начальный загрузчик MXOS

`SECTOR.asm` восстанавливает исторический 256-байтный `boot-system.bin` побайтно. JMP по адресу 0000h пропускает заголовок FAT12/16 с расширенным BPB: его длина 3Eh (62 байта). Это загрузочный сектор тома, а не первый сектор таблицы FAT. Оригинальный бинарный шаблон сохранён.

BOOTBANK.asm — штатный bootstrap банковой системы. Из линейного ROM он переносит себя по 8000h и загружает BIOS.SYS в main с C000h, IO.SYS с F000h. Полный FONT.FNT (256 глифов, 2048 байт) читает из слота 5800h и транспонирует в восемь страниц RAM по FONT_ADDR=E300h. Таблиц диапазонов и заголовка в RAM нет. Стек SP=8FDFh. Временное тело bootstrap исполняется с 8000h и должно заканчиваться не выше STACK_BOTTOM=8E00h. При холодном старте оно может занимать ещё не используемую область RUN 8C00h–8DFFh; стек не затрагивается. BOOT.SYS уже содержит основное тело загрузчика и включённый установочный образ MEM.SYS: ограничение относится к временной копии в RAM, а не к размеру загрузочного сектора. Файловые службы DOS для загрузки шрифта не нужны.

| Файл | Фиксированный адрес в системном ROM |
|---|---:|
| BOOT.SYS | 2000h |
| BIOS.SYS | 3000h |
| FONT.FNT | 5800h |
| IO.SYS | 6000h |
| MEM.SYS | 7000h |
| DOS.SYS | 8000h |

Далее bootstrap проверяет флаг готовности DOS и совместимость MEM_RUNTIME_REVISION в банке ДОЗУ 0. При холодном старте он прямо копирует DOS.SYS из ROM в этот банк по 0100h; при сохранённой готовности и совместимой ревизии оставляет DOS, её кэш, драйверы и RAM-диск. Устанавливает транспорт и клиентские хвосты и передаёт управление BIOS. Каждое аппаратное Reset заново загружает BIOS, IO и шрифт. Программный возврат на C000h/C800h обрабатывается BIOS без повторного bootstrap. Старые BOOT.asm и legacy-unpacker.asm оставлены для исторических вариантов; BOOTBANK.asm задаёт текущий путь.

Размеры экспортирует scripts/build/build-bootstrap.py; физические слоты гарантирует scripts/images/build-image.ps1. Переполнение слота, конфликт с метаданными или недопустимый диапазон прекращает сборку. Обновление этих файлов обычными файловыми командами не заменяет пересборку ROM. Bootstrap включает точный установочный образ MEM.SYS и использует его сегменты; отдельный MEM.SYS также помещается в фиксированный слот системного диска.

Проверка: python scripts/emu80/check-bootstrap.py --report docs/banked/bootstrap-new. Она проверяет холодный старт, Reset с сохранением DOS и B:, восстановление шрифта и возвраты в NC/CLI. Эмулятор запускается видимым, без звука и закрывается после проверки. Старые измерения bootprobe относятся к этапу подготовки переноса и не описывают штатную загрузку.

## Межбанковый транспорт

Общий код вынесен в [source/mem](../mem/README.md), собираемый в MEM.SYS. Bootstrap устанавливает полный профиль в main и DOS и минимальный копировщик в банки данных. Протокол и кадры возврата описаны в [transport.md](../mem/transport.md). IO.SYS остаётся отдельным непрерывным образом основной памяти. Слоты физических драйверов заполняются их инициализаторами.

При несовпадении ревизии транспорта DOS загружается заново: её внутренние адреса нельзя использовать с другим MEM. Это дешёвая проверка версии, не контрольная сумма исполняемой памяти. После обычного Reset с той же ревизией DOS сохраняется. Сигнатура FF00h–FF03h и восстановление после STD-записи в MX сейчас обрабатываются BIOS при C000h/C800h; автоматический переход из этой проверки в bootstrap ещё не подключён.
