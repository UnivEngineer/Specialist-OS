# Сменные шрифтовые движки

`FONT.COM` располагается в корне A:, а движки и шрифты — в `A:\FONTS`. Каталоги группируются по размеру знакоместа. Имена укладываются в FAT 8.3; регистр несущественен. PATH для поиска файлов движков не используется.

```text
FONT 6x8/Rotate
FONT 6x8/Rotate.fnt
FONT 6x8/Packed6K
FONT 6x8/Fast12K
FONT 6x8/Fast12K -FILE
```

Первые две команды выбирают `A:\FONTS\6x8\Rotate.fnt`. Загрузчик принимает `/` и `\` как разделители. `.dll` обозначает исполняемый модуль с готовым встроенным шрифтом, `.fnt` — исходные битмапы, а не исполняемый комплект. Например, `6x8/KOI8.pf` содержит обычные 256 глифов по восемь последовательных байтов. Имя каталога задаёт геометрию, имя файла — вариант: `Rotate`, `Fast12K`, `Packed6K`. Наличие имени в этой схеме не означает, что соответствующий движок уже реализован.

## Текущее состояние

Собираются `Rotate.fnt`, `Packed6K.fnt`, `Fast12K.fnt` и `Compact.fnt` для 6×8, `Fast8.fnt` для 8×8 и `Cpm4.fnt` для 4×8. Bootstrap устанавливает выбранный в системном манифесте самодостаточный движок вместе со шрифтом до первого вывода BIOS; по умолчанию это Rotate. `FONT 6x8/Packed6K` резервирует 4096 байт в MAIN через MEM, подготавливает P0/P1 и устанавливает модуль. При отсутствии других системных резерваций плоскости занимают 7C00h–8BFFh, а memTop становится 7BFFh. `FONT 6x8/Rotate` освобождает эту резервацию и восстанавливает границу с учётом других системных блоков. Выход FONT.COM, возврат в NC и программный C800h не освобождают память действующего движка. Bootstrap после подмены ядра восстанавливает выбранный загрузочный движок и сбрасывает эти резервации.

Fast12K резервирует 10240 байт (6400h–8BFFh при отсутствии других резерваций), memTop=63FFh. В верхнем шрифте хранится исходная фаза, внизу — пять плоскостей b<<2, b>>2, b<<6, b>>4, b<<4. Четвёрки сливают байты простым OR, одиночные символы и края используют COL6PRE; обычные и инверсные ядра раздельные.

Преобразование плоского шрифта и генерация таблиц вынесены в отдельный временный `Init6.dll`. Он загружается только на время работы FONT, не входит в резидентный слот и освобождается вместе с программой. STD-программы получают текущий memTop; RUN проверяет границы загружаемого тела, но не контролирует последующие записи самой программы. Совместимость программ, игнорирующих memTop, проверяется вручную. Выбор испытанного комплекта можно закрепить в BAT перед RUN.

## Резидентный контракт

Слот занимает D800h–EC7Fh. BIOS заканчивается до D800h. Модуль содержит ядра, выбор пакетов и одиночных символов, собственные данные и встроенный шрифт; положение шрифта задаёт заголовок. Стандартные файлы сейчас используют E400h–EBFFh. Вращающий вариант хранит восемь страниц строк по 256 кодов; Packed6K хранит в этом месте P2, а P0/P1 требуют 4096 байт нижней памяти.

| Смещение от D800h | JMP-вход |
| ---: | --- |
| 00h | Attach: DE — заранее подготовленные нижние плоскости или 0 |
| 03h | printChar: C — код, обработка управляющих кодов |
| 06h | printCharRaw: A — любой код глифа |
| 09h | printStringZ: HL — ASCIZ с управляющими кодами |
| 0Ch | printStringRawZ: HL — ASCIZ без управляющих кодов |
| 0Fh | printStringRawLim: HL — буфер, BC — длина |
| 12h | Переключение физической раскладки KOI7/8 |
| 15h | Внутренний скалярный вход BIOS, C — код |
| 18h | Запрос состояния ресурсов |

На смещении 20h расположен заголовок: `FNT1`, версия (1 байт), ширина, высота, формат (0=Rotate, 1=Packed6K, 2=Fast12K, 3=Compact, 4=Fast8, 5=Cpm4), затем четыре слова: размер резидентного образа, адрес шрифта, размер нижних ресурсов, адрес имени временного инициализатора. Внешний контейнер — стандартный 16-байтный заголовок MXOS DLL с адресом загрузки и входа D800h и флагом MAIN.

FONT проверяет контейнер, суммы, размер и версию до копирования в слот. После копирования `FONT_ENGINE_INIT` (D800h) вызывает Attach и переписывает только адреса публичных входов BIOS C000h/C800h. Внутренние вызовы BIOS и банковый диспетчер всегда используют фиксированную таблицу D800h; они не патчатся. Прямые публичные BIOS-вызовы идут сразу в реализации. Attach не должен обращаться к DOS, выделять память или печатать: ресурсы готовятся до начала замены. При ошибке чтения или проверки DLL прежний движок остаётся доступен для сообщения об ошибке.

Обработка ESC, управляющих кодов и прокрутки остаётся в BIOS. Внутренние вызовы C881h/C884h/C887h предназначены для движка; прикладной код использует обычные публичные текстовые входы. Шаги курсора влево/вправо, табуляция и колонка ESC Y учитывают ширину установленного движка. Вертикальный шаг пока общий: 10 пикселей.

## Импорт и готовые таблицы

```text
FONT 6x8/Fast12K -FILE
FONT 6x8/Fast12K -IMPORT A:/FONTS/6x8/KOI8.pf
FONT 6x8/Fast12K -IMPORT A:/MyFont.pf -OUT B:/Custom.fnt
FONT B:/Custom.fnt -FILE
```

`-IMPORT` принимает плоский файл ровно 2048 байт: 256 глифов по восемь строк. Инициализатор преобразует его в раскладку выбранного движка, после чего строит пререндер. Команда устанавливает результат и сохраняет новый комплект. Без `-OUT` выбирается первый доступный смонтированный RAM-диск с возможностью записи (обычно B:); имя берётся из исходного шрифта. Например, `MyFont.pf` даёт `B:\MyFont.fnt` и `B:\MyFont.pre`. При отсутствии такого диска установка сохраняется, а FONT сообщает, что файл не записан. `-OUT` задаёт явный путь к новому `.fnt` (расширение можно опустить); каталог должен существовать. Рядом записывается сопровождающий инициализатор, поэтому комплект можно сразу загрузить командой `FONT B:/MyFont.fnt -FILE` или заново сгенерировать его таблицу без `-FILE`. Rotate сохраняется без `.pre`. При совпадении имени файл назначения перезаписывается; исходный плоский `.pf` и DLL-шаблон не изменяются, если пользователь явно не выбрал шаблон как назначение. Запись нескольких файлов не атомарная: при ошибке остаются уже записанные файлы и установленный движок, выводится код ошибки. Расширение `.pf` обозначает редактируемые битмапы; движок со встроенным шрифтом хранится в `.fnt`. `-IMPORT` и `-FILE` несовместимы: импорт требует построить пререндер из новых глифов, а не прочитать готовые плоскости от прежнего шрифта.

`-FILE` читает одноимённый `.pre` прямо в зарезервированные страницы MAIN, без промежуточного копирования и без проверки CS данных. Файл содержит только сырые плоскости: 4096 байт у Packed6K, 10240 у Fast12K. Проверяется точный размер. Это новый формат: прежние файлы FPR1 с 16-байтным заголовком необходимо пересоздать. При отсутствии или ошибке чтения таблица целиком генерируется заново из подготовленного шрифта, новый движок устанавливается, затем выводится код ошибки чтения. До окончания восстановления вывод текста запрещён: старые плоскости могли быть затёрты. Совпадение содержимого `.pre` с выбранным шрифтом по CS больше не проверяется.

Сам DLL движка по-прежнему загружается во временный буфер и проверяется: его нельзя частично записывать поверх работающего рендерера, который нужен для сообщений об ошибках. Небольшой исполняемый инициализатор также проверяется по CS. Эти проверки не проходят по 10 КиБ пререндера.

## Временный инициализатор

Публичный контракт находится в `source/include/font-init.inc`. Дескриптор движка по смещению 46 от начала тела содержит резидентный адрес ASCIZ-имени сопровождающего инициализатора (8.3). FONT находит его рядом с DLL движка. Стандартный MAIN DLL загружается по 5000h, максимальный конец — 5800h. Вход начинается с JMP, затем сигнатура `FIN1`, версия 1. Плоский вход размещается по 4000h; он не перекрывается со staged DLL или инициализатором.

Вызов: A=0 импорт, A=1 генерация; HL указывает на три слова: адрес тела временного образа движка, адрес плоского входа, адрес зарезервированного пререндера. Все регистры разрушаются; CF=0 означает успех, CF=1 и A — ошибку DOS. Импорт меняет встроенные данные staged DLL; генерация пишет только нижние плоскости. Инициализатор не выделяет память, не выполняет I/O и не печатает. FONT управляет файлами и MEM, а инициализатор знает упаковку своего движка. В резиденте остаётся только Attach: настройка адресов и патч публичных JMP BIOS.

Отдельный генератор на хосте создаёт тот же сырой `.pre`:

```text
python scripts/build/build-font-prerender.py --font assets/system-rom/fonts/6x8/KOI8.pf --mode full --out bin/fonts/Fast12K.pre
python scripts/build/build-font-prerender.py --font assets/system-rom/fonts/6x8/KOI8.pf --mode packed --out bin/fonts/Packed6K.pre
```

Сборка ОС вызывает этот генератор и помещает оба `.pre` и временный `Init6.dll` в системный образ.

## Компактный FONTKOI

`FONT 6x8/Compact` устанавливает движок со встроенным компактным шрифтом из общего `assets/system-rom/fonts/6x8/KOI8.pf`. Сборщик выбирает нужные диапазоны в генерируемый `bin/fonts/Compact.pf`; отдельного редактируемого Compact.pf нет. Только DEL заменяется пустым прямоугольником для отсутствующих символов. В модуле 162 глифа: 20h–7Fh, C0h–FFh, ё/Ё (A3h/B3h). Битмапы занимают 1296 байт, таблица индексов — 256 байт. Весь резидентный образ занимает 3088 байт (3104 с файловым заголовком) и не резервирует MAIN.

Это компактный посимвольный движок со сдвигами на лету: строки сохраняют регистры один раз, но не используют четвёрки или пререндер. Инверсия, управляющие коды и все пять текстовых ABI поддерживаются; отсутствующие коды, включая псевдографику 80h–BFh кроме ё/Ё, отображаются глифом DEL (7Fh), пустым прямоугольником. Переключение KOI7/8 переставляет 32 индекса. Импорт плоского шрифта выполняет временный `InitKoi.dll` (261 байт): он выбирает тот же набор 162 кодов; при сохранении `.pre` не создаётся.

## Выбор движка Bootstrap

В `scripts/images/manifests/A-System.txt`:

```text
@bootfont FONTS/6x8/Rotate.fnt
```

Можно выбрать `FONTS/6x8/Compact.fnt` или другой самодостаточный совместимый модуль без нижней таблицы. Именованный DLL должен быть явно объявлен среди файлов манифеста. Сборщик размещает его контейнер по ROM 4800h, передаёт Bootstrap реальную длину тела и проверяет границы слота. Для разовой сборки есть `-BootFont FONTS/6x8/Compact.fnt` у `scripts/images/build-image.ps1` (SystemEmuWritable/SystemHardware). В самом манифесте остаётся основной выбор.

Движки с резервацией MAIN (Fast12K/Packed6K) пока не поддерживаются как загрузочные: сборщик отклоняет их с объяснением. Их можно устанавливать через FONT в AUTOEXEC после запуска MEM/DOS. Неявного расширения или переключения выбранного движка Bootstrap не выполняет. BOOT.SYS и MEM.SYS также объявлены непосредственно в системном манифесте; сборщик проверяет их наличие и фиксированные ROM-позиции, но больше не добавляет скрытые записи.

## Выравненные 8×8 и 4×8

`FONT 8x8/Fast8` устанавливает исправленный KOI8-R шрифт на основе оконного монитора ([происхождение](FONT8WIN.md)); `FONT 4x8/Cpm4` — шрифт CP/M Сябра, уже использовавшийся в FontBen. Оба хранят восемь страниц по 256 кодов в E400h–EBFFh, не резервируют MAIN и поддерживают все пять текстовых ABI. Fast8 копирует восемь строк без масок, строковый цикл держит указатели в регистрах. Cpm4 хранит повторенный полубайт: пары пишут полный байт без чтения экрана, одиночные символы сохраняют соседний полубайт. Строки развёрнуты через DUP. Инверсия и физическое переключение KOI7/8 поддержаны.

Координата X округляется влево до границы знакоместа. Вертикальный шаг остаётся 10 пикселей. Приложения должны учитывать эту геометрию. NC адаптирует панели, диалоги, строку ввода и тулбар при возврате из FONT. Временный `InitA.dll` транспонирует плоский импорт, для Cpm4 берёт младший полубайт и дублирует его. Нижних таблиц и .pre нет. Исходный Win8.pf включён в образ для редактирования.

Пользовательская инструкция всех шести движков: `A:\FONTS\README.TXT`, KOI8-R, окончания строк CR. Ниже — FontBen, локальный ВИ53 Emu80 2 МГц, прямой MAIN ABI, 1152 байтов (24 × 46 + CRLF), без подготовки, обычный вывод. StringZ обрабатывает CRLF, RawLim рисует их. Это эмулятор, не оборудование; при разных ширинах площадь вывода различается. Полная [матрица BIOS / MAIN, включая инверсию](../../docs/bench/resident-vs-standalone/README.md) содержит исходные измерения и условия проверки.

## Единый код и кодировка

FontBen собирает эти же исходники с `FONT_BENCH_MAIN`, размещая модуль в MAIN. Резидент и standalone используют одинаковые публичные фронтенды и ядра; исторические экспериментальные двигатели остаются отдельной коллекцией LEGACY. Обычные и инверсные пиксельные ядра раздельны во всех шести актуальных модулях, в том числе в скалярном выводе. Компактный модуль увеличился до 3088 байт из-за второго набора скалярных ядер.

`FONT_ENGINE_ENCODING` (D812h) — штатная резидентная точка: A=0 выбирает KOI8, любое ненулевое значение KOI7. AF/BC/DE/HL сохраняются; повторная установка той же кодировки ничего не переставляет. Вызовы BIOS `bios_setFontEncoding` и банковый `MXOS_BIOS_SET_FONT_ENCODING` ведут к ней. Меняются группы 60h–7Fh/E0h–FFh: у Compact — индексы, у остальных — битмапы; Packed6K/Fast12K переставляют также все нижние плоскости. Это операция движка, не временного инициализатора: она нужна и после завершения FONT.COM. Attach возвращает уже установленный модуль в KOI8 корректной обратной перестановкой, а не только сбросом флага. Горячие циклы не проверяют KOI.

Короткое имя (`FONT Packed6K`, `FONT Fast8`, `FONT Cpm4`) ищется в A:\FONTS, затем в подпапках 6x8, 8x8 и 4x8, в таком порядке. Расширение .fnt добавляется автоматически. Указанный путь с разделителем или диском используется буквально; повторный поиск допускается только при ошибке «файл не найден». Сообщения FONT используют верхний регистр ASCII для совместимости с KOI7.

Вспомогательные инициализаторы имеют расширение `.dll`, сохраняют проверяемый контейнер MXOS и временный ABI FIN1. Это не устанавливаемые движки: FONT ищет короткие имена только с расширением .fnt и проверяет дескриптор FNT1. Файлы .dll нужны для импорта и подготовки; экспорт переносит их вместе с движком. Compact/FONTKOI отображает все отсутствующие коды через индекс DEL (7Fh); штатный глиф DEL — пустой прямоугольник. При импорте плоского шрифта используется его собственный глиф 7Fh.

FONT выводит номер и текст ошибки: 11 кодов DOS, 7 кодов MEM и общий текст неизвестной ошибки. Все постоянные сообщения написаны заглавными ASCII, без начального перевода строки.

Файлы `.fnt` ассоциированы с `A:\FONT.COM` через CLI.EXT: Enter на файле в NC устанавливает движок. `.fnt` сохраняет контейнер MXOS и дескриптор FNT1; `.dll` — вспомогательный инициализатор FIN1, `.pre` — таблицы, `.pf` — редактируемый пиксельный шрифт. Импорт плоского .pf требует 2048 байта; компактный промежуточный bin/fonts/Compact.pf с заголовком MXFN создаётся сборщиком из общего KOI8.pf. Расширение .pf локальное и не означает BDF/PCF.

`A:\FONTS\4x8\Cpm4.pf` — плоский шрифт CP/M: ровно 2048 байт, 256 глифов по восемь строк, адрес `code*8+row`. В строке один глиф в младших четырёх битах (3 — левый пиксель, 0 — правый), старшие четыре бита нулевые. Для импорта: `FONT Cpm4 -IMPORT A:/FONTS/4x8/Cpm4.pf`. Исходный построчный FONT4CPM.bin с повторёнными полубайтами сохранён; первоначальное извлечение .pf побайтно воспроизводило его. Теперь Cpm4.pf — редактируемый источник: сборка Cpm4 и FontBen транспонирует его в bin/fonts/cpm4-paged.bin, не меняя исторический .bin.
