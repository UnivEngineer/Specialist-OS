# Сменные шрифтовые движки

`FONT.COM` входит в `C:\DOS`, а движки и шрифты находятся в `C:\FONTS`. Каталоги группируются по размеру знакоместа. Имена укладываются в FAT 8.3; регистр несущественен. PATH для поиска файлов движков не используется.

```text
FONT 6x8/Rotate
FONT 6x8/Rotate.fnt
FONT 6x8/Packed
FONT 6x8/Fast
```

Загрузчик принимает `/` и `\` как разделители. Движок со встроенным шрифтом хранится в `.fnt`, временный инициализатор — в `.dll`, редактируемый шрифт — в `.pf`. Например, `6x8/KOI8.pf` содержит обычные 256 глифов по восемь последовательных байтов. Имя каталога задаёт геометрию, имя файла — вариант, например `Rotate`, `Fast` или `Packed`.

## Текущее состояние

В системном образе 6×8 и 8×8 доступны как `Rotate.fnt`, `Packed.fnt` и `Fast.fnt` в соответствующем каталоге. В `4x8` доступны `Compact.fnt`, `Packed.fnt` и `Fast.fnt`. Компактный движок 6×8 собирается для стенда и встроенных ядер. Bootstrap устанавливает выбранный в системном манифесте самодостаточный движок вместе со шрифтом до первого вывода BIOS. По умолчанию это `6x8/Rotate`. `FONT 6x8/Packed` резервирует 4096 байт в MAIN через MEM, подготавливает P0/P1 и устанавливает модуль. При отсутствии других системных резерваций плоскости занимают 7C00h–8BFFh, а memTop становится 7BFFh. `FONT 6x8/Rotate` освобождает эту резервацию и восстанавливает границу с учётом других системных блоков. Выход FONT.COM, возврат в NC и программный C800h сохраняют резервацию действующего движка. Bootstrap после подмены ядра восстанавливает выбранный загрузочный движок и сбрасывает резервацию.

`6x8/Fast` резервирует 10240 байт (6400h–8BFFh при отсутствии других резерваций), memTop=63FFh. В верхнем шрифте хранится исходная фаза, внизу — пять плоскостей b<<2, b>>2, b<<6, b>>4, b<<4. Четвёрки сливают байты простым OR, одиночные символы и края используют COL6PRE; обычные и инверсные ядра раздельные.

### Фиксированный KOI-7R

`FONT 6x8/K7Rotate` — основной профиль для программ KOI-7R.

Команды `FONT 6x8/K7Rotate`, `FONT 6x8/K7Packed` и `FONT 6x8/K7Hybrid` устанавливают движки с готовыми таблицами в верхнем резидентном слоте. После установки они занимают 0 байт прикладного MAIN. Rotate хранит 1 КиБ таблиц, Packed и Hybrid — по 3 КиБ. У Hybrid средняя пара фаз раздельная и сливается через OR, внешние фазы рассчитываются поворотами. У всех вариантов `7Fh` стирает знакоместо, а в Raw-входах берутся семь младших битов кода.

K7Packed разворачивает растры по четыре строки. Установка и позиционирование лежат после таблиц E000h–EBFFh, резидентный образ заканчивается перед EC6Eh. K7Fast хранит все фазы раздельно в 6 КиБ таблиц и использует их для пакетного и посимвольного вывода. Стендовая сборка предназначена для MAIN, встраиваемые пробы для Монитора‑2 и RAMFOS-MXOS используют верхнюю память.

Физическая раскладка этих модулей всегда KOI-7R. Для возврата в KOI-8 установите обычный `Rotate`, `Packed` или `Fast`. Вход псевдографики рисует восьмистрочное тело. Комплекты поставляются с готовыми таблицами, `-IMPORT` для них недоступен. [Замеры](../../docs/bench/fontben-koi7-2026-11-21/README.md)

Преобразование плоского шрифта и генерация таблиц вынесены в отдельный временный `Init6.dll`. Он загружается только на время работы FONT, не входит в резидентный слот и освобождается вместе с программой. STD-программы получают текущий memTop; RUN проверяет границы загружаемого тела, но не контролирует последующие записи самой программы. Совместимость программ, игнорирующих memTop, проверяется вручную. Выбор испытанного комплекта можно закрепить в BAT перед RUN.

## Резидентный контракт

Слот занимает D800h–EC7Fh. BIOS заканчивается до D800h. Модуль содержит ядра, выбор пакетов и одиночных символов, собственные данные и встроенный шрифт; положение шрифта задаёт заголовок. Стандартные файлы сейчас используют E400h–EBFFh. Rotate хранит восемь страниц шрифта по 256 кодов и рисует четвёрку по трём столбцам экрана. Два указателя на глифы сохраняются на весь столбец. Слияние выполняется в аккумуляторе, цикл развёрнут на четыре строки. Вертикальное направление чередуется между столбцами и четвёрками; Packed6K хранит в этом месте P2, а P0/P1 требуют 4096 байт нижней памяти.

| Смещение от D800h | JMP-вход |
| ---: | --- |
| 00h | Attach: DE — заранее подготовленные нижние плоскости или 0 |
| 03h | printChar: C — код, обработка управляющих кодов |
| 06h | printCharRaw: A — любой код глифа |
| 09h | printStringZ: HL — ASCIZ с управляющими кодами |
| 0Ch | printStringRawZ: HL — ASCIZ без управляющих кодов |
| 0Fh | printStringRawLim: HL — буфер, BC — длина |
| 12h | Переключение физической раскладки KOI7/8 |
| 15h | Внутренний скалярный вход BIOS, C — код |
| 18h | Запрос состояния ресурсов |
| 1Bh | printStringRawPseudo: HL — буфер, BC — длина |

На смещении 20h расположен заголовок `FNT1`: версия 2 (1 байт), ширина, высота, формат, затем четыре слова с размером резидентного образа, адресом шрифта, размером нижних ресурсов и адресом имени временного инициализатора. Внешний контейнер — стандартный заголовок MXOS DLL (`IMAGE_HEADER_SIZE`, сейчас 32 байта) с адресом загрузки и входа D800h и флагом MAIN.

`printStringRawPseudo` доступен из MAIN по C8F6h и через MXCALL 012Dh. Сначала `printStringRawLim` рисует тело экранной строки штатным ядром. Второй проход читает коды четвёрками и собирает байтовые маски для двух дополнительных рядов. Пиксели псевдографики KOI8-R берутся из верхнего и нижнего рядов уже нарисованного глифа. Для остальных кодов, включая Ё и ё, подставляется текущий фон. Compact заполняет добавленные ряды фоном для всех кодов. Обе стадии завершаются до прокрутки.

FONT проверяет контейнер, суммы, размер и версию до копирования в слот. После копирования `FONT_ENGINE_INIT` (D800h) вызывает Attach и переписывает только адреса публичных входов BIOS C000h/C800h. Внутренние вызовы BIOS и банковый диспетчер всегда используют фиксированную таблицу D800h; они не патчатся. Прямые публичные BIOS-вызовы идут сразу в реализации. Attach не должен обращаться к DOS, выделять память или печатать: ресурсы готовятся до начала замены. При ошибке чтения или проверки DLL прежний движок остаётся доступен для сообщения об ошибке.

Обработка ESC, управляющих кодов и прокрутки остаётся в BIOS. Внутренние вызовы C881h/C884h/C887h предназначены для движка; прикладной код использует обычные публичные текстовые входы. Шаги курсора влево/вправо, табуляция и колонка ESC Y учитывают ширину установленного движка. Вертикальный шаг пока общий: 10 пикселей.

## Импорт и готовые таблицы

```text
FONT 6x8/Fast -FILE
FONT 6x8/Fast -IMPORT C:/FONTS/6x8/KOI8.pf
FONT 6x8/Fast -IMPORT A:/MyFont.pf -OUT B:/Custom.fnt
FONT B:/Custom.fnt -FILE
```

`-IMPORT` принимает плоский файл ровно 2048 байт: 256 глифов по восемь строк. Инициализатор преобразует его в раскладку выбранного движка, после чего строит пререндер. Команда устанавливает результат и сохраняет новый комплект. Без `-OUT` выбирается первый доступный смонтированный RAM-диск с возможностью записи (обычно B:); имя берётся из исходного шрифта. Например, `MyFont.pf` даёт `B:\MyFont.fnt` и `B:\MyFont.pre`. При отсутствии такого диска установка сохраняется, а FONT сообщает, что файл не записан. `-OUT` задаёт явный путь к новому `.fnt` (расширение можно опустить); каталог должен существовать. Рядом записывается сопровождающий инициализатор, поэтому комплект можно сразу загрузить командой `FONT B:/MyFont.fnt -FILE` или заново сгенерировать его таблицу без `-FILE`. Rotate сохраняется без `.pre`. При совпадении имени файл назначения перезаписывается; исходный плоский `.pf` и DLL-шаблон не изменяются, если пользователь явно не выбрал шаблон как назначение. Запись нескольких файлов не атомарная: при ошибке остаются уже записанные файлы и установленный движок, выводится код ошибки. Расширение `.pf` обозначает редактируемые битмапы; движок со встроенным шрифтом хранится в `.fnt`. `-IMPORT` и `-FILE` несовместимы: импорт требует построить пререндер из новых глифов, а не прочитать готовые плоскости от прежнего шрифта.

`-FILE` читает одноимённый `.pre` прямо в зарезервированные страницы MAIN, без промежуточного копирования и без проверки CS данных. Файл содержит только сырые плоскости: 4096 байт у Packed6K, 10240 у Fast12K. Проверяется точный размер. Это новый формат: прежние файлы FPR1 с 16-байтным заголовком необходимо пересоздать. При отсутствии или ошибке чтения таблица целиком генерируется заново из подготовленного шрифта, новый движок устанавливается, затем выводится код ошибки чтения. До окончания восстановления вывод текста запрещён: старые плоскости могли быть затёрты. Совпадение содержимого `.pre` с выбранным шрифтом по CS больше не проверяется.

Сам DLL движка по-прежнему загружается во временный буфер и проверяется: его нельзя частично записывать поверх работающего рендерера, который нужен для сообщений об ошибках. Небольшой исполняемый инициализатор также проверяется по CS. Эти проверки не проходят по 10 КиБ пререндера.

## Временный инициализатор

Публичный контракт находится в `source/include/font-init.inc`. Дескриптор движка по смещению 46 от начала тела содержит резидентный адрес ASCIZ-имени сопровождающего инициализатора (8.3). FONT находит его рядом с DLL движка. Стандартный MAIN DLL загружается по 5000h, максимальный конец — 5800h. Вход начинается с JMP, затем сигнатура `FIN1`, версия 1. Плоский вход размещается по 4000h; он не перекрывается со staged DLL или инициализатором.

Вызов: A=0 импорт, A=1 генерация; HL указывает на три слова: адрес тела временного образа движка, адрес плоского входа, адрес зарезервированного пререндера. Все регистры разрушаются; CF=0 означает успех, CF=1 и A — ошибку DOS. Импорт меняет встроенные данные staged DLL; генерация пишет только нижние плоскости. Инициализатор не выделяет память, не выполняет I/O и не печатает. FONT управляет файлами и MEM, а инициализатор знает упаковку своего движка. В резиденте остаётся только Attach: настройка адресов и патч публичных JMP BIOS.

Отдельный генератор на хосте создаёт тот же сырой `.pre`:

```text
python scripts/build/build-font-prerender.py --font assets/system-rom/fonts/6x8/KOI8.pf --mode full --out bin/fonts/Fast12K.pre
python scripts/build/build-font-prerender.py --font assets/system-rom/fonts/6x8/KOI8.pf --mode packed --out bin/fonts/Packed6K.pre
```

Сборка ОС создаёт `.pre` для тестов. В системном образе поставляются движки и их временные инициализаторы. При штатной установке инициализатор строит таблицы. Для `-FILE` нужен готовый файл рядом с устанавливаемым `.fnt`.

## Компактный FONTKOI

`FONT 6x8/Compact` устанавливает движок со встроенным компактным шрифтом из общего `assets/system-rom/fonts/6x8/KOI8.pf`. Сборщик выбирает диапазоны 20h–7Fh, C0h–FFh и ё/Ё (A3h/B3h) в генерируемый `bin/fonts/Compact.pf`. В модуле 162 глифа шрифта и отдельный пробельный глиф для DEL в KOI-7R. Битмапы занимают 1304 байта, таблица индексов — 256 байт. Движок обходится без резерва в MAIN.

Компактный посимвольный движок сдвигает битмапы на лету и сохраняет регистры один раз на строку. Он поддерживает инверсию, управляющие коды и все пять текстовых ABI. Для отсутствующих кодов, включая псевдографику 80h–BFh кроме ё/Ё, в обеих кодировках используется исходный глиф 7Fh. В штатном шрифте это контур прямоугольника. Временный `InitKoi.dll` при импорте выбирает те же 162 кода. Для Compact достаточно сохранять файл `.fnt`.

## Выбор движка Bootstrap

В `assets/C-Flash-512k-MMX-System.txt`:

```text
@bootfont FONTS/6x8/Rotate.fnt
```

Можно выбрать `FONTS/8x8/Rotate.fnt` или другой самодостаточный совместимый модуль без нижней таблицы. Именованный DLL должен быть явно объявлен среди файлов манифеста. Сборщик размещает его контейнер по ROM 4800h, передаёт Bootstrap реальную длину тела и проверяет границы слота. Для разовой сборки есть `-BootFont FONTS/6x8/Compact.fnt` у `scripts/images/build-image.ps1` (SystemEmuWritable/SystemHardware). В самом манифесте остаётся основной выбор.

Движки с резервацией MAIN (Fast12K/Packed6K) пока не поддерживаются как загрузочные: сборщик отклоняет их с объяснением. Их можно устанавливать через FONT в AUTOEXEC после запуска MEM/DOS. Неявного расширения или переключения выбранного движка Bootstrap не выполняет. BOOT.SYS и MEM.SYS также объявлены непосредственно в системном манифесте; сборщик проверяет их наличие и фиксированные ROM-позиции, но больше не добавляет скрытые записи.

## Выравненные 8×8 и 4×8

`FONT 8x8/Rotate` устанавливает исправленный KOI8-R шрифт на основе оконного монитора. При выровненном X пакет копирует восемь строк без масок и чередует направление между соседними глифами. Z, RawZ и RawLim используют одни и те же пиксельные циклы. [Происхождение шрифта](FONT8WIN.md)

Все три движка 4×8 используют шрифт CP/M Сябра и поддерживают обычный, инверсный и псевдографический вывод и переключение KOI7/8. Координата X округляется влево до границы знакоместа, вертикальный шаг 10 пикселей. Пара символов пишет полный байт, одиночный символ сохраняет соседний полубайт. `InitA.dll` преобразует общий `Cpm4.pf` в формат выбранного движка.

| Движок | Таблицы | MAIN | memTop при свободном верху MAIN |
|---|---|---:|---:|
| `4x8/Compact` | Строки двух соседних кодов в одной восьмибайтной записи. 1 КиБ в E400h–E7FFh и обратная копия 1 КиБ в E000h–E3FFh. | 0 | 8BFFh |
| `4x8/Packed` | 2 КиБ, полубайт повторён в обеих половинах байта, E400h–EBFFh. Ядро 4DUP. | 0 | 8BFFh |
| `4x8/Fast` | 4 КиБ, старший полубайт в E400h–EBFFh, младший в резервации MEM. Слияние через `OR`. | 2 КиБ | 83FFh |

`FONT 4x8/Fast` строит нижнюю таблицу в MAIN. Готовая таблица для `-FILE` имеет размер 2048 байт. В штатной раскладке таблица занимает 8400h–8BFFh. При переходе на `4x8/Packed` или `4x8/Compact` FONT освобождает резервацию. Эти два движка также можно выбрать в качестве загрузочных.

Все три движка 4×8 чередуют направление между парами. Compact готовит обратную таблицу при Attach и при смене KOI. Таблица занимает выравнивание перед основным шрифтом, поэтому размер FNT и резерв MAIN прежние. Все штатные 6×8 кроме посимвольного Compact чередуют направление между четвёрками. У 6×8 Packed и Fast направление меняется также между тремя столбцами внутри четвёрки. [Замеры MAIN и BANK](../../docs/bench/fontben-alternating-2026-11-21/README.md)

Пользовательская инструкция с таблицами MAIN находится в `C:\FONTS\README.TXT`. Пример адресации и таблицы памяти приведены в справке. Строковые и посимвольные замеры в MAIN и BANK собраны в [общей таблице FontBen](../../source-apps/fontbench/RESULTS.MD).

## Единый код и кодировка

FontBen собирает общие исходники модулей из коллекции standalone с `FONT_BENCH_MAIN`, размещая их в MAIN. Резидентные 4×8 `Compact`, `Packed` и `Fast` измеряются через `-E=BIOS` после вызова FONT. С `-E=FAST4` FontBen загружает самостоятельную сборку Fast с обеими таблицами внутри DLL. Исторические ядра доступны в коллекции LEGACY.

`FONT_ENGINE_ENCODING` (D812h) выбирает KOI8 при A=0 и KOI-7R при любом ненулевом A. AF/BC/DE/HL сохраняются. Вызовы BIOS `bios_setFontEncoding` и банковый `MXOS_BIOS_SET_FONT_ENCODING` ведут к этой точке. При смене кодировки движок меняет местами глифы 60h–7Eh и E0h–FEh во всех активных плоскостях. 6×8 Compact переставляет индексы. В KOI-7R DEL (7Fh) использует нулевой битмап и стирает знакоместо с учётом инверсии. Возврат в KOI8 восстанавливает исходный глиф 7Fh, в том числе импортированный. На FFh сохраняется исходный глиф Ъ. Attach возвращает модуль в KOI8 той же операцией. Горячие циклы используют готовые глифы напрямую.

Путь без диска считается относительно `C:\FONTS`. Указывайте размер явно, например `FONT 6x8/Packed`, `FONT 8x8/Rotate` или `FONT 4x8/Fast`. Команды FONT Rotate, FONT Cpm4 и FONT Fast8 выбирают 6x8/Rotate, 4x8/Packed и 8x8/Fast. Остальные короткие имена ищутся в каталоге `C:\FONTS`. Расширение .fnt добавляется автоматически. Явный путь с диском используется буквально. Сообщения FONT используют верхний регистр ASCII для совместимости с KOI7.

Вспомогательные инициализаторы имеют расширение `.dll`, контейнер MXOS и временный ABI FIN1. FONT ищет устанавливаемые движки с расширением .fnt и проверяет дескриптор FNT1. Файлы .dll нужны для импорта и подготовки. Экспорт переносит их вместе с движком. Compact/FONTKOI берёт заполнитель отсутствующих кодов из исходного глифа 7Fh. При импорте используется глиф 7Fh из плоского шрифта.

FONT выводит номер и текст ошибки: 11 кодов DOS, 7 кодов MEM и общий текст неизвестной ошибки. Все постоянные сообщения написаны заглавными ASCII, без начального перевода строки.

Файлы `.fnt` ассоциированы с `C:\DOS\FONT.COM` через CLI.EXT: Enter на файле в NC устанавливает движок. `.fnt` сохраняет контейнер MXOS и дескриптор FNT1; `.dll` — вспомогательный инициализатор FIN1, `.pre` — таблицы, `.pf` — редактируемый пиксельный шрифт. Импорт плоского .pf требует 2048 байта; компактный промежуточный bin/fonts/Compact.pf с заголовком MXFN создаётся сборщиком из общего KOI8.pf. Расширение .pf локальное и не означает BDF/PCF.

`C:\FONTS\4x8\Cpm4.pf` — плоский шрифт CP/M из 2048 байт. Каждый из 256 глифов занимает восемь строк по адресу `code*8+row`. Пиксели лежат в младших четырёх битах, от бита 3 слева до бита 0 справа. Команда импорта `FONT 4x8/Fast -IMPORT C:/FONTS/4x8/Cpm4.pf` подходит и для `4x8/Compact` или `4x8/Packed` при замене имени движка. `Cpm4.pf` остаётся общим редактируемым источником для трёх форматов и FontBen. Исторический `FONT4CPM.bin` хранит повторённые полубайты.

Глиф Tab (09h) во всех редактируемых шрифтах изображает стрелку вправо со стенкой (`->|`). 6×8 Compact отображает этот код через Raw API глифом-заполнителем отсутствующих кодов. В обычном printChar/printStringZ код 09h перемещает курсор к следующей позиции, кратной четырём знакоместам от левого края. Если позиция выходит за правую границу, курсор переходит в начало следующей строки.

## Восстановление после программ и Reset

DOS запоминает успешную команду FONT вместе с её аргументами и исходным каталогом. Если EXCLUSIVE-программе нужна вся MAIN, нижний пререндер временно освобождается и устанавливается верхний Rotate. Перед возвращением в NC/CLI выбранный движок, глифы и пререндер восстанавливаются повторным FONT; запись импортированного шрифта и экспорт при этом не повторяются. Тёплый Reset сохраняет профиль в банке DOS и также восстанавливает его. При холодном включении выбор задают bootstrap и AUTOEXEC. Файлы выбранного профиля должны оставаться доступными.


`FONT 8x8/Rotate` устанавливает движок для точного позиционирования. X передаётся в единицах по два пикселя, как и в других движках. При X, кратном четырём, работает пакетный путь Fast8. В остальных позициях глиф и мигающий курсор могут занимать два байта экрана. Фаза сохраняется до явной смены позиции или переноса. Если глиф заходит за правый край, видимая часть рисуется, затем курсор переходит на следующую строку. Graph8 использует тот же шрифт и InitA.dll, что и Fast8.

Для невыровненных строк Graph8 обрабатывает по одному экранному байту за итерацию, Graph8x2 — по два. Движок определяет фазу и длину пачки перед отрисовкой. StringZ останавливает пачку перед управляющим кодом, RawZ — перед нулём, RawLim учитывает оставшуюся длину. На каждой из восьми пиксельных строк читаются только краевые байты, а внутренние записываются целиком. Graph8x2 читает пары кодов через стек и отдельно рисует нечётный хвост. Graph8x4 обрабатывает две пары за итерацию и держит перенос между ними в регистре. В системный образ входит Graph8x4 под именем `8x8/Rotate.fnt`. Поштучный и парный варианты оставлены в сборке для экспериментов. Все три используют один шрифт без резервации MAIN.


### Варианты 8×8 для сравнения

| Модуль | Выровненный текст | Невыровненный текст | Резерв MAIN |
|---|---|---|---:|
| `Fast8` (контроль FontBen) | Восемь байтов каждого глифа подряд | X округляется вниз до знакоместа | 0 |
| `Fast8Row` (экспериментальная сборка) | Восемь проходов по тексту, по одному на пиксельную строку | X округляется вниз до знакоместа | 0 |
| `8x8/Rotate` | Ядро Fast8 | Четыре байта за итерацию, вращение на лету | 0 |
| `8x8/Packed` | Ядро Fast8 | Три фазы повёрнутых байтов. Маски извлекают две части из одного байта. | 6 КиБ |
| `8x8/Fast` | Ядро Fast8 | Для каждой строки и фазы две соседние страницы содержат готовые части. Внутри строки слияние через OR. | 12 КиБ |

У обоих пререндеров исходный шрифт занимает ещё 2 КиБ в верхнем слоте. При невыровненном выводе экран читается только по краям текстового участка. `InitA.dll` готовит таблицы из встроенного или импортированного `.pf`. Для загрузки с `-FILE` положите готовый одноимённый `.pre` рядом с `.fnt`. Для сравнения используйте `FontBen -X0 -Q -N` при выравнивании и `-X1`, `-X2`, `-X3` для смещений на 2, 4 и 6 пикселей.
