# Драйверы ROM и flash

`FLASH.COM`, `FLASHFST.COM`, `FLASHSYS.COM` загружаются с **0000h**.
Нерезидентный установщик сначала сохраняет кэш текущего тома, определяет
чипы через software product ID и только при успехе копирует рабочий код:

| Программа | Резидент | Поддерживаемое оборудование |
|---|---|---|
| FLASH | DE00h–DFFFh | 1–4 AT29C040A, синхронная запись |
| FLASHFST | DE00h–DFFFh | 1–4 AT29C040A, конвейерная запись |
| FLASHSYS | DC00h–DD3Fh | системная AT29C010A / C020 / C040A |
| ROM | DE00h–DFFFh | прежний внешний ROM, установщик загружается в DE00h |

Манифесты и задачи сборки содержат адрес загрузки 0 для трёх flash-программ.
COM-файл содержит установщик и резидент; его нельзя целиком загружать в
DC00h/DE00h. ROM.COM сохраняет прежний способ установки. После запуска
flash-программы её нижняя память освобождается, резидент остаётся до перезагрузки
или замены другим драйвером. Общие исходники — `flash-install.inc` и
`flash-map.inc`. Во время установки FLASHSYS временный код занимает
8200h–82FFh: он может обращаться к нижнему ROM при верхнем стеке.

Хвост окна DD40h–DDFFh выделен для RAMD.COM; сборка FLASHSYS проверяет
эту границу. Установщик копирует только фактический резидент и не затирает RAMD.

## Идентификация и ёмкость

Вход: AAh@5555h, 55h@2AAAh, 90h@5555h; читаются manufacturer по 0000h
и device по 0001h. Выход: AAh@5555h, 55h@2AAAh, F0h@5555h. Обе паузы
превышают 10 мс при 2–2,5 МГц. Эти команды не программируют данные и не
меняют SDP. Алгоритм описан в [документации Atmel](https://ww1.microchip.com/downloads/en/appnotes/doc0510.pdf).

| Чип | Manufacturer / device | Ёмкость | Физическая страница записи |
|---|---|---:|---:|
| AT29C010A | 1Fh / D5h | 128 КиБ | 128 байт |
| AT29C020 | 1Fh / DAh | 256 КиБ | 256 байт |
| AT29C040A | 1Fh / A4h | 512 КиБ | 256 байт |

FLASHSYS выбирает ёмкость и разбиение 256-байтного сектора на две записи
по 128 байт по **ID**, независимо от BPB. Например, том 128 КиБ на физическом
512-КиБ чипе всё равно записывается физическими страницами 256 байт.

FLASH/FLASHFST проверяют четыре гнезда и используют только AT29C040A.
Два чипа дают **1 МиБ / 4096 секторов**, четыре — 2 МиБ / 8192 сектора.
Поддерживаются также один и три чипа. Логические чипы нумеруются в порядке
найденных физических гнёзд; таблица допускает промежутки между ними.
При четырёх заполненных гнёздах прежняя нумерация не меняется. Нельзя менять
порядок чипов заполненного носителя: это изменит соответствие секторов данным.

FFh производителя трактуется как пустая шина. Неизвестный непустой ID
отклоняется. В частности, **AT29C040 без A** имеет ID 5Bh и страницу 512 байт:
он не совместим с нынешней 256-байтной записью, поэтому не принимается.
Меньшие AT29C010A/C020 внешними драйверами пока не обслуживаются.

При недоступном/неподдерживаемом ID установщик возвращает CF=1 и оставляет
прежний резидент и регистрацию драйвера. Если /WE отключён перемычкой,
software ID также недоступен: для системного ROM остаётся встроенное чтение.
Автоматического предположения «чип 512 КиБ» при отказе нет.

## ABI и формат тома

B=3 возвращает **физическую** ёмкость в 256-байтных секторах и DISK_INFO в HL;
BC=0 для FLASH/FLASHSYS, BC=2048 для FLASHFST — подсказка распределителю.
Для одного чипа DOS сам переходит к линейному выделению. B=FFh возвращает
имя/описание с фактическим числом чипов либо ёмкостью системной flash.
Обращения за физическую границу через B=1/2/5 отклоняются с CF=1.
Остальные контракты функций, включая B=4 у FLASHFST, сохранены.

Размер тома в BPB — отдельная величина. Определение чипов не форматирует
носитель и не исправляет BPB. Для двух чипов нужен образ на 1 МиБ или
форматирование этого диска; простое обрезание 2-МиБ образа не создаёт
корректный том. `FORMAT.COM H: -Y` создаёт пустой том по физическому B=3
и уничтожает прежний каталог. FAT/каталог не меняют расположение из-за ID.

## Проверки

`scripts/emu80/check-flash-detect.py` проверяет 1/2/3/4 чипа, ID без изменения
данных/SDP, чтение, запись с проверкой, границы и отказ без ID. Системные
128/256/512 КиБ проверяются с физическими страницами 128/256/256 байт.
`check-flash-detect-file.py` проверяет форматирование двухчипового 1-МиБ тома,
файл через DOS с цепочкой на обоих чипах, удаление с восстановлением FAT
и независимость от меньшего размера тома в BPB. Результаты в `docs/flash/`.
Emu80 моделирует незаполненные последние гнёзда; промежуточные пустые гнёзда
требуют отдельной аппаратной проверки. На реальной плате эти проверки пока
не выполнены.
