# RAMDISK.COM

RAMDISK.COM — одноразовый установщик с флагом DRIVER, исполняемый в банке DOS по адресу, выбранному загрузчиком для контейнера v3. Он резервирует фиксированный пул через RAMLIMIT, монтирует готовый том либо размечает новую память через FORMAT, затем передаёт пул самой DOS через MEMORY/RAMDISK COMMIT. DLL, модульный handle и отдельный резидент не создаются; после RET область установщика доступна другим драйверам.

## Фиксированный пул

Штатный AUTOEXEC вызывает C:\DRIVERS\RAMDISK.COM -P 4. Четыре банка данных закрепляются через MEMORY/RAMLIMIT; банк DOS в эти четыре не входит. Вместе с DOS заняты пять банков из шестнадцати, одиннадцать свободны для FAR-памяти и BANK-программ. RAMLIMIT и RAMDISK возвращают `DOS_ERR_NO_MEDIA` (14, `No media`), если запрошенный размер превышает число физических банков данных. На MX с единственным банком под DOS тот же код возвращают обращения к B:.

Размер выбирается при первоначальной подготовке. Повторный запуск без -P запрашивает состояние пула через MEMORY/RAMDISK STATUS и сохраняет прежний размер. Первый запуск без аргументов использует -P 4. Повторный запрос прежнего размера сохраняет данные. RAMLIMIT отказывает при чужих выделениях и при готовом томе другого размера. Параметр -P сам такой том не форматирует.

При нехватке DATA-банков ядро рассматривает пул RAM-диска с приоритетом 254. Оно завершает отложенные записи, монтирует том и проверяет корневой каталог. При файле, каталоге или ошибке проверки пул остаётся за томом, а запрашивающее приложение получает E8h, имя RAMDISK.COM и причину. У проверенного пустого тома ёмкость временно обнуляется и весь пул становится доступен приложениям. После возврата банков DOS запускает штатный FORMAT для прежней буквы и размера. Если FORMAT либо проверка нового тома завершается ошибкой, восстановление остаётся в очереди.

Физический обмен предоставляет общий транспорт MEM/CPM32. Установщик использует штатные секторные службы, а не устанавливает собственный переключатель страниц. Последний физический сектор каждого банка данных защищает хвост MEM и отмечается BAD в FAT. Банки B: исключены из DATA/EXEC-аллокатора.

## Подготовка и тёплый сброс

RAMDISK.COM монтирует B: перед передачей пула DOS. Проверка тома и буфер остаются во временной области установщика. Готовый том принимается без записи. При неподдержанной разметке boot-сектор проверяется консервативно: ошибка чтения, узнаваемый MX/FAT-заголовок, расширенная сигнатура 29h либо правдоподобный размер сектора исключают автоматическое форматирование. Это не полная проверка FAT и каталогов.

Для неразмеченной памяти вызывается C:\DOS\FORMAT.COM <буква>: -R -Y через FILE_EXEC_NATIVE. FORMAT исполняется в main и возвращается в установщик. Сообщения установщика — UPPER ENGLISH; он не переключает KOI7/KOI8 и не переустанавливает шрифт. Проверка тома восстанавливает исходный диск. FORMAT может оставить B: текущим, как при отдельном запуске.

При тёплом Reset DOS сохраняет владение фиксированным пулом и содержимое B:. Повторный AUTOEXEC заново запускает установщик: он принимает готовый том и повторно подтверждает передачу пула DOS. Поиск резидента и RESTORE/CLOSE для RAM-диска не используются. При холодной загрузке новой DOS готовый том прежнего размера принимается без переразметки. Сохранение питания и сохранность самой ДОЗУ остаются необходимыми условиями.

При холодном старте bootstrap передаёт признак утраты хвоста MEM первого банка B:. В этом случае RAMLIMIT не требует заполнения первого сектора байтами 00h/FFh; если том не монтируется, RAMDISK вызывает FORMAT независимо от случайных признаков BPB в ОЗУ. При сохранённом хвосте существующий или повреждённый узнаваемый том не переразмечается автоматически. Успешный COMMIT сбрасывает признак новой памяти. Ошибка AUTOEXEC остаётся на экране до Enter.

## Исторические варианты

Штатный RAMDISK собирается с относительной базой 0000h и флагом DRIVER. Самостоятельные реализации CP/M buf16 и R4 для сравнения алгоритмов доступны в COPYBEN.

## Сборка

Сборка системы создаёт RAMDISK.cpu (v3, WORD16, DRIVER); системный манифест упаковывает его в RAMDISK.COM. DLL для RAM-диска не требуется. После изменения установщика пересоберите системный образ. Все инструкции совместимы с Intel 8080.
