# FILEOPS.DLL

Общий загружаемый движок COPY, междискового MOVE, рекурсивного DEL/ERASE и создания дерева MKDIR. DOS лениво читает `A:\FILEOPS.DLL`; последующие операции используют оставшийся в памяти код. FILEOPS ничего не печатает и не очищает экран. F5/F6 NC используют пошаговый интерфейс; CLI и прежние COPY/MOVE-входы DOS используют синхронный фасад этого же движка. Перемещение внутри тома остаётся операцией над метаданными DOS.

## Публичный интерфейс

`MXOS_CALL MXOS_DOS_FILEOPS`: A — операция, HL — `FILEOPS_JOB` в банке вызывающего. Размер объекта 112 байт, поля и значения объявлены в `source/include/mxos.inc` и C SDK. CF/A описывает ошибку API; результат самой файловой операции находится в `job.state` и `job.error`.

- BEGIN принимает `mode=COPY/MOVE/DELETE` и исходный `FILE_COPY_REQUEST`: имена 8.3, диски и каталоги. Буфер и callback клиента не используются. Возвращает непрозрачный handle.
- STEP обрабатывает очередной участок: до 4 КиБ данных либо элемент каталога. Возвращает RUNNING, CONFIRM, DONE или FAILED. Обычный ответ переносит только 26-байтный заголовок состояния; `request` возвращается при CONFIRM и в остальные моменты сохраняет исходное содержимое клиента. Подготовка цепочки файла и отдельная операция драйвера могут занимать дольше одного переноса; это не гарантия времени исполнения.
- ANSWER после CONFIRM принимает `answer`: 0 No, 1 Yes, 2 Yes to all, 3 No to all. `request` в ответе содержит текущий файл, включая дочерние элементы дерева. Ответ All действует до конца этой операции.
- CANCEL завершает текущую операцию с `DOS_ERR_CANCELLED=12`. Незавершённый файл назначения удаляется; уже перенесённые файлы остаются перенесёнными. Ранее существовавшее содержимое файла после подтверждённой перезаписи не восстанавливается.
- SKIP_PREPARE (5) прекращает только предварительный подсчёт и продолжает копирование с `known=0`. Во время переноса вызов ничего не меняет. Флаг BEGIN `FILEOPS_NO_PREPARE` сразу выбирает этот режим.
- CLOSE обязателен и после успеха, и после ошибки. Для незавершённой операции выполняет отмену, освобождает закрепление арены и обнуляет handle.

`bytes` — число успешно записанных байтов, `files` — завершённых файлов. Во время PREPARE `files` считает найденные файлы, `total` — их суммарный размер, `bytes=0`; перед переносом счётчик `files` начинается заново. `phase` различает PREPARE/COPY/DELETE независимо от `state`. `known=1` означает завершённый подсчёт, `required` — оценку дополнительных кластеров назначения. Необязательный `path` указывает на отдельный MAX_PATH-буфер в банке вызывающего, не пересекающий FILEOPS_JOB; указатель принимается только BEGIN. Буфер получает текущий полный путь с NUL и сохраняет его между STEP. Между STEP можно обращаться к BIOS/DOS, но нельзя изменять обрабатываемые файлы и дерево из другого действия. Контекст диска/каталога вызывающего восстанавливается на каждом возврате. Один активный FILEOPS_JOB; handle и владелец проверяются, повторные STEP после завершения допустимы. Завершение владельца отменяет оставленную операцию; после Reset стек операции и её handle отбрасываются без возобновления. Сам код FILEOPS остаётся кэшированным в сохранённом банке DOS.

## Арена и сборка

Движок собирается по C000h, вместе со своими данными и частным 512-байтным стеком с защитным словом. Занятый интервал заканчивается на `fileopsEnd`, не округляется до размера слота и закреплён до CLOSE. Остальные DOS-DLL регистрируют `[start,end)` в реестре MODULE_TABLE. Инициализатор драйвера регистрирует свой фактический интервал на время выполнения. Проверяются пересечения, а не занятость всей арены: непересекающиеся DLL и установщики могут сосуществовать. Вытеснение FILEOPS разрешено только при отсутствии активной операции и только при пересечении; явные DLL автоматически не выгружаются.

Установщики собираются с адреса `DOS_BANK_DRIVER_END − размер`, поэтому вероятность пересечения с FILEOPS уменьшается; выросший FILEOPS может быть вытеснен установщиком, если его фактический интервал пересекается. Адрес загрузки записывается в заголовок COM; релокации при загрузке нет. Повторная загрузка FILEOPS проверяет контейнер, суммы и вектор соответствия приватных экспортов ядра. `host.inc` — внутренний контракт совместно собираемых DOS/FILEOPS, не интерфейс прикладной программы.

`scripts/build/build-project.ps1 OS` собирает FILEOPS после DOS через `scripts/build/build-overlays.py`; системный манифест включает FILEOPS.DLL. Модуль использует существующие операции FAT и не меняет формат накопителей. Маски источника COPY/MOVE раскрывает общий ENUM.DLL в отдельной нижней арене; каталог назначения должен существовать. Во время копирования очередного совпадения курсор ENUM остаётся закреплённым. Сам FILEOPS получает структурированный запрос на конкретный файл/каталог; см. [перечислитель](../enumerate/README.md).

## Создание дерева каталогов

MKDIR/MD и F7 NC через CLI_OP_MKDIR вызывают этот же модуль. Путь `Games/Almaz-2/MXOS` обрабатывается последовательно по префиксам: существующий каталог пропускается, отсутствующий создаётся резидентным примитивом DOS для одного каталога. Файл вместо каталога — ошибка. Стек не растёт с числом компонентов; исходные диск и CWD восстанавливаются. Escape проверяется между компонентами, активный модуль защищён от вытеснения. Уже созданные родительские каталоги при ошибке или отмене остаются; это не транзакция. Рекурсивные COPY/MOVE/DELETE используют общий обходчик глубиной до 32 каталогов.


## Подготовка, удаление и интерфейс

Пошаговые COPY и междисковый MOVE для дерева по умолчанию сначала перечисляют источник через ENUM.DLL без записи на диск. Учитываются размеры файлов, повторное использование цепочек подтверждённых файлов, новые каталоги, свободные записи и расширение каталогов; для фиксированного корня проверяется ёмкость записей. Оценка не рассчитывает на освобождение места будущими перезаписями: это консервативная проверка, а не резервирование свободного места. После пропуска подсчёта ошибки заполнения по-прежнему возвращает обычная запись. Синхронный фасад CLI COPY/MOVE выполняет перенос без предварительного прохода. MOVE внутри тома остаётся короткой операцией над метаданными без сканирования.

Подсчёт занимает единственный курсор ENUM до завершения, пропуска или отмены. Если приложение уже удерживает свой курсор, оно должно выбрать FILEOPS_NO_PREPARE. Пути ограничены MAX_PATH, файловые имена — 8.3. При CONFIRM можно ответить Yes/No/Yes to all/No to all. Общий размер остаётся размером найденного источника; пропущенные файлы не добавляются к фактически перенесённым байтам.

DEL/ERASE и F8 NC удаляют дерево в глубину, затем пустые каталоги. Корень, `.`/`..`, текущий каталог и его предки защищены; атрибуты read-only/system не обходятся. При ошибке либо отмене уже удалённые элементы не восстанавливаются. RD/RMDIR сохраняет отдельную семантику удаления только пустого каталога.

NC опрашивает клавиатуру между STEP, ограничивает обновление окна четырьмя в секунду и не показывает его для короткой операции. В фазе подготовки Cancel или Escape отменяет только подсчёт, Abort — всю операцию. После подготовки остаётся Abort; Escape также прекращает перенос. Окно сохраняет размер между фазами и восстанавливает подложку только при закрытии. При известном размере проценты расположены слева от полосы, при пропущенном подсчёте полоса и проценты скрыты, остаются фактические байты и путь.

Текстовые поля обновляются только при изменении значения, непрозрачно и с пробельным заполнением остатка. Проценты находятся вне полосы; сама полоса монотонно наращивается по 8 пикселей без стирания заполненной части. Интервал обновления отсчитывается после завершения рисования, клавиатура опрашивается независимо от него.

Для одиночного файла предварительный проход по назначению и подсчёт свободных кластеров пропускаются. total содержит точную длину из дескриптора, known=1, required=0 не означает наличие свободного места. Ошибку заполнения возвращает перенос; обычная очистка частичной копии сохраняется. FILEOPS_NO_PREPARE по-прежнему явно отключает общий прогресс и для файла.

`totalFiles` retains the complete source file count when `known=1`; `files` is the number completed during transfer. Unknown totals must use an activity indicator, not a percentage.
